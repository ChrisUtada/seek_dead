# 架构待办

## 1. 武器硬耦合到 Player 场景

**问题：** `WeaponComponent._ready()` 遍历子节点收集武器，换武器必须手动改 Player `.tscn`。无全局武器库/掉落系统。

**目标：** 引入武器数据库 + 掉落/拾取机制，武器不再硬编码为场景子节点。

**状态：** ✅ 已通过 Phase 7 武器-装备统一解决。WeaponData Resource + 模板池 + EquipmentDrop 生成，WeaponNode 动态装备。

---

## 2. 子弹对象池未接通

**问题：** `projectile.gd` 有 `_pool` 字段和 `_return_to_pool()`，但从未被赋值。每次射击 `instantiate` + `queue_free`，高频射击时 GC 压力大。

**目标：** `RangedWeaponNode` 发射时从 `ObjectPool` 借弹，命中/超时归还。

**状态：** ✅ 已接通。`GameManager.get_bullet_pool()` 预分配 30 发，`weapon_node.gd` 远程攻击从池中 acquire。

---

## 3. Boss 配置数据流混乱

**问题：** `boss_enemy.gd` 同时存在 `_apply_boss_config()`（硬编码数值）和 `apply_config(config: EnemyConfig)`（数据驱动），两套入口互打架。

**目标：** 统一走 `BossConfig` Resource，删除 `_apply_boss_config()` 硬编码分支。

**状态：** ✅ 已统一。`boss_enemy.gd` 删除 `_apply_boss_config()`，加入 `@export var config: BossConfig`，`_ready()` 走数据驱动 `apply_config(config)`，无 config 时保留 fallback 硬编码。

---

## 4. 技能硬编码

**问题：** `player_controller.gd:63-64` 写死注册 `HealSkill` + `ShockwaveSkill`，换角色不能换技能列表。

**目标：** 技能列表由 `PlayerConfig` 定义，`@export var skills: Array[SkillBase]`，角色 `.tres` 配置自带技能组。

**状态：** ✅ 已通过 Pure DMD 路线解决。技能独立拾取，SkillDatabase 自动发现 `resources/skills/`，SkillManager 2 槽管理，EscapeSkill 独立不占槽。

## 6. RoomManager 硬编码 fallback

**问题：** `room_manager.gd:44-47` 硬编码 `room_1.tres` / `room_2.tres` 路径作为 `DirAccess` 失败的兜底。新增房间时需同步更新此列表。

**目标：** 删除 fallback，确保 `DirAccess` 路径在生产构建中也能正常工作，或替换为可维护的注册机制。

**状态：** ✅ fallback 列表已扩展为全部 5 个已知房间（room_1/room_2/room_3_medium/room_4_large/room_boss）。

## 7. 房间无环境碰撞体，玩家可走出导航网格 ✅ 已解决（2026-07-08）

**原问题：** 运行时加载的 `room_1.tscn`/`room_2.tscn`/`room_3_medium.tscn`/`room_4_large.tscn` 由旧 `room_builder` 生成，无任何墙壁碰撞体；而 `room_generator.gd` 产出的含墙场景（`room_small_test.tscn` 等）因命名不一致未被 `.tres` 引用，导致玩家可穿墙、敌人导航被截断。

**修复（2026-07-08）：** 房间改为**手工维护的 `.tscn` 资产**（设计者可在 Godot 编辑器内自由细化），直接产出含墙版本覆盖遗留文件：
- `scenes/rooms/room_1.tscn` / `room_2.tscn` / `room_3_medium.tscn` / `room_4_large.tscn` 现已包含 `StaticBody2D` 墙体围栏（4 面墙，门处留洞）+ 障碍碰撞（`Pillar`/`Crate`/`Bookshelf`/`Counter`）+ `NavigationPolygon` 导航网格
- 碰撞体为纯几何 `RectangleShape2D`，**不依赖美术资源**；地板/墙用 `ColorRect` 占位，未来可换 TileMap/精灵
- 玩家 `collision_mask=4` 与墙 `collision_layer=4`（Environment 层）已匹配，`CharacterBody2D.move_and_slide()` 正常阻挡
- `room_generator.gd` 降级为几何参考工具，不再作为房间来源

**结论：** 房间碰撞体问题已闭环。未来房间设计直接在 Godot 编辑器细化这些 `.tscn`（门位、障碍、装饰、贴图）即可，无需重新跑生成器。
