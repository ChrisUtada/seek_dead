# 商店升级系统重构 · 执行方案

> 状态：**✅ T3 已落地（2026-08-07）**——joker 退役 → 体魄/精准/回复；`GoldUpgradeDef` 数据驱动（effect/per_level/bind）；`ShopSystem` 统一轨道表 + 动态 `charm:<path>`/`weapon:<path>` 展开；结算点全部接线（见 §5 改动清单）。本节以下为设计依据，实现以代码为准。
> 关联讨论：2026-08-05 设计讨论（"升级应绑定真实系统、且后期可替换内容"）
> 代码基线：`duel_controller.gd` HEAD、`shop_screen.gd`、`battle_hud.gd`

---

## 1. 背景与问题

当前商店「升级」页（S12）是 4 个**写死在战斗代码里**的抽象增益：

- 定义：`duel_controller.gd:180` 的 `GOLD_UPGRADE_DEFS`（power / line / joker / shield）
- 购买与刷新：`duel_controller.gd:1027-1082`（`_gold_upgrade_defs` / `_on_gold_upgrade_pressed`）
- 结算读取：`_agg_power_flat`(2007) / 连线倍率(1773) / `_agg_damage_mult`(2019) / 房间护盾(1271)
- UI 渲染：`shop_screen.gd:148` 遍历 `_gold_upgrade_defs()` 生成卡片

**三个痛点（用户原话）：**

1. **割裂** —— 这 4 个按钮加的数字跟玩家携带的装备 / 武器 / 护符**毫无关系**，是凭空冒出来的 buff。
2. **无来源** —— 玩家问"这四个升级没有任何来源非常奇怪"，缺乏世界观锚点。
3. **不可替换** —— 增删 / 改一种升级要同时动 `GOLD_UPGRADE_DEFS`、对应 `effect` 的结算分支、`_gold_upgrade_desc` 三处；没有统一母体。

---

## 2. 目标

把"商店能升什么"从**散落各处的硬编码**重构为**一张可编辑的数据表 + 一个统一分发器**：

- **可随时替换**：增删 / 改一条升级只动数据表，结算代码零改动。
- **不再割裂**：每条轨道都 `bind` 到一个游戏里真实存在的系统（训练 / 卷轴 / 已装备护符 / 已装备武器），来源天然成立。
- **UI 通用化**：商店升级页遍历数据表渲染，加轨道自动出现，不再写死 4 个格子。

---

## 3. 目标设计：Upgrade Track 框架

### 3.1 数据表 `UPGRADE_TRACKS`

把 `GOLD_UPGRADE_DEFS` 升级为带 `bind` / `effect` 的表（建议放到 `scripts/upgrade_tracks.gd` 或 `duel_controller.gd` 顶部）：

```gdscript
const UPGRADE_TRACKS := [
  # bind="training"：通用训练（"训练假人"叙事，非实物来源）
  {"id":"power",  "icon":"🗡", "name":"训练：锋锐", "bind":"training", "effect":"power", "per_level":3,  "base":6,  "step":4, "max":6},
  # bind="reel"：卷轴掌握（原"连线精通"换皮，保留 line 构筑轴）
  {"id":"line",   "icon":"🔗", "name":"卷轴掌握",   "bind":"reel",     "effect":"line",  "per_level":1,  "base":8,  "step":6, "max":4},
  # bind="training"：防御训练（原"壁垒"换皮）
  {"id":"shield", "icon":"🛡", "name":"训练：壁垒", "bind":"training", "effect":"shield","per_level":5,  "base":5,  "step":3, "max":5},
  # bind="charm" / "weapon"：动态轨道（运行时按已装备展开，见 3.2）
]
```

字段说明：`id` 唯一键；`bind` 决定来源叙事与等级存储位置；`effect` 决定结算分支；
`per_level` 每级增量；`base/step/max` 价格曲线与上限。

### 3.2 `bind` 类型（静态 vs 动态）

| bind | 含义 | 轨道形态 | 等级存哪 |
|------|------|----------|----------|
| `training` | 训练假人（通用数值） | **静态**（始终在清单） | `track_levels[id]` |
| `reel` | 卷轴 / 符号掌握 | **静态**（始终在清单） | `track_levels[id]` |
| `charm` | 强化已装备护符 | **动态**：运行时为每个 `selected_charms` 展开一条「强化<护符名>」 | `charm_track_levels[path]` |
| `weapon` | 锻造已装备武器 | **动态**：运行时为每个 `selected_loadout` 展开一条「锻造<武器名>」 | `weapon_track_levels[path]` |

> 动态轨道的 `id` 用 `charm:<path>` / `weapon:<path>` 区分，避免同类撞键。
> 这样"升级当前拥有的护符 / 武器"自然成为框架的两种 `bind`，而非独立系统。

### 3.3 统一分发器 `_apply_track`

结算方不再直读 `gold_upgrades["xxx"]`，改为读 `track_levels` / `*_track_levels`：

```gdscript
# 替代原 _agg_power_flat 里 gold_upgrades["power"] 的用法
func _track_level(id: String) -> int:
    return track_levels.get(id, 0)

func _agg_power_flat() -> float:
    return BattleMath.agg_power_flat(run_power_bonus, charm_power_bonus, player_buffs, track_levels, "power", POWER_STEP)
```

`BattleMath.agg_power_flat` 内部把 `track_levels.get("power",0) * POWER_STEP` 累加即可，其余 `effect` 同理映射到既有钩子（连线倍率 / `charm_damage_mult` / 房间护盾）。**新增 `effect` 类型只需在聚合层加一行求和，结算零改动。**

### 3.4 商店 UI 通用化

`shop_screen.gd:148` 的 `_refresh_shop_up()` 改为：

```gdscript
for u in controller._upgrade_track_defs():   # 静态 + 动态（charm/weapon 展开）
    up_grid.add_child(hud._make_upgrade_card(u))
```

`hud._make_upgrade_card` 与 `_on_gold_upgrade_pressed(id)` 保持不变（按 `id` 通用处理）。

## 6. 关联：铁砧方向最终定案（武器 / 护符零盘外数值升级 · 铁砧 = 纯 gacha）

**最终决策（2026-08-05 用户拍板）**：武器与护符**不做任何盘外数值升级**，铁砧回归"纯获取"定位。

### 6.1 决策演变（为何走到这一步）

1. 早期 §6 设想"铁砧 = 老虎机抽装备"（取代 `charm_upgrades` 升级入口）。
2. 用户提出"武器/护符成长放盘外做强化以增加重复可玩" → 一度转向"铁砧 = 盘外强化 owned"。
3. 用户追问"抽与强化是否必须二选一" → 澄清二者正交、可共存（双 tab 方案，复用 `anvil_points`）。
4. **用户最终判断："不升级武器/护符是否可行？涉及的数值感觉太多"** → 采纳：放弃盘外单件数值升级，铁砧 = **纯 gacha（抽装备进拥有池）**，所有"强化"只留在局内商店。

### 6.2 最终架构

```
盘外（铁砧，单 tab 单币种，run 间）：
   铁砧点数 anvil_points ── 纯 gacha ──→ 随机注入 meta["owned_weapons"] / ["owned_charms"]（拥有池）

局内（每局清零，gold 驱动）：
   商店 6 训练轨道（玩家属性：锋锐/卷轴/壁垒/体魄/精准/回复）
   商店动态锻造轨道（临时强化"当前 loadout"的武器/护符，每局清零）
   build 层：装备固有强度（.tres 的 base_power/hit_rate/crit_mult/symbols[].weight）
```

- **铁砧 = 单 tab**。此前讨论的"强化 tab + 招募 tab 双 tab"方案**作废**——没有强化 tab 可开。
- **不引入第三币种**：铁砧仍只用 `anvil_points`，gacha 即唯一消费路线。
- **武器/护符的"变强"只剩两条路径**：① 抽更高稀有度/更适配 build 的新装备（盘外 content breadth）；② 局内商店动态锻造（临时）。**绝无 per-item 永久 +N creep**。

### 6.3 删掉的 meta 旋钮（待代码清理）

原 `meta` 里以下 per-item 永久养成旋钮**全部退役**：
`weapon_upgrades`（主符号权重）/ `weapon_base_bonus`（基础伤害）/ `weapon_hit_bonus`（命中率）/ `charm_upgrades`（护符乘区）/ `interference_resist`（全局抗干扰）。
→ 这些正是"数值太多"的根源（per-item × 拥有池规模 → 成百上千独立数值）。退役后 meta 层只保留 `anvil_points` + `owned_*` 拥有池。

### 6.4 前置依赖：拥有池 `owned_*`

铁砧 gacha 需要有落点。当前代码只有 `selected_loadout`（**本局临时**），无跨局拥有池。需新增：
- `meta["owned_weapons"]: Array[Resource]` — 跨局拥有的武器
- `meta["owned_charms"]: Array[Resource]` — 跨局拥有的护符
整备屏从 `owned_*` 选起始 loadout；铁砧 gacha 写入 `owned_*`；商店售卖/掉落也可写入 `owned_*`。

### 6.5 设计收益

- **架构最简**：单 tab 单币种、零 per-item 旋钮；最强贴合"加内容 = 新建 .tres"。
- **平衡最好控**：无"神装刷满"拖累早期 run，难度仅由 ante + 内容稀有度决定。
- **重复可玩不损**：gacha 抽装备（开图鉴冲动）+ 商店锻造（这局成形快感）+ build 组合深度，三件套齐全。
- **§15 HP 失衡不受影响**：生存由商店 6 轨道（体魄/回复）承担，与武器是否升级无关。

> 代价：失去"我的剑永久 +99"式 ARPG 积累感，换来"我拥有更多/更好装备、越来越适配打法"的另一种积累感（后者更耐刷）。
> 重复产出处理见 **§6.7**（已给出建议方案：软保底返还 + 保底计数器 + 收藏度，单币种闭环，待用户拍板）。

### 6.6 商店卖武器：Gungeon 对标与方案 A（推荐 · 已拍板 2026-08-05）

> 关联：用户第 26 条「商店还能购买武器吗？参考挺进地牢」。结论：商店**本就在卖武器**（既有行为），沿用 Gungeon 模型即可，无需新增系统；放弃的只是"盘外永久养成"，**不是 run 内交易**。

**事实**：`duel_controller.gd:901-915` 的 `_roll_shop` **当前已从 `WEAPON_POOL` 抽武器进商店**（商店升级页之外，有独立的「购入页」卖武器）。所谓"商店不能买武器"是误解——本文 §6 放弃的仅是"武器/护符的盘外 per-item 数值升级"，与"run 内花钱买装备"正交。

**Enter the Gungeon 对标**：
- 商店是单局内买枪的**主渠道**，枪**固定数值、无 +N creep**（枪的强弱来自种类本身，不来自养成的 +N）；
- 枪的解锁靠 Ammonomicon（收集图鉴）累积——解锁后进**全局枪池**，但**单把枪数值不变**；
- 与本文 §6 完全同构：Gungeon 的 Ammonomicon 解锁 = 本作 `owned_*` 拥有池，铁砧 gacha 抽装备即"开图鉴"。

**方案 A（推荐 · 已拍板）**：
- 商店 = **从全池售卖**（`WEAPON_POOL` / `ITEM_POOL` 全量），玩家可买到**尚未拥有**的武器/护符；
- `owned_*` 拥有池**仅影响整备屏的起始 loadout**——"已拥有"决定你能从哪堆里选开局装备，但**不限制商店卖什么**；
- **三层获取互不绑架**（总图见 `docs/装备收集规划_200.md` §12.3）：
  1. 铁砧 gacha（盘外）：抽装备 → 注入 `owned_*` 拥有池（开图鉴冲动）；
  2. 整备选起始（免费）：从 `owned_*` 选本局开局装备；
  3. 商店买 + BOSS 掉落（run 内）：全池随机获取，**与 `owned_*` 解耦**——没抽到的装备也能在 run 内买到/掉到。
- 该设计即 Gungeon 模型：拥有池管"开局可选范围"，商店/掉落管"这局实际能拿到什么"，二者正交。

**为何不引入"仅卖 owned 武器"的受限商店**：会把"抽到神装"和"本局能用神装"强绑定，背离"三层获取互不绑架"；Gungeon 经验证明全池商店手感更顺，且本作 §6 已让武器强度只由 .tres（稀有度/base_power/crit_mult）决定，全池售卖不会制造养成通胀。

### 6.7 重复产出处理（铁砧 gacha dupe 方案 · 建议，待拍板）

> 约束：零 per-item 数值升级（§6.2）。重复产出**绝不**写成 `+N` 到某件装备，只能转成「货币返还 / 保底进度 / 图鉴完成度」三类不污染装备强度的东西。

**问题本质**：铁砧 gacha 从全池抽装备写入 `owned_*`。随 `owned_*` 增长，重复概率单调上升；若重复毫无产出，则「接近满图鉴时每次拉动都是垃圾格」，抽卡爽感崩塌。又因为 §6.6 已定「商店从全池售卖（与 `owned_*` 解耦）」，**玩家在 run 内本就能拿到任何具体装备**——铁砧的 Unique 价值只剩「扩张 `owned_*` 拥有池（给整备免费开局更多选择）+ 开图鉴多巴胺」，**不是**「针对性获取某件装备」。重复补偿必须服务这个定位，而非去和商店抢「给具体装备」。

**建议方案：三层补偿（单币种，无第三货币）**

1. **软保底返还 `anvil_points`（基础不浪费）**
   - 抽到已拥有的物品 → 按稀有度返还铁砧点数：`ANVIL_DUPE_REFUND[rarity]`（建议 common 3 / uncommon 5 / rare 7 / epic 10，epic 满返一次拉动成本 `ANVIL_ROLL_COST=10`）。
   - 越稀有被重复 = 图鉴越深 = 返得越多，奖励老玩家而非惩罚。
   - 严格沿用 §6.2「不引入第三币种」：`owned_*` 之外只动 `anvil_points`，无镀层/碎片等新币种。
2. **保底计数器 `anvil_pity`（保证必然满图鉴）**
   - 维护 `meta["anvil_pity"]` = 连续「非全新」拉动次数。
   - 当 `anvil_pity >= ANVIL_PITY_MAX`（建议 10）且「尚未拥有子集非空」时，下一次拉动**强制从 not-yet-owned 子集抽取**（保证出新）。
   - 抽到全新物 → `anvil_pity` 清零。
   - 图鉴满后该计数器自动失效（已无 not-yet-owned）。这是标准 gacha 保底，直接解决「脸黑永远凑不齐整备可选范围」。
3. **收藏度 `collection_pct`（图鉴完成度 · 元进度正反馈）**
   - `collection_pct = len(owned_*) / POOL_SIZE`。
   - 在阈值（25% / 50% / 75% / 100%）解锁元进度奖励：建议「每局结束 +X 铁砧点数」（收集者分红）——图鉴越满，攒点越快，形成正向飞轮。
   - 纯 meta，不触碰任何单件装备数值，符合「膨胀放 build 层 / 零 per-item 升级」铁律。

**为什么不引入「镀层/碎片 + 定向兑换」**：§6.6 商店已全池售卖，玩家 run 内可定向买任意装备；铁砧再做「花镀层定向换某件」纯属和商店功能重叠、且需引入第二币种，违背 §6.2。故 dupe 补偿只走「返还 + 保底 + 图鉴度」三路，单币种闭环。

**与「非数值护符」子问题的关系**：因重复不再做「+1 级」，原 §4「剔除纯布尔护符」的入池护栏**动机已消失**——任何护符（含开关型）进池后，首次出=入库、重复出=返还，逻辑自洽。建议放宽 §4.2，所有护符均可入池（纯布尔护符只是「首次入库即满价值」，无害）。

**代价 / 待平衡**：`ANVIL_DUPE_REFUND` / `ANVIL_PITY_MAX` / 收藏度分红数值需平衡。⚠️ 满图鉴后每次拉动必重复→必返还，若返还 ≥ 成本则 `anvil_points` 只增不减（通胀）；缓解：满图鉴后返还下调为 0 或改为一次性「满图鉴成就」不再返点，或拉动成本随 `collection_pct` 微涨。

### 6.8 铁砧点数获取（多源模型 · 建议，待拍板）

> 现状缺口：当前 `anvil_points` 仅在 `_roll_meta_choices`（duel_controller.gd:632）的「通关三选一」里作为**兜底候选**之一出现，玩家未必选得到——gacha 没有稳定蓄水池，抽卡节奏全看脸。本节约其获取模型，与 §6.7 重复补偿、通胀护栏自洽。

**建议模型：Hades 式「每局稳定 drip + 可选兑换 + 里程碑分红」**

   - 像 Hades 每次逃脱尝试都掉 Darkness，保证 gacha 永远有细水长流。
2. **三选一主动兑换（保留现有，给 agency）**
   - 保留 `anvil_points` 作为三选一可选支（玩家用一次伤害 / HP 成长换点数）。想抽时优先点它，不想抽时换战力。
3. **收藏里程碑分红（§6.7 第三层的入口版）**
   - `collection_pct` 跨 25% / 50% / 75% / 100% 时给**一次性**大额红包（建议 +50 / +100 / +150 / +200）。奖励「集齐」行为本身。
4. **（可选）首通 / 首获奖励**
   - 每个 BOSS / 精英首杀、或首次经商店 / BOSS 拿到某件装备，给一次性点数（建议 +10 / 次）。鼓励广度探索，不与重复补偿重叠。

**⚠️ 与 §6.7 通胀护栏联动（获取侧必须收口）**

- 局末基础发放设**每局上限**（建议 `ANVIL_PER_RUN_CAP = 40`），防单局刷爆。
- 收藏分红做**里程碑一次性**（跨阈值发一次），**不要**做成「每局 +X」循环——否则高收藏 = 无限点数工厂，与 §6.7 满图鉴后「必重复→必返还」叠加爆仓。
- 目标：`基础发放 + 分红` 总速率 ≈ 略低于 `拉动消耗`，靠 dupe 返还补差，形成健康闭环（既不饿死抽卡，也不通胀）。

**代价 / 待平衡**：`ANVIL_BASE` / 各表现浮动权重 / `ANVIL_PER_RUN_CAP` / 里程碑红包数值均需平衡；首通奖励若启用需去重（同一 BOSS 只发一次，存 `meta["first_clears"]`）。

## 7. 开放项与决策状态

### 7.1 「卷轴掌握」(line) 的来源归属 —— 已拍板：选 A（2026-08-05）

> 原 open item 是"保留/删除 line"，但用户指出**真问题是 line 的来源**：它是护符提供的，还是玩家自身属性？这决定它该走哪类 `bind`。**结论：选 A（来源 = 玩家自身属性）**，与 §6.2 架构图、§7.4 六轨道表一致。

**事实**：line（连线倍率）当前是 `duel_controller.gd` 里 `gold_upgrades["line"]` 的**全局玩家属性**，结算处 `mult = raw + (gold_upgrades["line"] * LINE_STEP if raw >= 2 else 0)`——它不绑定任何具体装备，本质是"玩家对整个老虎机转轮的熟练度"，并非某件武器的特征。

**决策依据（A vs B）：**

- **A. 来源 = 玩家自身属性（✅ 已选）**：保留 static「卷轴掌握」训练轨道，`bind="reel"`，来源叙事 = 玩家对转轮/卷轴的熟练度（训练假人研习卷轴）。保留"连线数"作为玩家**独立可调乘区**，最可控，且不与"升级绑定真实系统"冲突——转轮本身就是游戏里真实存在的系统。
- **B. 来源 = 护符（未选）**：删除 static line 轨道，改由"某类符文护符固有 line 加成 + 动态护符轨道强化"提供。更彻底地消除通用 buff，但"连线数"不再是玩家独立可调轴，沦为护符 build 的一部分（想堆 line 就必须堆这类护符）。

**选 A 的理由**：line 是全局机制熟练度，天然属于玩家而非单件装备；把它做成训练轨道，既来源成立（转轮熟练度），又保留你平衡哲学里"三乘区 = 连线数 × 护符 × 克制"的独立连线轴，调参最干净。若选 B，则连线倍率被绑死在护符种类上，build 自由度反而下降。

### 7.2 动态护符 / 武器轨道 —— 已拍板：默认开启

商店升级页除 3 条 static（锋锐 / 卷轴掌握 / 壁垒）外，运行时按 `selected_loadout` / `selected_charms` 自动展开「锻造<武器名>」/「强化<护符名>」动态轨道。这正解决"割裂/无来源"痛点，且贴合"升级应绑定真实系统"的初衷。代价仅是 UI 多渲染几条动态卡片，无结算复杂度。

### 7.3 铁砧与商店的衔接 —— 已澄清：铁砧是盘外(run 间)成长，非当局可用

- 铁砧**仅在全局结束、重开新 run 时**可用；单局 21 房内不可访问。
- 衔接**唯一路径**：铁砧产出 → 拥有池 → 下一局整备装备 → 该局商店强化（见 §6）。
- 原"选项 A 下一局 / 选项 B 当局可用"二分作废，仅剩上述唯一路径。

### 7.4 「护符共鸣」(joker) 退役 + 玩家属性补全 —— 已拍板（用户同意，2026-08-05）

> 用户提议：把"护符共鸣"换成"HP 增长"，使玩家基础四属性覆盖 伤害 / 护盾 / 熟练度 / 血量；并问还缺什么属性需加入升级。

**事实**：`joker`（护符共鸣）当前是 `duel_controller.gd` 里 `gold_upgrades["joker"]` 的**玩家层全局伤害乘区**（×(1+N·step)，封顶 `JOKER_CAP_FACTOR`）。它来源混乱——既是玩家训练、又是对"护符"的呼应，与 `power`（同是伤害、加算）和 build 层护符乘区**双重重叠**。

**决策：退役 joker，替换为「体魄」(HP 增长) 轨道**

理由：
1. **来源干净**：joker 来源混乱（玩家层伤害乘区 vs 护符 build 乘区），退役后玩家伤害层只剩 `power`（加算）+ `line`（连线乘区），不重叠。
2. **四属性成完整正交集**：锋锐(伤害) / 壁垒(护盾) / 卷轴掌握(熟练度) / **体魄(血量)** = 进攻 / 防御 / 技巧 / 生命，完整不冗余。
3. **补 §15 生存缺口**：体魄给玩家确定性 HP 上限增长，对称于敌人 ante 缩放（落地路径见 `docs/装备收集规划_200.md` §15.6）。

**还缺失的属性（建议补 2 条）：**
- **精准（accuracy，命中率）** = 覆盖「可靠性」维度。当前 per-item `hit_rate` 决定废铁占比，**玩家层无任何命中成长**；符号打不打得中全交给装备随机。新增全局 +命中率轨道，主动降低废铁率——这是四属性里唯一没覆盖的战斗维度。
- **回复（regen，再生）** = 覆盖「持续性」维度。当前回血只靠 heal 符号 / 回春护符 / 随机 heal 卡；新增每房回 X% 上限轨道，直接治本 §15「跨房掉血不回」雪崩（比单纯加血上限更彻底）。

**推荐最终 6 轨道表：**

| # | 轨道 | 字段 | 每级 | 维度 | 来源 |
|---|---|---|---|---|---|
| 1 | 锋锐 | `power` | +3 伤害 | 进攻（加算） | 现有 |
| 2 | 卷轴掌握 | `line` | +1 连线倍率 | 技巧 | 现有（7.1 选 A） |
| 3 | 壁垒 | `shield` | +5 开局护盾 | 防御 | 现有 |
| 4 | **体魄** | `hp_max` | +15~20 上限 | 生命 | **替换 joker** |
| 5 | **精准** | `accuracy` | +2% 命中 | 可靠性 | **新增** |
| 6 | **回复** | `regen` | 每房 +X% 上限 | 持续性 | **新增（修 §15）** |

可选（非必需）：抗干扰（减 jam/lock/chaos 时长）、贪婪（+金币掉落）。

**架构提醒（铁律）**：joker 退役后，**玩家层不再引入任何「伤害乘区」**——保持 `power`（加算）+ `line`（连线乘区）。所有乘区留给 build 层（护符 / 克制 / crit_mult / `symbols[].weight`），符合「战斗内只许 special 连锁一处乘区、膨胀放 build 层」。
