# Seek Dead · Step 4 多对策提示与结果反馈（2026-11-11）

> 依据：`docs/战斗策略性_统一调优执行方案_2026-11-11.md` §9 Step 4  
> 前置：Step 1 数值落地、Step 3 精英/BOSS 节奏（`docs/战斗策略性_Step3_精英BOSS节奏复测_2026-11-11.md`）  
> 本轮定位：**标准模式显示局势与真实可选对策 + 结果反馈区分行为类别**；不新增机制、不改结算公式、不改难度。  
> 边界：提示只读当前带子 / 消耗品 / 机制状态，不生成带内不存在的对策；结果反馈只报本回合真实落地数值。

---

## 1. 本轮两个目标

| 目标 | 做法 |
|---|---|
| 多对策提示 | 主栏用短标签显示当前真实对策（最多 2 条 + `…`），完整清单与数值进 tooltip；不显示唯一目标 |
| 结果反馈分类 | 回合结算反馈按「防御 → 破甲 → 恢复 → 核爆 → 充能爆发 → 总伤害 → 连击/三连/克制」排序；消耗品使用后写单行结果 |

## 2. 多对策提示

### 2.1 改前的问题

480 逻辑宽度下，主栏拼的是完整标签：

```
⚖ 爆发 · 护甲 28/28 · 可应对：特殊三连 / …
```

第二条对策被省略号吞掉，玩家看到的仍是「一条对策」。战后核对截图（Step 4 第一次采集）确认：主栏只完整显示 1 条。

### 2.2 改后

`ReadabilitySystem` 的每条对策增加 `short` 短标签（完整文案仍在 `label` / `note` / tooltip）：

| 对策种类 | 短标签 |
|---|---|
| 特殊三连 | 特殊三连 |
| 穿透符号 | 穿透 |
| 破甲酸液 / 清净 / 净化 / 治疗药 / 强化 / 攻击药 / 重转 / 精华 | 酸液 / 清净 / 净化 / 治疗药 / 强化 / 攻击药 / 重转 / 精华 |
| 护盾 / 治疗 / 输出符号 | 护盾 / 治疗 / 输出 |
| 兜底项 | 承伤 / 抢攻 / 留资源 / 磨甲 |

主栏同时压缩连接词（`可应对：` → `对策：`，` / ` → `/`），480 宽下能完整显示 **2 条真实对策 + `…`**：

```
⚖ 爆发 · 护甲 28/28 · 对策：特殊三连/穿透/…
```

- 超过 2 条时主栏仍只放 2 条 + `…`，完整清单保留在 tooltip（每条带 note 与数值）。
- 对策只来自当前带子（`reel_strips`）、腰带（`consumable_slots`）与机制状态（护甲 / 冻结 / 意图）；带内没有的符号不会出现在列表里。
- 固定目标对照 `--p1-target` 仍显示 `🎯 单目标`，不受影响。

|---|---|---:|---:|---:|---:|---|---|

## 3. 结果反馈

### 3.1 改前

- 只有「护盾准备 / 恢复 / 总伤害 / 连击 / 克制」；
- 破甲（特殊三连清空护甲）与元素核爆、充能爆发都并入总伤害，玩家无法区分「这回合清了多少甲」「核爆贡献多少」；
- 消耗品使用后没有结果行，只有日志。

### 3.2 改后

`CombatSystem` 在 `_reset_turn_state()` 新增本回合分类累计，只供 HUD 文案，不参与结算：

| 累计 | 来源 |
|---|---|
| `_turn_armor_cleared` | `on_counter("special")` 清甲、`release_element_burst()` 清甲 |
| `_turn_counter_burst` | `on_counter("element")` 的克制核爆伤害 |
| `_turn_charge_burst` | `release_element_burst()` 的爆发 + 额外伤害 |

`_show_turn_feedback` 顺序改为：

```
护盾 → 破甲 → 恢复 → 核爆 → 充能爆发 → 总伤害（+收尾窗口） → 连击 → 三连 → 克制/抵抗
```

480 宽时先裁掉尾部细节（连击/三连/克制），保证「发生了什么」在前：

```
破甲-53 / 核爆-125 / 充能爆发-195 / -303 / 火斩×3 / …
```

- 数值全部来自真实结算：清甲量 = 实际清零的护甲；核爆/充能爆发 = 实际打出的伤害；总伤害为 `acc` 累计。
- 调用点移到 `apply_enemy_hp_floor()` 之后，反馈包含充能爆发的完整回合。

### 3.3 消耗品单行反馈

| 消耗品 | 反馈 |
|---|---|
| 净化药剂 | `净化：抵消重击` / `净化：无目标` |
| 清净药剂 | `清净：寒霜`、`清净：寒霜、酸蚀` / `清净：无状态` |
| 治疗药剂 | `恢复+N`（只报实际入账） / `恢复：已满` |
| 强化药剂 | `强化×N` |
| 重转 | `重转×N` |
| 元素精华 | `元素注入：火` |
| 攻击药剂 | `伤害-N` / `伤害：0` |
| 破甲酸液 | `破甲-N`（只报实际清除） / `破甲：无护甲` |

与回合结算反馈共用同一行，下一次结算自然覆盖；纯展示，不参与结算。

## 4. 测试

`tests/g7d_decision_test.gd` 新增 ⑧ Step 4 检查组（含既有出口）：

- 分类反馈顺序：`破甲-53` 在 `格挡`/总伤害之前，`核爆-79`、`充能爆发-84` 均出现；
- 消耗品反馈与真实数值一致：`破甲-12`、`清净：寒霜`、`净化：抵消注废`、`恢复+3`；
- 标准模式不显示 `🎯`；`对策` 结构；主栏裁切与省略号；

## 5. 出口判断

| 出口 | 结果 |
|---|---|
| 标准模式显示局势与当前真实可选对策 | ✅ 主栏「局势 + 对策：A/B/…」，≥2 条真实对策；完整清单在 tooltip |
| 不指定唯一答案 | ✅ 无 `🎯`、无「必选」文案；固定目标对照才显示单目标 |
| 提示与带子/消耗品/机制一致 | ✅ 对策由 `reel_strips` / `consumable_slots` / 机制状态生成；g7d 覆盖空带、空腰带 |
| 不生成虚假对策 | ✅ 无对应符号或消耗品时不会出现该条；兜底项（承伤/留资源）明确标注代价 |
| 结果反馈区分防御/净化/破甲/恢复/爆发 | ✅ 护盾、破甲、恢复、核爆、充能爆发、总伤害分段显示；消耗品单行反馈 |
| 480×270 / 960×540 / 1440×810 不遮挡操作 | ✅ 三档提示与反馈均在视口内、不与 SPIN 相交；文本宽 248 ≤ 259 |
| 玩家不会因提示无脑操作 | ✅ 每段至少 2 条对策 + 兜底；反馈报真实数值，不承诺未发生的效果 |

**结论**：Step 4 出口成立。
