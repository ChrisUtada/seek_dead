# Seek Dead · 美术制作与 AI 量产最佳实践方案

> 状态：执行建议，作为《统一落地执行计划》M0/M3/M4/M6 的美术专项参考  
> 制定日期：2026-10-29  
> 视觉方向：暗紫褐底、暖白线框、灰白玩家、红色敌人、少色图标、强剪影  
> 核心决策：武器以物品图标为主，不走全量小人化；UI 模板化、敌人剪影化、BOSS 精修化、动画程序化、AI 候选化

---

## 1. 总体结论

要在当前参考风格下达到最佳效果，推荐采用：

> **人工制定规范 + AI 生成候选 + 自动像素化 + 少量人工修像素 + 实机画面验收**

不建议采用“AI 一键出图后直接入库”。这种方式虽然能快速增加数量，但很难稳定控制：

- 角色轮廓与像素密度
- 同批资源的色板和描边
- 16×16 小图标可读性
- 同角色跨动作比例
- BOSS 与普通敌人的体量关系
- 素材与实际战斗 UI 的协调程度

不会画画并不妨碍完成最后修整。需要做的主要是选择候选、擦除孤立噪点、合并色块、检查锚点和比较剪影，而不是重新手绘整张资源。

如果坚持完全不进行人工像素清理，则必须增加候选数量、严格自动验收并接受更高返生成率；其质量上限通常低于“AI 候选 + 少量人工修整”。

## 2. 美术分工原则

| 资源类型 | 推荐制作方式 | 不采用的方式 |
|---|---|---|
| UI 边框、按钮、面板 | 统一组件模板、StyleBox、九宫格与少量角饰 | 每张 UI 单独让 AI 生成 |
| 武器、护符、消耗品 | AI 候选 → 剪影筛选 → 量化 → 像素清理 | 厚涂高分辨率图直接缩小入库 |
| 转轮、状态、元素图标 | 按图标族生成，并独立简化到 16×16 | 将 48×48 主图直接缩成 16×16 |
| 普通敌人 | 轮廓族先行，红色少色主体，附件形成变体 | 只给同一张图随机换色 |
| 精英敌人 | 同族基础上增加轮廓附件、底座或武器 | 只放大、提高亮度或增加噪点 |
| BOSS | 独立描述卡、多轮候选、重点精修 | 与普通敌人使用同一套低审美术流水线 |
| 玩家 | 先定 Golden Master，再制作有限动作 | 每个动作重新生成一个新角色 |
| 动画与特效 | 静态关键帧 + 位移、闪白、碎片、飘字 | 所有角色都生成完整动作集 |

关键原则：

1. **UI 不靠 AI 量产**：AI 不适合稳定生成尺寸精确、状态统一的交互组件。
2. **AI 负责物体和角色候选**：人负责风格筛选与最终验收。
3. **形状优先于细节**：在平涂少色风格中，正确的大轮廓比丰富纹理更重要。
4. **实机效果优先于单图效果**：单独漂亮但放进战斗画面不协调，仍属不合格。

## 3. 视觉规范与 Golden Master

### 3.1 首批黄金样板

量产前先完成以下最小组合：

- 1 个灰白玩家
- 1 把剑的 48×48 武器图标
- 对应的 16×16 转轮符号
- 1 个普通敌人
- 1 个 ACT1 BOSS
- 1 组按钮、卡片和侧栏边框

不要分别验收孤立 PNG，必须将它们放进同一张战斗画面。

### 3.2 黄金样板需要锁定的事项

- 角色在画布内的实际占比
- 是否使用 1px 暗色描边
- 暗部使用深紫褐还是接近纯黑
- 红色敌人的亮部、主体和暗部层次
- 武器图标的视觉重量与留白
- BOSS 与玩家的实际大小关系
- UI 线框与角色的视觉主次
- 转轮图标与角标、元素色的叠放关系

黄金样板通过后，才能形成项目自己的参考包。

### 3.3 项目参考包

后续生成应提供：

- 已批准的玩家参考图
- 已批准的武器图标
- 已批准的普通敌人
- 已批准的 BOSS
- 项目调色板
- 对应资产的轮廓描述卡

第三方截图只用于研究配色、构图和信息层级，不直接作为项目训练数据集，也不复制具体角色、图标和边框设计。

## 4. 资源制作细则

### 4.1 UI 组件

推荐直接制定可复用规则：

- 方角、1px 普通线框、2px 重点框
- 暖白主线框、较暗次级线框
- 4px 基础间距，紧凑处 2px
- 统一的普通、悬停、按下、禁用和选中状态
- 一级框架才使用少量铆钉或角饰
- 主 HUD 保留转轮与战斗信息的视觉优先级

UI 组件应由 Theme、StyleBox、组件场景和少量原创九宫格组成，不需要为每个页面生成独立 AI 背景图。

### 4.2 武器与物品图标

推荐流程：

1. 用一句话定义物体身份。
2. 指定一个主要轮廓和一个身份部件。
3. AI 生成 3–4 个候选。
4. 选择形状最清楚而非细节最多的候选。
5. 去背景、量化、归一画布。
6. 清理小色块和孤立噪点。
7. 在实际卡片、商店和奖励界面验收。

武器图标只保留：

- 武器主体轮廓
- 一个识别部件，如特殊护手、斧刃、弓臂或杖头
- 一个元素身份色
- 必要的暗部

不要加入复杂场景、文字、光晕和无法在小尺寸下辨认的装饰。

### 4.3 转轮与状态图标

16×16 图标必须独立简化，不从 48×48 主图直接缩小。

以火焰剑为例：

- 48×48 主图可保留剑柄、护手和火焰。
- 16×16 图标只保留剑形与一团身份火焰。
- 细小护手、纹理和高光全部舍弃。

同组图标需要统一：

- 视觉重量
- 透视方向
- 描边规则
- 主体占比
- 元素色面积

不能仅通过给同一个轮廓换六种颜色来制造元素图标。

### 4.4 普通敌人与精英

先建立轮廓族，再生成具体变体：

| 轮廓族 | 主要识别特征 |
|---|---|
| 人形 | 头、躯干、武器方向明确 |
| 兽形 | 低重心、四肢、头部突出 |
| 构装体 | 方形、厚重、关节和装甲明确 |
| 灵体 | 悬浮、下缘缺失、轮廓不规则 |
| 巨兽 | 宽体量、明显前伸部位、强横向剪影 |

精英可以通过以下方式形成升级感：

- 角、冠、背部结构
- 装甲或外骨骼
- 更大的武器轮廓
- 独特底座或悬浮环

不建议仅通过放大、换色或增加全身纹理区分精英。

### 4.5 BOSS

每个 BOSS 在生成前先写三项内容：

1. **一句话轮廓**：例如“封口巨瓮，两侧有冻住的锁链”。
2. **一个标志性部件**：罐口、独眼、天平、巨翼等。
3. **一个机制姿态**：闭合防御、展开攻击、俯视玩家等。

验收要求：

- 看剪影能大致猜测机制方向
- 与普通敌人同屏有明显体量差
- 红色主体下仍能读出内部大结构
- 阶段变化可通过附件、姿态和局部特效表达
- 不挤压转轮、SPIN 和右侧意图

13 个 BOSS 值得逐个精修；普通敌人和物品才适合高度模板化。

## 5. AI 生成方法

### 5.1 输入描述卡

每个资产在生成前准备：

- 一句身份：它是什么
- 一句轮廓：最远处也能识别的 1–2 个特征
- 分类与元素：决定色系与图标语义
- 目标画布、朝向、锚点和色数
- 项目自有参考图
- 负面约束：无抗锯齿、无渐变、无厚涂、无噪点、无背景、无文字、无多余肢体

### 5.2 候选筛选顺序

每次生成 3–4 个候选，按以下顺序筛选：

1. 纯黑剪影是否可辨
2. 是否适合目标尺寸
3. 结构是否简单，能否清理成少色块
4. 是否符合当前像素密度
5. 是否存在无意义零件、碎光与纹理
6. 是否与同批资源视觉重量一致

优先选择“形状正确”的候选，而不是第一眼细节最丰富的候选。

### 5.3 避免高分辨率厚涂直接缩像素

高分辨率精美立绘直接缩到 48×48，常见问题包括：

- 半透明边缘和大量过渡色
- 无意义颜色噪点
- 轮廓断裂
- 小零件变成不可辨认色块
- 与原生像素资源的视觉密度不一致

应在生成阶段就要求：

- 平涂色块
- 无抗锯齿
- 无渐变
- 少颜色
- 粗轮廓
- 大形状、少细节
- 透明或纯色易分离背景

然后再执行透明化、整数归一、调色板量化和清理。

## 6. 动画与特效方案

### 6.1 默认采用程序化演出

| 行为 | 推荐表现 |
|---|---|
| 待机 | 静态图 + 1px 上下浮动，或少量呼吸帧 |
| 攻击 | 位移 + 1–2 张关键姿态 + 命中特效 |
| 受击 | 暖白闪或明暗反相 + 轻微后退 |
| 死亡 | 轮廓碎裂、溶解或色块消散 |
| BOSS 阶段 | 附件切换、底座变化、局部特效与意图图标 |

只有玩家和极少数重点角色制作完整帧动画。敌人与 BOSS 优先静态图加程序化演出。

### 6.2 玩家动画规则

- 先批准 idle 站立帧，再生成其他动作。
- 后续动作必须附带已批准的 idle 参考图。
- 同角色动作使用同一会话或种子族。
- 检查身体宽高、脚底、朝向和武器长度。
- 站立帧身体比例偏差超过 ±8% 时退回生成端。
- 不用非整数缩放或涂抹掩盖动作结构失败。
- 攻击动画继续受现有 0.35 秒战斗窗口约束。

### 6.3 受击与颜色

红色敌人不能继续只使用红色受击闪。推荐：

- 暖白闪
- 明暗反相
- 短暂轮廓加亮
- 少量位移或震动

受击反馈必须短促，避免大面积白屏和持续粒子遮挡转轮。

## 7. 工具组合建议

### 7.1 生成端

候选后端可包括：

- Retro Diffusion：用于测试像素角色、图标与动画候选
- PixelLab：用于测试静态像素图标和角色
- 本地 ComfyUI：适合已有合适显卡、希望长期控制模型与参考图的情况
- 其他可稳定联网的像素生成 MCP 或服务

不根据宣传选择工具，应使用同一组描述卡进行盲评。

### 7.2 后端对比测试

使用同一组输入：

- 4 个武器图标
- 4 个普通敌人
- 4 个 BOSS

每个后端每个主题保留 2–3 个候选，使用相同后处理并制作 contact sheet。

评分维度：

| 维度 | 需要回答的问题 |
|---|---|
| 剪影成功率 | 多少候选无需重画就有清楚大轮廓 |
| 小尺寸可用率 | 多少候选能清理成目标尺寸 |
| 色彩稳定性 | 是否容易量化到项目色板 |
| 参考图一致性 | 能否保持同一角色比例和像素密度 |
| 透明背景 | 去背景是否干净 |
| 动画能力 | 同角色动作是否保持同一人物 |
| 返修率 | 每张合格图平均需要多少次重生成 |
| 成本与耗时 | 每张合格图而非每张直出图的实际成本 |

最终选择一个主后端和一个备用后端。

### 7.3 修整端

- Aseprite：像素清理、动画播放和接触表检查
- 免费替代：Pixelorama、LibreSprite、Piskel
- 后处理：Python/Pillow 负责透明化、量化、尺寸、锚点与 contact sheet

不会画画时，修整端主要用于选择、擦除和比较，不要求完整手绘。

## 8. 后处理与验收

### 8.1 静态资产生产链

```text
描述卡
→ AI 生成候选
→ 纯黑剪影筛选
→ 去背景与透明化
→ 整数归一到目标画布
→ 项目色板量化
→ 自动规格检查
→ 少量人工像素清理
→ 同批 contact sheet 验收
→ Godot 实机画面验收
→ 入库与资源绑定
```

原始 AI 图、候选图和最终入库图分开保存，原始大文件不混入游戏资源目录。

### 8.2 自动检查

每张资源至少检查：

- 尺寸、RGBA 和透明背景
- 文件命名与目录
- 色数和调色板外颜色
- 非预期半透明边缘
- 包围盒、锚点和脚底对齐
- 帧间中心与脚底偏移
- 图标是否由正确源规格制作

### 8.3 人工目视验收

- 实际大小下可辨，不只在 5×放大图中好看
- 纯黑剪影仍能识别
- 无孤立噪点和无意义碎色块
- 同批描边、比例和视觉重量一致
- 图标不被匹配角标、边框和元素色淹没
- BOSS 与普通敌人有明确体量差
- 在 480×270 实机截图中整体协调

### 8.4 实机分辨率

- 480×270：无裁切、重叠、非预期滚动和文字溢出
- 960×540、1440×810、1920×1080：整数放大清晰
- 1280×720：至少布局可用，无遮挡
- 转轮运动、匹配角标和受击演出同时出现时仍可读

## 9. 美术资源投入优先级

推荐按以下顺序分配精修精力：

1. **玩家与 BOSS**：决定第一印象和战斗记忆点。
2. **战斗 UI 与转轮图标**：决定每分钟的可读性。
3. **武器图标**：决定收集欲、换装和成长反馈。
4. **普通与精英敌人**：模板化生产，保证轮廓差异。
5. **护符、消耗品和次要图标**：最后批量补齐。

不建议平均分配时间，也不建议先完成 90 把武器，再发现战斗 UI 与 BOSS 风格不成立。

- 完成资产映射和描述卡。

- 每幕制作 contact sheet 检查风格漂移。
- 所有正式内容完成实机验收。

## 11. 明确避免的做法

- AI 直出图不经检查直接入库
- 只靠 prompt 中的“保持风格一致”维持统一
- 高分辨率厚涂直接缩成小像素图
- 48×48 图标直接缩成 16×16 转轮符号
- 为全部武器制作小人和完整动画
- 给低质量轮廓简单套红色滤镜
- 普通敌人只靠换色制造差异
- BOSS 只靠放大和增加纹理制造压迫感
- 每个面板使用不同 AI 边框
- 在样板验收前批量生成几十或几百张资源
- 只验收单张素材，不验收实际战斗画面

## 12. 最终执行建议

采用以下六条即可形成稳定生产体系：

> **UI 模板化、武器图标化、敌人剪影化、BOSS 精修化、动画程序化、AI 候选化。**

首批只制作一个完整战斗黄金样板。样板通过后，将已批准资源作为项目自己的参考包，再开始 ACT1 批量生产。

每次生成先追求形状正确，再追求颜色统一，最后才增加少量身份细节。所有资源最终都必须以实际游戏画面，而非 AI 展示图，作为验收标准。
