## 1. 现状盘点（全部基于真实代码，非推测）

### 1.1 ❌ 已废弃：旧 `forging.gd` / `forge_material.gd`
```
# scripts/equipment/forging.gd
class_name Forging
extends RefCounted
# 锻造系统已废弃（2026-07-01）
# 替换方案：装备自然掉落 + 房间附魔台有限修正

# scripts/resources/forge_material.gd
class_name ForgeMaterial
extends RefCounted
# 锻造材料系统已废弃（2026-07-01），与锻造系统一并移除
```
**结论：不要复用这俩文件**。它们已被设计上废弃，正式阶段的"锻造"是 M5 铁砧原型，不是它们。

### 1.2 ✅ 可复用：M5 铁砧原型（元进度核心）
位置：`prototypes/reel_combat/reel_combat.gd`
状态数据（原型的 `meta` 字典）：
```gdscript
var meta: Dictionary = {"anvil_points": 0, "weapon_upgrades": {}, "interference_resist": 0}
# weapon_upgrades: weapon_path -> int  （该武器主符号额外权重，转轮升级）
# interference_resist: int             （抗干扰等级，降低敌人干扰概率）
```
- **货币发放** `_award_meta(is_boss)`：普通房 +8、Boss +25，发完即持久化。
- **锻造项 A — 武器转轮升级** `_on_anvil_weapon_pressed(path)`：
  - 成本 `cost = (lvl+1) * 10` 铁砧点数；`weapon_upgrades[path] = lvl+1`
  - 应用：在 `_build_pool()` 给该武器**权重最高的符号**额外 +`bonus` 权重
- **锻造项 B — 抗干扰** `_on_anvil_resist_pressed()`：
  - 成本 `cost = (rl+1) * 15`；`interference_resist = rl+1`
  - 应用：在 `_start_room()` 叠加护符抗扰，`rf = max(0.25, 1.0 - total_resist*0.12)`（每级 -12%，下限保留 25% 干扰）
- **UI**：`_build_anvil_screen()` 全代码构建（Grid 卡片 + 点数标签 + 返回），已验证布局收缩可行。

> ⚠️ 原型用自己的 JSON：`user://reel_combat_save.json`（与正式 `save_system.gd` 接口一致但**未接**）。正式化时必须迁移到 `save_system`。

### 1.3 ✅ 可复用：WeaponData.reel_symbols + 8 把武器 .tres
`WeaponData` 已含老虎机专用字段（主工程，非原型）：
```gdscript
@export var reel_symbols: Dictionary = {}   # key=符号id(0-8), value=权重
@export var special_symbol: int = -1        # 该武器特殊符号 id
```
8 把武器 .tres 已配符号池，例如：
- `iron_sword.tres`：`reel_symbols = {0:6.0, 5:3.0, 6:1.0, 8:2.0}`，`special_symbol=0`
- `pistol.tres`：`reel_symbols = {1:7.0, 8:3.0}`，`special_symbol=1`

**这就是"武器锻造"的改造对象**：升 `reel_symbols` 权重 / 改 `special_symbol` / 解锁新符号 id，全部作用于这个字典，零侵入。

### 1.4 ✅ 可复用：reel_symbol.gd（符号单一事实来源）
`scripts/battle/reel_symbol.gd`（原型与正式共用）：
- `enum Id { SLASH, SHOT, BURN, FROST, POISON, BLOCK, HEAL, SPECIAL, TRASH }`
- `CATALOG` 含每个符号的 `label/name/kind/base/color/status`
- 铁砧"解锁新符号"也直接查这里，无需新定义。

### 1.5 ✅ 可复用但未接：save_system.gd（autoload）
`autoload/save_system.gd` 已实现并注册到 `project.godot`：
- `save_game/load_game` → `user://save_data.json`
- `save_lobby_data/load_lobby_data` → `user://lobby_data.json`（带 0.5s 防抖批量落盘）
- 房间附魔台已用 `lobby_data` 存金币。

**铁砧元进度应并入这里**（在 `lobby_data` 加一个 `anvil_meta` 键），替换原型自带的 JSON。

### 1.6 ✅ 可复用：enchantment_table.gd（局内附魔台 → 词缀重铸底座）
`scripts/rooms/enchantment_table.gd`：房间清空后靠近弹面板，现有「重铸(300金) 重随一件装备词缀数值」按钮（`_reroll_item` 按稀有度重 roll 词缀 `level`）。这正是上一轮讨论的"**词缀替换**"的局内入口底座——只需加 B 模式（选装备+选槽+三选一换成老虎机原生词缀）。

### 1.7 ❌ 不存在：角色等级 / 经验 / XP
全工程搜索 `level|xp|exp|experience` 结果：
- `skill_base.gd: @export var level` — 技能等级（技能系统）
- `affix.gd: @export var level` — 词缀等级（附魔重 roll 用）
- `equipment_base.gd: @export var level` — 装备等级

**没有任何 `player_xp` / `player_level` / 经验曲线 / 升级奖励**。`PlayerConfig` 字段只有：
```gdscript
max_hp, max_energy, max_stamina, walk_speed, body_color, eye_color,
starting_weapon_main, starting_weapon_offhand
```
`player_controller.gd` 仅读 `config` 初始化 HP/能量/体力，**无等级概念**。`combat_stats.gd` 是实时战斗的按伤害类型加成/减免（类型安全替换旧 Dictionary），与老虎机符号体系是两套，基本不互通。

## 2. 武器锻造/升级 — 正式化方案

### 2.1 核心动作：把 M5 铁砧从原型迁到主工程
不要重写，直接搬逻辑：`meta` 模型 + `_award_meta` 发放 + `_build_anvil_screen` UI + 两个应用钩子（`_build_pool` 加权重、`_start_room` 降干扰）。差异点：
- 存档从 `user://reel_combat_save.json` → `SaveSystem.lobby_data["anvil_meta"]`（复用防抖落盘）。
- 入口：大厅/铁砧场景（局外）+ 房间附魔台（局内，复用 `enchantment_table.gd` 的靠近弹面板）。
- 货币来源：房间通关发点（原型逻辑），或掉落"残余物"（策划案 §4.3 击败 Boss 掉高品质符号/转轮蓝图）。

### 2.2 扩展方向（当前只升主符号权重，建议补）
M5 只做了"主符号 +权重"。正式阶段可扩展为真正的"锻造深度"：
| 锻造项 | 作用字段 | 说明 |
|---|---|---|
| 主符号权重+ | `WeaponData.reel_symbols[dom]` | 已有（M5） |
| 特殊触发率+ | 新字段 `special_rate_mul` | SPECIAL(💥) 触发阈值/概率提升 |
| 副符号权重+ | `reel_symbols[副符号]` | 让非主符号也变强，丰富策略 |
| 废铁率- | 新字段 `trash_down` | 降低 🗑️ 出现（直接改 `_build_pool` 权重分配） |
| 解锁新符号 | 扩 `reel_symbols` 注入新 id | 用铁砧点解锁策划案说的"解锁词条" |

这些全是在 `WeaponData` 字典/字段上做文章，与战斗代码只在 `_build_pool`/`_evaluate` 两处相交，**改造成本低、风险小**。

### 2.3 与"词缀替换"协同
铁砧页可同时提供「词缀替换」（上一轮讨论的 B 模式），复用 `affix_database.gd` + 新 `ReelAffixDatabase` 作替换池，改 `EquipmentBase.affixes` 数组——下一局 `ReelAffixResolver` 自动生效，不用动对决代码。

### 2.4 存档落地建议
```gdscript
# SaveSystem.lobby_data 结构（扩展）
{
  "gold": 0,
  "anvil_meta": { "anvil_points": 0, "weapon_upgrades": {}, "interference_resist": 0 }
}
```
原型 `_load_meta/_save_meta` 直接换成 `SaveSystem.load_lobby_data()/save_lobby_data()` + `flush_lobby_data()`（关键节点立即落盘）。

## 3. 角色等级 — 是否需要？

### 3.1 现状：没有，且从未设计（见 §1.7）
策划案与所有既有系统都是"**无固定职业 + 自由带入物品**"（见项目记忆），玩家没有角色等级概念。

### 3.2 三条进度轴冲突分析
如果把"角色等级"加进来，会和现有两个进度轴打架：
| 轴 | 来源 | 承担什么 |
|---|---|---|
| 局内 | 对决 HP（跨房保留、每局重置） | 单局生存力 |
| 元进度 | 铁砧（武器升级/抗扰/解锁） | 跨局变强 |
| **（拟）角色等级** | XP→等级→属性点 | ？ |

"角色等级"能给的（HP+ / 伤害+ / 解锁技能）**几乎都被前两轴覆盖**：HP 由局内承担、伤害/解锁由铁砧承担。再加一条轴只会稀释"老虎机即武器"的聚焦，并和"自由构筑"理念冲突（等级往往绑定固定成长曲线）。

### 3.3 建议：v1 不做角色等级
- "跨局变强"的需求已由**铁砧元进度**满足（武器升级 + 抗扰 + 解锁符号/武器）。
- "局内成长"已由**跨房 HP 保留 + 房奖励三选一**满足（M4 已落地）。
- 若想给玩家"长期目标感"，优先做：**铁砧解锁新武器/新符号/新护符**（内容解锁式成长，比数值等级更契合老虎机主题），而非 XP 等级。

### 3.4 若坚持要角色等级：最小方案
只在"确实想要 RPG 养成感"时做，且**只做薄薄一层**：
- `PlayerConfig` 加 `level: int = 1`、`xp: int = 0`、`xp_to_next: int`（按关卡曲线）。
- 升级奖励只给**中性的、不破坏老虎机平衡**的东西：每级 +1 铁砧点上限 / +1 本局起始净化次数 / 解锁一个槽位上限（而非直接 +伤害%）。
- 承接点：`_award_meta` 同源，在房间通关时给 XP；升级时回调 `PlayerConfig` 持久化（`save_system`）。
- 注意：这会变成第三条轴，务必控制其数值权重，避免盖过铁砧。

## 5. 建议落地顺序（修订里程碑）
1. **原型真机 smoke test**（堵住"从未跑过 Godot"的最大风险）
2. **建 `DuelController` + 对决 Scene**，迁入 M0–M6 核心逻辑，复用数据层
3. **铁砧正式化（M5b）**：迁 `meta`/发放/UI → 接 `save_system`；扩展特殊率/副符号/解锁（§2.2）
4. **词缀替换（M6b）**：`enchantment_table` 加 B 模式 + 原生词缀池 + `ReelAffixResolver` 接入
5. **M7 打磨**：SpriteLiveliness 动画、连线特效、数值平衡
6. **角色等级**：默认跳过；如坚持，按 §3.4 薄做（建议作为独立后续，不阻塞主线）
