## 1. 本次做了什么

### 1.1 棋盘移动

```text
棋盘待机
→ 点击「🎲 前进」
→ 1D3（全局 RNG，种子可复现）
→ 高亮所有合法落点
→ 只有一个合法落点时自动前进；分支由玩家点击选择
→ 棋子纯视觉移动（0.09s/格，上限 0.4s）
→ 落点效果只执行一次
→ 回棋盘待机 / 进入战斗 / 打开商店 / 休整 / 拾取
```

- 只允许向 BOSS 方向移动；超过 BOSS 停在 BOSS，不做回头或绕圈。
- 进入节点即标记消耗；重复点击、重复 `advance_to` 都不会二次结算。
- 移动动画不消耗 RNG；只有掷骰使用全局 RNG。
- 已消耗节点变暗且禁用；当前节点金色边框 + 棋子；合法落点暖白边框。

### 1.2 固定拓扑（§7.1）

```text
起点 → 普通 → 武器 → 普通 → 分支 A：商店
                         分支 B：休整
     → 普通 → 精英 → 护符 → 普通 → 精英 → BOSS
```

| 节点 | 类型 | 深度 | 说明 |
|---|---|---:|---|
| n0 | 起点 | 0 | 无结算，已消耗 |
| n1 | 普通战斗 | 1 | RoomData + 战后成长 |
| n2 | 武器 | 2 | 提前可见的具体武器，落地直接入槽 / 满槽替换 |
| n3 | 普通战斗 | 3 | 分支前战斗 |
| n4 | 商店 | 4 | 复用现有货架 / 价格 / 刷新 |
| n5 | 休整 | 4 | 恢复 25% 最大 HP |
| n6 | 普通战斗 | 5 | 分支汇合 |
| n7 | 精英战斗 | 6 | 战后成长 + 既有精英掉落 |
| n8 | 护符 | 7 | 提前可见的具体护符，落地入槽 / 满槽折算 |
| n9 | 普通战斗 | 8 | — |
| n10 | 精英战斗 | 9 | — |
| n11 | BOSS | 10 | 专属战利品；ACT1 最终战 |

- 12 节点、7 场战斗（4 普通 + 2 精英 + 1 BOSS）；实际经过 4–10 步（依赖骰子与分支）。
- 具体房间从 ACT1 合法池抽取；BOSS 沿用 `pick_boss` 权重；武器 / 护符走既有获取权重。
- 护符池排除 BOSS 信物；武器只在未装备池中抽。

### 1.3 难度映射

- 非 BOSS 战斗按路径顺序分配 `ria = 0..5`；BOSS 固定 `ria = 7`（与线性 ACT1 8 房一致）。
- `RunSetup.ante_scale(r, idx, ria_override)` 新增显式 ria 参数；线性路径传 `-1`，仍按 ROOMS 扫描，零行为变化。
- 棋盘跳过部分战斗时，难度不随「实际战斗数」下降——Boss 始终按满爬升计算。

### 1.4 节点接入

| 节点 | 行为 | 返回 |
|---|---|---|
| 普通 / 精英 | `start_room_data(node.room, battle_index, ria, final=false)` → 现有战斗 | 胜利 → 战后成长 → 回棋盘 |
| BOSS | 同上，`final=true` | 胜利 → BOSS 专属战利品 → 元进度三选一 |
| 商店 | 复用现有商店（货架 / 刷新 / 价格） | 离开 → 回棋盘，节点已消耗 |
| 休整 | `ceil(maxHP × 25%)`，不超过上限；满血提示「无需休整」 | 立即回棋盘 |
| 武器 | 落地直接获得预确定武器；双武器满 → 现有替换预览；取消 = 跳过（节点已消耗） | 回棋盘 |
| 护符 | 落地入槽；未到硬天花板可开槽；满 3 折算金币 | 回棋盘 |

- 非战斗节点不额外发放金币 / 熟练 / 历练（武器 / 护符格是节点本身的奖励）。
- 战斗胜利后 `game_state` 收回 `PLAYING`，避免棋盘待机重复触发胜利结算。

### 1.5 线性入口保留

- `board_config.enabled = false`（默认）→ 完全不生成棋盘，`ROOMS` 仍为 24 + 真·最终，15 套既有回归零变化。
- 棋盘模式开启条件：
  1. 整备底栏点「🗺 棋盘」按钮（显示「🗺 棋盘✓」即开启；确认开战后生效，不写存档）；
  2. `resources/config/board_config.tres` 的 `enabled = true`；
  3. 启动参数 `--board`（不改资源即可试玩）；
  4. 测试内显式 `duel.board_config.enabled = true`。
- 线性模式仍可随时用 `full_reset()` / `_confirm_loadout()` 进入，保留测试入口。

### 2.1 与「线性依赖盘点」的差异

盘点文档建议把 13 个 gimmick、奖励、铁砧、HUD 全部改读 `current_room`。本阶段采用**桥接方案**：

- 棋盘模式下 `ROOMS` = 本局 7 个战斗房（按路径顺序），`room_index` = 该战斗房在 `ROOMS` 中的下标；
- 因此既有 `ROOMS[room_index]` 消费者（gimmick / 奖励 / 铁砧 / HUD）保持有效；
- 新的 `current_room / current_act / current_room_ria / run_final` 是棋盘入口的显式状态源，不再用 `ROOMS.size()` 表达棋盘总进度。

这样避免了 25 个文件的机械替换与行为风险。若后续接多幕棋盘或需要「当前节点不是战斗房」的消费者，再把消费方逐个迁到 `current_room`。

## 4. 设计取舍与已知限制

1. **M2 只做 ACT1 棋盘。** 多幕、随机拓扑、事件池、宝箱、隐藏房均未做（§7.2）。
2. **武器 / 护符格是 M2 基础授予。** 提前展示、替换 / 折算、熟练追赶、共鸣预览、图鉴来源记录属于 M3；当前替换复用既有弹层，取消会跳过该节点。
3. **商店格复用展台式 HUD 商店。** 打开时临时显示战斗 HUD 作为背板；离开后回棋盘。M2 灰盒可接受，后续若需要独立商店视图再抽。
4. **BOSS 固定 `ria = 7`。** 棋盘可能只打 2–6 场战斗就抵达 BOSS，Boss 难度仍按线性满爬升计算。这是有意的「难度不因跳关而下降」，但会让快速路线更硬；需 P0 复测确认。
5. **「实际经过 7–8 个节点」是平均值。** 高点数可 4 步到 BOSS，低点数约 10 步；测试只断言 4–12 节点与 ≤12 步抵达。
6. **棋盘待机是 `PLAYING` 状态。** 战斗胜利后 `return_to_board()` 收回 `WON`，否则重复掷骰会重复结算。
7. **无中途存档。** 棋盘运行状态不写入永久存档（§10.3）。
8. **移动动画不消耗 RNG。** 只有掷骰 / 生成 / 既有战斗与奖励使用全局 RNG。
9. **主视图为代码构建，无独立 `.tscn`。** 节点位置集中在 `POS` 常量，便于灰盒阶段快速调整；验收后再决定是否抽场景资源。
