## 1. 新增三个文件

| 文件 | 职责 | 边界 |
|---|---|---|
| `scripts/battle/pattern_matcher.gd` | 纯判定：输入最终三格 → 输出命中的牌型 | 不写战斗状态、不改 grid、不碰 RNG |
| `scripts/battle/pattern_data.gd` | 牌谱资源定义（`PatternData`） | 只存数据与解锁判定，不写数值逻辑 |
| `scripts/battle/pattern_system.gd` | 解锁集、优先级解析、补牌候选 | 不结算，只回答「本回合哪条生效」 |

## 2. 统一输入

```gdscript
cards = [{ sym: SymbolData, element: String, source: String, valid: bool }, ...]
```

`PatternMatcher.cards_from_grid(ctrl)` 从 `grid / grid_elem / grid_src / frozen_cols` 直接构造，
保证战斗与测试用同一份口径。

输出：

```gdscript
{ ok, reason, valid_count,
  triple_kind: "source" | "family" | "",
  patterns: [{id: "G01"}, {id: "G02"}, {id: "G03"}] }
```

`triple_kind` 与现有结算一一对应，这是 Step 1 验收（「同一输入结果一致」）的抓手：

| 现有 `combat_system` | 本类 |
|---|---|
| `raw >= 3`（同源）用武器专精倍率 | `triple_kind = "source"` |
| `combo_raw >= 3`（同族）固定 ×1.5 | `triple_kind = "family"` |
| `elem_total >= 3`（元素共鸣） | `patterns` 含 `G03` |

## 3. 一致性验证（第 60 套 D 组）

同一手牌分别跑现有结算与 Matcher，逐项比对：

| 场景 | 现有结算 | Matcher |
|---|---|---|
| 同源三连 | `triple = true` | `source`，同时命中 G01 + G02 |
| 同族三连（3 来源） | `triple = true` | `family`，不命中 G01 |
| 三个不同符号同元素 | `element_resonance = true` | 命中 G03，`triple_kind = ""` |

三组全部一致。

## 4. 边界用例（E 组，15 条）

| 边界 | 结论 |
|---|---|
| **无序** | 三种排列判定完全一致（方案 §3.3） |
| **重复牌** | 只有 2 张同族 → 不算三连，但 3 张都算有效牌；同元素仍命中清一色 |
| **冻结列** | 该格按无效牌处理 → `valid_count = 2`、不构成三连、`reason = not_enough_valid` |
| **MISS / 废铁** | `kind == "trash"` 一律不算有效牌 |
| **无元素** | 三格同符号 `none` → 三连成立，但不命中清一色 |
| **来源去重** | 同符号同来源 = `source`；三个不同来源 = `family`；**空来源（技能符号）只算 `family`，不算同源** |

最后一条容易漏：现有实现里 `source_triple` 要求 `raw >= 3 and source_id != ""`，
所以空来源的三连绝不能判成同源刻，否则会错误地吃到武器专精倍率。

## 5. 装备解锁与优先级（F / G 组）

`PatternData.unlocked()` 的语义改成 **AND**：

| 牌谱 | 条件 | 表达 |
|---|---|---|
| S01 烈焰共鸣 | 两件火装备 | `unlock_tags = ["element:fire"]`, `unlock_count = 2` |
| S02 冰火二重 | 冰、火各至少一件 | `unlock_tags = ["element:ice", "element:fire"]`, `unlock_count = 1` |
| S03 黎明圣辉 | 圣辉长剑 + 破晓之弓 | `unlock_paths = [两者]`（全都要有） |

第一版写成「任一标签 + 数量」导致 S02 在两件火装备时误解锁、S03 在只有圣辉长剑时误解锁，
已修正为「每个标签都要满足 / 每条路径都要有」。

优先级解析（`PatternSystem.resolve_equipment`）：

- 装备牌谱每回合至多一条
- `priority` 降序 → 同优先级按 `id` 升序（稳定、无随机、**不弹窗**）
- 通用牌型不参与装备竞争（即使它的 priority 更高）
- 连携卷轴已指定的牌谱优先
- 无命中时返回 `null`，不硬塞

## 7. 一个仍然悬着的差异

旧共鸣与 S 牌谱的**机制不同**，不是换说法（Step 0 已记录）：

| | 旧共鸣 | S 牌谱 |
|---|---|---|
| 烈焰共鸣 | 火斩/燃烧 **+2 权重**（更容易摸到） | 火伤 **+25%** + 燃烧 +1 层 |
| 冰火二重 | crit **+0.5**（倍率 2.0→2.5） | 火冰 20% **转穿透** + 各 +1 层 |
| 黎明圣辉 | light 伤害 **×1.2** | 追加一次**穿透齐射**（攻击和 50%） |

Step 2 删旧效果时，这三条的实际手感会变。第 60 套 B 组已经把旧数值钉住，
删完之后如果 B 组断言不跟着改，就会红 —— 这是有意的。
