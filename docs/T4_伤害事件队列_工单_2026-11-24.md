## 2. 目标数据模型

新增 `scripts/battle/damage_ledger.gd`（`class_name DamageLedger extends RefCounted`）：

```gdscript
var events: Array = []

func begin(turn: int, hp_before: int) -> void      # 清空并记录起始 HP
func record(kind: String, amount: int, before: int, after: int,
            tag: String = "", element: String = "none", source: String = "") -> void
func drain() -> Array                               # 取走并清空（每个表现阶段取一次）
func total() -> int                                 # sum(amount)，供测试对账
```

事件字段固定：

```gdscript
{ "kind": "hit"|"pierce"|"dot"|"dot_burst"|"burst",
  "amount": int, "before": int, "after": int,
  "tag": String, "element": String, "source": String }
```

**铁律**：`before/after` 由调用方传入，账本**不重算**任何数值；账本不碰 `enemy_hp`。

## 3. A 组 · 记录（生产改动，不碰 UI）

**A1** `duel_controller` 持有账本并暴露 `damage_ledger`；`_reset_run_state()` 里 `reset()`。

**A2** `combat_system.evaluate()` 开头（`:250` 取 `enemy_hp_before` 之后）调用 `begin(turn_count, enemy_hp_before)`。

**A3** `apply_enemy_damage()` 两个写 HP 点各自记录：
- 穿透分支（`:1251`）：`before = enemy_hp`（加之前），`after = before - dmg`，`kind="pierce"`
- 破甲分支（`:1259`）：记录打掉护甲后真正进 HP 的 `to_hp`；`kind="hit"`；`amount` 记 `to_hp`（不是总伤害），避免 UI 与血条不一致
- `source` 记 `"apply_enemy_damage"`，`tag` 留空，`element` 按当前符号元素（可从 `_turn_enemy_*` 上下文取；取不到就 `"none"`）

**A4** `tick_status()`（`:1347-1348`）把一次 `enemy_hp -= dot` 拆成按 `dot_pops` 顺序逐条扣：

```gdscript
var hp_now := int(_ctrl.enemy_hp)
for pop in dot_pops:
    var one := int(pop[1])
    if one <= 0: continue
    var before := hp_now
    hp_now -= one
    _ctrl.enemy_hp = hp_now
    ledger.record(kind_for(pop), one, before, hp_now, String(pop[0]), String(pop[2]), "tick_status")
```

- `kind_for()`：爆发条目（标签里带「爆发」）记 `dot_burst`，其余 `dot`
- **必须保证 `tick_status()` 返回值 `dot` 与拆分前完全相同**（总数守恒），`_career.note_status_damage(dot)` 仍用总数
- 允许 `enemy_hp` 中途为负：与现状一致，UI 端 clamp

**A5** `on_counter()` 的破甲本身不改 HP，不记事件；其核爆若走 `apply_enemy_damage()` 会自动记录，不要重复记。

## 4. B 组 · 回放（UI）

**B1** `battle_hud.gd` 新增：

```gdscript
func play_damage_events(events: Array, hp_max: int, skip: bool) -> void
```

- 逐条：用 `event.after / hp_max` 调 `_apply_hp_bar(enemy_hp_bar, enemy_vitals, ratio, prev_ratio, shield)`（`prev_ratio` 取上一条的 after 比例，首条取当前 `_ev_hp_prev`）
- 飘字：`_popup("-%d" % amount, 颜色, _enemy_sprite_anchor(), slow)`；颜色优先 `ElementCounter.color(element)`，`none` 用 `Palette.POP_DAMAGE`；DoT 段 `slow=true`
- 段间等待 0.12s；`skip == true` 时不等待、只在最后一次性刷新
- 结束时把 `_ev_hp_prev` 置为 `clamp(enemy_hp/hp_max)`

**B2** 接入点（两处，顺序即真实结算顺序）：
1. `combat_system._present_turn()` 里 `hud.release_enemy_preview()` 之后（`:1067` 与 `:1084` 两处都要），调用 `await hud.play_damage_events(ledger.drain(), enemy_hp_max, presentation_skip)`
2. `turn_flow.gd` 的 `tick_status()`（`:132`）返回后、死亡检查（`:144`）之前，同样调用一次

**B3** 回放不得改变任何状态：不改 `enemy_hp` / `enemy_armor` / `game_state` / RNG；只读事件。

## 5. C 组 · 死亡与跳过

1. **死亡顺序**：死亡判定必须保持在回放之后（现有 `turn_flow.gd:124` 与 `:144` 天然满足，加断言锁死）。
2. **DoT 致死**：回放把 bar 走到 0，再进 `_settle_kill_async()`；不得先播死亡再补条。
3. **跳过**：`presentation_skip == true` 时 `play_damage_events` 不逐段等待，直接落到最终值；跳过不得改变最终 HP 或跳过死亡演出本身。
4. 快速跳过只压缩演出：`play_damage_events` 内部不接受任何改写 `_ctrl` 的参数。
