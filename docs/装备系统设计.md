## 一、设计理念

### 核心原则

> **词缀改变玩法，而非堆叠数值。**

借鉴 Death Must Die 的设计哲学，本装备系统强调：

1. **构筑导向** — 每条词缀都应该让玩家产生"如果我拿到 X，就能搭配 Y"的想法
2. **局内成长** — 装备主要在单局内获取和替换，形成每局不同的构筑体验
3. **化学反应** — 词缀之间、词缀与角色机制之间产生乘法效应，而非加法堆叠
4. **精简明确** — 词缀总量控制在 25-35 条，每条都有明确的构筑定位

### 与暗黑路线的区别

| 维度 | 暗黑路线 | 本方案（DMD 路线） |
|------|----------|-------------------|
| 词缀数量 | 上百条，大量 +5% 暴击类 | 25-35 条，每条改变行为逻辑 |
| 核心追求 | 数值慢慢累积，刷完美词缀 | 构筑 synergy，局内快速成型 |
| 获取方式 | 反复刷怪爆装备 | 局内房间奖励/宝箱/Boss 掉落 |
| 成长周期 | 跨局成长（小时级） | 单局成长（20-30min） |
| 装备槽 | 10+ 槽，层层叠加 | 精简 6 槽，每件选择都有明显影响 |
| 数值平衡 | 线性叠加，边际递减 | 乘法叠加，追求机制联动 |
| 开发成本 | 极高，测试周期长 | 中等，可逐条精雕细琢 |

## 二、装备槽位

### 2.1 槽位定义

| 槽位 | 英文 | 数量 | 说明 |
|------|------|------|------|
| 武器 | Weapon | 1 | 主武器，决定基础攻击方式和伤害类型 |
| 头盔 | Helmet | 1 | 头部防具，偏防御/功能 |
| 身体 | Body | 1 | 核心防具，偏生存/属性 |
| 手部 | Hand | 1 | 手套/护臂，偏进攻/技巧 |
| 腿部 | Leg | 1 | 腿甲/靴子，偏移动/机动 |
| 饰品 | Accessory | 2 | 戒指/护符，偏特效/构筑核心 |

共计 **7 个槽位**（1 武器 + 4 防具 + 2 饰品）。

### 2.2 槽位定位

```
武器     —— 怎么打（近战/远程/属性类型）
头盔     —— 怎么防（减伤/免疫/反制）
身体     —— 怎么活（回复/护盾/抗性）
手部     —— 怎么攻（攻速/暴击/穿透）
腿部     —— 怎么动（移速/闪避/范围）
饰品 x2  —— 怎么变（玩法改变的核心槽位）
```

### 2.3 基础属性

每个装备槽位提供一个**基础固定属性**，不受词缀影响：

| 槽位 | 基础属性 |
|------|----------|
| 武器 | 武器自身的 `WeaponBase` 数值（已有系统） |
| 头盔 | `defenses` 中对应类型防御 +0.1 |
| 身体 | `max_hp` +50 |
| 手部 | 攻击速度 +10% |
| 腿部 | 移动速度 +10% |
| 饰品 | 无基础属性，纯词缀槽 |

**装备品质不影响基础属性，只影响词缀数量和词缀等级。**

## 三、Room 适配方案（关键设计决策）

### 3.1 核心问题

> **DMD 是大面积大地图 + 密集怪海 → 词缀每秒触发多次 → 持续爽感**
> **Seek Dead 是小房间 + 少量怪 → 词缀触发机会少 → 爽感可能不足**

不改变 Room 模式的本质（保留外卖柜的"柜门背后未知"的悬念感），而是通过**房间尺寸分级 + 波次刷新**来解决。

### 3.2 房间尺寸分级

```
小房间 (40%)  —— 1 波，6-8 怪      ← 现在的模式
   代表：单个外卖柜格
   节奏：30 秒清完，快速推进

中房间 (35%)  —— 2 波，8-12 怪    ← ✅ 已实现
   代表：贯通的两三个柜格
   节奏：1 分钟清完，词缀有 1-2 次触发机会

大房间 (20%)  —— 3 波，12-18 怪    ← ✅ 已实现
   代表：仓库区 / 冷藏库
   节奏：1.5 分钟清完，构筑进入全力运转

Boss 房 (5%)  —— 3 波，14-18 怪 + Boss ← ✅ 已实现
   代表：站点最深处 / 冷库核心区
   节奏：2-3 分钟，构筑完整释放，词缀全面触发
```

> **注**：实际实现的怪物数低于设计值，因为 640x360 小屏幕下 30+ 怪会严重拥挤。
> 通过波次刷新（ENEMIES_LEFT 触发）保持场上 8-12 只常驻，兼顾帧率和词缀触发频率。

**房间尺寸递进本身就是天然的难度曲线**：前几层小房间快节奏推进，中层中房间开始构筑验证，深层大房间考验持续输出，Boss 房全盘检查。

### 3.3 波次刷新机制

不改 RoomConfig 的大结构，只在现有 `SpawnMarker` 系统上加一个分波字段：

```gdscript
# RoomConfig 新增字段
@export var waves: Array[WaveConfig]  # 波次配置列表

class_name WaveConfig
extends Resource

@export var spawn_marker_ids: Array[String]   # 本波使用的 SpawnMarker 名称
@export var trigger_condition: WaveTrigger    # 触发条件：ON_START / ENEMIES_LEFT(n) / TIMER(n)
@export var delay: float = 0.0                # 触发后延迟多少秒再刷
@export var announce: String = ""             # 刷波提示文字（如"更多腐化外卖涌来了！"）
```

**波次触发条件：**

| 条件 | 说明 | 适用场景 | 实现状态 |
|------|------|---------|---------|
| ON_START | 进门立即刷 | 第一波 | ✅ |
| ENEMIES_LEFT(3) | 场上剩 3 只时刷下一波 | 保持场上密度 | ✅ |
| ENEMIES_LEFT(1) | 场上剩 1 只时刷 | 接近清空时补怪 | ✅ |
| TIMER(15) | 进门 15 秒后刷 | 时间触发，防止玩家拖太久 | ✅ |
| BOSS_PHASE(0.5) | Boss HP 低于 50% 时刷 | Boss 房多波压力阶段 | ✅ |

**波次刷新示例 — 中型房间：**

```
Wave 1 (ON_START):
  SpawnMarker: marker_a, marker_b, marker_c
  刷 6 只哥布林

── 玩家杀到剩 3 只时 ──

Wave 2 (ENEMIES_LEFT 3):
  SpawnMarker: marker_d, marker_e
  刷 6 只骷髅
  提示："柜门深处传来响动..."
```

**波次刷新示例 — Boss 房：**

```
Wave 1 (ON_START):
  刷 8 只杂兵

Wave 2 (ENEMIES_LEFT 2):
  刷 Boss + 4 只小怪

Wave 3 (BOSS_PHASE 2):
  Boss 60% HP 时刷 6 只精英

Wave 4 (BOSS_PHASE 3):
  Boss 30% HP 时刷 8 只小怪 + 1 只精英治疗怪
```

**核心指标：场上常驻敌人数**

| 房间类型 | 波间场上常驻 | 峰值场上 |
|----------|------------|---------|
| 小房间 | 6-8 | 8 |
| 中房间 | 8-10 | 15 |
| 大房间 | 10-12 | 25 |
| Boss 房 | 8-12 + Boss | 30+ |

这样即便是 640x360 的小屏幕，词缀的触发目标也始终充足。

### 3.4 波次对词缀体验的影响

| 体验维度 | 无波次（当前） | 有波次刷新 |
|----------|-------------|-----------|
| 触发频率 | 开火 6 次打完，触发 0-1 次 | 开火 20 次，触发 3-5 次 |
| 构筑验证 | 还没触发就结束了 | 每波都是构筑的 mini-test |
| 节奏感 | 进门→清完→走人（平） | 进门→清→补怪→清→补怪（起伏） |
| 套装爽感 | 攒齐套装只剩 1 间房 | 攒齐套装还有 3+ 间房可以爽 |

### 3.5 RoomConfig 改造清单

```gdscript
# scripts/rooms/room_config.gd 新增/修改字段

@export var room_size: RoomSize = RoomSize.SMALL  # SMALL / MEDIUM / LARGE / BOSS

@export_group("Wave System")
@export var waves: Array[WaveResource] = []  # 波次配置

@export_group("Room Rewards")
@export var reward_count: int = 1            # 清空奖励的装备数量（中房间 2，大房间 3）
@export var reward_quality_bonus: float = 0.0  # 品质加成（大房间 +0.2）
```

### 3.6 尺寸递进与关卡流程

一局（10 房间，已实现）的典型节奏：

```
房间 1:  小 ← 上手，熟悉装备
房间 2:  小 ← 捡到第一件蓝装
房间 3-4: 中/大 ← 触发类词缀初体验
房间 5-7: 中/大 + BOSS(随机1间) ← 构筑验证，Boss 可逃
房间 8-10: 中/大 ← 构筑全力运转，最后一波爽
```

确保在 Boss 房之前有足够的大/中房间让玩家验证构筑，避免"刚成型就结束了"的失落感。

Boss 出现于房间 5/6/7（随机 1 间），前 4 间保证安全发育。逃离 Boss 房后 Boss 本局不再出现，奖励减少。

## 四、词缀系统（核心）

### 3.1 词缀结构

每条词缀是一个 `AffixResource`，包含：

```gdscript
class_name Affix
extends Resource

@export var affix_name: String            # 显示名，如"灼烧"
@export var affix_description: String     # 效果描述
@export var affix_icon: Texture2D         # 图标
@export var affix_type: AffixType         # 枚举：前缀/后缀
@export var rarity: Rarity                # 普通/魔法/稀有/传奇

# 效果定义
@export var stat_modifiers: Array[StatModifier]  # 数值修改列表
@export var trigger_effects: Array[TriggerEffect] # 触发式效果
@export var conditional_bonuses: Array[ConditionalBonus] # 条件型加成
```

三种效果类型的详细定义：

#### 3.1.1 StatModifier（数值修改器）

直接修改角色的某个数值属性：

```gdscript
class_name StatModifier
extends Resource

@export var target_stat: StatTarget       # 目标属性枚举
@export var modifier_type: ModifierType   # 加法/乘法/覆盖
@export var value: float
@export var per_affix_level: float = 0.0  # 每级词缀额外增加
```

`StatTarget` 枚举（对接现有 `StateComponent`）：

| StatTarget | 影响对象 | 说明 |
|------------|----------|------|
| MAX_HP | `state.max_hp` | 最大生命值 |
| HP_REGEN | `state.hp_regen` | 生命回复/秒 |
| MAX_ENERGY | `state.max_energy` | 最大能量值 |
| ENERGY_REGEN | `state.energy_regen` | 能量回复/秒 |
| MAX_STAMINA | `state.max_stamina` | 最大体力值 |
| STAMINA_REGEN | `state.stamina_regen` | 体力回复/秒 |
| MOVE_SPEED | `movement.speed` | 移动速度 |
| ATTACK_SPEED | 武器攻击速度 | 攻速（乘法叠加） |
| ATTACK_DAMAGE | 武器伤害 | 伤害（乘法叠加） |
| CRIT_RATE | `DamageSystem` 暴击率 | 基础 5% |
| CRIT_DAMAGE | `DamageSystem` 暴击倍率 | 基础 1.5x |
| `PUNCTURE_DEF` ~ `WIND_DEF` | `state.defenses` | 8 种防御 |
| `PUNCTURE_BONUS` ~ `WIND_BONUS` | `state.bonuses` | 8 种攻击加成 |
| DODGE_COOLDOWN | `dodge.cooldown` | 闪避冷却缩减 |
| DODGE_DISTANCE | `dodge.distance` | 闪避距离增加 |
| HEAT_PER_ATTACK | 武器产热 | 每次攻击产热量 |
| HEAT_COOLING | `state.heat_cooling` | 冷却速度 |

#### 3.1.2 TriggerEffect（触发式效果）

核心玩法改变来源，对接现有 `EventManager` 信号系统：

```gdscript
class_name TriggerEffect
extends Resource

@export var trigger_event: TriggerEvent   # 触发条件
@export var effect_action: EffectAction   # 触发效果
@export var cooldown: float = 0.0         # 触发冷却（0=无冷却）
@export var chance: float = 1.0           # 触发概率（0.0~1.0）
@export var targets: EffectTarget         # 效果目标
```

**触发条件（TriggerEvent）:**

| 事件 | 说明 | 对接 EventManager 信号 |
|------|------|----------------------|
| ON_HIT | 命中敌人时 | `damage_dealt` |
| ON_KILL | 击杀敌人时 | `enemy_died` |
| ON_HURT | 受到伤害时 | `damage_dealt`（反向） |
| ON_DODGE | 闪避时 | 新信号 `dodge_performed` |
| ON_CRIT | 暴击时 | `damage_dealt` + crit 判断 |
| ON_SKILL_USE | 释放技能时 | `skill_used` |
| ON_MELTDOWN | 进入超载时 | `meltdown_triggered` |
| ON_ROOM_CLEAR | 房间清空时 | `room_cleared` |
| ON_EMPTY_AMMO | 弹药耗尽时 | `ammo_empty` |
| ON_RELOAD | 装弹时 | `reload_started` / `reload_finished` |
| ON_STATUS_INFLICT | 施加状态时 | 新信号 `status_inflicted` |
| ON_PICKUP | 拾取物品时 | `item_picked_up` |

**效果动作（EffectAction）:**

| 动作 | 参数 | 说明 |
|------|------|------|
| EXPLODE | radius, damage, damage_type | 触发爆炸 |
| SPAWN_PROJECTILE | bullet_data, count, spread | 额外发射子弹 |
| SPAWN_POOL | pool_scene, count, duration | 生成范围效果（毒池/火池） |
| CHAIN_LIGHTNING | targets, damage, chain_count | 闪电链 |
| HEAL | heal_amount, heal_type | 治疗 |
| SHIELD | shield_amount, duration | 护盾 |
| STATUS_INFLICT | status_type, duration, damage | 施加状态 |
| FIRE_AURA | radius, damage, interval | 光环效果 |
| SUMMON | summon_scene, count, duration | 召唤物 |
| KNOCKBACK | force, radius | 击退 |
| TELEPORT | distance | 瞬移 |
| SLOW_ENEMIES | radius, speed_mult, duration | 范围减速 |
| DODGE_RESET | — | 重置闪避冷却 |

#### 3.1.3 ConditionalBonus（条件型加成）

特定条件下激活的加成：

```gdscript
class_name ConditionalBonus
extends Resource

@export var condition: ConditionType      # 条件
@export var condition_value: float        # 条件参数
@export var bonus: StatModifier           # 激活时生效的加成
```

**条件类型（ConditionType）:**

| 条件 | 说明 |
|------|------|
| HP_ABOVE | HP 高于 X% 时 |
| HP_BELOW | HP 低于 X% 时 |
| ENEMIES_NEARBY | 周围 X 像素内有敌人时 |
| STAMINA_FULL | 体力全满时 |
| HEAT_ABOVE | 热量高于 X 时 |
| STATUS_ON_SELF | 自身有某状态时 |
| STATUS_ON_ENEMY | 目标有某状态时 |
| NO_AMMO | 弹药为 0 时 |
| AFTER_DODGE | 闪避后 X 秒内 |
| AFTER_SKILL | 使用技能后 X 秒内 |
| COMBO_COUNT | 连击数 > X 时 |

#### 触发类（12 条）

**Room 适配规则**：触发概率在小房间保持原值，中/大房间额外获得"场上怪物数"加成。核心逻辑是：**每房间至少有 1 次保底触发**（首个击杀/首次命中必定触发），后续触发按概率进行。

| # | 词缀名 | 触发条件 | 效果 | Room 适配 |

## 五、套装系统

### 通用适配原则

所有套装效果的触发强度与**房间尺寸 + 波次编号**正相关：
- 小房间：效果生效，但视觉/数值收敛
- 中大房间 + Boss 房：效果全力展开
- 多波次房间：每波都可以重新触发，波次越靠后效果越强

### 5.1 套装规则

- 每套 3 件（头/身/手/腿/饰品中选 3 个槽位）
- **2 件激活**：基础套装效果
- **3 件激活**：完整套装效果——通常是玩法改变级效果
- 套装效果与词缀独立叠加

### 5.2 套装列表（初版 5 套）

### 9.3 EquipmentManager（局内单例）

负责：
- 管理玩家当前穿戴的 7 件装备
- 应用/移除词缀的 StatModifier 到 StateComponent
- 注册 TriggerEffect 到 EventManager
- 注册 ConditionalBonus 到条件检查循环
- 激活/停用套装效果

```gdscript
# 核心流程
func equip(item: EquipmentBase):
    # 1. 移除旧装备的所有词缀效果
    unequip(item.slot)
    
    # 2. 记录新装备
    _equipped[item.slot] = item
    
    # 3. 应用 stat_modifiers → StateComponent
    for affix in item.affixes:
        for modifier in affix.stat_modifiers:
            _apply_stat_modifier(modifier)
    
    # 4. 注册 trigger_effects → EventManager
    for affix in item.affixes:
        for effect in affix.trigger_effects:
            _register_trigger(effect)
    
    # 5. 检查套装激活
    _check_set_bonuses()
    
    # 6. 发射装备变更信号
    equipment_changed.emit(item.slot, item)
```

### 9.4 词缀条件检查系统

```gdscript
# 每帧检查 ConditionalBonus（在 EquipmentManager 中）
func _process(delta: float):
    for condition_bonus in _active_conditions:
        var is_active = _evaluate_condition(condition_bonus.condition)
        if is_active != condition_bonus.currently_active:
            condition_bonus.currently_active = is_active
            if is_active:
                _apply_stat_modifier(condition_bonus.bonus)
            else:
                _remove_stat_modifier(condition_bonus.bonus)
```

### 9.5 掉落生成流程

```gdscript
# EquipmentDrop.gd
func generate_drop(quality_roll: float, slot: EquipmentSlot) -> EquipmentBase:
    var equip = EquipmentBase.new()
    equip.slot = slot
    equip.rarity = _determine_rarity(quality_roll)
    
    var affix_count = _get_affix_count(equip.rarity)
    var affix_level_range = _get_affix_level_range(equip.rarity)
    
    for i in affix_count:
        var affix = _random_affix(equip.slot)
        affix.level = randf_range(affix_level_range.x, affix_level_range.y)
        equip.affixes.append(affix)
    
    # 如果是套装，固定搭配
    if equip.rarity == Rarity.SET:
        equip.set_id = _pick_set_for_slot(slot)
        equip.affixes = _get_set_affixes(equip.set_id, slot)
    
    return equip
```

## 十二、风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 词缀与现有数值系统平衡被打破 | 高 | 所有 StatModifier 乘法叠加设上限（2.5x max），触发效果设内置 CD |
| 条件类词缀每帧检查性能开销 | 中 | 条件检查改为事件驱动优先，真·每帧检查不超过 5 条 |
| 触发效果执行器数量膨胀 | 中 | 先实现 6 个核心执行器，后续按需添加 |
| 装备面板 UI 开发量大 | 中 | 用 Control 节点 + VBoxContainer 组合，不做复杂嵌套 |
| 词缀组合产生意料之外的强力 synergy | 低 | 测试阶段重点覆盖 2-3 件套组合，上线后通过热修调整数值 |
| **波次系统 + 现有 RoomManager 兼容** | 中 | WaveConfig 作为 RoomConfig 可选字段，不改造旧房间配置 |
| **火径/毒云跨波持续的性能** | 中 | 限制同时存在的特效区域 ≤ 5 个，超限时最早生成的消失 |
| **小房间触发保底机制滥用** | 低 | 保底仅限"每房间首次"，不叠加到后续触发 |
