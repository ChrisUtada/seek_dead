# Seek Dead · 牌谱进三选一是"无效成长"吗？（2026-11-19）

> 用户直觉："牌型放在三选一里面很奇怪，变成一种无效成长了。"
> 本文基于代码事实 + 行业实践核查这个直觉。**结论：直觉正确，且问题比表面更严重——
> 当前三张 rule_mod 卡强化的是一个"签名候选"牌谱，绝大多数玩家抽到即完全无效。**

---

## 1. 直觉成立：代码事实核查

### 1.1 三张规则卡绑定的是签名候选，不是基础牌谱

我 P1-B 做的三张规则卡全部指向 `SIG02`（冰火二重）：

| 卡 | 效果 |
|---|---|
| rule_burn_up | SIG02 触发时燃烧 +1 |
| rule_frost_up | SIG02 触发时霜冻 +1 |
| rule_pierce_up | SIG02 触发时穿透 +10% |

但 `s02_frostfire_dual.tres` 的真实定义：
```
track = "signature"          ← 签名轨，不是基础牌谱
unlock_tags = ["element:ice", "element:fire"]
unlock_count = 1
match_rule = 火斩 + 冰霜晶弹 同时出现
```

**这意味着抽到规则卡后，必须同时满足：**
1. 玩家携带冰、火两件装备；
2. 转轮上同时凑出火斩 + 冰霜晶弹；
3. 签名已习得（如果是签名牌谱的额外前提）。

### 1.2 三重概率叠加 → 无效成长

按当前牌谱机制，SPIN 的转轮是 3 格 1 行，凑出"火斩+冰霜晶弹"特定组合的概率本就不高；
再叠加"必须携带冰火双元素武器"的构筑前提——**大多数玩家抽到这三张卡后，整局都不会触发一次**。

这就是用户说的"无效成长"：卡面写着强化，实际什么都没发生。
行业里这叫 **"dead reward"（死奖励）**——选了等于没选，违背 roguelite 奖励设计的底线。

### 1.3 行业原则：奖励价值必须"情境可见且当下有用"

行业共识（Slay the Spire / Balatro / deckbuilder 设计框架）：

- **奖励应是"情境化选择"**（situated choice）：价值随当前构筑/血量/路线变化，
  但**必须有一个可理解、在可见未来能兑现的用途**。
- **"改变决策而非加数字"**：好的遗物/规则奖励应该改变策略优先级或创造新协同，
  而不是给一个永远触发不了的条件加成。
- **协同应该是"玩家发现的"**，但前提是**基础组件已经存在**——
  给一个没有组件的协同奖励，等于给玩家一张空头支票。

对照本作：三张规则卡要求玩家先有冰火双武器 + 凑出特定牌型——
**组件不在玩家手里，却先给了强化组件的奖励**，顺序反了。

## 2. 更深的问题：牌谱增强的"位置"错了

用户的直觉还指向一个结构性问题——**牌谱信息不该出现在三选一里**。

策划案 V1.0 §1.3 的定位：
> 牌谱：自动判定、自动结算的组合规则库，**不需要玩家在战斗外逐张管理**。
> 玩家操作始终是 SPIN，而不是管理卡牌。

那么问题来了：

| 视角 | 分析 |
|---|---|
| 玩家认知 | 三选一给"冰火二重燃烧+1"，玩家要理解：①什么是冰火二重 ②怎么触发 ③我当前能不能触发 |
| 游戏定位 | 牌谱是自动后台规则，玩家不该管理它；但三选一让玩家"管理"了一个后台数值 |
| 反馈闭环 | 即使触发了，玩家看到的是 SPIN 战斗飘字，很难归因到"因为我三选一选了那张卡" |
| 决策质量 | 玩家在"看不懂/用不上/没反馈"的情况下，只能靠猜或按稀有度选——三选一退化成假选择 |

**结论**：把后台牌谱的参数增强做成前台三选一卡，既违背"不管理卡牌"的设计原则，
又因触发条件太苛刻变成死奖励。**这是设计层面的错位，不只是数值问题。**

---

## 3. 三个专业方案

### 方案 A：只强化"玩家当前已生效"的牌谱（最小改动，推荐）

**核心**：rule_mod 卡不再静态绑定 SIG02，改为**动态构造**——
只从玩家当前构筑下"已解锁且能参与判定"的牌谱里挑目标。

类似 P0.2 符号权重卡的做法：
- `_make_rule_defs()` 遍历 `pattern_system` 已解锁牌谱（按当前武器/技能）；
- 只为**已解锁**的牌谱生成强化卡；
- 卡面明确显示"当前生效：烈焰共鸣"等。

**优点**：抽到即可用，消除死奖励；符合"情境化选择"。
**缺点**：需要实现"当前已解锁牌谱"查询（`pattern_system.unlocked_patterns` 已有，可直接用）。

### 方案 B：牌谱增强改为"授予牌谱"而非"强化参数"（更符合品类）

**核心**：三选一不强化已有牌谱的参数，而是**让玩家获得一个新牌谱**（类似杀戮尖塔拿新卡）。
- 三选一给"冰火二重"本身（习得这个组合规则）；
- 玩家后续凑出火斩+冰霜晶弹时自动生效；
- 强化数值做成牌谱的"变体卡"（如"冰火二重·改"），同样是授予而非参数叠加。

**优点**：符合"玩家发现协同"的品类乐趣；卡面价值明确（得到一条新规则）；
与现有 `learn_signature` 机制一致（已有签名习得卡）。
**缺点**：需要牌谱"已拥有/未拥有"的状态管理（当前基础牌谱似乎是全自动解锁的）。

### 方案 C：把 rule_mod 从三选一移除，改成"战斗内即时规则改造"（最彻底）

**核心**：中奖规则改造不在战后三选一发，而是在战斗中通过特殊符号/事件触发，
直接反馈到 SPIN 结算——玩家当场看到"这次因为规则改造多了一段伤害"。

**优点**：完全符合"奖励必须在 SPIN 中可见"的原则；反馈闭环最强。
**缺点**：改动最大，需要新的触发载体。

## 4. 我的推荐：A + B 的组合，且要回答一个前置问题

**推荐路线**：
1. **短期（本次可立即修）**：方案 A——把三张 SIG02 规则卡改为动态构造，
   只强化玩家当前已解锁的牌谱，消除死奖励。
2. **中期（P2 签名接入时）**：方案 B——签名牌谱的习得/变体走三选一授予，
   参数强化退居次要。
3. **不建议方案 C**——改动大，且策划案 V1.0 已定"战后三选一是唯一主要成长分发器"，
   战斗内改造会打破这个架构。

**但要先拍板一个前置问题**：
> 策划案 V1.0 §10.3 明确"牌谱不新增独立成长层"，而规则参数强化本质上就是牌谱的
> 隐性成长层。这两者是否冲突？
> - 如果**不冲突**（可接受的隐性成长）→ 走方案 A，做"情境化的参数强化"；
> - 如果**冲突**（坚持牌谱纯后台自动）→ 规则卡应完全改为方案 B 的"授予新规则"，
>   或把 rule_mod 权重挪给 symbol_mod/reel_control。

## 6. 结论

**用户的直觉是对的，而且抓到了一个真实的设计错位：**

- 当前三张规则卡强化签名候选 SIG02，触发条件三重叠加 → **绝大多数情况下是死奖励**；
- 把后台自动结算的牌谱参数做成前台三选一卡 → **违背"玩家不管理牌谱"的设计原则**；
- 反馈闭环断裂：玩家很难把 SPIN 的战斗结果与三选一的选择关联起来。

**专业建议**：走方案 A（动态强化已解锁牌谱）消除死奖励，
中期结合 B（授予新规则），并先回答"规则强化是否违背不建牌谱成长层"这个前置问题。
