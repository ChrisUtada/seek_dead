## 1. 一句话定位

> **你手里没有枪，你手里是一台老虎机。转轮就是你的武器，三连就是你的暴击。**

Seek Dead 是一款把「老虎机对决」与「Roguelike 地牢探索」缝合在一起的回合制游戏（PC / Godot 4.7）。玩家扮演一名深入地牢的冒险者，攻击方式不是扣扳机，而是拉动转轮——每一列停下的符号就是打出去的「弹药」。武器决定转轮带由哪些符号组成（火剑带火格、冰枪带冰格），元素克制决定打在敌人身上是「×1.5 弱点爆发」还是「×0.85 被抗」。

但项目在后续迭代中把核心幻想进一步收束为：

> **玩家通过战后三选一与武器替换，持续改造老虎机的符号构成、中奖规则与滚轴操控，最终形成一台具有独特玩法的「中奖引擎」。**

也就是说，游戏真正的深度不在「这一转转出什么」，而在「我如何改造这台机器，让它更容易转出我想要的结果」。

两条贯穿始终的诉求（用户拍板）：

1. 带来**数值爆炸的爽感**；
2. 玩法和计算**不要过于复杂**。

## 2. 游戏概览

| 维度 | 说明 |
|---|---|
| 类型 | Roguelike 地牢探索 + 老虎机战斗结算（回合制，1 条赔付线） |
| 核心幻想 | 老虎机作武器，地牢作舞台 |
| 结算灵感 | 小丑牌 Balatro（乘区爆炸 + 伤害分解可读） |
| 结构灵感 | 挺进地牢 Enter the Gungeon（房间 / 精英 / BOSS / 装备驱动 / 元解锁）、杀戮尖塔（构筑决策在局间，战斗内是兑现） |
| 操作层 | 真人老虎机：手动按停，转速 = 难度，眼力手速 = 技巧 |
| 单局规模 | 3 幕 × 8 节点 = 24 节点 + 真·最终 BOSS（第 25 节点）；共 19 场战斗 |
| 单局时长 | 约 45–55 分钟（早期目标值，当前结构已调整为 25 节点 / 19 战） |
| 引擎 / 平台 | Godot 4.7 / GDScript，PC |
| 分辨率 | 视口 480×270（复古掌机感，nearest 像素过滤，外嵌 DeviceFrame），窗口 960×540 |

**设计基石**：小丑牌玩家完全掌控出什么牌；老虎机是纯随机出符号。若照搬「战斗内多乘区」，伤害就会变成「随机符号 × 一堆看不出哪个生效的乘区」的黑箱。因此本作把**策略放在 build 层（转轮之前）**，战斗内保持简单直观，这是整个设计的基石。

## 3. 核心体验循环

```text
读取敌人意图
→ 选择目标符号
→ 手动停轮
→ 结算符号 / 牌谱 / 回路
→ 看懂伤害与生存结果
→ 战后做一次主要改造（三选一 / 换装）
→ 在下一场兑现构筑
```

老版循环可概括为「整备 → 转轮 → 结算 → 奖励 → 商店 → 下一房」，新版更强调「改造引擎 → 兑现引擎」的节奏。

**策略发生在**：战后三选一、武器换装、商店投资、符号/回路改造。
**技巧发生在**：转轮按停时机（转速越来越快，越转越难停在目标符号）。
**爽感发生在**：连线命中、大数字 + 伤害分解。

## 4. 一局的结构：房间与流程

### 4.1 线性房间（无地图）

当前正式玩法**不保留分岔地图**，采用线性连续构筑战斗。每幕固定 8 个节点：

| 顺序 | 房间 | 职责 |
|---|---|---|
| 1 | 普通战斗 | 开始构筑 |
| 2 | 普通战斗 | 延续构筑 |
| 3 | 宝箱或事件 | 直接惊喜 / 有代价的交易 |
| 4 | 精英战斗 | 第一次机制验收 |
| 5 | 普通战斗 | 兑现特殊房收益 |
| 6 | 精英战斗 | 第二次机制验收 |
| 7 | 营地 | Boss 前恢复（25% HP）或整理（精简符号 / 卸除技能） |
| 8 | Boss | 本幕总验收 |

构成 = **3 普通 + 2 精英 + 1 宝箱/事件 + 1 营地 + 1 Boss**；真·最终 Boss 另按流程追加（第 25 节点）。不设军械库、随机房间多选一或额外地图层。

- 三幕共 24 节点 + 真·最终 Boss = 25 节点；
- 普通/精英/幕末 Boss 战斗 18 场 + 最终 Boss = **19 场战斗**；
- 宝箱/事件 + 营地共 6 个非战斗节点；
- 整局普通/精英三选一（Draft）共 15 次，幕末 Boss 奖励 3 次。

### 4.2 战后流程

```text
战斗胜利 → 战后三选一 → 房间歇页 → 可选打开商店，或直接下一房
```

不回大厅、不重置成长、不强制每战进商店。战斗强度按**本幕已实际经历的战斗数**计算，宝箱/事件/营地不抬高下一场敌人的 ante。

### 4.3 信息公开

- 当前 ACT 的 Boss 在开幕时公开名称、立绘、元素、弱抗与核心机制（只给客观信息，不给推荐答案）；
- 宝箱类型可见，具体物品保密到主动开启；
- 事件选项、收益与代价在进入后展示。

## 5. 战斗系统：老虎机转轮

### 5.1 转轮带模型

- **3 列 × 1 行**（`REELS=3`、`ROWS=1`），唯一一条赔付线（payline）。
- **转轮带由符号按权重展开成格子**再洗牌，每列一份副本（同构成、异顺序）。权重 = 带子上该符号的格子数，概率与带子长度一一对应，不是后台黑箱概率表。
- 带长下限 30 格，不足时整份平铺补足（各符号占比不变）。
- **MISS / 废铁（统称「无效格」）**：武器 `hit_rate` 决定 MISS 格占比（`miss_w = Σ权重 × (1-hit_rate)`）；敌人意图可额外注入废铁（jam/chaos）。无效格不匹配、不结算、可滚过规避。
- 金币符号常驻 2 格，落线转化为金币、不造成伤害。

### 5.2 手动按停（操作即技巧）

- 按 SPIN → 转轮旋转 → 玩家手动按停每一列 → 落定后结算。
- 转速从 `0.09s → 0.035s` 每跳加速（约 37 跳封顶，≈28 格/秒）——越转越快，越难精确停在目标符号。
- 三条停止入口：SPIN 按钮、空格键、点击某列单独锁定。**不设自动兜底，不停就一直转**。
- 冻结（frost 层数）会锁住转轮列：失效格本轮不可转、不参与结算。

### 5.3 连线判定

遍历赔付线 3 格，按「符号 resource_path + 有效元素」分组计数 `raw`：

- `raw=1` 单符号、`raw=2` 二连、`raw=3` 三连（满线）；
- 同元素三连（非 none 元素全线出现 ≥3，可跨符号）触发元素共鸣类效果；
- 冻结列不参与计数。

> 重要：结算**不要求凑三连**，1 连也照常出伤害。多带武器的代价是隐形的（符号被稀释、目标符号密度下降、按停变难），不是打空。

## 6. 伤害与结算

### 6.1 单符号伤害

```text
flat      = 武器 base_power + 聚合加算加成（护符 damage_bonus / buff power / 训练锋锐）
mult      = raw + 连线精通加成（仅 raw≥2 生效）
em        = 元素克制倍率 × 共鸣加成
crit_mult = 三连必暴 / 同元素三连 / 随机暴击时按物品 crit_mult（默认 ×2）

单符号基础 dv = flat × mult × em × crit_mult
```

### 6.2 回合乘区链

```text
buff_mult = 护符伤害乘区 × Π 玩家增益(damage_mult)   （护符乘区硬顶 ×6.0）
assault   = 强袭药剂倍率（用后清 1，仅下次转轮）
total     = int((连线伤害 + special 伤害) × assault × buff_mult × player_dmg_mult)
```

- 伤害分「普通」与「穿透」两部分结算：穿透符号直接扣 HP；非穿透先扣敌人扁平护甲池，溢出进 HP。
- 结算顺序：buff / 治疗 / 护盾 / 状态先落地 → 三连与克制钩子（破甲 / 核爆）→ 攻击乘区链 → 敌人回合 → 状态 DoT tick。
- **伤害分解面板**：逐符号显示「基础 × 连线 × 克制 = 小计」+ 回合级乘区，让玩家看懂每个大数字的来源。

### 6.3 反制即爆发

- **破甲**：`triple_pierce` 武器三连，或克制元素连线 ≥2，触发 `on_counter` → 敌人护甲清零。
- **元素核爆**：`kind="element"` 的克制三连额外造成「敌人最大 HP × 12.5%」穿透伤害。
- **元素充能**：克制命中累计充能，满 6 点释放元素爆发（清甲 + 敌人最大 HP ×15% 穿透）。

## 7. 武器系统（重点）

武器是整套玩法的**底盘**：它决定了转轮带里有哪些符号、各自多少格、带什么元素、命中与暴击特性，以及能否触发特殊机制。项目当前共有 **90 把武器**，全部以独立 `.tres` 资源存放在 `resources/weapon_templates/`，由资源扫描自动入池——**加武器 = 新建 .tres，不改代码**。

### 7.1 三层模型

武器设计遵循「基础属性 / 机制 / 元素」三层正交模型：同一机制可配不同元素，同一元素可配不同数值。

```text
武器 .tres
├── ① 基础属性层（决定"多强"）
│      rarity 稀有度 / base_power 攻击力 / crit_mult 暴击倍率
│      crit_chance 非三连暴击率 / hit_rate 命中率
├── ② 机制层（决定"什么效果"）
│      机制符号（status）/ triple_pierce 三连破甲 / 符号 pierce_armor 穿透
└── ③ 元素层（决定"克制谁"）
       element 武器元素 / reel_element 特殊符号元素 / 符号元素继承
```

| 字段 | 含义 | 取值 / 说明 |
|---|---|---|
| `base_power` | 武器级攻击力 | **唯一现行伤害数值源**，档位约 7–23；旧的 `damage` 字段是遗留残留，转轮战斗不读取 |
| `hit_rate` | 命中率 | 1 − hit_rate = MISS 格占比；高攻击武器往往低命中（代价轴） |
| `crit_mult` | 三连/同元素三连暴击倍率 | 默认 ×2，epic 可达 ×2.5 |
| `crit_chance` | 非三连暴击率加成 | 0–0.15；总暴击率 = 全局 20% + 此值；高 base 低暴击是「代价轴」 |
| `rarity` | 稀有度 | common / uncommon / rare / epic，**只定强度，不定频率** |
| `triple_pierce` | 武器级三连破甲 | 三连时清空敌人护甲；15 把持有 |
| `element` | 武器元素 | 普通符号自身 element=none 时继承此值；用于克制与着色 |
| `reel_element` | 特殊符号元素 | 仅 `kind=="special"` 的符号优先取此值 |
| `symbols` | 符号池 | `Array[SymbolWeight]`，符号资源 + 权重，直接引用资源、无 id 查表 |
| `archetype` | 武器原型 | LIGHT / MEDIUM / HEAVY / MAGIC，是分类标签 + 行为开关 |
| `weapon_type` | 武器类型 | MELEE / RANGED |

> **遗留字段**：`damage / attack_speed / attack_range / damage_type / bullet_speed / max_ammo / cleave_angle / knockback_force / status_effect_*` 等是早期 ARPG 原型残留，转轮战斗不读取（其中 6 个零引用字段已从脚本删除）。制作/阅读武器时以 `base_power` 为准。

| 稀有度 | 存档值 | 数量 | 占比 |
|---|---|---:|---:|
| 基础 | `common` | 36 | 40.0% |
| 进阶 | `uncommon` | 35 | 38.9% |
| 稀有 | `rare` | 11 | 12.2% |

**按元素**：火 15 / 冰 15 / 毒 15 / 光 15 / 暗 14 / 无 16（当前资源中每把武器的 `element` 与 `reel_element` 完全一致，两字段尚未分叉，但结算逻辑仍分别处理）。

**按原型（archetype）**：

| 原型 | 有效数量 | 特征（同源三连时） |
|---|---:|---|
| LIGHT 轻型 | 24 | 追加 50% 伤害 |

### 7.3 武器原型的作用机制

原型不是独立资源、不是父对象，而是每把 `WeaponData.tres` 上的一个枚举标签（分类 + 行为开关）。当**同源符号三连**（同一符号资源 + 同一有效元素落满 3 格）时触发对应效果：

- LIGHT：伤害 ×1.5；
- RANGED：35% 穿透 / 65% 普通伤害；
- MAGIC：充能 +1、状态 +1、35% 穿透、标记元素共鸣；
- HEAVY：清空敌人护甲。

运行时由 `reel_system.gd` 把武器的原型/类型写入映射表，`combat_system.gd` 在结算时读取。原型还决定武器熟练铭印的候选组合（LIGHT→调律/校准、MEDIUM→锋铸/调律、HEAVY→锋铸/暴虐、MAGIC→调律/锋铸）。

> 注意：`resources/archetypes/*.tres` 是**敌人**原型（`EnemyArchetype`），与武器原型同名不同域，不要混淆。

### 7.4 武器与符号的绑定

武器的符号池通过 `SymbolWeight`（`symbol` 资源引用 + `weight` 权重）直接持有 `SymbolData` 资源，**无全局注册表、无 id 查表**。制作新武器时只需在 `.tres` 里内联 `sub_resource` 引用符号资源。

建池时，每个 `SymbolWeight` 展开为 `[符号, 权重, 有效元素, 武器id, 武器base_power]`。符号有效元素由纯函数 `effective_element()` 决定：

```gdscript
if sym.kind == "special":
    return reel_element if reel_element != "none" else sym.element
return sym.element if sym.element != "none" else weapon_element
```

即：普通符号自身有元素就用自身的，否则继承武器 `element`；特殊符号优先取 `reel_element`。

**符号跟随武器图标规则**：`*_slash` 斩击符号永远用携带它的武器图标；其余伤害符号只在该武器仅有它一个 damage 符号时才跟随（90 把中有 16 把带 2 个 damage 符号，避免两格显示同一张图抹掉区分度）。

### 7.5 符号类型与频率

武器符号池里可能出现的 kind：

| kind | 结算 | 连线行为 |
|---|---|---|
| `damage` | 主伤害 | ×1 / ×2 / ×3（三连必暴） |
| `special` | 与 damage 同源（高 base 爆发） | 三连按机制判定破甲 |
| `status` | 挂状态层（burn / frost / poison） | 层数 = 连线 × 暴击倍率 |
| `buff` / `shield` / `heal` | 武器侧不携带（归技能 / 护符） | — |
| `trash`（无效格） | 不结算 | 可滚过规避 |

权重档位：`w≥4 → 4 格` / `w≥2 → 3 格` / 保底 2 格。rare/epic 且单源的功能符号（status/special）封顶 2 格，damage 符号不受封顶；共享符号 ≥2 源可破封顶——这让「双同属性武器」陷阱构筑成为正道。

**武器结构定位（S2 审计）**：90 把武器实际约有 17 种符号结构签名，约 83% 以数值和权重差异为主、存在显著结构重复（这是结构重复度指标，不代表这些武器无价值——签名、三连破甲、命中与暴击差异仍使其可用）。真正具独特机制结构的是 4 把 special 武器 + 11 把 signature 武器 + 15 把穿甲武器。引擎身份中「集中/状态/破甲」充足，「覆盖/对子」稀缺，「防御/治疗」为结构性空白（90 把全为 `role=damage`，符号池 0 个 shield/heal）——这是后续内容深化的重点。

### 7.7 武器成长

武器有两条独立的成长线（均不修改共享 `.tres` 资源，一律走运行时加成表）：

1. **武器熟练（weapon_mastery）**：每房按有效结算累计熟练点，R2/R3/R4 门槛 3/7/12。每次升级给一次「铭印」选择，候选由原型决定（锋铸 +2 攻、校准 +5% 命中、暴虐 +0.25 暴击倍率；「调律」可真实改变符号格数）。重复武器转化为该武器熟练。
2. **武器槽成长（weapon_slot_growth）**：槽位是战斗位置、不是武器身份。换装后新武器立刻继承该槽成长，被换下武器不带走也不留下。每槽最多 2 次通用铭印，单种最多 2 次。

另有跨局的**武器基础强化**：通关最终 BOSS 后的元进度三选一里，本局携带武器各可出一张「+base」候选。

## 8. 符号体系

符号（`SymbolData`，共约 76–80 个）是转轮的最小单位，完全由武器/技能持有、无全局注册表。

**按 kind 分类**：damage / special / status / buff / shield / heal / gold / trash（无效格）。武器侧只有 damage / special / status；shield / heal / buff / gold 主要由技能、护符与常驻金币格提供。

**符号元素继承**：符号自身 `element != none` 时独立生效（覆盖继承），否则继承武器 `element`；special 符号优先取 `reel_element`。符号按有效元素着色（火红、冰蓝、毒绿、光金、暗紫、特殊亮色），玩家一眼分辨吃加成的符号。

**状态符号**：burn（基础伤害 12 / fire）、poison（基础 9 / poison）、frost（基础 0 / ice，纯减攻）。base 即每层实跳伤害（所见即所得）。

## 9. 牌谱与回路

这是最新版本相对早期策划**新增的核心深度层**，让转轮从"看符号"升级为"凑牌型"。

### 9.1 牌谱（Pattern）

由 `PatternData` 资源定义（约 24 种），判定条件放在结构化 `match_rule` 里，由 `PatternMatcher` / `PatternSystem` 统一解析，不在 UI 里写 24 个 if。

- 三条轨道：公共武器牌型 G01–G03（只读武器牌）、武器攻击牌谱 W01–W06（只读武器牌）、技能辅助术式 T01–T03（恰好一张技能牌 + 两张武器牌）。
- 通用牌型每种每回合最多触发一次、加算不乘算；装备牌谱每回合最多触发**一条**，同时满足多条时按 priority 降序、同优先级按 id 升序（无随机、无弹窗）。
- 签名（signature）不增加牌型编号，而是修改所属基础牌谱的解锁/组件/效果，绑定关键武器路径——装上才生效、卸下立即失效。11 把武器拥有专属签名。

### 9.2 回路（Circuit）

回路是本局改造「中奖规则」的奖励内容（如 `circuit_triple_echo`、`circuit_pair`、`circuit_armor_break`、`circuit_damage_shield`、`circuit_status_react`、`circuit_tri_color` 等）。回路最多装备 2 个，不无上限递归。它们与牌谱共同构成「中奖规则」这一改造面。

四类物品各自独立槽位、互不算总：

| 类别 | 数量 | 初始槽 | 上限 | 进转轮池？ | 职责 |
|---|---:|---:|---:|---|---|
| 武器 WeaponData | 90 | 2 | 2（硬限） | ✅ | 普通攻击、精度、MISS、元素、签名（底盘） |
| 技能 SkillData | 40 | 1 | 3 | ✅ | 治疗、护盾、增益、净化、吟唱、连携与特色术式 |
| 消耗品 ConsumableData | 25 | 1 | 4（腰带） | ❌ | 应急资源，按格与 charges 管理，允许同类重复 |
| 护符 CharmData | 45 | 1 | 3 | ❌ | 全局乘区（唯一收集乘区，数值爆炸主引擎） |

- **技能**：一个 `SkillData.symbol + weight` 进入转轮，停轮命中后自动触发，不改成轮外点击战技、不增加主动技能阶段。纯普攻技能进入内容复核。40 个技能涵盖伤害（火/冰/毒/光/暗/无）、恢复、护盾、状态等。

- **消耗品**：腰带 4 格，按 uid 精准使用/卖出。含治疗/强袭/重转/净化/五色元素精华/攻击型（毒刃药剂、炽热瓶、破甲酸液、冰霜瓶等）。

> 总装备量：**200 件**（武器 90 + 护符 45 + 技能 40 + 消耗品 25）+ 符号约 76 个 + 共鸣 3 个。

## 11. 元素克制体系

采用 **v2 互克对 + 同元素 + 毒链**（2026-08-10 拍板），取代旧五元单向环。全部关系一句话可解释：

```text
克制 ×1.5：火→冰（融化）、火→毒（消毒）、冰→火（灭火）、
           光→暗（驱散）、光→毒（净化）、暗→光（吞噬）、毒→暗（腐蚀）
抵抗 ×0.85：同元素对打（宝可梦式同属性减伤）、毒打火/光
中性 ×1.0 ：其余组合；任意一方为 none
```

| 攻击\防守 | 火 | 冰 | 毒 | 光 | 暗 |
|---|---|---|---|---|---|
| 火 | 0.85 | 1.5 | 1.5 | 1.0 | 1.0 |
| 冰 | 1.5 | 0.85 | 1.0 | 1.0 | 1.0 |
| 毒 | 0.85 | 1.0 | 0.85 | 0.85 | 1.5 |
| 光 | 1.0 | 1.0 | 1.5 | 0.85 | 1.5 |
| 暗 | 1.0 | 1.0 | 0.85 | 1.5 | 0.85 |

**武器定位**：火/光期望 ×1.17（双克，强势）；冰/暗 ×1.07（均衡）；毒 ×1.01（攻击面最弱，以 DoT 补偿）；无属性 ×1.00（稳健基准）。

HUD 从敌人视角显示「弱 火 ×1.5 / 抗 毒 ×0.85」，玩家无需背表。克制命中累计充能、触发元素爆发（见 §6.3）。

## 16. 技术架构

- **数据即 Resource**：符号 / 武器 / 技能 / 护符 / 消耗品 / 房间 / 牌谱全部 `.tres`，`@export` 直接引用，**禁止全局注册表 / 枚举字典查表**。加内容 = 新建 `.tres`，不改代码。
- **资源扫描**：`resource_scan.gd` 用 `ResourceLoader.list_directory()` 按目录自动发现 `.tres`（导出后资源进 PCK，禁用 `DirAccess.get_files()`）。
- **表现 / 逻辑分离**：`duel_controller.gd` 主状态机 + 纯逻辑编排，`battle_hud.gd` 纯 UI（5 套覆盖层：整备/奖励/元进度/商店/铁砧，各自独立 `.tscn`）。控制器经只读快照驱动 HUD，单向数据流。
- **纯结算抽离**：`battle_math.gd`（全 static func）做纯数学聚合，`combat_system.gd` 做战斗结算主逻辑，`reel_system.gd` 建带与转轮，`element_counter.gd` 克制矩阵，`pattern_system.gd` / `circuit_system.gd` 管理牌谱与回路。
- **子系统拆分**：正在把 duel_controller 拆为 5 个 RefCounted 子系统（MetaStore、AnvilSystem 已完成，Shop/Reward/Loadout 收尾中），子系统 `_init(ctrl)` 注入、不持有 meta。
- **RNG 纪律**：战斗演出随机走独立 `RandomNumberGenerator` 实例，特效走 `Px.Rng`，禁全局 `randf()`；随机生成不因演出/开关商店/重复点击消耗额外随机流。
- **特效**：统一使用 `pixelfx-godot` 库烘焙的 `.res` SpriteFrames（自包含内嵌纹理），如斩击 `sword_slash.res`。
