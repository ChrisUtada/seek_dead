# Seek Dead · 核心玩法全局优化与重构执行方案

> 日期：2026-11-19  
> 文档性质：目标策划案 + 制作任务书 + 验收合同；**不是实施完成记录**  
> 核心命题：局内成长不是收集卡牌或升级角色，而是通过战后三选一与武器替换，持续改造老虎机的符号构成、中奖规则和滚轴操控，最终形成独特的中奖引擎。

## 0. 执行摘要

### 0.1 总结论

Seek Dead 已经有足够的内容和一个有辨识度的战斗底座，不需要再做一轮“加武器、加卡牌、加成长树”。当前最需要的是把分散的系统收束成一条可感知的主线：

```text
武器决定底盘
→ 战后选择直接修改符号带 / 赔付规则 / 操控能力
→ 下一房通过目押兑现修改
→ 敌人与路线迫使玩家继续调整
→ Boss 验收当前引擎
→ 局末总结“我这台机器如何形成”
```

当前主要矛盾不是内容少，而是：

1. **符号改造很快触顶**：权重只映射为 2/3/4 格，灌注上限使改造空间很快耗尽。
2. **中奖规则没有形成正式成长入口**：`rule_mod` 当前禁用，已有牌谱参数覆盖能力没有对应正式内容。
3. **武器替换与武器获取混用**：普通 Draft 主要从局外 `owned_weapons` 生成换装，不是本局新武器获取。
4. **成长轴重复**：熟练、武器铭印、槽位铭印、研磨、锻魂、符号强化和护符共同争夺同一数值职责。
5. **三选一并不总能表达“改造机器”**：技艺、治疗、金币和只写构筑分数的共鸣会稀释核心承诺。
6. **奖励与敌人节奏未完全服务引擎成长**：精英奖励堆叠，Boss 信物不一定进入最终展示，完美目押探针仍出现爆发性死亡。

因此，推荐做一次**有安全门的结构性收束**，而不是推倒重做：保留三列单赔付线、手动目押、双武器、元素、牌谱、敌人和地图资产；重构局内状态归属、符号带编辑粒度、奖励生成契约和规则结算顺序。

### 0.2 最重要的产品决策

本方案默认拍板以下方向，实施时不再反复翻案：

- 战后卡片只是“改造操作”的呈现方式，**不是需要收集和升级的卡牌**。
- 普通/精英战后三选一的常规候选全部属于引擎改造；通用技艺、纯治疗和纯金币不再作为常规主池类别。
- 武器分为“本局新获得”和“本局仓库换装”，两者分开生成、展示和统计。
- 局外解锁只决定“什么内容可能出现”，不等于每局免费拥有全部历史武器。
- 固有牌谱继续由装备自动激活；本局获得的规则改造另称“回路”，最多装备 2 个。
- 目押基础可读性属于产品质量，不应靠抽到缓速奖励才能正常使用。
- 删除旧成长前必须先通过输出曲线、低分位局和真人验收安全门。
- 铁砧删除的是“点数 + 随机摇奖”，不是图鉴、成就、定向解锁或已有收藏。

### 0.3 预期成果

完成本方案的核心阶段后，玩家在一局内应能明确说出：

> “我开局用的是两把普通武器；后来我删掉了低效符号、把火符集中起来，装上了对子赔付回路，并保留了一次单轴复转。现在这台机器靠对子和状态反应赢，不只是攻击数字变大了。”

这句话是本方案最重要的体验验收标准。

### 1.1 本次核查范围

本次只读核查覆盖：

- 核心战斗：转轮建带、目押、符号贡献、三连、元素、破甲、充能、牌谱、状态与演出顺序。

### 1.4 数据解读限制

- 自动探针的“完美目押 + 固定最高权重伤害符号”不是真人最优策略，0/6 不能直接等价为游戏不可通关。
- 现有部分文档仍把牌谱写为 21 张或“签名需习得”；当前资源和 `pattern_system.gd` 已改为 20 张、签名随武器生效。后续以代码和资源为准。

- 本文没有重新运行测试，因此不宣称当前测试全绿，也不把历史测试记录当成本次验证结果。

## 2. 设计北极星、支柱与非目标

### 2.1 北极星

> **玩家经营的不是角色等级或卡册，而是一台会被持续拆解、重组和改写的中奖机器。**

每次有效成长至少改变以下一项：

1. **会停出什么**：新增、删除、转化、集中符号。
2. **停出后如何赔**：新增对子、混合元素、状态、位置等规则。
3. **玩家如何影响落点**：预览、制动、保留、复转或坏格补救。
4. **机器用什么底盘运行**：获取或替换武器，改变符号池和固有签名。

### 2.2 五项设计支柱

| 支柱 | 要求 | 反例 |
|---|---|---|
| 改造可见 | 选择前后能看到真实对象、格数、规则和来源 | “构筑 +1”“增强方向” |
| 下房兑现 | 普通奖励应在下一场战斗中有机会被感知 | 整局不触发的被动 |
| 选择有权衡 | 强度、浓度、覆盖、生存和操作之间需要取舍 | 无代价全局乘区 |
| 随机可修正 | 有路线、重抽、换装和精简，不靠隐藏动态评分替玩家选 | 三个无效候选 |
| 结算可归因 | 大数字能回答“由哪个符号、牌谱、回路和乘区产生” | 多系统同名叠加且不可查 |

### 2.3 非目标与冻结项

核心阶段明确不做：

- 不做卡组收集、卡牌等级、角色经验或属性等级。
- 不增加第四列、第二赔付线或更多常驻乘区。
- 不让正常 SPIN 消耗金币，不用收费制造时长。
- 不用永久攻击/生命作为跨局主要奖励。
- 不为 90 把武器各做一棵成长树。
- 不用更多静态卡牌掩盖动态目标生成问题。
- 不在新输出曲线未通过前直接删除熟练、铭印、锻魂等旧支撑。
- 不用堆敌人 HP 或拉长动画证明成长有价值。

## 3. 目标跑局闭环与节奏

### 3.1 单回合

```text
读取敌人意图与本幕 Boss 目标
→ 选择本回合目标（输出 / 防御 / 状态 / 破甲）
→ 使用有限操控（可选）
→ 手动按停三列
→ 基础符号结算 → 固有牌谱 → 回路 → 敌方修正
→ 看懂结果并调整下一回合目标
```

目标体验：普通回合有技巧但无额外菜单；只有玩家主动使用操控时才增加操作。

### 3.2 单房间

| 环节 | 玩家得到什么 | 时间目标 |
|---|---|---:|
| 普通战斗 | 一次明确的三选一改造 | 45–75 秒 |
| 精英战斗 | 一次高质量、带主题倾向的改造 | 75–120 秒 |
| Boss | 一个高潮包：遗物 + 主题武器/高级改造 | 2–4 分钟 |
| 非战斗节点 | 路线、经济、精简或换装决策 | 10–35 秒 |

时间仅为真人测试目标，不靠增加等待达到。

### 3.3 单幕

每幕至少形成三次可复述变化：

1. 一次符号构成变化；
2. 一次规则或操控变化；
3. 一次武器获取/替换或有方向的精简。

幕底 Boss 应检验本幕主题，而不是只检验数值是否达标。

### 3.4 整局

- 完整三幕真人目标时长先维持 **30–40 分钟**，超过 45 分钟优先减少重复战斗与无效间歇。
- 普通 2–4 回合、精英 4–7 回合、Boss 6–10 回合作为首轮观察窗。
- 每局至少能形成一个主引擎身份和一个辅助应对手段。
- 玩家失败后应能指出“构筑、路线、操作或资源决策”中的原因，而不是只说“没抽到”。

## 4. 目标系统结构：一台机器，四个改造面

| 改造面 | 核心对象 | 常规来源 | 数量约束 | 主要职责 |
|---|---|---|---|---|
| 底盘 | 当前装备武器、本局武器仓库 | 战后、藏库、精英、Boss、商店 | 装备 2，仓库有上限 | 符号池、基础效能、命中、签名与元素 |
| 符号带 | 实际格子、符号效果、来源 | 普通/精英 Draft、休整、事件 | 由真实格子与保护规则限制 | 决定停出什么、目标密度与循环 |
| 中奖规则 | 固有牌谱 + 本局回路 | 牌谱随装备；回路随 Draft | 回路装备 2 | 决定什么组合如何赔付 |
| 滚轴操控 | 信息、节奏、保留、复转、补救 | Draft、少量武器特性 | 主动能力有次数，被动有触发上限 | 决定玩家能怎样影响过程 |

外围系统只服务这四个面：

- 金币：重抽、商店、定向服务。
- 治疗/护盾：路线与战斗风险管理。
- 技能：作为符号来源进入机器，不建立第二套角色升级。
- 护符：整备期横向修正。
- Boss 遗物：稀有规则或引擎顶点，不再只是普通护符数值。
- 图鉴/生涯/铸式：提供下一局的新选项，不提供永久强度墙。

## 5. 核心系统优化规格

## 5.1 武器：把“获得、换装、收藏”彻底分开

### 三种状态

| 状态 | 含义 | 能否直接用于本局换装 |
|---|---|---|
| 局外已解锁 | 永久图鉴与内容池资格 | 否，只决定能否在本局出现 |
| 本局已拥有 | 本局实际拾取、购买或开局携带的武器 | 是 |
| 当前已装备 | 正在贡献符号的两把武器 | 已生效 |

当前普通 Draft 从局外收藏生成候选，容易让“永久解锁”直接变成“本局免费仓库”。目标是新增明确的**本局武器仓库**，永久收藏只承担解锁与图鉴职责。

### 两类武器奖励

**`weapon_acquire`：新武器获取**

- 从当前幕、来源、局外解锁和主题条件允许的池中选取。
- 展示时冻结具体武器、品质和来源。
- 获得后写入本局仓库；装备满时进入替换预览。
- 首次发现可写局外图鉴，但图鉴写入与本局获得是两个独立结果。
- 普通池可以低频出现；藏库、精英和 Boss 是主要定向来源。

**`weapon_swap`：本局仓库换装**

- 只从本局已拥有且未装备的武器生成。
- 卡面明确标“本局仓库换装”，不能伪装成新掉落。
- 主要解决元素应对、签名切换和构筑修正，不单独视为纵向变强。
- 仓库为空时类别自动失效，不用无效卡补位。

### 替换预览必须展示

- 新旧基础效能、命中/废铁、暴击和符号真实格数。
- 新增、减少和保持的符号及来源。
- 获得与失去的固有牌谱、签名和元素覆盖。
- 哪些改造跟随符号路径保留但休眠，哪些槽位效果继续继承。
- 换下的武器仍留在本局仓库，之后可再次换入。
- 确认前取消不消耗奖励；确认后只结算一次。

### 内容制作规则

90 把武器先做“机制身份审计”，不继续按稀有度复制同模板。每把正式武器至少回答：

1. 它服务哪种引擎？
2. 它换谁？
3. 它在哪个敌人或 Boss 前更有价值？
4. 它的代价是命中、浓度、覆盖、延迟还是资源？
5. 它与同 `unique_group` 的武器有什么实际玩法差别？

建议先选 12 把旗舰武器完成闭环，再决定其余资源的合并、重做或保留为收藏变体。

## 5.2 符号带：从“权重档位”升级为“真实格子编辑”

### 当前问题

`cells_for()` 把聚合权重映射为 2/3/4 格，使大量不同权重产生相同结果；符号灌注最多两次，且许多武器共享同一结构。它适合早期原型，不足以支撑整局持续改造。

### 推荐目标模型

**一格就是一单位构成，所有修改都直接落到真实格子。**

首轮原型采用最直观的规则：

- 武器/技能资源中的符号权重整数化，直接对应基础格数。
- 运行时修改用“目标符号 +N / -N 格”，不再经过 2/3/4 档。
- 最小带长仍可通过整份平铺维持视觉循环，但不得改变符号占比。
- 同一 `(符号路径, 有效元素)` 聚合；来源分配继续可追踪。
- 所有预览、结算、精简、灌注和图鉴共用同一个真实带模型。
- 不修改共享 `.tres`；修改只写本局运行时状态。

若直接整数化导致总带长或平衡波动，再用固定 36 格 + 最大余数分配作为对照原型；不得在正式版同时保留两套口径。

### 六类基础操作

| 操作 | 玩家看到的变化 | 核心限制 |
|---|---|---|
| 集中 | 目标符号 +N 格，总带长相应变化 | 有每符号预算，展示占比变化 |
| 转化 | 来源符号 -N，目标符号 +N，总带长不变 | 双方明确，不能制造无伤害死带 |
| 精简 | 非核心符号 -N 或移除 | 每把武器保留核心，次数有限 |
| 添入 | 添加一个具体新符号 | 展示来源、格数与稀释代价 |
| 刻印 | 目标符号自身伤害/状态/防御参数提高 | 只改实际读取的参数，有叠加上限 |
| 校准 | 目标武器 MISS/命中变化 | 展示实际废铁格变化，不只写百分比 |

“集中”和“转化”不能只是同一效果的两种文案：前者扩张循环，后者保持循环并牺牲另一符号。

### 合法性规则

- 满血不是符号改造的唯一过滤；所有卡都要按目标、预算和实际变化过滤。
- 共享符号必须显示作用范围：所有来源还是指定武器来源。
- 换武器后，不再存在于带中的改造保留记录但休眠，不暗中退款。
- 不允许删除到最后没有有效输出，不允许删除敌人临时注入的废铁。
- 纯 `run_power_bonus` 全局加伤不再作为常规符号改造主内容；只保留给幕间确定性基准或明确兜底。

## 5.3 中奖规则：固有牌谱与本局回路双层结构

### 边界

| 类型 | 获得 | 生效 | 是否占回路槽 |
|---|---|---|---|
| 通用赔付 | 游戏基础规则 | 满足牌型自动生效 | 否 |
| 装备牌谱 | 由当前装备条件决定 | 满足牌型自动生效 | 否 |
| 武器签名 | 携带指定武器 | 满足专属牌型自动生效 | 否 |
| 本局回路 | 战后三选一获得 | 按声明事件触发 | 是，最多 2 |

不再提供“某牌谱伤害 +25%”式的回路，也不恢复签名图纸。回路必须带来新的组合监听或赔付方式。

### 统一结算顺序

```text
落点快照
→ 基础符号贡献
→ 通用连线/三连
→ 当前装备牌谱与签名
→ 已装备回路（固定优先级 → 槽位顺序）
→ 明确的回合级修正
→ 敌方护甲、护盾、状态和伤害闸口
```

要求：

- 旧三连奖励与新牌谱不能重复表达同一效果而不向玩家解释。
- 每轨的互斥和优先级必须在“当前赔付表”中可查。
- 每个回路声明触发事件、目标、每 SPIN/回合/房间上限、是否允许连锁。
- 回路默认只响应原始事件，不能由自己的追加结果再次触发自己。
- 表现可聚合，结算效果绝不能因飘字条数而截断。
- 不做开放递归脚本语言；首版只支持经过测试的白名单事件。

### 启用门槛

`rule_mod` 只有同时满足以下条件才重新进入正式池：

- 至少 6 个机制不同的回路，覆盖至少 4 类组合条件。
- 每个回路有可达性过滤、真实结算、独立反馈和递归测试。
- 构筑摘要能查看、比较和替换回路。
- 固定种子证明不存在“合法展示但整局无法触发”的常见情况。
- 最多 2 个的替换流程和输出曲线通过验收。

## 5.4 滚轴操控：提升代理感，不取消目押

### 当前三项的处理

| 当前能力 | 评价 | 目标处理 |
|---|---|---|
| 废铁改判 | 有补救价值，但自动选择相邻格，代理感有限 | 保留为被动补救，明确选择规则与次数 |
| 废铁转化 | 属于经济缓冲，不是输出成长 | 可保留低频，按经济价值评估 |
| 缓速启动 | 可能是在收“基础可读性税” | 先保证基础可读；再决定保留为奖励或迁入辅助选项 |

### 目标能力结构

操控池至少覆盖四个不同维度，而不是三张废铁卡：

1. **信息**：更多后续格预览或当前目标提示。
2. **节奏**：指定列短时制动。
3. **保留**：保留一列到下一次 SPIN。
4. **修正**：有限单轴复转或废铁补救。
5. **转化**：坏格变资源，但不消除失败结果。

基础目押必须无需任何奖励也能学习和复现。操控奖励提供新的策略，不是修复界面。

### 操作约束

- 默认回合不增加确认步骤。
- 主动能力每房/每战斗有明确次数，按钮在使用时才突出。
- 复转若需要结算前窗口，只在玩家实际拥有且点击时展开。
- 敌人锁轮、冻结、注废和夺轮必须与普通操作失败有不同反馈。
- 操控不变成“每次必三连”的自动赢按钮。

## 5.5 技艺、技能、护符与资源的归属

### 技艺

普通/精英 Draft 不再把通用技艺作为常规类别。现有内容按以下方式迁移：

- 守势/蓄能：只保留一个清晰的每房护盾效果，可转休整、事件或护符。
- 积蓄/回收/余裕：只保留有决策差异的一种，其余转经济节点或删除。
- 坚韧/回春：转休整、事件或明确生存来源。
- 备用药剂：空腰带禁止出现；若改为复合卡，必须先给具体消耗品再增加次数。
- 不为维持八项而保留同义卡，不再设“前三房技艺保底”。

### 技能

技能继续是“选入转轮的功能符号”，不是角色技能等级。技能增加必须同时展示收益和稀释成本；休整可提供技能卸除。

### 护符与 Boss 遗物

- 护符：整备期选择，服务开局路线和横向变体。
- 遗物：Boss 获得，本局拥有即生效，不占护符槽。
- 两者可共享结算接口，但不在玩家认知上混成同一收集品。
- 普通乘区必须有总预算；遗物优先提供引擎规则顶点，不再只是 +攻击或 +护盾。

### 生存与经济

治疗、金币、护盾仍有价值，但常规入口移至：

- 战斗中的治疗/护盾/金币符号；
- 休整、事件、商店和路线奖励；
- 战后自动战果；
- 引擎池确实耗竭时的合法兜底。

这样避免玩家连续几场在“改造机器”和“拿 12 金”之间做与核心无关的选择。

## 5.6 消耗品扩展：临时元素调谐剂

### 定位

增加一组火、冰、毒、光、暗元素调谐剂，用于让玩家根据已公开的幕底 Boss 临时调整输出方向。它属于**消耗品驱动的引擎备战**，不是永久武器改造，也不进入普通/精英战后三选一主池。

示例承诺：

> **寒冰调谐剂**：下一场战斗中，选择一把已装备武器，其来源的伤害与特殊符号按冰元素结算。基础数值、状态类型和武器签名不变。

### 使用规则

| 项目 | 设计口径 |
|---|---|
| 目标 | 玩家主动选择一把当前装备武器 |
| 持续时间 | 下一场战斗；进入战斗时明确显示调谐状态 |
| 修改内容 | 该武器来源伤害/特殊符号的有效元素 |
| 不修改 | 基础攻击、命中、暴击、状态类型、签名归属和永久资源 |
| 叠加 | 同类不可叠加；后使用覆盖前一次，不叠倍率 |
| 使用时机 | 优先服务 Boss 战前准备；战斗中可作为应急 |
| 获取方式 | 商店、事件、精英或 Boss 前路线中的定向补给 |

### 与既有系统的分工

- **元素调谐剂**：保留下一场的符号构成，只改变一把武器的输出元素；消耗资源，解决短期应对。
- **武器替换**：长期改变底盘、符号池与固有签名；承担持续构筑取舍。
- **现有元素精华**：向本房转轮添入对应元素符号，保留新增符号带来的稀释代价。

三类入口不能互相伪装成同一效果。调谐剂不得转换燃烧、霜冻等状态类型，也不得改变签名所需的关键武器，否则会同时扰乱元素、DoT、牌谱与武器身份。

### 投放与平衡约束

- Boss 进幕公开后，玩家应能通过路线或商店主动追逐调谐剂，不能完全依赖临近 Boss 的随机掉落。
- 它是救场与备战选择，不应成为每个 Boss 前必须购买的税款；若接近必买，先调整投放与经济成本，不直接削弱元素倍率。
- 单场、单武器、一次性是防止它取代长期换装的核心限制。
- 当前真·最终 Boss“勇者的阴影”为无元素，因此调谐剂只服务常规幕底 Boss；最终 Boss 的备战仍由净化、操控、保留和复转等非元素对策承担。
- 验证时分别记录购买率、实际使用率、Boss 回合数、武器换装率和双元素构筑使用率；若换装或双元素路线明显萎缩，优先收紧投放与持续时间。

## 6. 战后三选一：生成与结算合同

## 6.1 常规类别与初始权重

内容全部达到启用门槛后的首轮基线：

| 类别 | 初始权重 | 内容 |
|---|---:|---|
| `symbol_mod` | 35% | 集中、转化、精简、添入、刻印、校准 |
| `rule_mod` | 25% | 新组合与新赔付回路 |
| `weapon` | 25% | 新武器获取与本局仓库换装，分开记录 |
| `reel_control` | 15% | 信息、节奏、保留、复转、补救 |
| **合计** | **100%** | 常规池不再混通用技艺和纯资源 |

这些只是基础抽样参数。经过合法性过滤、组内约束和来源修正后，最终展示分布需要另行统计，不能要求仍机械等于此表。

任何类别内容未就绪时权重为 0，在剩余合法类别间归一化；禁止放空效果卡维持比例。

## 6.2 候选生成顺序

1. 固化房间、来源、幕次、当前引擎和本局仓库快照。
2. 各 Provider 生成**全部合法动态候选**，不得先随机只注入一个符号或一把武器。
3. 过滤未解锁、无目标、零变化、已拥有的一次性能力、满层和当前不可达成的回路。
4. 按可用类别归一化权重。
5. 逐槽应用软偏置和多样性，不让槽位偏好变成固定顺序。
6. 在类别内按稀有度与具体权重抽取。
7. 检查组内操作差异、目标差异和同族重复。
8. 保证至少一个“结构改造”：新武器、构成变化、新回路或新操控；纯数值卡不能独占整组。
9. 最终重新验证三张卡的数量、唯一性、目标、预算和可结算性。
10. 冻结具体目标、数值、替换要求和预览结果，再展示。

## 6.3 硬约束

每次普通/精英 Draft 必须：

- 恰好三张，ID 不重复，全部可结算。
- 不出现当前零收益、无目标或不可达成项。
- 不出现已拥有的一次性能力。
- 至少两张属于不同操作族；禁止三张都是同一数值模板换皮。
- 至少一张能改变结构，而不是三张都只有 +伤害/+金币。
- 动态卡展示具体对象与真实前后变化。
- 候选不足时使用合法通用引擎兜底，不允许缩成一两张。

软约束包括槽位倾向、类别多样性、稀有度和共现价值；任何软约束都不能突破硬过滤。

## 6.4 稀有度

- 普通来源可从 70/25/5 开始，精英使用独立高质量来源表。
- 稀有度表示机制影响范围、复杂度或来源稀缺，不等于无条件更大数值。
- 先在合法类别内抽稀有度；空层只在本类别现有层间归一化。
- 不为了凑稀有度跨类别补卡。
- 所有动态目标卡也必须有明确的稀有度语义，不能统一标“进阶”只用于改变权重。

## 6.5 重抽、跳过与兜底

- 保留整组付费重抽，首次 5 金，之后每次 +5。
- 重抽保持来源与结构约束；存在其他合法组合时不得返回完全相同三张。
- 重抽重新冻结目标，禁止展示与结算对象不一致。
- 跳过免费且无补偿，是合法策略。
- 通用兜底优先使用真实的小幅引擎改造；只有引擎池彻底耗竭才用金币/护盾。
- 兜底率、重抽后相同组率、结算失败率必须进入遥测。

## 6.6 结算事务

- 先生成完整 Apply Plan，再统一提交；任何校验失败都不得修改部分状态。
- 多效果奖励必须全部预检通过，失败时保持原状态。
- 武器替换等待玩家选择旧武器时，不消耗奖励、不标记已结算。
- 效果、日志、图鉴、本局仓库和转轮重建必须来自同一冻结结果。
- 选择完成后，玩家能立即在机器摘要中复核变化。

## 7. 奖励来源与房间职责

| 来源 | 目标内容 | 不再做什么 |
|---|---|---|
| 普通战 | 一次标准三选一改造 | 不再叠额外成长欠选 |
| 精英战 | 一次高质量三选一，至少一个主题/高影响候选 | 不再同时自动堆护符、主题武器和普通 Draft |
| Boss | 遗物自动获得 + 同屏一个主题武器或高级改造选择 | 不把必得遗物混入随机三张后可能消失 |
| 藏库 | 两把具体新武器选一，完整换装预览 | 不用抽象“武器卡” |
| 商店 | 确定性购买、卖出、重抽与定向服务 | 不让免费掉落按高价无限变现 |
| 休整 | 回血 / 精简 / 卸除技能等二选一 | 不只是无决策回血按钮 |
| 事件 | 有代价的符号、回路或资源变化 | 不只是随机发 maxHP/护盾 |
| 幕间 | 暂时保留确定性锻魂，后续可改定向淬炼 | 新曲线未过门前不删除 |

### 精英奖励的推荐结构

精英 Draft 仍只让玩家做一次主选择，但通过来源参数体现高价值：

- 至少一个武器获取、符号结构改造或高阶回路；
- 更高的 uncommon/rare 条件概率；
- 可有本房克制主题，但不能强制塞入当前完全不适配的武器；
- 不再额外自动掉一个护符和一把武器。

### Boss 奖励的推荐结构

Boss 胜利同屏完成：

1. 战果与专属遗物自动入账，演出一次；
2. 展示两个主题武器/高级改造候选，玩家选一个或跳过；
3. 不增加第二个奖励页面；
4. 最终 Boss 保留特殊结局与独立收束，不套普通掉落。

## 8. 战斗、敌人与 Boss：成为引擎的考题

## 8.1 每回合必须有可读的决策

敌方意图至少回答：会做什么、预计后果、影响哪列/资源、当前有哪些真实对策。现有 ReadabilitySystem 已具备基础，应保留并统一为正式信息层。

推荐每回合只突出一个主问题：

- 重击：防御、治疗、抢攻或硬吃。
- 高甲：破甲、穿透或磨甲。
- 注废/锁轮：净化、保留、利用坏格回路或照常输出。
- 恢复窗：治疗、准备或集中爆发。
- 残血：收尾，不再拖长无决策回合。

提示只列当前真实存在的对策，不替玩家自动选择。

## 8.2 普通怪与精英的教学分工

| 阶段 | 普通怪职责 | 精英职责 |
|---|---|---|
| ACT1 | 单机制教学：克制、破甲、重击、基础状态 | 检验一个已教学机制 |
| ACT2 | 两种机制组合，迫使换目标 | 检验换装、浓度或资源管理 |
| ACT3 | 组合压力与引擎完整性 | 检验回路、操控和应急能力 |

DoT 不能只在专项探针中成立。状态武器出现、目标高亮、层数阈值和爆发预告必须让玩家看得懂并愿意主动停状态符号。

## 8.3 Boss 设计规范

每个 Boss 必须有：

- 一句可复述的机制身份；
- 至少两条不同构筑的对策，不设单一元素硬门；
- 明确的蓄势、爆发和恢复信息；
- 阶段变化改变玩家目标或滚轴规则，而不只是加攻加甲；
- 与主题武器、遗物和图鉴目标相互呼应。

### 爆发安全线

首轮真人/模拟验收采用以下规则：

- 非终局狂暴状态下，单次未充分预告的攻击不应从健康血量直接杀死玩家。
- 超过玩家当前最大 HP 35% 的预期伤害必须提前至少一回合明确预告，并展示至少一种真实对策。
- 多段伤害要按总预期评估，不能拆成多段绕过安全线。
- 若完美操作仍频繁死亡，先检查构筑补给与爆发窗口，不直接增加玩家全局伤害。

### 去同质化

“每 N 回合施压、下一回合恢复”可作为节奏工具，但不能成为大多数 Boss 的全部身份。每个 Boss 至少有一个独占变量：护甲循环、锁列语言、元素切换、律法条件、资源剥夺、罪业累积或特殊和解。

## 8.4 爽感与数值纪律

- 三连、破甲、克制核爆仍是主要高潮，不另加同级常驻爆发系统。
- 大数字拆分为符号基础、连线、关键牌谱/回路、回合修正和敌方结算。
- 百分比最大 HP 伤害要单独记录占比，防止绕过构筑成为唯一答案。
- 护符、Buff、回路和签名的乘区顺序固定且可回看。
- 同类飘字可合并，详细日志必须保留来源。

## 9. 地图、路线与经济

## 9.1 正式地图方向

分岔 DAG 比开放网格更适合本作：地图负责风险与构筑方向，转轮负责主要玩法。建议在完整 F6 后将分岔图设为唯一正式模式，线性仅保留调试和回归入口，不继续维护两套正式平衡。

目前 15 层/幕先作为内容上限原型，不直接锁定正式节奏。真人计时后可在 11–15 层间调整；减少的是重复节点，不是必要的构筑选择。

## 9.2 路线必须提供构筑代理感

- 进幕公开 Boss、元素和机制主题。
- 节点图标之外显示奖励倾向，如“藏库：新武器”“休整：精简”“精英：高阶回路”。
- 精英、藏库、休整、商店应能纠正不同坏局，而不是都只是随机奖励。
- 路线选择形成“更多改造机会 vs 生存/经济”的取舍。
- 不在 Draft 内做隐藏的情境评分替玩家做决定；把方向选择上移到玩家可见的路线。

## 9.3 经济闭环

金币的合理使用出口：

- Draft 整组重抽；
- 商店购买具体武器、技能、消耗品和护符；
- 定向符号转化/精简服务；
- 少量应急恢复。

需要持续观察：

- 起始 25 金与利息是否令早期商店有真实选择；
- 重抽价格和商店价格是否争夺同一笔预算但不形成死亡螺旋；
- 免费物品变现是否形成无限或高收益循环；
- 后期是否有合理金币出口，不靠不断加新货币解决。

不为经济系统新增“碎片、精华、改造点”等平行货币。

## 10. 局外成长、复玩与存档

## 10.1 铁砧迁移

推荐“条件解锁 + 定向选择”替代随机摇奖：

```text
击败 Boss / 达成生涯行为 / 完成武器挑战
→ 解锁一个明确的新武器、护符、技能或铸式
→ 图鉴展示新玩法与下一目标
→ 下一局可选择新的开局路线
```

保留：`owned_*`、图鉴、生涯、铸式、来源记录和已有收藏。  
删除或退役：点数 drip、随机摇奖、空白、随机保底、重复返还和相关假三选一。

老存档原则：

- 已解锁内容绝不回锁。
- 已有点数不清空作废；推荐每 10 点折算一次**玩家自选定向解锁**，用完后退休旧字段。
- 铸式当前依赖历史 R2，必须先迁移为“完成指定武器行为条件”，再移除局内熟练数值。
- 图鉴保留历史使用记录，但不再展示失效的 R 等级门槛。

## 10.2 复玩目标

优先级依次为：

1. 不同引擎路线与 Boss 对策；
2. 生涯成就和定向解锁；
3. 武器铸式等横向形态；
4. 少量改变决策的挑战；
5. 最后才考虑 Boss Rush 或大型 GAME+。

挑战不能只增加 HP/ATK，应改变路线、符号带、操控或奖励规则。

## 10.3 局末总结

局末不只显示技艺数和熟练 R 等级，应显示：

- 最终两把武器与本局替换路径；
- 最关键的符号构成变化；
- 两个回路及其触发次数；
- 操控使用次数与实际补救结果；
- 本局主引擎名称/标签；
- 新解锁与下一局可追逐目标。

## 10.4 局内续玩

当前只持久化大厅。完整局目标达到 30–40 分钟后，建议增加房间/节点边界的续玩存档：

- 只在节点完成或房间间歇保存；
- 不保存到 SPIN 中途；
- 保存本局仓库、真实带修改、回路、操控、路线与 RNG 可复现状态；
- 这是核心稳定后的 P2 项目，不与本轮结算重构同时铺开。

## 11. UI、可读性与新手引导

## 11.1 三选一界面

每张卡必须包含：

- 操作类型图标：底盘 / 构成 / 规则 / 操控；
- 具体对象；
- 当前 → 修改后；
- 生效范围与次数；
- 构筑代价或失去内容；
- 稀有度只在确有语义时显示。

顶部战果栏保留，但不增加额外确认页。底部始终可见重抽价格、跳过和当前机器摘要入口。

## 11.2 机器摘要

提供一个统一面板回答：

- 当前两把武器和本局仓库；
- 每个符号的真实格数、占比和来源；
- 当前可触发牌谱/签名与所需牌型；
- 已装备回路、触发条件和次数；
- 操控能力与剩余次数；
- 关键生存与经济状态。

该面板同时服务整备、换装预览、战后复核和局末总结，不再为每个入口写不同口径。

## 11.3 目押与辅助

- 视觉中心、输入缓冲、预览和实际落点必须一致。
- 基础预览与反馈不能依赖奖励。
- 缓速、额外预览可作为奖励时，必须仍有其他构筑价值或明确辅助定位。
- 反馈不遮格，不为精准目押再增加隐藏伤害乘区。
- 建议提供速度/预览的辅助选项，但与奖励遥测分开记录。

## 11.4 新手引导

首局只教四件事：

1. 停符号会结算；
2. 武器改变符号带；
3. 战后选择会真实改造机器；
4. 敌人意图提示本回合对策。

回路、复杂签名和局外铸式在玩家遇到时再解释，不在开局堆教程弹窗。

## 12. 首批内容制作包

以下内容是用于形成最小闭环的**模板 brief**，不是免验收的直接上线清单。

## 12.1 符号改造模板

| 模板 | 示例承诺 | 合法性/限制 | 主要验收 |
|---|---|---|---|
| 集中 | 指定符号 +2 格 | 单符号预算；展示总带长与占比 | 下房实际格数一致 |
| 转化 | A -2 格，B +2 格 | 玩家知道 A/B；总带长不变 | 不制造死带 |
| 精简 | 非核心符号减少 2 格 | 核心保护；次数有限 | 精简不是无条件最优 |
| 添入 | 加入具体符号 2 格 | 明示稀释与来源 | 新符号能结算 |
| 锋刻 | 指定伤害符号基数 +2 | 最多 3 层；不做全局伪装 | 伤害分解可归因 |
| 状态刻印 | 指定状态符号 +1 层 | 只对真实状态符号 | 层数与 DoT 正确 |
| 守备刻印 | 指定护盾/治疗符号增强 | 不读取无效攻击参数 | 真实入账一致 |
| 校准 | 指定武器命中 +5% | 接近上限过滤 | MISS 格前后一致 |

动态模板按当前合法目标实例化，不需要为每个符号复制静态卡。

## 12.2 首批回路方向

| 回路 | 触发条件 | 初始效果 brief | 限制与边界 |
|---|---|---|---|
| 对子赔付 | 恰好一对同族伤害，第三张不同 | 对子部分追加 35% 效能 | 每 SPIN 一次，不与三连同时触发 |
| 两端呼应 | 第 1、3 列同族，中列不同 | 两端各追加 25% 效能 | 只响应原始符号 |
| 末符回响 | 第三列为有效伤害且至少一个其他有效符号 | 末符追加 40% 基础效能 | 每 SPIN 一次，不再触发回响 |
| 异色协奏 | 三列是三种不同有效元素 | 追加本次伤害 20% 的穿透 | 当前池必须可达 |
| 险注 | 恰好一个废铁，另两列为有效伤害 | 两列伤害 +50% | 敌人强制结果也计，但不产生三连 |
| 状态反应 | 同一 SPIN 新施加两种不同 DoT | 各结算一次 50% 标准 tick | 每回合一次，不递归爆发 |
| 攻守转换 | 同一 SPIN 同时产生伤害与护盾 | 追加护盾入账 30% 的穿透 | 每 SPIN 一次，上限另定 |
| 余量蓄电 | 治疗发生溢出 | 每溢出指定量获得 1 充能 | 每回合一次，不与既有溢出转盾重复计算 |

上线前必须删除同义项、补数值、做触发率与递归测试。回路最多装备 2 个，第三个进入明确替换预览。

## 12.3 操控内容顺序

1. 保留现有废铁改判、废铁转化作为对照。
2. 基础目押验收后再决定缓速启动去留。
3. 新增“点刹”：每房 2 次，指定一列短时降速。
4. 新增“驻留”：每房 1 次，SPIN 前保留一列上次符号。
5. 最后原型“单轴复转”：每房 1 次，结算前主动重转一列；若窗口破坏节奏则不上线。

## 12.4 六条可验收引擎路线

| 路线 | 核心武器/符号 | 规则与操控 | 明确代价 |
|---|---|---|---|
| 同系三连 | 高浓度同族符号 | 三连/签名，保留或预览 | 元素覆盖窄 |
| 对子稳定 | 两种主要符号 | 对子赔付、两端呼应 | 峰值低于三连 |
| 异色覆盖 | 双元素武器 | 异色协奏，目标切换 | 浓度与三连率低 |
| DoT 反应 | 状态 + 兑现符号 | 状态反应、阈值遗物 | 需要回合铺垫 |
| 破甲穿透 | special/穿透符号 | 破甲窗口与末符回响 | 对无甲目标部分收益浪费 |
| 防御运筹 | 护盾/治疗/资源符号 | 攻守转换、余量蓄电 | 直接输出较低 |

每条路线至少有核心来源、强化方式、适合的敌人和真实弱点，才称为可玩路线。

## 13. 必要的技术重构边界

本节只定义实施契约，不要求重写整个项目。

## 13.1 单一局内引擎状态

建议收敛为一个可快照的 Run Engine 状态，逻辑上包含：

- 当前装备两槽与本局武器仓库；
- 符号带运行时修改及来源/作用域；
- 当前可用牌谱与签名；
- 已装备回路和操控；
- 本局确定性基准修正；
- 可复现的修改历史。

`DuelController` 负责流程编排，不再作为所有字段的默认存放处。现有字段可分阶段适配，不要求一次性迁移全部代码。

## 13.2 模块职责

| 模块 | 应负责 | 不应负责 |
|---|---|---|
| ReelSystem | 真实带构建、旋转、按停、操控落点 | 奖励选择、图鉴、永久收藏 |
| CombatSystem | 统一结算顺序、数值与战斗事件 | 直接解释奖励 UI |
| Pattern/Circuit | 条件匹配、优先级、限制和来源 | 各自维护一套重复结算公式 |
| DraftComposer | 合法候选、组合约束、冻结结果 | 随机改写已展示目标 |
| RewardResolver | 预检、事务结算、结果回执 | 多效果半结算 |
| Presentation | 使用同一真实模型生成前后差异 | 手写与逻辑不一致的文案 |
| MetaStore | 永久解锁与图鉴 | 充当本局武器仓库 |
| Telemetry | 结构化记录展示、选择、触发和结果 | 影响 RNG 或战斗结果 |

## 13.3 数据与状态原则

- 静态 `.tres` 永不在局内直接修改。
- 运行时修改以稳定 ID、资源路径、武器来源和明确作用域记录。
- 展示和结算必须读取同一冻结模型。
- 新增内容优先通过模板与资源，不为每个符号写独立分支。
- 演出不得消耗全局 RNG。
- 导出环境的资源扫描继续遵循 `ResourceLoader.list_directory`。
- 回路使用白名单事件，不建立无法验证的通用递归脚本系统。

## 13.4 旧系统迁移顺序

| 旧系统 | 目标 | 前置安全门 |
|---|---|---|
| 武器熟练数值与铭印欠选 | 移除重复局内成长；保留历史行为记录 | 新 Draft 输出与换装曲线通过 |
| 槽位铭印 | 并入明确的武器/符号改造或退役 | 替换预览能解释继承与休眠 |
| 全局研磨卡 | 退出常规主池 | 各幕基础输出不依赖随机兜底 |
| 幕间锻魂 | 暂时保留，后续定向淬炼 | 替代曲线稳定后再改 |
| 元素共鸣分卡 | 兑现真实效果或退出正式池 | 不再只加构筑分 |
| 牌谱参数强化接口 | 不作为正式回路方向 | 兼容旧状态后再清理 |
| 铁砧 gacha | 条件/定向解锁 | 所有点数来源与空池兜底已迁移 |

## 14. 数值与验证方法

## 14.1 不再只用完美目押

所有关键平衡至少分四种操作模型：

| 模型 | 用途 |
|---|---|
| 随机/新手 | 检查下限与是否完全不可玩 |
| 普通目标命中 | 主要真人近似曲线 |
| 熟练目标命中 | 检查技巧收益 |
| 完美目押 | 只测上限，不代表正常通关率 |

普通与熟练模型的目标停中率通过真人首轮测量后锁定，不能继续用 100% 强制落点代表所有玩家。

## 14.2 对照组

至少保留：

- 无新增成长；
- 仅符号构成；
- 仅符号数值；
- 仅回路；
- 仅操控；
- 武器集中路线；
- 武器覆盖路线；
- 完整混合成长。

同种子、同敌人、同操作模型比较，记录中位数和低分位，不只看平均值。

## 14.3 核心平衡指标

- 每幕进入普通、精英、Boss 前的预期 SPIN 输出与实际兑现输出。
- 目标符号格数、占比、循环时长和真人停中率。
- 普通/精英/Boss 回合数、承伤、治疗、格挡和死亡原因。
- 三连、核爆、DoT、回路和操控的实际触发/伤害占比。
- 每局武器获取、换装、精简和结构改造次数。
- 空候选、无效候选、Fallback、重抽和结算失败。
- 平均之外的 10% 低分位局，防止坏局不可恢复。

## 14.4 调参纪律

- 一次只改一个主要轴：带模型、回路数值、敌人攻击或奖励概率不同时改。
- 先修不可兑现与不可理解，再调百分比。
- 选择率只作为复查信号；至少按展示次数、幕次、构筑和共现候选分桶。
- 高于 80% 或低于 5% 且展示样本达到 30 次时进入复查，不自动加强或删除。
- 胜率用于发现假设，不用于宣称某张卡单独导致胜负。

## 15. 分阶段执行路线图

以下周期是“一名开发 + 一名策划/验证”的粗略排期单位，不是承诺工期；每阶段独立可验收、可回退。

### G0 · 事实基线与文档收口（1–2 天）

**任务**

- G0-1：冻结当前数值、资源数量、默认配装和跑局模式。
- G0-2：统一 20 张牌谱、签名自动生效、Draft 当前类别等事实口径。
- G0-3：保存旧成长输出基线、六种引擎路线基线和当前测试清单。
- G0-4：建立本文任务追踪，不再把目标、现状和实施日志混写。

**出口**：后续每项改动都能与同一基线比较；旧文档不再作为冲突指令源。

### G1 · 奖励正确性与事务安全（2–4 天）

**依赖**：G0。  
**任务**

- G1-1：最终验证不足三张时继续补合法候选，不允许静默缩卡。
- G1-2：Fallback 复用完整过滤、去重、拥有状态和可结算检查。
- G1-3：动态 Provider 输出全部合法候选，消除“先随机注入一张”的瓶颈。
- G1-4：统一 stack/max_stack/eligibility 的真实执行口径。
- G1-5：多效果结算改为全预检后提交，覆盖失败无半状态。
- G1-6：五张共鸣退出正式池，或先兑现明确真实效果；不允许继续只加构筑分。
- G1-7：重抽保持约束并避免相同组合。

**出口**：极端状态下始终恰好三张合法卡；所有奖励真实结算；重抽、跳过和失败路径可复现。

### G2 · 本局武器仓库与换装预览（3–5 天）

**依赖**：G1。  
**任务**

- G2-1：区分局外解锁、本局拥有、当前装备。
- G2-2：拆分 `weapon_acquire` / `weapon_swap` 的生成、卡面、日志与遥测。
- G2-3：所有来源统一写入本局仓库，永久图鉴单独记录。
- G2-4：完成新旧符号、格数、牌谱、签名、改造休眠的完整比较。
- G2-5：换下的武器保留本局仓库，取消与重复点击不消耗奖励。

**出口**：新武器获取和仓库换装均端到端可用；玩家能在确认前说清得失。

### G3 · 真实符号带编辑（3–5 天）

**依赖**：G1；可与 G2 并行。  
**任务**

- G3-1：制作“一格一权重”原型并与当前档位模型对照。
- G3-2：统一建带、灌注、调律、精简、预览和图鉴口径。
- G3-3：实现集中、转化、精简、添入、刻印、校准的合法性规则。
- G3-4：处理共享符号、多来源、换装休眠、核心保护、敌人注废。
- G3-5：确定最小带长、预算和每符号上限，不用隐藏全局补偿。

**出口**：连续多次改造仍有真实变化；预览与实际完全一致；不存在死带和共享资源污染。

### G4 · 回路结算与赔付表（5–8 天）

**依赖**：G1，正式启用还依赖 G3 的可达性信息。  
**任务**

- G4-1：固定基础符号、通用赔付、牌谱/签名、回路和敌方修正顺序。
- G4-2：实现回路状态、2 槽替换、触发限制和来源日志。
- G4-3：先完成 3 个不同事件的原型，再扩到至少 6 个。
- G4-4：建立当前可达性过滤和“为什么未触发”调试信息。
- G4-5：统一当前赔付表，解释旧三连与新规则的关系。
- G4-6：达到 §5.3 启用门槛后才恢复 `rule_mod` 类别。

**出口**：至少 3 条路线因回路改变目标选择；无递归、无静默截断、无不可达成候选。

### G5 · 操控与最小内容闭环（4–6 天）

**依赖**：G2、G3、G4 原型。  
**任务**

- G5-1：基础目押无需奖励即可读、停、复盘。
- G5-2：评估现有三操控，补点刹/驻留，单轴复转单独原型。
- G5-3：上线首批符号模板和回路，移除同义技艺主池入口。
- G5-4：形成六条引擎路线的 ACT1 垂直切片。
- G5-5：采集新输出曲线，与旧熟练/铭印/锻魂基线比较。

**安全门**：新方案各幕中位输出原则上不低于旧基线 90%，低分位无不可恢复断层；具体上下限在 G0 数据后锁定。未通过则继续补新系统，不删旧成长。

### G6 · 来源、敌人与路线收束（5–8 天）

**依赖**：G5 安全门。  
**任务**

- G6-1：普通/精英/Boss 奖励按 §7 分工，精英去掉额外堆叠。
- G6-2：Boss 遗物保证入账，主题选择同屏完成。
- G6-3：休整加入精简/卸除取舍，事件改为有代价的引擎决策。
- G6-4：Boss 爆发安全线、对策覆盖和机制身份逐只验收。
- G6-5：分岔图完整真人验证后设为正式模式，线性转调试。
- G6-6：按真人时长调整每幕节点，而不是堆 HP 延时。

**出口**：三幕路线、奖励和敌人共同检验引擎；没有奖励过载、Boss 无预警秒杀或固定唯一对策。

### G7 · 旧成长、局外解锁与表现迁移（4–7 天）

**依赖**：G5 安全门；铁砧还依赖 G6 的所有兜底迁移。  
**任务**

- G7-1：铸式解锁改行为条件，保留历史已解锁内容。
- G7-2：移除重复熟练/铭印/欠选和常规全局加伤入口。
- G7-3：铁砧改条件/定向解锁，处理所有点数来源和老存档。
- G7-4：机器摘要、赔付表、局末引擎总结统一。
- G7-5：完善新手引导和辅助选项。
- G7-6：核心稳定后再评估节点边界续玩存档。

**出口**：玩家只面对一套局内成长语言；旧存档不回锁；下一局目标明确。

### G8 · 全量平衡与发布验收（3–5 天）

**依赖**：G1—G7 目标范围。  
**任务**

- 固定种子多路线模拟、低分位局复核、真人完整三幕。
- 项目标准测试、相关专项测试和导出后资源扫描全部通过。
- 检查 480×270、窗口缩放、奖励/换装/地图/商店覆盖层。
- 清理本阶段产生的临时探针和报告，更新当前事实文档。

**出口**：满足 §16 的发布 DoD；未通过项保持阶段打开，不以“基本完成”结案。

## 16. 验收体系与 Definition of Done

## 16.1 自动验收

### Draft

- 空池、单候选、全满层、无仓库武器、操控耗尽、满血、空腰带等状态均恰好三张合法卡。
- 无重复、无零收益、无已拥有的一次性能力、无不可达回路。
- 结构改造覆盖、类别多样性、重抽约束和费用正确。
- 每个效果至少一次真实 resolve；多效果失败无半结算。
- 基础抽样与完整生成器最终分布分别测试。

### 转轮与换装

- 所有增删改在预览、实际带、来源分配和结算中一致。
- 共享符号、多来源、最小带长、MISS、注废、锁列和精简边界正确。
- 换装后失去/获得牌谱正确，休眠改造可恢复，旧武器仍在仓库。
- 同种子与同输入可复现，演出不消耗全局 RNG。

### 回路

- 触发顺序固定，自身不递归，次数上限准确。
- 所有已获效果均生效，表现预算不影响结算。
- 候选在获得时可达；换装后不可达的回路有明确休眠/替换规则。

## 16.2 端到端场景

至少覆盖：

1. 新档首局完成一次集中、一次回路、一次换装。
2. 本局获得新武器 → 换入 → 换回 → 原改造正确恢复。
3. 三组候选均不想要 → 重抽 → 跳过，费用与状态正确。
4. 符号池耗竭 → 合法兜底 → 不空屏。
5. 精英只产生设计内的一次主奖励决策。
6. Boss 遗物必得且主题选择可完成。
7. 休整精简、事件代价、商店购买与卖出形成经济闭环。
8. 锁轮/注废/冻结/夺轮下操控不软锁。
9. DoT 路线在普通真人策略中能主动形成并触发爆发。
10. 完整三幕、最终特殊结局、局末总结和永久解锁。
11. 老存档解锁、铸式与点数迁移不回锁。
12. 导出包中的资源扫描、奖励与地图内容与编辑器一致。

## 16.3 真人验收

首轮建议至少 5 名测试者、每人 3 局，覆盖新手与熟练玩家：

- 80% 以上测试者能说出本局引擎与开局的一个具体差异。
- 玩家能解释一次大数字的主要来源，而非只注意到数字大。
- 玩家能说明一次换装的得失和一次路线选择理由。
- 基础目押不依赖操控奖励才能正常使用。
- 至少四条引擎路线被认为有明确差异，不是同一输出模板换皮。
- 普通 Draft 中位决策时间目标 5–12 秒；长期犹豫优先检查信息而不是缩计时。
- 完整局时长、失败原因和再玩意愿达到 §3 目标或有明确修正任务。

## 16.4 发布 DoD

只有全部满足才可称为核心重构完成：

- 核心承诺的四个改造面都真实进入常规游玩。
- 没有伪成长、半结算、空奖励、不可达回路或预览/结算不一致。
- 新输出曲线通过安全门，旧重复成长已按迁移顺序收口。
- 普通、精英、Boss、地图、商店、局外解锁职责唯一。
- 自动测试、端到端、真人和导出验收全部通过。
- 当前事实文档、设计目标和实施记录分开且同步。

## 17. 遥测与复盘合同

### 17.1 Draft 事件

每组至少记录：

- run、seed、房间、幕、来源、draft_id；
- 三候选的 ID、类别、操作族、稀有度、具体目标和冻结数值；
- 合法性过滤、Fallback、结构保护和实际权重；
- 展示、选择、跳过、重抽前后组合与费用；
- 武器获取/换装、本局仓库、被替换对象、牌谱与休眠变化；
- 选择时 HP、金币、武器、真实带、回路、操控快照；
- 结算结果和失败原因。

### 17.2 战斗与引擎事件

- 每次 SPIN 的真实带版本、目标、停中、速度、缓冲和操控使用。
- 基础符号、牌谱、回路、核爆、DoT、充能的来源与输出/生存贡献。
- 回路获得后的展示、触发、零触发和休眠。
- 每房回合、承伤、治疗、死亡原因与操作模型。
- 最终引擎标签只作摘要，不把相关性当因果。

### 17.3 数据健康线

- 结算失败：必须为 0。
- 非法/不足三张：必须为 0。
- 预览与实际带不一致：必须为 0。
- 内容完整后的通用 Fallback：目标低于 1%，超过先查池与过滤。
- 回路零触发、极低选择率、极高选择率：进入分桶复查，不直接削数值。
- 遥测详细事件不能继续只保留最近 64 条；开发/测试环境需能导出完整一局。

## 18. 风险、回退与防范围扩散

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 直接格子化改变平衡 | 同配装输出/目押突变 | 保留旧模型对照，单独验收 G3 |
| 回路变成隐藏乘区 | 玩家不知道为何增伤 | 限制乘区、显示来源、优先组合规则 |
| 操控取消随机与技巧 | 每局必三连或等待最优解 | 次数限制、操作成本、分技能模型测量 |
| 换装惩罚过强 | 玩家拒绝新武器 | 本局仓库、改造休眠、完整预览 |
| 改造池过快耗竭 | Fallback 上升 | 动态模板、不同操作族，不补同义卡 |
| 奖励减少导致生存断档 | 低血局无恢复手段 | 用路线/符号/休整补，不回填纯资源主池 |
| 删除旧系统导致强度断层 | 低分位局崩盘 | 执行 G5 安全门，保留旧系统直到通过 |
| 铁砧迁移破坏收藏 | 老档回锁或点数消失 | 永久保留已解锁，定向折算点数 |
| 文档再次漂移 | 数量/状态互相矛盾 | 事实、目标、实施日志分文档维护 |

### 回退原则

- 每阶段保留可切换原型和固定 seed 对照，但不长期维护两套正式规则。
- 发现契约失败先停在当前阶段，不顺手扩内容。
- 不用删除测试、降低断言或隐藏错误换取通过。
- 不用一次性大重构替代分阶段验证。

## 20. 最终执行口径

```text
先修奖励真实有效
→ 分清武器获取、换装与永久收藏
→ 让符号带可以持续、精细、可见地编辑
→ 用少量回路和操控建立不同中奖引擎
→ 让敌人、Boss、路线和经济检验并服务这台引擎
→ 通过输出与真人安全门后，再删除重复成长和随机铁砧
```

最终判断标准不是系统更多、卡更多或数值更大，而是：

> **玩家每次选择都知道自己改了机器的哪一部分，下一场能感受到它，整局结束后能复述这台机器为何独一无二。**
