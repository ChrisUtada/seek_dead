## C4. 10 种无序组合映射草案（铁剑攻击 + 另外两格）

口径：固定一格 `iron_sword.tres` 的 `iron_slash.tres`（damage/none，iron_sword.tres:5），另外两格从 {火焰 F=`burn.tres`, 冰霜 I=`frost.tres`, 守备 G=`guard.tres`, 弹丸 P=`pistol_shot.tres`} 中可重复取，不区分顺序 → C(4+2−1,2)=10 种。三态：**可用** = 现有 `match_rule` 的 `sym`/`kind`/`source_*` 条件可表达；**需新字段** = 需要新增类别/标记字段才能可靠表达；**无法** = 现有字段与调用时机都不支持，且不宜硬编码。

| # | 组合 | 三态 | 依据与冲突点 |
|---|---|---|---|
| 1 | 铁剑 + F + F（双火焰 → 燃刃/强化燃刃） | **可用** | W01/SIG 的 `all:[{"sym":burn}, {"kind":"damage","source_element":"fire"}, {"source_kind":"weapon"}]` 已表达（w01_flame_resonance.tres / sig_fire_sword.tres）。冲突：双火「强化燃刃」若按 SIG_W01 实现需带对应武器且 `key_paths` 命中；T3-3 要求「不消耗层数、不提前结算」，现有 `burn_extra` 只加层，语义需评审 |
| 2 | 铁剑 + F + I（冰火转化） | **需新字段** | SIG02 的 `all:[fire_slash, ice_crystal]` 只覆盖固定 sym 对，且 `track="signature"`、priority=10（`s02_frostfire_dual.tres`）；铁剑+`burn`+`frost` 无法匹配。要表达「牺牲状态换穿透」需新效果字段或新规则；与 SIG02 的 `pierce_ratio=0.2` 语义重叠 → 冲突点 |
| 3 | 铁剑 + F + G（燃刃 + 守备） | **需新字段** | T02 `skill_role="shield"` 要求技能来源（`t02_defense_support.tres`），而本组合守备来自 `guard.tres` 符号（shield/none），无 `source_kind="skill"`；`kind="shield"` 可表达但「守备类别」无字段。与 T02 同层：若技能位也命中 T02，会走辅助层共存，需评审是否双算 |
| 4 | 铁剑 + F + P（两者基础伤害有效 + 小额穿透） | **需新字段** | 弹丸只能按具体 `sym` 路径或 `pierce_armor` 表达；`match_rule` 条件无 `pierce_armor` 键（`pattern_matcher.solve_rule` 未定义该条件，见 :215-222 附近）。与 W01 冲突：火焰条件已命中 W01，新增主组合需明确主/辅层级或取代 |
| 5 | 铁剑 + I + I（双冰） | **可用（部分）** | W02 `all:[frost, kind=damage,source_element=ice, source_kind=weapon]` 可表达单冰+冰伤；双冰需两条 `{"sym":frost}`（现有规则支持重复条件），但 W02 的 `threshold`/`enemy_atk_mult` 语义是减攻而非双冰专属 → 效果需评审 |
| 6 | 铁剑 + I + G | **需新字段** | 同 #3 的守备类别问题；W02 可表达冰侧但守备无字段 |
| 7 | 铁剑 + I + P | **需新字段** | 同 #4 的弹丸类别问题；W02 可表达冰侧 |
| 8 | 铁剑 + G + G（双守备） | **需新字段** | `kind="shield"` 可匹配两条，但无「守备」类别字段；W06 要求 `source_element="none"` 的 damage×2，与 shield 不符；没有现成守备主组合 |
| 9 | 铁剑 + G + P | **需新字段** | 守备 + 弹丸两类别都缺字段 |
| 10 | 铁剑 + P + P（双弹丸） | **需新字段** | 只能按 `sym` 路径列具体资源（`pistol_shot` / `bolt_shot`），无法按类别；`pierce_armor=true` 在 `match_rule` 中不可表达。W06 的 `source_element="none"` + damage×2 可能误命中 → 冲突点 |

**三态统计**：可用（含部分可用）2 条（#1 双火、#5 双冰）；需新字段 8 条（#2/#3/#4/#6/#7/#8/#9/#10）；无法表达 0 条。**没有一条需要「无法表达」**，但 8 条都依赖评审先定义「类别字段/主辅层级」——这正是 A 未批准不写生产代码的原因。

与 T01–T03 的冲突点汇总：T01/T02/T03 的 `match_rule` 第一条均为 `source_kind="skill", skill_role=power/shield/heal`（t01/t02/t03 .tres），即辅助组合**绑定技能来源**；本试点的守备来自符号、回春/炎息来自技能。若「铁剑+火焰+回春」同时满足 T03 与新主组合，会走「主辅共存」，但现有 `resolve_equipment` 只留 1 条装备牌谱、`resolve_universal` 全留，`T*` 与 `W*` 分属不同轨，是否双算/如何分行列示需拍板（C5-Q2）。

## D. 评审裁决（2026-11-24）

> 本节是评审拍板结论，不是实现记录。按基线「A 未批准不写生产代码」，本轮仍不写任何组合生产代码；下列裁决作为 B 轮原型结算的输入。

**Q1 · 同层裁决与层级推导（已拍板）**
- 同层确定性优先级：**具体度（`match_rule` 必需条件数）降序 → `priority` 降序 → `id` 字典序**。具体度优先保证「更精确的条件先于更宽泛的条件」，`priority` 与 `id` 仅作同级 tiebreak。
- 层级不新增字段，由 `track` 推导：`weapon*` = 主组合，`skill*` = 辅组合，`base`/G 系 = 基础组合，`signature` = 主组合变体。
- **签名不参与主组合竞争**：走独立变体通道，不与 W 系争同一个「主」名额。

**Q2 · 签名隐藏前置（已拍板）**
- 取消 `find_signature()` 的「先命中基础 W + `w_pick` 非空」隐藏前置，改为「`key_paths` 含当前武器 + `match_rule` 成立」即可达。
- SIG02 保持 `track="signature"`，但**不进本轮试点**；试点只对 `iron_sword` 生效。

**Q3 · G01–G03（已拍板）**
- 保持 `pattern_matcher.gd` 的脚本常量，**不迁 PatternData**。
- 统一组合面板加一层只读展示适配：`track="base"`、`priority=0`，只用于显示来源分解，**不进 `resolve_equipment`**。

**Q4 · 符号类别字段（已拍板，B 轮实现）**
- 新增 `SymbolData.symbol_category`，枚举 `blade|flame|frost|guard|projectile|arcane|none`，默认 `none`。
- `match_rule` 增加 `symbol_category` 条件；**只给试点四类符号打标**（blade/flame/frost/guard/projectile），其余保持 `none`。
- **禁止路径白名单方案**（脆弱、不可维护）。本轮只落档，不改 `symbol_data.gd` 与 `.tres`。

**Q5 · 技能侧与双算（已拍板）**
- T 系仍绑 `source_kind="skill"` + `skill_role`；符号不触发 T 系。
- 主辅各结算一次，**不双算**。
- 补反向用例：「铁剑 + 火焰 + 守备（符号）不误触 T02」。

**B 轮入口**：以上五条为 Step B 原型结算的硬约束；实现时不得回退到「priority 单独裁决 / 签名隐藏前置 / G 系迁资源 / 路径白名单 / 符号触发 T 系」。

**B 轮范围（2026-11-25 落定）**：本轮只做**一组**主组合「强化燃刃」W07（iron_sword + blade + flame + flame），用于单变量验证，不做平衡结论。**爆燃 / 余烬（熟练变体）与冰火转化明确不进本轮**；它们依赖 T3-3 后续步骤与本轮 A/B 数据，不提前实现。实施与验收见 `docs/T3-3B_强化燃刃_实施与验收_2026-11-25.md`。
