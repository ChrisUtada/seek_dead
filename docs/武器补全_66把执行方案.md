## 3. 设计规则（从现有文档与代码提炼）

### 3.1 三层模型（每把武器只填这三层）

| 层 | 字段 | 本方案用法 |
|---|---|---|
| ① 基础属性 | `rarity` / `base_power` / `hit_rate` / `crit_chance` / `crit_mult` | 决定“多强”；稀有度只定强度，不定频率 |
| ② 机制 | 机制符号 / `triple_pierce` / 符号 `pierce_armor` | 决定“什么效果” |
| ③ 元素 | `element` / `reel_element` | 决定“克制谁”；普通符号 element=none 时继承武器元素 |

### 3.2 元素 → 状态铁律（沿用现状，不跨元素）

| 元素 | 必带状态 | 说明 |
|---|---|---|
| 火 fire | `burn` | DoT，无视护甲 |
| 冰 ice | `frost` | 减攻，纯控制 |
| 毒 poison | `poison` | DoT + 减攻 |
| 光 light | **不挂状态** | 靠双克制与高暴击，不叠状态 |
| 暗 dark | **不挂状态** | 靠高攻/破甲/双攻击符号 |
| 无 none | **不挂状态** | 纯物理底池 |

> 现有 16 把光/暗/无武器零状态（光 5 + 暗 6 + 无 5），这是已结案的平衡决策；新武器继续执行。火/冰/毒**每把都带本系状态**，差异由状态格数（2/3/4 格）与基础数值承担。

### 3.3 数值锚点

| 稀有度 | `base_power` | `hit_rate` | `crit_chance` | `crit_mult` |
|---|---|---|---|---|
| common | 9–12 | 0.82–0.88 | 0–0.12 | 2.0 |
| uncommon | 8–20 | 0.80–0.88 | 0–0.15 | 2.0 |
| rare | 13–20 | 0.78–0.90 | 0.05–0.12 | 2.0 |
| epic | 16–20 | 0.80–0.90 | 0.08–0.15 | **2.5（本方案首次启用）** |

- **代价轴**：高 `base_power` → 低 `hit_rate` / 低 `crit_chance`；低 `base_power` → 高暴击/高命中。典型：`forge_greatsword` 20 / 0.78 / 0%；`flare_dagger` 9 / 0.88 / 15%。
- **`crit_mult` 首次系统性启用**：8 把新 epic 统一 2.5；建议同批把现有 `flame_staff` 也从默认 2.0 补到 2.5，避免新 epic 单方面占优。若担心平衡，可先全部 2.0，F6 后再抬（见 §8 待拍板）。

### 3.4 符号 → 转轮格数（写权重前必须知道）

代码事实（`reel_system.cells_for`）：

| 权重 w | 格数 |
|---|---|
| w ≥ 4 | 4 格 |
| 2 ≤ w < 4 | 3 格 |
| w < 2 | 2 格 |

- **damage 攻击符号不受稀有度封顶**：w ≥ 4 恒 4 格。
- **status/buff/special 等功能符号**：rare/epic 且单源（sources < 2）封顶 **2 格**；共享符号 ≥2 源可突破封顶。
- 因此：
  - 攻击符号统一写 **w 4–6**（都是 4 格，w 再高只影响 MISS 占比，不增加格数）。
  - common/uncommon 状态符号：w 4 = 4 格；w 2–3 = 3 格；w 1 = 2 格。
  - **rare/epic 状态符号写 w 1 即可拿 2 格**；写 >1 不会多格，只会增加 MISS，属死权重。
- 验收口径：**无死权重**——凡“加了权重但格数不变”的写法，一律改成 1 或删掉。

### 3.5 机制白名单

允许：

- 本系状态符号（fire→burn / ice→frost / poison→poison）。
- `triple_pierce`（该武器三连清甲）。
- 同元素共享符号（现有 `shadow_slash` 被 5 把暗武共用、`frost` 状态被 4 把冰武共用，属正道）。

> 穿透默认**不新增**：`0218b18`（2026-08-14）已把穿透从 9 把收敛到 1 把，只保留 `bolt_shot`（穿甲重弩），目的是让敌人护甲重新有意义。新武器不得给旧符号加回 `pierce_armor`；如确需新穿透，单独拍板 + 新建专用符号 + F6。

禁止：

- `heal` / `shield` / `buff` 符号。
- 新增 `special`（新武器默认不用；炎爆仍是唯一先例）。
- 跨元素挂状态（火武挂霜之类）。

> 光/暗/无武器允许“双攻击符号”（如 `holy_slash + dawn_light`），与现有 `dawn_blade`、`shadow_guillotine`、`holy_mace` 一致；这不算副攻机制。

### 3.6 文件、命名与图标

- 路径：`resources/weapon_templates/<id>.tres`，**一个武器一个文件**，小写蛇形。
- 字段：`category = "weapon"`，填 `weapon_name` / `rarity` / `base_power` / `hit_rate` / `crit_chance` / `crit_mult` / `archetype` / `weapon_type` / `element` / `reel_element` / `symbols`。
- 遗留字段（`damage` / `attack_speed` / `status_effect_*` 等）**不填**，转轮战斗不读取。
- 图标：有现成 16/24 图标才绑；否则 `icon_tex` / `art` 留空，走 emoji / 默认图。不为 66 把武器安排美术任务。

#### 3.6.1 火焰剑图标参考结论（2026-11-02 实查）

- `assets/icons/16/fire_sword.png`：16×16 RGBA，仅 **3 色**——`#E2D7BD` 暖白剑刃 / `#D5A33D` 金色护手 / `#3A222B` 深色剑柄；硬边像素、无半透明、主体在 x=2..13 / y=1..14。
- `assets/icons/24/fire_sword.png`：上述 16×16 **原尺寸居中**（偏移 (4,4)），不是放大；卡面实际仍是 16px 主体。
- **关键**：火焰剑图标本身不含火色。红色 `#E35B50` 用在 `fire_slash` 符号图标上；武器图标是中性剑。
- 现状只有 **2 / 24** 把武器绑了图标（`fire_sword`、`battle_axe`），其余 22 把走 emoji；图标系统目前是样板级，不是全量内容级。
- 结论：
  1. **本批 66 把不阻塞于图标**，继续 emoji / 占位，符合统一计划“美术缺失不阻塞玩法”。
  2. 若要做全量图标：沿用该 3 色 16×16 像素规范与 `tools/art_pipeline/make_icons.py`，用“8–10 个轮廓族（匕首/剑/巨剑/斧/锤/长枪/法杖/弓/枪械/瓶）× 6 元素强调色”生成；24×24 由 16×16 居中派生。现有 `PALETTE` 缺冰/毒/光/暗强调色，需补 4–5 个颜色（仍遵守每图标 ≤3 色）。
  3. **元素可读性**：要么像 `fire_slash` 那样把刃/强调块染成元素色，要么在卡面图标旁加元素角标；不要用中性图标全面替换现在的 emoji 回落——现回落是 `🗡️+🔥`，换成中性图标反而丢失元素信息。
  4. `make_icons.py` 依赖 Pillow；当前环境未安装（`ModuleNotFoundError: PIL`），要跑需先建 venv / 安装依赖。

## 4. 前置数据修正与新符号

### 4.1 穿透现状与纪律（勿回退 0218b18）

**2026-08-14 的 `0218b18` 是一次有意的穿透收敛：9 把 → 1 把。** 6 个共享符号去掉了 `pierce_armor`，只保留穿甲重弩的 `bolt_shot`，目的是让敌人护甲重新有意义。`装备全览` / `武器制作逻辑` 里“冰弹/枪击/圣辉穿刺/圣锤/暗影锁链/深渊撕咬穿透”的表述是**收敛前的旧口径**，不要按旧文档把标记加回去。

本方案据此执行：

- 66 把**不新增任何穿透载体**；`bolt_shot` 仍只属于现有 `armor_pierce_crossbow`。
- 毒系不靠穿透：DoT tick 本来就无视护甲；重武破甲走 `triple_pierce`。
- 冰/光/暗的远程武器用普通伤害符号，身份写在命中/暴击/双攻击符号上，不写“穿透”。
- 如确实要新增穿透例外：单独拍板 + 新建专用符号 + F6，不与本批混在一起。

### 4.2 新符号（5 个：4 毒 + 1 无属性箭）

现有毒系只有 `poison` 状态符号，没有毒伤害符号；14 把新毒武必须先补攻击符号。无属性猎弓还需要一个**不穿透**的箭矢符号，避免把穿透从穿甲重弩扩散出去。

| id | 名称 | label | kind | element | base | pierce_armor | 用途 |
|---|---|---|---|---:|---|---|
| `venom_bite` | 毒牙 | 🐍 | damage | poison | 8.0 | false | 毒系通用攻击 |
| `corrosive_spray` | 蚀液 | 🧪 | damage | poison | 9.0 | false | 法器/瓶罐主符号 |
| `plague_bolt` | 疫弹 | 🦠 | damage | poison | 9.0 | false | 远程挂毒（不穿透） |

字段写法：`status_type = ""`；毒系四符 `color = Color(0.60, 0.90, 0.40, 1)`（与现有 `poison` 同色系），`arrow_shot` 用中性金属色。`base` 只作展示/参考，伤害读取武器 `base_power`（T12）。

以 `venom_dagger` 为例（数值按 §5.3 表）：

```ini
[resource]
script = ExtResource("weapon_data")
weapon_name = "獠牙匕"
category = "weapon"
rarity = "common"
base_power = 8
hit_rate = 0.86
crit_chance = 0.12
crit_mult = 2.0
archetype = 0          # LIGHT
weapon_type = 0        # MELEE
element = "poison"
reel_element = "poison"
triple_pierce = false
# symbols: venom_bite w4 + poison w2
# icon_tex / art 留空 → emoji 回落
```

> 其余 65 把照此模板 + §5 表逐行填；不填 `damage` / `attack_speed` / `status_effect_*` 等遗留字段。
