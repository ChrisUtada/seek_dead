## 3. 维护约定

- 新任务立项时：在此文登记 → 开工 → 完成勾选 → 在对应执行文档回写。
- 文档改名：改名前先全库检索引用（docs/*.md + scripts/**/*.gd 注释），批量替换后再 git mv。
- 本文档为 docs/ 待办唯一入口；各专项执行方案保留详细设计，本文档只留任务条目与来源。
- **文档统一格式约定（2026-08-07 起）**：设计/执行类文档统一包含以下小节，顺序固定——
  1. 状态 header（`> 状态：` 一行，定稿/落地状态 + 拍板记录）
  2. 定位与目标（含教学主题/设计意图）
  3. 核心设计（数值表/机制分节）
  4. 解法矩阵 / 联动（与既有机制交叉引用）
  5. **内容清单**（见下方表格规范）
  6. 配套内容（课程化/缺口）
  7. **实现步骤**（分步落地表：每步 = 内容 + 改动文件 + F6 验证点 + 独立提交纪律）
  8. F6 验证清单（验收勾选）
  9. 关联（总清单编号 + 依赖任务）
  参照：`BOSS_冰封铁瓮_设计.md`（首个按此格式的文档）。
- **内容清单表格规范**：涉及内容（武器/技能/护符/消耗品/怪物等）一律列全量表，字段含名称/类型/数值/定位，**末列「状态」标注**：`原`（现有调试内容，可随时调整删除）/ `调整`（现有需改）/ `【新增】`（需新建）/ `规划`（后续阶段）；表格后附「调整说明」汇总。
- **单侧性纪律（2026-08-09 拍板，强制）**：**同一种东西不能同时作用于玩家和敌人**——武器 / 技能 / 护符 / 消耗品 / 怪物 / 状态等任何内容资源，职责必须单边化（纯玩家侧或纯敌人侧）；出现跨侧需求时**必须新增独立资源**，不得在同一资源上扩语义。判例：净化药剂（清敌人意图）与清净药剂（解玩家状态）拆分（2026-08-09）；新增内容前先自查单侧性，BOSS 设计文档的内容清单须标注作用侧。
