# 敌人系统设计 — 实施规划

## 架构总览

```
EnemyBase（HP/闪白/状态效果/击退/血条）
  ├── goblin.gd / skeleton.gd    ← 普通敌人（复用 AIComponent）
  ├── Elite*                      ← 精英敌人（独有脚本，独有行为）
  └── BossEnemy                    ← Boss（BossAIComponent 阶段系统）
```

**敌人 = 脚本（行为） + 场景（骨架/碰撞/节点） + 配置（EnemyConfig .tres）**

## 当前问题

1. **AI 行为单一**：所有敌人都走 chase→attack 循环，到达后行为趋同（停在 `attack_range` 附近周期攻击）
2. **无行为多样性**：没有后退射击、圆周走位、定点炮台、召唤等模式
3. **精英系统未实现**：`Elite*` 脚本、精英掉落、房间投放均不存在
4. **导航不完善**：环境碰撞体缺失（可穿墙），NavigationAgent2D 参数未按敌种调优

## Phase 1 — AI 行为框架（P0）

**目标**：让敌人能表达多种行为模式，而不是硬编码 chase→attack 循环。

### 1.1 行为队列系统

不再在 `_process_chase` 中硬编码导航目标，改为给 AIComponent 一个**行为队列**，每个行为定义：

| 字段 | 类型 | 说明 |
|------|------|------|
| behavior_type | enum | CHASE, STRAFE, RETREAT, TURRET, SUMMON, PATROL 等 |
| duration | float | 执行时长，-1 持续到条件触发 |
| condition | Callable | 何时切到下一个行为 |
| priority | int | 打断优先级 |

AIComponent 每帧执行当前行为，行为结束后按队列/条件切到下一个。

**文件**：`scripts/components/ai_component.gd`（已有）

### 1.2 行为注册机制

行为定义为独立函数或方法，按名称注册：

```gdscript
enum BehaviorType {
    CHASE,          # 冲向玩家（当前行为）
    STRAFE,         # 圆周走位，保持距离
    RETREAT,        # 后退射击
    TURRET,         # 原地射击
    SUMMON,         # 拉远召唤
    PATROL,         # 巡逻搜索
    FLEE,           # 低血量逃跑
}
```

每个行为有 `_tick_<behavior>(delta)` 方法控制移动和攻击，互不干扰。

**灵活性**：普通敌人全用 AIComponent 配置（`@export var behaviors: Array[int]`），精英/Boss 覆写特定行为。

### 1.3 具体行为定义

| 行为 | 移动方式 | 攻击方式 | 适用 |
|------|---------|---------|------|
| CHASE | 导航到玩家 + 散开偏移 | 近战攻击 | 哥布林、骷髅 |
| STRAFE | 绕玩家圆周移动，保持 `attack_range` | 周期射击 | 精英法师 |
| RETREAT | 玩家靠近时后退，远时前进 | 边退边射 | 远程怪 |
| TURRET | 不移动 | 周期弹幕 | 固定炮台 |
| SUMMON | 拉远到安全距离 | 召唤小怪 | 召唤精英 |
| FLEE | 远离玩家 | 不攻击 | 低血量逃跑 |
| SEARCH | 沿巡逻点移动 | 发现玩家后切 chase | 初始状态 |

**文件改动**：
- `scripts/components/ai_component.gd` — 加 BehaviorType 枚举，行为队列，各 `_tick_*` 方法
- `scripts/battle/enemy_base.gd` — 可选：暴露 `behavior_weights` 或 `default_behavior`

## Phase 2 — 精英敌人系统（P1）

**目标**：实现 Elite* 专属脚本 + 投放 + 精英掉落。

### 2.1 精英脚本模式

每个精英敌人是独立脚本 `extends EnemyBase`，覆写 `_ready` 配置专用行为序列：

```gdscript
# elite_mage.gd
class_name EliteMage
extends EnemyBase

func _ready():
    super()
    ai.set_behavior_sequence([STRAFE, RETREAT, SUMMON])
    ai.attack_range = 200.0
```

已有草稿：`scripts/battle/elite_mage.gd`

**需新建**：
- `scripts/battle/elite_goblin.gd` — 强化近战，加 FLEE 行为
- `scripts/battle/elite_archer.gd` — 远程，STRAFE + RETREAT

### 2.2 精英投放

RoomManager 支持两种方式，可混合：

**RoomConfig 配置**（数据级）：
```gdscript
@export var elite_count: int = 0
@export var elite_pool: Array[PackedScene]
```

**SpawnMarker 显式放置**（场景级）：
```
SpawnMarker (groups=["spawn_elite"])
```

RoomManager._spawn_enemies 逻辑：优先取 `spawn_elite` 组位置，不足时从普通 `spawn` 补位。

**文件改动**：
- `scripts/rooms/room_manager.gd` — `_spawn_wave` 加精英生成逻辑
- `scripts/rooms/room_config.gd` — 加 `elite_count` / `elite_pool` 字段
- 新建 `scenes/enemies/elite_goblin.tscn`, `elite_archer.tscn`

### 2.3 精英掉落

精英死亡掉落量高于普通怪：
- 金币：50~100（普通 10~25）
- 装备掉落概率翻倍
- 可配置 LootEntry 表（待实现完整掉落管线时可延后）

**文件改动**：
- `scripts/rooms/room_manager.gd` — `_on_enemy_died` 检测 `is_in_group("elite")` 时提高掉落

## Phase 3 — 导航与环境碰撞（P0 积压）

**目标**：解决敌人穿墙、NavigationAgent2D 参数调优。

### 3.1 房间环境碰撞体

每个房间场景加 StaticBody2D + CollisionPolygon2D 围住可通行区域边界。

参考 `docs/房间环境碰撞体实施计划.md` 中每个房间的墙线坐标。

**文件**：`scenes/rooms/room_*.tscn`（共 5 个房间场景）

### 3.2 NavigationAgent2D 参数按敌种调整

AIComponent._ready 中已设 `target_desired_distance = attack_range * 0.8`，但需为远程敌调大：

| 敌种 | attack_range | target_desired_distance |
|------|-------------|------------------------|
| 近战（哥布林/骷髅） | 50 | 40 |
| 远程（精英法师） | 200 | 160 |
| Boss | 视阶段 | 动态 |

### 3.3 NavigationPolygon 障碍物烘焙

添加环境碰撞体后重新烘焙 NavigationPolygon，使导航网格不覆盖墙壁。

**文件**：`scenes/rooms/room_*.tscn` — NavigationRegion2D 子节点

## 实施顺序建议

```
Phase 1 (AI 框架) ──→ Phase 2 (精英) ──→ Phase 3 (导航)
     ↓                     ↓
 可单独验证            可单独验证
（K 键刷怪测试）      （房间出现精英）
```

每个 Phase 完成后可独立验证，不阻塞下游。建议先做 Phase 1 的行为队列 + 3~4 个具体行为，再做 Phase 2 精英接入。
