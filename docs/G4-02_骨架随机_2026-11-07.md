# G4-02 骨架随机 · 尾路长短（2026-11-07）

> 对应：`docs/统一制作执行计划_2026-11-06.md` §8.1 / §8.2
> 代码：`scripts/board/board_generator.gd`（`SHAPES` / `LONG_TOPOLOGY` / `LONG_EDGES`）、
> `scripts/board/board_system.gd`（`shape_id` / `layout`）、`scripts/board/board_screen.gd`（数据驱动布局）
> 测试：`tests/m2_board_test.gd` §②d/②e（181 checks / 0 fails）；smoke 16 套全绿（3617 checks / 0 fails）

---

## 1. 结论先说

按 2026-11-07 的决定（选项 3：允许尾路 4 格、节点总数可变），本轮加入**第二套骨架**，
每局开局随机抽一套：

| 骨架 | 节点 | 单局路径 | 尾路构成 | 布局 |
|---|---:|---:|---|---|
| `standard` | 25 | 13 格 | 普通 → 营地 → BOSS | 13 列 × 34px（G3 原坐标） |
| `long_tail` | 29 | 14 格 | 普通 → 营地 → **商店** → BOSS | 14 列 × 30px（x0 4 / dx 34） |

两条骨架都保持：4 条尾路、4 个 BOSS、单局 **8 场战斗**、**BOSS 前营地**、
1 个武器格 / 1 个护符格、商店与休整在中段同深度互斥。

长尾多出来的第 4 格是**商店**，不是战斗、不发奖励：它只把「BOSS 前把余钱花掉」的机会公开出来，
不改变经验、掉落、金币收入与战斗数值。选择理由：
- 若第 4 格是普通/精英战斗，单局会变 9 战，成长与难度曲线一起变，超出本次授权；
- 若第 4 格是第二个营地，BOSS 前可回两次血，等于削弱 BOSS；
- 商店复用现有货架/价格/刷新，不新增系统，且正好回应「商店太少、钱花不出去」。

## 2. 生成顺序

```text
本局种子
→ 抽骨架（standard / long_tail，50/50）
→ 抽分支价值模板（standard / mirror / elite_first）
→ 按骨架拓扑写节点类型（模板只换类型，不换骨架/深度/边）
→ 分配战斗 RoomData（同一张棋盘 16 场不重复）
→ 分配具体武器 / 护符
→ 冻结并展示（移动前公开，落点不重掷）
```

`BoardConfig.shape_id` 为空时随机；填 `"standard"` / `"long_tail"` 可固定骨架
（测试、截图工具与排查用，正式开局不填）。

## 3. 节点与坐标

长尾骨架新增 `n25–n28`（尾路商店，深度 12），BOSS `n14/n16/n18/n20` 顺延到深度 13：

```text
n13 普通(10) → n21 营地(11) → n25 商店(12) → n14 BOSS(13)
n15 普通(10) → n22 营地(11) → n26 商店(12) → n16 BOSS(13)
n17 普通(10) → n23 营地(11) → n27 商店(12) → n18 BOSS(13)
n19 普通(10) → n24 营地(11) → n28 商店(12) → n20 BOSS(13)
```

节点坐标不再写死在 BoardScreen：
`x = x0 + depth · dx`，`y = row_y[node.row]`（24 / 58 / 92 / 126 / 160）。
棋盘、道路、透明热区按钮、棋子、状态框全部按 `board.layout` 计算，
换骨架只重建按钮集合，不改任何移动/结算规则。

## 4. 规则层面的已知取舍

- **刷新次数共用**：商店刷新上限记在 `_shop_system.reroll_used`（一局一份）。
  走「中段商店 + 尾路商店」时两处共用本局上限，尾路商店不会白送额外刷新；
  走休整侧则只有尾路一家商店。此处暂不改，等真人反馈决定是否按店分配。
- **骨架概率固定 50/50**，未按幕或难度加权；ACT1 只有两套，先看玩家是否感知到差异。
- **岔路提示**沿用 `_bosses_under` 遍历，长尾多出的商店不影响「下游 BOSS」文案。
