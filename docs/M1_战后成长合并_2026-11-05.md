## 1. 本次做了什么

### 1.1 流程变化

**旧流程**

```text
胜利 → 奖励三选一（普通 / 精英）
     → 应用奖励 → 铁砧/金币/掉落 → 历练/熟练结算
     → 若有待选：再弹「成长结算」独立屏（技艺 + 铭印）
     → 间歇
```

**M1 流程**

```text
胜利 → 先结算历练/熟练（成长触发进入队列）
     → 一次「战后成长 · 选择一项」三槽屏
        补给位：治疗 / 最大 HP / 护盾 / 金币 / 消耗品
        构筑位：武器 / 真实增格符号 / 本局伤害
        成长位：技艺 / 铭印 / 下一房对策
     → 选一项 → 铁砧/金币/掉落 → 间歇
BOSS → 不显示普通三槽屏，保留专属战利品；未处理成长进入下一战斗房成长位
```

### 1.2 成长队列

- `GrowthSystem.pending_picks`（技艺）与 `WeaponMastery.owed`（铭印）在胜利结算后进入
  `PostBattleSystem.queue`，顺序与触发一致：先历练，后熟练。
- 一次战后成长最多选一项；选中成长卡才从队列移除。
- 未选中的成长保留到下一战斗房，继续占用成长位，不额外增加战力次数。
- 候选在首次展示时冻结（技艺 id、铭印 id / 调律目标符号），确认前不再随机；
  铭印成长位在锋铸 / 调律中随机取一项并冻结；
  跳过不会刷新成长候选。

### 1.3 候选合法性

- 满血时补给位不出现纯治疗。
- 补给位与构筑位按槽位分别抽取，不会出现两张治疗 / 金币 / 同义数值卡。
- 刷新后展示真实前后值：
  - 治疗：`HP x/y → z/y`；
  - 最大 HP：`最大 HP x → y`；
  - 护盾 / 精英结界：`下一房开局护盾 x → y`；
  - 金币：`金币 x → y`；
  - 伤害：`本局符号伤害 +x → +y`；
  - 铁砧点：`铁砧点数 x → y（跨局）`；
  - 武器 / 符号 / 消耗品沿用 M1-01/02 的预确定 payload。
- 腰带已满时，消耗品卡直接写明「腰带已满 → 折算金币 +N」。
- 武器满双武器仍走既有替换弹层；替换成功 / 失败都回到同一条收尾路径。
- 无待处理成长时，成长位提供真实生效的「下一房对策 · 护盾 +N」；已是最后一场时折算金币。

### 1.4 BOSS 与终局

- BOSS 胜利继续显示专属战利品三选一，不弹普通三槽屏。
- BOSS 触发的技艺 / 铭印不立即处理，留在队列；下一战斗房的成长位接住。
- 最终 BOSS 仍走局末元进度三选一 → 回整备。
- 新一局 / 战败回整备时 `PostBattleSystem.reset_run()` 清空队列。

## 4. 设计取舍与已知影响

1. **技艺选择从「三选一」变为「一次成长位给一项具体技艺」。**
   这是 §4.6「三张卡各为具体对象」的直接结果：玩家选择的是槽位（补给 / 构筑 / 成长），
   而不是在同一屏里挑三张技艺。候选在触发时抽取并冻结；跳过会在下一战斗房继续提供同一项。
   若后续要恢复「成长位内三选一」，需要把成长位扩展为子选择，属于新的设计决定。

2. **普通房 ACT1 构筑位以「本局伤害」为主。**
   旧规则「幕一不出武器」保留；符号灌注只有真实增格时入池。因此 ACT1 普通房构筑位
   可能是锋锐打磨，精英房可出武器。这样保证构筑位永不为空，也不制造死效果。

3. **成长结算提前到选择前。**
   为了让成长位知道本房触发了什么，历练 / 熟练先结算，再生成三张卡。升级回血与
   最大 HP 奖励的先后顺序因此与旧版不同，数值总量不变。

4. **基线探针的成长路径变化。**
   `p1b_baseline` / `audit_playthrough` 仍只取成长位、放弃奖励；`m2_balance_probe`
   优先成长位、否则补给位；`p0_growth_baseline` 仍只取指定铭印类型，没有匹配项就放弃。
   与旧版基线对比时需注明这是 M1 的一次选择制，而不是数值改动。

5. **导出 Demo 仍是 `b004c7b` 构建。**
   `Seek Dead ACT1 Demo.exe`（2026-11-05 20:33）不包含 M1。若要人工复测 P0-1/P0-2，
   继续用该包；若要验证 M1，需要重新导出。两者不要混用同一批答案。
