# 铁砧老虎机 · 执行方案

> 关联文档：`docs/商店升级重构_执行方案.md`（商店 = 每局金币临时强化；本方案 = 跨局永久老虎机）
> 状态：✅ **主线已采纳（gacha 老虎机方向）**：本方案描述的「铁砧 = 老虎机抽装备」正是 `商店升级重构_执行方案.md` §6（2026-08-05 用户拍板）**纯 gacha 定案**所采纳的实现方向——1 行 3 格 mini-reel、消耗 `anvil_points` 摇出武器/护符/消耗品/金币/空白、独立 mini-reel 不依赖战斗 HUD——**应以此为据实现铁砧 gacha**。
> ⚠️ **但「重复 = 升阶」那条线已被取代**：§3 的「重复产出 → `weapon_base_bonus` / `charm_upgrades` 等级通道」、§5 的 per-item 数值升阶扩展，与 §6「武器/护符零盘外数值升级」冲突——§6 已退役 `weapon_upgrades` / `weapon_base_bonus` / `weapon_hit_bonus` / `charm_upgrades` / `interference_resist` 这些 per-item 旋钮。重复产出的正确做法见 §6.5 待办：抽到已拥有的装备 → **转化为点数 / 镀层 / 收藏度**，而非 +N 升阶。实现时 §3/§5 的升阶逻辑需替换为该处理（下文已标注）。

---

## 1. 背景与痛点

当前铁砧（anvil）由两部分组成：

1. **锻造界面**（`anvil_screen.gd`）：花 `anvil_points` 永久升级「武器转轮权重」(`weapon_upgrades`) 与「抗干扰」(`interference_resist`)。
2. **通关三选一元进度**（`_roll_meta_choices`，`duel_controller.gd:632`）：候选池仅含 `damage_mult` 护符、武器基础伤害、武器命中率、铁砧点数兜底。

> ⚠️ 注：上述「锻造界面」(`weapon_upgrades` / `interference_resist` 升级) 是**当前铁砧的现状**，但在 `商店升级重构_执行方案.md` §6（2026-08-05）定案中**已退役**——铁砧改为纯 gacha，不再做任何 per-item 数值升级。本方案 §2–§10 主线（老虎机抽装备）即该定案采纳的方向。

用户新需求：**把铁砧改成一台小老虎机**——消耗铁砧点数去「摇」，摇出**装备（武器）与护符**。

两大待解问题：

- **重复产出**：摇到已拥有的武器/护符怎么办？
- **非数值护符**：部分护符是机制/开关型（无数字可放大），老虎机摇到重复时「+1 级」无意义。

---

## 2. 目标设计

- 铁砧屏改为 **1 行 3 格老虎机**（复用战斗转轮视觉语言，独立 mini-reel，不依赖战斗 HUD 转轮）。
- 每次拉动消耗固定 `ANVIL_ROLL_COST` 铁砧点数（可调，默认建议 10）。
- 3 格各自独立掉落：武器 / 护符 / 消耗品 / 金币 / 空白，整组结算。
- 掉落已有物 → 走「重复处理」（见 §3 修订 + `商店升级重构_执行方案.md` §6.7：按稀有度返还 `anvil_points` / 累计保底计数器 / 图鉴完成度，**不再做 per-item 升阶**）；全新物 → 永久入库（写入 `owned_*` 拥有池）。
- `anvil_points` 跨局持久（现有 `meta["anvil_points"]` 不变）。

## 3. 重复产出处理（核心）—— 方案 A + 封顶兜底

> ⚠️ **2026-08-05 修订（与 §6 冲突，本节升阶逻辑不再采用）**：本节「重复 = 升阶」方案（写 `weapon_base_bonus` / `charm_upgrades` 等级）与 `商店升级重构_执行方案.md` §6「武器/护符零盘外数值升级」**直接冲突**——§6 已退役这些 per-item 旋钮。本节的升阶逻辑**作废**，重复产出的正确做法改为 §6.5 待办：「抽到已拥有的装备 → 转化为点数 / 镀层 / 收藏度」。下文仅保留作「若未来改回允许 per-item 养成」的历史参考，**实现铁砧 gacha 时请勿照此写升阶**。

复用现有 `meta` 字典的「拥有物 → 等级」映射，零新增持久结构：

| 掉落类型 | 已拥有时 | 写入字段 |
|---|---|---|
| 武器（重复） | `weapon_base_bonus[path] += WEAPON_BASE_STEP` | `meta["weapon_base_bonus"]` |
| 护符（重复） | 按 effect 升该护符等级（见 §5） | `meta["charm_upgrades"]` |

**永不浪费**：每次重复都在给收藏「打补丁」，与现有架构零摩擦。

**封顶兜底**：若某物品已达该轴升级上限（`charm_upgrades` 总乘区封顶 `CHARM_MULT_CAP=6.0`，或某 effect 自定义 `max_level`），则自动转成**少量铁砧点数返还**（建议返还 `floor(ANVIL_ROLL_COST * 0.5)`），避免「摇满后全变废格」。

> 注意：当前 `_apply_charms` 仅对 `damage_mult` 应用 `charm_upgrades` 等级（`:572-573`）。非伤害护符要能吃重复升阶，**必须先做 §5 的等级通道扩展**，否则它们的「升级」形同虚设。
>
> ✅ **实际重复处理机制（取代本节升阶，见 `商店升级重构_执行方案.md` §6.7）**：抽到已拥有物 → 按稀有度返还 `anvil_points`（软保底）+ 累计 `anvil_pity` 保底计数器（满则强制从 not-yet-owned 子集抽，保证满图鉴）+ 图鉴完成度 `collection_pct` 元分红。本节「重复=升阶」仅作历史参考，实现铁砧 gacha 时**勿照此写升阶**。

## 4. 入池规则（解决「非数值护符」问题）

老虎机的「重复=升阶」成立的前提是**池内每件东西都能被升级**。据此定入池规则：

### 4.1 入池 = 「可升级」物品
- **数值型护符**（现有 10 个全是）：等级按 §5 公式放大数值。
- **机制型但带「次数/范围」的护符**：等级 = 加次数/加范围。例：「每房免费重转 1 次」重复 → 「2 次」「3 次」，与数值型走同一套 `level` 框架。
- **武器**：基础伤害 / 命中率 / 转轮权重任一可升。

### 4.2 不入池 = 纯布尔/开关型护符
- 效果只有「有/无」、无法用数值或次数表达（例：「首符号必三连」「解锁某系统」）。
- **从老虎机池剔除**，改走其他获取途径：商店、固定掉落、通关/精英奖励、铁砧三选一残留通道。
- 原「方案 A 对池内所有东西都干净自洽，不会卡在 +1 级算啥」的护栏动机，在「重复=返还而非升阶」（§6.7）后已消失——任何护符进池后首次出=入库、重复出=返还，逻辑自洽。建议放宽 §4.2，所有护符（含纯布尔型）均可入池（纯布尔护符只是首次入库即满价值，无害）。

### 4.3 当前护符入池判定（核对结果）

全部 10 个现有护符均为数值型 → **全部可入池**：

| 护符 | effect | 入池 | 升阶方式 |
|---|---|---|---|
| 深渊之瞳 / 狂怒 / 锋锐 | `damage_mult` | ✅ | 乘区 `×(1+STEP·lv)`（现有） |
| 守备 / 铁壁 | `shield` | ✅ | 每回合护盾值 `+value·lv` |
| 守望 | `room_shield` | ✅ | 开局护盾 `+value·lv` |
| 回春 | `heal` | ✅ | 每回合回血 `+value·lv` |
| 锈蚀核心 | `damage_bonus` | ✅ | 伤害符号 `+value·lv` |
| 抗扰 / 呓语残页 | `interference_resist` | ✅ | 抗扰 `+value·lv`（或 +1/级） |

> 结论：**现有内容无需任何「不参与」例外**；入池规则是为「未来机制型护符」预留的护栏。

## 5. 非数值护符的升级通道 —— `charm_upgrades` 等级扩展

> ⚠️ **2026-08-05 修订（与 §6 冲突，本节不再采用）**：本节扩展 `charm_upgrades` 等级通道的前提是「铁砧可 per-item 升阶护符」，但 §6 已定「武器/护符零盘外数值升级」、退役 `charm_upgrades` 等旋钮。故本节**作废**，实现时护符强度只由 `.tres`（`rarity` / `base_power` / `crit_mult`）决定，铁砧不再对任何护符做 +N 升阶。仅保留作历史参考。

### 5.1 现状缺口
`_apply_charms()`（`:564-573`）对各 effect 独立 `match`，只有 `damage_mult` 分支读取 `meta["charm_upgrades"][path]` 等级。其余 effect 直接 `+ cd.value`，忽略等级。

### 5.2 改造目标
把 `charm_upgrades` 等级**扩展到所有 effect**，每 effect 一套 `step` 与 `cap`：

```gdscript
# duel_controller.gd 顶部新增（示例数值，待平衡）
const CHARM_LV_STEP := {
    "damage_mult":        {"mode": "mult", "step": 0.12, "cap": 6.0},   # 现有 CHARM_MULT_STEP/CAP
    "damage_bonus":       {"mode": "add",  "step": 0.25, "cap": 4},     # 每级 +25% 原值
    "room_shield":        {"mode": "add",  "step": 0.25, "cap": 4},
    "shield":             {"mode": "add",  "step": 0.25, "cap": 4},
    "heal":               {"mode": "add",  "step": 0.25, "cap": 4},
    "interference_resist":{"mode": "addi", "step": 1,    "cap": 5},
}
```

`_apply_charms()` 改为：先按 `cd.value` 取基础值，再乘/加 `charm_upgrades` 等级增益（封顶）。

### 5.3 机制型护符的等级语义
机制型护符（带次数）在 `ItemData` 增加可选字段：

```gdscript
@export var level_note: String = ""   # 机制型护符专用：描述每级增益（如"每房免费重转 +1 次"）
```

`_apply_charms` 对机制型 effect 按 `level_note` 约定的次数叠加（由各机制模块读取 `meta["charm_upgrades"][path]` 自行处理，不在 `_apply_charms` 内写死）。

### 5.4 同步修复三选一缺口
`_roll_meta_choices()`（`:646-649`）当前 `if cd.effect != "damage_mult": continue` 跳过非乘区护符。扩展后改为：所有 `levelable` 护符都进候选池，描述按 effect 动态生成（复用 §5.2 的 `CHARM_LV_STEP`）。

## 7. 与商店升级重构的关系（双系统边界）

| 维度 | 商店升级（S12 重构） | 铁砧老虎机（本方案） |
|---|---|---|
| 货币 | 每局金币（临时） | 铁砧点数（永久） |
| 作用对象 | **已装备**物品，本局生效 | 摇出**新物品**或升阶收藏（跨局） |
| 来源感 | 强化身上带着的装备 | 摇奖获得/养成收藏 |
| 生命周期 | `_full_reset` 清零 | `meta` 持久 |

两者不冲突：商店动「本局在手的装备」，铁砧动「跨局收藏库」。
