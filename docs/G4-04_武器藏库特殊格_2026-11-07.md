## 1. 本轮做了什么

按计划 §8.4「首批只允许宝箱、神龛、武器藏库三类，每幕至多 1 个特殊格」，补上第三类 **武器藏库**：

- 特殊格仍是一个槽位，生成时在 `treasure` / `shrine` / `armory` 中随机一类；
- 武器藏库替换 4 条尾路中随机一条的**首格普通战斗**（depth 10），节点总数不变（标准 25 / 长尾 29）；
- 生成时冻结**两把互不相同、且当前装配未持有的武器**，节点文案直接公开两把名字
  （与宝箱相反：这里没有隐藏信息，玩家选路前就知道能拿什么）；
- 落地弹出**二选一面板**：选中一把立即入槽；武器槽已满则接续既有替换弹层；也可以跳过。

`BoardConfig.special_id = "armory"` 用于测试、调试与截图固定类型。

## 2. 结算规则

| 情况 | 结果 |
|---|---|
| 有空武器槽 | 选中武器直接入槽，写入图鉴/来源，重建转轮带 |
| 武器槽已满（2） | 接续既有替换弹层：选一把旧武器替换；取消 = 放弃（节点已消耗） |
| 跳过 | 不获得武器，节点消耗 |
| 候选已持有（落地前变动） | 折算金币 +15 |
| 藏库为空（池耗尽） | 折算金币 +15 |

全部复用既有武器授予、替换预览、图鉴记录与金币兜底；没有新增伤害、成长、掉落或存档字段。

## 3. 生成顺序（在 G4-02 之后）

```text
本局种子
→ 抽骨架（standard / long_tail）
→ 抽分支价值模板
→ 按骨架写节点类型
→ 抽特殊格并替换一条尾路的普通战斗
   ├─ 宝箱：冻结类别 + 具体物品（只公开类别）
   ├─ 神龛：冻结效果 + 数值（开局公开）
   └─ 武器藏库：冻结两把不同武器（开局公开名字）
→ 分配剩余战斗 RoomData（同盘不重复）
→ 分配武器格 / 护符格
→ 冻结并展示
```

两把候选通过既有获取权重无放回抽取，并排除当前装配；同种子可复现（已断言）。

## 4. 已知取舍

- **单一槽位**：一局只出现宝箱 / 神龛 / 武器藏库之一，武器藏库约 1/3；
  若希望「每局都能见到装备向特殊格」，需要再讨论槽位数量或权重。
- 该尾路 **7 场战斗**（特殊格顶掉一场普通战斗），与宝箱、神龛相同。
- 武器藏库给的是**确定武器**而非战斗奖励，不走战后成长；是否让装备来得太轻松待 G5 真人判断。
- 二选一面板是新增 UI，但只复用现有按钮/面板样式，不引入新系统。
- 武器池 14 把、装配上限 2，两把候选永远能凑齐；空池兜底只作为防御性分支。
