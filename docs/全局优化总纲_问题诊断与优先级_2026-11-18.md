# Seek Dead 全局优化总纲 · 问题诊断与优先级路线图

> 日期：2026-11-18（含内容系统整合更新）
> 性质：全局诊断 + 优先级规划（**未改代码**）
> 依据：对战斗 / 经济 / 成长 / 结算 / 元进度 / 存档 / 初始状态 / 三选一 / 地图 / 内容系统的全项目核查
> 关联企业诊断：`战斗策略与数值结构审查_2026-11-11.md`、`设计建议_去铁砧与怪物学技能_2026-11-16.md`

---

## 1. 一句话结论

**项目工程完成度很高，但存在"数值结构失衡 + 大量设计/实现脱节 + 内容系统缺位"三类系统性问题。**
优化顺序：**修正确性（L0）→ 定数值（L1）→ 建结构（L2）→ 完善内容机制（L3）→ 内容扩展打磨（L4）**。
理由：地图节点依赖经济参数、收集品框架依赖结构层稳定、内容机制依赖框架——**地基不定，上层返工**。

---

## 2. 五层优先级路线图

| 层 | 主题 | 范围 | 周期 | 为什么这个顺序 |
|---|---|---|---|---|
| **L0** | 地基 · 修正确性 | 死字段 / 死配置 / 假选项 / 注释矛盾 | 1-2 天 | 低风险高确定性；所有决策依赖正确数据 |
| **L1** | 核心 · 数值结构 | 战斗曲线 / 经济 / 元素 / 成长节奏 | 1-2 周 | 决定"好不好玩"；地图节点与掉落依赖它 |
| **L2** | 结构 · 系统骨架 | 分岔地图 + **本局收集品框架**（遗物/牌谱） | 4 阶段 + 2 阶段 | 依赖 L1 参数；一次性架构投入解决多个内容问题 |
| **L3** | 机制 · 内容系统 | 意图 / DoT / 信物机制 / BOSS 去同质化 / 决策深度 / **战后结算呈现** | 2-3 周 | 依赖 L2 收集品框架；让内容有"玩法"而非纯数值 |
| **L4** | 扩展 · 内容打磨 | 三选一补卡 / 玩法改变型成长 / 元进度 / 新手引导 | 持续 | 地基稳后堆量才有意义 |

> **逐层推进原则**：完成并 F6 验证一层，再进下一层。每层单独提交。

### 3.3 L0 补充修复：技艺选不到（2026-11-18，P0-P4 重构遗留）

**问题**：m2_growth_test 有 1 项失败暴露了真实功能缺失——升级 Lv.2/4/6 给的 `pending_picks`（技艺选择）
在新 Draft 战利品路径里永远无法兑现。旧 `GrowthLootOffer._inject_queued_growth()` 会把成长位塞进战利品选项，
但 P2 切到 Draft 引擎后 `definition_to_option()` 只有 `kind="reward_definition"`，
`auto_pick_post_battle` 找不到 `queued_growth`，`after_loot_settled()` 又 `clear_pending_choices()`——
玩家看到"获得 1 次技艺选择"日志，却永远选不到技艺。真人 F6 也受影响（技艺界面不出现）。

**方案（用户拍板 A）**：技艺并入 Draft 卡池，与种子卡同屏竞争，统一为构筑决策。
- `_make_perk_def()` 动态构造技艺卡（`effect_id=pick_perk`，不做静态 .tres 污染常驻卡池）
- `pending_picks>0` 时注入 3 张家族各异的技艺卡，`_compose_samples` 保证至少 1 张进候选
- Resolver 加 `pick_perk` 分支调 `growth.pick()`（校验并扣减 pending_picks）
- `auto_pick_post_battle` 适配新路径（识别 `id` 以 `perk_` 开头的卡）
- 技艺卡设 uncommon，选中即兑现升级奖励；不选则随 `after_loot_settled` 放弃（符合现有语义）

**验证**：P0/P1 38/0、P2/P3/P4 39/0（新增 4 项技艺验证）、m2_growth_test 85/0（原失败项已修复）。

## 4. L1 核心层：数值与战斗结构（最关键）

> 这是游戏"好不好玩"的根本。项目组自己的审查文档已识别核心矛盾，但代码未收敛。

### 4.1 战斗数值曲线（经实测重审，结论已修正）

> ⚠️ 旧诊断（基于 2026-11-11 审查文档）部分已过时，本节用当前代码实测重写。

**旧诊断的两处错误**：
1. "三连必暴×2.0"已不存在——当前代码（`combat_system.gd:87-134`）是"同源三连用武器专精倍率、
   同族混合固定1.5倍、同元素共鸣不再自动必暴"（2026-08-07 改）。
2. "核爆/充能改固定值"的建议不成立——百分比伤害是合理机制（对抗高血量的保底），
   且秒杀主因不是它（170HP 怪一回合吃 264 伤害，核爆12.5%才21点）。

**2026-11-18 实测扫描**（strategy_probe，4 档倍率 × 2 策略 × 2 种子）：

| 倍率 | 普通怪回合 | 精英回合 | BOSS 回合（明细） |
|---|---|---|---|
| **1.5（当前）** | 1.4 | 1.5 | 5.5（3/7/3/9） |
| 1.2 | 1.5 | 1.9 | 4.0 |
| 1.0 | 1.9 | 2.6 | 9.2（3/19/3/12，方差爆炸） |
| 0.8 | 2.6 | 2.9 | 6.8 |

**核心结论**：
- 玩家"会瞄准=100%停中→秒杀通关，不会=22.6%→第4房死"——**问题是目押决定论（技巧鸿沟），不是纯数值**。
- 全局降倍率到 1.0 虽让 BOSS 均值达 9.2，但**方差爆炸**（3-19回合，取决于 BOSS 机制），不稳。
- 单纯堆 BOSS HP 会被 maxHP% 核爆抵消。
- **BOSS 回合数的答案在机制层（L3），不在数值层**——应靠阶段无敌/护甲回复/恢复窗口让机制撑起时长，
  而非堆血或降倍率。

**决策（2026-11-18，用户认同）**：
- 倍率 1.5 **保留**（是全部数值的平衡基准，推翻要重做整个敌人体系，风险收益比最差）
- 不做全局数值大改；战斗时长作为"机制设计结果"而非"调参目标"
- 战斗数值这块**不在 L1 硬调**，移交 L3：BOSS 机制去同质化 + 目押鸿沟弥合（§6.1/§6.4/§6.5）
- L1 经济调整已完成（§4.2），战斗曲线项到此收口

### 4.2 经济闭环（P0-P1）

| 问题 | 事实 |
|---|---|
| 起始金币 4 买不起任何东西 | 最便宜消耗品 5、武器 8（`shop_config.tres:7`）；稀有武器 8×3=24、epic 40 |
| 利息自我封顶 | `meta_store.gd:223` `min(gold/5,5)`，持 25 金即触顶，后期金币边际效用归零 |
| 槽位天花板锁死出口 | 武器开局满 2（`loadout_system.gd:65-72`），商店对武器永远只能替换不能扩槽 |

**建议（经典校准）**：起始金币 **4 → 20-30**（参考杀戮尖塔 99，按本项目低产出下调）；
利息改**衰减曲线**；提供金币高位出口（付费移除负向护符/元素重铸）；复核稀有定价倍率。

**✅ L1 已实施（2026-11-18，保守起步值，待 F6 验证微调）**：

| 项 | 原值 | 新值 | 落地位置 |
|---|---|---|---|
| 起始金币 | 4 | **25** | `balance_config.tres.starting_gold`（单一真源，duel_controller/loadout_system 均读它） |
| 利息 | 每5金+1，上限5（25金即触顶） | **每15金+1，上限8** | `balance_config.tres.interest_per_gold/interest_cap`，meta_store.award_gold 读取 |
| 稀有定价倍率 | common1/uncommon1.8/rare3.0/epic5.0 | **1 / 1.6 / 2.4 / 3.6** | `shop_config.tres.rarity_price_mult` |

武器定价变化：common 8（不变）/ uncommon 14→13 / rare 24→**19** / epic 40→**29**。
起始 25 金可买 common×3 或 rare×1+消耗品×2。
利息新曲线：25金=+1、50金=+3、120金=+8（原25金就+5，开局吃满）。
"槽位天花板锁死出口"未在本轮处理，留待后续金币高位出口设计。

验证：解析无错、P0/P1 38/0、P2/P3/P4 39/0、m2 85/0、g7_run3 52/0、board_ui/boss_loot/boss_rhythm/charge_rule 全通过。

### 4.3 元素与 BOSS 数值（P1-P2）

**元素环**：光克暗+毒、火克冰+毒（各 2 目标），冰/暗/毒只克 1（`element_counter.gd:24-30`）；
光系符号最多（16 vs 冰/火 7）→ 隐性支配。同元素 ×0.85 惩罚单元素构筑。
→ 建议：克制数量对称化、符号池配平、减轻/取消同元素惩罚。

**BOSS 数值**：13 个 gimmick 中约 8 个是"每 N 回合施压 + 恢复窗"同一模板；多个 P2/P3 只是调 atk_mult/armor 的假机制。
→ 机制层面的去同质化放到 L3（§7.2），本层只处理数值曲线。

**L1 验收**：F6 实测战斗回合数落在目标区间；起始商店可消费；元素胜率无支配；全量测试回归。

### 5.2 本局收集品框架（2 阶段）★ 新增

> **核心洞察**：信物（遗物）、牌谱本质是同一类东西——"本局永久生效的规则层收集品"。
> 不为它们各建一套系统，而是建一个统一框架，一次投入解决多个内容问题。

**信物遗物化（用户已拍板：独立遗物栏）：**

现状问题（这是用户直觉"信物是个大问题"的根因）：
- 12 个信物是 epic 护符，**占护符槽 1/3**（`reward_system.gd:802`：槽满就不出）→ 打赢 BOSS 却因槽满拿不到，高潮落空
- 效果与护符同质（+6 攻/+18 盾/+1.3 倍率…），身份混淆
- 一局最多戴 3 个，其余白打

**方案**：
- 信物脱离护符槽，成为**独立遗物栏**：拥有即生效、不占槽、不互斥
- 打赢 BOSS 必得，永久增强本局——经典 roguelike 遗物做法（杀戮尖塔遗物 / 哈迪斯紧凑道具 / Balatro 小丑牌）
- 现有 12 信物效果可直接迁移，不用重做内容；玩家能攒一排遗物，成就感强烈
- **否决"信物做武器"**：武器已 90 把，BOSS 已掉主题武器（`roll_boss_rewards` ①），再做武器是重复且丢失纪念品身份

**统一框架设计：**

| 收集品类型 | 来源 | 效果性质 | 挂载 |
|---|---|---|---|
| 遗物（信物改造） | BOSS 掉落 | 数值 / 规则增强 | 拥有即生效 |
| 牌谱 | 专属掉落（精英/节点） | 规则解锁（凑牌） | 拥有即生效 |

两者共用：收集容器、UI 列表、"拥有即生效"结算钩子、本局清零。
牌谱物品化详见 `牌型作为成长奖励_设计评估_2026-11-18.md`。

**实施阶段：**
- 阶段 E：收集品数据层 + 结算钩子（遗物从护符剥离，牌谱接入）
- 阶段 F：收集品 UI 面板（遗物栏 + 牌谱栏，可视化"本局收集"）

**L2 验收**：地图走通；BOSS 遗物必得且无需槽位；遗物/牌谱面板正确显示与生效；战斗与三选一零回归。

## 6. L3 机制层：内容系统（让内容有"玩法"）

> 依赖 L2 收集品框架。这一层解决"内容只是数值、缺玩法"的问题。

### 6.1 意图系统（P1）

现状：`IntentData` 已有，BOSS 有可预告机制，但**普通怪意图不改变玩家决策**（只有 BOSS 律法是正例）。
→ 建议：让敌人意图真正影响玩家回合选择——敌人蓄力重击时防御/治疗符号收益临时提升，
  迫使玩家根据意图调整按停目标。契合 L1 §4.4"局内决策深度"。

### 6.2 DoT 系统（P2）

现状：`status_system` + burn/frost/poison 已有（`symbol_data.gd:13`），但 DoT 存在感弱，只是附属伤害。
→ 建议：把 DoT 做成**独立构筑流派**——毒系符号/遗物/技艺联动（如"每层毒额外+X""毒层满触发爆发"），
  让毒成为一条可专注的 Build 路线，而非锦上添花。

### 6.3 信物机制深化（P2，L2 之后）

L2 完成遗物栏后，进一步让每个遗物绑定 BOSS 机制主题（如冰封铁瓮→冻结相关），
拿到后"解锁/强化对应流派玩法"，而不只是 +数值。契合总纲"玩法改变型成长"。

### 6.4 BOSS 机制去同质化（P2）

合并机制重叠 BOSS（呓语教徒 vs 迷宫低语者）；阶段变化绑定"改变玩家决策规则"而非纯数值放大。
与 §6.1 意图系统联动：让每个 BOSS 有独特的"意图语言"。

### 6.5 局内决策深度（P3）

充能改手动释放（现满 6 自动，`combat_system.gd:655`）；给每回合一次轻量战术选择；
弥合目押技巧双曲线（100% vs 22.6% 停中）。

### 6.6 战后结算呈现：三选一界面升级为结算页（P1，用户 2026-11-18 提出）

**问题诊断**：战后收益散落、玩家感知弱。核查 `room_flow.gd`：

- `_settle_victory()`（:174）：经验 / 回春 / 积蓄 / 武器熟练——只写日志
- `_award_victory()`（:186）：铁砧点 / 金币 / 掉落——只写日志 / 飘字
- 然后直接进三选一；打赢 BOSS 的成就感被一闪而过的日志流冲淡

**否决"独立结算过场页"**：收益全是自动发放（无需玩家选择），做成独立页 = 每场战斗多点一次"确定"。
经典 roguelike（杀戮尖塔 / Balatro / 哈迪斯）均无每战过场页——这是节奏灾难。

**方案：三选一界面 = 战后结算页（合一）**：

- **普通战**：三选一界面顶部加一条"本场战果"栏——金币 +X / 历练 Lv / 熟练 +Y / 铁砧 +Z / 掉落，
  把散落日志汇总到一处（数据已在各 settle 方法里，只是没汇总展示）
- **中间仍是三选一卡片**：唯一需要玩家决策的地方，不增加任何点击

### 7.1 技艺卡品质与数量（与三选一卡片同步优化）

> 用户 2026-11-18 指示：技艺卡与三选一卡片的优化**同时进行**，数量可增可减。

品质栏显示【进阶】——但这是无意义的统一标签，不对应任何真实差异。

**核心认知（避免踩坑）**：
- 技艺是"升级欠账兑现"，不是从池子里按稀有度抽出来的——`pending_picks>0` 时才注入，
  且"3 张家族各异 + 保证至少 1 张进候选"。**稀有度梯度对技艺无意义**。
- 给技艺分 common/uncommon/rare 会重蹈"共鸣品质不一"覆辙（同系统卡品质不一 = 玩家困惑）。
  品质是给玩家看的语义，不是统计旋钮。
- 技术细节：技艺卡 rarity 会影响 `RARITY_WEIGHT` 采样权重（common 60 vs rare 9）。
  若统一设 common 会过度出现、压过共鸣卡——**需把它放"保底位"或用独立权重处理**，不能简单改 rarity 了事。

**待决策点（L4 阶段拍板）**：
1. 技艺卡品质策略：全部统一 common / 卡面用家族标签（生存·运筹·目押）替代品质显示 / 其他
2. 技艺数量：当前 8 项是否增减（与三选一种子卡 8 张同步考虑）
3. 采样方式：技艺卡是否脱离稀有度加权（保底位注入），避免挤压种子卡

## 8. 横切主题：贯穿所有层的三条原则

1. **配置单一真源**：`.tres` 为准，删脚本默认值、删死配置，避免"改了没生效"。
   本项目已多次出现"定义了没实现"（rarity/stack_rule/loot_skip_gold），这是最大隐患来源。
2. **设计意图要落文档**：三选一的多次返工（幸运余波、共鸣品质）都因意图没固化。每做完一个决策就写进对应文档。
3. **每阶段单独验证 + F6**：数值改动实测回合数；结构改动端到端走通；不一次性推倒。

## 10. 一句话总结

**先清垃圾数据（L0），再定数值结构（L1），再建系统骨架——分岔地图 + 统一收集品框架（L2），
再让内容有玩法（L3），最后堆量打磨（L4）。**

项目的病不在"功能不够"，而在"数值失衡 + 设计实现脱节 + 内容系统缺位"——把三类问题解决，现有内容潜力即可释放。
