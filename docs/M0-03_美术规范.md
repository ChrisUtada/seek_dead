# M0-03 · 美术规范（候选锁定）

> 状态：**候选规范已锁定（2026-10-29）**。数值与规格可直接用于 M3 制作；颜色在 M3 实机截图中复核，通过后转正式规范。
> 依据：《统一落地执行计划》M0-03、《UI与像素美术_整体改造计划》§3、《美术制作与AI量产_最佳实践方案》。
> 工具：`tools/art_pipeline/`（`palette.json` 为色板权威来源，`pipeline.py check` 为自动验收）。
> 纪律：本阶段只定规范与工具，不改 `battle_theme.tres`、`palette.gd`、任何战斗逻辑。

## 1. 分辨率与显示基准

- 逻辑分辨率 **480×270**，默认窗口 960×540（`canvas_items` 2× 整数放大），纹理过滤 NEAREST。
- 核心规则：**素材原生分辨率 = 逻辑显示尺寸（1:1）**，禁止靠非整数缩放制造大小差异。
- 同屏像素密度一致：玩家 1 像素 = 敌人 1 像素 = BOSS 1 像素；BOSS 靠画布更大表达体量，不靠放大同一张图。

| 对象 | 原生画布 | 逻辑显示 | 现行实现 | M3 需要的调整 |
|---|---|---|---|---|
| 玩家 / 友方 | 48×48 | 48×48 | `battle_hud.tscn` 玩家节点 48×60 + `KEEP_ASPECT_CENTERED` → 48×48，已 1:1 | 无 |
| 普通敌人 / 精英 | 48×48 | 48×48 | `ENEMY_SPRITE_SIZE = 44×60` → 44×44，16×16 默认图被放大 2.75× | **容器改 48×60**（表现层，一处常量） |
| 常规 BOSS | 96×96 | 96×96 | `art_scale 2.0 × 44` → 88×88，48×48 旧图被放大 1.83× | 基准改 48 后 `art_scale 2.0` → 96×96，1:1 |
| 真·最终 BOSS | 144×144 | 144×144 | 未启用 | M6 试，`art_scale 3.0` |
| 转轮 / 状态 / 元素符号 | 16×16 | 16×16 | emoji label | 独立绘制，不从 48×48 缩小 |
| 物品栏 / 商店图标 | 24×24 | 24×24 | emoji label | 独立绘制 |
| 武器卡面主图 | 48×48 | 48×48 | 无 | 独立绘制，不缩小 24×24 得到 |
| UI 面板 / 按钮 | 1px 硬边，9-slice 或 StyleBox | — | Theme/StyleBox | 见 §3 |

**与《UI与像素美术_整体改造计划》的差异（有意为之）**：

1. 该文档建议 BOSS「优先 64×64」。64 与现行 44 / 目标 48 基准都无法整数对齐，实机会被缩放到 1.375× 或 0.69×，违反 1:1 规则。**改为 96×96**（= 48×2），`docs/M0-02_样板范围.md` 中冰封铁瓮的 64×64 同步按本表修订。
2. 该文档「武器小人 48×48」已被 M0-02 取代：武器主视觉是**物品图标**（24 + 48），不做武器小人，也不做武器攻击动画。

### 2.4 色数上限

| 资产 | 上限 | 说明 |
|---|---:|---|
| 角色 / 普通敌人 / 精英 | 12 | 单帧 |
| BOSS | 16 | 允许少量标志性部件色 |
| 24×24 物品图标 | 8 | 1–2 个主色 + 暗部 |

使用纪律：

- 红只表达敌方、伤害、危险；金只表达可操作、奖励、重要选择。
- 元素身份必须「形状 + 颜色」双编码，不允许同一轮廓换六色。
- 不使用主色板外的颜色；半透明仅允许 0 或 255（`pipeline.py` 会硬化）。
- 面板底色用实色，不用高透明叠色。

## 3. 线宽、圆角与间距

- 圆角一律 0；所有组件方角。
- 普通分隔 / 格子 / 次级容器：**1px**；当前选中、主操作、BOSS 重点框：**2px**。不再整体 2px。
- 基础间距单位 **4px**；紧凑处 2px；面板内边距 4–6px。
- 主线框暖白 `text_main`，次级容器 `text_muted` 的暗化值，禁止所有面板同时高亮。
- 铆钉 / 角饰只用于一级框架与稀有奖励。
- M3 移除主 HUD 的 10px `DeviceFrame` 厚框与无功能装饰点（`palette.gd BORDER_WIDTH` 由 2 收回 1，重点处单独 2）。

---

## 4. 字体与字号

- 字体保持 `VonwaonBitmap-12px`（主）+ `zpix`（中文回落），不更换。
- 仅使用已缓存档位 **9 / 10 / 16px**；禁止任意字号与非整数缩放。
- 战斗 HUD 删除常驻「Seek Dead · 老虎机对决」标题；产品名只出现在开始 / 结算 / 试玩说明。
- 数值一律「图标 + 数字」；HP、攻击、意图不得只靠 9px 弱文字。
- 中文正文在 9px 下读不清时，删文案或放大 tooltip，不缩字。
- 装饰性字体仅限英文短标题。

## 5. 图标、锚点与命名

### 5.1 锚点

- 角色（玩家 / 敌人 / BOSS）：脚底贴画布最后一行；水平包围盒中心与画布中心偏差 ≤1px。
- 图标（16 / 24 / 48）：主体居中；16×16 主体占画布 ≥50% 边长，24×24 ≥40%。
- 多帧动画：帧间脚底偏移 0px、中心偏移 ≤1px；站立帧身体宽高跨批偏差 >±8% 判不合格。

### 5.2 目录与命名

```text
assets/
├── characters/<npc_id>/idle_01.png …        # 玩家与需要多帧的角色（48×48）
├── enemies/<visual_id>.png                  # 普通 / 精英（48×48）
├── bosses/<boss_id>.png                     # 常规 96×96，最终 144×144
├── icons/
│   ├── weapons/<weapon_id>_24.png           # 24×24
│   ├── weapons/<weapon_id>_48.png           # 48×48 卡面
│   ├── symbols/<symbol_id>.png              # 16×16
│   ├── statuses/<status_id>.png
│   └── intents/<intent_id>.png
└── ui/                                      # 九宫格与角饰
```

- 命名一律 `snake_case`，与 `resources/` 中的资源 id 同名（`fire_sword.tres` → `icons/weapons/fire_sword_24.png`）。
- 帧命名 `idle_01`、`attack_01`…；不写尺寸、版本、作者。
- 原始 AI 图放 `raw/art/<批次>/`（不入库），入库只放归一后的成品。

## 6. 自动验收阈值

`python tools/art_pipeline/pipeline.py check <files> --mode <mode>`，逐条对应：

| 检查 | 判定 | 阈值 |
|---|---|---|
| 尺寸 | FAIL | 必须等于目标画布 |
| RGBA / 透明 | WARN | 模式非 RGBA；透明像素 <5% |
| 色数 | FAIL | 超过 §2.4 上限 |
| 板外色 | FAIL | >5% 像素不在主色板 |
| 主体占比 | FAIL | 16 / 24 图标包围盒面积 <25% |
| 脚底 | WARN | 角色距画布底 >1px |
| 居中 | WARN | 包围盒中心偏移 >1px |

人工验收（每批必须做）：

1. 1× 实际大小可辨（不看放大图）。
2. 纯黑剪影可区分（`sheet --silhouette`）。
3. 同批描边、比例、视觉重量一致。
4. 与同屏转轮、SPIN、意图、匹配角标同时出现时仍可读。
5. 实机 480×270 / 960×540 / 1440×810 / 1920×1080 整数放大清晰，1280×720 布局可用。

## 7. 动画与演出

- 玩家：idle 4 帧（循环），attack 5 帧，单次攻击 ≤0.30s；受击/死亡走程序化演出。
- 敌人 / BOSS：静态帧 + 位移 / 暖白闪（`impact`）/ 明暗反相 / 死亡溶解；不做完整动作集。
- 受击禁止红色闪烁（红敌会糊成一片）；用 `impact` 暖白或反相。
- 演出随机仍走局部 RNG，不消耗全局种子。
- 动画只由演出层读取，不改变战斗结算节奏。
