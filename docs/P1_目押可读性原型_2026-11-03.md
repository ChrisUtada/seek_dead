## 2. 预设表

命令行：`-- --p1-preset=<name>`（注意 `--` 之后才是用户参数）。战斗内 **F8** 在 `control` / `readable` 之间切换，便于同局 A/B。

| 预设 | 起始间隔 | 最快间隔 | 加速/拍 | 下格预览（洞察 +1） | 视觉落点 | 一拍缓冲 | 停轮反馈 |
|---|---:|---:|---:|---:|---|---|---|
| `control` | 0.15 | 0.06 | 0.0010 | 0 | 关 | 关 | 关 |
| `readable` | 0.15 | 0.085 | 0.0007 | 2 | 开 | 开 | 开 |
| `speed` | 0.15 | 0.085 | 0.0007 | 0 | 关 | 关 | 关 |
| `preview` | 0.15 | 0.06 | 0.0010 | 2 | 关 | 关 | 关 |
| `visual` | 0.15 | 0.06 | 0.0010 | 0 | 开 | 关 | 关 |
| `buffer` | 0.15 | 0.06 | 0.0010 | 0 | 开 | 开 | 关 |
| `feedback` | 0.15 | 0.06 | 0.0010 | 0 | 关 | 关 | 开 |

- `control` 与 P0 基线完全一致：0.15 / 0.06 / 0.0010。
- `readable` 不是把所有参数调到最慢；它只把最快阶段从 0.06 抬到 0.085（带尾两格反应窗口 0.12s → 0.17s），并叠加独立可拆的预览/落点/缓冲/反馈。
- 洞察（`insight`）在 P1 预览行开启时额外 +1 格；`control`（预览 0）仍走原来的格内 ▸ 预览，不改变对照。
- `steady` 技艺仍按 `GrowthSystem.spin_wait_base()` 把每房前 2 回合基础间隔抬到 0.17s；P1 不改这条规则。

## 3. 关键语义

### 3.1 视觉落点与逻辑落点

- 逻辑游标 `reel_cursor` 每逻辑拍 +1；视觉 `ReelSpinView` 每帧按同一节拍推进 `_index/_frac`。
- 玩家按停时，`ReelSpinView.center_index()` 返回**视觉上最接近窗口中心的一格**：
  - `_frac < 0.5` → `_index`；
  - `_frac ≥ 0.5` → `_index + 1`（模带长）。
- `visual` / `readable` 只允许在逻辑游标 **前/后一格**内对齐；视觉索引偏离更多时回落到逻辑游标，避免帧卡顿变成隐式多格缓冲。

### 3.2 最多一拍输入缓冲

仅当同时满足以下条件才排队：

1. 预设开启缓冲（`readable` / `buffer`）；
2. 视觉中心正好是逻辑游标的下一格；
3. 该列尚未进入队列。

行为：按停当拍不落子，下一逻辑拍游标到达该格时锁定。**最多一拍**；队列在 `finish_spin()`、新一局、列已停时清空。它不会自动选择目标，也不会跨多格追符号。

### 3.3 目标声明

- 默认目标 = **主武器（配装第一把）中权重最高的 `damage` 符号**；P0 基准配装下为 `fire_slash`（`burn` 是 status，不计入）。
- 可用 `--p1-target=res://resources/symbols/xxx.tres` 覆盖；覆盖后整局不切换。
- HUD 目标行显示 `🎯 符号名 · 预设名`，让测试者无需打开武器面板即可确认当前目标。

### 3.4 命中反馈（不改数值）

- 每列停轮后显示：`1 火斩✓`（目标）、`1 匕斩`（普通）、`1 MISS`（废铁/MISS）、`1 注废`、`1 锁轮`、`1 夺轮`。
- 回合结算底部仍显示原有反馈，并新增 `三连` / `同元素三连` 文案。
- 只有 `feedback` / `readable` 预设显示停轮结果；`control` 保持原界面，避免反馈本身污染对照。

### 3.5 遥测

`RunTelemetry` 新增：

| 字段 | 含义 |
|---|---|
| `target_symbol` | 本局声明目标 |
| `stop_total` | 玩家主动按停列数（不含敌人夺轮） |
| `target_hits` | 落在目标符号的列数 |
| `target_hit_rate()` | `target_hits / stop_total` |
| `forced_stops` | 敌人夺轮等非玩家停轮 |
| `buffer_queues` | 进入输入缓冲的次数 |
| `stop_outcomes` | `target/normal/miss/jam/lock/forced` 分布 |

局末 `RoomFlow` 原有的一行 summary 已包含「目标停中 n/m(pct) · 缓冲 n」。

- [ ] `steady` / `insight` 仍有增益空间：去掉它们后，`readable` 的目标停中率应可测量地下降，而不是“有没有都一样”。
- [ ] 没有测试者反馈“预览/目标行本身让我不用看转轮”。

### 5.4 解读限制

- `readable` 同时改速度、预览、落点、缓冲、反馈，第一轮只能回答“组合是否有效”；要拆单项，用 `speed` / `preview` / `visual` / `buffer` / `feedback` 预设做第二轮。
- 目标停中率的分母是玩家主动按停列数；敌人夺轮、冻结列、锁轮列不计入。
- 同一局内 F8 切换会让数据混组；只允许局间切换。
- P1 不改数值，因此通关率变化只应来自操作质量与承伤，不应出现“停中后伤害凭空变高”。

## 6. 已知限制

1. **预览是独立行，不是格内滚动层**：38px 格子 + `clip_contents` 使格内实际只能看到当前格和下一格的一半；`ReelSpinView` 的 5 槽布局在裁剪后不等于“前向 2 格”。P1 用右侧独立预览行解决，不改格子尺寸。
2. **视觉索引仍可能受帧率影响**：正常 60fps、最快 0.085s/格时不会跨多格；代码已把对齐限制在前/后一格，异常帧只会回落到逻辑游标。
3. **目标自动选择只覆盖主武器最高权重 damage**：多目标、三连路线、同元素构筑的取舍不在 P1。
4. **未做真人数据**：本文档只给出协议与自动验证，不把 bot 结果写成真人结论。
5. **`feedback` 只影响 HUD 文案**：遥测在所有预设下都记录，方便对照组成绩仍可比较。
