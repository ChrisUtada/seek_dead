## 0. 一句话设计

老虎机 + build 策略 + 数值膨胀。**爽感来自"看得懂的大数字"，策略来自"转轮之前的 build 决策"，复杂度靠"砍平行系统、呈现层降负"压住。**

---

## 1. 核心矛盾与解法（本框架的根基）

**矛盾**：小丑牌(Balatro)的乘区爆炸之所以成立，是因为玩家**完全掌控出什么牌**（组牌 + 自己把手牌打出去）。但老虎机是**纯随机出符号**——玩家对"这一转转出什么"几乎零控制。

**若照搬小丑牌"战斗内多乘区"**：伤害 = 随机符号 × 一堆看不出哪个生效的乘区 = 黑箱。策略感从"我怎么出牌"降级成"我堆了哪些 buff"，**反而削弱**老虎机。

**解法（两条）**：

- **策略放在 build 层（转轮之前）**：决策发生在整备、商店、升级；战斗内是决策的兑现（纯随机连线爽感）。
- **膨胀长在 build 层**：数值爆炸来自"武器升级（线性）× 护符（乘法）"的积累，不来自战斗内的多步计算。

这条是整个 v2.0 的基石，所有取舍都由此推出。

---

## 2. 设计原则

沿用 `分类重构方案.md` 的「数据即 Resource / 无全局注册表 / 文件夹自动发现 / 表现逻辑分离」，并新增：

- **P0 爽感可解**：每个大数字都能分解出"为什么这么大"（伤害分解显示，见 §5）。
- **P1 策略在 build 层**：决策在整备/商店/升级，战斗内是兑现。
- **P2 温和奖罚**：保留"带对克 ×1.5 / 带错抗 ×0.85"的真实相克（更有深度、更真实），但**幅度温和、从敌人视角呈现（弱点/抗性）**，不背环、不崩盘（见 §6.2）。
- **P3 少而强的乘区**：乘区数量少（3 个），每个都直观（连线/护符/克制）。
- **P4 双轨膨胀**：线性（武器升级）× 乘法（护符），两条线玩家算得过来。
- **P5 取舍即策略**：策略性来自有意义的取舍（如武器槽稀缺 vs 元素覆盖），**不是机制数量**。计算负担 ≠ 决策质量。
- **P6 敌我同步膨胀（ante）**：玩家变强，怪物同步变强，否则中期秒怪、游戏提前结束。
- **P7 禁 mutate 共享 .tres**：局内改动一律走"按 `resource_path` 的运行时加成表"（复用 `run_symbol_bonus` 范式），绝不改共享资源。
- **P8 内容广度撑长尾**：长线新鲜感靠更多武器/护符/敌人/房间，**不靠再加系统**。
- **P9 技能层归玩家**（v2.1 新增）：转轮结果由玩家按停时机决定，不由后台 RNG 代劳。凡"玩家能操作的环节"，不设自动兜底。
- **P10 槽位按"是否进池"管控**（v2.1 新增）：进转轮池的（武器/增益）稀释带子、影响手感与克制浓度，必须严格限量；不进池的（消耗品/护符）只占界面，可宽松。**不按数量一刀切。**

## 3. 核心循环

```
整备(build) → 转轮(随机连线爽) → 结算(伤害分解) → 奖励(金币/掉落)
     ↑                                                  ↓
     ←──────────  商店(投资) ← 下一房(更深更难/ante)  ←
```

- **策略**发生在：整备（选武器/符号池）、商店（投资配比）、升级（线性 vs 乘法）。
- **技能**发生在：转轮（按停时机，见 §4）。
- **爽感**发生在：转轮（连线命中）、结算（大数字 + 分解）。

## 4. 转轮交互模型（方案 A：实体转轮带 + 玩家手动停）

> v2.1 新增。**已落地**，取代原先的"后台加权随机一次抽完"。

### 4.1 为什么改

原模型是：按 SPIN → 后台按权重抽一次随机数 → 直接出结果。玩家零操作空间，结果 100% 由 RNG 决定。这导致"权重"在玩家眼里像一张**被后台操控的不透明概率表**，而不是一台看得见的老虎机。

真实老虎机的"权重"本质就是**转轮带上该符号的格子数**（strip composition）。整备界面的「🔥×5 ✕×3 🗑️×2」本就该读作"火格占 5/10、交叉 3/10、废铁 2/10"——概率与带子长度一一对应，权重本身没有问题，**缺的是玩家的操作环节**。

### 4.2 模型定义

| 概念       | 实现                                              | 说明                                                     |
| -------- | ----------------------------------------------- | ------------------------------------------------------ |
| **转轮带**  | `reel_strips[r]` = Array[[SymbolData, element]] | 由合并符号池按权重展开（权重 5 = 带子上 5 格）后洗牌，每列一份副本（同构成、异顺序）         |
| **最小带长** | `_STRIP_MIN_CELLS = 30`                         | 带子过短时**整份平铺**补足，只拉长视觉周期，**各符号占比、命中概率完全不变**             |
| **旋转**   | `_spin_timer` 节拍器，每跳推进 `reel_cursor[r]`         | 加速 `0.09s → 0.035s`（约 37 跳封顶，≈28 格/秒）                  |
| **停止**   | 玩家操作，落点 = 按停瞬间的 `reel_cursor`                   | **无自动兜底，不停就一直转**                                       |
| **落定**   | `emit_signal("spin_finished")`                  | `_on_spin_pressed` / `_free_spin` await 后再 `_evaluate` |

**三条停止入口**（均不会被禁用，无卡死风险）：

| 入口      | 行为                         |
| ------- | -------------------------- |
| SPIN 按钮 | 旋转中 = 停下**下一列**            |
| 空格键     | 同上（仅整备界面 `in_loadout` 时屏蔽） |
| 点击某一列   | **单独锁定**该列                 |

### 4.3 设计意义

- **难度来源迁移**：从"后台概率"变成"转速 + 你的眼力手速"。越转越快 = 越难精准停在目标符号上。
- **权重语义澄清**：权重不再是黑箱概率，而是"带子上看得见的格子数"。稀有强力符号照旧稀有（格子少），但玩家有主动权去博它。
- **与 build 层耦合**：带子长度 = 所有携带武器的权重总和。**带的武器越多，目标符号密度越低、越难按停**——这让 §7 的槽位收紧有了直接的手感反馈（见 §12.1）。
- **敌人干扰意图仍生效**：注废（jam）/ 锁轮（lock）在 `_lock_reel` 的瞬间覆盖结果，玩法不变。

### 4.4 调参入口

| 常量                 | 当前值        | 效果                                    |
| ------------------ | ---------- | ------------------------------------- |
| `_SPIN_BASE_WAIT`  | 0.09       | 起始每跳间隔，调大 = 起手更慢更好停                   |
| `_SPIN_MIN_WAIT`   | 0.035      | 最高速封顶，**调大 = 变慢好停，调小 = 变快难停**（主要难度旋钮） |
| 加速斜率               | 0.0015 / 跳 | 调大 = 更快进入高速                           |
| `_STRIP_MIN_CELLS` | 30         | 仅影响视觉重复周期，不影响概率                       |

## 5. 战斗结算模型（3 乘区 + 伤害分解）

### 5.1 三个乘区（少而强）

**单符号伤害 = base × 连线数 × 护符 × 克制**

| 乘区      | 来源     | 玩家直觉                              | 现状                                              |
| ------- | ------ | --------------------------------- | ----------------------------------------------- |
| **连线数** | 老虎机原生  | 连得越多越痛                            | ✅ 已有（`mult` = 同符号计数）                            |
| **护符**  | 收集/商店  | 护符越多全局越痛（收集爽）                     | ✅ 已落地（`charm_damage_mult` → `_agg_damage_mult`） |
| **克制**  | 带对元素武器 | 弱点 ×1.5 / 抗性 ×0.85 / 无关 ×1.0（策略点） | ✅ 已落地（`element_counter.gd`）                     |

**回合总伤 = Σ 各落线符号伤害**（沿用 `_evaluate` 逐符号累加结构，改动最小）。

> ⚠ **易误判的机制事实**：结算**不要求凑三连**。`_contribute(s, c, ...)` 中 `c = 1` 也照常出伤害，`special` 仅在 `c >= 3` 时额外追加一次 base。因此"多带武器"不会让玩家打空——**它的代价是隐形的**（见 §7.2）。这一点直接决定了槽位该怎么管。

### 5.2 伤害分解显示（P0 的落地）

伤害数字旁给分解，让玩家**爽得明白**：

```
符号[火·剑]  8 × 连线3 × 护符2 × 克制1.5 = 72
```

> 爽感的一半来自"看懂这一下为什么这么大"。这比堆更多系统更划算。同时是 ante 调参的 debug 面板。

## 6. 武器系统（元素化 + 克制奖罚并存·温和）

### 6.1 武器元素化

- `WeaponData` 加 `@export var element = "none"`（火/冰/毒/光/暗/无）。
- 符号自身 `element == "none"` 则继承武器 `element`；**着色 = 元素**（火=红、冰=蓝…），玩家一眼认出"哪个符号吃加成"。
- 开局武器 = `element="none"`（中性，稳定 ×1.0，教程/兜底/对冲）；属性武器为后期掉落。
- **攻击力差异化（资源化，每把武器专属符号，已落地）**：每把武器的伤害符号是**各自独立的 .tres**、base 不同，而非共用 `slash.tres`（原固定 base=10）。例：战斧 `axe_slash` 14 / 铁剑 `iron_slash` 11 / 火焰剑 `fire_slash` 10 / 冰枪 `ice_shot` 9 / 手枪 `pistol_shot` 8 / 匕首 `dagger_slash` 7，火焰法杖 `flame_special` 25。结算 `_contribute` 用 `sym.base + 全局bonus`，故每把武器的斩/射有各自攻击力；差异围绕 10 浮动，靠废铁权重/出现频率自然平衡（见 §7.2）。毒匕首无直接伤害符号，攻击力走 `poison` 层伤（设计特性）。

### 6.2 克制奖罚并存（温和，P2）

- **弱点 ×1.5，抗性 ×0.85，无关/中性 ×1.0。**
- 带对元素（命中敌人弱点）→ 爆发爽点；带错元素（撞上敌人抗性）→ 轻微吃亏，但**不崩盘、有退路**（中性武器恒 ×1.0）。

**为什么保留惩罚（而非只奖不罚）**：惩罚带来不可替代的价值——

- **真实感**：元素相克本就该"被克变弱"，去掉惩罚则元素退化成单向增益。
- **更深策略**：带对 ×1.5 vs 带错 ×0.85 是**真实风险博弈**（赌克制爆发 vs 保中性稳），优于"贪心覆盖多元素"的浅决策。
- **中性武器价值回归**：恒 ×1.0 成为风险对冲工具（只奖不罚下它毫无意义）。
- **抑制"全元素覆盖流"无脑化**：凑齐元素即稳的困境被打破。

**怎么让惩罚不爆炸复杂度**（三件套控复杂度）：

- **幅度温和**：×0.85 而非 ×0.7，无"带错就崩"的挫败。
- **敌人视角呈现**：显示「弱 火 ×1.5」「抗 毒 ×0.85」，玩家从敌人角度判断，不用背五元环。
- **中性常驻对冲**：永远有 ×1.0 退路，不会"被迫吃惩罚"。
- 伤害分解面板让"为什么 ×0.85"透明可学。

### 6.3 用"敌人弱点/抗性"呈现替代背环（呈现层大简化）

- 底层保留克制关系数据（决定哪敌人弱什么、抗什么），但**呈现给玩家的是敌人视角的"弱点/抗性"而非全局克制环**。
- 敌人显示「弱 火（你打它 ×1.5）」「抗 毒（你打它 ×0.85）」。玩家从敌人角度判断"这怪我打它什么好、什么差"，**零记忆负担**。
- 不用记"火克冰、冰克毒…"的传递环；伤害分解面板让倍率透明可学。

### 6.4 武器槽

- 当前武器**初始配额 2**（开局免费配给；商店「买即开槽」无限扩槽，**无硬天花板**）：带越多废铁越多/按停越难，稀释效应自身即刹车，金币价随已持数递增为第二道闸门。详见 §7。

## 7. 整备槽位（进池 vs 不进池）

> 槽位模型（当前代码事实）。**已落地**：四类各自占独立槽位，互不算总、不共享上限——v2.1 曾引入的全局 `TOTAL_MAX=5` 共享闸门已**移除**（会导致"带满护符即锁死武器"的误判），改回每类独立上限。

### 7.1 分类原则（P10）

槽位不按"总数多少"管，按**是否把符号塞进转轮带**管——这是两把完全不同的尺子：

| 类别       | 初始 | 天花板 | 进池？   | 影响                   | 管控尺度                     |
| -------- | -- | --- | ----- | -------------------- | ------------------------ |
| **武器**   | 2  | **`UNCAPPED` 无上限**  | ✅ 进池  | 稀释带子、摊薄克制浓度、拉低目标符号密度 | 稀释自身即刹车 + 递增价（+5/件）      |
| **主动增益** | 1  | **`UNCAPPED` 无上限**  | ✅ 进池  | 同上，挤占转轮带最凶           | 同上，步进更陡（+6/件）           |
| **消耗品**  | 1  | `CONSUMABLE_CAP=2` | ❌ 不进池 | 仅占界面与心智              | 硬限（无自然刹车）                |
| **护符**   | 1  | `CHARM_CAP=3`      | ❌ 不进池 | 唯一收集乘区，是膨胀主引擎        | **硬限**（零代价纯收益，步进价最贵）     |

**天花板按「进池与否」分野，不按类别拍脑袋**：

- **进池类（武器 / 增益）→ 无天花板**。它们的符号挤进同一条转轮带，带越多则废铁占比升高、目标符号命中率被稀释、克制浓度摊薄、按停难度上升——**稀释效应本身就是刹车**，人为封顶属于重复收费。约束交给「金币线性递增价 + 稀释代价」双闸门即可。实际可带数还受**内容池大小**天然限制（武器池 8 / 增益池 4，且同一件不可重复购买）。
- **不进池类（消耗品 / 护符）→ 硬天花板**。它们不进转轮、零稀释代价、**没有任何自然刹车**，尤其护符是「唯一收集乘区」纯收益越多越强，必须硬限量（2 / 3），否则乘区无限叠加直接崩坏数值。

**四类各自独立槽位、互不算总**：初始配额之和 = 2+1+1+1 = 5，但这**只是初始值之和，不是共享闸门**——任一类满槽绝不影响其他类。取舍张力来自**各自内部**（越扩越贵、稀释代价），而非跨类合计，故不存在"总槽已满"导致别类被锁死的误判。

### 7.2 多带武器的三条隐形代价

因为 `c = 1` 也结算伤害（§5.1），多带武器**不会让玩家打空**，坏处全部隐形。而**一个没有可感知代价的选项等于没有选项**，玩家会一直带满——这比"带满就废"更糟。三条代价：

1. **克制乘区吃不满**。带 1 把火剑 → 三格大概率全火 → 全吃 ×1.5；带 5 把杂武器 → 各元素混杂 → 有 ×1.5 有 ×0.85，期望被拉回 ×1.0。精心设计的克制系统被玩家自己稀释掉。
2. **`special` 的 ×3 爆发几乎不触发**。这是武器的"必杀感"来源，带满等于主动放弃。
3. **带子变长、按停变难**（方案 A 落地后新增）。1 把武器 ≈ 10 格（火占 50%），5 把 ≈ 50 格（火占 10%）。想按停在火格上，等待时间变成 5 倍——**刚做完的技能层被"带满"这个选项废掉**。

### 7.3 成长规划

**统一成长机制「买即开槽」**：在商店购买某类物品时，若该类当前槽位已满且未触天花板，本次购买**直接把该类上限 +1**（不单独售卖抽象的"槽扩展"商品）。节奏闸门 = 同类价格随已持数递增，且**加价从「首次扩槽」那一件起算**（填初始空位仍是原价）：

| 槽位  | 初始 | 天花板 | 步进  | 价格曲线（去随机项）      | 备注                            |
| --- | -- | --- | --- | --------------- | ----------------------------- |
| 武器  | 2  | **∞** | +5  | 8 · 8 · 13 · 18 · 23 · 28 … | 无硬顶；带越多废铁越多/按停越难即自然刹车，递增价为第二道闸门 |
| 增益  | 1  | **∞** | +6  | 6 · 12 · 18 · 24 …       | 无硬顶；进池挤占转轮带最凶故步进最陡          |
| 护符  | 1  | 3   | +8  | 10 · 18 · 26      | 不进池、零代价故须硬顶；唯一收集乘区，步进最贵；混合护符负面为未来第三道刹车 |
| 消耗品 | 1  | 2   | +4  | 5 · 9            | 不进池，仅界面负担，硬顶宽松                 |
| 增益  | 1  | 1   | +0  | 6               | 进池挤占最凶，初始即满、不成长（买不到第 2 个）     |

## 8. 防御系统（单一护盾资源）

- **职责分离**：防御全部归入「护盾」单一资源，由护符/奖励/增益按不同时机灌入（满足"武器进攻、护符提供防御"）。**不另设独立护甲数值**——避免"两个平减数字"的重复感（经典做法参考小丑牌/杀戮尖塔的单一防御资源）。
- **护盾三来源、两种节奏**：
  - 开局爆发：`ward_charm`（`room_shield`，每房开局一次性灌入）、`守望结界`奖励（`run_shield_next`）。
  - 每回合涓流：`guard_charm`（`shield`，每回合 +N，走 `_agg_shield()`，与铁壁增益同通道）——挨打才消耗、不挨打则累积，等效"常驻减伤"手感。
- **受伤公式**：`受伤 = max(0, raw − shield)`（护盾会耗尽，每房刷新；涓流每回合补）。**最简单、不背环**，与"克制用敌人视角呈现"的简化精神一致。
- 代码：`charm_shield_trickle` 聚合（镜像 `charm_room_shield`）→ `_agg_shield()` 在 `_evaluate` 阶段 1 落地；`_enemy_deal_damage` 仅消费 `player_shield`。`player_armor / charm_armor / _agg_armor / _affix_armor` 已全部删除。
- **属性抗性（fire_def…）：冻结**（进阶可选；要加再说，见 §13）。`StatTarget` 预留的 `FIRE_DEF…` 继续作死代码，本期不启用。

## 9. 护符系统（唯一收集乘区）

- 护符 = **全局乘区 ×N**，是数值爆炸的主引擎；堆叠产生复利爽感。
- 槽位：**初始 1、硬天花板 `CHARM_CAP=3`**（把乘区数量约束在 3 内便于平衡，低于 Balatro 的 5）。护符不进池、零稀释代价、纯收益，**没有任何自然刹车**，故与进池类（武器/增益无上限）不同，必须硬限。经商店「买即开槽」成长，步进价最贵（10→18→26）以保稀缺。未来混合护符（正负并存）的负面为第三道刹车（§7.3）。护符上限独立，不因他类占满而受影响。
- 部分护符兼作防御来源（给 shield：如 `ward_charm` 开局爆发、`guard_charm` 每回合涓流）。
- 代码：✅ 已落地——`ItemData` 加 `mult_value` 字段，`_apply_charms` 的 `damage_mult` 分支累乘进 `charm_damage_mult`，由 `_agg_damage_mult()` 在回合层结算（属全局乘区）。示例资源 `resources/items/rage_charm.tres`（×1.5）。

## 10. 数值膨胀（双轨 + ante）

### 10.1 双轨膨胀（P4）

- **武器升级（线性 base，8→20）**：看得见摸得着的成长。沿用铁砧/升级管线（`meta.weapon_upgrades` 按 `resource_path` 加成，**不改共享 .tres**）。
- **护符乘区（乘法 ×N）**：复利爆炸。
- 线性 × 乘法 = 数字自然膨胀，但只有两条线，玩家算得过来（极简版 chips×mult）。

### 10.2 ante 难度曲线（P6，膨胀的必需前提）

- `RoomData` 存**基础值** `base_hp / base_atk`；`_start_room` 按全局已通关房间数 `n` 缩放：
  - 推荐（平滑）：`hp = base_hp × (1+α)^n`，`atk = base_atk × (1+β)^n`。
  - 初值参考：α_hp ≈ 0.15、β_atk ≈ 0.10（**需真机调**）。
- **run 结构（roguelike 骨架）**：3 个 act，每 act = 6 普通房 + 1 Boss 房；通关第 3 act Boss 获胜。教程段 = 第 1 act 前 2–3 房。
- **敌方必须同步指数增长**，否则玩家爆炸后无怪可打。

### 10.3 转轮列数 ~~REELS 3→4~~（v2.1 已撤销·移入冻结清单）

> ❌ **此条目已失效，勿按旧路线实施。** 保留记录以防重复提案。

**撤销理由**：原条目写于"后台加权随机一次抽完"的旧模型下——那时加一列的操作成本为零，伤害期望直接 ×4/3，确实是白捡的杠杆。方案 A（§4）落地后，**列数从"数值参数"变成了"节奏参数"**，每一列都要玩家亲手按停，第 4 列 = 每回合操作量 +33%。这个代价在写原条目时根本不存在。

三条具体损失：

1. **节奏被稀释**：老虎机的爽点是"短促紧张 → 立刻见结果"，按停链从 3 拉到 4，紧张感摊薄成疲劳感。
2. **`special` 的爆发阈值恰好绑定 3 列**：`c >= 3` 即三连即满屏，是全局唯一的"完美一击"瞬间。4 列后三连只占 3/4，满屏仪式感消失；阈值改 4 又几乎打不出来。这个数值美感是 3 列白送的。
3. **与槽位收紧（§7）直接打架**：武器砍到 2 把就是为了抬高目标符号密度、让按停变好按；加一列等于要求玩家在同一难度下多做一次正确判断，两个改动方向相反。

**唯一支持理由（策略深度）在当前代码下不成立**：结算是逐符号独立计数（`c = 1` 也出伤害），不是 payline 匹配。第 4 格产生的不是新组合，只是**第 4 份独立加法伤害**——策略深度一分没涨，纯加数值。

**若确需更多格子**：`ROWS 1→2` 优于加列——一次按停同时定下 2 格，**格子 +100% 而操作次数不变**。代价是同屏信息量翻倍、`_evaluate` 计数需覆盖多行、界面更挤。同属"可选、非必须"。

**回头重估的判据**（真机 3 列跑顺后）：

- 反馈"还没爽到回合就结束了 / 单回合决策太单薄" → 加列对症，可重议；
- 反馈"按停三次已经手忙脚乱" → **永久否决**；
- 若将来把结算改成"必须连成线才算"，多一列会真正改变组合空间，届时需完全重新评估。

### 10.4 局内爆发杠杆：special 三连「连锁重触发」（✅ 已落地 `afcfb29`）

**要解决的问题**：局内所有乘区都被刻意剥离（防黑箱），导致每回合伤害是一条平线；到 BOSS 阶段 build 已定型，只剩"再打十几回合"的机械感，**没有任何单回合的数值尖峰**。

**机制**（Balatro 重触发思路，但保持可读）：
- 打出 `special` 三连 → **免费重转一次**，且**只有 special 部分**吃连锁倍率 `CHAIN_STEP = 1.5`；
- 连锁可累计：第 n 次重转 special 倍率 = `1.5^n`；
- 上限 `CHAIN_MAX = 4`（=1 次正常 + 3 次免费重转），理论峰值 special ×3.375；
- 敌人被打死立即中断连锁；伤害分解尾部显示 `连锁×N`，日志 + 飘字实时提示。

**为什么不算黑箱**：倍率只作用在**玩家亲手按停凑出的 special 三连**上，因果链是"我按准了 → 立刻多一次机会"，不是后台暗算。这是**唯一的局内乘区**，其余全部留在 build 层。

### 10.5 跨局爆发杠杆：每局结束元进度三选一（✅ 已落地 `4afacf2`，三选一/BUG 修正见后续提交）

**双轨在 meta 层的具体承载**（对应 §10.1）：

| 轨 | 载体 | 常量 | 上限 |
|---|---|---|---|
| 线性 | `meta.weapon_base_bonus[武器路径]` | `WEAPON_BASE_STEP = 3` | 无（受 ante 曲线制衡） |
| 乘法 | `meta.charm_upgrades[护符路径]` | `CHARM_MULT_STEP = 0.12` /级 | 总乘区硬顶 `CHARM_MULT_CAP = 6.0` |

- **触发时机**：**通关整局**（最后一间 BOSS）后弹出，选一项 → `_save_meta()` → `_full_reset()` 开新局。
- **候选构成**：本局携带武器各 1 张（+base）+ **仅乘区型护符**各 1 张（+mult）+ 铁砧点数 1 张兜底 → `shuffle()` 取 `META_CHOICE_COUNT = 3`。
  - ⚠ 非 `damage_mult` 的护符（守备/抗扰/丰沛/守望）**不出卡**——它们没有升级通道，出卡等于假选项。
- **护符乘数化**：锋锐护符由加法 `damage_bonus +1` 改为乘数 `damage_mult ×1.10`，护符线正式成为"唯一收集乘区"（§9）。**护符数量上限仍锁死 3**，膨胀只走"数值增值"，不走"数量增长"——数量不涨才保证乘区可算。
- **与局内连锁叠乘**：武器 base 在 `_contribute` 中于所有乘法**之前**叠加，因此同时被护符乘区与连锁倍率放大 → 跨局成长直接喂给局内爆发。

## 11. 经济与商店

- **局内金币**：击杀/清房获得（清房 +5 / Boss +10），**每局清零**（膨胀留局内，防滚雪球）；起始 4 金。
- **转轮金币符号**：`resources/symbols/gold.tres` 常驻转轮池（权重 `GOLD_POOL_WEIGHT=3.0`，远低于伤害符号，防稀释 DPS），落在线上的金币符号按 `GOLD_PER_COIN=1 × 命中数` 转化为金币、不造成任何伤害。与清房/利息构成「批发 + 零售」双收入，喂给商店（S7）。
- **商店**：房间之间出现（奖励三选一之后），卖武器/护符/消耗品/增益；**刷新随机**（每房 `candidates.shuffle()` 取 6 件，防背公式）。与房奖励三选一并存（前者白送、后者消费，构成经济循环）。购买写入对应 selected 数组，下房 `_start_room` 重建符号池 + 重算护符被动使其生效。
- **消耗品 = 可消耗资源（非自动恢复）**：自 S6–S8 商店落地后，消耗品**不再每房/每局自动回满**——仅在「进入持有」时初始化一次次数（整备确认 / 商店购买），用掉即消耗；商店是补给唯一来源。用尽的消耗品从持有中移除并空出槽位，可于商店再次购入。此改动让商店对消耗品真正有意义（否则免费每房回满使购买无意义）。
- **同类物品唯一持有（不可重复购买）**：商店购买前校验 `selected_*` 是否已含该资源路径，已拥有则拒绝（"已拥有，无法重复购买"）。武器/护符/物品/增益均适用——避免同一护符效果因重复购买而叠加（原 bug：`_apply_charms` 用 `+=` 累加，两张相同护符会使效果翻倍）。整备屏因每张卡为独立对象、靠 `card["selected"]` 切换，本就不会重复，漏洞仅在商店。
- **利息（S8）**：清房金币发放时并入 `min(gold//5, 5)`（每 5 金 +1，上限 +5），制造"存钱 vs 消费"决策。
- **定价**：武器 8 / 护符 10 / 物品 5 / 增益 6，附随机 ±1~2（防背公式），下限 3。
- **铁砧点（`meta.anvil_points`）**：**回退跨局 meta**（解锁武器/护符池用），**不进 build、不滚雪球、不与金币兑换**。防跨局买局内战力破坏 ante 曲线。
- 经济初值参考：起始 4 金 / 清房 +5 / Boss +10 / 利息每 5 金 +1 上限 +5（**需真机调**）。

## 12. 策略性设计（策略在哪、怎么防无脑）

### 12.1 六层策略（决策层 + 技能层）

| 层                 | 决策                                   | 取舍                                      |
| ----------------- | ------------------------------------ | --------------------------------------- |
| **build 构建**      | 武器槽 2–3 对 5 元素覆盖谁                    | 覆盖广(稀释带子/按停难/克制被摊薄) vs 覆盖窄(浓度高/好按停/怕不克) |
| **资源配比**          | 升级武器(线性,前期强) vs 买护符(乘法,后期复利)         | 投资重心何时切换                                |
| **概率工程**          | 编程带子分布：高base低权重(赌爆发) vs 低base高权重(求稳) | Boss 高方差 / 清怪低方差（老虎机特有，小丑牌没有）           |
| **进程时机**          | 精英房(高风险高回报)？攒利息 vs 立即战力？增益留 Boss？    | 风险与节奏                                   |
| **战斗内时机**         | 增益/消耗品何时用                            | 关键回合抉择（少量但爽）                            |
| **按停技能**（v2.1 新增） | 盯克制符号按停 vs 求快随便停                     | 高速下的眼力手速；带子越短越好按，与 build 层直接联动          |

> **build 层与技能层的耦合是本作特色**：带的武器越少，目标符号在带子上越密、越好按停。"带得少反而好打"这个反直觉的手感差异，是槽位设计能否立住的核心判据。

### 12.2 策略 → 爽感闭环

对的 build 决策（看敌人换元素覆盖 → 配对护符 → 保浓度 → 攒利息）→ 汇成一次爆炸数字。**决策是因，大数字是果**；"我算出来的"比数字乱涨更爽。

### 12.3 防无脑化四机制（已在框架内）

1. **四类初始配额 2/1/1/1 + 统一「买即开槽」成长**（进池类武器/增益 `UNCAPPED` 无天花板，不进池类 `CONSUMABLE_CAP=2`/`CHARM_CAP=3` 硬限）+ **各自独立槽位、互不算总** → 取舍来自每类内部（废铁/稀释自然刹车 + 金币递增价），不再有"总槽锁死他类"的误判。
2. **商店刷新随机** → 每局 build 不同，不能背公式。
3. **敌人元素随 ante 多样化** + **克制奖罚并存** → 倒逼按敌人弱点/抗性调整覆盖，不能一套打到底。
4. **按停技能层**（v2.1）→ 同样的 build 在不同玩家手里结果不同，消除"配好就自动赢"。

### 12.4 长线新鲜感的诚实说明

极简版策略**上限**较低。玩家长线新鲜感靠**内容广度**（更多武器/护符/敌人/房间/事件），而非再加系统。用内容撑长尾比用系统复杂度撑更健康、更好平衡。

## 17. 验收标准

1. 带护符后伤害**明显膨胀**，敌人随 ante **同步变肉**（中期不秒怪）。
2. 玩家能**心算每个大数字的来源**（连线/护符/克制，伤害分解可查）。
3. **惩罚温和可控**：带错元素仅 ×0.85 小亏、不崩盘，中性武器提供对冲退路；玩家凭弱点/抗性信息决策而非背环。
4. build 决策**可见地影响**伤害（换元素覆盖/配对护符 → 数字变化）。
5. **按停技能层成立**（v2.1 新增）：高速下停在目标符号上"难但可能"；且**带 1 把武器明显比带 2 把好按**——这条手感差异是槽位设计能否立住的判据。
6. F6 真机跑通核心循环：整备 → 转轮(手动停) → 结算(分解) → 奖励 → 商店 → 更深房。
