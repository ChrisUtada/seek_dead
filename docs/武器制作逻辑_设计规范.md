# 武器制作逻辑 · 设计规范（基础属性 / 机制 / 元素三层模型）

> 状态：规范文档（2026-08-07 **最终形态 v2**；2026-08-14 修订：special 存活口径、共享符号规则、base_power 档位、五元环→v2 互克对）。依据：LoadoutItem/WeaponData/SymbolData 字段 + 全部分衡收敛（T1 专属符号、T22 资源化、同元素三连、T12 攻击力直算、crit_chance 代价轴、**强制双武器、三要素模型**）。
> 用途：新武器制作 = 按本文档分层填 .tres，零代码；T4（90 武器）批量铺料的唯一规范。
> 关联：装备收集规划_200（数量/稀有度分配）、战斗平衡收敛_执行方案（数值锚点）。

---

## 0. 武器模型（一句话）

> **武器 = 攻击力（base_power）+ 元素克制（element）+ 机制（特殊机制符号 / triple_pierce / pierce）**
> 附带数值旋钮：rarity（强度档）/ crit_mult（三连暴击倍率）/ crit_chance（非三连暴击率）/ hit_rate（**2026-08-09 恢复**：带子 MISS 占比）。
> **整备强制带满 2 把武器**（`loadout_min=2`，主+副）——消灭"单带"，三连率结构性控制。

## 1. 核心模型：武器 = 三层

```
武器 .tres
├── ① 基础属性层  数值骨架（多强）：rarity / base_power / crit_mult / crit_chance
├── ② 机制层      行为效果（什么效果）：机制符号（status）/ triple_pierce / pierce_armor
└── ③ 元素层      克制身份（克制谁）：element / reel_element / 符号元素继承
```

三层正交：同一机制可配不同元素；同一元素可配不同数值。

## 2. ① 基础属性层（数值骨架 · 决定「多强」）

| 字段 | 位置 | 规范 | 说明 |
|---|---|---|---|
| `rarity` | LoadoutItem | common/uncommon/rare/epic（40/30/20/10 金字塔） | **只定强度，不定频率**（神装也正常出现） |
| `base_power` | LoadoutItem | 实测档位：common 9~12 / uncommon 8~20 / rare 13~20 / epic 16（烈焰法杖）；设计参照 8~20 区间 | **唯一伤害数值源**（T12）：伤害 = `base_power + agg_flat` × 连线 × 克制 × 暴击 |
| `crit_mult` | LoadoutItem | 2.0（common）~3.0（epic 上限） | 三连/同元素三连暴击倍率 |
| `crit_chance` | LoadoutItem | 0.0 ~ 0.15 | **非三连暴击率加成**：总暴击率 = `BALANCE.crit_chance(0.20)` + 此值；**高 base 低暴击 = 代价轴** |
| `hit_rate` | LoadoutItem | 0.78 ~ 0.90（**2026-08-09 复活**） | 带子 MISS 占比（`Σ 符号权重 × (1-hit)` 聚合）；**高 base 低命中 = 代价轴**（与低暴击同构）；1.0 = 无 miss |

**数值锚点**：伤害 = `base_power + 局内加成` × 连线 × 克制 × 暴击 × player_dmg_mult(1.5)（T12 起符号 `base` 不参与缩放；`damage` 遗留字段不读取）。

## 3. ② 机制层（行为效果 · 决定「什么效果」）

机制载体 = **机制符号（kind=status）+ 武器级机制标记**：

| 机制 | 载体 | 说明 |
|---|---|---|
| 挂状态 | `status` 符号（burn/frost/poison → StatusDef） | 如毒匕挂毒、冰枪挂霜、火剑灼烧 |
| 破甲 | `triple_pierce: bool`（武器级） | 该武器三连时清空敌人护甲（战斧/夜幕镰刀/铁剑） |
| 穿透 | 攻击符号 `pierce_armor: bool` | 无视护甲直击（pistol/ice_shot） |
| special | 符号 kind=special | **与 damage 同源结算（T12）**——三连判定走 triple_pierce；现存唯一：烈焰法杖「炎爆」。⚠ 2026-08-14 勘误：旧版写"special 已退役"错误——退役的是**连锁重转机制**（2026-08-07），special kind 本身存活 |
| ~~heal/shield/buff~~ | — | **武器不携带**（归护符/技能/房奖励） |

**设计原则**：
- **武器符号 = [1 个攻击符号（weight 3~6）] + [可选机制符号（weight 1~3）]**
- 攻击符号 = 武器身份；机制 = 武器灵魂。⚠ 2026-08-14 勘误：旧版「专属攻击符号禁共享」与现状相反——**同元素武器普遍复用攻击符号**（shadow_slash 5 把暗武共用 / burn 3 把火武 / frost 4 把冰武 / holy_slash 3 把光武），且 08-14 起「共享符号 ≥2 源破稀有度封顶」机制让共享构筑成为正道（双同属性武器陷阱构装修复）。

## 4. ③ 元素层（克制身份 · 决定「克制谁」）

| 字段 | 位置 | 规则 |
|---|---|---|
| `element` | WeaponData | 武器元素：攻击符号（自身 element=none 时）**继承**此值 |
| `reel_element` | WeaponData | 特殊符号（special）优先取其值；保留字段兼容 |
| `symbol.element` | SymbolData | 非 none 则**独立生效**（覆盖继承） |

**继承规则**（`_eff_element`）：
```
攻击符号 → 自身 element 非 none 用之；否则继承武器 element
special 符号 → 优先武器 reel_element
```

**克制模型（v2 互克对 + 毒链，2026-08-10 定稿）**：`火↔冰、光↔暗` 互克；`火→毒、光→毒、毒→暗` 单向（克制 ×1.5 / 抵抗 ×0.85 / 同元素 ×0.85，单向玩家→敌人）。旧「五元环 火>冰>毒>光>暗>火」已废弃。

**分布规范**（装备收集规划 §14.6）：
- BOSS 多为强元素（逼克制核爆）；普通怪 none 居多
- 武器池元素均匀（90 把 = 6 元素桶 ×15，§12.3）；**当前 24 把：火3/冰4/毒1/光5/暗6/无5**

**双武器配合（强制 2 把的意义）**：
- **同元素双带** → 攻击符号聚合 + 同元素三连判定 → 三连率 ~15%（三连赛道）
- **异元素双带** → 三连 ~2%，走充能/覆盖流（克制 ×1.5/格 + 充能爆发）——元素选择 = 赛道选择

## 5. 组装规则（新武器制作流程）

```
Step 1 · 身份元素：定 element（或 none）
Step 2 · 定强度：rarity → base_power（对照 §2 档位）→ crit_mult → crit_chance（高 base 低暴击）
Step 3 · 设计符号：攻击符号（label 元素 glyph）weight 3~6
         + 可选机制符号（status，weight 1~3）/ triple_pierce / pierce_armor
         ✗ 不携带 heal/shield/buff/副攻（special 仅烈焰法杖先例，新武器默认不用）
Step 4 · 数值自查：§6 校验清单
```

**模板**（新 .tres 骨架）：参照 `fire_sword.tres`（攻击符号燃 w5 + 机制符号火斩 w3 双符号）或 `holy_sword.tres`（单符号圣辉斩 w5 极简）；⚠ 旧版「holy_sword = 圣辉斩+治疗+special 标准样板」已失真（现为单符号）。

## 6. 平衡校验清单（制作后自查）

- [ ] 攻击符号**归属明确**（可与同元素武器共享——共享 ≥2 源破顶；不与技能符号混淆）
- [ ] `base_power` 与 `rarity` 匹配档位（§2，8~20 区间）
- [ ] `crit_mult` 在 2.0~3.0 内；**`crit_chance` 与 base_power 成反比**（战斧 20/0、手枪 9/0.15）
- [ ] 攻击符号 weight 3~6、机制符号 1~3（**无 heal/shield/buff/副攻**；special 仅烈焰法杖先例）
- [ ] 穿透武器（如远程）攻击符号置 `pierce_armor`
- [ ] 元素归属明确（克谁/被谁克），不与同幕 BOSS 元素冲突
- [ ] 遗留字段（damage/attack_speed/attack_range/cleave/knockback/bullet/ammo/heat/status_effect_*）**不填**（ARPG 原型残留，转轮战斗不读取，见 §7）

## 7. 遗留字段说明（勿填）

`WeaponData` 中以下字段为早期 ARPG 原型残留，转轮战斗**不读取**：`damage / damage_type / attack_speed / attack_range / weapon_scene / grip_point / visual_offset / visual_scale / status_effect_type / status_effect_damage / status_effect_duration / heat_per_attack / bullet_scene / bullet_speed / max_ammo / ammo_per_shot / cleave_angle / knockback_force`。
→ 制作武器时忽略；如需清理，可后续立项移除（建议随 T4 内容批次一起）。

## 8. 样板拆解：战斧（uncommon）

| 层 | 配置 | 理由 |
|---|---|---|
| 攻击力 | base_power 20 | uncommon 高位 |
| 元素 | none（中性） | 稳定通用、不吃克制环 |
| 机制 | triple_pierce（三连破甲） | 重击破甲流 |
| 数值 | crit_chance 0（高 base 低暴击）| 代价轴 |
| 符号 | 斧斩（攻击，weight 5） | 无机制符号（破甲走武器标记） |

**双带示例**：战斧 + 铁剑（都 none）→ 两把中性武器 = 异符号混合（三连靠同符号目押）；战斧 + 火剑 → 异元素（充能/覆盖流）。
