## 1. 完成范围

| 改动 | 位置 | 结果 |
|---|---|---|
| 删除 `RARITY_RANK` / `_RARE_CAP_CELLS` | `scripts/battle/reel_system.gd` | 品质不再参与格数计算 |
| `cells_for(w)` 只读聚合权重 | `scripts/battle/reel_system.gd` | `<2 → 2 格`、`[2,4) → 3 格`、`≥4 → 4 格` |
| 建带聚合去掉 `rank` / `sources` 记账 | `scripts/battle/reel_system.gd` | 同族总格数只由权重和决定 |
| 预览口径同步 | `scripts/systems/reel_preview.gd` | 删除 `_rarity()` / `rank` / `sources` 字段 |
| 灌注预览口径同步 | `scripts/systems/reward_system.gd` | `_symbol_cells()` 不再读 `pool_items[].rarity` |
| 新增第 41 套回归 | `tests/loot_frequency_test.gd` | 34 项断言 |
| 新增只读取证工具 | `tools/loot_step2_frequency_report.gd` | 输出受旧封顶影响的完整对照表 |

旧的频率规则（已删除）：

```gdscript
if kind != "damage" and rank >= RARITY_RANK["rare"] and sources < 2:
    cnt = mini(cnt, _RARE_CAP_CELLS)   # rare/epic 非伤害符号封顶 2 格
```

新规则：

```gdscript
static func cells_for(w: float) -> int:
    var cnt := 2
    if w >= 4.0: cnt = 4
    elif w >= 2.0: cnt = 3
    return cnt
```

符号类型（damage / status / shield / heal…）、物品品质、同符号来源数量都不再参与格数。
同一件装备只把 `rarity` 从 `common` 改到 `epic`，转轮带逐格不变。

单源口径（该符号只由这一件装备携带）。旧规则下 `sources < 2` 才封顶，所以多件装备共享同一符号时本来就不封顶，也不在此表内。

| 火焰剑 | rare | 燃 | status | 5.0 | 2 | 4 | +2 |

共 7 行 / 6 件装备，涉及 3 个符号：霜、燃、炎爆。其余 66 条非伤害符号条目权重 `<2`，新旧都是 2 格，不受影响。

> **本轮没有同步下调这些符号的权重。** 计划 §8 明确要求返工时只改一个变量；品质解耦与权重再平衡分开做，

## 7. 已知影响与下一步

- `燃` / `霜` 的实际上带频率上升（2→4 / 2→3 格），这是移除品质封顶后的直接结果。数值平衡留给 Step 8 大样本，不在 Step 2 顺手改权重。
- 火焰剑 + 霜晶法杖的符号带从 11 格增至 14 格；`g6_forge_test` 中烈刃 -5% 命中的 MISS 增量在 14 格带子上会被取整吞掉，夹具已改用 11 格配装保留方向覆盖（见该测试注释）。
- 奖励卡 `RewardData.rarity` 的抽取权重、`acquisition_weight` 与商店定价仍按旧稀有度工作，属于 Step 3「来源品质表」范围。
- 下一阶段（Step 3）应先用本步的对照表确认受影响符号在真实配装中的权重预期，再建立来源品质表。
