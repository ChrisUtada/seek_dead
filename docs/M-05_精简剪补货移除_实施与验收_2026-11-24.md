## 1. 删除范围与「为什么换装不能改货架」

生产主体在 **8132ffe** 落地，本轮不重复修改该逻辑：

- 删除的调用：`scripts/systems/shop_system.gd` 中 `on_shop_buy_replace_pressed()` 末尾的 `_ensure_trim_offer()`（含 `source == "camp"` 与 `"shop"` 两条路径共用的替换入口）。
- 删除的函数：`_ensure_trim_offer()`（原逻辑：货架无精简剪时，把最后一格覆盖为 `trim_scissors.tres`）。
- 删除的常量：`TRIM_ITEM_PATH := "res://resources/consumables/trim_scissors.tres"`（随函数一并移除）。
- 保留：营地 `StripTrimSystem` 的 `grant / trims_left / candidates / apply` 通道；消耗品自然池中的精简剪；价格与库存上限未改；抽取权重未改。

**为什么换装不能改货架**：换装是一次配装决策，不是补给事件。原实现无论来源是商店还是营地，只要货架无精简剪就把最后一格强制覆盖，导致：① 连续换装反复覆盖货架、破坏固定货架的可预测性；② 玩家没有购买精简剪的机会就被塞一件消耗品，与营地整理的职责重叠；③ 覆盖动作发生在购买路径内，等价于「换装免费附带补给」，绕过商店经济。因此换装路径必须只读自己的 offer，绝不回写 `shop_offers`。

## 3. 供给决策：**方案 C（接受随机供给）**

- 原注释「它是带子变胖的唯一解药，不能靠掉落运气」不再成立：strip_trim_system 已取消每幕免费次数，精简剪只作为 26 个消耗品之一在自然池出现。
- 本轮按用户拍板选择 **方案 C**：不做每幕首 roll 保底，不新增 `_ensure_trim_on_shelf`，不引入新的 RNG 隔离或商店占位规则；在基线 §4.3（用户工单称 §4.2）记明风险。
- 理由：保底会与 A2「换装后货架不含精简剪」的正向断言语义冲突（保底后货架本来就有精简剪，断言无法区分「自然存在」和「换装补货」）；且恢复任何形式的强制供给都等于以另一种方式复活原冲突。
- 必做修复照做：`duel_controller.gd:1568` 的 `can_trim` 增加 `trims_left() > 0` 条件，避免 0 次时按钮仍亮、点进去显示「剩余 0 次」再拒绝。
