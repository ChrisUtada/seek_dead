## 1. 现状链路

### 1.1 状态符号从哪来

- 状态符号是普通 `SymbolData` 资源，`kind = "status"` + `status_type` 指定状态族
  （`scripts/battle/symbol_data.gd:10`、`:13`）。
- 实际存在的 5 个状态族与 11 个符号资源（`resources/symbols/`）：

| 状态族 | 符号资源 | kind | status_type |
|---|---|---|---|
| burn | `burn.tres` / `ember.tres` / `ignite.tres` | status | burn |
| frost | `frost.tres` / `chill.tres` | status | frost |
| poison | `poison.tres` / `blight.tres` | status | poison |
| holy_burn | `holy_burn.tres` / `holy_burst.tres` | status | holy_burn |
| shadow_blight | `shadow_blight.tres` / `shadow_taint.tres` | status | shadow_blight |

  例：`resources/symbols/poison.tres:12-15`（`kind="status"`、`status_type="poison"`、`element="poison"`）。
- 武器通过 `symbols: Array[SymbolWeight]` 引用符号（`scripts/equipment/weapon_data.gd:44`；
  例 `resources/weapon_templates/poison_dagger.tres:34` 的 `symbols = Array[...]([SubResource("sw0")])`）。
- 技能通过 `SkillData.symbol + weight` 引用符号（`scripts/items/skill_data.gd:24-25`）。

### 1.2 怎么进轮池

1. 建池入口：`DuelController._build_pool()`（`scripts/battle/duel_controller.gd:536-538`）→
   `ReelSystem.build_pool()`（`scripts/battle/reel_system.gd:870-887`）。
2. 武器段：`_collect_weapon_items()`（`reel_system.gd:1019-1039`）→ `weapon_syms()`
   （`reel_system.gd:1069-1078`），把每把武器的每个符号展开成
   `[SymbolData, weight, 有效元素, 武器id, base_power]`。
3. 技能段：`_collect_skill_items()`（`reel_system.gd:1042-1047`）→ `skill_pool_item()`
   （`reel_system.gd:1082-1084`）。
4. 元素精华段：`_collect_essence_items()`（`reel_system.gd:1051-1055`）。
5. 扁平池 + 金币常驻：`reel_system.gd:881-883` / `flatten_pool()`（`reel_system.gd:1092-1102`）。

### 1.3 怎么进转轮、落线

- `build_strips()`（`scripts/battle/reel_system.gd:337-402`）：同符号族按权重聚合（`:356-364`），
  格数 = `cells_for(weight)`（`:466-467`，clamp 1..8）；命中率不足按 `hit_rate` 聚合 MISS 格
  （`:389-392`），MISS/废铁同为 `kind="trash"`。
- 只有 1 条 payline：三列各取第 0 行（`scripts/battle/duel_controller.gd:377-380`）。
- 停轮后 `grid[col][0]` 即本 SPIN 的 3 张牌。

### 1.4 怎么被匹配

- 牌谱匹配只读 3 张牌卡：`PatternMatcher.cards_from_grid()`（`scripts/battle/pattern_matcher.gd:277-293`）
  生成 7 字段卡（`card_meta()`，`:244-272`）；规则由 `solve_rule()`（`:99-113`）逐条件匹配，
  `sym` / `kind` / `source_element` / `source_kind` 等条件在 `_card_satisfies()`（`:132` 起）判定。
- 状态符号没有任何独立的"匹配"语义；只有当某条牌谱规则显式写
  `{"sym": ".../poison.tres"}` 这类条件时，它才参与匹配（见 §5.2）。
- 废铁不参与匹配：`INVALID_KINDS := ["trash"]`（`pattern_matcher.gd:19`）。

### 1.5 怎么结算成 DoT

1. SPIN 结算入口：`TurnFlow.on_spin_pressed()` → `combat.evaluate()`（`scripts/battle/turn_flow.gd:118`）。
2. 符号计数：`CombatSystem._phase_symbols()`（`scripts/battle/combat_system.gd:342-422`），
   按 `(符号路径|元素)` 计数（`:347-360`），每个来源分别 `contribute()`
   （`:393-406`；`contribute()` 定义见 `:82`）。
3. 状态落层：`contribute()` 的 `status` 分支（`combat_system.gd:169`）把
   `mult（该来源的格数）× 暴击/三连倍率 + 各类加成` 累加进 `acc["status_stacks"][status_type]`。
4. 状态落地：结算后段 `add_enemy_status()`（`combat_system.gd:686-690`；
   定义 `duel_controller.gd:1975-1980`）。同段还有：
   元素共鸣对已有状态 +1（`combat_system.gd:686-688`）；
   回路「状态反应」+1（`combat_system.gd:584-588`，定义 `circuit_system.gd:28-32`）；
   奥术三连 +1（`combat_system.gd:120-122`、`:169`）。
5. 牌谱追加层：`pattern_effects._add_status()`（`scripts/battle/pattern_effects.gd:313-319`），
   由 `combat_system.gd:509-513` 统一落地；调用点如 `:105`（W01/W07 燃烧）、`:127-128`（SIG02）、
   `:153`（W02 霜冻）。
6. DoT 结算：`CombatSystem.tick_status()`（`scripts/battle/combat_system.gd:1325-1393`）：
   `每跳 = 层数 × StatusDef.base × 元素克制 × 状态护符乘区`（`:1340-1347`）；
   层数达 `dot_burst_threshold=8` 时爆发 `×2.0` 并消耗 4 层（`:1357-1364`、`balance_config.tres:46-48`）；
   每回合衰减 `StatusDef.decay`（`:1366`）；BOSS 房记生涯状态伤害（`:1388-1389`）。
   调用点：`turn_flow.gd:134`。状态定义表：`status_system.gd:51-59`，base/element 读取 `:145-158`。
7. 非武器来源的挂层：敌人 gimmick（`scripts/battle/gimmicks/normal_trait_gimmick.gd:324`）、
   消耗品（`scripts/systems/consumable_system.gd:206`）。

### 1.6 明确回答

**现状的"状态"是轮上的符号格：必须停在三列之一并参与 `_phase_symbols` 的逐格计数，才按格数结算成 DoT；
不是攻击后按概率触发。** 依据：状态仅由 `contribute()` 的 `status` 分支写入
（`combat_system.gd:169`），入口是 payline 计数（`:347-360`、`:393-406`）；武器上的
`status_effect_type / status_effect_damage / status_effect_duration`
（`weapon_data.gd:24-26`）**全代码 0 处读取**，没有任何"攻击后触发"通道。

## 3. DoT 代表武器候选

### 3.1 `poison_dagger`（毒匕首，必选）

- 现状触发路径：唯一符号 `poison.tres`（权重 5，`poison_dagger.tres:9-10`、`:34`；命中 0.88，`:21`；
  base_power 7，`:20`）→ 入池（`reel_system.gd:1019-1039`）→ 三列落线计数
  （`combat_system.gd:342-360`）→ status 分支按格数加层（`:169`）→ `add_enemy_status`
  （`:690`、`duel_controller.gd:1975`）→ `tick_status` 按 `poison.base=9` 每跳结算
  （`combat_system.gd:1340-1347`、`resources/statuses/poison.tres`）。
- 迁成"攻击后概率触发"后的差异：
  - 当前：0 个伤害符号，全部输出来自毒层 DoT；三列毒 = 一次给约 3 层。
  - 迁移后：符号池为空 → 该武器既不落线、也不造成任何伤害；必须另配一个基础伤害符号
    才有"攻击"可挂概率。候选：`venom_bite.tres`（`kind="damage"`、`element="poison"`、base 8，
    `resources/symbols/venom_bite.tres:12-14`）。
  - 状态层改由每 SPIN 至多 1 次概率判定，频率与转轮脱钩，期望层数需另做模拟，本盘点不给估算数。
- 受影响的牌谱：`W03`（`resources/patterns/w03_venom_burst.tres:17`，条件含 `poison.tres`）、
  `SIG_W03_REAPER`（`resources/patterns/sig_plague_reaper.tres:17`，同样含 `poison.tres`）。

### 3.2 `fire_sword`（火焰剑）

- 现状：`burn.tres` 权重 5（`fire_sword.tres:5`、`:12-13`）+ `fire_slash.tres` 权重 3（`:6`、`:17-18`）；
  `hit_rate 0.88`（`:29`）。落线燃 → 灼烧层，`burn.base=12`（`resources/statuses/burn.tres`）。
- 迁移后：燃符号离池，火斩仍提供火伤害；灼烧改为攻击后概率触发（同一武器每 SPIN ≤1 次）。
  行为差异：当前"三列燃"可直接叠 3 层并触发 `acc["triple"]`？注意 status 分支不设 `acc["triple"]`
  （`combat_system.gd:169` 与 `:136`/`:180` 对比），三列燃只给层数，不提供三连事件。
- 受影响牌谱：`W01`（`w01_flame_resonance.tres:17`）、`SIG_W01_FIRESWORD`
  （`sig_fire_sword.tres:17`，解锁路径即 fire_sword）、`SIG_W01_EMBER`（`sig_ember_sword.tres:17`）、
  `SIG_W01_FLAMESTAFF`（`sig_flame_staff.tres:17`）——后两者虽由别的武器解锁，但火剑的燃同样是可达来源。

### 3.3 `frost_blade`（寒冰刃）

- 现状：`frost_slash.tres` 权重 4（`frost_blade.tres:5`、`:10-11`）+ `frost.tres` 权重 3（`:6`、`:15-16`）；
  `hit_rate 0.88`（`:25`）。`frost.base=0`（`resources/statuses/frost.tres`），不是 DoT，
  而是敌方减攻：`combat_system.gd:1214` 读取 `enemy_status.frost` 降低敌人攻击。
- 迁移后：霜符号离池，霜冻改概率触发；由于 `frost.base=0`，"概率触发"的收益是减攻覆盖率而非伤害。
  这使 frost 不太适合作为"DoT 代表"（不是伤害型状态），但它是状态迁移冲突面的代表（W02 系列）。
- 受影响牌谱：`W02`（`w02_frost_seal.tres:17`）、`SIG_W02_ZERO`（`sig_absolute_zero.tres:17`）、
  `SIG_W02_GLACIER`（`sig_glacier.tres:17`）、`SIG_W02_ICEGUN`（`sig_ice_gun.tres:17`）。

### 3.4 `holy_sword`（圣辉长剑）

- 现状：`holy_slash` 5 + `holy_verdict`（special）2.5 + `holy_burn` 3.5
  （`holy_sword.tres:11-12`、`:17-18`、`:22-23`、`:45`）；`hit_rate 0.88`（`:32`）。
  `holy_burn.base=10`（`resources/statuses/holy_burn.tres`）。
- 迁移后：圣灼离池，圣辉斩/圣裁仍正常；圣灼改概率触发。`status_effect_type=-1`（`holy_sword.tres:39`）
  说明该武器目前**没有**可用的状态元数据，迁移动要新填字段。
- 受影响牌谱：**0 条**——`W04`/`SIG_W04_HOLYSWORD` 的条件是 `holy_slash + dawn_bolt + light`，
  不含 `holy_burn`（`w04_holy_volley.tres:17`、`sig_holy_sword.tres:17`）。冲突面最小。
- 另注意：`mechanism_summary` 只写了圣辉斩（`holy_sword.tres:48`），未提圣裁/圣灼，属资源文案缺漏。

### 3.5 `night_scythe`（夜幕镰刀）

- 现状：`shadow_slash` 5 + `shadow_blight` 3.5（`night_scythe.tres:10-11`、`:16-17`、`:40`）；
  `hit_rate 0.75`（`:27`）。`shadow_blight.base=11`（`resources/statuses/shadow_blight.tres`）。
- 迁移后：蚀影离池，暗斩保留；蚀影改概率触发。`status_effect_type=-1`（`:36`），同样需要新字段。
- 受影响牌谱：**0 条**——`W05`/`SIG_W05_NIGHT` 只要求暗伤害 ×2（`w05_shadow_execution.tres:17`、
  `sig_night_scythe.tres:17`）。冲突面小。
- 文案同样只写暗斩（`night_scythe.tres:45`），未提蚀影。

## 4. 「每把武器每 SPIN 最多一次」的挂点

### 4.1 一次 SPIN 内可能让同一武器多次/多量触发状态的位置

| # | 位置 | 证据 | 说明 |
|---|---|---|---|
| 1 | 多格同线 | `combat_system.gd:169`、`:393-406` | 同一来源 3 格状态 → 一次调用给 `mult=3` 层；输出随格数线性 |
| 2 | 两把武器同状态族 | `combat_system.gd:169`、`:393-406` | 两武器各自 contribute，合并进同一个 `status_stacks[type]`，无来源归属 |
| 3 | 元素共鸣 | `combat_system.gd:686-688` | 同元素 3 格时，本回合已有状态统一 +1 层 |
| 4 | 回路「状态反应」 | `combat_system.gd:584-588`；`circuit_system.gd:28-32` | `status_applied` 事件额外 +1 层（每 SPIN 上限 1） |
| 5 | 奥术三连 | `combat_system.gd:120-122`、`:169` | MAGIC 同源三连 +1 层 |
| 6 | 牌谱追加层 | `pattern_effects.gd:105/127-128/153`；`combat_system.gd:509-513` | 与符号落线无关，额外叠层 |
| 7 | 武器 `status_effect_*` 字段 | `weapon_data.gd:24-26` | 0 读取；迁移要接的就是这个口 |
| 8 | DoT tick | `combat_system.gd:1325-1393` | 只消耗/衰减/爆发，不反向挂层；反射也只记录伤害，不挂状态 |

结论：当前**没有任何"每武器每 SPIN 最多一次"的收敛点**；状态层是按格数线性累加的，且同一状态族
不区分来源（`acc["status_stacks"]` 的键只有 status_type，`combat_system.gd:169`）。

### 4.2 候选挂点

**挂点 A：`CombatSystem.contribute()` 的 status 分支（`combat_system.gd:169`）**

- 做法：新增每 SPIN 集合 `_status_src_done: Dictionary`（键 = `source_key(sym.path, source_id)`，
  `reel_system.gd:957-958`），在 status 分支命中且该键未出现时给一次层数并置位；
  在 `_reset_turn_state()`（`combat_system.gd:321-338`）清空（该函数每次 evaluate 都会调用，
  `:250`；免费重转也走同一入口 `turn_flow.gd:181-188`）。
- 副作用：
  - 元素共鸣/回路/牌谱仍在其后追加层，不会被该挂点拦截；"最多一次"只约束转轮落线这一路。
  - 技能符号 `source_id=""`，需按符号路径去重；两把武器共用同一状态符号时按 `path|source` 区分，
    仍各自触发一次（符合"每把武器"口径）。
  - 同一武器携带两个不同状态符号时会各触发一次；当前 90 把武器均只有 1 个状态符号，
    若要"每武器"而非"每符号"，键需去掉符号路径。
- 可验证断言：
  - 正：单武器 3 格毒 → `enemy_status["poison"]` 只增加一次（例如 1 层 + 既有加成），不是 3 层。
  - 负：两把武器各带毒 → 同 SPIN 内两次挂层累计（各自一次）。
  - 边界：下一 SPIN 重置后再次挂层；元素共鸣仍 +1。

**挂点 B：`DuelController.add_enemy_status()`（`duel_controller.gd:1975-1980`）**

- 做法：给函数加可选 `source: String = ""`，内部维护 `_status_spin_sources`（每 SPIN 清空，
  可在 `begin_player_turn()` 清，`turn_flow.gd:40`；或 evaluate 起始清）；`source != ""` 且已记录时直接返回。
  调用点共 4 处需传来源：`combat_system.gd:513`（牌谱）、`:690`（转轮）、
  `normal_trait_gimmick.gd:324`、`consumable_system.gd:206`。
- 副作用：
  - 牌谱/回路/消耗品若也传同一来源会被误拦截，需明确"只有转轮路径传 source"；
  - 该入口拿不到状态类型以外的来源信息，无法区分"同武器两个状态符号"；
  - `enemy_status_pending` 的相位逻辑（`:1979-1980`）需与去重顺序一致（先判重再累加）。
- 可验证断言：
  - 正：同一 source 同 SPIN 连续两次 `add_enemy_status(..., "poison", 2, src)` → 只落一次。
  - 负：不同 source 各自落层；`source=""` 的调用（消耗品/gimmick）不受影响。
  - 边界：新 SPIN 后同 source 可再次落层。

## 5. 冲突面

### 5.1 `poison_dagger` 与 P3 和解

- 现状：`poison_dagger` 只有 1 个状态符号、0 个非状态符号（§2 矩阵）。P3「勇者的阴影」和解条件 a)
  已收口为"任意三列同符号"（含 status），直接读 grid：
  `scripts/battle/gimmicks/shadow_projection_gimmick.gd:101-121`（2026-11-24 注释与实现，
  `:105-108` 明确写了 `poison_dagger` 这类无核心符号武器会死局）；条件 b) 治疗符号
  `:122-126`；条件 c) 恢复/净化消耗品 `:133-136`。
- bot 侧同构和解：`tests/audit_playthrough.gd:189-198`（优先消耗品，否则定向锁列凑三连）、
  `:221-233`（P3 探测）、`:246-266`（选目标，明确"status(poison) 三列同符号也能和解"）；
  `tests/counterplay_test.gd:461-522`、`tests/p1b_baseline.gd:266-299` 同口径。
- 迁出轮池后它还剩什么三连？
  - `poison_dagger` 自身：**0 个非状态符号、0 个状态符号** → 单独装备时 grid 永远没有它的格子，
    既无三连、也无任何伤害输出（`reel_system.gd:1019-1039` 只会给它一个空 syms 的 pool_item，
    `build_strips()` 跳过空 syms，`reel_system.gd:346-349`）。
  - 双武器时：同伴武器的符号仍可三连，和解 a) 仍可达成；但若同伴也是状态-only（当前不存在第二把）
    或双方符号被 MISS 覆盖，只剩 b)/c) 两条路。
  - **会不会重新死锁**：会——只要"poison_dagger + 无治疗符号/无恢复消耗品且同伴符号不可三连"的
    状态出现，和解 a) 就拿不到任何同符号三列。单武器测试配置下则必然死锁。
    因此迁移必须同时给它一个基础伤害符号（如 `venom_bite`），或把和解 a) 扩成

## 6. 三个候选口径

### 口径 A：完整迁移（武器状态符号离池 + 攻击后概率触发）

- 改动面（粗估）：
  - `weapon_data.gd`：新增 `status_type: String`、`status_chance: float`、`status_stacks: int`（约 +6 行；
    现有 `status_effect_type/damage/duration` 是死字段，可复用/替换，`weapon_data.gd:24-26`）。
  - `reel_system.gd:1069-1078`：`weapon_syms()` 过滤 `kind=="status"`（约 +3 行）。
  - `combat_system.gd`：每个来源结算后按概率触发一次 + 每 SPIN 去重（挂点 A，约 +30 行，含 `:321` 重置）。
  - 55 把武器的 `.tres` 资源：移除状态符号条目、填触发字段（试点阶段只改 1 把）。
  - 10 条牌谱规则改造（试点阶段 2 条：W03/SIG_W03）。
  - 测试：新增概率/去重/技能不受影响/牌谱可达性用例（约 +120 行）。
- 对 §5 冲突面的影响：5.1 → `poison_dagger` 必须补基础符号或扩和解条件（见 §5.1）；
  5.2 → 10 条规则要改；5.3 → 技能不动；5.4 → 无键变化，保留符号资源即可。
- 可写的正/负断言：
  - 正：`status_chance=1.0` 的武器每次 SPIN 恰好挂一次状态，且层数固定。
  - 负：`status_chance=0.0` 不挂层；同 SPIN 落 3 格状态符号不叠加；
    两把武器各自一次；技能状态符号落线仍给层（防误伤）。
- 风险：最高。资源与牌谱同日改动面最大；DoT 总输出与频率改变，需重估平衡；
  poison_dagger 的和解通路需要额外裁决。

### 口径 B：状态符号保留为"触发卡"（不产层，按武器每 SPIN 触发一次）

- 改动面（粗估）：`combat_system.gd:169`（status 分支改为标记该来源触发，约 +10 行）、
  `:686-690`（统一按来源结算触发，约 +6 行）、`:321`（重置，约 +2 行）；资源零改动，牌谱零改动。
- 对 §5 冲突面的影响：5.1 → 状态符号仍在 grid，`poison_dagger` 仍能凑三连，和解不死锁；
  5.2 → 10 条牌谱全部保留可命中；5.3 → 技能不动；5.4 → 无影响。
- 可写的正/负断言：
  - 正：3 格毒 → 只结算 1 次层（不随格数放大）。
  - 负：两把武器同状态各自一次；下一 SPIN 重置；元素共鸣/回路/牌谱追加仍生效（不被误拦）。
- 风险：中低。但不是"攻击后概率触发"：状态仍占轮格、仍与转轮绑定，只是不再线性叠层；
  与基线 `:47` 的目标只完成一半。

### 口径 C：最小限频（不动符号位置，只把层数收敛为每武器每 SPIN 一次）

- 改动面（粗估）：`combat_system.gd:169` 加每来源去重 + `:321` 重置（约 +10 行）；其余零改动。
- 对 §5 冲突面的影响：全部保留（符号仍在池、牌谱仍可命中、poison_dagger 仍和解）。
- 可写的正/负断言：正——同一武器 3 格状态只给 1 次层；负——两把武器互不影响；下一 SPIN 复原。
- 风险：最低，但方向性不足：不实现"攻击后概率触发"，也不把状态格迁出轮池，
  做完仍要再做 A 或 B。

## 7. 结论

**推荐口径 A（完整迁移），试点只做 `poison_dagger` 一把。** 理由：基线 `:47`/`:357` 明确要求
"状态格迁移为实际攻击后的概率触发、每把武器每次 SPIN 最多判定一次"；口径 B/C 都达不到该目标，
只能作为过渡。`poison_dagger` 是唯一"零非状态符号"的武器，先做它能把 §5.1 的最坏冲突面一次暴露。

**需要用户拍板的点（3 个）**：

1. **触发概率与数值**：每武器一个固定概率字段（如 poison_dagger 35%），还是由 `hit_rate` 派生？
   是否需要"连续 N 次未触发则保底"？
2. **多次落线的补偿**：迁移后同武器 3 格状态被压成 1 次判定，层数是严格 1 次量，还是按落格数补偿层数
   （例如每年判定 +1 层/格）？这直接决定 DoT 期望输出。
3. **10 条状态牌谱的改造方式**：改成"武器元素/攻击"条件；或保留状态符号作为"仅技能可提供"的素材，
   接受"不带对应技能时这 10 条不可达"。

**若通过，第一步只做**：

- 武器：`poison_dagger`。
- 路径：符号表改为 `venom_bite`（伤害，poison 元素）+ 新字段 `status_type="poison"` /
  `status_chance`；`combat_system.gd` 增加"攻击后每 SPIN 一次"触发（挂点 A），
  `weapon_syms()` 过滤状态符号；`poison_dagger.tres` 移除 `poison` 符号并填字段。
- 牌谱：同步改 `W03` 与 `SIG_W03_REAPER` 的 `poison.tres` 条件（按拍板 3 的方案），并加可达性测试。
- 估算：代码约 45 行、资源 1 个、牌谱 2 个、测试约 120 行，合计约 **160–180 行**。

## 8. 基线 ↔ 代码偏差

1. **目标 vs 现状（核心偏差）**：基线 `:47` 写"武器附带的燃烧、中毒等命中特性不额外生成可瞄准的
   属性 Buff 格；目标是实际攻击造成伤害后按概率触发"，而代码里状态**就是**可瞄准的轮上符号格，
   完全由落线结算（`combat_system.gd:169`、`:690`）；武器上的状态字段
   `status_effect_type/damage/duration`（`weapon_data.gd:24-26`）0 读取。本盘点不改基线，仅登记。
2. **"每把武器每 SPIN 最多一次"未落地**：代码中没有任何按来源去重的状态挂层逻辑；
   `acc["status_stacks"]` 只按状态族聚合（`combat_system.gd:169`）。
3. **资源文案缺漏**：`holy_sword.tres:48`、`night_scythe.tres:45` 的 `mechanism_summary`
   只写了主攻击符号，未提第三/第二状态符号（`holy_burn`/`shadow_blight`），
   与 `.tres:45`、`:40` 的符号表不一致；图鉴路线/机制（`codex_system.gd:318-392`）会按符号表显示，两者观感不一致。
4. **状态三连不产生三连事件**：status 分支不设 `acc["triple"]`（对比 `combat_system.gd:136`/`:180`），
   所以"三列同毒"只给层数，不触发三连回响回路（`circuit_system.gd:23-27`）；P3 和解 a) 则是
   直接读 grid 三列（`shadow_projection_gimmick.gd:111-121`），二者口径不同、但当前并存且都有测试依赖
   （`tests/audit_playthrough.gd:246-266` 等）。

## 附录 A：矩阵复算脚本

在 Windows PowerShell 5.1 下运行（只读，不改仓库）。输出每把武器的符号数/状态数/非状态三连可达性，
以及按状态族汇总。

```powershell
$symDir = "E:\YID\seek_dead\resources\symbols"
$kindOf = @{}
Get-ChildItem $symDir -Filter *.tres | ForEach-Object {
    $t = Get-Content $_.FullName -Raw
    $k = if ($t -match '(?m)^kind = "([^"]+)"') { $matches[1] } else { "?" }
    $kindOf["res://resources/symbols/" + $_.Name] = $k
}
$rows = @()
Get-ChildItem "E:\YID\seek_dead\resources\weapon_templates" -Filter *.tres | ForEach-Object {
    $t = Get-Content $_.FullName -Raw
    $symMap = @{}
    foreach ($m in [regex]::Matches($t, '(?m)^\[ext_resource type="Resource" path="(res://resources/symbols/[^"]+)" id="([^"]+)"\]')) {
        $symMap[$m.Groups[2].Value] = $m.Groups[1].Value
    }
    $entries = @(); $weights = @()
    foreach ($sw in [regex]::Matches($t, '(?ms)\[sub_resource type="Resource" id="([^"]+)"\](.*?)(?=\n\[|\z)')) {
        $body = $sw.Groups[2].Value
        if ($body -match 'symbol = ExtResource\("([^"]+)"\)') {
            $sid = $matches[1]; $w = 0.0
            if ($body -match '(?m)^weight = ([\d.]+)') { $w = [double]$matches[1] }
            if ($symMap.ContainsKey($sid)) { $entries += $symMap[$sid]; $weights += $w }
        }
    }
    $maxNonW = 0.0
    for ($i = 0; $i -lt $entries.Count; $i++) {
        if ($kindOf[$entries[$i]] -ne "status" -and $weights[$i] -gt $maxNonW) { $maxNonW = $weights[$i] }
    }
    $statusEntries = @($entries | Where-Object { $kindOf[$_] -eq "status" })
    $rows += [pscustomobject]@{
        Weapon = $_.BaseName; Total = $entries.Count; Status = $statusEntries.Count
        NonStatus = $entries.Count - $statusEntries.Count
        Triple = $(if ($maxNonW -ge 2.5) { "yes" } else { "NO" })
        StatusSyms = (($statusEntries | ForEach-Object { ($_ -replace '.*/','') -replace '\.tres','' }) -join "+")
    }
}
$rows | Sort-Object Weapon | Format-Table -AutoSize
```
