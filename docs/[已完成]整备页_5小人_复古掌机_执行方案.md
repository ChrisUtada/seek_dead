## 1. 目标与动机

把"整备 + 铁砧"从**抽象列表**改造成**有角色人格的营地 hub**，并整体把游戏缩小成**复古掌机观感**，让内容更生动、更"掌机"。

两个独立诉求：

1. **生动化**：四类整备类目（武器/技能/消耗品/护符）+ 铁砧，各自人格化成一个**像素小人站**。玩家点小人 → 展开该类目。不再是冷冰冰的四列卡片。
2. **复古掌机化**：整体缩小 + 像素质感，让界面更像 GameBoy / DS 这类复古掌机。

## 3. 设计目标形态

### 3.1 掌机外壳（保留机身，屏内无按钮）

```
┌─────────────────────────────┐   ← 掌机机身外壳（复古塑料质感，纯视觉）
│ ▪ ▪ ▪         ●  ●  ●         │   ← 顶部扬声器孔 / 电源灯（装饰）
│ ┌───────────────────────┐   │
│ │                       │   │   ← 屏幕（唯一交互区）
│ │   主屏内容：5 小人     │   │
│ │                       │   │
│ └───────────────────────┘   │
│  ·····   （虚线区）   ·····  │   ← 方向键/AB 在屏幕外实体按键，屏上不画
└─────────────────────────────┘
```

- **机身外壳保留**（凹陷屏槽 + 边框 + 顶部装饰孔），做复古视觉氛围。
- **屏内不画任何按钮**：方向键 / A·B 理解为屏幕外的实体按键，玩家在屏幕上只看到"非按钮内容"（主屏 5 小人 + 可收起副屏）。
- 不用虚拟按键挤占屏幕空间 → 主屏内容区始终满宽。

### 3.2 主屏：5 个小人 hub

整备主屏顶部一排 5 个像素小人（用 `wq/jn/xh/hf/tz.png`），每个是一个"站"：

| # | 立绘 | 站 | 点击行为 |
|---|---|---|---|
| 1 | `wq.png` | ⚔ 武器 | 右侧副屏展开「武器卡堆」（`selected_loadout` 池） |
| 2 | `jn.png` | ✦ 技能 | 副屏展开「技能卡堆」（`selected_skills` 池） |
| 3 | `xh.png` | 🧪 消耗品 | 副屏展开「消耗品卡堆」（`selected_consumables` 池） |
| 4 | `hf.png` | 🛡 护符 | 副屏展开「护符卡堆」（`selected_charms` 池） |
| 5 | `tz.png` | 🔨 铁砧 | **直接进铁砧老虎机**（不进副屏） |

- 5 个小人横向一排，在 480 设计宽下每人 ~80px 即可放下（5×80=400 < 480）。
- 点小人 → 高亮选中 + 副屏滑出该类目。
- 底部保留「确认开战」按钮（这是交互按钮，不是装饰；放在屏内底部，属于"非掌机按键"的 UI 按钮，符合"屏内不画掌机虚拟键、但正常 UI 按钮仍可用"）。

### 3.3 副屏：放大 + 可收起的右侧抽屉

- **默认收起** = 屏幕右缘一条细竖条把手（约 8~12px 设计宽，带小箭头/图标）。
- **点把手 / 点对应小人** → 副屏从右滑出**大面板**（目标占主屏宽 ~55~60%、满高），显示该类目的装备卡堆（**复用现有 `_add_loadout_column` 逻辑，一次只显示一类目**，完美适配小屏）。
- **再点把手 / 点别处 / 切到另一小人** → 收起或切换。
- 铁砧小人点开直接跳铁砧场景，不进副屏。

> 副屏本质是"把原来 4 列并列"改为"1 列 + 抽屉切换"，因为小屏放不下 4 列 250px 宽。

## 4. 落地阶段（每阶段 1 commit + verify_overlays.py 全绿 + 你 F6 复验 + SSH 推送还原 HTTPS）

### P1 · 掌机外壳 + 降分辨率 + 像素缩放（✅ 已落地 2026-08-06）
- **`project.godot` 改动**：
  - `window/size/viewport_width=480` / `viewport_height=270`
  - `window/size/window_width_override=960` / `window_height_override=540`（= 480×270 ×2，整数倍）
  - `window/stretch/mode="canvas_items"`（保持）
  - `window/stretch/aspect="keep"`（**改 `expand`→`keep`，防拉伸变形**）
  - `window/size/min_width=480` / `min_height=270`（最小即设计分辨率）
  - 渲染层加 `rendering/textures/canvas_textures/default_texture_filter=0`（**`nearest`，硬边无模糊**）。注：Godot 4.7 该键路径以实际导出项为准，若无则用 `ProjectSettings` 全局纹理过滤设置。
- **外壳节点**：在 `battle_hud.tscn` 或各覆盖层根加一个 `DeviceFrame`（MarginContainer/PanelContainer + 九个宫格线或边框 + 顶部装饰孔），纯视觉、不拦输入（`mouse_filter=IGNORE`）。
- **不动玩法**，仅视觉外壳 + 缩放。验证：F6 整体缩小、像素硬边、不拉伸。

> **⚠️ P1 落地连带影响（预期内，非 bug）**：`viewport` 降至 480×270 后，现有 UI（按 1280×720 设计）在 480 设计空间内会**溢出 / 字号过大、排版挤压**，需接续 **P2（TypeScale 重标定 + 像素字体）** 与 **P3（整备页重排）** 才能正常显示。这是分阶段规划必然结果。另：`default_texture_filter=0`（nearest 硬边）原本已存在于 `project.godot`，P1 未重复添加；`DeviceFrame` 内联于 `battle_hud.tscn` 根（非实例覆盖），`z_index=100` + `mouse_filter=IGNORE`，自动罩住所有运行时加载的覆盖层（整备/铁砧/商店/奖励）。

### P2 · 像素字体接入 + Palette 硬边化 + TypeScale 重标定（✅ 已落地 2026-08-06，commit `f0adb30`）
- **像素字体（实际用 zpix，非 m5x7）**：UI 含中文（整备/武器/技能…），纯拉丁像素字体（m5x7/Press Start）无法覆盖 CJK，故选用 `zpix`（开源中文像素字体，`assets/fonts/zpix.ttf` + `zpix_font.tres`，`antialiased=false` 硬边）。通过 `project.godot` 的 `gui/theme/default_font="res://assets/fonts/zpix_font.tres"` 全局生效——所有 Label 自动走像素字，无需逐 Label override。这是"复古感"最大杠杆。
- **`Palette` 硬边化**：`palette.gd` 新增 `PANEL_RADIUS=0` / `BORDER_WIDTH=2` 常量。所有内联 StyleBoxFlat（`battle_hud.gd` tooltip/转轮格、`anvil_screen.gd` 老虎机卡、`loadout_screen.gd` 列面板）的 `set_corner_radius_all(6)` / `set_border_width_all(1)` 统一改为读 `Palette.PANEL_RADIUS` / `Palette.BORDER_WIDTH`。转轮"元素强调格"保留 `set_border_width_all(3)` 作为选中强调，不归并。
- **`.tscn`/`.tres` 内置主题硬边化**：`battle_hud.tscn`(sb_dmg/sb_legend/sb_frame/sb_dot)、`reward_screen.tscn`、`symbol_cell.tscn`、`ui_button.tscn`、`battle_theme.tres`(PanelContainer) 的 `corner_radius_*` 全部归零；面板/卡片类边框 `1→2`（`ui_button`/`reward_screen` 边框保持，避免小按钮过重）。
- **`TypeScale` 按 480×270 重标定**（约原值 /2.4，CJK 下限抬到 ≥9px 保证可读）：
  - REEL 16 / OVERLAY 12 / TITLE 13 / LEAD 12 / SUBTITLE 11 / BODY 11 / MEDIUM 10 / META 10 / TINY 9 / CAPTION 9
  - 个别散落字面量（如 `battle_animator` 飘字 40、`battle_hud` 部分 13/18）未强约束，留作后续按需收口。

## 6. 风险与必须遵守的铁律

- **手写 .tscn 铁律（最高优先级）**：绝不用文本给 Godot 实例（`instance=ExtResource`）内部写覆盖子节点——Godot 4.7 重新保存会整段剥离（本项目 `dd04c1c` 已因此踩坑，PlayerPanel/EnemyPanel 已改内联根治）。**5 小人 / 副屏抽屉一律用内联节点或编辑器 Editable Children 流程**，绝不做"实例 + 手写子节点"。
- **抽屉动画用 Tween 操控 `position`/`custom_minimum_size`**，不要靠运行时 `add_child` 实例覆盖——保持节点在文件内是稳定的直属节点。
- **`viewport` 降到 480×270 后，所有现有 UI 需重测可读性**：战斗 HUD（转轮 3 格 + 立绘 + SPIN）、商店列表、奖励卡片、铁砧老虎机，字体走 P2 新阶梯，必要时缩内容密度。这是 P1/P2 的连带影响。
- **`nearest` 过滤会让非像素美术出现锯齿**：`wq/jn/xh/hf/tz.png` 需是像素图（确认已是），`char.png`/`enemy.png` 若非像素风可能显糙，P4 时评估。
