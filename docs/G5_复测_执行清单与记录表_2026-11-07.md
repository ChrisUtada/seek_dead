### 1.1 机器与版本

- Windows 10/11 x86_64；窗口化运行，记录实际分辨率（480 / 960 / 1440 / 其他）。
- 解压/复制整个 `build/ACT1_Demo_2026-11-07_g5/` 目录，不要只拷 exe。
- 版本核对（任一不符则停止，不要继续记数据）：
  - `BUILD_INFO.txt` 的 SHA-256 与 `Seek Dead ACT1 Demo.exe` 一致；
  - 整备页底栏有「🗺 棋盘」按钮；
  - 棋盘节点图标为 16×16 点阵（起点/战/精/王/武/符/店/营/宝/龛/库）。

### 1.2 存档

- 测试前备份：
  `%APPDATA%\Godot\app_userdata\Seek Dead Prototype\lobby_data.json`
  复制为 `lobby_data_T1_backup.json`（T1 换成测试者编号）。
- 自己机器测完可还原；**外部测试者的真实进度只备份，不要用你的备份覆盖**。
- 新旧包、线性与棋盘子局共用同一存档；不要为了“干净档”删除他人进度。

### 1.3 日志（推荐，不强制）

- 双击 `启动_棋盘模式_记录日志.bat`：在本目录生成 `g5_log.txt`。
- 日志包含：
  - 确认开战后的「棋盘模式：ACT1 / 节点数 / … / 骨架 / 模板」；
  - 局末（通关或战败）的 `TELEMETRY|…` 一行（回合、三连、承伤、TTK、换武器、停中率等）。
- **每次启动会覆盖 `g5_log.txt`**：一局结束、退出游戏后立刻改名为 `T1_R1.txt`，再开下一局。
- 日志为空或缺失时，以手填记录表为准，不影响测试。

## 2. 每局执行清单

开测前（每局都做）：

- [ ] 测试者知道：死亡/通关都算一局，不重开补数据。
- [ ] 保持默认目押预设（`control`），不改设置、不摇铁砧、不花局外点数。
- [ ] 计时从点击「确认开战」开始，到通关/失败结算或主动退出为止。

局内（记录员观察，不提示答案）：

- [ ] 第一次看到棋盘时，请测试者 10 秒内指出下一步合法落点，记录用时与对错。
- [ ] 每次选路后问一句「为什么选这边」，记录关键词（BOSS/特殊格/主题/商店营地/随便）。
- [ ] 遇到特殊格：记录类型、节点位置、测试者的选择与反应。
- [ ] 记录死亡点（房间/节点名）、是否差点输、是否出现卡住/报错/奖励异常。
- [ ] 数战斗场次（普通+精英+BOSS）；走特殊格尾路通常为 7 场，其余 8 场。

局后（立刻填，不凭记忆）：

- [ ] 每局主表（§3.1）
- [ ] 每局问卷（§3.2，15 题）
- [ ] 特殊格观察（§3.3，若本局遇到）
- [ ] 日志改名（若启用）

### 5.1 通过标准（来自计划 §9）

- [ ] 无阻塞流程、错误奖励、旧 UI 数值或不可达内容（0 次）。

## 6. 中止 / 异常处理

- 卡死、崩溃、奖励明显错误、节点不可达：立即截图，记录节点与操作序列，停止该局。
- 同一次测试出现 2 次以上同类异常：暂停招募，先修再测。
- 测试者明显疲劳（连续打哈欠、频繁误触、说“随便”）：休息或改天，不要把疲劳数据当难度数据。
- 外部测试者的存档只备份不覆盖；不要为了复现删除对方进度。
