## 1. 任务目标

将当前战斗 HUD 改造成以下视觉方向：

- 暗紫褐背景
- 暖白/灰米色细线框
- 灰白玩家、红色敌人与 BOSS
- 武器和转轮使用像素图标，不使用全量小人
- 左侧玩家装备、中央角色与转轮、右侧敌人信息三栏结构保持不变
- 顶部继续提供房间、金币、回合和间歇操作
- 中央继续保留玩家、敌人、三列转轮和 SPIN

最终交付不是静态图片，而是**可以在 Godot 中实际操作、通过回归测试的战斗 UI 样板**。

## 2. 目标图与布局解释

### 2.1 目标图的使用方式

目标图用于判断：

- 色彩和明暗关系
- 线框、间距和面板层级
- 玩家与 BOSS 的视觉体量
- 图标、文本和转轮的相对位置
- 整体风格与信息密度

目标图不是要求逐像素复制的场景文件。实现时继续使用 Godot Container、锚点和最小尺寸，不要把整张界面写成绝对坐标。

### 2.2 480×270 逻辑布局参考

| 区域 | 参考范围 | 保留内容 |
|---|---|---|
| 外框 | 约 1px 四边 | 细线框与少量角部铆钉 |
| 顶栏 | 高约 21–23px | ACT/房间、金币、回合、商店、下一房 |
| 左栏 | 宽约 90–92px | 玩家 HP/护盾、双武器、技能/护符、消耗品、金币 |
| 右栏 | 宽约 90px | BOSS 名称、HP/护甲、弱抗、意图、状态、充能、机制摘要 |
| 中央舞台 | 顶栏下至转轮上方 | 玩家、敌人/BOSS、敌人意图、HP |
| 转轮区 | 三格约 38×38px，居中 | 三列转轮、匹配角标、SPIN |
| 底部反馈 | 中央底部一行 | 三连、克制、总伤害等短反馈 |

实现时以现有节点和容器为准调整，不要求完全等于上述像素值。

## 3. 明确不做

执行 AI 不得借本任务实施以下事项：

- 不修改 `combat_system.gd` 的伤害公式或动画时序。
- 不修改 `balance_config.tres`、伤害倍率、ante、命中、暴击或敌人属性。
- 不新增角色历练、武器熟练、铭印或其他成长系统。
- 不修复或重构奖励、铁砧、收藏和 GAME+，这些属于其他里程碑。
- 不改变双武器、技能槽、护符和消耗品规则。
- 不增加 ROWS=2、主动锁定、抢击或额外界面按钮。
- 不批量生成 90 把武器、全部敌人或全部 BOSS。
- 不执行全量武器小人化，不新增 `character + anim_class` 作为武器默认路线。
- 不覆盖原始 `knight1.png`、`bossbf.png` 等历史素材；风格化版本必须另存。
- 不为了模仿参考图而复制《He is Coming》的具体素材。

### 4.2 工程约束

- 逻辑分辨率 480×270，默认窗口 960×540。
- 纹理使用 NEAREST，禁止引入模糊缩放。
- 中文字体链保持 `VonwaonBitmap-12px + zpix`。
- 手写 `.tscn` 时，不给 `instance=ExtResource` 的实例内部覆盖子节点。
- 修改节点路径前，必须同步检索 `battle_hud.gd` 中的 `$...` 引用。
- 所有演出随机继续使用局部 RNG，不消耗全局随机流。
- 每阶段独立验证、独立提交，不把全部改动压成一个巨大提交。

## 5. 视觉规范

### 5.1 样板色板

以下颜色与概念图一致，可在实机验收时微调，但不得每个节点单独创造新色。

| 语义 | 色值 | 用途 |
|---|---|---|
| 主背景 | `#160D13` | 全屏与中央舞台 |
| 面板背景 | `#1D1219` | 左右栏、卡片和按钮 |
| 深描边 | `#3A222B` | 内部隔断、角色暗部 |
| 主文字/主线框 | `#E2D7BD` | 关键文字、外框、重点线 |
| 次级文字/次线框 | `#A99D89` | 描述、次级边框 |
| 弱信息 | `#6E5F57` | 禁用、非重点提示 |
| 玩家灰白 | `#B9B8B0` | 玩家和中性装备 |
| 敌人红 | `#E35B50` | 敌人、伤害、危险意图 |
| 敌人暗红 | `#8C3438` | 敌人暗部、危险框 |
| 交互金 | `#D5A33D` | SPIN、奖励、可用操作、匹配角标 |
| 生命绿 | `#A4BC4D` | HP 和治疗 |
| 护盾蓝 | `#62A1C2` | 护盾、护甲、防御 |

颜色纪律：

- 红色不用于普通稀有度装饰。
- 金色只强调可操作、奖励和匹配，不大面积铺背景。
- 面板使用稳定实色，避免多层透明叠色造成色偏。
- 禁用状态同时降低边框和文字亮度，不能只改文字颜色。

### 5.2 线框与间距

- 外框和内部普通分隔使用 1px。
- 当前选中、SPIN、关键奖励可以使用 2px 或金色强调。
- 取消当前 10px `DeviceFrame` 厚外壳及无功能装饰点。
- 主 HUD 不再常驻显示“Seek Dead · 老虎机对决”标题。
- 一级外框可以保留少量铆钉，不给每个小格子添加铆钉。
- 面板间距优先 2px/4px，避免无效空白挤压舞台。

### 5.3 字体与文本

- 保持现有像素字体，不更换中文正文。
- 优先使用现有 9px/10px 缓存档位。
- 长机制说明不得全部常驻右栏，只保留当前阶段摘要，完整内容走 tooltip。
- 关键 HP、意图、SPIN 不得使用过暗弱信息色。
- 不用缩小字号解决布局溢出，优先缩短文本或调整区域。

## 6. 分步实施方案

## Step 0 · 基线与引用检查

1. 保存当前战斗界面截图。
2. 运行一次 `run_smoke.bat`，记录基线结果。
3. 检查 `battle_hud.tscn` 中 `TitleLabel`、`DeviceFrame`、三栏和转轮节点。
4. 全局检索这些节点的脚本引用，确认删除、隐藏或保留的影响。
5. 列出本任务需要替换的颜色、StyleBox 和图标回落。

**交付**：现状截图、引用清单、基线测试结果。  
**禁止**：本步不修改游戏逻辑。

## Step 1 · 统一色板和基础主题

1. 在 `palette.gd` 中按语义整理新色板。
2. 更新 `battle_theme.tres` 的背景、面板、Label、Tooltip 样式。
3. 更新 `ui_button.tscn` 的普通、悬停、按下、禁用状态。
4. 更新 `ui_panel.tscn`、`symbol_cell.tscn` 的边框和底色。
5. 清理会被新 Theme 覆盖的重复局部样式，但保留真正有语义的例外，如危险、锁轮和元素色。

**验收**：所有基础组件在实机中风格一致；禁用按钮、tooltip、转轮角标仍可读。  
**独立提交点**：主题与基础组件换肤。

## Step 2 · 战斗 HUD 结构整理

1. 移除或隐藏常驻产品标题，释放顶栏空间。
2. 移除 10px 厚外壳与装饰点，改成细外框。
3. 保留顶栏、左栏、中央舞台、右栏、ReelDock 和 SPIN 的现有结构关系。
4. 调整 Margin、最小尺寸和间距，使三栏接近概念图比例。
5. 中央转轮继续居中，不改成参考游戏的其他布局。
6. 保留商店/下一房按钮的禁用与间歇逻辑。
7. 同步更新所有受影响的 `$节点路径`。

**验收**：480×270 下无重叠、裁切、非预期滚动；SPIN、转轮和右侧意图完整可见。  
**独立提交点**：HUD 结构与线框调整。

## Step 3 · 样板角色风格化

1. 以 `assets/knight/knight1.png` 为输入，另存灰白版本，不覆盖原图。
   （执行口径：实机玩家立绘为 `assets/characters/viking/idle_01..04 / attack_01..05`，已按备注③改用该组输入，输出 `assets/characters/viking_ash/`。）
2. 以 `assets/bossbf.png` 为输入，另存红色版本，不覆盖原图。
3. 使用少量色阶，保留透明背景和 48×48 原始像素规格。
4. 将玩家灰白版本接入战斗 HUD。
5. 将红色 BOSS 版本通过 `RoomData.art` 接入冰封铁瓮。
6. BOSS 可使用现有 `art_scale` 形成体量差，但优先使用整数倍率，并验证舞台空间。
7. 将红色敌人的受击反馈改为暖白闪或明暗反相，避免红闪在红色主体上不可见。

**验收**：玩家与 BOSS 剪影清楚；BOSS 不遮挡意图和转轮；受击反馈可见。  
**独立提交点**：样板角色与演出适配。

## Step 4 · 武器与转轮图标样板

1. 只为样板内容制作少量图标：火焰剑、战斧、对应攻击/火焰符号，以及 HP、护盾、金币、护甲、充能等基础语义图标。
2. 卡片主图可以使用 24×24 或 48×48；转轮图标必须独立制作 16×16。
3. 不将 48×48 主图直接缩成 16×16。
4. 使用通用 `art/icon` 绑定思路，不引入全量武器小人和动画字段。
5. 复用 `ItemCard.set_art()`；缺少图标的物品保留现有 emoji/文本回落。
6. 转轮格新增图标显示时，保留匹配角标、元素色、锁定/干扰/冻结状态和 tooltip。
7. 本次只完成样板绑定，不批量替换所有物品。

**验收**：转动和停止时图标可辨；角标不遮挡主体；无图标资源时旧表现正常。  
**独立提交点**：图标组件与样板资源。

## Step 5 · 信息层级与细节收敛

1. 左栏优先显示 HP、护盾、双武器和消耗品。
2. 右栏优先显示 BOSS 名称、HP、护甲、弱点、抗性和下一意图。
3. 充能、状态和机制摘要按重要性排列，避免所有文字同等高亮。
4. 底部只保留短反馈，如“火斩×3 / 克制×1.5 / -46”，不恢复大段伤害分解面板。
5. 检查商店抽屉、奖励卡片、整备界面在本任务改动后没有被主题变化破坏。
6. 清理本任务新增的旧视觉注释，但不顺带进行大规模代码重构。

**独立提交点**：信息层级与细节修正。

## Step 6 · 实机验收与交付

1. 执行完整自动回归。
2. 进行 F6 实际交互。
3. 输出改造前后对比截图。
4. 记录仍未完成的资源与限制。
5. 由用户确认是否以该样板继续全界面改造。
