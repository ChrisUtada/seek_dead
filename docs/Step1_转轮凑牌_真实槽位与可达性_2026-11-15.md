## 1. 怎么测的

- 固定配置：2 武器 + 1 技能 + 1 护符（不依赖扩槽）
- 枚举 **90 把武器的全部 4005 个无序双武器组合**
- 对每个组合，用**这两把武器真实能提供的符号**构造三格全部排列（≤ 4³ 种）
- 交给 `PatternMatcher.solve_rule` 判定（复用实现，不另写一套逻辑）
- 技能术式：40 个技能 × 两把武器

这不是「理想牌面」：牌面严格限制在两把武器产出的符号范围内，正是「真实可达」的定义。
触发率统计才必须用真实转轮带（第 62 套在做）。

## 3. 最重要的发现：W01 的判定语义是错的

统计武器携带的符号后发现：

| 武器元素 | 携带的 (kind, element) |
|---|---|
| **fire** | damage/**none** ×14、status/**fire** ×15、special/none ×1 |
| ice | status/ice ×15、damage/ice ×11、damage/none ×4 |
| poison | damage/poison ×14、status/poison ×15 |
| light | damage/light ×24 |
| dark | damage/dark ×21 |
| none | damage/none ×16 |

**火系武器的伤害符号 element 是 `none`，不是 `fire`。**

火斩的机制描述也写着「火斩（5权重，**无属性伤害**）」。

后果：现有 `s01_flame_resonance.tres` 的 `match_rule` 里那条 `{"element": "fire"}`，
匹配到的**不是火系伤害，而是「燃」这张火元素状态牌**。

它现在「可达」（105 对正例），但走的是「火斩 + 燃 + 燃」这种牌面 ——
第二个条件被状态牌满足，与方案 §5.2「灼烧＋**火系武器伤害**＋任意武器牌」不是一回事。

### 必须的修法（Step 2 处理）

「火系武器伤害」必须按**来源武器的元素**判定，不能按符号自身的元素：

```text
条件应为：{ kind: damage, source_weapon_element: fire }
而不是：  { kind: damage, element: fire }
```

这需要匹配输入里带上「来源武器的元素」这一维度（方案 §8 的 `source_kind` 扩展）。

冰系与毒系没有这个问题（有 element=ice / poison 的伤害符号），但为了一致性，
W01–W03 建议统一按来源武器元素判定。

## 7. 一个方法论上的收获

对比第 62 套的触发率统计：那个回答的是「凑出来之后多常发生」，这个回答的是「能不能凑出来」。
