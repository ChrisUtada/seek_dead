# 光系武器补强 · 圣裁与稀有度重分配（2026-11-15）

> 起因：方案 §6.2 写「当前无高稀有光系武器」，核实后确认属实 —— 但根因不是数值，是**光系没有任何机制符号**。  
> 方案选择：**B —— 用 special 承担机制，不新增武器**。

---

## 1. 查到的三件事

### 1.1 数值不弱

| 元素 | base_power 均值 |
|---|---:|
| dark | 15.5 |
| **light** | **14.3** |
| fire | 13.9 |
| ice | 13.5 |
| none | 13.3 |
| poison | 12.0 |

光系排第二。

### 1.2 稀有度标签与数值错配

稀有度与 power 并非强相关（uncommon 有到 23 的，rare 有 11 的），但光系的构成明显异常：

```
common 4 / uncommon 11 / rare 0 / epic 0
```

其他元素的 uncommon 都在 3–8 把，光系堆了 11 把，且 0 把高稀有。

### 1.3 真正的拦路石：分类学硬规则

项目约定（`item_taxonomy_test`）：

> **rare / epic 武器必须有状态 / 特殊 / 三连机制**，不能是纯伤害。

而光系 15 把武器的符号**全是 `kind = damage`** —— 没有状态、没有 special。

第一次尝试直接升格 4 把，测试立刻红 3 条：

```
FAIL  dawn_blade       高阶武器有状态/特殊/三连机制
FAIL  holy_sword       高阶武器有状态/特殊/三连机制
FAIL  sunforged_blade  高阶武器有状态/特殊/三连机制
```

（十字军巨剑例外：它有 `triple_pierce = true`，三连清甲机制。）

**所以光系不是「数值不够」，是「没有内容可以承载高阶」。**

## 2. 处置：新增光系 special「圣裁」

```text
圣裁  holy_verdict.tres
  kind    = special
  element = light      ← 与炎爆（none）不同：吃光系元素克制
  base    = 20         ← 低于炎爆 25，因为光系有其他加成
  weight  = 2.0~2.5    ← 低频率、高单格
```

挂到 3 把纯伤害光武（另一把十字军巨剑已有三连机制，不需要）：

| 武器 | 原符号 | 加圣裁后 | 权重 |
|---|---|---|---|
| 晨曦之刃 | 圣辉斩 + 晨曦之光 | + 圣裁 | 2.0 |
| 圣辉长剑 | 圣辉斩 | + 圣裁 | 2.5（单符号武器，给更高权重） |
| 日铸圣剑 | 圣辉斩 + 晨曦之光 | + 圣裁 | 2.0 |

圣裁的意义不是「过测试」：它是光系第一张特殊牌，给光系提供「低频率高单格」的节奏 ——
与冰系的持续霜冻、火系的灼烧叠加形成区分。

## 3. 稀有度重分配（按数值对齐）

| 武器 | power | 原 | 现 |
|---|---:|---|---|
| 十字军巨剑 | 22 | uncommon | **epic** |
| 日铸圣剑 | 20 | uncommon | **epic** |
| 晨曦之刃 | 19 | uncommon | **rare** |
| 圣辉长剑 | 18 | uncommon | **rare** |

升格依据是数值落在同档区间内（rare 11–23 均值 17.8 / epic 15–23 均值 19.2），
不是「随便挑 4 把」。

结果：

```
光系   common 4 / uncommon 7 / rare 2 / epic 2
fire   common 6 / uncommon 5 / rare 2 / epic 2   ← 与 fire 齐平
```

分类学 **4702 / 0 fail**（比调整前多 4 条检查，因为升格后触发了机制校验）。

## 4. W04 终于有名分了

新增签名 `SIG_W04_HOLYSWORD`（黎明圣辉·圣裁齐射）：

| 项 | 值 |
|---|---|
| 关键武器 | 圣辉长剑 |
| 改写 | 齐射伤害 = 两件来源武器攻击和的 50% → **80%** |
| 约束 | 仍要求圣辉长剑＋破晓之弓占满双武器槽（不放开解锁） |

方案 §6.2 对 W04 的要求是「保留指定双武器组合，不为填签名强行新增内容」——
这条签名没有放宽解锁，只强化效果，符合要求。

## 4.5 两次连带修复（升格影响到了下游）

升格光武器后，全量回归红了两个套件 —— **都不是光系本身的问题，是它们隐式依赖了掉落池构成**。

### boss_loot_quality：「12 个 BOSS 的分布都是 10/60/30（不符：无名虚空）」

无名虚空的奖励池里正好有圣辉长剑与晨曦之刃，升格后池子从
`2 uncommon + 1 rare + 1 epic + 1 common` 变成 `3 rare + 1 epic + 1 common`，
分布自然歪掉。

修复：把这两把换成仍是 uncommon 的光武（圣光钉锤、辉光军刀），保持「暗系 BOSS 掉光系武器」的主题。
换完之后 uncommon 抽到 **0%** —— 因为替补武器缺 `boss` 来源标签被池子过滤，
补上 `boss` 后才恢复 10/60/30。

### board_ui：「宝箱结算后回到地图」

宝箱内容由掉落池随机决定，升格后正好抽到武器 → 触发「替换武器」弹层 → 地图不可见。

这条测试本来要验证的是「非战斗节点共用的 `return_to_board` 出口」，
替换弹层是合法中间态但不属于它的验证范围。修复：测试里把宝箱固定成金币路径，
并在注释里写明原因 —— **不要让测试依赖掉落池的稀有度构成**。

验证方式：`git stash` 收起全部改动后 board_ui 是 97 项全过，
带改动是 96 项 1 失败 —— 确认是我引起的，不是既有 flaky。

## 5. 过程中的两个坑

| 坑 | 现象 | 处理 |
|---|---|---|
| `%` 格式化与中文冲突 | 用 `body % (HS, HS)` 写 tres 时 `ValueError: unsupported format character`，文件根本没写入，但随后的可达性测试照样通过（它测的是基础 W04） | 改用列表 `join` 拼接 |
| 手写 sub_resource 后 `load_steps` 没更新 | 少一行空行、`load_steps=5` 但实际 7 个资源 | 按 ext+sub+1 重算 |

第一个值得记：**写文件失败但测试仍绿** —— 因为那条测试根本不检查这个文件。
