## 1. 一句话结论

90 把武器实际只有**约 17 种符号结构签名**；**约 83% 武器以数值和权重差异为主，存在显著结构重复**（这是符号结构重复度指标，不代表这些武器没有价值——部分仍有签名、三连破甲、命中与暴击差异）。真正具独特机制结构的是 **4 把 special 武器 + 11 把 signature 武器 + 15 把穿甲武器**。引擎身份光谱中**防御/治疗完全空白、覆盖与对子结构性稀缺**；写规格前需裁定 2 处命中事实偏差（校准命中未进建池、稳手文案数值过时）。**本轮不动内容，先定规格。**

## 2. 数据口径

- 解析 `resources/weapon_templates/*.tres`（90 把）与 `resources/symbols/*.tres`（80 个），重建 ext/sub_resource 引用链，提取 element / reel_element / archetype / weapon_type / symbols(符号+权重) / base_power / hit_rate / triple_pierce / unique_group / status_effect_* 等。
- 与已提取背景数据交叉验证全部吻合：90 把；符号结构 65×2 符号 / 21×1 符号 / 4×3 符号；frost/poison/burn 各 15。
- 元素：fire/ice/dark/poison/light 各 15，none 显式 10 + 未声明 5（默认 none）= 15。
- **关键事实**：90/90 把 `role="damage"`，`family_tags` 全部含 `"combo"` —— 武器侧无防御/治疗/资源角色。

## 3. 聚类结果

### 3.1 按 unique_group（元素主线 + triple）

| 组 | 数量 | BP 范围 | 机制判断 |
|---|---|---|---|
| `weapon_light_pure_line` | 14 | 8~20 | **唯一真正分化的元素组**：含 4 把 3 符号 + 3 把 special(holy_verdict) + 最多 signature |
| `weapon_ice_frost_line` | 13 | 8~16 | frost 状态 + 冰/中性伤害符号的权重变体；3 把 signature 提供机制 |
| `weapon_fire_burn_line` | 12 | 8~18 | 纯数值换皮：`fire_slash + burn` 两符号调权重 |
| `weapon_poison_poison_line` | 12 | 7~15 | 三种模板权重变体；1 把 signature |
| `weapon_dark_pure_line` | 12 | 8~23 | 重复度最高之一：shadow_slash/chain + 可选 shadow_blight；无 special |
| `weapon_none_pure_line` | 11 | 8~14 | "白板武器集中营"：`iron_slash×5` 占 5 把 |
| 五个 `*_triple` 组 | 15 | 12~23 | 唯一机制区分轴 = `triple_pierce=true`（三连清空护甲），其余与 line 组同符号 |
| `weapon_fire_special_line` | 1 | 15 | 火焰法杖：唯一 special 火武器（flame_special） |

### 3.2 特殊机制资产全集

- **special kind 符号全表仅 2 个**：`flame_special`（炎爆，base25）、`holy_verdict`（圣裁，base20）。持有武器 4 把：晨曦之刃、圣辉长剑、日铸圣剑、火焰法杖。
  - 代码事实：两者**共享同一套结算**（高 base 爆发 + 可凑三连通用破甲 `pierce_armor`），差异仅 base 与元素；真正机制来自 signature 牌谱。S2 规格须明确"机制归符号还是归牌谱"。
- **signature 武器 11 把**（有专属 sig 牌谱，如火焰剑/余烬长剑/冰霜枪/蚀日之刃/冰川巨剑等）。
- **status_effect_type != -1 的 5 把**：匕首/火焰剑/赤焰弯刀/冰霜枪/毒匕首。
  - **重大事实**：`status_effect_type` 全代码库**只有声明无消费点**（仅 `weapon_data.gd:24`），是遗留字段；真实状态由符号 `kind=="status"` + StatusDef 驱动。S2 不应把这 5 把当独立机制来源。

## 4. 换皮 / 重复清单

### A 级：符号种类+权重完全相同（最严重，纯数值换皮）
| 符号签名 | 数量 | 代表武器 |
|---|---|---|
| `iron_slash×5` | 6 | 决斗军刀、铁枪、铁剑、钉头锤、短剑、战锤 |
| `shadow_slash×5 + shadow_blight×3.5` | 4 | 幽暗军刀、夜幕镰刀、暮影匕、暗影匕首 |
| `poison×2 + venom_bite×5` | 3 | 枯萎长枪、疫木斧、锈蚀砍刀 |
| `burn×2 + fire_slash×5` | 3 | 烬木手斧、烬光军刀、熔岩重锤 |
| `shadow_slash×6` / `shadow_slash×5` / `axe_slash×5` / `pistol_shot×5` | 各 2 | 惊惧巨剑&审判大剑 / 暮色手斧&墓穴重锤 / 战斧&伐木斧 / 燧发枪&手枪 |
| 另有 8 组各 2 把（burn+frost+poison+holy 系） | 16 | 详见逐组审计 |

### B 级：符号集合相同、仅权重微调
- `burn + fire_slash`：**14 把**（全表最大换皮簇）
- `poison + venom_bite`：8 把；`frost + frost_slash`：7 把；`shadow_blight + shadow_slash`：5 把 等。

### C 级：中性伤害符号多命名（功能等价）
`iron_slash` / `axe_slash` / `dagger_slash` / `pistol_shot` / `arrow_shot` / `bolt_shot` / `fire_slash`(元素none) / `ice_shot`(元素none) 全是 `kind=damage, element=none`，仅 base 不同。

**量化（符号结构重复度指标）**：90 把 → ~17 种符号结构；独特结构（3符号/special/独立signature）≤15 把；约 75 把（83%）以数值和权重差异为主、存在显著结构重复。此为结构重复度指标，不等于这些武器无价值（签名、三连破甲、命中/暴击差异仍存在）。

## 5. 定位空白（引擎身份支撑度）

武器侧符号 kind 统计：`damage 104 / status 55 / special 4`，**shield/heal/buff/gold 为 0**。

| 引擎身份 | 支撑度 | 证据 |
|---|---|---|
| 集中 | ✅ 充足 | 21 把单符号武器；`circuit_triple_echo` 几乎必达 |
| 覆盖 | ⚠️ 稀缺 | 仅 4 把 3 符号全在光系；**无一把武器内部跨元素**（75 把单元素 + 15 把无元素） |
| 状态 | ✅ 充足 | 55 个 status 符号格，五类齐全；W01/W02/W03 牌谱覆盖 |
| 破甲 | ✅ 但单一 | 15 把 `triple_pierce` + 战斧铸式；几乎只有"重武器三连"一种途径 |
| **防御/治疗** | ❌ **完全空白** | 武器符号池 0 个 shield/heal，90 把全 `role=damage`；`circuit_damage_shield` 在纯武器构筑下不可达 |
| 对子 | ⚠️ 中等偏弱 | 无"单武器自带一对"设计，主要靠双武器组合达成 |
| 元素反应(异色) | ⚠️ 中等 | 需 3 种有效元素，只能靠跨装备组合，无武器主动支撑 |
| 元素反应(冰火二重) | ⚠️ 仅 1 条 | `s02_frostfire_dual` 唯一跨元素牌谱 |
| 资源/金币/buff | ❌ 武器侧空白 | 仅靠技能 T01-T03 |

**空白优先级**：① 防御/治疗身份（最大）；② 跨元素/覆盖身份；③ 对子身份；④ 非三连破甲；⑤ 规则改变型机制武器。

## 7. 铭印命中 / 铸式命中叙事边界（须裁定，不删系统）

UI 刻意分段（正向）：`duel_controller._weapon_info()` 把"槽位锻造（换装继承）"与"武器专精（熟练/调律/横向铸式）"分开，测试强制校验。但发现 4 处事实偏差：

1. **校准命中未进建池（风险一，须复核）**：`reel_system.gd:901` 建池只加 `forge_style.hit_delta`，未加 `weapon_slots.hit_bonus(slot)`；面板 `weapon_hit_in_slot()` 两者都加。玩家选"校准+5%"面板显示上升，但转轮 MISS 格不减少。`weapon_slot_growth_test` 只比符号分布、未校验 MISS 格，故未覆盖。
2. **稳手文案数值过时**：`forge_style_system.gd:43` 写"82%→90%"，但 dagger 实际 hit_rate=0.86，应为 86%→94%（测试断言 0.94）。
3. **命中修正不可感知**：铸式 ±5% 在格数取整下常被吞掉，MISS 格变化为空。
4. **"命中"三重含义**：武器 hit_rate→MISS 格 / 敌人攻击命中帧 / 暴击三连判定，共用一个词。

**待裁定**：a) 校准命中是否应真正进入建池（统一两套路径）；b) 修正稳手文案；c) 为命中修正定义可感知最小格数保证；d) 文案区分三种"命中"。

## 8. S2 制作规格（草案，待确认）

### 8.1 内容实施原则
- **不按数量扩张，按机制密度扩张**：优先新增有机制价值的内容。
- 对 75 把换皮武器：不删除（保留资产），通过"符号结构微调 + signature 补齐 + 定位标签"渐进赋予差异，避免一次性大改。
- 优先补齐**防御/治疗**与**跨元素**两类空白（新增符号结构，而非改现有 90 把）。

### 8.2 武器身份标签规范
每把武器应登记：`engine_identity`（集中/覆盖/状态/破甲/防御/对子/元素反应）、`mechanism_summary`（1 句）、`advantage`/`cost`、`target_enemy`、`replace_relation`。当前 90 把全 `role=damage`，需补标签。

### 8.3 机制归属裁定
- special 符号与 signature 牌谱的机制归属须二选一并在文案中明确（建议：符号=触发器，牌谱=机制主体）。
- 遗留字段 `status_effect_type` 不参与新机制设计。

### 8.4 命中边界裁定
见 §7 待裁定 a~d；在裁定前不改命中机制、不删熟练/铭印。

## 9. 验收指标（草案）

- 武器差异化：每种引擎身份至少 1 把合格旗舰（防御身份当前空缺，需补）；独特结构武器占比从 ~17% 提升。
- 换皮率：A 级完全重复签名数量下降（目标：从 16 组降至个位数，通过结构微调而非删武器）。
- 定位覆盖：6 身份中防御/覆盖/对子从"空白/稀缺"变为"有合格候选"。
- 可解释性：玩家能从武器卡面说清"优势/代价/目标敌人/替换关系"。
- 回归：新增内容不破坏 G5 输出安全门、G1 奖励三合法卡、G2 换装预览一致性。
- 叙事边界：校准命中路径统一、稳手文案修正、命中术语分层（裁定后验证）。

## 11. 用户裁定（2026-11-20 审阅通过，最终口径）

> 本节为用户已批准的最终决策；与 §3~§9 审计原貌冲突处以本节为准。

### 11.1 聚类/换皮/空白
- 认可约 17 种符号结构、火系重复簇、防御/治疗空白、跨元素稀缺。
- "83%"统一表述为**符号结构重复度指标**：约 83% 武器以数值和权重差异为主、存在显著结构重复；不解释为"75 把都没有价值"。

### 11.2 旗舰候选裁定（三批准、三重立项）
| 身份 | 裁定 | 落地 |
|---|---|---|
| 集中＝绝对零度 | ✅ 通过 | 正式旗舰 |
| 状态＝冰霜枪 | ✅ 通过 | 正式旗舰 |
| 破甲＝蚀日之刃 | ✅ 通过 | 正式旗舰 |
| 覆盖＝晨曦之刃 | ❌ 不作为正式覆盖旗舰 | 保留为"**多符号/特殊符号**"原型（仅证明多符号结构，非跨元素） |
| 防御＝无候选 | ✅ 同意空缺 | 需制作**真正防御武器原型** |
| 对子＝圣辉长剑+破晓之弓 | ❌ 不作为对子旗舰 | 保留为"**指定武器组合**"原型（固定双武器牌谱，非对子赔付结构） |
| 覆盖 / 防御 / 对子 | 🔨 分别重立项 | 各制作一个**真正结构原型**，不用现有组合代替身份验证 |

### 11.3 命中边界裁定（a~d）
- **a. 校准必须进入真实建池**：这是已确认的功能错误，非数值偏好。面板与实际带必须读同一精度结果；补"校准后 MISS 格真实减少"测试。**作为 S2 内容实施前的独立正确性小步，不与武器改造混提交。**
- **b. 稳手文案立即修正**：82%→90% 改为 **86%→94%**；核对同卡其他数值文案，但不改铸式机制。
- **c. 不采用"所有 ±5% 强制至少变化一格"通用保证**（会在不同带长/双武器下产生隐藏取整补偿）。改为：①校准奖励仅在真实 MISS 格至少减少 1 格时出现；②卡面显示修正前后实际格数；③提交前验证，零变化则不消耗奖励；④固定铸式展示当前配装真实结果，不暗中补格。
- **d. 术语分三层**：`hit_rate`→UI 称"**武器精度**"（对应废铁率/MISS 格）；手动按停→"**目押停中/停中率**"；动画命中帧→内部"攻击命中帧"，不作为武器属性展示。三连与暴击继续独立术语，不并入"命中"。

### 11.4 S2 制作规格裁定
- **补空白但不增武器总数**：从 A 级完全重复簇中选少量武器改造，不新增第 91–96 把。首批 **3–6 把试点**：①一把防御武器（真实含伤害+护盾/治疗符号，使防御回路可达）；②一把跨元素武器（内部≥2 种有效元素）；③一把对子武器（双主符号结构，支持对子回路）；④其余仅验证明确空白，不为凑数扩范围。
- **机制归属**：special 符号=触发器，signature 牌谱=机制主体（按草案批准）。
- **元数据**：优先复用现有 `role`/`family_tags`/`unique_group`/`mechanism_summary`；`advantage/cost/target_enemy/replace_relation` 先进入设计矩阵，UI 确实消费时才新增资源字段。

### 11.5 验收指标裁定（分两层）
**本轮试点出口**（不作为全局目标）：
- 六种引擎身份各有一个真实可玩代表，覆盖/防御/对子不再用近似替代；
- 新防御武器能实际产生护盾或治疗并触发对应回路；
- 跨元素武器在真实转轮保留两种有效元素；
- 对子武器能通过对子回路形成非三连打法；
- 校准前面板、奖励预览、实际 MISS 格一致；
- 换装预览正确展示新增/失去的符号、元素和牌谱；
- G1 三合法卡、G2 仓库/换装、G5 输出安全门不回归；
- 不修改无关武器、不顺手调整全局敌人曲线。

**后续全局指标**（试点验证后再定目标值）：A 级重复组下降、独特结构占比提升。
