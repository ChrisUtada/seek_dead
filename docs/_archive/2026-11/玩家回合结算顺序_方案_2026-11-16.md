# 玩家攻击回合：结算展示顺序

> 2026-11-16 14:35。**顺序方案，待确认后再改代码。**

## 一、现在代码里的实际顺序

```
停轮（玩家按停：左 → 中 → 右）
  ↓
三格逐格闪（0.20s/格，只闪不出数）
  ↓ 停 0.25s
金币数字（若线上有金币格）
  ↓
护符闪 → 停 0.20s → 护盾数字 → 0.26s → 治疗数字
  ↓ 停 0.26s
护符闪 → 停 0.20s → 总伤害（敌人侧）
  ↓ 停 0.60s
```

**问题：数值出现的顺序和三格的读取顺序无关。**

代码是先按「符号 + 元素」分组聚合（`counts[sym|elem]`），再按护盾 / 治疗 / 伤害分阶段播报。
所以哪怕第 0 格是治疗、第 2 格是攻击，玩家也会先看到护盾、最后才看到伤害。

## 二、按你的意思应该是这样

```
① 停轮：列0 → 列1 → 列2（已实现）
        ↓
② 读格（左→右，每格一个节拍）
     格0 亮 → 若是治疗 / 护盾 / 增益 / 金币，当场出数
     格1 亮 → 同上
     格2 亮 → 同上
     （攻击类格子此时只闪、不出数，标记为「待合计」）
        ↓
③ 攻击合计
     所有攻击格「同时」亮起（视觉上区别于逐格闪）
     弹出一个总伤害数字
        ↓
④ 护符（不进转轮，单独一段）
     护符图标闪 → 停一拍 → 对应数值
        ↓
⑤ 收尾：底部短反馈 → 敌方回合
```

核心区别：

| | 现在 | 目标 |
|---|---|---|
| 数值顺序依据 | 按效果类型分组（盾 → 治疗 → 伤害） | **按格子从左到右** |
| 攻击 | 单独最后弹总数 | 不变，改为「几格一起亮」再弹总数 |
| 治疗 / 护盾 | 合并成一个数 | **按格子逐个出** |

## 三、可行性逐项

| 环节 | 可行性 | 说明 |
|---|---|---|
| ② 治疗 / 护盾按格顺序出数 | 需小改 | `contribute()` 里加 `source_heal` / `source_shield` 两个累加器（照抄 `source_dmg` 的写法）。同一来源的格子公式相同，按格数均分是**精确**的，不是估算 |
| ② 金币按格顺序 | 几乎不用改 | 金币已经是即时弹出 |
| ② 增益（buff） | 无数字 | buff 不产生飘字，只需格子亮 |
| ③ 攻击格一起亮 + 总伤害 | 改动小 | 已有 total，改成「攻击格集合同时脉冲」再弹总数 |
| ④ 护符闪 → 数值 | 已实现 | 第二步已完成 |

## 四、两个要你拍板的点

### 1. 同来源多格，分开出还是一起出？

```
情况：格0 和格1 都是同一个技能提供的「治疗」符号

方案甲（逐格）：格0 亮 → 治疗+4 ；格1 亮 → 治疗+4
方案乙（合并）：格0 亮 → 无数字 ；格1 亮 → 治疗+8
```

我倾向 **甲**：既然要「按读取顺序」，就该一格一个数。而且两格同源时数值本来就相等（公式相同），均分是精确的。

### 2. 混合回合的观感

```
格0 = 治疗，格2 = 攻击
  ↓
格0 亮 → 治疗+5      ← 先加血
格1 亮 → （无）
格2 亮 → （无，标记待合计）
攻击格一起亮 → 总伤害-24
```

这符合你说的「先出现治疗就先加治疗」，但代价是**伤害数字会比现在晚出现**（要等治疗播完）。

确认接受这个延迟吗？

## 六、已实施（2026-11-16 15:05）

采用最终方案：**分组依据是「接收方」，不是「效果类型」**。

```
⓪ 牌型横幅（若本回合凑成牌谱）
① 护符（防御类）闪 → 停一拍 → 它的护盾/治疗数字
② 读格：左 → 右，玩家侧收益格逐个亮起并出数（攻击格跳过）
②b 增益授予飘字（无格子归属，读完格后统一发）
③ 护符（伤害类）闪 → 停一拍
④ 攻击格「一起亮」→ 攻击动画 → 总伤害（数字在敌人身上，只出一次）
④b 元素爆发 / 克制核爆 / 状态提示
⑤ 底部短反馈 → 留白
```

### 架构改动：结算与表现彻底分离

`evaluate()` 现在只做两件事：

```gdscript
var counts := _phase_symbols(acc)
_phase_defense(acc)
_phase_counter(counts, acc)
_apply_patterns(acc)
_phase_attack(counts, acc)      # 全部结算完成，全程零飘字
await _present_turn(acc, counts)  # 统一回放
```

`_phase_defense` / `_phase_attack` 里的 `await`、飘字、血条刷新全部移除，改成 SQL 式的「只算不放」。
所有视觉集中到新的 `_present_turn(acc, counts)`。

### 新增的只读账本

| 键 | 用途 |
|---|---|
| `source_heal` / `source_shield` | 按来源累计治疗/护盾，供按格精确分配 |
| `charm_shield` / `charm_heal` | 护符涓流分量（不由任何格子提供，单独播报） |
| `gold_gain` / `total_damage` / `elem_tag` | 延后播报的数值 |
| `pending_player_pops` / `pending_enemy_pops` | 无格子归属的飘字（增益授予 / 元素爆发） |
| `pending_banners` | 牌型横幅 |

**结算口径完全没动**：`acc["shield"]`、`acc["heal"]`、`acc["dmg"]`、`total` 的计算一行未改，新增的全是旁路账本。

### 数值一致性保证

| 类型 | 分配方式 |
|---|---|
| 治疗 | 按来源均分 × 「真实入账 / 总治疗」缩放 → 各格之和 == 血条实际回血量 |
| 护盾 | 按来源均分，余数给最后一格 → 各格之和 == 总护盾 |
| 伤害 | 不分配，只出总数 |

### 节奏常量（`combat_system.gd`）

| 常量 | 值 | 含义 |
|---|---|---|
| `CELL_PRESENT_STEP` | 0.30 | 每格亮起 + 出数后的停留 |
| `CHARM_FLASH_HOLD` | 0.20 | 护符闪起 → 出数前的停顿 |
| `ATTACK_FLASH_HOLD` | 0.26 | 攻击格齐亮 → 总伤害出现前 |
| `POPUP_BEAT` | 0.26 | 连续飘字之间 |
| `TURN_TAIL_HOLD` | 0.60 | 播报结束到敌方回合 |

全攻击回合约 **1.4s**；混合回合（含治疗/护盾）约 **2.5~3.5s**。

- `play_cell_sweep` / `settle_cell_sweep` / `SWEEP_TO_NUMBERS_HOLD` / `_popup_gain` 已成为死代码，保留未删
