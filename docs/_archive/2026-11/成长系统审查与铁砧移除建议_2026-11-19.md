# Seek Dead · 成长系统审查与铁砧移除建议（2026-11-19）

> 视角：roguelike/roguelite 最佳实践 + 经典游戏对照。
> 目的：①审查现有成长系统是否合理；②论证"删除铁砧点数玩法"的可行性；③给出让游戏更好玩的重构方案。
> 前置：`成长系统完整归纳_2026-11-19.md`（现状全景）。

---

## 1. 一句话结论

**局内成长设计相当健康，问题集中在跨局层（铁砧 gacha）。**

- 局内（武器熟练/铭印、槽位、研磨锻魂、牌谱、技艺、三选一）invites 有意义的构筑决策，符合品类最佳实践；
- 铁砧 gacha 是典型的 **"meta power 反模式"**：用随机抽卡驱动跨局解锁，既稀释单局意义，又引入付费式挫败感；
- 建议：**删除铁砧点数与摇奖玩法，改为"解锁即内容"的纯粹 meta**（杀戮尖塔/Balatro 式的 variety-not-power）。

---

## 2. 行业最佳实践对照

### 2.1 四种跨局成长范式

| 范式 | 代表 | 做法 | 对本作启示 |
|---|---|---|---|
| **无 meta power，纯局内** | 杀戮尖塔、Balatro | 跨局只解锁新卡/新角色/新难度，从不加起始属性 | ✅ 最推荐：每局起点相同，靠构筑变强 |
| **meta power 是核心** | 哈迪斯、死亡细胞 | 镜中之夜/细胞升级永久变强 | ⚠️ 适合叙事驱动，需持续调平衡 |
| **gacha 式解锁** | 某些手游 roguelite | 抽卡解锁角色/装备 | ❌ 与 roguelike 的"公平随机构筑"冲突 |
| **无跨局，纯单局** | 传统 roguelike | 死亡即一切归零 | ⚠️ 硬核，留存压力大 |

### 2.2 关键设计原则（有据可查）

1. **"Meta as variety, not power"**：解锁更多选项，不解锁更强属性。
   - 杀戮尖塔明确拒绝 meta-power，Mega Crit 访谈意译：*"不想让 meta 变强，因为那会掏空单局的意义"*。
   - Balatro 最严格：第 1 局和第 200 局的初始筹码/倍率/手牌完全相同。
2. **Run integrity（单局完整性）**：第 1 局和第 100 局的难度应一致，否则：
   - 数值漂移→敌人被迫跟着涨→假难度；
   - 老玩家早期内容变无聊，新玩家 gap 拉大；
   - 单局不再是设计单元，而变成"攒下一局数值的踏脚石"。
3. **知识才是永久优势**：失败的一局应该教会玩家"更安全的路线/更强的组合"，而不是"没抽到卡所以弱"。
4. **解锁应选择权而非数值**：解锁新武器/新构筑，让每局更有趣，而不是更容易。

## 3. 现有成长系统审查

### 3.1 局内系统：✅ 合理，甚至优秀

| 系统 | 评价 | 理由 |
|---|---|---|
| 武器熟练 R1–R4 + 铭印 | ✅ | 局内攻击主轴，4 原型差异化候选，换装追赶机制完善——符合"构筑决策" |
| 槽位成长 | ✅ | 解决换装丢成长的问题，预算制防止无限叠加 |
| 研磨/锻魂 | ✅ | 换幕给确定性奖励，形成节奏曲线 |
| 牌谱 21 张 | ✅ | 构筑型成长，签名绑定专属武器（身份感强） |
| 三选一 + 重抽 | ✅ | 标准 roguelite 构筑流程，金币重抽是良性资源决策 |
| 技艺 15% 注入 | ⚠️ | 新机制，需真人验证频率手感 |

### 3.2 跨局系统：❌ 铁砧 gacha 是主要问题

**铁砧系统现状**：
- 房胜利获得点数（每局上限 40）→ 整备页花 10 点摇奖 → gacha 抽武器/护符/消耗品/技能 → 写入 `owned_*` 拥有池。
- 有保底（`anvil_pity`）、图鉴里程碑、重复转化补偿。

**为什么它不合理**：

| 问题 | 说明 |
|---|---|
| 1. gacha 违背构筑公平 | roguelike 的乐趣在于"用随机给定的牌打出最优解"；gacha 把随机性前置到 meta，玩家会抱怨"没抽到所以打不过"而非"我没构筑好" |
| 2. 点数 drip 稀释单局 | 每局结束攒点数，注意力从"这局怎么赢"转向"这局能攒多少点"——run integrity 被侵蚀 |
| 3. 随机解锁 ≠ 有趣 | gacha 解锁的是"选项"，但用随机方式给，玩家无法规划；杀戮尖塔的解锁是"达成条件即给"（可预期），体验更健康 |
| 4. 双随机叠加 | 局内三选一已经随机，meta 再 gacha 一层，挫败感叠加 |
| 5. 保底机制是补丁 | `anvil_pity` 的存在本身就说明基础体验有挫败感需要缓解 |

**注意**：铁砧承载的"跨局解锁新装备"功能本身是**有价值的**（扩大构筑空间），要删的是**点数+摇奖的 gacha 形式**，不是解锁本身。

## 4. 重构方案（三选一，需拍板）

### 方案 A：解锁即内容（强烈推荐，最小改动）

**核心**：删掉铁砧点数与摇奖界面，把解锁改为**达成条件自动解锁**（杀戮尖塔式）。

| 项 | 做法 |
|---|---|
| 删 | `anvil_points`、摇奖按钮、`anvil_pity`、铁砧 gacha 界面、`anvil_system.gd` 的摇奖逻辑 |
| 改 | 解锁触发：击败某 BOSS / 通关某幕 / 达成生涯成就 → 自动解锁对应武器/护符/技能 |
| 保留 | `owned_*` 拥有池、图鉴、铸式、生涯、里程碑——这些是"内容解锁"不是"数值加成" |
| 迁移 | 现有 `anvil_points` 按"1点=1解锁进度"折算，或直接清零重来（demo 阶段建议清零） |

**优点**：最符合品类最佳实践；玩家有明确目标（"打败 X 解锁 Y"）；无挫败感；改动集中在铁砧系统 + 解锁触发点。
**缺点**：失去"整备页摇奖"的仪式感（但这是可以用其他方式补的）。

### 方案 B：成就/任务驱动解锁（推荐，更有目标感）

**核心**：类似杀戮尖塔的"解锁条件"，每个内容绑定一个可展示的成就。

| 项 | 做法 |
|---|---|
| 解锁条件示例 | "用火焰剑通关 ACT1"→解锁新武器；"无伤击败 BOSS"→解锁护符；"凑出签名牌谱"→解锁技能 |
| UI | 图鉴里显示每个未解锁内容的条件（灰色卡片 + 条件文本），达成后解锁动画 |
| 保留 | 拥有池、图鉴、铸式、生涯 |

**优点**：解锁有故事感和目标感，引导玩家尝试不同打法；比纯 gacha 更有掌控感。
**缺点**：需要设计解锁条件表 + 条件检测逻辑（中等工作量）。

### 方案 C：纯 roguelike，完全无跨局解锁（最激进）

**核心**：所有内容开局全解锁，没有任何跨局成长。

**优点**：最纯粹的 roguelike，run integrity 最强，平衡最简单。
**缺点**：内容量必须足够大（本作 90 把武器，全解锁会导致选择瘫痪）；失去长期目标；留存压力大。
**适用**：如果目标是"硬核 roguelike"体验，且内容库足够大。

---

## 5. 我的推荐：方案 A + 方案 B 的融合

**推荐做法**：以方案 A 为骨架（删除 gacha），以方案 B 为解锁体验（成就驱动）。

```
删除：铁砧点数、摇奖、保底、gacha 界面
保留：owned_* 拥有池、图鉴、铸式、生涯、里程碑
新增：
  1. 解锁条件表（每个武器/护符/技能绑定一个成就条件）
  2. 图鉴 UI 显示未解锁内容的条件（灰色 + 条件文本）
  3. 达成即解锁 + 解锁动画/日志
  4. 新局 seed_default_owned 给基础 starter 套装（已有）
```

这样：
- ✅ 每局起点相同（run integrity）
- ✅ 跨局解锁是"选择权"不是"数值"（variety not power）
- ✅ 玩家有明确长期目标（成就条件）
- ✅ 无 gacha 挫败感
- ✅ 图鉴/铸式/生涯等已有跨局内容全部保留

## 6. 删除铁砧的影响面（代码层）

> 详细文件清单见 §7 代码索引。这里给决策层概览。

| 层面 | 涉及 | 处理 |
|---|---|---|
| 点数系统 | `anvil_points` / `anvil_pity` 存档字段 | 删除或迁移 |
| 摇奖逻辑 | `anvil_system.gd` 的 roll/pity/refund | 整个删除 |
| UI | `anvil_screen` / `anvil_cell` / 整备页入口 | 删除或改造为图鉴入口 |
| 结算发放 | `room_flow` 每房给点数 | 删除，改为成就进度 |
| 平衡配置 | `balance_config` 的铁砧常量 | 删除 |
| 解锁来源 | `meta_store` / `reward_system` / `shop_system` 写入 owned_* | **保留**（战利品/商店局内解锁仍有效） |
| 测试 | 约 12 个测试文件引用铁砧 | 适配 |

**关键区分**：删"铁砧 gacha"，**不删**"跨局解锁/图鉴/铸式/生涯"——后者是健康的内容解锁，只是换个触发方式。
