## 2. 最小制作流程（八步）

```text
① 内容 brief
   用途/定位一句话；属于哪条玩法路线（六身份之一或通用）。
② 优势 / 代价 / 构筑定位
   明写"强在哪、弱在哪、给谁用"；禁止只写泛用攻击乘区。
   若需要新战斗 hook → 先过 §3 门槛，否则本步改用现有 effect/hook。
③ 资源制作
   .tres 字段齐全；图标路径存在；mechanism_summary 写清机制与代价。
④ 静态校验
   content_lint（图标/枚举/命名）→ smoke_lint（数量/effect）→ item_taxonomy_test（语义/来源）。
⑤ 真实建池 / 结算验证
   不是".tres 能加载"就算过：用 loot_source_pool_test 确认进池；
   用 settle_loot_offer / 真实战斗路径确认结算生效、幂等、不重复授予。
⑥ 获取路径验证
   精英/商店/生涯定向/宝箱（默认关）中至少一条真实可得；
   确认图鉴 list_entries/detail_lines 列出并可读。
⑦ 基线与回归
   数量基线（export_resource_scan）、相关 smoke 与回归全绿。
⑧ 文档登记
   G0 台账 + 内容全览 + 本规范的版本记录；写明来源、代价、验证证据。
```

**收口标准**：八步缺一不可，尤其 ⑤⑥——静态加载通过不等于内容可用。

## 3. 新战斗 hook 准入门槛

未实现机制位（对子赔付 / 异色协奏 / 处决线 / 攻守转换 / 三连专属赔付等）**保持候选需求，不自动实施**。新增 hook 必须同时满足：

1. **明确玩法价值**：解决哪个已记录的构筑缺口（有规格/探针数据支撑，非"看起来缺"）；
2. **具体验收方案**：能写出"触发条件→预期结算数值→可复现测试"三段式；
3. **不重复造轮**：优先复用现有 effect/hook（13 种数值 hook + 回路系统 + 同源三连），确无落点才新增；
4. **复杂度可控**：新 hook 不得引入并行账本或绕过剥夺/封顶等既有纪律；
5. **独立评审**：与内容补齐分开，单次只做一个 hook 并带完整回归。

不满足任一条 → 不新增 hook，候选需求继续留在台账。
