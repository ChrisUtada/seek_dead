# Seek Dead · P0 完成后现状审查与 P1 范围建议（2026-11-19）

> 背景：用户已完成真人 F6 验收，暂未发现问题。建议先审查设计与代码现状，判断 P1 该补什么，
> 而不是直接扩大奖励池。本文基于实测数据 + 代码核查 + 行业实践。
> 结论先行：**P1 的首要任务不是"加更多奖励卡"，而是修复三选一的结构性失衡——
> 当前 600 张抽样卡里只有 2 个类别，设计中的 7 类实际只剩 3 类在生效。**

## 1. 实测数据（200 组 Draft / 600 张卡）

用诊断脚本读取当前 pool 并连续生成 200 组三选一，结果如下：

| 类别 | 设计权重(V1.1 §3.1) | 实际归一化权重 | 静态/动态候选数 | 600 张抽样中实际出现 |
|---|---:|---:|---:|---:|
| `symbol_mod` 符号改造 | 25% | **58.1%** | 6 静态 + 1 动态 = 7 | **400** |
| `rule_mod` 中奖规则 | 25% | —（0 候选） | **0** | **0** |
| `reel_control` 滚轴操控 | 15% | —（0 候选） | **0** | **0** |
| `weapon` 武器 | 12% | —（P0 关闭） | 0 | 0 |
| `skill` 技艺 | 8% | **18.6%** | 3 动态（技艺卡） | **200** |
| `survival_resource` 生存资源 | 10% | **23.3%** | 3 静态 | **0** ← 有权重但从不出现 |
| `signature` 签名 | 5% | —（P0 关闭） | 11 静态 | 0 |

**三个关键异常**：

1. **rule_mod（25%）与 reel_control（15%）完全消失**——零候选被归一化剔除，
   设计上占 40% 权重的两大"老虎机改造"方向，在 P0 里一行都不存在。
2. **survival_resource 有 23.3% 权重却 0 次出现**——这是生成逻辑 bug（见 §3），
   不是内容问题。
3. **实际生效的只有 symbol_mod + skill 两类**——600 张卡全是这两类，
   与策划案"改造老虎机的四个方向"严重不符。

| 模块 | 评价 | 说明 |
|---|---|---|
| 统一生成器 / 类别权重 / 槽位倾向 / 同质化 / Fallback | ✅ 健康 | 代码结构清晰，测试 21/0 + 20/0 |
| 技艺保底迁移 / 单一权威来源 | ✅ 健康 | p03 12/0，一次性保底语义正确 |

**所以 P1 不该推倒重来，而是补齐缺失环节。**

## 3. 根因诊断：为什么 survival 有权重却 0 出现

看 `_compose_by_slots()` 的槽位偏好（`draft_composer.gd:22-24`）：

```
Slot A 偏好: symbol_mod, rule_mod
Slot B 偏好: reel_control, skill, rule_mod
Slot C 偏好: symbol_mod, rule_mod, reel_control, skill, survival_resource
```

`_draw_for_slot()` 严格按偏好顺序抽，**第一个有候选的类别就被选中**：
- Slot A → symbol_mod（有 7 张）✅ 选中
- Slot B → reel_control（0）→ skill（有 3 张）✅ 选中
- Slot C → symbol_mod（还有 5 张，同类≤2 未超）✅ 又选中 symbol_mod

结果：**survival_resource 永远排不到**。`_draw_any()` 权重替补只在 `_draw_for_slot()` 返回 null 时触发，
但 symbol_mod 永远有候选，替补从不发生。

**这是槽位倾向的硬编码顺序问题**，不是类别权重的问题——category weights 的 23.3% 从未被使用过。

## 4. P1 该补什么（按优先级）

### P1-A：修复生成结构性失衡（最高优先级，非扩池）

这是**代码改造**，不需要新内容：

1. **让 `_draw_for_slot()` 真正使用归一化权重**，而不是硬编码偏好顺序。
   建议：Slot A/B 保留"核心/战术"倾向作为**软偏置**（如权重 ×1.5），
   最终仍按权重抽；或让 Slot C 强制从"未出现过的类别"里抽。
2. **保证同类 diversity**：同一组优先覆盖不同类别，而非 A/B/C 都能抽 symbol_mod 就全抽它。
3. **修复后实测**：600 张抽样应至少出现 4 个类别，survival 不再为 0。

> 这一项不做，加再多卡也会被槽位硬编码吃掉——**这是"先审查再扩池"的核心结论**。

### P1-B：补 rule_mod（中奖规则改造）的真实接口（内容+接口）

rule_mod 设计权重 25%，是"改造老虎机中奖收益"的核心，但当前**零候选**。
根因（问题整理 §问题5）：`pattern_effects` 静态读 `.tres` 参数，无运行时通用强化通道。

建议两种路线二选一：
- **路线 1（推荐，小改动）**：给 `pattern_data` 加一个 Run 级参数覆盖字典
  （类似 `run_symbol_bonus`），Resolver 新增 `pattern_bonus` Adapter 写这个字典，
  结算时 `pattern_effects` 优先读覆盖值。这样无需改 21 张签名卡。
- **路线 2**：为若干高频牌谱做静态变体 `.tres`（如"烈焰共鸣·强化版"），
  通过 `learn_signature` 类似机制授予。改动小但内容量大。

### P1-C：补 reel_control（滚轴操控）的真实接口（内容+接口）

reel_control 设计权重 15%，同样零候选。当前操控能力（吸附/宽判/废铁豁免）在技艺里，
与操控类别重复定义。

建议：把技艺里的 3 个操控类能力**拆成独立操控奖励**（复用现有接口，
通过 `pick_perk` 之外的 `reel_control_*` effect_id 授予到 controller 的对应字段），
技艺保留生存/运筹类。这样两个类别各有内容，且消除重复。

### P1-D：内容量补齐（最后做）

在 A/B/C 修好、实测类别分布合理后，再按规格 §15 的 MVP 数量补卡：
- symbol_mod 已有 7（够）
- survival 已有 3（可补到 4–6）
- rule_mod / reel_control 按 B/C 的接口补 4–6 项
- 技艺 8 项已够（F6 未发现问题，不要动频率）

## 5. 不建议现在做的事

| 不建议 | 理由 |
|---|---|
| 直接扩大奖励池数量 | 结构失衡下，新卡大概率也只进 symbol_mod，无法改善多样性 |
| 调整类别权重数值 | 权重本身没问题，是生成逻辑没用上（§3） |
| 改技艺出现频率 | F6 真人验收通过，没有证据表明需要改（规格 §30 也说先观察再调） |
| 删旧武器成长进 P3 | 安全门要求"新成长输出验证通过"——当前新成长只有两类在生效，远未达标 |
| 接入武器/签名类别 | P0 明确关闭，需先确认安全调用条件（规格 §24） |

## 7. 结论

**P1 的真问题不是"奖励不够多"，而是"设计中的七类实际只有两类在跑"。**

- P1-A 是必做的前置——否则扩池无效；
- P1-B/C 是"老虎机改造"核心玩法的补齐，需要少量接口改造（不是纯加卡）；
- P1-D 内容量补齐放最后；
- 技艺频率、旧成长删除都暂不动。

建议先拍板 P1-A 的具体修法（软偏置 vs 强制未出现类别），再进入实施。
