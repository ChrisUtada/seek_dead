# Seek Dead · 局内成长与战后三选一重构策划案 V1.2（审查重构稿）

> 日期：2026-11-19  
> 性质：对 V1.1 的专业审查与结构性重构，不是实施完成记录  
> 范围：局内成长、普通/精英战后三选一、武器替换及相关旧系统迁移  
> 约束：本稿只提出设计决策、内容契约和验收标准，不修改项目代码  
> 使用方式：§1—§3 是审查结论；§4—§12 可作为新的目标策划案独立阅读

---

## 1. 执行结论

V1.1 的北极星是对的：**玩家改造的是老虎机，而不是管理一套卡牌数值。**武器、符号、自动牌谱和滚轴操控的分层也有潜力。

但 V1.1 目前不宜直接作为实施与验收依据，原因不是措辞，而是六个结构性问题：

1. **类别权重合计为 94%，不是 100%。**
2. **“获得新武器”和“切换已拥有武器”被混为一谈。**后者主要是横向调配，不能独自承担主要纵向成长。
3. **“牌谱全解锁”与“三选一授予新组合规则”没有状态边界。**需要把固有牌谱与本局习得的规则模块分开。
4. **设计承诺超出当前武器模型。**当前武器没有“牌谱槽位数、随机/顺序滚轴模式”等通用参数，不能把这些写成既有底盘事实。
5. **旧系统删除会破坏关联内容。**熟练 R2 仍是铸式解锁条件，不能只写“彻底删除”而没有迁移方案。
6. **现状、目标、建议和已完成事项混写。**文内多处互相否定，且部分代码事实已经与 V1.1 不一致。

因此，本稿建议保留核心定位，但重做奖励契约、生成规则、内容启用门槛和迁移顺序。**先保证每个候选真实有效，再讨论出现率；先建立输出基线，再删除旧成长。**

### 2.3 对现有内容的专业判断

#### 武器：方向正确，但成长语义不成立

如果三选一只能换入仓库里已有的武器，它提供的是**构筑修正和路线转向**，不必然提供强度增长。把这类候选称为“主要变强来源”，会导致两个问题：

- 没有仓库候选时，武器类别直接消失，输出曲线更依赖随机仓库状态；
- 玩家可能拿到更顺手但更弱的武器，系统却把这次选择记为一次成长。

建议将 `weapon_acquire` 与 `weapon_swap` 分开。普通战后奖励可以两者都出现，但卡面、日志和遥测必须区分。

#### 技艺：不能用同义卡维持数量

守势与蓄能都是每房护盾，积蓄与回收都是每房金币。它们不是新的构筑方向，只是同一效果的不同数值版本。技艺池先保留五个真正不同的机制，比强行维持八项更健康。候选生成器本应能处理池缩小的状态，不能为了适配“每次必须给三项”而污染内容池。

#### 操控：数量少不是唯一问题，价值口径不统一才是问题

废铁改判提供战斗结果补救，废铁转化提供经济，缓速启动提供操作容错。三者分别对应输出、资源和操作辅助，不能只用同一个出现权重假定价值相等。尤其缓速如果只对部分玩家有价值，应通过 F6 判断它究竟应是奖励，还是辅助功能/武器特性。

#### 生存资源：不是次等奖励

治疗、护盾和金币不参与“中奖引擎”并不代表它们没有决策价值。问题只在于它们是否能在当前路线、血量和经济状态下改变玩家决策。将它们统一要求为“下一次 SPIN 可见”会错误地淘汰健康的风险对冲。

## 3. 本稿的关键设计决策

| 决策 | 推荐结论 |
|---|---|
| 核心定位 | 保留“改造老虎机”，但把生存资源明确放在引擎之外。 |
| 武器奖励 | 同时支持新武器获取与仓库换装，分开标记；不再把换装单独视为纵向成长。 |
| 牌谱 | 基础/签名牌谱仍是装备驱动的固有自动规则，不做参数升级卡。 |
| 三选一规则改造 | 改名为“规则模块/回路”，是本局习得状态，与固有牌谱分开；内容不足时权重为 0。 |
| 符号生态 | 新跨符号组合统一归规则模块，避免与符号改造重复。 |
| 类别权重 | 使用合计 100 的初始目标；它只是调参起点，不是验收玩家最终看到分布的唯一真值。 |
| 稀有度 | 类别内、合法候选内条件抽样；不为了凑 70/25/5 生成无效稀有卡。 |
| 保底 | 首版只保留“每组至少一个引擎改造”和“前三有效普通房一次技艺展示保护”。 |
| 技艺池 | 不为凑八项保留同义卡；空腰带过滤备用药剂。 |
| 幕间成长 | 暂时保留确定性锻魂，不能在新输出曲线验证前改成完全随机的三选一。 |
| 熟练/铭印 | 先迁移铸式与图鉴依赖，再移除局内重复数值轴；不做无迁移的直接删除。 |
| 规则触发上限 | 用内容规则限制递归与触发频率；绝不静默截断已获得的合法效果。 |

# 目标策划案

## 4. 设计北极星与原则

### 4.1 北极星

> **Seek Dead 的局内构筑，是围绕两把武器持续调整符号、习得少量规则模块并获得有限滚轴操控，让同一套 SPIN 操作在一局内逐渐形成不同的中奖引擎。**

“变强”可以来自新底盘、符号效能、组合规则和操作能力，也可以来自有代价的横向换向。**不要求所有成长都表现为大数字，但要求每个奖励都能兑现卡面承诺。**

### 4.2 五项原则

1. **真实有效**：候选生成时必须知道目标、数值、触发条件和当前是否有效。
2. **玩家可理解**：展示具体对象和前后变化，不用“增强构筑”“提高共鸣”等无兑现口径的抽象词。
3. **结果可归因**：触发时能看到来源；选完能在转轮、数值、规则列表或资源状态中复核。
4. **随机但可修正**：保留适应随机的空间，通过合法过滤、少量保护和付费重抽减少坏组合。
5. **一个主要决策入口**：普通/精英战后只要求玩家做一次主要成长选择，不再叠加额外的铭印欠选流程。

## 5. 系统边界与结算模型

### 5.1 系统对象与边界

| 对象 | 获得方式 | 职责 | 是否进入普通三选一 |
|---|---|---|---|
| 武器 Weapon | 开局、战后、Boss、探索、商店 | 基础效能、命中、暴击、符号池、元素与签名条件 | 是 |
| 符号改造 Symbol Mod | 战后 | 修改当前符号的权重或自身结算参数 | 是 |
| 固有牌谱 Pattern | 随装备与牌型自动判定 | 提供基础组合与武器签名效果 | 否 |
| 规则模块 Circuit | 本局三选一习得 | 增加有明确触发条件的全局结算监听 | 是，内容启用后 |
| 滚轴操控 Reel Control | 战后 | 有限改变落点、转速或废铁结果 | 是 |
| 技艺 Perk | 战后 | 少量非转轮生存/运筹辅助 | 是 |
| 生存资源 Supply | 战后及其他来源 | 治疗、护盾、金币等风险对冲 | 是 |
| 技能 Skill | 整备期选入 | 作为符号进入转轮并自动结算 | 否 |
| 消耗品 Consumable | 整备、商店、掉落 | 战斗中主动使用的一次性干预 | 否 |
| 护符/铸式 | 整备或特定奖励 | 开局策略与武器横向变体 | 不进入普通池 |

实现层当前用 `skill` 表示技艺类别时，可以在数据迁移前保留 ID，但策划与 UI 统一称“技艺”，避免与 `selected_skills` 混淆。

### 5.2 不再使用单一乘法公式描述整个游戏

概念流程改为：

```text
滚轴落点
  → 中奖符号的基础结算（武器基础效能 + 符号自身修正）
  → 固有牌谱与签名判定
  → 本局已习得规则模块按声明顺序响应
  → 敌方减伤、护盾、状态等实际战斗结算

滚轴操控主要影响“落点与过程”；生存资源位于引擎之外。
```

规则模块的默认约束：

- 同一事件只能触发自身一次，默认不能由自己的复制/重触发结果再次触发自身；
- 多模块按固定优先级和槽位顺序执行，结果可复现；
- 每张卡必须声明触发事件、目标、每 SPIN/回合/房间上限以及是否允许连锁；
- 获得后始终有效，不因表现条数过多而被截断；
- 同类飘字可以合并，完整明细进入战斗日志。

## 6. 战后三选一的职责与奖励来源

### 6.1 普通与精英战斗

战后三选一负责一次主要成长决策：

- 新武器获取或已有武器换装；
- 符号权重/效果改造；
- 规则模块；
- 滚轴操控；
- 技艺；
- 生存资源。

允许免费跳过，跳过不补偿金币或数值。跳过是合法策略，不应通过故意制造差选项强迫玩家拿奖励。

### 6.2 Boss 与幕间

- Boss 保留专属奖励流程，负责高潮、主题武器与信物，不用普通池稀释。
- 幕间锻魂在新曲线验收前保留确定性基础成长，避免关键强度完全依赖随机候选。
- 长期可把幕间奖励改为“定向武器淬炼”等可预览选择，但不能只改成普通随机 Draft 后直接删除旧数值。

### 6.3 商店、探索与消耗品

商店、探索、Boss 掉落可以继续使用各自来源表。技能与具体消耗品不进入普通三选一；普通生存池也不通过“随机给一件消耗品”绕开该决定。

## 7. 类别、权重与稀有度

### 7.1 初始类别目标

| 类别 | 初始目标 | 说明 |
|---|---:|---|
| symbol_mod | 34% | 包含具体符号权重与自身效果改造 |
| rule_mod | 12% | 预留；规则模块未达到启用条件时为 0 |
| reel_control | 16% | 一次性能力耗竭后自然退出并归一化 |
| weapon | 20% | 新武器与换装共享类别，但分别记录 |
| skill（技艺 perk） | 6% | 低频辅助，不是第二个主成长树 |
| survival_resource | 12% | 风险对冲与经济修正 |
| **合计** | **100%** | |

这些数值是**基础类别抽样参数**，不是“经过槽位偏置、多样性、保底、过滤之后，每张卡最终占比仍必须等于该数”的承诺。

当 `rule_mod` 未启用或任何类别无合法候选时，只在剩余类别间按原比例归一化。禁止为了维持 12% 而补入空效果卡。

### 7.2 规则模块的启用门槛

满足以下条件前，`rule_mod` 保持停用：

- 至少 6 个机制不同、已通过合法性过滤的模块；
- 至少覆盖 3 种触发事件，而不是同一模板的六个元素版本；
- 每个模块都有独立触发反馈、叠加上限和递归测试；
- 固定种子模拟证明存在合理触发频率，不是整局零触发；
- 玩家可以在构筑摘要中查看已习得模块。

### 7.3 稀有度

普通 Draft 使用 common/uncommon/rare 三档，初始条件概率为 70/25/5。其正确口径是：

1. 先得到合法类别；
2. 在该类别内先按稀有度目标抽取；
3. 若该稀有度没有合法候选，在**本类别现有稀有度间**归一化；
4. 再按具体卡权重抽取；
5. 精英来源可修改稀有度参数，Boss 不使用此表。

不得跨类别强行补稀有度，也不得把稀有度直接等同于绝对强度。稀有度可以代表机制复杂度、构筑影响范围或代价，不只是更大的数值。

70/25/5 的自动验收使用“各类别各 rarity 都有合法候选”的固定测试池；真实对局只记录最终分布并用于观察，不要求机械贴合。

## 8. Draft 生成契约

### 8.1 生成顺序

1. 固化本房快照与来源参数。
2. 生成全部合法动态候选，不先随机只注入一张符号卡或一张武器卡。
3. 过滤已拥有的一次性能力、重复 ID、满层、无目标、未解锁和当前零收益项。
4. 计算可用类别并归一化基础权重。
5. 逐槽按槽位软偏置与组内多样性抽类别。
6. 在类别内按稀有度和具体卡权重抽取。
7. 保证同类不超过 2，并避免无意义同族共现。
8. 若存在合法引擎候选，保证至少一张来自 weapon/symbol_mod/rule_mod/reel_control。
9. 应用技艺早期展示保护。
10. 最终逐项复核；不足三张时使用合法通用兜底，不允许静默缩成一两张。
11. 冻结具体武器、符号、数值和替换要求，再展示与记录日志。

### 8.2 硬约束与软约束

硬约束：

- 恰好三张、ID 不重复、每张都可结算；
- 不出现当前零收益项；
- 不出现已拥有的一次性能力；
- 至少一个引擎改造，除非整个引擎池确实耗竭；
- 武器卡展示具体对象，符号卡展示具体目标。

软约束：

- 同类最多两张；
- 槽位偏好；
- 组内类别多样性；
- 共现候选之间的价值差异。

软约束不能突破硬过滤，也不能为了多样性把无效卡重新放回池中。

### 8.3 通用兜底

通用兜底必须是真实、始终可用的效果，例如小额金币、下一房护盾、少量全局符号效能。兜底卡：

- 只在正常候选不足时注入；
- 有稳定独立 ID 和明确数值；
- 同样可结算、可记录、可重抽；
- 不伪装成稀有新机制；
- 兜底触发率本身是必须监控的健康指标。

### 8.4 保护机制

首版只保留两类：

1. **引擎覆盖**：每组尽量至少一个引擎改造，避免三张全是补给。
2. **技艺展示保护**：前三个有效普通奖励房内，若尚未自然展示技艺，则第三个有效房强制展示一次；重抽保持该保护。

短期 pity、洗牌袋、动态类别限幅和资源见底救济暂不叠加。只有遥测明确显示问题，且现有重抽无法解决时，才单独新增一种保护并重新验收分布。

### 8.5 重抽

- 整组重抽，首次 5 金，之后每次增加 5 金；
- 展示当前价格，余额不足不能支付；
- 保留本房来源、技艺保护和引擎覆盖要求；
- 若存在其他合法组合，付费重抽不得返回完全相同的三张；
- 重抽重新冻结具体候选，不能展示一个对象、结算另一个对象；
- 记录重抽前后组合，评估它是否真正提供了纠正能力。

## 9. 内容设计规范

### 9.1 武器：获取与换装双轨

#### 新武器获取 `weapon_acquire`

- 从当前幕、来源和解锁规则允许的武器池中抽取具体武器；
- 展示前确定品质与对象；
- 空槽直接装备，满槽进入替换预览；
- 获得后是否写入图鉴沿用现有获取规则，但不能在卡面上模糊其永久收藏影响；
- 是新内容与新底盘的主要来源。

#### 已有武器换装 `weapon_swap`

- 从已拥有且未装备武器中生成；
- 明确标注“仓库换装”，不伪装成新掉落；
- 主要承担构筑修正、元素应对与签名换向；
- 单独统计出现率和选择率，不与新武器混算。

#### 当前底盘展示字段

普通武器至少展示：

- 基础效能；
- 命中率/废铁占比；
- 三连暴击倍率；
- 符号及真实转轮格数差异；
- 元素与关键符号效果；
- 可获得或失去的固有牌谱/签名。

“符号槽位数、顺序滚轴、随机滚轴”等不是当前通用能力，不进入 MVP 承诺。若后续制作，应先做单武器原型，证明其决策与 UI 可读，再提升为武器通用维度。

#### 替换事务规则

- 玩家必须主动选择被替换的旧武器，取消不消耗奖励；
- 替换前显示新旧差异，不只显示名称；
- 旧武器离场后，其专属符号不再参与转轮；
- 以符号路径记录的改造默认保留但休眠，重新装备该符号来源时可再次生效；
- 不默认转移旧武器专属改造，也不暗中退款；
- 卡面与预览必须明确哪些效果会休眠、哪些槽位效果会继承；
- 替换成功后只结算一次，并重建转轮与可用牌谱预览。

### 9.2 符号改造：只改已有符号自身

合法方向：

- 权重改造：显示真实格数变化，无格数变化则不出现；
- 基础效能：伤害、治疗、护盾或状态层数等目标符号自身参数；
- 暴击/命中等：只能给实际读取该参数的符号；
- 符号转化/新增：后续内容，必须展示新增或移除的具体对象。

边界：

- 新增“A+B 触发额外结算”不再归入符号改造，而归规则模块；
- 全局 `run_power_bonus` 可作为内部数值通道，但卡面必须说清“所有符号”还是“目标符号”；
- 五张元素共鸣在未形成真实战斗或生成影响前，不作为正式稀有奖励上线；
- 不允许只写“燃烧增强”，必须写清每层、每次或每次触发的具体变化。

### 9.3 规则模块：少量、可追踪、非牌谱升级

规则模块是独立的本局获得物，建议最多装备 2 个；获得第三模块时必须明确替换，不能无限堆叠。

首批内容应优先使用可统一结算的事件，而不是直接开放任意“回到首位再触发”的通用递归语法。可原型化的方向示例：

| 模块方向 | 触发示例 | 必要限制 |
|---|---|---|
| 末符回响 | 有效中奖后，末位中奖符号追加一次部分效能 | 每 SPIN 一次，不能再触发回响 |
| 异元素协奏 | 同一有效结果包含两种指定不同元素 | 当前符号池确实可达成时才出现 |
| 状态转化 | 燃烧达到指定层数后，火系中奖部分转为穿透 | 每回合一次，明确转化比例 |
| 护盾联动 | 本次同时产生伤害与护盾时触发追加效果 | 只响应原始结算，不响应自身追加 |

这些只是内容 brief，不是免验收的直接制作清单。每个模块仍需确定真实事件点、数值、触发频率与视觉反馈。

禁止：

- 对固有牌谱做 `damage_mult +X` 一类隐藏参数升级；
- 给当前无法达成的组合发模块；
- 无上限重触发；
- 以自毁、扣血或占武器槽作为所有强模块的通用平衡手段；
- 因同时触发过多而在结算层丢弃效果。

### 9.4 滚轴操控：按价值类型验收

当前三张可作为测试池，但不视为最终定稿：

- 废铁改判：战斗补救，每房一次；
- 废铁转化：经济补偿，每回合一次；
- 缓速启动：操作容错，需要单独验证其奖励价值。

短期不再增加第三张废铁卡。后续扩充优先覆盖不同操作维度，如单轴锁定、有限重转或预览，但每种都要原型验证，不能以“更可控”为理由无限削弱随机性。

若缓速长期只被少数玩家选择，且强度模拟显示它不构成对等成长，应移为辅助选项、武器特性或与其他明确收益组合，而不是靠提高稀有度包装。

### 9.5 技艺：先保证差异，再考虑数量

首版以五个不同机制为健康基线：坚韧、守势、回春、备用药剂、积蓄。

- 蓄能不作为守势的简单缩小版长期共存；
- 回收不作为积蓄的同数值普通房版长期共存；
- 余裕若仍是满血金币，需要证明它与积蓄的决策差异，否则一并重做；
- 备用药剂在空腰带时过滤，或者改为明确“先获得一件消耗品再加次数”的复合卡，不能给零收益；
- 技艺不形成等级树，不增加第二套战后选择流程。

池少于八项不是缺陷。生成器必须正确应对合法池缩小，而不是迫使策划填充同义内容。

### 9.6 生存资源：明确使用时机

保留治疗、下一房护盾、金币等基础项，并满足：

- 满血不出现纯治疗；
- 护盾显示生效时机和是否可叠加；
- 金币显示准确数量，依赖当前经济 sinks 验证价值；
- 复活/保命不作为普通池常规填充，优先留给 Boss、特殊事件或高代价内容；
- 生存奖励的验收看“是否改变承伤、路线或消费决策”，不要求修改下次 SPIN。

## 10. 固有牌谱、技能、消耗品与铸式

### 10.1 固有牌谱

- 20 张现有资源继续作为装备驱动的自动规则库；
- “全解锁”指没有额外三选一习得门槛，不代表无条件生效；
- 基础牌谱按自身装备条件与牌型判定；
- 签名要求携带对应 key weapon 并满足牌型；
- 不提供牌谱经验、牌谱等级或参数强化卡；
- 规则模块不是第 21 张隐藏牌谱，而是本局获得、有数量上限、可在摘要查看的另一类状态。

### 10.2 技能与消耗品

- 技能在整备期选入并进入转轮，不进入普通三选一；
- 消耗品保持战斗中主动使用，不作为具体物品卡进入普通三选一；
- 技艺是被动辅助，与上述两者严格分词、分 UI、分遥测。

### 10.3 铸式与历史熟练

在移除局内熟练数值前，必须完成：

1. 新解锁条件设计，例如使用该武器完成指定场次、触发其签名或完成对应生涯条件；
2. 已解锁铸式与历史最高记录迁移；
3. 老存档已解锁内容不得回锁；
4. 图鉴不再展示失效的 R 等级口径；
5. 所有依赖 R2 的 UI、测试与解锁提示同步更新。

## 11. 旧系统迁移与安全门

| 旧系统 | 目标处理 | 前置条件 |
|---|---|---|
| 武器熟练 R1—R4 的局内数值与欠选 | 移除重复成长选择和数值叠加 | 新 Draft 输出曲线通过；铸式/图鉴迁移完成 |
| 武器铭印与槽位铭印 | 合并或移除重复数值轴，不保留两套同名系统 | 符号/武器奖励能覆盖对应决策，替换规则明确 |
| `run_power_bonus` | 可保留为内部共享数值通道，不保留独立成长树 | 卡面归属清晰，不能全局/单符号混写 |
| 幕间锻魂 | 当前保留确定性成长，后续再评估定向淬炼 | 替代方案能稳定支撑幕间强度 |
| 铁砧点数/gacha | 删除随机跨局抽取，改成就与条件解锁 | Boss 空池、精英奖励、局末奖励中的铁砧兜底全部有替代 |
| 旧 LootOffer | Boss/探索/商店暂保留独立来源规则 | 不因统一普通 Draft 而强迫所有奖励同池 |
| 牌谱参数覆盖 | 不作为正式奖励方向 | 兼容旧存档时明确清理或迁移 |

### 11.1 输出安全门

在删除旧局内数值前，用相同内容、相同 seed 集和相同敌人曲线比较旧/新版本：

- 各幕普通、精英、Boss 前的符号基础效能与预期 SPIN 输出；
- 转轮格数与目标符号概率，而不只看面板攻击；
- 规则触发率、武器替换率、空候选率和兜底率；
- 低输出分位局，防止平均值正常但坏局失去成长；
- 操作能力对滚轴结果的影响，自动模拟与真人 F6 分开报告。

初始建议门槛：新方案各幕中位输出不低于旧基线的 90%，低分位不出现不可恢复的断层，且普通奖励房不存在稳定零有效选择。具体上下限应在首轮基线采集后锁定，不能没有数据就宣称通过。

### 11.2 推荐实施顺序

1. 修正文档状态口径与候选有效性规则。
2. 完成生成器硬约束、动态候选和兜底测试。
3. 区分武器获取/换装，完成替换预览。
4. 处理零收益共鸣、空腰带技艺与同义技艺。
5. 扩充并验证符号内容；规则模块达到门槛后再启用类别。
6. 采集输出基线并进行真人 F6。
7. 通过安全门后，迁移铸式/图鉴并移除旧重复成长。
8. 最后处理铁砧及其所有奖励兜底引用。

## 12. 表现、遥测与验收

### 12.1 必要表现

每次选择后，玩家至少能在以下一处看到并复核变化：

- 转轮格数或符号构成；
- 武器对比与替换结果；
- 赔付、状态、护盾或治疗数字；
- 已习得规则/操控/技艺摘要；
- 金币与资源状态。

规则触发时显示模块名或统一图标。多个效果可以合并飘字，但日志必须能回答“这次结果为什么发生”。

### 12.2 遥测字段

每组 Draft 至少记录：

- run、房间、act、来源、draft_id、seed 或可复现标识；
- 三个候选的 ID、类别、稀有度、具体目标和共现组合；
- 过滤原因、兜底原因、保护触发、槽位偏置后的实际权重；
- 展示、选择、跳过、重抽前后组合与费用；
- 武器获取/换装、被替换对象、失去的签名与休眠改造；
- 选择时血量、金币、武器、符号和已拥有奖励快照；
- 规则模块后续触发次数与零触发情况；
- 结算失败及原因。

“选后 N 场收益变化”只能作为相关指标，必须同时记录后续其他选择和装备变化，不能把全部变化归因于一张卡。

### 12.3 生成器自动验收

- 任意正常状态恰好三张、无重复、全部可结算；
- 空池、单候选池、全满级、满血、空腰带、无仓库武器、操控耗尽等极端状态仍有合法结果；
- 引擎覆盖与技艺保护符合规则，重抽后仍成立；
- 付费重扣费正确，余额不足拒绝，相同组合禁止规则生效；
- 固定测试池中类别基础权重合计 100，稀有度条件抽样符合容差；
- 完整生成器另测最终分布，不与基础权重混为一项断言；
- 每种奖励至少一次真实 resolve，多效果奖励失败不能造成半结算；
- 规则递归、顺序与触发上限可复现；
- 已拥有、满层、零收益目标不会借兜底重新进入。

### 12.4 内容与体验验收

- 所有卡面承诺都有对应生产效果；没有“只加构筑分”的伪成长；
- 每个动态候选展示具体对象和真实变化；
- 符号权重卡的预览与真实转轮一致；
- 武器替换能看到新旧符号、牌谱和改造休眠差异；
- 没有合法奖励因反馈预算被截断；
- 真人能复述至少一个“我的引擎现在与开局有什么不同”；
- 玩家遇到不想要的三张时，能理解重抽价格与跳过后果；
- 操控奖励分别按输出、经济、操作容错评估，不共享一个模糊的“感知良好”结论。

### 12.5 数据判读

- pick-rate 的分母是实际展示次数，不是总对局数；
- 按阶段、构筑、血量、稀有度和共现候选分桶；
- 样本过少时只记录，不下平衡结论；
- 高于 80% 或低于 5% 可作为复查信号，但不是自动删除线；
- 胜率用于发现假设，不能单独证明某卡导致胜利；
- 优先修复零收益、不可理解和无法触发，再调整百分比与数值。

## 13. 仍需项目负责人确认的事项

本稿已给出推荐默认值；以下事项需要明确拍板后才能转为实施任务：

1. 普通 Draft 是否允许直接获得未装备的新武器，并与仓库换装并列？推荐允许。
2. 是否接受“固有牌谱”与“本局规则模块”的双层命名和最多 2 个模块上限？推荐接受。
3. 幕间锻魂是否在新曲线安全门前继续保留？推荐保留。
4. 是否同意技艺不强行维持 8 项，先移除同义与零收益候选？推荐同意。
5. 缓速启动最终定位是成长奖励还是操作辅助？推荐 F6 后按数据决定，不提前锁死。
6. 铸式的新解锁条件采用“使用次数”“签名触发”还是专属生涯成就？推荐按武器选择可验证的行为条件，并保留老存档解锁。

## 14. 一句话总结

> **武器提供真实底盘，符号提供基础结算，固有牌谱提供自动组合，规则模块提供少量本局改写；战后三选一负责让这些变化具体、有效、可比较、可归因。先消灭无效奖励与成长断层，再谈权重、稀有度和删除旧系统。**
