# 巡逻怪追逐玩家（需求 1）

> 2026-11-15。作者要求「巡逻怪应该主动追逐玩家」。  
> 口径：**警戒范围 5 格**——玩家进入 5 格内就追，否则沿原巡逻路线。

---

## 1. 做法

| 位置 | 改动 |
|---|---|
| `MapGrid.pursuit_step(grid, from, to, max_dist)` | 一次 BFS 同时回答「目标是否在 max_dist 步内」与「朝它走的第一步」；超距/不可达返回 -1 |
| `MapPatrol.ALERT_RANGE = 5` | 警戒范围常量 |
| `MapPatrol.next_cell(patrol, grid, player_cell)` | 在范围内走最短路一步（相邻时返回玩家格 = 接触），否则沿原环前进 |
| `MapPatrol.advance(...)` | 推进一格；若走回原路线上的格就同步 `path_index`，之后能继续巡逻 |
| `MapRuntime._advance_turn` | 用 `advance` 替换 `step` |
| `MapRuntime.patrol_preview/trap_preview` | 预告改用 `next_cell`，与实际行动**共用同一决策函数**，保证「预告 = 实际」 |

为什么是 5 格：距离够短能「把怪引到陷阱格再打」，够长能拉脱。无条件追逐会让怪一直贴脸，诱导只剩地形可用。

## 2. 暴露并修掉的两个真 bug

### 2.1 巡逻战不退场 → 无限接触

固定环时代，怪走到玩家格后下一回合会自己沿环走开，所以「接触 → 战斗 → 接触」不会连成串。
追逐之后怪永远朝玩家走，**赢下战斗它还在原地**，下一回合又贴上来。

修法：`resolve_battle()` 区分巡逻战与内容战。

```gdscript
if is_patrol:
    resolved_patrols[pid] = victory
    if victory:
        for p in patrols:
            if String(p["id"]) == pid:
                p["active"] = false      # 打赢就退场
else:
    battles[cell] = {...}                # 内容战仍按格去重
```

巡逻战单独用 `resolved_patrols`（key = 巡逻 id）去重：巡逻接触发生在玩家格上，用 cell 做 key 会把
「同一格先后两场巡逻战」误判成重复结算。`resolved_patrols` 同时纳入 `signature / to_dict / from_dict`。

### 2.2 存档只记 path_index → 恢复错位

追逐会让怪离开巡逻环，而 `to_dict` 只存 `path_index`，`from_dict` 用 `path[path_index]` 推位置 →
恢复后怪跳到环上别的格。修法：存实际 `cell`，旧存档没有 `cell` 时才退回用 `path_index`。

## 3. 测试口径随之调整

| 套件 | 原来 | 现在 |
|---|---|---|
| 第 55 套（巡逻） | 「12 回合 36 次预告 = 实际」含玩家移动 | 只在玩家不动时比较（追逐目标随玩家位置变，移动后对照是不公平的） |
| 第 55 套 | 「第 1/2 回合前进到路径第 N 格」 | 改为「实际 = 决策输出」；新增「玩家远离（>5 格）后回到沿环前进」 |
| 第 56 套（陷阱） | 用「沿环第 1/2 回合谁踩哪个陷阱」 | 加 `_rt(idle)`：把玩家放到所有怪警戒范围外，稳定复现沿环行为；追逐本身在第 55 套测 |
| 第 56 套 | 「玩家踩陷阱不进入战斗」 | 追逐下怪可能正好贴上来，改为「若有战斗，来源必须是巡逻而非陷阱」 |
| 第 57 套（路线） | 动态模拟三条路线走到 BOSS | **改为静态可达性**：主路 / 逐个避开精英 / 排除巡逻出生格后都必须仍可达 BOSS；诱导路线改验「本幕至少一条环经过陷阱」 |

第 57 套为什么改口径：追逐上线后「AI 能否走到 BOSS」取决于怪怎么动，那是 AI 能力，不是地图验收。
地图层的可判定形式是可达性——这也正好对应「巡逻不永久堵死 BOSS」这条既有约束。

## 4. 效果

实测（ACT I，玩家从起点沿主干走到 BOSS）：

```
step 0  player=58  p0@44 p1@39 p2@109
step 3  player=60  p0@59 p1@26 p2@96     ← p0 从 44 一路追到 59
step 8  player=63  p0@62 p1@40 p2@67     ← 始终差一步贴住
step 11 player=65  p0@64 p1@25 p2@65     ← p2 追到玩家格 → 接触 → 战斗 → p2 退场
step 13 player=66  p0@65 p1@39 p2@65:off
```

原来怪只会沿固定环巡逻，玩家走主干时完全遇不到 A 区的 p0；现在它会一路跟着，压力明显。

## 5. 仍未做（需求 2）

作者同时提的「每次进入非巡逻怪随机出现（位置与种类）」**没有在本轮做**。

现状：`board_config.map_seed = 20261110` 写死，内容格位置写在地形字符里，所以每局完全一样。

要做的话需要一次数据层重构：

1. `LAYOUT` 拆成「地形骨架（`#` / `.` / `D` / `S` / `B`）+ 内容配额」；
2. `generate()` 按配额把战斗/宝箱/商店/休整/事件/陷阱随机撒在可行走格上（种子控制，保留可复现）；
3. 落点变化后，第 50/57 套的「固定数量 + 固定落点」断言要改成「区间 + 可达性」；
4. 每局用随机种子（而不是写死 20261110）。

这是独立的一块，建议单独一轮做，避免和追逐的手感验证混在一起。
