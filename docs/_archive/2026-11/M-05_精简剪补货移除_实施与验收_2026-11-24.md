## 1. 删除范围与「为什么换装不能改货架」

生产主体在 **8132ffe** 落地，本轮不重复修改该逻辑：

- 删除的调用：`scripts/systems/shop_system.gd` 中 `on_shop_buy_replace_pressed()` 末尾的 `_ensure_trim_offer()`（含 `source == "camp"` 与 `"shop"` 两条路径共用的替换入口）。
- 删除的函数：`_ensure_trim_offer()`（原逻辑：货架无精简剪时，把最后一格覆盖为 `trim_scissors.tres`）。
- 删除的常量：`TRIM_ITEM_PATH := "res://resources/consumables/trim_scissors.tres"`（随函数一并移除）。
- 保留：营地 `StripTrimSystem` 的 `grant / trims_left / candidates / apply` 通道；消耗品自然池中的精简剪；价格与库存上限未改；抽取权重未改。

**为什么换装不能改货架**：换装是一次配装决策，不是补给事件。原实现无论来源是商店还是营地，只要货架无精简剪就把最后一格强制覆盖，导致：① 连续换装反复覆盖货架、破坏固定货架的可预测性；② 玩家没有购买精简剪的机会就被塞一件消耗品，与营地整理的职责重叠；③ 覆盖动作发生在购买路径内，等价于「换装免费附带补给」，绕过商店经济。因此换装路径必须只读自己的 offer，绝不回写 `shop_offers`。

## 3. 供给决策：**方案 C（接受随机供给）**

- 原注释「它是带子变胖的唯一解药，不能靠掉落运气」不再成立：strip_trim_system 已取消每幕免费次数，精简剪只作为 26 个消耗品之一在自然池出现。
- 本轮按用户拍板选择 **方案 C**：不做每幕首 roll 保底，不新增 `_ensure_trim_on_shelf`，不引入新的 RNG 隔离或商店占位规则；在基线 §4.3（用户工单称 §4.2）记明风险。
- 理由（主次）：**主因是不扩大消耗品系统重构**——保底会新增商店供给规则、RNG 隔离与货架占位逻辑，超出本次「只移除换装强制补货」的范围；「保底会让 A2 断言无法区分自然存在与换装补货」只是可测性层面的次要顾虑，且已由夹具（测试在 roll 后先移除自然池精简剪）解决。恢复任何形式的强制供给都等于以另一种方式复活原冲突。
- 营地入口不做次数 gating：`_start_linear_camp` 在算 `can_trim` 前已执行 `_trim.grant(1)`，`trims_left()` 恒 ≥ 1，0 次不可达；间歇态入口已有 `left > 0` gating（`battle_hud._refresh_trim_entry`），`entry_state()` 在 0 次时返回 `"used"`。详见 §7 复核更正。

## 7. 复核更正（2026-11-24，撤销 B3 无效 gating）

**结论**：3908c4d 加入的 `trims_left() > 0` 是恒真条件，无行为变化；已由 `ba5c60a`（`Revert "fix(ui): 营地精简按钮按 trims_left() gating"`）撤销。保留本节记录，不删改 §3 历史原文之外的既有证据。

**为什么 0 次不可达**：`duel_controller.gd::_start_linear_camp` 在算 `can_trim` 之前先执行 `_trim.grant(1)`（line 1566），紧接着才是 `var can_trim := ...`（line 1568）。因此在进入该判断时 `trims_left() = granted - used ≥ 1`，再加 `trims_left() > 0` 不可能改变结果。真正的「无候选」场景由 `not _trim.candidates().is_empty()` 覆盖，并在 false 时回收授予（`granted -= 1`）。

**为什么不需要 gating**：间歇态入口另走 `battle_hud._refresh_trim_entry()`，那里已有 `left > 0` 的条件；`StripTrimSystem.entry_state()` 在 0 次时返回 `"used"`，按钮显示「本幕已用」，不会出现「按钮亮着但显示剩余 0 次再拒绝」的状态。因此营地与间歇态两条路径都不缺次数判断。

**如何被引入与撤销**：上一轮复核把「营地 0 次仍亮按钮」误判为真实缺陷，在 3908c4d 给 `can_trim` 加了 `trims_left() > 0`；该提交 message 声称的「改前红 → 改后绿用例 g7b::_test_replace_keeps_shelf」实为误挂——g7b 新用例只验证换装不改写货架，完全不覆盖营地按钮 gating。本次复核纠正判断，执行 `git revert --no-edit 3908c4d` 并在 revert message 中写明误判原因；`can_trim` 回到 `not _trim.candidates().is_empty()`，未换成其他 gating 写法。生产行为不变，g7b / t0_camp / f09 / t15 与 55 步 run_smoke 保持全绿。
