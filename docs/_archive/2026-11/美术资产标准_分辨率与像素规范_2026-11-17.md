# Seek Dead · 美术资产标准：分辨率与像素规范（2026-11-17）

> 本文是本项目的**资产制作标准**（给美术/生成素材时按此执行）。所有数值来自实际配置与现有素材实测，非推断。
> 适用范围：战斗背景、UI 底图、图标、立绘等所有进游戏的位图素材。
> **分辨率口径已锁定**（用户 2026-11-17 拍板）：逻辑画布 480×270，窗口锁死 960×540（精确 2×）。不放开多档。

---

## 0. 一句话标准

**所有素材按 480×270 逻辑画布的 1:1 像素尺寸绘制，用 Nearest 采样，引擎在 960×540 窗口做精确 2× 整数放大。**

记住这条等式，就不会错：

```
素材像素尺寸 : 逻辑画布 = 1 : 1
屏幕显示 = 素材尺寸 × 2   （960×540 窗口下）
```

---

## 1. 分辨率与缩放（锁定口径）

| 项 | 值 | 来源 |
|---|---|---|
| 逻辑画布 | **480 × 270** | `project.godot:29-30` viewport_width/height |
| 窗口尺寸 | **960 × 540**（默认且最大） | `project.godot:31-32` window_*_override；`autoload/window_policy.gd` 的 `MAX_W=960/MAX_H=540` |
| 缩放倍率 | **精确 2×**（960÷480=2，540÷270=2，无小数） | 计算得出 |
| 缩放模式 | `canvas_items`，**非 integer** | `project.godot:33`；`window_policy.gd` 注释明确不用 integer |
| 纹理采样 | **Nearest**（`default_texture_filter=0`） | `project.godot:173` |
| 最小窗口 | 480×270（允许缩小到 1×，仍为整数倍） | `project.godot:34-35`、`window_policy.gd` |

### 为什么不把画布做成 960×540

- 960 画布 1:1 显示 = 每游戏像素占 2×2 屏幕像素，与现在 480→2× 放大**视觉完全等效**，清晰度零收益。
- 现有全部素材都是 480 基准（背景 480×270、底栏 480×74、图标 16/24/32px、立绘 16×16），改 960 画布要全部重画，成本极高。
- 对像素画而言，**锐利来自整数倍放大 + Nearest**，不是高分辨率渲染再缩小。缩小（下采样）反而破坏像素网格。

### 真正会模糊的情况（当前已规避）

1. 非整数倍缩放（如 480→900）：像素对不齐 → 当前锁 960 精确 2×，规避。
2. 线性采样（Linear）：会插值出灰边 → 当前全局 Nearest，规避。

> 若真机仍见到模糊：先查该素材的 `.import` 是否被单独设成 filter≠0，或窗口是否处于非 960×540 尺寸。不要因此改整个画布架构。

## 2. 背景素材规格（当前需求）

| 项 | 要求 |
|---|---|
| **尺寸** | **480 × 270 px**（逻辑尺寸，1:1）。参照 `assets/camp_bg.png`（480×270，整备界面在用） |
| 格式 | PNG，RGBA 或 RGB |
| 采样 | Nearest（继承全局，`.import` 不必单独设） |
| mipmaps | 关闭（`mipmaps/generate=false`），Godot 导入默认即关 |
| 压缩 | `compress/mode=0`（Lossless），与现有素材一致 |
| 放置层级 | 战斗 HUD 内，在纯色 `Bg` 之后、其他 HUD 元素之前 |
| 节点类型 | `TextureRect`（全屏锚点）或 `Sprite2D`（`position=(240,135)`），二选一 |

### 背景的美术要求：暗、低对比、给前景让路

战斗 HUD 有大量前景叠在背景上，背景必须"安静"：

| 屏幕区域 | 前景内容 | 背景要求 |
|---|---|---|
| 顶部 y≈0–40 | 顶栏（房间/回合/商店按钮） | 不放亮色/高对比细节 |
| 中部两侧 | 玩家面板 / 敌人面板 | 压暗、纹理简单 |
| 正中央 | 角色与敌人立绘（视觉焦点） | 最暗，避免与立绘抢眼 |
| 底部 y≈197–270 | 底带（已做好的 `bar_full.png`） | 会被完全盖住，可不画细节 |
| 全屏动态 | 飘字 / 横幅 / 粒子特效 | 背景不能太花，否则飘字读不清 |

**建议**：整体压暗，主色沿用深紫黑 `#161013` 系（接近当前纯色背景 `Color(0.086,0.051,0.074)`）。只做低对比墙面/地砖纹理、柔和暗部渐变；局部可有很弱的火把光晕/氛围色，但不要大面积亮块或高频纹理。

## 3. 各类素材的尺寸基准（实测现有分布）

| 素材类型 | 基准尺寸 | 实例 |
|---|---|---|
| 整屏背景 | 480 × 270 | `assets/camp_bg.png` |
| UI 底带 | 480 × 74 | `assets/ui/bar_full.png`（本轮重绘） |
| 槽位/九宫格框 | 32 × 32（margin 8） | `assets/ui/dark_ages/frames/slot_blue.png` |
| 图标（多规格并存） | 16 / 24 / 32 / 48 px | `assets/icons/16/`、`/32/`、`/48/`（项目有 359 张，四档并存） |
| 元素/状态小图 | 16 px | `assets/fx/` |
| 立绘 | 16 px 基准 | `assets/enemy.png`、`char.png` |
| 角色大图（菜单用） | 96 / 128 px | `assets/icons/96/`、`/128/` |

**原则**：新素材优先复用已有尺寸档位；图标保持 2 的幂或项目既有档位（16/32），避免引入 20px、24px 这类需要额外缩放的中间尺寸（24px 项目已有少量，非首选）。

## 4. 导入设置标准（所有位图统一）

新建 PNG 时 Godot 会自动生成 `.import`，确认以下值：

```ini
compress/mode=0            # Lossless，像素画不用有损
mipmaps/generate=false     # 关 mipmap，避免缩小采样
mipmaps/limit=-1
process/fix_alpha_border=true   # 修透明边缘渗色（bar_full 已开）
```

采样由全局 `project.godot:173 default_texture_filter=0`（Nearest）统一控制，**不要**在单张素材上另设 filter。

## 5. 与旧文档的关系（重要）

`docs/UI适配_缩放与字号方案_2026-11-17.md` 是一份**诊断/方案**文档，它推荐"去掉 960×540 上限、放开 3×/4×、integer 缩放"——这与当前**锁定 960×540** 的决定**冲突**，**不要**当标准执行。

本文（美术资产标准）才是当前口径：
- 逻辑画布 480×270 不变；
- 窗口锁死 960×540 精确 2×；
- Nearest 采样；
- 素材按逻辑尺寸 1:1 绘制。

旧文档仅保留其字体许可证、素材许可证调研部分（§4）作参考；其缩放方案部分（§0–§3、§5–§6）已不适用于当前锁定策略。

## 6. 新增背景的接入检查清单

- [ ] 图片为 480×270，PNG，Nearest，mipmaps 关，Lossless。
- [ ] 画面压暗、低对比，中央最暗，底带区域可不画细节。
- [ ] 素材放 `assets/` 下（背景类，参照 `camp_bg.png` 的位置）。
- [ ] 在 `battle_hud.tscn` 的 `Bg` 之后插入 `BattleBg`（TextureRect 全屏锚点 或 Sprite2D 居中 (240,135)）。
- [ ] 960×540 窗口截图确认：像素锐利、前景可读、无双线/遮挡。
- [ ] 若随房间/幕切换背景，走 `duel_controller` 按 room/act 切换 texture，不改画布尺寸。
