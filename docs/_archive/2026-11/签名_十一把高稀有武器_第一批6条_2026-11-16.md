## 2. 架构限制：「单件即解锁」做不到

方案 §6.2 给余烬长剑的方向是「单武器核心化」，但实现不了：

`find_signature()` 在**基础牌谱已经命中之后**才执行。如果 W01 因为只有一把火武器而没有解锁，
签名层根本不会被查询。

所以余烬长剑改成了「火伤 +35% + 燃烧 +2」（蓄燃路线），XML 注释里写明了这一点。

要让「单件即解锁」成立，得让基础牌谱的 `unlocked()` 也读签名 —— 那是架构改动，不是加个资源。

## 3. 签名冲突：加了层级裁决

铺量后立刻撞上一个问题：玩家带两把**都有签名**的武器时，只能生效一个。

第一版规则是「同 priority 按 id 升序」—— 纯属字典序偶然：

```
带 [绝对零度(epic), 冰霜枪(rare)]  →  SIG_W02_ICEGUN 胜（I < Z）
带 [蚀日之刃(epic), 夜幕镰刀(rare)] →  SIG_W05_ECLIPSE 胜
```

绝对零度那个是错的：**epic 武器的签名被 rare 抢了**。

修法：同 priority 时先比 `pattern_tier`：

```text
mastery(3) > epic_signature(2) > rare_signature(1) > 其它(0) > 再比 id
```

方案 §6.1 说「传说品质不自动获得更高优先级」—— 那指的是**不能凭品质压低别人的 priority**；
同 priority 的 tiebreak 用层级是合理的，否则谁生效纯看 id 字典序。

## 5. 过程中的三个坑

| 坑 | 现象 | 原因 |
|---|---|---|
| 签名全部不生效 | `pattern_signature` 为空 | 生成 tres 时 `key_paths` 拼路径**漏了 `.tres` 后缀**，与 loadout 的完整路径匹配不上 |
| J 组 W02 断言全红 | 期望霜冻 +2 实际 +3 | 测试装备里用了 `ice_gun`，而它现在带签名（frost_extra 3）——**给武器加签名会改变既有测试的基线** |
| 蚀日之刃 35% 断言失败 | 实际比例 0.60 | 测试假设 HP 50% 不算处决线，但签名把阈值提到了 **60%** —— 逻辑是对的，测试假设错了 |

第三个值得记：**签名改变的不只是"更强"，还包括触发条件的语义**，写断言时要把阈值一起算进去。
