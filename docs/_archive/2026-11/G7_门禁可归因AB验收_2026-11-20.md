## 1. 为什么之前的 G0 基线 B 无效，这次有效

| | G0 基线 B（p0_growth_baseline） | 本次 G7 门禁 A/B |
|---|---|---|
| 操作模型 | bot「任何有效符号即停」（弱） | tactical 完美目押 + 自动喝药 |
| ACT1 存活 | 0/40 通关，全死第 4–5 房 | 4/6 到达 ACT3 |
| 成长领取 | picks_mean 全 0（bot 从未领到成长） | boot 时直接注入成长状态（可归因） |
| 结论 | 无法量化成长贡献，门禁阻塞 | ✅ 成功量化 |

**关键修正①**：换用 tactical 策略让 bot 活过 ACT1。
**关键修正②**：成长在 boot 后直接注入（而非 bot 战斗中自由领取），确保组间差异只来自成长轴。

## 2. 四档定义与注入方式

| 档位 | 注入方式 | 验证状态 |
|---|---|---|
| no_growth | `mastery.enabled=false`，weapon_slots 无 forge | ✅ 注入确认 |
| forge | 每把武器 `weapon_slots.choose(slot,"forge")` ×2（FORGE_STEP=2 → +4 基础攻击） | ✅ 注入确认（forge=2×2） |
| tune | `mastery.imprints[path]["tune"]={sym:2}`（+2 权重） | ✅ 注入确认（fire_slash+2/dagger_slash+2） |
| mixed | forge + tune 都注入 | ✅ |

🔴 **踩坑记录**：最初把 forge 写进 `mastery.imprints[path]["forge"]`，但结算实际读
`weapon_slots.forge_bonus(slot)`（`mastery.forge_bonus` → `weapon_slots`），导致第一版 A/B 数据无效
（forge 反而 -3.8%）。修正为走 `weapon_slots.choose` 后数据才合理。已作废旧数据并重跑。

## 6. 结论与门禁状态

**✅ G7 可归因 A/B 四条门槛全部达标** → 方案 §4.1「G7 删除旧成长保持阻塞直到四条门槛达标」的**解除条件已满足**。

⚠️ 重要边界：
- 本次只证明"旧成长贡献可量化、新系统有独立支撑"，**不等于建议立即删除旧成长**。
- 门禁解除只是允许 G7-2（移除重复熟练/铭印/欠选和常规全局加伤入口）进入实施，
  具体删除仍需按 G7 迁移顺序 + 真人验收（方案 §4 门禁 + G5 安全门精神）。
- 锋铸 +20.9% 是显著贡献——删除时需用新系统（符号模板/回路/构筑）补足这部分强度，
  否则会重演 G6-1「精英去堆叠」的安全门失败。
