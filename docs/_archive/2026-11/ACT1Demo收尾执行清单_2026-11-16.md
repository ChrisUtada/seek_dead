## 1. 武器图标（12 把）· 最高优先

现状：白名单 14 把里只有 `fire_sword`、`flame_scimitar` 有图标，其余 12 把回落 emoji，是 demo 最直接的观感缺口。

**做法**：不按元素整批（那要做 75 把），只做 demo 需要的这 12 把；出图 → `tools/prep_weapon_icon.py --degreen` → 32px 格子图 `tools/make_weapon_cell_icons.py`。
**通用验收**：48×48 母版可读 / 主轴 -45°±15 / meanL 42-88 / 无手无布缠 / 元素色粒子目视可见 / 清单同步。

**图标跟随规则（2026-11-16 定）**

> `*_slash` 永远跟随武器；其余伤害符号（`pistol_shot` / `bolt_shot` / `dawn_light` 等）**只在该武器只有它一个 `kind==damage` 符号时**才跟随。状态、buff、技能、精华一律不跟随。

依据：90 把武器里有 **16 把带 2 个伤害符号**（`dawn_blade` 的 `holy_slash`+`dawn_light`、`rune_repeater` 的 `pistol_shot`+`arrow_shot`、`abyss_scythe` 的 `shadow_slash`+`abyss_bite` 等）。若一律跟随，这两格会显示同一张武器图，但两格伤害不同——等于抹掉符号区分度，比不显示武器图标更糟。
实测结果：`pistol` / `armor_pierce_crossbow`（唯一伤害）→ 跟随；`dawn_blade` → 斩击跟随、光弹不跟随；`rune_repeater` → 两格都不跟随。实现见 `DuelController._symbol_follows_weapon()` + `_weapon_damage_count`。

## 1.7 物品图标（技能 / 护符 / 消耗品）· 2026-11-16 新增

背景：白名单 37 件物品里只有 3 件挂过图标（`recovery` / `guard_charm` / `heal_potion`，且是 16–24px 旧图），
其余全靠 emoji 回落。技能/护符/消耗品是整备与奖励页的主要视觉内容，需要正式图标。

**规格**：48×48（`ItemCard.set_art` 默认尺寸），路径 `assets/icons/items/icon_<id>.png`，96 母版存 `_source/`。
**风格**：与武器同一套「暗炭铁 + 旧金 + 元素色」，但**正面居中构图**（不是武器的 45° 斜置）。
**管线**：`prep_weapon_icon.py --degreen --target-l 66`（自动亮度归一到 66，实测同批跨度 33.8–134.8，手工调不现实）。
**🔴 红 / 熔岩类必须再加 `--warm-boost 150–165`**：全图 meanL 归一为照顾大面积暗玻璃，会把仅占 16% 的暖色也压平（实测 heal_potion 的"红液体"只有 (109,67,31)、亮度 75，是暗棕橙不是红）。warm-boost 对 R 主导像素**等比提亮**（三通道同乘一个系数），只提亮度不改色相。第一版曾把 R 顶到固定值、G/B 增幅递减，结果红色被推成橙色且丢层次，已废弃。
**绑定**：`ItemData.icon_tex` 已有字段；`SkillData` 继承 `LoadoutItem` 也已有 —— 只需往 `.tres` 写 `icon_tex = ExtResource(...)`，**无需改任何 UI 代码**（`card_factory` 用 `data.get("icon_tex")` 动态读）。
