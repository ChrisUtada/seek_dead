## 3. 看着像冗余、但绝对不能按引用删

| 类别 | 数量 | 为什么不能删 |
|---|---:|---|
| `assets/` 零引用资源 | 228 个（9.2 MB） | 存在**拼接路径**加载，例如 `weapon_icons.gd` 用 `"res://assets/icons/elements/%s.png" % e`。字符串引用扫描抓不到，删了会运行时崩 |
| `resources/` 零引用 `.tres` | 100 个 | 靠 `ResourceLoader.list_directory()` **目录扫描**动态加载（护符 / 消耗品 / 奖励池 / 协同），本来就没有字符串引用 |
| `.gd` 零路径引用 | 16 个 | 全部有 `class_name`，通过类名使用（实测 2–107 次）。例如 `ElementCounter` 用了 107 次、`LootSourceTable` 85 次 |
| `docs/mockups/current_map_design_ui.png` | 1 个 | 你给的「当前地图方案」设计稿 |
| 并行产物 3 个 | `docs/武器成长与BOSS换装解耦…md`、`docs/胜利掉落…md`、`tools/make_current_map_mockup.py` | 不是本轮产出的，按约定不入库、不删 |

## 4. 结论

- 真正能安全删的只有 **25 个**（一次性工具 + 零引用面板 + 两个死 gimmick + 临时目录）。
- 项目里「看起来冗余」的大头是 **228 个美术资源 + 100 个数据池 `.tres`**，它们靠约定路径 / 目录扫描加载，
  没法用引用计数判断，需要人工按内容判断（比如整批已废弃的角色帧动画）。
- 如果你要清 artwork，我建议按目录整批确认（例如 `assets/characters/char/` 整套 30 帧），
  而不是按引用计数删单张 —— 单张删了很可能在某个动画序列里缺帧。
