# 修复：战斗（以及宝箱/神龛/商店/休整）结束后回不到地图

> 2026-11-14。作者试玩报「战斗结束后没有回到地图上继续探索」。  
> 根因一处：`BoardSystem.return_to_board()` 是空实现。全量回归见
> `docs/baseline/2026-11-14_smoke_57_return/`。

---

## 1. 根因

`scripts/board/board_system.gd`：

```gdscript
func return_to_board() -> void:
	pass
```

单路径收敛（`163c258`）重写门面时，这个函数被写成了空壳。它是**所有非战斗流程的返回出口**：

| 调用点 | 场景 |
|---|---|
| `room_flow._after_victory()` | 战斗胜利后 |
| `room_flow.advance_act()` | 幕 BOSS 通关切下一幕 |
| `duel_controller._board_treasure()` | 宝箱结算后 |
| `duel_controller._board_shrine()` | 神龛结算后 |
| `duel_controller._board_armory*()` | 武器藏库选完 / 放弃 |
| `duel_controller._board_weapon/charm()` | 装备格落地 |
| `duel_controller._board_shop()` | 离开商店 |
| `duel_controller._board_rest()` | 休整完 |
| `duel_controller.board.set_feedback` 路径 | 起点提示等兜底 |

所以不止战斗——**任何非战斗节点走完都停在结算界面**，只是战斗最容易被先碰到。

## 2. 修法

恢复收敛前的实现（去掉已不再需要的 `grid_mode` 判断）：

```gdscript
func return_to_board() -> void:
	note_battle_won()
	_ctrl.game_state = _ctrl.FlowState.PLAYING
	_ctrl.in_interroom = false
	_ctrl.hud.set_interroom_enabled(false)
	_ctrl.hud.show_board_screen(self)
```

幂等：重复调用只是再展示一次棋盘。战败不走这里（走局末收口）。

## 3. 诊断时差点误判的两件事

1. **`node_mode` 与开局路径**：直接 `board.generate()` + `show_board()` 会让 `node_mode` 仍是
   `false`，胜利后 `_after_victory()` 走线性分支（`enter_interroom`），看起来像「也回不去」。
   真实开局必须走 `loadout_system.confirm_loadout()` → `full_reset()`，那里才置 `node_mode`
   并 `show_board_screen`。
2. **`_is_run_final()` 的误判**：`node_mode=false` 时它按 `room_index >= ROOMS.size()-1` 判断，
   地图节点的 `battle_index=5` 在 6 房线性表里正好是最后一房 → 直接进「整局通关结算」。
   这也是为什么第 56 套原先那条链看起来「进了战斗但回不去」——测试环境与产品路径不一致。

## 4. 回归防护

第 56 套 `board_ui_test` 从 87 项扩到 **95 项**，并把测试入口改成真实开战路径：

| 新增断言 | 拦的是什么 |
|---|---|
| 开战后进入地图模式（`node_mode`） | 开局没走 `full_reset` |
| 开战后地图可见 | 开局没展示棋盘 |
| **战斗胜利后回到地图** | `return_to_board` 空实现 |
| 回到地图后不在房间歇态 | `in_interroom` 没复位 |
| 回到地图后位置有效 / 当前格有 id | 棋盘状态没恢复 |
| **宝箱结算后回到地图** | 非战斗节点共用同一出口 |

## 6. 教训

这一类「空实现」在测试里最难发现：它不报错、不抛异常，只是**什么也不做**。
更麻烦的是，只要测试不经过真实入口（这里是 `full_reset`），就会连 `node_mode` 一起错，
把「空实现」伪装成「另一个模块的行为差异」。

以后凡是收敛 / 重写门面，应当对着旧实现逐个核对**有副作用的方法**是否都搬过来了，
而不是只看新方法签名还在。
