# 转轮凑牌重构 · Step 6b 触发演出与效果反馈（2026-11-15）

> 依据：拍板结论第 4 条 —— 「如果爽感不足，优先增强触发时的演出和效果反馈，而不是继续提高频率」  
> 状态：**第一版演出完成**（横幅 + 飘字 + 日志 + 伤害分解四层）

---

## 1. 为什么先做这个

W 的定位定成「中频高潮」之后，**频率就被锁死了**：3–5 回合一次，不能靠加密来制造爽感。

那么一次触发就必须足够有存在感。否则「每 4 回合亮一次、但玩家没注意到」= 白做。

所以这一轮只做一件事：**让触发被看见**。

## 2. 四层反馈

| 层 | 位置 | 内容 | 时长 |
|---|---|---|---|
| **横幅** | 屏幕中上（y ≈ 22%） | `🔥 W01 烈焰共鸣·余烬处决` | 淡入 0.14s → 停留 0.55s → 淡出 0.30s |
| **飘字** | 敌人立绘处 | 牌谱名 | 走既有 popup 机制 |
| **日志** | 战斗日志 | `🗂 武器牌谱 W01 烈焰共鸣·余烬处决` | 常驻 |
| **伤害分解** | Debug 日志 | `🔥 烈焰共鸣：火系伤害 +30%（+14）` | 常驻 |

横幅是这次新加的，其余三层原本就有。

## 3. 配色规则

| 类型 | 颜色 | 理由 |
|---|---|---|
| 武器牌谱 W（基础） | `POP_DAMAGE` 伤害红 | 它主要是伤害事件 |
| 武器牌谱 W（带签名） | `POP_GOLD` 金色 | 金色 = 稀有度感，与基础牌谱区分 |
| 技能术式 T01 增伤 | `POP_BUFF` 紫 | 增益语义 |
| 技能术式 T02 防御 | `POP_SHIELD` 蓝 | 护盾语义 |
| 技能术式 T03 恢复 | `POP_HEAL` 绿 | 治疗语义 |

用的是现有 `Palette` 常量，没有新增颜色 —— 牌谱不该在视觉上另开一套语言。

## 4. 实现细节

`battle_hud.show_pattern_banner(text, color)`：

- **动态创建** `PanelContainer + Label`，不进 `battle_hud.tscn`（避免为一条演出改场景文件）
- `mouse_filter = IGNORE`，不挡任何点击
- 新横幅出现时先 `queue_free` 旧横幅，避免快速连续触发时堆叠
- 用 `create_tween()` 做淡入/停留/淡出，最后自动 `queue_free`
- `is_inside_tree()` 为 false 时直接返回 —— headless 测试里不会因为 UI 缺失而崩

调用点在 `combat_system._apply_patterns()`，武器轨与技能轨各一处。

## 5. 测试

第 60 套 116 → **118 项**，新增两条：

| 断言 | 结果 |
|---|---|
| 牌谱触发时有横幅演出（`hud._pattern_banner` 非空） | ✅ |
| 横幅文本含牌谱 id（W01） | ✅ |

这两条能保证「演出被真的调用」，而不是只改了 HUD 却忘了接。

它测不到的是**观感** —— 字体大小、停留时长、位置是否合适，这些只能真机看。

## 6. 这一版明确没做的

| 项 | 说明 |
|---|---|
| 音效 | 项目里没有音效系统（grep 无 SFX 调用），做不了 |
| 卡牌飞入 / 组件连线动画 | 需要美术与更长的演出时序，会和「最后一列停下直接结算」的铁律抢时间 |
| 牌谱面板常驻展示（§9.1 两分区） | 属于「随时可见」而非「触发时可见」，是另一件事 |
| 签名专属演出 | 目前只靠金色横幅区分，没有独立表现 |

## 7. 真机需要确认的三件事

自动化测不出观感，建议实际跑一场看：

1. 横幅位置会不会挡住敌人意图 / 血量
2. 0.55s 停留是否够看清（BOSS 连续触发时会不会看不过来）
3. 金色（签名）与红色（基础）在像素风背景上是否够区分

如果不够，只调这三个参数即可 —— 不用动任何战斗逻辑。
