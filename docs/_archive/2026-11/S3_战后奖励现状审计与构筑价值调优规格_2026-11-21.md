## 2. 现状事实表：奖励有效性

### 2.1 零收益过滤链
- 生成侧只覆盖两类：符号权重灌注（`reward_system.gd:477-482`，达 MAX 或无格数变化跳过）、符号效果强化（`:525-537`，只 status/damage）、满血治疗（`draft_composer.gd:369-371`）、已拥有（`:357-359`）、无效定义（`:363-365`）。
- **缺口**：circuit/操控/pattern 重复只在结算期 preflight 拦截（`reward_resolver.gd:86-179`），会造成"展示了但选中报失败"。修正方向：**回路拥有状态加入生成侧过滤**，操控/技艺现有过滤继续保留，Resolver preflight 不删除（防御性保留）。
- `seed_edge_polish`（run_power_bonus）无上限（max_stack=-1）属实，但已拍板退出常规主池（S1-03），不再为其建设 max_stack，直接禁用主池卡。

### 2.2 兜底链（完备，不造假卡）
- 空池兜底 `_fallback`（`draft_composer.gd:76-77,426-431`，reason=`empty_eligible`，复用相同硬过滤）。
- 槽位级替补 `_draw_any`（`:209-213,276-287`）。
- 补足与缺口：`refilled`/`refill_shortfall`（`:88-104,116-117`）。
- 技艺保底：前 3 房 `SKILL_PITY_ROOMS=3`（`reward_system.gd:44-49`），trace `force_skill_replace`。
- 空类别权重移除与重归一（`category_resolver.gd:61-84`）。

### 2.3 重抽 / 去同组 / 跳过 / 失败
- 付费重抽：费用 `5+5×次数`（`draft_composer.gd:179-181`）；注释称免费优先但实际 draft 分支只有付费路径，`draft_free_rerolls` 字段存在但无调用点。
- 去同组：`compose_reroll` 重试 12 次（`:124-162`），仍相同则 `last_reroll_same_group=true`。
- 同类上限 `MAX_SAME_CATEGORY=2`（`:32`），多样性因子 1.5、槽位偏置 1.6。
- 跳过：`settle_loot_skip`（`reward_system.gd:834-859`），draft 分支 mark 技艺保底。
- 结算失败：preflight 失败不置 `_loot_settled`（`reward_system.gd:789-795`），可重试；武器槽满 `needs_replace` 属等待输入非失败。

## 3. 现状事实表：构筑覆盖与 S1 收敛

### 3.1 六身份构筑的可获得性
- 武器奖励仅两类通用卡：`weapon_swap`（本局仓库未装备的）/`weapon_acquire`（局外已解锁未拥有的）——结构上对任何构筑可用，不按身份硬编码。
- **事实瓶颈**：新档 STARTER_WEAPONS 只有 **4 把**（dagger/fire_sword/battle_axe/ice_staff，`meta_store.gd:69-76`），不含手枪、不含六身份武器；六身份武器能否作为奖励取决于局外收藏/本局仓库是否已持有。
- **处置边界（S3-0 评审）**：不默认把六身份武器加入 STARTER_WEAPONS。先证明商店、宝箱、精英/Boss 等路径能否获得，再决定是否调整初始收藏。
- `eligibility_rule` 当前只有 3 条（`""`/`not_full_hp`/`has_build_fire`），无按构筑身份锁死的规则；`min_sources` 属牌谱效果参数、非奖励 eligibility，不会锁死候选。**不存在"构筑被锁死无候选"的代码路径，但存在"新档六身份武器奖励可见性"瓶颈**。

### 3.2 S1 收敛项现状
- `run_power_bonus`（seed_edge_polish）**仍在常规主池**（`enabled=true`，category=symbol_mod），与 S1-03"退出常规主池"决议冲突。
- 替代通道已存在代码入口：幕间确定性基准 `growth_system.gd:133-146`（`grant_act_boon` 复用 `run_power_bonus`）+ 明确兜底；S3 需落地"退出常规主池"并回归 m1_reward_reach / reward_p2 / 战斗输出基线。
- 技艺 8%（8 项，前3房保底，被动辅助非第二成长树）；生存资源 10%（3 张，风险对冲），V1.2 目标曾提 12%。

## 6. 调优任务清单（按 S3-0 评审调整）

### 保留并优先执行
1. **禁用 seed_edge_polish**：落实 S1-03，保留幕间确定性基准与明确兜底；回归 m1_reward_reach / reward_p2 / 战斗输出基线。
2. **回路拥有状态加入生成侧过滤**：circuit 重复在生成侧过滤；操控/技艺现有过滤继续保留；Resolver preflight 不删除（防御性保留）。
3. **修正 Draft 展示分母**：区分来源，不能简单同时增加旧 `rewards_shown` 造成双计数（draft_shown 与 rewards_shown 分开记）。
4. **扩展 run JSON 与现有 S0 汇总器**：在 `tools/s0_run_aggregator.gd` 现有能力上补充展示、选择、构筑快照及回路实际触发贡献字段——是**扩展现有汇总字段与遥测落盘**，不是新建汇总层。

### 删除或改写
- **删除**"评估 seed_edge_polish 上限"：已拍板退出主池，不再建设 max_stack。
- **改写**"rule_mod 无禁用残留"→ **当前事实文档更新为上线后口径；历史实施记录保留原文并加注记**，不得篡改当时状态。
- **改写**"六身份加入新档"→ **先证明商店、宝箱、精英/Boss 等路径能否获得，不默认加入 STARTER_WEAPONS**。
- **改写**"实际贡献"：不写成奖励直接导致胜负；只记录选择后状态变化、后续触发和共现因素。

### 权重纪律
- S3-0 已锁六类活跃类别（signature 禁用），记录当前归一化基线（§1.1）。
- **S3-1/S3-2 完成前不改类别权重，也不调整新档初始武器。**
- 后续权重调整须是独立平衡任务，基于展示率、有效候选率与六身份适配结果单独评审，**不与文案统一混提交**。

### 不混入
S5 铁砧迁移（anvil_system.gd 等，仅点数发放与 reward_system 弱耦合，不进 Draft 池）。

### 实施顺序
```
S3-0 修正规格事实与历史文档口径（本轮）
→ S3-1 禁用攻击研磨 + 回路生成侧拥有过滤（正确性小步）
```
