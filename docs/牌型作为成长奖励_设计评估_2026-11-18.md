# 牌型作为成长奖励｜设计评估与最佳实践

> 日期：2026-11-18
> 性质：设计评审文档（**未改代码**）
> 触发：用户提议「牌型变成成长的一部分，没获得牌型前凑牌无效，获得后才解锁」
> 依据：源码核实 `pattern_data.gd` / `pattern_system.gd` / `combat_system.gd` / `resources/patterns/`

---

## 1. 结论先行

**方向合理，但不能一刀切。** 牌型解锁机制**当前已经存在**，只是解锁来源不同。真正的增量价值在于
**把 11 张签名牌谱（rare/epic signature）做成战后三选一的解锁奖励**——这是投入产出比最高、
且最契合刚完成的构筑奖励系统的做法。通用牌型绝不能锁，基础装备牌谱不应叠加第二道门槛。

---

## 2. 现状核实（代码事实）

### 2.1 牌型分三类，解锁语义已存在

`PatternData.kind` = `universal | equipment`（`pattern_data.gd:16`），
`unlocked(loadout_paths, tag_of)` 按构筑判定是否可用（`pattern_data.gd:60+`）。

| 类别 | 资源 | 数量 | 当前解锁方式 | 凑牌行为 |
|---|---|---|---|---|
| **通用牌型** G01–G03 | 硬编码 `pattern_matcher.gd:21-23` | 3 | 无门槛，`is_universal()` 恒可用 | 人人可凑，永远有效 |
| **基础装备牌谱** | W01–06 / T01–03 | 9 | `unlock_paths / unlock_tags / unlock_count`，靠携带装备自动解锁 | 带对装备即可凑 |
| **签名牌谱** | `sig_*.tres` | 11 | 基础牌谱 + `key_paths` 关键武器在装备里 | 带关键武器才生效 |

- 签名 11 张：6 张 epic（absolute_zero / eclipse / flame_staff / glacier / holy_sword / night_scythe）
  + 5 张 rare（ember_sword / exec_axe / fire_sword / ice_gun / plague_reaper）。
- 调用链：`combat_system.gd:380` → `_pattern_system.unlocked_patterns(loadout, tag_of)` 每回合按当前构筑重算；
  `resolve_equipment()` 从命中里选一条生效（`:71`），`resolve_universal()` 通用牌全部返回（`:88`）。
- 签名专属 `find_signature(base_id, loadout, cards)`（`pattern_system.gd:99`）。

### 2.2 对提议的事实修正

提议「没获得牌型之前凑牌无效，获得后才解锁」——**这个逻辑已存在，只是"获得"=携带装备，不是抽到卡**。
所以这不是从零设计，而是**给现有解锁系统增加一个 OR 来源**：`已携带装备 ∨ 已通过奖励习得`。
改动点小：`unlocked_patterns()` / `find_signature()` 多接收一个"已习得集合"参数。

## 3. 合理性评估

### 3.1 合理的部分 ✅

1. **给构筑成长增加"知识/图纸"维度**：从"我带了什么"扩展到"我学会了什么"，长线成长多一条轴。
2. **填补三选一的 Build 类空缺**：当前 5 张种子卡里几乎没有真正的"改变玩法"卡（火焰共鸣算半个）。
   签名解锁卡天然是 Build 类——它解锁一套新的凑牌打法，而非加数值。
3. **契合 BuildState 系统**：签名可按元素/武器标签出现在对应构筑的三选一里，与 P3 火焰推导天然联动。
4. **签名本身就是高稀有构筑内容**：做成成长奖励符合它的身份。

### 3.2 两个必须避开的坑 🔴

**坑 1：通用牌型 G01–G03 绝不能锁。**
它们是保底可玩性——玩家开局没有任何装备时，凑牌至少要有基础反馈。
若连它们都锁，前几房转轮纯粹空转，直接违背用户拍板的"数值爆炸爽感"。**这层必须永远开放。**

**坑 2：双重门槛（double gating）会让签名形同虚设。**
基础装备牌谱现在要"带对装备"才解锁，这本身已是构筑决策。若再加"三选一抽到图纸"，
变成**既要带装备、又要抽到卡**——两个条件同时满足的概率大幅下降，玩家大概率整局都看不到签名生效。
这是典型的双重收费反模式。对签名尤其致命（签名还要求关键武器）。

---

## 4. 最佳实践：分层解锁

| 层 | 解锁方式 | 决策 | 理由 |
|---|---|---|---|
| 通用 G01–G03 | 永不锁 | 不动 | 保底可玩，凑牌永远有反馈 |
| 基础装备牌谱 W/T | 维持"携带装备解锁" | 不动 | 它本身就是构筑目标，再叠图纸门槛是重复收费 |
| **稀有/史诗签名（11 张）** | **改为三选一习得解锁** | ✅ 采纳提议 | 高稀有构筑内容，做成成长奖励符合身份，且填补 Build 类卡空缺 |

**关键：只动签名层。** 这样既有成长感，又不破坏现有战斗手感，也不踩双重门槛。

---

## 5. 推荐落地形态

**用"习得"语义，而不是"未获得就无效"：**

- 未习得的签名牌谱：**不进池**（玩家看不到，也不会"凑了个寂寞"），
  而不是"凑齐了但判定无效"——后者制造挫败，前者只是"还没解锁"。
- 三选一获得「XX 签名」→ 写入本局 `learned_signatures` 集合 →
  下次 `RunStateAnalyzer.capture()` 时纳入解锁集 → 之后可正常凑牌生效。
- UI 明确区分"未习得（灰）"与"已习得（亮）"，给玩家收集目标。
- 每局清零（本局成长），或按设计决定是否跨局（meta）——建议先本局，与现有三选一一致。

### 5.1 实现影响面（预估，未实施）

| 文件 | 变更 |
|---|---|
| `pattern_system.gd` | `unlocked_patterns()` / `find_signature()` 增加 learned 集合参数 |
| `combat_system.gd:380` | 传入 controller 的 `learned_signatures` |
| `duel_controller.gd` | 新增 `learned_signatures: Array[String]`，每局清零 |
| `reward_definition` / `reward_resolver` | 新增 `effect_id = "learn_signature"` 分支 |
| `resources/rewards/defs/` | 新增签名解锁卡（按元素/武器标签定向出现） |
| `resources/patterns/sig_*.tres` | 增加"是否为解锁奖励"标记（或由 Registry 按 tier 识别） |

### 5.2 与刚完成的三选一系统的对接

- 签名解锁卡是**理想的 Build 类种子卡**，可与 `seed_flame_resonance` 同类出现。
- 用 `build.fire` 等标签做定向：玩家已有火构筑时，火焰签名解锁卡权重上升。
- 效仿 `flame_affinity`：Resolver 写 `learned_signatures`，Analyzer 下次 capture 生效——
  与 P3 火焰构筑完全同构，实现风险低。

---

## 6. 一句话总结

**牌型做成长奖励，方向对；但只锁"签名"这 11 张，别碰通用牌型和基础牌谱。
用"未习得不进池"而非"凑牌无效"的语义，玩家永远不为没解锁的牌凑个寂寞。
这是投入产出比最高、且最契合现有构筑系统的做法。**
