## 1. 测前准备（5 分钟）

### 1.1 备份存档

导出的 Demo 与主工程共用同一用户目录，试玩会写入存档：

```text
%APPDATA%\Godot\app_userdata\Seek Dead Prototype\lobby_data.json
```

复制到桌面备份，复测结束后还原。

### 1.2 确认进入的是 Demo 模式

启动 `Seek Dead ACT1 Demo.exe` 后：

- 整备页武器池只有 Demo 白名单（约 14 把）；
- 进入战斗后 HUD 显示 `ACT I · 房 x/8`；
- 第 8 房是 BOSS，打完即「ACT1 试玩结束」。

若能看到三幕或大量武器，说明跑的是正式版预设，停止并回报。

### 1.3 不要按 F8

本版本带有 P1 目押可读性原型，默认 `control` 预设（与 F6 首测一致）。F8 会切到 `readable`（减速/预览/缓冲），**本次复测保持默认，不按 F8**，否则难度和目押数据无法与基线比较。

### 1.4 准备计时

每局从点击「开始/进入房间」起算，到通关或失败结算为止，记录分钟数。

## 2. 每局流程

1. 进入整备，**使用默认配装**（第 1 局必须；第 2–3 局也建议默认，便于对比）。
2. 确认武器、技能、护符与上一局相同，不摇铁砧、不花局外点数。
3. 开始计时，正常游玩，不刻意刷商店、不反复重开。
4. 每房结束记录：房型、回合数（大约即可）、是否掉血严重。
5. 遇到成长结算时，**按自己的真实想法选**，不要为了测试强行选某一类；记下选了什么。
6. BOSS 战记录：BOSS 名字、回合数、是否差点输、有没有死亡。
7. 结算后立刻填写本局答案（不要三局后凭记忆补）。
8. 回到整备，开始下一局。

> 中途死亡也算一局（第 2 题选 B/C/D），不要重开同一局补数据。

## 6. 判定规则

### 6.1 P0-1（难度）

**通过**（3 局中至少 2 局满足）：

- 23 = B，44 = B；
- 47 ≠ D（至少出现过一次「差点输」）；
- 14 = B，43 = B；
- 3 落在 B/C（12–20 分钟）。

**失败分支**：

| 现象 | 结论 | 动作 |
|---|---|---|
| 23 = C/D 或 44 = C/D | 调过头 | 按 `docs/P0-1_难度调优_2026-11-03.md` §6 回滚（先降 4 个 BOSS 的 atk） |
| 23/44 仍 = A，47 = D | 没调够 | 说明数值不是有效杠杆，转 P1-4 意图数值化 |
| 14/43 超窗 | 节奏问题 | 先查回合数来源，不继续堆数值 |

### 6.2 P0-2（成长）

**通过**（3 局中至少 2 局满足）：

- 38、39、42 至少两项 = A/B；
- 37 = A/B；
- 40 不集中在 A（太少）或 D（太多）。

**失败分支**：

| 现象 | 动作 |
|---|---|
| 38 仍 = C | 成长方向仍不可复述：补「打法建议」而不是再加数值 |
| 39 仍 = C | 变强感不足：对比幅度加大（把每转期望/实际带子写进卡片） |
| 42 仍 = C | 成长不影响打法：让技艺选择直接改变下一房策略 |
| 40 = A | 评估 Lv.3 增加一次小型成长（需单独立项） |
