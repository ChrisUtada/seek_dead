## 2. 门禁：Step 7 的前置条件

这是 Step 7 的执行内容，不是门禁；门禁在 Step 6 出口：真人能描述多种真实选择、至少一次主动改变打法、
没有强制换装/无答案局势/提示代替操作。

当前状态：

- Step 6 的样本（≥3 名测试者、旧口径对照 + 新样板）**尚未开始**；

- 因此现在启动 Step 7 会违反「通过后再扩展」，**本轮只做条件检查，不实现**。

## 3. 模型通用性审计（readability 是否只认叠甲）

### 3.1 已通用：查询的是控制器真实状态，不是机制名

`scripts/systems/readability_system.gd` 的局势判断只读下列通用字段：

| 局势 | 数据来源 | 是否机制专属 |
|---|---|---|
| 重击 | `enemy_intent.type == "heavy"` + `value` | 否 |
| 低血 | `player_hp / player_hp_max ≤ 40%` | 否 |
| 熔铸间隙 | `current_gimmick.recovery_window(_ctrl)` | 钩子通用，但目前只有 rust 实现 |
| 高甲 | `enemy_armor / enemy_armor_max` | 否 |
| 干扰 | `pending_jam_reel` / `pending_lock_reel` / `pending_chaos` / `pending_auto_stop` / `intent.data.purifiable` / `player_frost` / `player_status.poison` | 否 |
| 残血 | `enemy_hp / enemy_hp_max ≤ 25%` | 否 |
| 输出窗口 | 以上都不满足 | 否 |

对策查询同样只读带内符号与腰带消耗品（`_symbol_counter` / `_consumable_counter` / `_pierce_counter`），
不读 `current_gimmick` 的具体类名。**结论：核心判断没有写死叠甲。**

### 3.2 仍偏叠甲的四处

| 编号 | 位置 | 现状 | 影响 |
|---|---|---|---|
| G1 | `readability_system.gd:297` | 间隙文案固定为「熔铸间隙」「不新增叠甲/冻结」 | 其他机制实现 `recovery_window` 后文案会失真 |
| G2 | `boss_gimmick.gd:41` | 只有 `recovery_window()` 布尔钩子，没有「窗口名/窗口说明」 | 开合窗口只能落回「输出窗口」，玩家看不到「脆弱窗口」 |
| G3 | `resources/rooms/*.tres` | `mechanic_summary` 只有寒铁精英与冰封铁瓮两间有 | 新样板 HUD 没有机制摘要，反伤/开合/毒爆只能靠日志 |
| G4 | `tests/g7d_decision_test.gd` | 已测 jam、冻结；**未断言** lock / chaos / auto_stop / 毒层 / 元素翻转 | 扩展到非叠甲机制时缺定向回归 |

### 3.3 其他机制的现有可见性

- **毒层（酸蚀）**：HUD 已显示 `☣酸蚀×N`，达到爆炸阈值整行警示（`battle_hud.gd:1047-1057`）；
  readability 会给出「干扰 酸蚀」与清净药剂对策（有腰带时）。
- **锁轮/注废/乱权/夺轮**：`pending_*` 已进入「干扰」局势，并按类型显示名称。
- **元素翻转**（躁怒元素使 P2）：gimmick 主动刷新敌人元素栏（`bipolar_phase_gimmick.gd:63`），
  玩家能看到弱点变化；readability 不额外命名「阶段切换」。
- **反伤（碎裂石像鬼）**：只有开房日志与机制摘要（当前为空），readability 无对应局势；
  设计上「护盾同时挡重击与反弹」，但提示层没有把反弹列为压力。
- **开合窗口（茧居石雕）**：开合期护甲归零 + 强制重击，readability 会显示「重击 N」；
  护甲行因 `enemy_armor_max = 0` 隐藏，玩家看不到「甲已归零」这一输出窗口。

## 4. 候选样板（不同机制的精英 + BOSS）

计划要求「一个不同机制的精英和 BOSS」，且「逐个复用现有意图组件」。
按与叠甲的距离排序：

| 候选 | 类型 | 机制 | 与叠甲差异 | 现有意图复用 | 缺口 |
|---|---|---|---|---|---|
| 毒疫术士（ACT1 elite） | 精英 | `acid_bomb`：每回合挂毒 + 层数爆炸 | 时间压力 / 清净解 | attack / chaos / heavy / auto_stop（行为族 `elite_caster`） | 机制摘要、毒层/乱权/夺轮定向测试 |
| 碎裂石像鬼（ACT1 boss） | BOSS | `glass_cannon`：高攻低甲 + 受击反弹 | 反伤压力 / 护盾双挡 | attack / heavy | 反伤提示（摘要即可）、反弹定向测试 |
| 茧居石雕（ACT1 boss） | BOSS | `cocoon_cycle`：周期厚甲 + 开合窗口 + 回血 | 节奏窗口 | attack / heavy / jam | 窗口命名（G2）、摘要、窗口测试 |
| 酸蚀恶鬼（ACT1 boss） | BOSS | `acid_bomb`：毒层爆炸 | 同毒疫术士家族 | attack / heavy | 与精英同族，差异化较弱 |

**建议第一切片**：精英「毒疫术士」+ BOSS「碎裂石像鬼」。

- 两者都不是叠甲：一个考「解状态/速杀」，一个考「护盾挡反伤/抢杀」；
- 毒疫术士的行为族 `elite_caster` 自带 `chaos` / `auto_stop`，正好补上当前定向测试的空缺；
- 都不需要新意图资源，符合「逐个复用现有意图组件」；
- 都是 ACT1，ria 口径可与 Step 4/5 的寒铁精英（ria=4）和冰封铁瓮（ria=7）直接对照；
- 「茧居石雕」留作第二切片，用来验证 G2 窗口钩子；不建议第一步就做，避免同时改提示结构与新钩子。
