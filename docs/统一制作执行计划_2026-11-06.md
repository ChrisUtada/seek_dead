### 生成顺序

```text

→ 冻结本局棋盘并展示
```

### 怪物约束

- 普通、精英、BOSS 分池，只使用当前 ACT/Demo 合法内容。
- 避免同一路径连续重复同一敌人；重复主题必须有意图或课程关系。
- 难度由路径深度与既有 ria 规则决定，不按实际掷骰结果暗改。
- 不因玩家火系、冰系等构筑而连续安排针对性高抗怪。
- 精英显示核心机制，武器/护符和精英奖励在移动前可查看。
- 主题分布：尾路首战与 BOSS 同元素，共享段/中段相邻战斗不同元素，同路径两个精英不同元素；
  内容池不足时退回未用房间，保证不空置、不重复（见 `docs/G4_主题分布_2026-11-07.md`）。

### 装备约束

- 武器格与护符格在开局抽定，确认后不再随机。

## 13. 冻结、暂缓与关闭清单

| 项目 | 当前决定 | 重新评估条件 |
|---|---|---|
| 正常旋转消耗金币 | 不做 | 无；会制造死亡螺旋 |
| 永久无限 HP/攻击/武器成长 | 不做 | 与横向解锁目标冲突 |
| T13 每武器独立转轮 | 冻结 | 当前三列模型有实测不足 |
| T14 ROWS=2 | 冻结 | 单行可读性和决策不足有证据 |
| T16 主动锁定/抢击/更多按钮 | 冻结 | 目押与意图数据完成后专项评审 |
| 整备小老虎机 | 暂缓 | ACT1 成长收藏稳定，货币重新设计 |
| 身世/R4 原型专精/完整永久祝福 | 暂缓 | G6/G7 基础成立 |
| GAME+/难度契约/BOSS RUSH | 暂缓 | 完整三幕稳定后逐项立项 |
| 隐藏房/献祭/复杂随机事件 | 暂缓 | G4 基础随机和特殊格通过 |
| 多方向自由移动/回头/循环棋盘 | 不做进当前方案 | 需要全新探索玩法提案 |
| 全量武器小人化/90 套独立成长树 | 不做 | 保留图标与共享原型规则 |
| 转轮带 40% 攻击密度硬保证 | 关闭 | 只保留密度监测 |
| 独立首通奖励平行系统 | 关闭 | 由生涯成就承担 |
| 武器/护符/消耗品继续凑数量 | 关闭 | 只按明确 Build 缺口增补 |
| 已完成 BOSS/怪物立绘批量重绘 | 关闭 | 仅修具体实机问题 |

## 15. 每个任务的统一交付与停止条件

### 最小交付

1. 明确的范围外事项，避免顺手改平衡或其他系统。
2. 代码/资源、UI/tooltip、定向测试和必要实机截图。
3. 新机制验证同种子可复现；动画和展示不消耗全局 RNG。
4. `run_smoke.bat` 全绿；涉及成长、装备和存档时验证新老档。
5. 在本计划回写完成状态、测试证据、已知限制和下一步。
6. 独立、可回退的改动单元；是否提交和推送由用户确认。

### 标准命令

```bat
cmd //c "run_smoke.bat"
```

```bash
"/d/Godot/Godot_v4.7-stable_win64.exe/Godot_v4.7-stable_win64_console.exe" --headless --editor --path . --quit
```

棋盘试玩使用 `--board`；目押预设只在局间切换，详细协议沿用 P1 专项。

### 停止扩内容

出现以下任一情况，暂停下一阶段：

- 回归失败、奖励不可达、死升级、假选项或展示与结算不一致。
- 成长仍需多层弹窗，或棋盘移动比战斗决策更耗时。
- 玩家持续无法理解停轮、意图、双武器分工或本局成长。
- 骰子与随机持续压过路线选择，玩家觉得没有控制。
- 新装备只是换名换色，或新一局与上一局只有房间顺序不同。
- 收集仍主要依赖重复抽取，玩家说不出下一局目标。

## 16. 最终体验验收

完成 G5 时，玩家应能回答：

- “我为什么停中或失误，这一列的目标是什么？”
- “我的两把武器分别负责什么，共鸣和元素如何影响选择？”
- “这局我走了什么成长路线，在哪次选择后明显变强？”
- “我在棋盘上主动追逐了哪件装备，为什么选这条路线？”
- “这一局与上一局的地图、敌人或 Build 有什么不同？”
- “下一局我想解锁或尝试什么？”

以上回答比单纯增加房间、装备数量或永久属性更能证明本项目已经具备可玩、可探索、可收集和可重复游玩的完整闭环。
