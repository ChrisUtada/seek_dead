# 设计建议：去掉铁砧 + 怪物掉技能

> 2026-11-16 12:40。**纯设计咨询，未改动任何代码。**
> 所有「现状」结论均来自读代码与资源，未凭印象。

## 一、先明确铁砧现在到底在干什么

它不是「一个抽奖面板」这么简单，代码上同时承担 **4 个职责**：

| 职责 | 实现位置 | 说明 |
|---|---|---|
| **物品解锁引擎** | `anvil_system._anvil_grant_owned` → `meta.owned_*` | 铁砧是唯一能往 `owned_*` 写新条目的地方（除初始播种） |
| **可选池的闸门** | `loadout_system.owned_arr` | 整备屏 / 商店 / 奖励池都只读 `owned_*`，不在里面就**永远拿不到** |
| **点数出口** | `award_meta` + `roll_anvil` | 战斗产 `anvil_points`（普通 0 / 精英 3 / BOSS 5 / 真最终 8，每局上限 40），铁砧是唯一消耗口 |
| **图鉴进度** | `collection_milestones` + `anvil_pity` | 收集百分比里程碑、重复返还、保底计数 |

铁砧池 = **全部武器 + 护符(passive) + 技能**（排 BOSS 信物，信物只能 BOSS 掉）。

新档靠 `MetaStore.STARTER_WEAPONS` 等常量播种：**4 把武器 + 4 个护符 + 基础消耗品**。

## 二、直接删掉铁砧会怎样

| 后果 | 严重度 | 说明 |
|---|---|---|
| 新档只剩 4 武器 + 4 护符，其余**永远不可获得** | 🔴 致命 | 90 把武器 / 17 护符 / 40 技能里绝大多数变成死数据 |
| `anvil_points` 变死数据 | 🟡 中 | `award_meta` 还在产点，但没人花，UI 会显示一个永远用不掉的数字 |
| 图鉴里程碑失效 | 🟡 中 | `collection_milestones` 没有更新源 |
| 老档迁移风险 | 🟡 中 | 若删 `anvil_points` 字段，`load_meta` 的 defaults 变更会让老档读取异常 |

**结论：铁砧可以删，但必须先有一个替代的「物品解锁源」。** 否则不是去掉一个系统，而是砍掉整个收集循环。

## 三、想法 2 可行性：基础设施已经存在

这是最关键的一条 —— **「击败特定敌人 → 获得特定战利品」这套机制已经实现了**：

```gdscript
# room_data.gd
@export var boss_reward_weapons: Array[String] = []   # BOSS 战利品·主题武器池
@export var boss_relic_path: String = ""              # BOSS 战利品·专属信物
```

现有行为：BOSS 房结算时按 `boss_reward_weapons` 主题池发武器，按 `boss_relic_path` 发信物。

所以「怪物掉技能」不是从零造系统，而是 **给 RoomData 加一个 `boss_reward_skills` 字段**，复用同一套结算与 UI 路径。这是本方案里成本最低、风险最小的部分。

## 四、但有一个硬约束，必须正视

| 项 | 数值 | 来源 |
|---|---|---|
| 一局房间数 | **每幕 8 房**（5 普通 + 2 精英 + 1 boss），3 幕约 24 房 | `duel_controller.gd` T25 重排注释 |
| ACT1 敌人总数 | **20 个**（4 boss + 4 elite + 12 normal） | `resources/rooms/*.tres` |
| ACT1 单局遭遇 | 约 **8 个** | 同上 |
| ACT1 可用技能 | **31 个** | `act_min <= 1 <= act_max` |

这意味着：

1. **单局最多学到约 8 个技能**，且具体是哪些取决于随机刷到哪几个怪。
2. **技能库 31 个，但一局只遇到 8 个怪** → 想让玩家凑齐需要多局积累。
3. **这恰好天然就是 meta 进度** —— 和「去掉铁砧」互补：铁砧是随机 gacha，怪物学技能是有目标的解锁。

## 五、技能怎么挂到怪物身上：三种方案

### 方案 A · 只挂 BOSS（最保守）

```
13 个 boss × 各 1 技能 = 13 个技能有出处
ACT1 只有 4 个 boss → 单局最多学 1 个
```

- 优点：改动最小，Boss 战利品规格感强，和现有 `boss_reward_weapons` 完全同构
- 缺点：**技能供给太少**，8 房里只有 1 次学技能机会，玩家几乎感受不到这个系统

### 方案 B · 精英 + BOSS（推荐）

```
12 elite + 13 boss = 25 个技能有出处
ACT1 = 4 elite + 4 boss = 8 个载体 → 单局最多学 3 个（2 精英 + 1 boss）
```

- 优点：技能供给与「一局 8 房」匹配；精英战本来就该有独特回报；25/31 覆盖大部分技能
- 缺点：仍需给剩下的 6 个技能找去处（可留在商店 / 初始池）

### 方案 C · 全部敌人各挂 1 个（最激进）

```
61 个敌人 vs 40 个技能 → 技能不够分，需要扩技能库到 60+
```

- 优点：每个怪都有身份，「这只怪会什么」成为玩家记忆点
- 缺点：技能库要扩近一倍，且普通房也给技能会让技能贬值（普通房本该是资源战）

## 六、我建议的整体方案（两个想法合并成一个闭环）

```
去掉铁砧的「抽奖」
        ↓
技能解锁源  →  击败精英/BOSS → 从其技能槽「三选一」→ 写入 owned_skills
        ↓
武器解锁源  →  战斗内掉落 + 商店（已有）+ BOSS 主题掉落（已有，boss_reward_weapons）
        ↓
护符解锁源  →  商店（已有）+ BOSS 信物（已有，boss_relic_path）
        ↓
anvil_points → 直接删除，或改名并入金币
```

### 为什么用「三选一」而不是固定给 1 个

固定掉落的问题：玩家不知道会遇到哪只怪，**无法规划 build**。

三选一的处理：

```gdscript
# 概念示意，不是现有代码
room.skill_pool = [技能A, 技能B, 技能C]
击败后 → 奖励三选一（复用现有 reward_screen）
         ↓
已学会的自动跳过 / 或替换为金币
```

这样玩家仍然有「选择权」，但**选项由遇到的怪物决定** —— 既保留 roguelike 的随机性，又给了掌控感。

## 七、必须提前想清楚的 5 个风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| 1 | **首局空白** | 新档没有任何技能，第一局只有武器，单调 | 保留 2~3 个初始技能（`STARTER_SKILLS`） |
| 2 | **重复遭遇** | 刷到已学会技能的怪，奖励变空 | 三选一里已学的过滤；若全学会则改给金币/护符 |
| 3 | **构筑不可预期** | 玩家想要某技能但刷不到对应怪 | 商店作为兜底渠道保留（现有 `shop` 来源） |
| 4 | **技能贬值** | 如果普通房也掉技能，技能失去稀缺性 | 普通房不掉技能，只掉资源/金币 |
| 5 | **老档迁移** | 删除 `anvil_points` 字段会让老档默认值错位 | 保留字段但停用，或写一次性迁移脚本 |

## 八、分阶段落地（每阶段可独立验收）

| 阶段 | 内容 | 影响面 |
|---|---|---|
| **P1** | `RoomData` 加 `boss_reward_skills`；4 个 ACT1 boss 各配 1 个技能 | 2 个文件 + 4 个 .tres，不碰 UI |
| **P2** | 击败 BOSS 时复用 `reward_screen` 做三选一 | 复用现有奖励 UI |
| **P3** | 扩到精英（4 个 ACT1 elite 各配技能） | 纯数据 |
| **P4** | 删铁砧 UI 与 `roll_anvil`；`award_meta` 停用或改产金币 | 涉及 `anvil_screen` / `battle_hud` / `balance_config` |
| **P5** | 图鉴并入 `codex_system`（它本来就独立，不受铁砧删除影响） | 小幅 UI 收尾 |

**建议从 P1 开始** —— 不删任何东西，先让「BOSS 掉技能」跑起来。等它验证有效，再删铁砧。这样即使中途改主意，铁砧还在，可随时回退。

## 九、需要你决策的 5 个问题

1. **技能载体选 A / B / C 哪个？**（我推荐 B：精英 + BOSS）
2. **掉落形式**：固定给 1 个，还是三选一？（我推荐三选一）
3. **初始技能**：新档送几个？还是完全不送？
4. **`anvil_points` 怎么处理**：删除 / 改产金币 / 保留但停用？
5. **武器和护符的解锁源**：完全靠战斗内掉落+商店，还是也给怪物挂？

## 十、一句话结论

两个想法**不是独立的两件事，而是同一件事的两半**：

> 铁砧提供了「解锁」，但方式是随机 gacha；
> 怪物掉技能提供了「解锁」，方式是目标明确。
>
> 用后者替代前者，既解决了「想去掉铁砧」，
> 又给了技能一个比 gacha 更有说服力的出处。

技术上完全可行：`boss_reward_weapons` / `boss_relic_path` 已经证明了「击败特定敌人 → 获得特定战利品」这条路是通的，扩到技能只是加一个字段 + 复用现有奖励三选一。
