## 1. 为什么重新设计

旧棋盘的核心是“移动与推进”：骰子、逐格行走、巡猎者接近、分支前进。它解决的是路线推进，却没有充分服务当前游戏真正有辨识度的内容——转轮战斗、装备 Build、成长与收藏。

新的核心目标改为：

> **玩家根据扫雷线索判断风险，为了具体武器、护符和补给主动探索；通过战斗与成长形成 Build；准备好以后，自主选择挑战已经看见的 BOSS。**

扫雷不是“随机踩雷受罚”，而是“用信息推断装备路线的成本”。

### 1.1 新体验闭环

```text
看见 BOSS、精英与装备目标
→ 根据数字推断普通威胁分布
→ 选择探索路线
→ 战斗／拾取／商店／休整
→ 获得装备与成长，形成或调整 Build
→ 判断自己是否准备好
→ 继续探索或挑战 BOSS
→ 获得专属战利品并进入下一幕
```

### 1.2 一句话体验目标

玩家能够说：

> “我根据数字判断这里有威胁，但那件武器值得我承担这场战斗；现在我准备好挑战 BOSS 了。”

## 2. 旧方案废止与新方案对照

| 旧设计 | 新决定 |
|---|---|
| 常规 1D3 与剩余步数 | 删除，不再有骰子移动 |
| 巡猎者按时间接近 | 从基础方案移除，敌人位置固定，保证扫雷数字稳定 |
| 节点主要服务前进 | 节点主要服务装备探索与 Build 准备 |
| 精英/BOSS 作为尾路门槛 | 精英与 BOSS 从开局直接显示，精英可绕行，BOSS 可提前挑战 |
| 巡猎倒计时驱动压力 | 由生命、补给、路线和战斗成本形成压力 |
| 多层迷雾兼管敌人移动 | 迷雾只负责未知内容与探索记忆，不隐藏可预测规则 |
| 所有怪都有特色≈精英化 | 普通怪保留单一短特性；精英与 BOSS 保留更高层级 |
| 强制等到敌人回合展示技能 | 普通怪特性可在入场或首次受击时展示 |
| 唯一动态目标建议 | 标准模式提供局势与多个真实对策，不替玩家决定 |

后续制作不得把巡猎者、骰子或旧“前进/继续”流程重新混入本方案。若未来需要移动威胁，必须作为独立变体重新评审数字更新规则。

## 3. 核心设计规则

### 3.1 探索与战斗的关系

- 点击未知格即进入并揭示该格内容。
- 若是普通敌人，先显示战斗确认，再进入现有转轮战斗。
- 若是装备或补给，按节点规则直接获得、替换或折算。
- 若是精英，确认层展示其高品质奖励与核心机制。
- BOSS 确认层提供“继续探索”和“挑战 BOSS”，不会因误点强制开战。
- 所有节点只结算一次，不通过撤退、查看构筑或重新打开界面重复获得。

### 3.2 扫雷不是直接伤害

- 踩到敌人不会先扣血，不造成无预告惩罚。
- 数字只提供威胁信息，不产生额外伤害。
- 不设置“踩雷即战败”。
- 战斗结果仍由转轮、Build、消耗品和玩家操作决定。

### 3.3 玩家自主决定何时挑战 BOSS

- BOSS 从开局显示名称、位置、元素与核心机制。
- 不设置装备数量、地图完成率或收集率门票。
- 玩家可以提前挑战，也可以继续探索。
- 选择“继续探索”不消耗资源，不推进任何敌人，不惩罚玩家。
- BOSS 不根据玩家装备数量或探索率暗中提高 HP、攻击或抗性。

### 3.4 探索的奖励目标

玩家探索的主要目的依次为：

1. 武器与护符等 Build 核心；
2. 战后成长与武器熟练；
3. 消耗品、金币、商店和休整；
4. 图鉴、来源记录与生涯目标。

普通战斗本身不是唯一目标，装备与 Build 才是地图探索的主要驱动力。

## 4. 网格、数字与邻接规则

### 4.1 原型规模

ACT1 首版建议使用固定 **4×4、16 格**网格：

- 一屏完整展示；
- 起点与 BOSS 对角或明显分区；
- 1 个精英直接显示；
- 2 个武器目标、1 个护符目标作为首轮探索动机；
- 普通敌人、补给、商店/休整按固定模板布置；
- 不追求把旧 21 节点原样搬进新网格。

16 格是原型规模，不是后续所有幕必须沿用的常量。扩展前先验证战斗数与时长。

### 4.2 数字定义

- 数字表示该格**上下左右四个相邻格中的普通敌人数量**。
- 移动与数字都使用四方向，禁止移动四方向、数字八方向的口径冲突。
- 数字范围为 0–4。
- 精英与 BOSS 直接显示，不计入普通威胁数字。
- 已击败的普通敌人从后续数字中移除；显示状态应与实际威胁同步。
- 节点内容固定，数字只在敌人被击败后按明确规则更新，不因揭示或查看随机变化。

### 4.3 数字显示

- 未知格也能看到由已公开信息推导出的合法线索，具体可见范围由界面样板验证。
- 数字与格子图标分区，不能互相遮挡。
- 0 表示相邻没有普通敌人，不代表该格奖励为空。
- 不仅靠红/绿颜色表达数字含义，必须同时显示数字与 tooltip。
- 悬停数字时可高亮其四个相邻格，帮助理解范围。

### 4.4 生成约束

- 起点与起点首个可选格必须有安全或低风险选择。
- 至少一条路线能够通过数字推理，而不是强制 50/50。
- 精英、BOSS、关键装备不参与随机暗换。
- 同一种子生成相同敌人、装备、地形和数字。
- 揭示、撤回、查看构筑、进入 BOSS 确认层都不能重抽。
- 首版使用人工验证模板，不直接完全随机布雷。

## 5. 精英、BOSS 与装备布局

### 5.1 普通怪：参与数字，提供基础成长

- 普通怪位置固定，参与相邻数字。
- 不需要全部击败。
- 提供既有战后成长和基础资源。
- 一只普通怪只保留一个鲜明、短小的核心特性。
- 普通战斗不能全部变成精英式多机制长战。

### 5.2 精英：直接显示，守护高品质目标

- 从开局显示位置、名称、元素与核心机制。
- 明确展示守护或关联的高品质武器、护符、补给。
- 玩家主动选择挑战，不在未知格中无预告出现。
- 精英是“高风险换定向奖励”，不是地图上的随机惩罚。
- 精英战败或绕过均不能造成额外地图惩罚。

### 5.3 BOSS：可见终点与 Build 验收

BOSS 确认层建议显示：

```text
BOSS：冰封铁瓮 · 冰
核心机制：叠甲与冻结／熔铸间隙
当前优势：火系克制、可用三连破甲
当前风险：净化资源不足
[继续探索] [挑战 BOSS]
```

这是机制与资源预览，不显示伪造的精确胜率，不设置装备评分门槛。

### 5.4 装备公开层级

| 内容 | 公开规则 |
|---|---|
| 武器/护符 | 重要目标直接显示具体物品、元素、品质与替换得失 |
| 精英奖励 | 挑战前显示具体奖励或明确的合法候选，不能落地重抽 |
| 商店/休整 | 显示节点类型与基本作用 |
| 普通补给 | 可只显示类别，具体数量可保留小幅惊喜 |
| 宝箱（后续） | 显示品质或类别，具体内容生成时冻结 |
| BOSS 战利品 | 保留现有专属规则，不与地图普通装备重复发放 |

## 6. 防止“全图拿完再开战”成为机械答案

允许玩家全清，但不能让全清既无成本又绝对最优。

### 6.1 使用自然成本

- 战斗会消耗生命、消耗品和操作精力。
- 路线与地形决定接近装备的战斗成本。
- 武器/护符/消耗品槽位限制无限叠加。
- 新装备可能要求替换当前成熟 Build，而不是永远纯收益。
- 更多战斗会改变成长方向，但不自动等于更适合当前 BOSS。

### 6.2 不采用的人为限制

- 每步扣金币或扣血；
- 强制回合倒计时；
- 收集率门票；
- 为阻止探索而生成巡猎者；
- 玩家多拿装备后暗中提高 BOSS 数值；
- 用长动画增加全清成本。

### 6.3 路线差异目标

- 快速挑战：少战斗、少成长，更依赖初始 Build 与操作。
- 定向探索：围绕某件装备或对策规划路线。
- 全图收割：付出更多战斗与资源成本，获得更广收藏，但不应成为唯一效率答案。

## 7. 普通怪、精英与 BOSS 的战斗分工

### 7.1 普通怪：特色化而非精英化

普通怪只保留一个核心特性，并尽早在战斗中呈现：

- 入场即生效的场地/状态特性；
- 第一次受击时的护盾、变形或弱点反应；
- 第一次转轮前即可读到的蓄力或意图预告。

即使玩家 1–2 回合爆发击杀，也应看见“它是什么、准备做什么、我如何解决它”。

### 7.2 不为了演出强行延长战斗

禁止：

- 首回合锁血；
- 强制复活；
- 固定伤害上限；
- 为看技能而设置无意义护盾；
- 强制播放长动画；
- 全局提高普通怪 HP。

普通操作约 2–3 回合，良好 Build 或爆发可以 1–2 回合结束。只有正常 Build 下仍无法看到核心机制时，才单独检查该怪的耐久或触发阈值。

### 7.3 精英与 BOSS 保留更高层级

| 类型 | 机制结构 | 节奏目标 |
|---|---|---|
| 普通 | 一个早期可见特性 | 快速、可读、提供成长 |
| 精英 | 一个主机制＋一个强化/组合 | 蓄势与爆发，有恢复窗口 |
| BOSS | 专属机制＋阶段变化 | 多阶段 Build 验收，不只堆数值 |

精英和 BOSS 可沿用“蓄势→预警→爆发→恢复”的弹簧节奏，但不得根据玩家 HP 或 Build 强度暗改数值。

### 7.4 多对策与无硬counter

- 每种高压机制至少有两种有效应对，并保留基础兜底。
- 无净化物品不能导致必败。
- 无特定元素也存在破甲或输出路径。
- 战中调整目标、连击、消耗品和爆发时机，不要求临时换 Build。
- 动态提示只描述局势与真实可选对策，不替玩家指定唯一答案。

## 8. 迷雾、记忆与信息公开

### 8.1 新迷雾职责

迷雾不再服务巡猎，而是服务探索：

- 未知格：隐藏普通怪具体身份与次要补给细节；
- 已揭示：显示真实内容与节点状态；
- 已消耗：保留地形与内容记忆，但明确奖励已领取/敌人已击败。

### 8.2 永不隐藏

- 网格邻接关系；
- 合法数字及其计算范围；
- 精英、BOSS 的位置与核心信息；
- 重要装备目标；
- 当前 Build 和可用对策；
- BOSS 确认层的继续探索/挑战选择。

### 8.3 揭示规则

- 揭示不消耗 RNG；
- 揭示不重抽内容；
- 揭示不额外推进世界状态；
- 查看构筑、撤回取消、打开 BOSS 确认层不重复揭示或领取奖励；
- 不用随机噪点或持续动态雾遮挡数字与图标。

## 9. 三幕连续结构

### 9.1 一张世界地图，三个局部雷区

- 世界总览只显示三个区域、完成状态、区域 BOSS 和最终目的地。
- 当前幕使用自己的局部网格，不把三幕全部格子同屏平铺。
- 每幕只探索自己的区域，只结算一个区域 BOSS。
- ACT1/2 BOSS 不触发整局结束，ACT3 才进入最终结算。

### 9.2 区域过渡

```text
区域 BOSS 胜利
→ 专属战利品
→ 世界地图显示新区域
→ 短过渡
→ 下一幕装备探索网格
```

- 三幕共享 HP、Build、成长、消耗品与收藏。
- 过渡不自动满血，不额外发一套同价值成长。
- 整局种子在开局冻结全部三幕内容，进入新幕不重抽。
- 不将上一幕未击败敌人带入下一幕。

### 9.3 区域主题

| 区域 | 探索主题 | 视觉方向 |
|---|---|---|
| ACT1 | 墓园废墟中的基础装备与对策 | 暗褐、灰绿、敌人红 |
| ACT2 | 冰封/深渊区域中的机制组合 | 冰蓝、暗紫 |
| ACT3 | 破碎王座中的高风险定向收集 | 暗金、裂红、虚无黑 |

## 10. 查看构筑、整备与撤回

### 10.1 查看构筑

随时只读查看武器、技能、护符、消耗品、真实转轮带、技艺、铭印与共鸣。查看不改变地图、不领取奖励、不消耗 RNG。

### 10.2 营地整备

只在明确的营地、休整或商店节点进行已有恢复、购买或替换功能。不能通过随时返回整备免费换装、回血或刷新地图。

### 10.3 撤回整备

- 随时可发起，必须二次确认。
- 确认后结束本次远征并回整备页。
- 保留已经入账的图鉴、收藏、解锁与局外点数。
- 失去本局临时成长、当前地图进度和未结算奖励。
- 不发区域 BOSS 或通关奖励，终局原因记录为“主动撤回”。
- 当前原型不提供继续本局；不得暗示有中途恢复。
- 打开或取消撤回不改变数字、节点、Build、HP 或 RNG。

## 11. UI 与像素美术规范

### 11.1 推荐布局

- 顶栏：ACT、HP、金币、当前目标和系统菜单。
- 中央：完整局部网格，所有格子在一屏内。
- 节点详情：选中格内容、奖励、数字含义、战斗或替换结果。
- Build 摘要：当前双武器、成长、共鸣与关键对策。
- 系统入口：查看构筑、撤回整备；不与主要探索操作相邻。

### 11.2 格子状态

| 状态 | 表现 |
|---|---|
| 未知 | 暗色底、可探索轮廓，次要内容隐藏 |
| 普通威胁已揭示 | 敌人图标＋明确数字关联 |
| 装备 | 具体物品图标，重要目标不被遮住 |
| 精英 | 尖刺框/金色底座＋名称 |
| BOSS | 大型地标＋名称与元素 |
| 已消耗 | 降低亮度，保留内容记忆 |
| 当前选择 | 暖白框 |
| 可探索 | 金色框或明确指针 |
| 数字悬停 | 四个相邻格同步高亮 |

### 11.3 素材

- 格子图标使用 16×16 或 24×24 原生像素。
- 点击热区大于图标，不能互相重叠。
- 地形使用大色块与成组剪影，不铺随机噪点。
- 玩家、普通敌人、精英、BOSS 与装备必须同时用形状和图标区分，不只换色。
- 数字、图标和边框不互相遮挡。
- 演出短促、可跳过，不消耗 RNG。

# 12. 分步制作计划

## Step 0 · 冻结旧方案并保存基线

### 执行

- 旧棋盘文档已移除；停止骰子/巡猎者方向的后续制作，不恢复旧规则。
- 保存当前回归、现有棋盘截图、战斗与奖励流程。
- 保留线性入口和现有测试入口，避免迁移期无法对照。
- 记录当前 ACT1 战斗数、成长、装备与 BOSS 流程。

### 出口

新旧范围明确，旧规则不会在新网格中残留。

## Step 1 · 固定 4×4 内容灰盒

### 执行

- 所有具体对象在开局冻结。
- 只验证内容与位置，不接新战斗机制。

### 出口

网格完整、BOSS 与精英可见、装备目标明确、无孤立格。

### 实施记录（2026-11-10）

  起点 `g00`、BOSS `g33`、精英 `g12`、武器 `g01`/`g22`、护符 `g11`；
- 内容：1 起点 / 6 普通 / 1 精英 / 1 BOSS / 2 武器 / 1 护符 / 2 商店 / 2 休整 = 16 格，
  战斗 8 场；房间、武器、护符在生成时冻结，同 seed 一致，不写 meta / 装配；
- 可见性：精英 / BOSS / 装备 / 商店 / 休整 / 起点开局公开，普通怪身份保持未知；

## Step 2 · 数字、揭示与一次性结算

### 执行

- 接入四方向普通威胁数字。
- 点击未知格揭示内容；敌人先确认再战斗，装备按既有规则获得。
- 接入已揭示、已消耗、数字更新与悬停相邻高亮。
- 所有节点只结算一次。

### 出口

数字与实际普通敌人一致；揭示不重抽、不重复奖励；无需盲猜即可找到基础路线。

### 实施记录（2026-11-10）

- `BoardConfig` 新增 `layout_mode`（默认 `legacy`，`grid4x4` 才启用）与 `grid_seed`（默认 20261110），
  `use_grid()` 另支持命令行 `--grid`（仍需 `--board`）；
- `BoardSystem` 新增 `grid_mode / revealed / defeated / last_move_revisit / _grid_data`：
  数字实时统计四方向未击败普通怪，进入即揭示，已消耗格可回访但不再结算，
  战斗胜利经 `return_to_board()` → `note_battle_won()` 标记击败并更新相邻数字；
- `BoardScreen` 网格分支：16 热区、隐藏骰子/前进、未知格只显示「?」与数字线索、
  数字徽标分色、悬停高亮四邻格、非相邻点击只查看、相邻敌人先确认后战斗；
- 定向回归 `tests/mine_grid_test`：**127 / 0**（含固定种子 16 格数字逐格比对、
  装备格既有结算与回访不重复获得）；
- 默认入口不变，Step 3（BOSS 继续探索/挑战选择、精英预告、查看构筑与撤回）未实施。

## Step 3 · 自主探索与 BOSS 开战选择

### 执行

- 接入 BOSS 确认层的“继续探索/挑战 BOSS”。
- 接入精英奖励预告与主动挑战。
- 接入查看构筑和二次确认撤回。
- 检查 BOSS 提前挑战、定向探索与全清三种路径。

### 出口

玩家可自由决定探索顺序和开战时机；没有收集率门票、误点强制开战或撤回刷新。

### 实施记录（2026-11-10）

- BOSS：点击相邻格只开确认层，不移动 / 不消耗；[继续探索] 留原格，[挑战 BOSS] 才进入；
  预览含真实弱点（`ElementCounter.weakness` ×1.5）与当前武器元素，无装备 / 收集率门槛；
- 精英：点击先看战利品（金币囤 + 铁砧点 + 1 项高品质奖励）、高品质候选与邻近装备目标，
  [返回探索] 不消耗，[挑战精英] 才进入；已击败后只移动、不重复开战；
- 查看构筑：只读弹层列出武器 / 技能 / 护符 / 消耗品 / 成长 / 符号权重；不调用 `build_strips`，
  因此不消耗 RNG、不改地图 / 数字 / HP；
- 撤回整备：两次确认后 `RunJournal.finish("retreat")` → 保留图鉴 / 收藏 / 局外点数与武器熟练，
  失去本局临时成长、地图进度与未结算奖励，回整备页；取消不改变任何状态；
- 定向回归 `tests/mine_grid_test`：**167 / 0**（含零击败挑战 BOSS、精英预告、构筑 RNG 不变、
  撤回两次确认与终局原因）；
- 默认 `legacy` 入口不变；Step 4（普通怪早期特性）与 Step 5（精英 / BOSS 节奏）未实施。

## Step 4 · 普通怪早期特性样板

## Step 7 · 受控随机模板

### 出口

## Step 8 · ACT1 真人验收

记录：

- 探索顺序、装备追逐、普通/精英/BOSS 战斗数；
- 回合、承伤、消耗品、换装与死亡点；
- 提前挑战、定向探索、全清的选择原因；
- 玩家是否理解数字、是否遇到被迫猜测；
- 普通怪特性是否可见，精英/BOSS 是否有真实节奏；
- 总时长、再玩意愿和下一局目标。

### 数据纪律

- AI 数据只用于流程、复现和自动测试。
- 不用 control 零延迟死亡或 readable 高停中率推断真人难度。
- 不用自动回归代替真人探索体验验收。

### 出口

玩家能复述“我为了哪件装备选择了哪条路线，以及为什么此时挑战 BOSS”；无流程阻塞、无硬门票、无重复奖励。

## Step 9 · ACT2/ACT3 接入

- 先连接 ACT1→ACT2，验证 HP、Build、成长、收藏和 BOSS 奖励连续。
- 两幕通过后再接 ACT3 和最终结算。
- 每幕使用独立合法池、地形主题和装备目标。
- 只有 ACT3 最终 BOSS 触发整局结算。

### 出口

三幕是同一局连续探索，无跨幕重复奖励、重抽或错误的整局结束。

## 13. 自动测试最低覆盖

- 四方向数字与当前普通敌人数一致；精英/BOSS 不混入。
- 起点安全、BOSS 可达、无孤立格与强制 50/50 模板。
- 同种子敌人、装备、地形与数字一致。
- 揭示、查看构筑、BOSS 确认和撤回取消不消耗 RNG、不重抽内容。
- 普通敌人被击败后数字按规则更新，其他内容不变。
- 每个节点只结算一次，满槽替换/折算合法。
- 精英与 BOSS 从开局可见，BOSS 可提前挑战或继续探索。
- 撤回只保留已入账永久内容，不发未结算或通关奖励。
- 普通怪早期特性在入场/首次受击/首次转轮前正确展示。
- 精英/BOSS 高压意图和恢复窗口与真实结算一致。
- ACT1/2 不触发整局结束，ACT3 正确结算。
- 线性入口保留；`run_smoke.bat` 全绿，新模块有定向测试。

## 14. 停止条件

出现以下任一情况，停止扩模板、扩幕和加内容：

- 数字与实际威胁不一致，或玩家必须盲猜关键路线。
- 踩雷直接扣血/战败，而不是进入可应对的战斗。
- 装备需要揭示后重新随机，或预告与落地不一致。
- 全图收割无成本且成为唯一效率答案。
- BOSS 需要收集率门票，或按玩家装备暗改数值。
- 所有普通怪被做成多机制精英，探索变成连续长战。
- 普通怪为展示技能而锁血、复活或播放长动画。
- 迷雾吞掉数字、精英、BOSS 或重要装备信息。
- 撤回、查看构筑或重新打开界面可以刷新奖励。
- 玩家只关注躲雷，无法说出自己在追逐什么装备。
- 自动回归失败或 AI 结果被当成真人难度结论。

## 15. 最终完成定义

棋盘只有同时满足以下条件才算成立：

1. 扫雷数字帮助玩家推断装备路线，而不是只帮助躲雷。
2. 精英与 BOSS 直接可见，玩家能主动规划挑战。
3. 玩家可以为了具体装备自主决定探索顺序。
4. BOSS 可提前挑战，不设置强制收集门票。
5. 普通怪有特色但短促，精英与 BOSS 保留更高机制层级。
6. 战中调整打法，局间调整 Build，不存在无答案硬counter。
7. 全清有成本但不被人为惩罚，快速路线与定向路线也有价值。
8. 所有随机在开局冻结，揭示和撤回不能刷新。
9. 三幕共享一局状态，只有最终 BOSS 触发整局结算。
10. 真人能够复述装备目标、路线理由和开战时机。

最终体验应当是：

> **我看见 BOSS 和装备目标，用数字推断风险，通过自己的路线形成 Build，并在自己认为准备好的时候主动挑战 BOSS。**
