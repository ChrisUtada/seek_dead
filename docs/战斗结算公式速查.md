## 0. 坐标系与转轮频率（老虎机本体）

| 项 | 值 | 含义 |
|---|---|---|
| `REELS` | 3（duel_controller.gd:71） | 转轮列数 |
| `ROWS` | 1（duel_controller.gd:72） | 每列行数 |
| `PAYLINES[0]` | 3 列各取第 0 行 | 唯一一条 payline |
| 落子 | 每列从自身 `reel_strip` 按停止时机取格 → `grid[reel][0]` | 频率 = 带子上该符号的格子数 |

> 1 行 3 格 ⇒ 一条线上最多「3 同」。所谓 2 连 / 3 连 = 同一「符号 + 有效元素」落了 2 格 / 3 格（evaluate 按 `path|elem` 分组计数，combat_system.gd:150-153）。

### 带子构建（build_strips，reel_system.gd:90-176）

- **聚合权重**：`w = 装备 weight + 符号灌注 run_symbol_bonus + 共鸣 weight_bonus`（reel_system.gd:108）；同「符号|元素」跨装备累加。
- **格数档位**（reel_system.gd:136-141）：`w ≥ 4 → 4 格` / `w ≥ 2 → 3 格` / 保底 `2 格`。
- **稀有度封顶**（reel_system.gd:142-143）：`kind != "damage"` 的功能符号（status/buff/special）若 `rare/epic`（rank≥2）且**单源**（sources<2）→ 封顶 2 格；damage 攻击符号不受封顶；**共享符号 ≥2 源突破封顶**（reel_system.gd:117）。
- **MISS**（reel_system.gd:100,118-121,149-152）：`miss_w = Σ 各装备段总权重 × (1 - hit_rate)`；`miss_cells = max(1, round(total_cells × miss_w / wsum))`。MISS 与废铁同语义（kind=trash，不匹配不结算，视觉显示 MISS，可滚过规避）。
- **金币**：常驻 2 格（`_GOLD_CELLS = 2`，reel_system.gd:24,153-154），与装备频率解耦。
- **废铁注入**：敌人乱权（chaos）注入 `round(带长×0.20)` 格（reel_system.gd:156-159）；深渊侵蚀 `boss_trash` 逐格注入（reel_system.gd:160-162）。
- **带长下限 30**（`_STRIP_MIN_CELLS = 30`，reel_system.gd:23,163-167）：不足则整份平铺补足，各符号占比不变。
- **3 根转轮 = 同一 base 的洗牌副本**（reel_system.gd:168-176）。
- 元素精华（消耗品）注入：权重 7.0（≈4 格档），房级、新房间失效（duel_controller.gd:26,458-462）。

## 1. 连线判定（counts）

遍历 payline 3 格，按 **`符号 resource_path + 有效元素`** 分组计数得 `raw`（c）：

- `c = 1` → 单符号；`c = 2` → 2 连；`c = 3` → 3 连（满线）
- **冻结列（失效格）不参与计数**——不匹配、不结算、无攻击（combat_system.gd:146-147）
- **同元素三连** `_elem_triple`：非 none 元素在全线总出现 ≥3（跨符号聚合，可不同符号）→ 必暴 + 克制核爆判定（combat_system.gd:155-164）

## 2. 每符号伤害分量（contribute，combat_system.gd:24-102）

```
line_bonus  = 训练·连线精通等级 × per_level(1.0)              # combat_system.gd:26-27
mult        = raw + (line_bonus 仅当 raw >= 2 时生效)
item_power  = _weapon_power_map[sym.path]  (武器/技能 base_power，共享符号取最高)
flat        = item_power + agg_power_flat()   若 item_power>0；否则 sym.base + agg_power_flat()
                                                        # combat_system.gd:30-31（BASE_POWER_REF 已退役）
agg_power_flat = run_power_bonus + 护符伤害加成 + Σbuff("power") + 训练·锋锐等级×4
                                                        # battle_math.gd:50-51
```

**元素倍率 `em`**（仅 damage/special 计算；护盾/治疗/状态符号豁免，不参与克制/充能/核爆，combat_system.gd:36-50）：

```
em = ElementCounter.multiplier(elem, enemy_element) × 共鸣元素加成(该元素)
     若 em > 1.0：em += 元素优势护符加成（仅克制时；无名虚空剥夺失效）
em > 1.0 → 本回合标 [克制] + charge_points += 1（元素充能，仅伤害类符号）
em < 1.0 → 本回合标 [抵抗]
```

**暴击**（方案 B，combat_system.gd:51-56）：

```
crit_rate     = BALANCE.crit_chance(0.20) + 物品 crit_chance   # 每符号实例独立判定
crit_mult_val = (物品 crit_mult(默认 2.0) + 共鸣暴击加成)
                若 raw>=3 或 _elem_triple 或 randf()<crit_rate，否则 1.0
```

### 各 kind 结算（match，combat_system.gd:59-102）

| kind | 公式 | 备注 |
|---|---|---|
| `damage` | `dv = flat × mult × em`；暴击 ×`crit_mult_val`；碎片王冠首击 ×`charm_first_hit`（每回合首个伤害符号，damage/special 共用一次） | `raw>=3` 打 `acc["triple"]` 标记；`sym.pierce_armor` 或 `randf()<破甲概率` → `acc["pierce"]`（穿透直击 HP）否则 `acc["dmg"]`（combat_system.gd:61-75） |
| `special` | `sv = flat × mult × em`，与 damage **完全同源**（同暴击/首击/穿透/三连标记，combat_system.gd:86-101） | 专指火焰法杖类专属高伤符号 |
| `shield` | `+= sym.base × mult × crit_mult_val` | 不吃武器攻击力/克制/元进度（combat_system.gd:78）；吃连线精通与暴击 |
| `heal` | `+= sym.base × [1.0, 2.5, 5.0][mini(raw-1,2)]`（1连×1.0 / 2连×2.5 / 3连×5.0） | **不吃**暴击/连线精通/克制（combat_system.gd:81-82）；`raw>=3` 打 `heal_triple`（溢出转盾，§4） |
| `status` | `acc["status_stacks"][type] += mult × crit_mult_val + 毒腺囊层数加成` | 每层 = 1 连线点；三连按物品 crit_mult 暴击（combat_system.gd:85） |
| `buff` | 见 §5（先结算，本回合即生效） | |
| `gold` | 见 §7 | |
| `trash`（MISS/废铁） | 不匹配、不结算 | combat_system.gd:170,187 |

## 3. special 规则（2026-08-07 与 damage 同源）

- 无独立「special 三连暴击」：三连暴击 = 全符号类型统一的 `crit_mult_val`（物品 crit_mult）。
- **special 三连不再通用清甲**：破甲仅两种——①克制三连（§5 核爆前置清甲）；②带破甲机制（`triple_pierce`）的武器/技能符号三连（`_item_pierce_map` 判定，combat_system.gd:233-242）。
- 任意同符号三连（含 special）触发 BOSS 钩子 `on_special_triple`（combat_system.gd:228-231）。

## 4. 结算顺序（evaluate，combat_system.gd:135-304）

**阶段 1：防御 / 增益 / 状态先落地**（buff 当回合即生效）：

1. 冻结列跳过计数（§1）。
2. **buff 符号**先结算：`grant_buff`，剩余回合 `add = max(1, sym.buff_turns) × 连线数`（combat_system.gd:172,342-346）。
3. **金币符号**：`g = BALANCE.gold_per_coin × 落数` 直接入 `gold`（combat_system.gd:176-181）。
4. **常规符号**（damage/shield/heal/status/special）走 §2 累加到 `acc`（combat_system.gd:183-191）。
5. 落地（combat_system.gd:196-221）：
   - `player_shield += acc.shield + agg_shield()`（铁壁 buff + 守备护符涓流）
   - `player_hp = min(hp_max, hp + acc.heal + agg_regen())`（回春 buff + 回春护符）
   - **治疗三连溢出转盾**：`heal_triple` 且治疗量 > 缺口 → 差额全部转护盾（combat_system.gd:214-218）
   - `enemy_status[type] += acc.status_stacks[type]`

**钩子 + 破甲/核爆**（combat_system.gd:226-242）：三连钩子 → `counter_triple`（克制元素连线≥2 或同元素三连）→ `on_counter("element")`；否则带 `triple_pierce` 机制的符号三连 → `on_counter("special")`（仅清甲，§5）。

**阶段 2：攻击结算（乘区链）**（combat_system.gd:244-252）：

```
buff_mult       = 护符伤害乘区 × Π 玩家增益("damage_mult")   # agg_damage_mult，battle_math.gd:59-60
assault         = assault_next_spin（强袭药剂倍率，用后清 1）
normal_subtotal = acc.dmg + acc.special
pierce_subtotal = acc.pierce
normal_total    = int(normal_subtotal × assault × buff_mult × BALANCE.player_dmg_mult(1.5))
pierce_total    = int(pierce_subtotal × assault × buff_mult × BALANCE.player_dmg_mult)
total           = normal_total + pierce_total
```

- 先 `apply_enemy_damage(normal_total, false)` 再 `apply_enemy_damage(pierce_total, true)`（combat_system.gd:275-278）。
- 掉血：**非穿透**先扣 `enemy_armor = min(armor, dmg)`，溢出进 HP；**穿透**直接扣 HP（combat_system.gd:415-426）。
- 伤害落地后：元素充能检查（§6）→ `tick_buffs()` 回合末递减玩家增益（combat_system.gd:293-304）→ BOSS 钩子 `on_turn_resolved`。

### 完整单发伤害公式（普通 damage 符号）

```
单符号(raw=1)  dv = flat × 1 × em
2 连(raw=2)    dv = flat × (2+line_bonus) × em
3 连(raw=3)    dv = flat × (3+line_bonus) × em × crit_mult_val（必暴）
→ 最终贡献 = int(dv × [首击×] × assault × buff_mult × 1.5)   （pierce 走穿透，其余先破甲）
```

## 5. 反制即爆发（on_counter，combat_system.gd:429-443）

```
if acc.counter_triple:     # 克制元素连线 ≥2（或同元素三连）——元素克制时 raw>=2 即埋点
    on_counter("element")
elif triple_pierce:        # 带破甲机制(武器/技能)的符号三连
    on_counter("special")
```

`on_counter(kind)`：
- **始终**：`enemy_armor > 0` → 护甲清零（对所有敌人通用的破甲窗口）。
- `kind == "element"`：额外核爆 `burst = enemy_hp_max × 0.20`，穿透直击 HP（combat_system.gd:437-441）。

## 6. 元素克制与充能爆发

**克制矩阵**（element_counter.gd:24-47，玩家符号元素 → 敌人元素单向；敌人打玩家恒中性）：

| 攻击元素 | 克制 ×1.5 | 抵抗 ×0.85 |
|---|---|---|
| fire | ice, poison | fire（同元素） |
| ice | fire | ice |
| poison | dark | poison, fire, light |
| light | dark, poison | light |
| dark | light | dark, poison |

规则：`atk == def` → ×0.85；`BEATS[atk]` 含 def → ×1.5；`BEATS[def]` 含 atk → ×0.85；任意为 none → ×1.0。

**元素充能**（T21，combat_system.gd:42-44,293-296,464-476）：
- 克制命中（damage/special 且 `em>1.0`）→ `charge_points += 1`（每房清零，duel_controller.gd:921）。
- 深渊凝视（信物）：每回合开始 `charge_points += N`（duel_controller.gd:987-988）。
- 满 `charge_max = 5` → 清零并 `release_element_burst()`：**清甲 + `enemy_hp_max × charge_burst_pct(0.15)` 穿透核爆**（与三连破甲互补：分散积累 vs 单次爆发）。

## 7. 金币结算

- 落在线上的金币符号（常驻 2 格/带）：`g = BALANCE.gold_per_coin(=1) × 落数`，直接加 `gold`，不造成伤害（combat_system.gd:176-181）。
- 冻结列上的金币不计数（§1）。

## 8. 攻击前 buff（player_buffs 回合制）

- **生效时机**：buff 符号在结算顺序第 2 步落地（evaluate 内），**命中当回合即吃到**（combat_system.gd:167-172）。
- **时长**：`add = max(1, sym.buff_turns) × 连线数`；`tick_buffs` 每回合末 −1，归零移除（combat_system.gd:342-346,377-385）。
- **效果类型**（buff_effect → 消费点，battle_math.gd）：

| effect | 聚合 | 消费点 |
|---|---|---|
| `power` | 加算进 `agg_power_flat` | contribute 的 `flat`（battle_math.gd:16-17,50-51） |
| `shield` | 加算进 `agg_shield` | evaluate 阶段 1 每回合护盾（battle_math.gd:19-20,53-54） |
| `regen` | 加算进 `agg_regen` | evaluate 阶段 1 每回合回血（battle_math.gd:22-23,56-57） |
| `damage_mult` | **连乘** `buff_damage_mult` | 阶段 2 `buff_mult`（battle_math.gd:26-31） |

- 护符乘区：`charm_damage_mult`（装配时 `min(×, charm_mult_cap=6.0)`，duel_controller.gd:564）与增益连乘，构成 `buff_mult`。
- 无名虚空（deprived_level≥1）：护符全部剥离（乘区回 1.0、加算回 0、破甲概率归零、DoT 倍率回 1.0、首击/反弹失效，combat_system.gd:58,65,317,322,326,330,406,453）。

## 9. 敌人回合

**意图抽取**（status_system.gd:47-78）：房间 `RoomData.intents` → 行为族 `intent_weights` → 房型默认表；可净化（干扰类）意图权重 × 抗扰系数（最低保留 25%，duel_controller.gd:919）。`attack` 值 = `enemy_atk`；`heavy` 值 = `enemy_atk × value_mult(2.0)`。

**意图执行**（enemy_system.gd:21-53）：

| 意图 | 行为 |
|---|---|
| `attack` / `heavy` | `enemy_deal_damage(value)` |
| `jam` | 下一轮随机一列被废铁占据 |
| `lock` | 下一轮随机一列固定不变 |
| `chaos` | 下一轮向整带注入 20% 废铁 |
| `none` | 落空（被净化） |

**敌人伤害闸口 `enemy_deal_damage`**（combat_system.gd:388-411）：

```
atk_down = 1 - min(0.5, enemy_frost×0.2 + enemy_poison×0.2)   # 敌人被冰/毒削弱（减攻）
eff      = round(raw × atk_down × boss_atk_mult)              # boss_atk_mult 由 BOSS 机制设
blocked  = min(player_shield, eff)
player_shield -= blocked ; dealt = max(0, eff - blocked) ; player_hp -= dealt
```

- **石屑之心（信物）**：`dealt > 0` 时反弹 `round(eff × thorns)` 穿透直击敌人（combat_system.gd:406-411）。
- 护甲是**扁平池**：敌我统一 `min(armor, dmg)` 吸收、溢出进 HP（combat_system.gd:422-426）。

**状态 DoT（tick_status，combat_system.gd:446-461，敌人回合意图执行后调用）**：

```
dot += round(enemy_status[st] × base × 元素克制 × BALANCE.status_dmg_mult(3.0) × 状态护符)
enemy_status[st] -= StatusDef.decay(当前全部状态 = 1)
```

- 状态元素克制：burn→fire / frost→ice / poison→poison 对敌人元素走同一单向矩阵（status_system.gd:104-107）。
- 状态定义（resources/statuses/*.tres）：burn base=4 fire、poison base=3 poison、frost base=0 ice（纯减攻）、frozen base=0 ice max_cols=2（玩家侧冻结）。
- 玩家侧冻结（寒霜侵蚀）：`_begin_player_turn` 中 frozen 先衰减再挂新层，`frozen_cols = pick_frozen_cols()`（不封废铁列，上限 2，combat_system.gd:357-374）；冻结列本轮不可转、不结算。

## 10. 房难度曲线（ante）

`_start_room`（duel_controller.gd:894-963）→ `_ante_scale`（duel_controller.gd:966-978）：

```
hp_scale  = 1.75^(act-1) × 1.15^ria
atk_scale = 1.46^(act-1) × 1.10^ria
enemy_hp_max  = round(房基础HP × hp_scale)     # 基础为 0 时取行为族基准
enemy_atk     = round(房基础ATK × atk_scale)
enemy_armor   = round(房基础护甲 × hp_scale)（扁平池）
ria = 同幕内序号 - 1（boss 恒为幕内峰值）
```

每房开局：`player_shield = 上房结界 + 守望护符 + 训练·壁垒等级×5`；体魄增量按 `等级×15` 提升 `player_hp_max` 并回满该增量（duel_controller.gd:928-936）。

## 12. 乘区纪律（架构铁律，勿破）

1. **战斗内无连锁重触发**（重转机制 2026-08-07 移除）。乘区链单发一次：`连线数 × 克制 ×（护符/增益/强袭/暴击）× 1.5`。
2. **玩家层无独立伤害乘区轨道**：power（加算）+ line（连线乘区）即上限；乘区全留给 build 层（武器/技能/护符/共鸣/信物）。
3. 强度轴（`base_power`/`hit_rate`/`element`/`crit_*`/`triple_pierce`）只定伤害；频率轴（`weight` → 格数档位）只定出现次数。稀有度：damage 不受频率封顶（修复反向稀有度惩罚）。
4. 平衡常量全收敛于 `balance_config.tres`；纯数学函数抽在 `battle_math.gd`；调参走数据层，勿硬编码。
