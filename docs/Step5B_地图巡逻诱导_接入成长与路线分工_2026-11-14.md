## 1. 本步做了什么

新增 `scripts/board/map_progress.gd`，把**地图战斗节点分流到既有奖励管线**，不另立一套奖励逻辑。

| 节点 | 管线 | 具体委托 | 历练 |
|---|---|---|---|
| `battle` / 巡逻遭遇 | `post_battle` | `post_battle.build("normal")` → 补给 / 构筑 / 成长 三选一 | 1 |
| `elite` | `post_battle` | `post_battle.build("elite")` → 同三选一，但补给池含 `elite_*` 档、构筑池保证可给武器 | 2 |
| `boss` | `boss_loot` | `reward_system.roll_boss_rewards(room)` → 主题武器 / 信物 / 铁砧兜底 | 3 |
| 战败 | — | 不发奖励、不发历练，节点照样消耗 | 0 |

历练走 `growth.grant_room_xp(kind)`，回春 / 积蓄走 `growth.apply_victory_perks(kind)`，与 `room_flow._settle_victory` 同序；本类不扣金币、不入腰带、不改掉落来源。

### 只结算一次（新增守门）

`MapRuntime.resolve_battle(victory)`：

1. 先查 `battles[cell]` 是否已结算——已结算直接返回 `already_resolved`，丢弃重复请求；
2. 消费 `pending_battle`，内容战斗节点写入 `consumed`；
3. 胜利才生成奖励卡与结算历练；战败只记录；
4. `battles` 进存档（只恢复「哪一场打过」，不重放奖励）。

## 4. 已知限制

1. **BOSS 主题层为空时只剩信物**：`roll_n` 在目标品质层没有主题武器时会走 `short_tier`，此时 BOSS 卡可能是「信物 +（槽满时）铁砧兜底」，不会出现武器。这是既有行为，属数据层补充范围，不是本步引入。
2. **`roll_n()` 仍是「空层即失败」**：`roll()` 已在 Step 5A 修好空层降级，`roll_n` 尚未；若后续出现空 offer，可用同一手法补。
3. **不接产品入口**：奖励卡只生成、不展示；选卡交互与界面属 Step 6。
4. **召回 / 战败后地图状态**：战败只标记录与消耗，不做撤退位移（产品规则由正式入口接入时定义）。
