# T3-3C · 第三格只读组合预览（2026-11-26）

> 性质：C 轮第 4 步——已锁两格后，对第三格的候选符号做**纯匹配预览**。
> 不做伤害/命中率模拟，不自动改判、不停轮、不消耗 RNG。
> 代码：`ComboCatalog.preview_third_slot()`、`ComboPanel.open(rows, sources, preview)` / `open_preview()`
> 验收：`tests/t3c_combo_preview_test.gd` → `T3CPREVIEW|RESULT PASS (checks=22 fails=0)`

## 1. 真实牌卡字段样例（A1 探针原文）

铁剑 + 匕首，grid 三格设为 `iron_slash / burn / fire_slash`，来源统一 `iron_sword`，
`PatternMatcher.cards_from_grid()` 的实际输出：

```text
CARD0 sym=res://resources/symbols/iron_slash.tres  element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=damage  category=blade
CARD1 sym=res://resources/symbols/burn.tres        element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=status  category=flame
CARD2 sym=res://resources/symbols/fire_slash.tres  element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=damage  category=flame
```

字段含义：

| 字段 | 来源 | 说明 |
|---|---|---|
| `sym` | `grid[col][row]` | SymbolData；`symbol_category`（blade/flame…）在符号资源上 |
| `element` | `grid_elem` | 该格有效元素（武器继承后） |
| `source` | `grid_src` | 产生该符号的来源 id（如 `iron_sword`），空串 = 无来源 |
| `source_kind` | 来源元数据 | `weapon` / `skill` / `resource` |
| `source_element` | 来源元数据 | 武器元素 / 技能符号元素 |
| `skill_role` | 技能符号 | `power` / `shield` / `heal`，非技能为空 |
| `valid` | `frozen_cols` | 冻结列（frost 失效格）为 false |

## 2. 「已锁两格」与候选口径（A2）

- **已锁两格 = `reel_system.reel_stopped[0]` 与 `[1]` 均为 true**（前两列已停/锁定）。
  `reel_stopped` 是逐列停轮状态：点击某列 `lock_reel()` 或 `stop_next_reel()` 置 true，
  `begin_spin()` 重置；这是「锁 = 保留并参与结算」的那把锁。
- `frozen_cols` **不是**锁：它是寒霜造成的「冻结 = 失效格」，不参与匹配/结算，语义相反；
  预览卡片的 `valid` 字段由它决定。
- 候选符号 = 当前 `pool_items[*].syms[*][0].resource_path` 去重（武器/技能池）。
  MISS / 金币不在 `pool_items` 中，不会成为候选。
- 预览对象固定为第三列（`PREVIEW_REEL = 2`），base_cards 取另外两列的真实卡。

## 3. 契约（B 组）

```gdscript
static func preview_third_slot(base_cards: Array, candidates: Array[String],
        pattern_system, tag_of) -> Array[Dictionary]
```

- `base_cards` 必须恰好 2 张（与 §1 同构）；否则返回空数组。
- 每行 `{"candidate": String, "candidate_name": String, "matched": Array[Dictionary]}`
  - `candidate`：符号资源路径；`candidate_name`：`SymbolData.name`（如「火斩」）。
  - `matched` 元素：`{"id","name","group"}`；`group` 复用 `_group_of()`（main/aux/base）。
- 每个候选都出一行；无命中时 `matched` 为空（面板显示「无组合」）。
- 判定范围：`track == weapon_attack` 与 `track == skill_support` 的牌谱，逐条
  `PatternMatcher.solve_rule(cards, p.match_rule)`；签名轨不单列。
  G01–G03 用 `PatternMatcher.match(cards).patterns` 一并记入（group=base）。
- 候选卡只携带 `sym`（`element=none`、`source=""`、`source_kind=resource`）：
  因此依赖 `element` / `source` / `source_kind` / `source_element` 的条件不会由候选格满足；
  依赖 `symbol_category` / `sym` / `kind` 的牌谱（如 W06/W07）正常命中。这是纯函数不读 `_ctrl` 的边界。

## 4. 只读证明（B4）

- `preview_third_slot()` 不接收 `_ctrl`，只读 `base_cards` / 候选路径 / 牌谱资源；
  `load()`、`solve_rule()`、`match()` 均为纯读取。
- `t3c_combo_preview_test` 断言调用前后 `_loot.seed_value()`、`enemy_hp`、`charge_points`、
  `frozen_cols`、`grid` 完全不变（5 条）。
- 面板 `open` / `open_preview` 对入参深拷贝，不写 `grid` / `frozen_cols` / 回合状态。

## 5. 与面板的接线（C 组）

```gdscript
func open(rows, sources = [], preview = []) -> void
func open_preview(preview_rows) -> void      # 沿用当前 rows/sources 重绘
```

- 区段顺序：**本轮来源 → 第三格预览 → 组合区段**（各自仅在非空时出现）。
- 预览行文本：`符号名：组合1、组合2`；无命中为 `符号名：无组合`。多个命中用「、」连接。
- 新增只读属性：`last_rendered_preview`、`rendered_preview_texts`。

接线点（`DuelController._on_combo_requested`）：

```text
in_interroom 守卫
  → build_rows(...) / build_sources(last_settlement_acc)
  → _combo_preview_rows()：
      reel_stopped.size() > 2 且 [0]/[1] 均 true
      → base = cards_from_grid 中除 PREVIEW_REEL 外的两张
      → candidates = _pool_symbol_paths()
      → ComboCatalog.preview_third_slot(base, candidates, _pattern_system, _pattern_tag_of)
      → 否 则返回空（面板不显示该区段）
  → hud.show_combo_panel(rows, sources, preview) → combo_panel.open(rows, sources, preview)
```

未锁两格 / 非间歇期均不显示预览区；接线只读，不改判、不替玩家停轮、不自动切换。
