## 1. 真实牌卡字段样例（A1 探针原文）

铁剑 + 匕首，grid 三格设为 `iron_slash / burn / fire_slash`，来源统一 `iron_sword`，
`PatternMatcher.cards_from_grid()` 的实际输出：

```text
CARD0 sym=res://resources/symbols/iron_slash.tres  element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=damage  category=blade
CARD1 sym=res://resources/symbols/burn.tres        element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=status  category=flame
CARD2 sym=res://resources/symbols/fire_slash.tres  element=none  source=iron_sword
      source_kind=weapon  source_element=none  skill_role=  valid=true
      kind=damage  category=flame
```

字段含义：

| 字段 | 来源 | 说明 |
|---|---|---|
| `sym` | `grid[col][row]` | SymbolData；`symbol_category`（blade/flame…）在符号资源上 |
| `element` | `grid_elem` | 该格有效元素（武器继承后） |
| `source` | `grid_src` | 产生该符号的来源 id（如 `iron_sword`），空串 = 无来源 |
| `source_kind` | 来源元数据 | `weapon` / `skill` / `resource` |
| `source_element` | 来源元数据 | 武器元素 / 技能符号元素 |
| `skill_role` | 技能符号 | `power` / `shield` / `heal`，非技能为空 |
| `valid` | `frozen_cols` | 冻结列（frost 失效格）为 false |

## 2. 「已锁两格」与候选口径（A2）

- **已锁两格 = `reel_system.reel_stopped[0]` 与 `[1]` 均为 true**（前两列已停/锁定）。
  `reel_stopped` 是逐列停轮状态：点击某列 `lock_reel()` 或 `stop_next_reel()` 置 true，
  `begin_spin()` 重置；这是「锁 = 保留并参与结算」的那把锁。

  该状态只在战斗中短暂存在。间歇期（`in_interroom`）三列恒为已停，因此那里不给预览——
  第三格早已定格，显示它会被读成预测。判定统一走 `DuelController.is_battle_combo_window()`。
- `frozen_cols` **不是**锁：它是寒霜造成的「冻结 = 失效格」，不参与匹配/结算，语义相反；
  预览卡片的 `valid` 字段由它决定。
- 候选符号 = 当前 `pool_items[*].syms[*]` 按 `path` 去重（武器/技能池）；
  每项取 `[sym, weight, elem, wid]` 的 `sym/elem/wid`，产出
  `{"path","element","source"}`（`element` 为武器继承后的有效元素，`source` 为武器 id）。
  MISS / 金币不在 `pool_items` 中，不会成为候选。
- 预览对象固定为第三列（`PREVIEW_REEL = 2`），base_cards 取另外两列的真实卡。

## 3. 契约（B 组）

```gdscript
static func preview_third_slot(base_cards: Array, candidates: Array[Dictionary],
        pattern_system, tag_of) -> Array[Dictionary]
```

- `base_cards` 必须恰好 2 张（与 §1 同构）；否则返回空数组。
- `candidates` 为调用方（`DuelController._preview_candidate_cards()`）构造好的候选牌卡：
  `PatternMatcher.card_meta()` 产出的 7 个判定字段 + 展示用 `path` / `name`。
- 每行 `{"candidate": String, "candidate_name": String, "matched": Array[Dictionary]}`
  - `candidate`：符号资源路径；`candidate_name`：`SymbolData.name`（如「火斩」）。
  - `matched` 元素：`{"id","name","group"}`；`group` 复用 `_group_of()`（main/aux/base）。
- 每个候选都出一行；无命中时 `matched` 为空（面板显示「无组合」）。
- 判定范围：`track == weapon_attack` 与 `track == skill_support` 的牌谱，逐条
  `PatternMatcher.solve_rule(cards, p.match_rule)`；签名轨不单列。
  G01–G03 用 `PatternMatcher.match(cards).patterns` 一并记入（group=base）。
- 候选卡元数据取自 `pool_items` 的 `[sym, weight, elem, wid]`，经 `PatternMatcher.card_meta`
  构造，与真实结算同源；因此元素/来源类条件的判定与实盘一致。

## 4. 只读证明（B4）

- `preview_third_slot()` 不接收 `_ctrl`，只读 `base_cards` / 已构造的候选卡 / 牌谱资源；
  `solve_rule()`、`match()` 均为纯读取（候选卡的 `card_meta` 构造发生在 duel 侧，仍不写状态）。
- `t3c_combo_preview_test` 断言调用前后 `_loot.seed_value()`、`enemy_hp`、`charge_points`、
  `frozen_cols`、`grid` 完全不变（5 条）。
- 面板 `open` / `open_preview` 对入参深拷贝，不写 `grid` / `frozen_cols` / 回合状态。

## 5. 与面板的接线（C 组）

```gdscript
func open(rows, sources = [], preview = []) -> void
func open_preview(preview_rows) -> void      # 沿用当前 rows/sources 重绘
```

- 区段顺序：**本轮来源 → 第三格预览 → 组合区段**（各自仅在非空时出现）。
- 预览行文本：`符号名：组合1、组合2`；无命中为 `符号名：无组合`。多个命中用「、」连接。
- 新增只读属性：`last_rendered_preview`、`rendered_preview_texts`。

接线点（`DuelController._on_combo_requested`）：

```text
in_interroom 或 is_battle_combo_window()
  → 间歇期：build_rows / build_sources → open(rows, sources, [])
  → 战斗窗口：open([], [], _combo_preview_rows())
```

close 时机：第三列落定或进入吸附（含夺轮 forced 停列）、起转、进入间歇态。
入口按钮：战斗期 `battle_combo_btn`「🗂 预览」，可见性由 `hud.set_reel_enabled` →
`_sync_battle_combo_entry` 单点驱动。

## 7. 已知修正：候选卡元数据硬编码（2026-11-26）

早先实现把候选卡写死为 `element=none / source="" / source_kind=resource / source_element=none`，
只携带 `sym`。由此产生两类误判：

- **漏报**：依赖 `source_element` / `source_kind` 的武器牌谱无法由候选格满足。
  例如火焰武器（`fire_sword` + 火斩）配装下，候选火斩本应命中 W01（燃 + 火焰伤害 + 武器），
  实际 `matched=["W06","W07"]`，W01 缺失。
- **误报**：候选的 `source_element=none` 让它冒充中性伤害牌，凑出 W06（无锋磨砺）。
  同一配装下 W06 被误报，实盘不会触发。
- **技能符号**：候选守备被判为 `resource`，T02（防御术式：技能盾 + 两武器）漏报。

修正方式：候选元数据改为取自 `pool_items[*].syms[*]` 的 `[sym, weight, elem, wid]`，
经新增的 `PatternMatcher.card_meta(ctrl, sym, elem, src)` 构造——与 `cards_from_grid`
实盘口径共用同一函数（单格 `[sym, elem, src]` → 7 字段卡）。候选卡在 duel 侧构造后传入，
catalog 仍为纯函数。

改前红（硬编码实现）：

```text
  C1 ids=["W06", "W07"]
FAIL  C1 火焰配装：候选火斩命中 W01（实测 ["W06", "W07"]）
FAIL  C1 火焰配装：候选火斩不误报 W06（实测 ["W06", "W07"]）
  C2 ids=[]
FAIL  C2 技能候选：守备（skill/shield）命中 T02（实测 []）
T3CPREVIEW|RESULT FAIL (checks=27 fails=3)
```

改后绿：

```text
  C1 ids=["W01", "W07"]
  C2 ids=["T02"]
T3CPREVIEW|RESULT PASS (checks=28 fails=0)
```

重建等价：`card_meta` / `cards_from_grid` 的逐字段等价由一次性对照脚本覆盖
（195 组单格 + 12 组整栅格 + valid 断言，`EQ|RESULT PASS (checks=208 fails=0)`）。
