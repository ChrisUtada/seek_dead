## 〇、改造背景与目标

### 0.1 为什么改

现有项目是俯视角**动作**肉鸽（WASD 移动 + 实时攻击 + 闪避/冲刺）。同类产品（动作 Roguelike）赛道拥挤、差异化困难。参考 **Slots & Daggers**（Steam 94% 好评，回合制策略肉鸽）与 **Slots & Skulls**（"老虎机即武器"、符号池自填装、凑整列翻倍、敌人干扰转轮、铁砧锻造元进度）验证了一个更稀缺、更有记忆点的方向：**把战斗本身做成老虎机**。

### 0.2 改什么 / 不改什么

**改为（核心）：**

- 战斗从「实时动作」改为「回合制 + 老虎机转轮结算」。
- 武器 = 一组转轮（ReelSet），由 WeaponData 配置驱动。
- 敌人新增「干扰转轮」能力（本玩法灵魂）。

**保留（复用，不重写）：**

- 全部 RPG 外壳：PlayerConfig、WeaponData/EquipmentBase 装备系统、词缀/套装/稀有度、forging 锻造、save_system 存档、room\_*.tscn 房间、SpriteLiveliness 角色表现。
- 伤害类型/克制（DamageSystem）、状态效果（StatusEffect/StatusEffectComponent）、实体注册（EntityRegistry）、全局单例（GameManager/EventManager/SceneManager 等）。

> 一句话定位：**「用老虎机当武器，靠转轮组合与敌人斗智的回合制肉鸽。」**

## 二、核心玩法循环

```
┌─────────┐   choose loadout    ┌──────────┐   enter   ┌──────────────┐
│  Lobby  │ ──────────────────▶ │  Run 开始 │ ───────▶ │  房间(战斗)   │
│ (大厅)  │                      │ (选转轮)  │           │ 转轮对决×N    │
└─────────┘ ◀────────────────── └──────────┘ ◀─────── └──────────────┘
      │   meta rewards(锻造/解锁)        │ 通关/失败                         │
      │                                  │ 房间奖励(新符号/材料/装备)         │
      └──────────── 铁砧锻造 ────────────┴───────────────┐                 │
                                                         ▼                 │
                                               ┌────────────────┐          │
                                               │  下一房间/Boss  │──────────┘
                                               └────────────────┘
```

- **单局（Run）**：从大厅携带一组转轮（=武器/装备）进入地牢，逐房推进，每房一场转轮对决，房内胜利获得奖励（新符号、材料、装备），失败或撤离结束本局。
- **元进度（Meta）**：局外用材料在「铁砧」锻造新转轮/符号、解锁词条，存档持久化（save_system 已实现 JSON 存档）。

## 三、老虎机战斗系统（核心）

### 3.1 转轮结构（Reel / Symbol / Payline）

- **转轮数（Reels）**：默认 3 个转轮（可随元进度/装备扩展到 4–5 个）。
- **每轮符号数（Rows）**：**1 行 3 格**（3 reels × 1 row）。对决时只展示一行符号，极简、一眼可读。
- **符号池（Symbol Pool）**：由当前装备的 **WeaponData（ReelSet）** 提供。每把武器定义自己的一组符号及权重（如铁剑偏向「斩」、手枪偏向「射」、火焰法杖偏向「燃」）。
- **连线（Payline）**：仅判定 **这一行 3 格**；规则详见 3.4。要点：每个非垃圾符号都按基础值结算（单符号必结算），某符号出现 `n` 次 → 该符号本轮产出 ×n（匹配=连击倍率）；特殊符号（💥/SPEC）需 3 格全同才触发。删去原先的多行 payline、对角线与"整列翻倍"规则。

### 3.2 回合流程

```
玩家回合 START
  ├─ 1) 旋转阶段：点击 SPIN，所有格重新随机（权重来自当前 ReelSet）
  ├─ 2) 结算阶段：逐格符号结算（单符号必结算 + 匹配连击倍率）→ 产生伤害/格挡/治疗/状态/特殊
  └─ 3) 敌人干扰预览：显示敌人下回合的干扰意图（读招）
玩家回合 END ──▶ 敌人回合 START
  ├─ 1) 敌人执行其攻击（造成伤害，无视转轮）
  ├─ 2) 敌人施加干扰（如：冻结 1 个转轮 / 注入 1 个 junk 符号 / 打乱符号权重）
  └─ 3) 状态结算（DoT 等）
敌人回合 END ──▶ 回到玩家回合（若双方均未倒下）
```

> 关键爽点：每回合纯转轮 + 敌人**干扰你的转轮**迫使你读招、布局、反制；每回合的"操作感"来自**配装**（带哪些武器 = 转轮里有哪些符号）与战斗中的**消耗品**（重转 / 净化 / 强袭），而非手动锁格。

### 3.3 符号表（基准集，可由武器/词缀扩展）

> **单一事实来源**：符号定义（id 枚举 + 标签/颜色/类型/基础值）集中在 `scripts/battle/reel_symbol.gd` 的 `ReelSymbol` 类（`Id` 枚举 + `CATALOG` 字典 + `get_symbol(id)`）。原型与正式系统共用，避免符号定义散落多份。

| 符号 id | 名称 | 单格效果（出现 n 次则 ×n） | kind | 来源倾向 |
| --- | --- | --- | --- | --- |
| 0 ⚔️ | 斩击 | 造成伤害（基础值×n） | damage | 铁剑、战斧、匕首 |
| 1 🔫 | 射击 | 造成伤害（远程，基础值×n） | damage | 手枪、冰枪 |
| 2 🔥 | 燃烧 | 叠加 Burning 层数（每层每回合 DoT） | status(burn) | 火焰剑、火焰杖 |
| 3 ❄️ | 冰霜 | 叠加 Frost 层数（每层每回合 DoT；正式版改为减速/冻结） | status(frost) | 冰枪 |
| 4 ☠️ | 毒素 | 叠加 Poison 层数（每层每回合 DoT） | status(poison) | 毒匕首 |
| 5 🛡️ | 格挡 | 获得护盾值，抵消敌人下次攻击 | shield | 通用 |
| 6 ❤️ | 治疗 | 回复 HP | heal | 通用/套装 |
| 7 💥 | 特殊 | 触发武器爆发（大伤害）；**需 3 格全同** | special | 武器专属（火焰杖/火焰剑带 SPECIAL 权重） |
| 8 🗑️ | 废铁 | 无效果，占格；可被「净化」清除 | trash | 敌人干扰注入 |

### 3.4 连线与倍率规则

- **单符号必结算（方案 A）**：一行 3 格中，每个**非垃圾符号**都按其基础值结算（斩/射 造成伤害 / 格挡 加护盾 / 治疗 回血 / 燃烧·冰霜·毒素 叠状态）。不再要求"≥2 同"才触发，保证**每轮都有正反馈**。
- **匹配 = 连击倍率**：某符号在行内出现 `n` 次 → 该符号本轮产出 **×n**（n=1 基础、n=2 ×2、n=3 ×3）。凑出 2/3 同的回合明显更强，匹配仍是核心策略。
- **特殊符号（💥/SPEC）仍需 3 格全同**才触发大招（单颗/双颗不触发，避免特殊技过于廉价）。
- 垃圾（🗑️/junk）仍是唯一"零产出"，故敌人"注废"干扰更具威胁，干扰机制地位上升。
- 暴击：WeaponData 配置暴击率/暴击倍率，命中Puncture/Slash时按 DamageSystem 既有规则结算。

### 3.5 锁定机制：已移除

- **决定**：经原型验证，手动锁定（lock）是"为防崩溃而加规则、又需新规则防它崩溃"的负收益机制。本玩法的深度来自 **配装（符号池） + 消耗品（重转/净化/强袭） + 敌人干扰**，不需要逐格锁定的微观操作。
- **每回合 = 纯 SPIN + 结算**：所有格每回合重新随机，无手动锁定、无锁定额度、无 TTL。
- **玩家每回合的"操作感"改为**：① 进场前的**配装**（选哪几把武器 = 转轮里有哪些符号）；② 战斗中使用**消耗品**主动操作转轮（详见 4.1 与 M3 干扰反制）；③ 针对敌人干扰意图做 read & counter。
- 原"锁死全盘导致数值崩溃"的风险随之消除。

### 3.6 敌人干扰转轮（灵魂机制）

敌人不再只是"掉血条"，而是**主动破坏你的转轮**：

| 干扰类型 | 表现                      | 应对              |
| ---- | ----------------------- | --------------- |
| 锁轮   | 冻结 1 个转轮本回合（不能旋转，强制坏运气）   | 用「冰霜/反制」降低其强度   |
| 注废   | 向随机格注入 🗑️ junk         | 携带「净化」符号或「格挡」扛过 |
| 乱权   | 临时改变某转轮符号权重（如大量塞入 junk） | 多转轮分散风险         |
| 读心   | 预知并针对你常出的符号/武器倾向削弱（如降低某武器符号权重） | 变换武器构筑 / 带不同武器 |

> 实现锚点：现有 `status_effect_component.gd` / `status_effect.gd` 可扩展为"转轮干扰效果"的数据载体；敌人 AI（`enemy_base.gd` / `ai_component.gd`）新增 `interference` 行为分支。

### 3.7 武器即转轮（WeaponData → 符号池映射）

现有 `scripts/equipment/weapon_data.gd` 与 8 个 `resources/weapon_templates/*.tres` 直接复用为"转轮定义"。**符号的统一定义见 `scripts/battle/reel_symbol.gd`（`ReelSymbol.Id` 枚举 + `CATALOG` 字典），武器只持有符号 id 与权重，不重复定义符号本身。**

- 每把武器新增字段（M1 已落地）：
  - `reel_symbols: Dictionary` —— key = `ReelSymbol.Id` 整数（0–8），value = 权重(float)。合并多把武器时按符号 id 累加权重，即"带哪把武器 → 该符号在转轮里更容易出现"。
  - `special_symbol: int` —— 该武器签名特殊符号的 `ReelSymbol.Id`（-1 表示无）。当前仅作记录，M3 接入"武器专属 special 效果"时使用。
  - （原 `reel_count` 字段未实现：每把武器固定提供 1 个转轮，转轮数 = 带入武器数，无需额外字段。）
- **带入模型（无职业、自由构筑）**：开局在「整备界面」从已解锁**物品池**中**自由勾选**要带入地牢的物品，不限定种类与数量（仅受容量约束，见 4.1）。其中**每把武器 = 1 个转轮**，其余物品（消耗品/护符）不占转轮、提供主动或被动增益。推荐带 3 把武器以构成默认 **1 行 3 格**，但可自由增减（转轮数随武器数伸缩）。
- 副手/主手概念取消；`PlayerConfig.starting_weapon_*` 不再使用，改由对局开始时的"整备/选物"界面决定（沿用 `weapon_component.gd` 双锚点系统仅作对决布阵展示）。

武器场景（8 个 `.tscn`：iron_sword/pistol/fire_sword/flame_staff/ice_gun/battle_axe/dagger/poison_dagger）的视觉表现（GripPoint/region_rect 已就位）继续在"对决布阵"界面展示所选武器。

## 四、武器装备与构筑（无职业）

### 4.1 自由带入物品（构筑核心）

- **取消固定职业**（骑士/法师/战士）。玩家不绑定角色，每局开局在「整备界面」从已解锁**物品池**中**自由勾选**要带入的物品。
- **物品三类**：
  1. **武器（转轮来源）**：每把武器 = 1 个转轮（符号来自其 `WeaponData.reel_symbols`）。带入几把武器就有几个转轮；**推荐 3 把 = 默认 1 行 3 格**。可自由带 1–5 把，转轮数随之伸缩（判定规则按转轮数自适应）。
  2. **消耗品（战斗中主动使用）**：如治疗药剂、净化弹（清 junk）、干扰弹（反制敌人干扰）。对决中按技能键使用，**不占转轮**。
  3. **护符/遗物（被动增益）**：如"抗干扰 +1""首轮免干扰""💥 触发率 +10%"。提供被动，不参与旋转。
- **携带规则（下限 + 分类容量）**——既保留自由，又杜绝废 build：
  - **硬下限：至少 1 把武器**。武器 = 转轮 = 唯一攻击手段，0 武器 = 无转轮 = 无法进攻，逻辑上必须。
  - **软下限：推荐至少 1 个消耗品**。消耗品是反制敌人干扰（注废 junk / 锁轮）的核心工具，0 消耗品 + 0 护符 = 完全无应对干扰手段、只能硬吃。先定为**推荐**（非强制），M2 试玩后再决定是否改为强制。
  - **分类容量上限**（比"每类必须 1 个"更灵活，自然避免堆满单一类）：
    | 类别 | 下限 | 上限 | 说明 |
    |------|------|------|------|
    | 武器 | 1 | 5 | 决定转轮数（默认推荐 3） |
    | 消耗品 | 0（推荐 1） | 3 | 战斗主动使用，不占转轮 |
    | 护符 | 0 | 2 | 被动增益 |
    | **总槽位** | — | **≈6** | 三类中各项之和上限，由容量硬约束 |
  - 超出某类上限则不能再带该类；总数受总槽位限制，无法"全带"。
- **构筑即策略**：不同武器符号倾向不同（铁剑偏 ⚔️、手枪偏 🔫、火焰杖偏 🔥/💥、毒匕首偏 ☠️…）；"带哪几把武器 + 配什么道具/护符"完全自由，构筑深度来自组合而非职业。
- **示例构筑**：
  - 爆发流：战斧 + 火焰剑 + 毒匕首（3 武器=1 行 3 格，多 💥/☠️）+ 净化弹（防注废）
  - 控场流：冰枪 + 火焰杖 + 手枪（3 武器）+ 干扰弹（反制锁轮）
  - 稳健流：铁剑 + 铁剑 + 手枪（3 武器，多 🛡️/⚔️/🔫）+ 护符"抗干扰+1"
  - 轻装流：单武器 + 多消耗品（1 转轮高风险高机动）
- 物品池随元进度（铁砧锻造/解锁）逐步扩充：8 把基础武器（iron_sword/pistol/fire_sword/flame_staff/ice_gun/battle_axe/dagger/poison_dagger）+ 消耗品 + 护符。

### 4.2 装备系统改造

- **保留**：EquipmentBase / WeaponData / 词缀(affix) / 套装(set) / 稀有度(rarity_table) / 掉落(equipment_drop) / 库存(equipment_inventory) —— 全部沿用。
- **接入**：词缀可附加「转轮效果」维度，例如：
  - "锋锐"：⚔️ 符号伤害 +15%
  - "净化"：每回合开局清除 1 个 junk
  - "镇定"：抗干扰 +1（降低敌人干扰强度）
  - "反制"：受到干扰时 30% 概率免疫
- 套装(set_bonus) 可设计为整体转轮风格（如"火焰套"全符号偏向 🔥/💥）。

### 4.3 锻造（forging.gd）与元进度

- `forging.gd` 已实现的锻造逻辑改造为「铁砧（Anvil）」：用单局获得的材料**锻造/升级转轮符号**、**解锁新符号**、**提升抗干扰强度/重转次数**。
- 元进度存档经 `save_system.gd`（JSON，game_data + lobby_data 分离）持久化。

## 十三、验收标准（MVP 口径）

1. 进入房间 → 开启 **1 行 3 格**转轮对决界面。
2. 玩家可 SPIN，符号正确结算伤害/状态（单符号必结算 + 匹配倍率，无锁定机制）。
3. 敌人有可见的干扰意图，并能实际影响下一轮转轮。
4. 击败敌人获得奖励（材料/符号），失败可撤离。
5. 一把武器（如 iron_sword）的转轮符号经 WeaponData 配置生效。
6. 元进度（锻造/解锁）经 save_system 跨局持久化。
