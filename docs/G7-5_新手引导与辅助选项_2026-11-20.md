## 1. 方案要求

§11.4：首局只教四件事（停符号结算 / 武器改变符号带 / 战后选择改造机器 / 敌人意图提示对策）；

## 2. 已实施

| 改动 | 内容 |
|---|---|
| 新系统 `onboarding_assist.gd` | 首局四件事提示（走 HUD._log，不弹窗，一次性、跨局保留）；contextual 提示（circuit/forge_style/signature 遇到时解释）；辅助来源标注 |
| `duel_controller.gd` | 注入 `onboarding`；首房触发"停符号/武器"两条引导 |
| `room_flow.gd` | 战后触发"选择改造机器"引导 |
| `turn_flow.gd` | 意图声明后触发"敌人意图提示对策"引导 |
| `run_telemetry.gd` | 新增 `assist_snapshot` 字段（summary 输出），与奖励数据分离 |
| `run_journal.gd` | 记录时注入 onboarding.assist_snapshot() |
| 测试 `g7_onboarding_test` | 27/0：四件事一次性/contextual/三种辅助来源(default/assist/reward)/遥测 assist 字段 |

**辅助来源判定**：
- `default`：control 预设且无 slow_ramp 奖励卡
- `assist`：玩家主动切到 readable 预设（辅助选项）
- `reward`：slow_ramp 奖励卡生效（奖励）

这样遥测能区分"玩家主动开辅助" vs "奖励给了缓速"，不再混在一起。

## 3. 边界与说明

- 引导走 `_log` 文字提示，不新增弹窗/遮挡——符合"不堆教程弹窗"
- contextual 提示（回路/铸式/签名）只提供文本 API，触发接线在玩家实际遇到这些内容时调用（当前接入了首局四件事的触发点）
- 辅助来源标注依赖现有 `reel_controls.slow_ramp` 与 `readability.preset`，未改这两个系统的行为
