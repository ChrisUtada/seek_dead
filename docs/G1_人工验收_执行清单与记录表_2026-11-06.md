## 0. 快速开始（5 分钟）

1. **备份存档**（测试机自己跑时）：
   
   ```text
   %APPDATA%\Godot\app_userdata\Seek Dead Prototype\lobby_data.json
   ```
   
   复制到桌面，命名为 `lobby_data_20261106_backup.json`；全部测完再还原。
   
   > 给外部测试者时不要还原：那是他们的真实进度，只备份不覆盖。
2. **启动**（`build/ACT1_Demo_2026-11-06_board/` 内）：
   - 线性：双击 `启动_线性模式.bat`（或 exe 本体）
   - 棋盘：双击 `启动_棋盘模式.bat`（或 exe `-- --board`，或整备底栏「🗺 棋盘」）
3. **确认版本**：
   - 整备底栏应有「🗺 棋盘」按钮；
   - 线性进战斗后 HUD 显示「ACT I · 房 x/8」；
   - 棋盘进战斗后 HUD 显示「ACT I · 第 x/12 格」。
     任一不符，停止并回报，不要继续记数据。
4. **测试顺序**（建议分三天，避免疲劳污染）：
   
   | 时段      | 内容                       | 局数   |
   | ------- | ------------------------ | ----:|
   | 第 1 次   | G1-01 线性 + 顺带 G1-02 三槽观察 | 3 局  |
   | 第 2 次   | G1-03 棋盘                 | 4 局  |
   | 第 3–4 次 | G1-04 目押 A/B（6 + 6）      | 12 局 |
5. **为什么不要一次跑完**：G1-01 判难度、G1-04 判目押，疲劳会显著改变停轮率与自评，必须分开。

## 1. 通用规则（所有 G1 子项）

- 默认配装；不摇铁砧、不花局外点数、不改设置。
- **G1-01 / G1-02 / G1-03 不按 F8**（保持 `control` 预设）；F8 只在 G1-04 的局间切换。

## 4. G1-03 · M2 固定棋盘真人验收

### 4.1 执行

- 4 局，全部用棋盘模式（`启动_棋盘模式.bat` 或整备开关）。
- 掷 1D3 = 1–3 步，逐格结算；遇到战斗会先弹确认层，点「进入战斗」才开打；商店/休整处理后点「继续」走剩余步数。
- 尽量覆盖：高点数快速路线 / 低点数长路线 / 两段岔路的不同选择 / 商店与休整。
- 每局记录骰子走势与经过节点，不要只记结果。

### 4.2 每局遥测

| 项                        | B1  | B2  | B3  | B4  |
| ------------------------ | --- | --- | --- | --- |
| 骰子序列（如 3-1-2-1-3-2）      |     |     |     |     |
| 实际经过节点（12 格）             |     |     |     |     |
| 岔路 A（上路 / 下路）            |     |     |     |     |
| 岔路 B（两个尾路各通向哪个 BOSS）     |     |     |     |     |
| 最终 BOSS（四个中的哪一个）         |     |     |     |     |
| 战斗场数（普通 / 精英 / BOSS）     |     |     |     |     |
| 获得的武器 / 护符               |     |     |     |     |
| 总时长（分钟）                  |     |     |     |     |
| 是否软锁 / 无法继续              |     |     |     |     |
| 是否重复结算同一节点               |     |     |     |     |
| 战斗 / 商店 / 休整后是否正确回棋盘     |     |     |     |     |
| 战斗前确认层是否看清敌人 / HP / 属性   |     |     |     |     |
| 剩余步数「继续」是否清楚             |     |     |     |     |
| 岔路是否提前看到下游 BOSS（名字 + 元素） |     |     |     |     |
| 移动与骰子动画是否拖沓              |     |     |     |     |

### 4.3 专门对照（每局结束后答）

1. 这局你**主动想走**哪个节点？为什么？（如果只跟着骰子走，记「无」）
2. 分支（商店 vs 休整）有没有犹豫？最后选了哪个？
3. 跳过战斗是好事还是坏事？你能说清代价吗？
4. 如果只能改一件事，你希望骰子/落点/动画怎么改？

### 4.4 判定

**通过（4 局中至少 3 局）：**

- 无软锁、无重复结算、返回状态正确；
- 掷骰、逐格移动、分支落点在无解释情况下可理解；
- 战斗前确认层能看清敌人、HP、攻击与属性，不会误点也不会嫌多余；
- 岔路能看到下游 BOSS 的名字与元素，选择不是盲盒；
- 武器/护符格展示的就是落地所得；
- 一局只结算一个 BOSS，未走的尾路不结算；
- 没有出现四条尾路中某一条明显更优（战斗数、难度、奖励大致对等）。

**失败分支：**

| 现象            | 动作                               |
| ------------- | -------------------------------- |
| 某条尾路明显最优      | 先查该路战斗数/奖励是否与其它路对等，不改 BOSS 数值    |
| 四个 BOSS 强弱差明显 | 记录具体 BOSS 与 ria，评审其机制/基础值，不做全局缩放 |
| 玩家只看骰子不选路     | 检查岔路 BOSS 信息是否可见、是否被读长文本淹没       |
| 动画拖沓          | 先修动画时长，不改规则                      |
| 「继续」被误认为重新掷骰  | 补文案或把剩余步数移到按钮上，不改步数规则            |
