# 像素小人 生成与接入 标准流程（AI 生成管道）

> 状态：**📋 流程定稿（2026-09-22）**——《武器小人化方案》的动画化补充与工程落地规范。
> 目的：让后续每一批 AI 生成的小人素材都走同一条管道，产出风格统一、即插即用的资源。
> 既有先例：玩家立绘 knight1-5.png（48×48，5 帧挥剑，BattleAnimator 逐帧换 texture，commit c1c0bf8）；BOSS 立绘 bossbf.png 48×48；预览脚本 `.workbuddy/knight_sheet.py`。

---

## 0. 动画分档（哪些角色做哪些动作）

| 档位 | 动作 | 适用对象 | 触发点 |
|---|---|---|---|
| **核心集**（标配） | 待机 idle（2-4 帧循环）、攻击 attack（4-6 帧单次） | 全部武器小人、系别符号小人 | 待机=常驻默认态；攻击=转轮按停→`combat_system` 的 `play_attack` 钩子 |
| **扩展集**（按需） | 受击 hit（2 帧）、死亡 death（3-4 帧）、奔跑 run（4-6 帧循环） | 仅"有生命的单位"：玩家化身（L3）、敌人、未来随从/宠物（T31） | 受击=承伤；死亡=HP 归零；奔跑=移动演出（当前无此场景，**暂缓**） |
| **符号格**（静态） | 无动画（或 2 帧呼吸） | 转轮符号格 16×16 图标 | 格子小、转动快，动画无辨识度收益 |

原则：**没有触发点的动作不生成**——死素材占成本、占验收精力。扩展集等对应功能立项后再补。

---

## 0.5 动作原型（anim_class）：近战/远程与武器个性化（2026-09-22 定稿方向）

**核心原则：不给每把武器做独有动画，而是动作原型分桶制**（参考怪猎/黑魂 weapon class）——同原型武器共享「帧时序 + 位移曲线 + 特效规则」，小人外观各自不同、动作编排复用。个性化通过有限维度参数化表达，保证成本与验收口径都可标准化。

### 0.5.1 原型分类表

| anim_class | 例子 | 帧数 | 动作特征 |
|---|---|---|---|
| `melee_light` | 匕首、短剑 | 3-4 | 快挥，突进大，屏震弱（~2.0） |
| `melee_heavy` | 大剑、战锤 | 5-6 | 前摇占比大，命中定帧 + 强屏震（~6.0） |
| `melee_long` | 长枪、长柄 | 4-5 | 直刺（非挥砍），轨迹平直，命中点更远 |
| `ranged_cast` | 法杖 | 4-5 | 原地不突进，举杖前摇→发射帧，命中特效在敌人侧 |
| `ranged_shoot` | 弓弩（如有） | 4-5 | 拉弦姿态，箭矢投射物 |

- **首批只落地 3 类**（`melee_light` / `melee_heavy` / `ranged_cast`）试跑，验证后补全——不要一次设计十类。
- 现有武器的分类归属表待排（排定后作为本节附表）。

### 0.5.2 三个差异化维度的表达方式

1. **重量 → 用相位占比表达，不用总时长**（所有类共用 0.35s 战斗窗口）：
   - 重武器：前摇帧占 ~60%（拖着抬不起）→ 挥出仅 1-2 帧（一旦挥出极快）→ 命中定帧 + 强屏震
   - 轻武器：前摇 ~20%，挥程流畅，屏震弱
   - 屏震强度数值按类入动作谱（knight 先例 `PLAYER_IMPACT_SHAKE=4.0` 即中位值）
2. **长度 → 武器像素长度规格化**：短 ≤12px / 中 16-20px / 长 24-30px。长度影响命中帧的**触及偏移量**（长枪命中点比匕首靠敌侧多偏 8-10px），偏移量入动作谱。AI 生成时武器长度须在 prompt 中明确给像素数，否则同一名称的武器张张长短不一。
3. **近战/远程 → 最大区别是位移与特效归属**：近战 = 突进 + 己侧挥砍特效；远程 = 原地 + 投射物。

### 0.5.3 投射物独立素材层

远程武器的投射物**与小人分离、独立成素材层**：
- 规格：8×8 ~ 16×16，2-4 帧循环，调色板量化同样适用
- 由演出层驱动飞行（速度/轨迹为动作谱参数），小人只负责"发射帧"姿态
- **跨武器复用**：一个火球素材服务所有火系法杖；AI 也画不好飞行轨迹，分离正好扬长避短

### 0.5.4 数据层与动作谱

- `WeaponData` 新增 `anim_class` 字段（枚举字符串，默认 `melee_light`）。
- 演出层为每个 anim_class 存一张**动作谱**：帧数、各相位时长占比、位移曲线、屏震强度、命中特效类型/位置/触及偏移、投射物引用与弹速。
- **可选优化**：`combat_system` 目前写死 `await 0.35s`，可改为读当前武器 `anim_len`（默认 0.35）——重武器将来想做 0.45s 蓄势大招时不用动战斗逻辑。一期用相位占比即可，不急着改。

### 0.5.5 对管道的连带要求

- prompt 模板的 `[动作描述]` 段**按 anim_class 预写英文描述块**（含重量词 `heavy slow windup` / 轨迹 `wide arc` vs `straight thrust` / 武器像素长度），生成时按武器的类拼入模板。
- §5 验收清单对应一项："动作符合其 anim_class 动作谱（帧数/相位/突进/屏震/触及偏移）"。

### 0.5.6 明确不做

- **不做 per-weapon 独有动画**（传说级武器如需再说）：成本爆炸且验收口径无法标准化
- idle 不搞类差异：顶多重武器拄地、轻武器垂手两个变体，不值得分桶
- 重量/长度差异只作用于 attack（奔跑/受击/死亡维持 §0 原判，武器小人无触发点）

## 1. 素材规格（硬规范）

| 项 | 规范 | 理由 |
|---|---|---|
| 画布 | **48×48 px**（战斗/卡面主规格）；转轮符号格图标 **16×16** 独立简化版 | 与 knight/bossbf 同规格；48→16 非整数缩放会糊，符号图标单独画 |
| 格式 | PNG，RGBA，**透明背景** | 与现有素材一致 |
| 缩放 | 全程 **NEAREST**（硬边），素材本身不抗锯齿 | 复古掌机视觉基调（viewport 480×270 + nearest） |
| 锚点 | 角色**脚底对齐底边、水平居中**，四周留 1-2px 安全边距 | 帧间/角色间切换不跳位；战斗 HUD 盒子 48×60 直接容纳 |
| 朝向 | 统一朝右（攻击动作向右挥） | 与 knight 挥剑方向一致 |
| 帧文件 | 逐帧单文件：`{角色名}/{动作}_{两位序号}.png`，如 `flame_sword/idle_01.png` | knight1-5.png 先例；比 spritesheet 更易逐帧返修 |

### 1.1 风格基准：`assets/char.png`（2026-09-22 用户拍板）

**项目像素小人的风格以 char.png 为唯一基准**，其特征即验收口径：

- **限制色数**：单角色 10 色上下（char.png 全图仅 9 色）——不许厚涂、不许渐变堆色
- **平涂 + 极少阴影**：大色块构成，至多 1 层暗部；禁止抗锯齿过渡色
- **1px 暗色描边**（char 用 #3f2631 暗红褐，非纯黑）
- **哑色（muted）气质**：低饱和、略偏暗的配色，与 UI 复古掌机基调同源
- **chibi 比例**：头身比约 1:1 ~ 1:1.5，剪影优先于细节

⚠ 反面教材：knight1-5.png / bossbf.png 是 AI 厚涂噪点风（503 / 435 种颜色），**仅作 48×48 画布规格与动作幅度参考，风格一律不作基准**；生成时拿它们当风格参考图 = 方向性错误。

## 2. 调色板（风格统一的核心手段）

AI 每次生成的色感必然漂移，**统一靠调色板强约束，不靠 prompt 祈祷**：

1. 维护一份项目调色板文件 `assets/characters/palette.png`（每色一格 8×8 色块的 PNG，同时给 AI 当参考、给后处理当量化目标）。
2. 初版色数 ≤ 24，含：六系主色（火/冰/毒/光/暗/无，与元素克制 HUD 配色同源）+ 通用肤色/金属/木/暗部/高光。
3. **每个角色的主色 = 其系别色**——转轮格上"看颜色辨系别"的克制可读性闭环（《武器小人化方案》§3 的拍板）。
4. 所有入库素材必须经后处理**量化到调色板**（见 §4），不允许出现调色板外的颜色。

## 3. AI 生成环节

### 3.1 输入物（每次生成前备齐）
- **风格锚点图**：`assets/char.png`（唯一风格基准，见 §1.1——喂给 AI 锁「限制色/平涂/哑色/1px 描边」）。knight1.png 仅当需要演示 48×48 构图/动作幅度时作辅助参考，**不得作风格参考**。
- **调色板文件**：palette.png（要求模型仅使用其中颜色；板的核心 9 色即 char.png 原色，用色气质天然对齐）。
- **角色描述卡**：一句话身份 + 系别 + 标志性轮廓（如「火焰大剑：宽刃、刃身缠绕火苗、系别色红橙」）。轮廓优先于细节——48×48 下细节全丢，**剪影可辨**才算成功。

### 3.2 Prompt 模板（按需翻译给具体模型）
```
pixel art character sprite, 48x48 canvas, transparent background,
very limited color count (about 10 colors per character), flat colors,
minimal shading (at most one darker shade per color), no anti-aliasing,
no gradient, no painterly rendering, muted low-saturation tones,
1px dark outline, chunky silhouette, chibi proportions (head ≈ 1/2 body),
facing right, feet on bottom edge, retro handheld game style,
strictly in the style of the reference sprite (char.png),
[角色描述卡], [动作描述]
```
动作描述要点：
- 待机：2-4 帧微幅呼吸/重心起伏（位移 ≤ 1px，帧间差异宁小勿大）
- 攻击：预备→挥出→命中（特效帧）→收势，**总帧数 × 帧时长 ≤ 0.30s**（见 §5 时序约束）
- 受击：后仰 1 帧 + 回弹 1 帧即可
- 死亡：倒地 3-4 帧，末帧静止
- 奔跑：4-6 帧循环，首帧=循环接缝帧

### 3.3 生成纪律
- **🔴 同角色所有动作必须同一次会话/同一批种子族产出**——分批生成必翻车（2026-09-22 hit 批实测三重漂移：身体宽 -12%、~200 种噪点色 vs 同批 14-21 色、色相偏橄榄）。**不接受"每个动作各自生成交货"的结果。**
- **尺度控制**：生成 idle 之后的每个动作时，把 **idle 站立帧（第 1 帧）一并喂作参考图**，并在 prompt 中强调 `character must occupy the same scale and proportions as the reference idle frame`——这是防"某动作整体偏小"最有效的手段。
- 逐动作生成序列（GIF 或 PNG 序列均可，管道同等受理）；每个动作多生成 2-3 候选，人工选帧进入后处理。
- AI 直出图**绝不直接入库**——必须过 §4 后处理 + §5 验收。
- **动作翻车不重绘、不修图**：任何后处理侧的缩放/补画都会毁像素（NEAREST 非整数缩放产生不均匀像素），正确做法永远是回 AI 侧同批重生成。

## 4. 后处理脚本（Python + PIL，仿 knight_sheet.py）

建 `.workbuddy/char_pipeline.py`，对每张候选帧依次执行：

1. **裁切归一**：裁到内容包围盒 → 等比缩放到 48×48 内（NEAREST）→ 脚底贴底、水平居中放回 48×48 透明画布。
2. **背景透明化**：纯色/近纯色背景转 alpha=0（AI 常给白底）。
3. **调色板量化**：每像素映射到 palette 最近色（RGB 距离），输出合规 PNG。
4. **帧间对齐校验**：同动作相邻帧的内容包围盒底边/中心偏移 > 1px 报警（防抖动）。
5. **跨动作一致性校验**：各动作站立帧（首帧）的**身体包围盒**（掩去披风/特效身份色）与 idle 基准比较，宽/高偏差 > ±8% 报警——AI 分批生成最常见的翻车就是某个动作整体偏小/偏色（2026-09-22 hit 批实测：宽 -12%、~200 噪点色、色相偏橄榄，三重证据确认非同批产出）。持械姿态（攻击帧）只报告不告警。中招的动作**不在管道内修图**（NEAREST 非整数缩放毁像素），退回 AI 同批重生成。
6. **预览接触表**：把某角色全部动作帧排成一张放大 contact sheet（knight_sheet.py 同款棋盘格底），供人工一眼验收。

## 5. 入库验收清单（逐张过）

- [ ] 48×48（或符号格 16×16）、RGBA、透明背景
- [ ] 全部颜色 ∈ palette.png
- [ ] 脚底贴底、居中、朝右
- [ ] 帧间无 >1px 抖动（后处理校验通过）
- [ ] **跨动作尺寸一致**：站立帧身体包围盒（掩披风/特效）与 idle 基准偏差 ≤ ±8%（`cross_anim_check` 无 ⚠）
- [ ] **动作符合其 anim_class 动作谱**（§0.5：帧数/相位占比/突进距离/屏震强度/触及偏移/投射物）
- [ ] 放大 5 倍 contact sheet 目视：剪影可辨、系别主色正确、**符合 char.png 风格口径（§1.1：限制色/平涂/哑色/1px 描边）**、各动作人物一般大
- [ ] 命名/目录合规：`assets/characters/{角色名}/{动作}_{nn}.png`
- [ ] 只提交 PNG 本体——`.import` 不入库（`.gitignore` 有 `*.import`）

> **历史素材豁免**：knight1-5.png / bossbf.png 生成于调色板规则之前（实测 503 / 435 种板外色），grandfathered 不追溯；如需统一可随时过后处理量化整改。**新素材一律不许豁免。**

## 6. Godot 接入（数据驱动 + 演出层）

### 6.1 数据层
- `weapon_data.gd` / `symbol_data.gd` 新增字段（《武器小人化方案》§5 已定 `character: Texture2D`；动画化升级为 **frame 数组或 SpriteFrames**——推荐 `SpriteFrames`，编辑器可预览、帧时长可视化）。
- `weapon_data.gd` 另增 `anim_class` 字段（§0.5：动作原型分桶，默认 `melee_light`）——演出层按类查动作谱，武器只声明自己属于哪类。
- 空值回落：无素材 → 回落系别默认小人 → 再回落 emoji（**任何一批素材没铺完都不破旧表现**，分批上量的前提）。

### 6.2 演出层
- 复用 knight 先例：`battle_animator.gd` 逐帧换 texture 模式；角色多了之后可平移到 AnimatedSprite2D，但**播放控制仍收在演出层，战斗逻辑零改动**。
- 渲染位优先级（对齐《武器小人化方案》§6）：① 卡面四卡（整备/商店/奖励/铁砧）→ ② 转轮格静态图标 → ③ L2 战斗随行（攻击动画的主舞台）。

### 6.3 🔴 三条铁律（违者必出事故）
1. **演出绝不消耗全局 RNG**——任何动画随机（抖动、粒子、帧长抖动）一律走本地 `RandomNumberGenerator` 实例（`BattleAnimator._rng` 先例）。全局流是种子局唯一随机源，动它 = 同种子不同局。
2. **攻击动画总时长 ≤ 0.35s**——`combat_system.gd` 在 `play_attack` 后 `await 0.35s` 进敌人回合。改帧数/帧长必须同步核对该窗口（knight 5×0.06=0.30s 是贴线值）。
3. **tscn 手写规范**——不给 `instance=ExtResource` 实例内写覆盖子节点（项目铁律 #1）。
