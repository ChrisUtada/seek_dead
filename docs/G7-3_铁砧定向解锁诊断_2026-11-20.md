## 2. 方案要求（§10.1 / §13.4）

**保留**：`owned_*`、图鉴、生涯、铸式、来源记录、已有收藏。
**删除或退役**：点数 drip、随机摇奖、空白、随机保底、重复返还、相关假三选一。

**新模型**：条件解锁 + 定向选择
```
击败 Boss / 达成生涯行为 / 完成武器挑战
→ 解锁一个明确的新武器、护符、技能或铸式
→ 图鉴展示新玩法与下一目标
→ 下一局可选择新的开局路线
```

**老存档原则**：
- 已解锁内容绝不回锁
- 已有点数不清空；推荐**每 10 点折算一次玩家自选定向解锁**，用完后退休旧字段
- §13.4 前置：所有点数来源与空池兜底已迁移

## 3. 关键决策点（方案未给具体数值，需拍板）

| 决策点 | 选项 | 建议 |
|---|---|---|
| 解锁条件 | 击败 Boss / 生涯行为 / 武器挑战 | 按武器/护符/技能分类挂不同条件；Boss 遗物走既有 Boss 战利品 |
| 点数折算比 | 每 10 点一次自选 | 方案推荐值，直接采用 |
| 旧 gacha 处理 | 彻底删除 / 保留兼容开关 | 彻底删除更符合方案，但需处理老存档点数 |
| 空池兜底 | 无目标时给什么 | 方案要求"空池兜底已迁移"；可给定向通用解锁或点数保留 |
| UI | 现有 anvil_screen 改造 / 新建定向解锁屏 | 现有屏改造，减少 UI 工作量 |

---

## 4. 风险

- 核心 gacha 重写，涉及点数经济 + 收藏 + 老存档，风险高（同级 G6-1 / G7-2）
- 老存档点数折算若处理不当会"点数消失"（§风险表明确的坑）
- 空池兜底未迁移会导致"解锁屏空屏"

---

## 5. 建议推进方式

G7-3 是"改造"而非"删除强度"，风险低于 G7-2，但仍需分步：
1. 先定 §3 的决策点（用户拍板）
2. 实现定向解锁核心（条件判定 + 定向选择 + 点数折算），保留旧 gacha 作为兼容开关
3. 处理所有点数来源（清房/返还/里程碑 → 新语义）
4. 老存档迁移测试（不回锁、点数折算、空池兜底）
5. UI 接入 + 全量测试
