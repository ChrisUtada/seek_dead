# Seek Dead · 棋盘探索、战后成长与局外生涯制作执行方案

> 状态：设计定稿建议，待原型验证，未实施  
> 制定日期：2026-11-05  
> 当前基础：ACT1 Demo、历练/技艺、武器熟练/铭印、奖励前置确定、新档收藏、铁砧与图鉴  
> 前置条件：先完成 P0-1 难度与 P0-2 成长感知复测；本方案不替代当前战斗核心  
> 核心结论：**棋盘负责路线与探索，战后成长统一奖励与养成，局外生涯负责收藏和下一局目标。三者共享装备与构筑信息，但不重复发放奖励。**

---

## 1. 文档目的与范围

本方案整合以下内容：

1. 将普通房/精英房奖励、角色技艺和武器铭印合并为一次“战后成长”选择。
2. 将线性遇敌改为轻量大富翁式棋盘移动，增加可见奖励与路线选择。
3. 在棋盘中提供稀缺、提前可见的武器和护符奖励。
4. 建立以图鉴、生涯成就、定向解锁和横向铸式为主的局外成长。
5. 保持现有转轮战斗、双武器、元素、装备和数值体系不被无关重构。

不覆盖美术全面量产、完整 GAME+、BOSS RUSH、第二行转轮或新增主动战斗按钮。

---

## 2. 设计目标与体验闭环

### 2.1 四层目标

| 层级 | 玩家行为 | 体验目标 |
|---|---|---|
| 单次移动 | 掷骰/选择路线 → 看向落点 | 我知道自己在追什么，而不是纯随机漂移 |
| 单场战斗 | 目押 → 结算 → 战后成长 | 每次胜利都推进 Build |
| 单幕棋盘 | 规划奖励与战斗路线 → 击败 BOSS | 探索路线与构筑相互影响 |
| 多局生涯 | 解锁装备/铸式/成就 → 尝试新路线 | 下一局有具体新目标 |

### 2.2 完整闭环

```text
棋盘看到装备/敌人/分支
→ 掷骰并选择可到达路线
→ 战斗、商店、休整或直接拾取
→ 战斗后统一选择补给/构筑/成长
→ 击败本幕 BOSS 并获得专属奖励
→ 新装备写入图鉴，生涯成就推进
→ 下一局出现新的武器、路线与构筑目标
```

### 2.3 体验验收口径

玩家在完成一幕之后应能回答：

- 我在棋盘上主动追逐了哪件物品或哪条路线？
- 我这局的两把武器和成长方向是什么？
- 我获得了什么新收藏，下一局想尝试什么？

## 3. 现有系统复用与边界

### 3.1 必须复用

- `RoomData`：普通、精英和 BOSS 战斗内容。
- `ReelSystem`、`CombatSystem`：实体带子与战斗结算，不改核心。
- `GrowthSystem`：历练等级、技艺候选与已获得技艺。
- `WeaponMastery`：武器熟练、铭印候选和运行时铭印。
- `RewardSystem`：具体奖励前置、权重、武器/消耗品获取与替换。
- `ShopSystem`：商店购买、卖出、刷新与价格。
- `MetaStore`、`AnvilSystem`：局外收藏、点数、保底和图鉴里程碑。
- 现有图标、Theme 和 480×270 布局。

### 3.2 禁止借机修改

- 不修改伤害公式、暴击、元素克制、充能或装备基础数值。
- 不增加每次正常旋转的金币费用。
- 不恢复旧训练点、四轨属性或金币升级。
- 不让棋盘动画消耗全局 RNG。
- 不让棋盘装备格绕过双武器/护符上限。
- 不让 BOSS 信物进入普通棋盘格或铁砧池。
- 不在原型中增加局内中途存档；局外收藏和成就继续正常落盘。

## 4. 战后成长统一规则

### 4.1 基本原则

普通房与精英房胜利后，只显示一次“战后成长三选一”。角色技艺、武器铭印不再打开独立成长窗口。

**历练和熟练仍负责成长节奏，但选择入口并入战后成长。**

### 4.2 三槽结构

| 槽位 | 定位 | 内容范围 |
|---|---|---|
| 补给位 | 保证生存和资源下限 | 治疗、最大 HP、下一房护盾、金币、具体消耗品 |
| 构筑位 | 推进武器与符号组合 | 具体武器、真实符号增格、换装、商店折扣/刷新、共鸣相关强化 |
| 成长/变化位 | 形成路线或应对下一步 | 角色技艺、武器铭印、下一房对策、少量规则变化 |

不得简单地把所有内容放进同一个随机池。每次必须按槽位生成，避免三张都是治疗、金币或同义数值卡。

### 4.3 成长触发与排队

- 房间胜利后先自动结算历练与武器熟练。
- 达到 Lv.2/Lv.4 时，角色技艺进入成长位。
- 达到 R2/R3 时，对应武器铭印进入成长位。
- 一次战后成长最多选择一项，包括成长卡。
- 同一房触发多个成长时按触发先后排队；未选择的成长进入下一战斗房的成长位，不额外增加战力次数。
- 成长位不能因另一项成长而出现“必须放弃全部补给”的隐藏规则；补给位和构筑位仍正常生成。
- BOSS 战后不显示普通三选一，直接保留专属战利品；未处理成长进入下一幕首房成长位。

### 4.4 候选合法性

所有候选必须遵守：

- 展示前确定具体对象，确认后不再随机。
- 显示当前值 → 选择后值，包含真实转轮格数变化。
- 满血时不提供完全无效的普通治疗；可以换成最大 HP、护盾或其他补给。
- 腰带满时明确显示替换或折算金币，不在选择后静默失败。
- 武器满双武器时进入替换预览。
- 调律、共鸣和符号强化若没有实际效果则不得入池。
- 当前 Build 无法触发的效果不得作为伪选项。
- 同一屏不出现重复 ID 或只改文案的同义卡。

### 4.5 推荐候选池

#### 补给位

| 内容 | 规则 |
|---|---|
| 治疗 | 按现有比例恢复；有实际恢复空间才出现 |
| 最大 HP | 使用现有上限成长与恢复规则 |
| 下一房护盾 | 进入下一战斗房生效，文案明确时机 |
| 金币 | 固定数值，不伪装成构筑成长 |
| 具体消耗品 | 展示物品、次数和腰带处理 |

#### 构筑位

| 内容 | 规则 |
|---|---|
| 具体武器 | 展示元素、攻击、命中、符号带与替换得失 |
| 符号灌注 | 展示具体符号和真实格数变化 |
| 武器熟练追赶 | 只在近期换装且存在追赶需求时出现 |
| 商店刷新/折扣 | 作用于下一次商店，不新增货币 |
| 共鸣强化 | 必须显示实际激活或数值结果，禁止死效果 |

#### 成长/变化位

| 内容 | 规则 |
|---|---|
| 角色技艺 | 使用现有技艺和完整前后预览 |
| 武器铭印 | 使用现有锋铸/调律及实际武器变化 |
| 下一房对策 | 根据已知下一战斗节点提供真实可用的消耗品/护盾等 |
| 特殊变化 | 原型阶段不做诅咒和献祭，后续单独评审 |

### 4.6 战后成长界面

- 标题：`战后成长 · 选择一项`。
- 页头保留当前历练、熟练、技艺和铭印摘要。
- 三张卡分别显示槽位标签、具体图标、名称、核心效果和前后变化。
- 卡片不堆长段说明，完整内容走 tooltip。
- 确认按钮固定，不被长文本挤出画面。
- 跳过可保留，但必须明确“放弃本次成长”，避免误点。

## 5. 棋盘移动规则

> **2026-11-06 修订（已实施）**：1D3 从「落点」改为「步数预算」——掷出 1–3 后逐格前进、逐格结算，
> 不再按落点跳过中间节点；遇到战斗/商店/休整停下，处理后继续剩余步数。
> 拓扑同时改为 21 节点 / 两段岔路 / 4 个 BOSS 结局（见 §7.1 修订）。
> 下文 §5.1–5.3 为初版规则，保留作历史对照。

### 5.1 原型规模

- 每幕 12 个节点（含起点与 BOSS）。
- 玩家实际经过约 7–8 个节点后抵达 BOSS。
- 棋盘至少一处分支，之后汇合到 BOSS 前主路。
- 只允许向 BOSS 方向移动，原型不做倒退和绕圈。
- 节点结算后被消耗，不允许重复刷奖励。

### 5.2 掷骰与路径选择

- 每次移动使用 **1D3**，结果为 1/2/3 格。
- 掷骰前玩家可以查看棋盘、节点与当前构筑。
- 掷骰后高亮所有合法落点；只有一个合法落点时自动选中。
- 有分支时由玩家选择合法落点，而不是系统随机选路。
- 超过 BOSS 时停在 BOSS，不做过头反弹。
- 原型不提供骰子重摇、改点或额外移动道具，避免与商店/技艺产生新消耗体系。
- 移动和骰子动画可跳过，不消耗额外等待时间。

### 5.3 移动时序

```text
棋盘待机
→ 玩家点击“前进”
→ 生成 1D3 结果（全局游戏 RNG，种子可复现）
→ 高亮合法落点
→ 玩家选择落点
→ 棋子移动（纯视觉）
→ 执行落点效果
→ 返回棋盘待机或进入战斗/商店/休整
```

落点效果必须在移动动画结束后只执行一次，重复点击不能重复触发。

### 5.4 动画时间规范

- 骰子反馈建议 0.2–0.4 秒。
- 棋子每格约 0.08–0.12 秒，总移动不超过约 0.5 秒。
- 直接拾取与节点信息出现不额外强制等待。
- 所有动画使用本地 RNG 或无随机，不能改变游戏种子流。

## 6. 棋盘节点内容与掉落规范

### 6.1 节点类型表

| 类型 | 数量建议（12 节点） | 结算内容 |
|---|---:|---|
| 起点 | 1 | 无效果 |
| 普通战斗 | 4 | 现有 RoomData + 战后成长 |
| 精英战斗 | 2 | 现有精英房 + 战后成长 + 既有精英掉落 |
| 武器格 | 1 | 提前可见的具体武器，直接获得/替换 |
| 护符格 | 1 | 提前可见的具体护符，直接获得/替换/折算 |
| 商店格 | 1 | 打开现有商店，无战斗奖励 |
| 休整格 | 1 | 恢复 25% 最大 HP，不提供额外奖励 |
| BOSS | 1 | 现有 BOSS 战与专属战利品 |

棋盘生成只保证节点总量与可达性，不保证玩家一幕内吃完全部奖励。

### 6.2 武器格

生成时：

- 从当前幕可用武器池按既有获取权重抽取。
- 优先展示当前未装备且能与当前 Build 形成明确差异的武器。
- 不使用 BOSS 专属限定或当前 Demo 白名单之外的物品。
- 展示图标、名称、元素、稀有度、攻击、命中和主要符号。
- 玩家移动前就能查看完整 tooltip。

落地时：

- 直接获得该武器，不再随机。
- 双武器未满则入槽；满槽进入已有替换预览。
- 替换显示旧武器损失、新武器熟练追赶、真实带子和共鸣变化。
- 获得后写入本局装备和局外收藏，保存时机沿用现有规则。
- 节点随后标记为已消耗。

### 6.3 护符格

- 从当前幕合法护符池抽取，排除 BOSS 信物。
- 提前展示具体物品和完整效果。
- 护符未满则入槽；满槽提供替换或折算金币。
- 不直接提高护符上限，不绕过 CHARM_CAP。
- 混合/诅咒护符必须同时展示负面，不允许只显示正面。

### 6.4 商店格

- 复用现有商店货架与刷新规则。
- 进入商店格即刷新本节点货架，离开后不产生额外战斗奖励。
- 商店价格和候选仍由当前局配置决定。
- 不把商店格当作无限制刷新点；离开后节点消耗。

### 6.5 休整格

- 恢复最大 HP 的 25%，不超过最大 HP。
- 满血时仍可选择进入，但显示“无需休整”，玩家可立即返回。
- 不额外发放金币、熟练或历练。
- 后续可扩展整备/卸下，但原型不增加功能。

### 6.6 战斗与 BOSS 格

- 普通/精英/BOSS 仍使用现有 `RoomData`。
- 战斗胜利后，普通/精英进入统一战后成长。
- BOSS 保留专属信物、主题武器和局末流程。
- 不为棋盘额外叠加一套同价值战斗奖励。

## 7. ACT1 灰盒棋盘内容

### 7.1 固定拓扑原型

> **2026-11-06 修订（已实施）**：改为 21 节点、两段岔路、4 个 BOSS 结局；
> 一局只走一条尾路、只打一个 BOSS，单局路径 12 格 / 8 场战斗。
> 四个 ACT1 BOSS 每局随机分配到四条尾路，岔路节点提前展示下游 BOSS 名字与元素。
> 实机截图见 `docs/baseline/2026-11-06_board/`。下面的 12 节点拓扑为初版，保留作历史对照。
>
> **2026-11-07 再修订（已实施）**：两条尾路的普通房与 BOSS 之间各加 1 个休整营地，共 25 节点、单局 13 格 / 8 战；
> 营地恢复 25% 最大 HP，并可花金币购买 1 件（武器/护符/消耗品各 1，买武器满槽走替换层）。
> 这样每条路线在 BOSS 前都有保底恢复与一次购物窗口；商店格仍只在上路。

第一版采用固定拓扑，只随机具体房间与物品：

```text
起点 → 普通 → 武器 → 普通 → 分支 A：商店
                         分支 B：休整
     → 普通 → 精英 → 护符 → 普通 → 精英 → BOSS
```

- 分支只影响当次一个节点，随后汇合。
- 不先做完全随机拓扑，便于判断玩法是否成立。
- 普通、精英从 ACT1 合法池抽取。
- BOSS 使用 ACT1 固定或当前合法候选规则。
- 武器、护符按 §6 生成并提前展示。

### 7.2 原型不做的内容

- 不做多方向自由移动。
- 不做循环地图和反复踩格。
- 不做骰子改点道具。
- 不做随机事件池、献祭、宝箱赌博和隐藏房。
- 不做第二幕/第三幕棋盘，直到 ACT1 验收通过。

## 8. 局外生涯与成长

### 8.1 设计定位

局外成长主要增加新选择，不提供无限永久属性。

| 线 | 内容 | 价值 |
|---|---|---|
| 图鉴 | 装备、BOSS、节点与路线记录 | 知道还差什么、去哪里获得 |
| 生涯成就 | 首次击杀、Build 挑战、棋盘路线挑战 | 提供明确下一局目标 |
| 定向解锁 | 通过 BOSS/成就选择未拥有内容 | 减少纯随机抽取挫败 |
| 横向铸式 | 有得有失的武器变体 | 同一武器支持不同玩法 |
| 身世/开局方向 | 后续候选，不进首批 | 提供不同初始路线 |

### 8.2 首批生涯成就

首批控制在 10 个以内：

| 成就 | 条件 | 建议奖励方向 |
|---|---|---|
| 初次深入 | 首次完成 ACT1 BOSS | 一次定向装备解锁 |
| 四席猎手 | 覆盖 4 个 ACT1 BOSS | 图鉴标记 + 新解锁候选 |
| 同系共振 | 同元素双武器完成一幕 | 解锁一个同系强化候选 |
| 异系调度 | 异元素双武器完成一幕 | 解锁一个充能/覆盖候选 |
| 破甲专家 | 以三连破甲击败一名 BOSS | 解锁破甲向内容 |
| 状态使徒 | 以灼烧/中毒为主要输出完成一幕 | 解锁状态向内容 |
| 坚守 | 以护盾/治疗路线完成精英或 BOSS | 解锁防御向内容 |
| 棋盘寻宝 | 主动选择并获得一个棋盘武器格 | 图鉴与定向解锁进度 |
| 高危路线 | 主动经过精英分支并完成一幕 | 高风险内容候选 |
| 特殊结局 | 后续完成非暴力和解 | 长期生涯标记 |

成就只发一次，不重复刷取。奖励内容必须真实存在，不能出现指向未制作装备的假解锁。

### 8.3 定向解锁

- 通过 BOSS、成就或挑战触发一次“未拥有装备三选一”。
- 候选只显示合法未拥有内容，并标明类别、元素和路线。
- 选择后立即写入图鉴与开局拥有池。
- 不新增解锁券货币；需要选择时直接打开解锁界面。
- 保留现有铁砧、重复返还和保底，不用定向解锁完全替代铁砧。

### 8.4 横向铸式

首批只验证 4 把代表武器：

| 武器 | 铸式示例 | 方向 |
|---|---|---|
| 火焰剑 | 烈刃：基础攻击 +2，命中 -5% | 高攻低命中 |
| 匕首 | 稳手：命中提高，基础攻击降低 | 稳定输出 |
| 战斧 | 破城：更偏三连破甲，普通攻击浓度下降 | 三连机制 |
| 霜晶法杖 | 霜鸣：更偏状态符号，直接攻击降低 | 状态构筑 |

规则：

- 每把武器最多装备一个铸式。
- 必须同时显示优势与代价。
- 必须预览真实带子变化。
- 标准形态不能成为绝对劣势。
- 首批验证通过前不扩展到全部 90 把武器。

## 9. UI 与素材制作规范

### 9.1 棋盘界面布局

沿用当前视觉语言，建议：

- 顶栏：幕、当前节点、金币与棋子状态。
- 左栏：当前双武器、技艺、铭印和关键资源摘要。
- 中央：棋盘、棋子、合法落点和移动按钮。
- 右栏：当前悬停/选中节点的名称、图标、奖励与风险详情。

不得把完整棋盘挤入现有战斗中央小区域。棋盘与战斗使用不同主视图，进入战斗再切换现有 HUD。

### 9.2 节点图形

- 节点使用 16×16 或 24×24 像素图标。
- 战斗、精英、武器、护符、商店、休整和 BOSS 必须同时用形状与文字区分，不只换颜色。
- 当前棋子、可到达、悬停、已消耗和 BOSS 使用不同边框/标记。
- 合法落点采用金色或暖白强调，已消耗节点降低亮度但仍可辨认。
- 不使用大面积光晕和持续闪烁。

### 9.3 素材规格

| 素材 | 规格 | 规则 |
|---|---|---|
| 节点图标 | 16×16 或 24×24 RGBA | 独立绘制，不从 48×48 缩小 |
| 武器/护符图标 | 沿用 16×16/24×24 | 使用现有资源与回落 |
| 棋子 | 16×16 或 24×24 | 清楚朝向与脚底锚点 |
| 棋盘连线 | 1px 暖白/灰米 | 不使用抗锯齿与渐变 |
| 奖励/状态标记 | 小型角标 | 不预烘焙进节点主图标 |

所有新增资源继续使用现有暗紫褐、暖白、金色、敌人红、生命绿和护盾蓝语义。

## 10. 技术拆分建议

### 10.1 新增模块

| 模块 | 职责 |
|---|---|
| `BoardNodeData` | 静态节点 ID、类型、房间/物品引用、连接与展示文本；消耗状态由 BoardSystem 运行时保存 |
| `BoardConfig` | 每幕拓扑、节点数量、奖励数量与生成约束 |
| `BoardGenerator` | 固定/随机拓扑、房间和装备分配、合法性检查 |
| `BoardSystem` | 当前节点、掷骰、合法落点、移动、落地一次性和节点消耗 |
| `BoardScreen` | 棋盘显示、落点选择、tooltip 和纯视觉动画 |
| `PostBattleSystem` | 战后三槽候选、成长队列、选择执行与结果预览 |
| `CareerSystem` | 成就条件、一次性记录、定向解锁与生涯查询 |

### 10.2 与现有流程的边界

- 棋盘系统只决定“接下来进入哪个 RoomData/节点”，不写战斗伤害。
- 战斗入口需要明确接收当前 `RoomData`，不要让棋盘依赖线性强索引推断最终 BOSS。
- 当前幕、已访问节点和最终战状态要有明确来源，不再用 `ROOMS.size()` 混合表达棋盘总进度。
- 下一房预告在棋盘模式由可见棋盘替代，不再叠加线性横幅。
- 既有线性模式可在迁移期保留用于测试，直到棋盘全流程通过。

### 10.3 数据与存档

- 节点和物品使用 Resource 引用或稳定资源路径，不修改共享 `.tres`。
- 棋盘运行状态包括：当前节点、已消耗节点、已生成分支、当前骰子结果和已分配物品。
- 局外存档只保存成就、收藏、解锁和铸式，不把临时棋盘动画状态写入永久存档。
- 原型不做中途退出后的棋盘恢复；该需求后续单独评审。

## 11. 制作与执行阶段

### M0 · 前置验证与冻结基线

- 完成 P0-1/P0-2 人工复测。
- 保存当前 ACT1 线性流程、回归和时长基线。
- 列出 `ROOMS`、当前房间、最终 BOSS、奖励与下一房预览的所有依赖。
- 冻结战斗数值与成长数值，避免归因混乱。

**出口**：现有系统稳定，棋盘迁移依赖明确。

### M1 · 战后成长合并

- 将普通/精英奖励、技艺和铭印合并为三槽界面。
- 实现成长队列和一次胜利只选一项。
- 保留 BOSS 专属奖励。
- 完成所有候选的具体结果与合法性检查。
- 暂时仍使用现有线性房间，便于独立验收。

**出口**：无双重成长弹窗，奖励差异和 Build 推进优于旧流程。

### M2 · ACT1 棋盘灰盒

- 实现固定 12 节点拓扑、1D3、合法落点、移动和一次性节点。
- 先接普通/精英/BOSS、商店和休整。
- 使用现有图标和简单棋子，不投入新美术量产。
- 保留线性测试入口，跑完整 ACT1。

**出口**：棋盘可达、无软锁、无重复触发，移动不拖时长。

### M3 · 棋盘装备与图鉴联动

- 接入 1 武器格和 1 护符格。
- 完成提前展示、替换/折算、熟练追赶与共鸣预览。
- 新装备正确写入图鉴与拥有池。
- 加入节点与装备来源记录。

**出口**：玩家会为了具体装备选择路线，奖励不与 BOSS 冲突。

### M4 · 最小生涯与定向解锁

- 实现首批最多 10 个成就。
- 接入未拥有装备三选一定向解锁。
- 制作 4 把武器的横向铸式样板。
- 局末展示本局路线、成长与新解锁。

**出口**：玩家能说出下一局具体目标，永久成长不形成数值义务。

### M5 · 复测与扩展决策

- 至少 3 名测试者 × 3 局。
- 检查路线选择、装备追逐、成长复述和再玩意愿。
- 通过后再制作 ACT2/ACT3 棋盘与挑战。
- 若棋盘只是增加移动时间，先修棋盘，不继续扩内容。

## 12. 测试与验收

### 12.1 自动测试

- 棋盘所有 BOSS 可达，无孤立节点和死路。
- 同种子生成相同拓扑、房间、物品和骰子结果。
- 骰子 1/2/3、分支、超过 BOSS 和节点消耗正确。
- 同一落点不能重复结算。
- 商店、休整、武器、护符和 BOSS 的进入/返回状态正确。
- 战后三槽候选合法，无死升级、空奖励和二次随机。
- 多个成长同房间触发时队列不丢失、不额外膨胀。
- 满武器/护符/腰带时替换和折算正确。
- 成就只发一次，定向解锁只给未拥有内容。
- 动画不消耗全局 RNG。
- 当前 `run_smoke.bat` 全绿，并加入新模块定向测试。

### 12.2 实机体验验收

- 玩家移动前能看懂奖励与风险。
- 玩家至少一次主动为装备或 Build 选择路线。
- 棋盘移动和骰子动画不显得拖时间。
- 玩家能复述本局 Build、成长和追逐的物品。
- 玩家结束后能说出下一局想解锁的内容。
- ACT1 仍以约 12–20 分钟为体验目标，不因棋盘明显超时。

### 12.3 停止条件

出现以下情况不进入下一幕量产：

- 骰子结果持续压过路线选择，玩家觉得没有控制。
- 棋盘移动比战斗结算更耗时。
- 装备格过多，导致 Build 频繁重置或 BOSS 奖励贬值。
- 战后成长仍然只是同义数值卡。
- 局外解锁仍然主要靠重复随机抽取。
- 玩家无法说清本局路线或下一局目标。

## 13. 最终制作原则

1. **棋盘不是另一套随机奖励机**：它必须提供可见目标和路线选择。
2. **战后成长不是第二个奖励窗口**：所有本局成长在同一个选择中完成。
3. **局外成长不是永久属性轨**：它提供新装备、新打法和新目标。
4. **装备掉落必须可见、稀缺且可处理满槽**。
5. **原型先固定拓扑、后随机拓扑，先 ACT1、后三幕**。
6. **任何新增内容都必须能回答：它如何改变本局路线或下一局目标。**

最终目标是形成：

> **看得见目标的探索 → 打得明白的战斗 → 选得清楚的成长 → 带得走的收藏 → 下一局想尝试的新路线。**
