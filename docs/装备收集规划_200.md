## 1. 稀有度体系（4 档）

本作稀有度 = **强度轴**，不定频率（`docs/[已完成]物品中心重构方案.md` 铁律：稀有度只定强度不定频率，避免「神装打不出去」）。频率由 per-item weight 自洽。

| 稀有度 | 代码值 | 定位 | 强度特征（建议方向） |
|---|---|---|---|
| 普通 | `common` | 新手骨架、开局可得 | 基线 base_power / hit_rate ≈0.85 / crit_mult=2.0 |
| 精良 | `uncommon` | 中期主力、单元素特化 | base_power ↑一档，或带一个元素/特殊符号 |
| 稀有 | `rare` | 构筑核心、机制独特 | 多元素协同 / 高 hit_rate / crit_mult 2.5 / 独特 special |
| 史诗 | `epic` | 追逐目标、Build 定义者 | crit_mult 3.0 / 复合机制 / 改变打法的「构筑支点」 |

> ✅ **代码缺口已闭合（T6，2026-08-07）**：`rarity` 现已在 `LoadoutItem`（武器/技能）与 `ItemData`（护符/消耗品）上齐备，17 个护符/消耗品 .tres 已分档；铁砧加权/dupe 返还自动生效。

### 1.1 稀有度的「三个轴」边界（铁律）
`rarity` 在本作**只管强度**（base_power / hit_rate / crit_mult 量级），但**另行驱动「获取频率」**——即商店出现率、BOSS/精英掉率（共享权重表，见 §11）。它**绝不碰第三个轴「转轮频率」**：那由每件装备自身的 `symbols[].weight` 决定（P2 装备自洽铁律）。三者正交：

| 轴 | 控制什么 | 由谁管 |
|---|---|---|
| 强度 | 数值多高 | `rarity`（本文件 §2.1 分布） |
| 获取频率 | 商店多常出现 / BOSS·精英多常掉落 | `rarity` → 共享 `acquisition_weight`（§11） |
| 转轮频率 | 装上后符号多常落在连线 | 每件装备 `symbols[].weight`（与 rarity 无关） |

> 设计红线：**获取频率可以随稀有度变稀，转轮频率绝不随稀有度变稀**。否则触发「神装稀有→符号少出现→打不出去」退化（见 `loadout_item.gd:18` 注释）。本方案保证 epic 既「难获得」又「装上照常好用」。

## 2. 总量分配（200 = 4 类 × 4 档）

设计取向：武器是「地牢式收集」的核心幻想（对标挺进地牢的枪），占近半；护符提供构筑多样性（协同/乘区），次之；技能是主动符号来源；消耗品是战术补充。

### 2.1 分类 × 稀有度矩阵

| 分类 | common | uncommon | rare | epic | 小计 | 占比 |
|---|---|---|---|---|---|---|
| **武器** | 36 | 27 | 18 | 9 | **90** | 45.0% |
| **技能** | 16 | 12 | 8 | 4 | **40** | 20.0% |
| **护符** | 18 | 14 | 9 | 4 | **45** | 22.5% |
| **消耗品** | 10 | 8 | 5 | 2 | **25** | 12.5% |
| **合计** | **80** | **61** | **40** | **19** | **200** | 100% |

全局稀有度曲线 ≈ **40% / 30% / 20% / 10%** 金字塔（epic 19 件 ≈ 9.5%）——普通装够厚作骨架，史诗装够稀作追逐。

> 说明：曲线刻意不做得更平。稀有度=强度轴下，若高稀有过密会导致「强度通胀、普通装失去存在意义」；40/30/20/10 保证每个档位都有明确的使用窗口。

## 3. 武器（90 件）细分

武器有 3 个正交维度：**元素 × 原型 × 稀有度**。用「三个独立切面」表达，落地时三者自由组合成具体武器。

### 3.1 切面 A · 元素（5 元素克制环 + 中性）
克制环：`火→冰→毒→光→暗→火`（`element_counter.gd`），中性 none 不参与克制。

| 元素 | 数量 | 定位 |
|---|---|---|
| 无元素 none | 15 | 开局/基础物理，新手友好 |
| 火 fire | 15 | 克制冰，burn 状态向 |
| 冰 ice | 15 | 克制毒，frost 状态向 |
| 毒 poison | 15 | 克制光，poison 状态向 |
| 光 light | 15 | 克制暗 |
| 暗 dark | 15 | 克制火 |
| **合计** | **90** | |

> 均匀 15/元素：保证每个元素都有足够「可被克制针对」的对策武器，克制玩法在任何 run 都成立。

### 3.2 切面 B · 原型（`Archetype`）
| 原型 | 数量 | 手感 |
|---|---|---|
| LIGHT 轻型 | 24 | 高 hit_rate / 低 base_power，快频 |
| MEDIUM 中型 | 26 | 均衡基准 |
| HEAVY 重型 | 22 | 低 hit_rate / 高 base_power / 高 crit |
| MAGIC 法器 | 18 | 元素/special 符号为主，状态向 |
| **合计** | **90** | |

### 3.3 切面 C · 稀有度
36 common / 27 uncommon / 18 rare / 9 epic（§2.1）。

> 组合示例（落地参考，非最终名单）：`火·HEAVY·rare` = 高暴击燃烧巨剑；`暗·MAGIC·epic` = 改变构筑的暗系法器。9 件 epic 应各占一个元素/原型象限的「天花板」，避免同质。

## 8. 命名与系列规范（建议）

- **系列化命名**：同元素武器用统一前缀/后缀（如 `ember_*` 火系、`frost_*` 冰系、`venom_*` 毒系、`radiant_*` 光系、`umbral_*` 暗系），便于玩家识别「这是一套对策系列」。
- **稀有度可视化**：UI 卡片按 rarity 上色（common 灰 / uncommon 绿 / rare 蓝 / epic 紫），与元素色相区分（元素色已定义于 `element_counter.gd`）——稀有度色建议用边框/角标，元素色用图标，避免冲突。
- **一装备一 .tres**：文件名 = 装备 id，蛇形小写，与现有命名一致。

## 11. 获取频率模型（稀有度 → 商店 / BOSS / 精英 共用）

现状（`duel_controller.gd`）：`_roll_shop` 用 `candidates.shuffle()` 均匀随机，`_roll_boss_rewards` 用「未持有过滤 + shuffle」，二者**都不读 rarity**。本方案改为**单一共享权重表驱动全部获取渠道**，一处定义、三处复用。

### 11.1 共享 `acquisition_weight(rarity)` 表
| 稀有度 | 获取权重 | 直觉 |
|---|---|---|
| common | 1.00 | 满地都是 |
| uncommon | 0.55 | 常见 |
| rare | 0.28 | 少见 |
| epic | 0.12 | 罕见 |

- 实现：抽选函数（`_roll_shop` / `_roll_boss_rewards` / 精英护符掉落）从「均匀 `shuffle`」改为「按 `acquisition_weight` 加权抽取（`weighted_pick`）」。
- 只动**获取轴**，不碰 `symbols[].weight`（转轮频率），故**不会**导致「神装打不出去」。
- 护符/消耗品需先有 `rarity` 字段（§1 代码缺口）才能参与权重。

### 11.2 BOSS 深度偏置（越深越出好货）
在共享权重基础上，再乘随幕/ante 递增的系数，使 BOSS（奖励高潮）比商店更慷慨地出高稀：

| 幕 | 深度系数 |
|---|---|
| 第 1 幕 | ×1.0 |
| 第 2 幕 | ×1.8 |
| 第 3 幕 | ×2.5 |

- BOSS 另有「未持有过滤」（只给没收集的武器），与稀有权重**叠加** → 既偏向稀有、又偏向补全收藏，双重好体验。
- 普通房奖励（`_roll_rewards`，run 增益卡）与精英补给（`_roll_elite_rewards`）**不参与**此权重——它们给的是货币/增益，不是按稀有度抽的装备。

## 12. 掉落分发结构（四类主渠道）

现状盘点（`reward_screen.gd:39-54`）：**只有 BOSS 掉装备**；普通房掉金币+run 增益卡、精英掉「战前补给」3 选 1（金币/铁砧点/结界），二者**都不掉装备**。

本方案的分发原则：**武器只在商店+BOSS 出，绝不从小怪掉**（转轮即武器池，小怪掉武器会稀释 build、冲淡「枪收藏」稀缺感）。

| 分类 | 主获取渠道 | 规则 |
|---|---|---|
| **武器** | 商店 + BOSS | 保持「枪收藏」稀缺性；不从小怪/精英掉 |
| **护符** | **精英**（保底）+ 商店 | 精英=小型装备时刻，与 BOSS 武器不重叠 |
| **消耗品** | 商店 + 小怪小概率 | 轻量战利品，不影响转轮 |
| **技能** | 商店 | 主动符号来源，商店供给即可 |

### 12.1 各渠道具体规则
- **普通房**：保持「金币 + run 增益卡」；可加 **10~15% 概率掉 1 个消耗品**（轻量、零转轮影响）。**禁止**普通怪掉武器/护符。
- **精英房**：在现有「战前补给」3 选 1 **之外**，加**保底 1 个护符掉落**（从 `ITEM_POOL` 的 passive 按 `acquisition_weight` 抽）。精英成为名副其实的「小 BOSS 装备时刻」。
- **BOSS**：维持「主题武器 / 强化券 / 信物」，稀有权重 + 深度偏置（§11.2）在此生效。
- **商店**：全类按 `acquisition_weight` 出（§11.1）。

### 12.2 稀有度权重覆盖范围一览
| 渠道 | 是否吃 `acquisition_weight` | 备注 |
|---|---|---|
| 商店（全类） | ✅ | 主经济闸门 |
| BOSS（武器/信物） | ✅ + 深度偏置 | 奖励高潮 |
| 精英（护符） | ✅ | 保底掉落 |
| 普通怪（消耗品） | ❌ flat-common / 轻权重 | 不参与稀有竞争 |

### 12.3 三层获取模型与 `owned_*` 角色（与商店文档 §6 联动）

把 §6.4 / §6.6 的盘外与 run 内获取整合为一张总图，明确 `owned_*` 拥有池**只管「开局可选范围」，不限制 run 内交易**：

| 层 | 时机 | 渠道 | 与 `owned_*` 的关系 | 作用 |
|---|---|---|---|---|
| **铁砧 gacha** | 盘外（run 间） | 铁砧屏纯 gacha | **写入**：抽到的装备注入 `meta["owned_weapons"]` / `["owned_charms"]` | 开图鉴冲动，扩大拥有池 |
| **整备选起始** | run 开局（免费） | 整备屏 | **读取**：从 `owned_*` 选本局起始 loadout | 决定"开局能选哪堆装备" |
| **商店买 + BOSS 掉落** | run 内 | 商店购入页 / BOSS 奖励 | **读取**：仅确认"是否已拥有"以走 BOSS 未持有过滤（补全收藏）；**不**用它限制售卖范围 | 决定"这局实际拿到什么" |

- **关键解耦**：商店 / BOSS 从**全池**（`WEAPON_POOL` / `ITEM_POOL`）售卖与掉落，与 `owned_*` 解耦——没抽到的装备也能在 run 内买到/掉到。
- **`owned_*` 唯一约束点** = 整备屏起始选装；其余两层的"拥有"只作 BOSS 未持有过滤（补全收藏），不作售卖闸门。
- 该模型即 Gungeon 对标（商店文档 §6.6）：Ammonomicon 解锁 = `owned_*`，但商店依旧全池卖枪——拥有池管"开局可选范围"，商店/掉落管"这局实际能拿到什么"，二者正交。

## 14. 敌人种类与数量规划（参考经典设计）

> 目标：把「敌人」也纳入可收集/可规划的内容体系，对标经典 Roguelike 的同时，贴合本作「3 幕短局 + 老虎机转轮」的特殊结构。

### 14.1 经典设计对标

| 游戏 | 敌人数 | BOSS 数 | 结构特征 | 对 Ded 的启示 |
|---|---|---|---|---|
| **Enter the Gungeon** | ~85 | 20 | 5 主层楼 + 4 角色「过去」+ 秘密/资源鼠；每层楼敌人池约 17、层末 BOSS；有 DPS 上限防秒杀 | 直接对标对象；本作幕更少，按比例缩放 |
| **The Binding of Isaac** | 100+（Repentance） | ~20 | 房间随机、敌族变体多；是 Gungeon 首要灵感来源 | 敌族×变体的「组合密度」思路 |
| **Nuclear Throne** | 少（~15 族） | ~8 | 同族变体（crowd/scrap/proto）制造密度，而非海量独立敌 | 「少量原型 × 变体」比「海量独立敌」更省工 |
| **Spelunky** | 少（~10 原型） | ~4 | 手工房 + 少量敌，靠布局而非数量 | 敌人不在多，在「配哪间房」 |

**结论**：本作单局 21 房 / 3 幕（2026-08-09 房数重排：每幕 4 普通 + 2 精英 + 1 BOSS），仍小于 Gungeon 的 5 层楼无限式地牢。**不需要 85 个独立敌人**——本作靠「行为族 × 元素 × 幕缩放」的组合数学即可制造足够密度。目标定为 **Gungeon 的约 60–70%（≈60 敌）**，兼顾「地牢式收集/对抗幻想」与可控工作量。

### 14.2 本作敌人模型（事实）

- **现状**：敌人 = `RoomData` 的 stat block（`hp / atk / jam / lock / chaos / heavy / armor / element / kind / gimmick_script`）。当前全量池 **51 个 .tres**（普通 36 / 精英 12 / BOSS 3，每幕 12/4/1）。
- **单局抽取**（`_build_run`）：每幕抽 4 普通（12 选 4）+ 2 精英（4 选 2）+ 1 BOSS（4 候选选 1，池随 BOSS 设计补齐至每幕 4）→ 21 房/局。
- **变化维度（组合数学来源）**：① 行为族（意图权重剖面：attack/heavy×2/jam/lock/chaos）② 元素（fire/ice/poison/light/dark/none，单向克制环）③ 护甲（有无/量，逼 special 破甲）④ 幕缩放（ante：HP×1.75^幕-1 × 1.15^幕内序；ATK×1.46^幕-1 × 1.10^幕内序）。
- **已实装 BOSS 机制**（`scripts/battle/gimmicks/`）：`rust_armor_gimmick`（熔铸护甲成长）、`abyss_erosion_gimmick`（按血量损失增强）、`whisper_lock_gimmick`（低语封锁）。
- ⚠️ **架构缺口**：敌人 stat block 与房间**绑定**（无独立行为原型），21 个 bespoke 房间。要扩到 60+ 且不爆工作量，建议抽离 `EnemyArchetype`（行为族 + 意图剖面 + 默认意图概率），`RoomData` 引用它 + `element` + `act`，缩放由 ante 曲线统一——避免手搓 60 份 stat block，呼应「加内容 = 新建 .tres」哲学。

## 15. ⚠️ 平衡缺口：玩家 HP 与敌人 ATK 的「军备竞赛」失衡（待决策）

> 状态：**已分析、方案已收敛（落地路径见 §15.6，代码未改）**。用户发现「攻击越来越强，玩家 HP 不升级似乎很难通关」，经代码核查，直觉正确且比想象的更严重——属结构性失衡，非手感问题。生存保底通道已由商店升级「体魄 + 回复」轨道承接（§15.6 / 商店文档 §7.4），待 F6 调参落地。

### 15.1 代码事实（来自 `duel_controller.gd`）

1. **玩家 HP 跨 21 房「累积掉血」，不是每房回满**
   - `player_hp = player_hp_max` 仅两处：
     - `:1158` `_full_reset()`（**新一局**才回满）
     - `:1748` `_retry_room()`（**战败重试该房**才回满）
   - 正常通关推进时 HP 连续消耗、无自动回满。仅有的回血：heal 符号 / 回春护符每回合回（`:1904`）、maxhp 奖励卡 +20 上限（`:770`）、heal 卡瞬回 35%（`:766`）。

2. **敌人 ATK 随 ante「确定性指数增长」**（`:1246-1250`）
   - `atk_scale = 1.46^(幕-1) × 1.10^(幕内序号)`
   - 第 3 幕末房：atk_scale ≈ 1.46² × 1.10³ ≈ **2.84**；基础 atk=14 → 普攻 **~40**，heavy=atk×2 ≈ **80**。
   - 敌人 HP 同样涨（1.75²×1.15³ ≈ 4.66 倍）→ **越深战斗拖得越长 → 玩家挨打回合数越多**。

3. **玩家「硬 HP」增长弹性 << 敌人 ATK 增长弹性**
   - HP 上限初始 100，唯一硬增长是 **maxhp 随机奖励卡 +20**（REWARD_POOL 5 选 1，与 power/symbol/shield/heal 竞争同一个随机池）。
   - 玩家「软 HP」（护盾/回血）全在 **build 构筑**里（shield 符号、护符 shield/回春）；纯攻击流这些来源 = 0。

### 15.2 根因

- 你们把「攻击增长」放进了 build 层（武器升级 / 护符乘法 / crit_mult / special 连锁），但**「生存增长」没放进任何确定性通道**——成了「靠运气抽 maxhp 卡 + 靠 build 取舍堆护盾」的孤儿。
- 一个没抽到生存牌、或走纯攻击流的玩家，在第 2–3 幕会被「敌人 ATK 累积 × 战斗拖长」磨死。
- 这违反平衡哲学的隐含前提：**进度层应给玩家一个生存保底，对称于敌人的 ante 缩放**。

> 补充：玩家护盾 `player_shield` 每回合 rebuild（`+=` 后挨打消耗，`:1620-1621`），纯攻击流无来源即为 0——护盾救不了偏攻 build，反而印证「生存全压构筑」的失衡。

### 15.3 候选方案（均未落地，待拍板）

| 方案 | 做法 | 收益 | 代价 |
|---|---|---|---|
| **A（推荐·进度保底）** | `_start_room` 每房回 15% 上限，或每幕 `hp_max += 50; hp = hp_max`（对称于敌人 ante） | 确定性、不抢 build 预算、符合「进度层给保底」直觉 | 略削弱生存压力 |
| **B（消除抽卡劝退）** | 把 maxhp 从 REWARD_POOL（5 选 1）拿出，改每幕**保底补给**（仿精英房战前补给结构）；随机池只留 heal/symbol/power/shield | 消除「想要肉却赌不到」的劝退 | 减少随机卡多样性 |
| **C（难度从打人疼→血厚）** | 下调敌人 ATK 系数（幕 1.46→1.30、房 1.10→1.06），让「玩家攻击越强→秒怪越快→挨打越少」成主解 | 攻击流也有解法，契合「攻击越来越强」直觉 | 降低生存构筑重要性 |
| **D（元进度开体魄分支）** | 元进度三选一加「体魄」（每局 +HP_max / 减伤） | 与现有框架一致，玩家主动投资生存 | 稀释「武器线性 / 护符乘法」二元结构 |

### 15.4 综合建议

**A + B 组合做保底，C 微调系数**：
- A/B 把生存放进「进度层」（不污染 build 乘区、不破坏「战斗内只许 special 连锁一处乘区」铁律）；
- C 保证纯攻击流也有解法。
- 三者都不动膨胀哲学，只补上「玩家生存」这个缺失的确定性通道。
