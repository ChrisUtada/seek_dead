测试断言的排版条件（每屏都查）：

1. 覆盖屏根节点 / 对话框 / 按钮都在 480×270 屏内；
2. 标题、副标题、点数行等 Label 的 `combined_minimum_size` 不超过自身尺寸（不横向压到邻居）；
3. `ItemCard` 的 `Center/VBox` 内容（标题 + 描述 + 主图）完整落在卡片内；
4. 卡片网格 / 四列卖出列表 / 底部按钮行合成最小宽度不超过容器（横向不溢出）；
5. 纵向超长时在滚动容器内可滚动；
6. 商店快速「关→开」后不会被旧补间的隐藏回调关掉。

打开方式全部走游戏真实路径（`_show_shop_screen` / `room_flow.begin_post_battle` / `_show_reward_screen(true)` /
`_show_anvil_screen` / `_show_meta_choice`），不手工拼假数据。
采集与测试均在隔离 `APPDATA=%TEMP%\seek_dead_probe_appdata` 下运行（`run_smoke.bat` 用自己的 `%TEMP%\seek_dead_smoke_appdata`）。

## 2. 实测问题（截图与测量证据）

| # | 屏 | 问题 | 证据 |
|---|---|---|---|
| 1 | 商店 | **抽屉补间竞争**：构建期 `hide_screen()` 的 0.18s 回调会在再次展开后触发，把刚展开的抽屉隐藏（`_open` 仍为 true） | 展开第 3 帧 `visible=false`，`offset_left` 仍在滑动；堆栈指向 `hide_screen` 的 `tween_callback` |
| 2 | 商店·卖出 | 「最后一把 · 不可卖」在 97px 四列里折成 2 行，内容高 37px 而卡高 26px → 文字画出卡外、压到下一张卡 | 测量 `vbmin=(76,37)` / `card.size=(97,26)`；截图旧版可见「不可卖」落在下一卡区域 |
| 3 | 商店·卖出 | 卖出四列**没有滚动容器**：技能/护符变多（技能池 10 条）时底部条目永远看不到 | `SellPanel/SellBox` 下直接是四个 VBox，无 `ScrollContainer` |
| 4 | 奖励（战后成长） | 成长槽描述 50+ 字在 76px 内容宽里折 8–9 行，内容 124px 高而卡固定 96px → 文字画出卡下沿 | 测量 `vbmin.y=124` / `card.size.y=96` |
| 5 | 奖励 | 对话框 200 高时内容需要 203（标题 + 摘要 + 卡组 + 跳过按钮）→ 底部溢出 3px、卡组出现滚动条 | 测量 `dialog=(300,200)`、`scroll=(268,99)`、`grid=(264,102)` |
| 6 | 商店·购入 | 货架卡标题不换行：长物品名（如「【常驻】护符 · 破甲符」）实测 137px，而三列各约 131px → 标题画到卡片边框外 | `vmin.x=137` / `card.size.x=131` |
| 7 | 铁砧 | 单格占位「?」贴在大格子顶部（`VBox` 顶部对齐），大块空白让格子像坏了 | 截图 `05_anvil.png` 旧版「?」在格子上沿 |
| 8 | 全屏 | **卡片内容不参与 Button 最小尺寸**：所有 `ItemCard` 的 `Center/VBox` 都不影响按钮最小高度，长内容一律靠固定 `custom_minimum_size` 兜 | 第 2/4 条的根因；也是 G8-04「卡片文字被裁掉」的同类问题 |

## 3. 修复

### 3.1 商店抽屉补间（`scripts/ui/shop_screen.gd`）

`_tween` 记录当前补间；`show_screen()` / `hide_screen()` 开始前 `kill()` 旧补间，避免旧 `tween_callback`
在展开后把抽屉关掉，也避免两条 `offset_left` 补间互相拉扯。行为语义不变（仍是 0.22s 滑入 / 0.18s 滑出）。

### 3.2 卖出卡与卖出列表（`scenes/ui/shop_screen.tscn`、`scripts/ui/shop_screen.gd`、`scripts/ui/card_factory.gd`）

- `SellPanel` 增加 `SellScroll`（`ScrollContainer`，横向滚动关闭）包住四列 `SellBox`；
  满技能 10 条时列表可在 480×270 内滚动查看；
- 「最后一把 · 不可卖」写成两行（`最后一把\n不可卖`），卡片最小高度 26 → 40，
  卡内容不再压到下一张卡；可见范围与原来一致（只是因为表现层拆行，文字一个没少）。

### 3.3 卡片按内容自撑（`scripts/ui/item_card.gd` + 全部 `ItemCard` 构造器）

`Button` 的最小尺寸只按自身 `text` 算，不包含子控件，这是第 2/4/8 条的同一根因。新增：

- `ItemCard.fit_min_height(min_y)`：声明「这张卡至少要多高」；
- 入树后逐帧等布局给出真实宽度（`VBox` / 标题 / 描述的宽度都到位）再按 `Center/VBox` 的
  真实最小高度撑高，**只增不减**；用 `_process` 而不是协程，避免卡片被回收时踩已释放对象；
- 高度到位后关闭 `_process`。

各构造器都声明了基线高度：奖励 / 成长 96、BOSS 60、元进度 60、解锁 84、商店 46、卖出 40。

### 3.4 成长槽文案显示层截断（`scripts/ui/card_factory.gd`）

成长候选描述常带提示语（50+ 字），在 76px 内容宽里必然 8–9 行。卡面复用整备卡已有的
`_short_desc()`（优先在句号处收尾、否则 34 字加「…」），完整说明仍在 tooltip —
与 G8-04 对物品卡的显示层截断策略一致，不改任何资源文本。

### 3.5 奖励对话框高度（`scenes/ui/reward_screen.tscn`）

`custom_minimum_size` 200 → 210：容下「标题 + 本局成长摘要 + 三张内容自撑的卡 + 跳过按钮」，
不再出现 3px 溢出与卡组滚动条。

### 3.6 货架卡标题换行（`scripts/ui/card_factory.gd`）

`shop_card` 的标题允许自动换行（与奖励/BOSS 卡一致）。三列宽度一致、长名称折成两行，
不再画到卡片边框外；行高由 3.3 的自撑逻辑接管。

### 3.7 铁砧单格居中（`scenes/ui/anvil_cell.tscn`）

`Panel/VBox` 加 `alignment = 1`（居中）：「?」与抽中后的两行文案都在格子中心，而不是贴顶。

## 5. 能读 / 不能读

**能读**：

- 四屏在 480×270（=`ProjectSettings` 逻辑分辨率，stretch `canvas_items`）下没有横向溢出、
  没有内容画出卡面、没有不可达的列表底部；
- 每个修复都由测量数字或截图指认，不是「看起来还行」；
- 商店快速开关不再被旧补间关掉（有回归项）。

**不能读**：

- 不是美术/交互的完整验收：图标观感、hover 文案、点击热区、动画节奏仍需真机手感判断；
- 铁砧三连旋转、局末数字的语义是否好理解，不在排版范围内；
- 商店三列货架仍是内容驱动的等宽列，长名换行后行高会略高，属可接受表现，不是缺陷；
- 音效 / 位移反馈分级（§12 另一条）与本切片无关，仍待做。
