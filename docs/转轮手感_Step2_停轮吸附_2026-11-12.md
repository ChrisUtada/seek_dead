## 1. 行为变化

| 阶段 | Step 1 之前 | Step 2 |
|---|---|---|
| 按停 | 立即解析落点并写 `grid`、立即结算 | 记录「请求时的落点」，进入吸附，不写 `grid` |
| 0.12–0.16s | — | ReelSpinView 从当前视觉位置缓出到落点格；该列不再被节拍器推进 |
| 吸附完成 | — | 写入 `grid`、刷新格子、记遥测；所有列停完才 `finish_spin` |
| 重复停轮 | 已停列忽略 | 吸附中的列同样忽略；不会改目标、不会重复结算 |

**落点语义保持不变**：吸附目标 = 按停瞬间的视觉中心（`visual_center_index`）。  
减速只是把「看到的那一格」停稳，不会额外前进一格，因此现有目押契约与 `visual / buffer / control` 预设的落点规则都不变。

## 2. 实现

### 2.1 ReelSystem

新增：

| 成员 | 作用 |
|---|---|
| `_absorb: Dictionary` | `reel -> {idx, reason, progress, tween}` |
| `is_absorbing(r)` | 该列正在吸附 |
| `absorb_progress(r)` | 0..1，供 `ReelSpinView` 只读驱动动画 |
| `absorb_target(r)` | 请求时记录的落点格 |
| `is_busy(r)` | 已停或吸附中，统一排斥重复输入 |
| `_begin_absorb(r, idx, reason)` | 记录落点、禁用该列、创建 tween；空带回落旧行为 |
| `_complete_absorb(r)` | 吸附结束才调用 `_lock_at` 写 `grid` 并检查是否全部停完 |
| `_absorb_seconds()` | 按当前节拍折算速度，`clamp(2·1格 / speed, 0.12, 0.16)`，常量取自 `ReelClock` |
| `_clear_absorbs()` | 新回合 / 房间重置时中断吸附，不落子 |

统一入口：

- 手动点列 → `lock_reel` → `_begin_absorb`
- 空格「停下一列」→ `stop_next_reel` → `lock_reel` → `_begin_absorb`
- 输入缓冲到点 → `on_spin_tick` → `_begin_absorb`
- 敌人夺轮 / 自动停 → `stop_next_reel(false, "forced")` → 同一 `_begin_absorb`
- 注废 / 锁轮列仍按机制直接落子（结果不由目押决定，且本来就不旋转）

去重与收尾：

- `reel_stopped` 在吸附完成前保持 `false`，因此 `finish_spin` 不会提前触发。
- 吸附中 `lock_reel`、`stop_next_reel`、`_on_reel_clicked` 都跳过该列。
- 吸附完成时 `_absorb` 先移除记录，再写格子，只可能结算一次。
- `begin_spin` / `reset_grid` / `finish_spin` 都会清理残留吸附。

### 2.2 ReelSpinView

- 只读 `is_absorbing / absorb_target / absorb_progress`，不写 `grid`、不推进逻辑游标。
- 首次看到吸附时记录当前连续位置，按二次缓出插值到目标格；完成后由 `ReelSystem` 写格子，下一帧本层隐藏。
- 吸附期间不显示洞察预览，避免「下一格」与落点冲突。

## 7. 后续修正（2026-11-13）：吸附时长重标定

| 项 | 修正前 | 修正后 |
|---|---|---|
| 图标 / 槽距 | 16px / 19px | 32px / 30px |
| 巡航速度 | 9.0 格/秒（0.111s/格） | 5.7 格/秒（0.175s/格） |
| 视觉像素速度 | 171 px/s | 171 px/s（刻意不变） |
| 吸附时长区间 | 0.12–0.16s | **0.16–0.20s**（实机回调档） |
| `t = 2d/v` 是否生效 | 否：`2d/v` 恒 > 上限 0.16，被截断，与速度脱钩 | 否：`2d/v` 恒 > 上限 0.20，被截断、实际恒 0.20s（用户拍板优先响应速度） |

**原因**：槽距变宽 58% 而像素速度不变，0.16s 内不干预继续滚只会走 27.4px（0.91 格），吸附却要走到 1 格中心（30px）。最坏情况下二次缓出的峰值速度约为滚动速度的 2.2×，停轮瞬间会先向前窜一下再急停。按 `t = 2d/v` 重标定后，吸附初速 ≤ 当时滚动速度，减速段真正减速。

**实机回调（同日，两轮）**：物理对齐档 0.26–0.35s 反馈「偏慢了一点」→ 折中 0.23–0.28s，仍反馈「还是偏慢」。追查链路后发现根因不在区间标定，而在 **`t = 2d/v` 用的是名义 d=1.0 格，但 `ReelSpinView._render_absorb` 的实际视觉差值 `|diff|` 平均仅约 0.5 格**（control 预设下 `diff ≈ -_frac`）——名义时长普遍是所需时长的 2 倍，每一档都在按最坏情况计时。用户两次拍板「要快」，优先级定为 **响应速度 > 物理对齐**，区间收回 **0.16–0.20s**（实际恒 0.20s，回到图标放大前的量级，比折中档快 0.08s）。代价：巡航段峰值约 1.75× 滚动速度，停轮可能轻微前窜。

**未实施的根本解法**：把 `t` 改为按实际 `|diff|` 动态计算（`t = 2|diff|/v`），可同时做到快与不窜（平均约 0.175s）；但需在逻辑层读取视觉连续位置、跨层耦合且要改测试，留待单独评估。另注：按停 → 飘字还叠加 `turn_flow.gd` 的 0.15s 死等与 `combat_system.gd` 的 0.25s 阶段间隔，吸附并非唯一延迟源。

**口径说明**：`ABSORB_DECEL_CELLS = 1.0` 是名义减速格数 d；`ReelSpinView._render_absorb` 的实际视觉差值 `diff` 通常在 ±1 格内（视觉对齐开启时多 ≤0.5 格）。落点仍为按停时的视觉中心，不因时长变化而前移。

**改动范围**：`scripts/battle/reel_clock.gd`（`MIN/MAX_STOP_SECONDS`）、`scripts/battle/reel_system.gd` 与 `scripts/ui/reel_spin_view.gd` 注释、6 个测试文件共 14 处等待（0.25→0.45 / 0.35→0.45 / 0.5→0.6）。回调后最长吸附 0.20s，0.45s 等待仍有 0.25s 余量，故测试等待值不再调整。落点契约、去重、自动停轮节奏、粒子与全局 RNG 均未改动。
