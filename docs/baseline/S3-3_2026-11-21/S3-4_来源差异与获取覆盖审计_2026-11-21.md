## 1. 等待/失败分类修正（数据分类，不改 Resolver 语义）

### 修正前问题
`reward_system.settle_loot_offer` 对 Resolver 返回的任何 `not ok`（含 `needs_replace`）统一调 `on_reward_apply_failed`，把"等待玩家选旧武器"错记为"结算失败"。S3-3 报告中 28 次失败全为 `needs_replace`，正是此误分类。

### 修正内容
| 类别 | 语义 | 处理 |
|---|---|---|
| `waiting_for_replace` | `needs_replace` = 等待玩家在替换弹层选旧武器，可继续 | 新事件 `reward_waiting_replace` + 计数 `draft_waiting_replace`，**不计失败** |
| `apply_failed` | 非法目标/重复获得/资源缺失等真实失败 | `reward_apply_failed`，真实失败 |
| `already_settled` | 重复点击守卫 | 新事件 `reward_already_settled` + 计数 `draft_already_settled`，**另列不与无效奖励混算** |

- Resolver 的等待语义**未改**（`reward_resolver.gd:435` 仍返回 `needs_replace` 等待输入）。
- S0 汇总器同步：新增 `reward_waiting_replace` / `reward_already_settled` 统计；对老数据事件流中 `reason=needs_replace` 的 `reward_apply_failed` **排除**，不当真实失败。
- 验证：重跑 S3-3 探针，事件流出现 `reward_waiting_replace`、无 `reward_apply_failed`；回归 reward_p2 / p01_generator / owned_filter / g5_circuit / g5_journal(--runlog) 全绿。

## 2. 六身份真实获取覆盖表（新档状态，全链路核查）

**关键机制**：LootPool 候选来源与 `meta.owned_weapons` 无关——`_build_index()` 扫描全武器目录（`loot_pool.gd:366-401`），`candidates()` 只按 `source_tags/act/theme/demo` 过滤（`loot_pool.gd:57-94`）。因此"新档未解锁"不阻止武器进池。

| 武器 | 普通Draft | 精英主题 | Boss主题 | 宝箱/藏库* | 商店 | 铁砧 | 合法路径 |
|---|---|---|---|---|---|---|---|
| 绝对零度 | ✗ | ✓(火精英) | ✓(2房) | ✓ | ✓(act3 epic) | ✓ | 多条 |
| 冰霜枪 | ✗ | ✓(火精英) | ✓(2房) | ✓ | ✓(rare槽) | ✓ | 多条 |
| 蚀日之刃 | ✗ | ✓(光精英) | ✓(3房) | ✓ | ✓(act3 epic) | ✓ | 多条 |
| 坚壁钉锤 | ✗ | ✗(无元素tag) | ✗ | ✓ | ✓(common槽) | ✓ | 多条 |
| 暮光手斧 | ✗ | ✓(光/暗精英) | ✗ | ✓ | ✓(common槽) | ✓ | 多条 |
| 双式军刀 | ✗ | ✗(无元素tag) | ✗ | ✓ | ✗(无uncommon武器槽) | ✓ | **仅铁砧+宝箱/藏库** |

\* 宝箱/藏库需开启棋盘模式（默认 `board_config.enabled=false`）。
**六把全部至少一条合法来源，无"无任何来源"项 → 不讨论补主题来源，更不加入 STARTER_WEAPONS。**

### 链路验证（候选展示 → 获得/替换 → 本局仓库 → 局外解锁/图鉴）
- 精英：`room_flow._grant_elite_trim` → `grant_elite_weapon` → `remember_weapon("elite")`（`duel_controller.gd:958-975`）→ 写 `run_weapon_inventory` + `meta.owned_weapons` + 图鉴（`reward_system.gd:1157-1172`）✓
- Boss：`apply_boss_reward` → `remember_weapon`（`reward_system.gd:1565-1579`）✓
- 商店：购买写 `meta.owned_weapons`（`shop_system.gd:264-277`）✓
- 铁砧：写 `meta.owned_weapons`（局外解锁资格），**不写本局仓库**——需后续经普通 Draft 的 `weapon_acquire` 才能进本局使用（三态分离设计，`meta_store.gd:1157-1163`）
- 普通 Draft 是闭环：`acquire` 只从局外已解锁取、`swap` 只从本局仓库取（`reward_system.gd:590-648`），**不是未解锁武器的引入口**——这解释了六把在普通 Draft 全 ✗（新档两处都没有）。

**最窄项双式军刀**：无元素 family tag → 进不了精英元素池；无 BOSS 主题池；uncommon 品质但商店武器槽只有 common/rare/epic → 商店够不到。仅铁砧（gacha/定向）与棋盘宝箱可得。可接受（仍有合法路径），但可作为"补主题来源"的未来候选（当前不动）。

## 3. 真实来源差异表（普通 vs 精英 Draft）

### 核查结论：用户怀疑成立——Draft 内部零差异
1. `build_loot_offer`(`reward_system.gd:658`) 的 growth_only 分支：`compose()` 调用（:670）**不含 source/act**；`source` 仅用于 view 标题（:676）与遥测标签（:692）；`act` 形参在 Draft 分支**完全未用**（遥测里的 act 取自 `_ctrl.current_act`，:690）。
2. `DraftComposer.compose`(`draft_composer.gd:67-68`) 无 source/act 参数；`category_resolver` 类别权重 `CATEGORY_WEIGHT`（:25-33）与稀有度权重 `RARITY_DRAW_MULT`（:15-20）均为**固定常量**，全项目无运行时改写、无来源分支。
3. `loot_source_weights`（`balance_config.tres:45`，elite 20/50/27/3）**只被旧 LootPool/LootOffer/探索/商店读取**（`loot_source_table.gd:61` → `loot_pool.gd:105` 等），**新 Draft 引擎一行不读**。
4. 精英当前真正生效的差异**全在 Draft 之外**：必给克制元素武器（`_grant_elite_trim` → `roll_elite_element_weapon`，`reward_system.gd:1217-1241`）+ 自动护符（`_drop_elite_charm`，:1671-1699），均由旧 LootPool 自动发放。旧"战前补给"（`roll_elite_rewards`/`ELITE_REWARD_POOL`）在当前战后主流程疑似未触发，属遗留。

### 规格落差
权威方案要求"精英来源提高高稀有度条件概率"（执行方案:545-550；V1.1:153；V1.2:237"精英来源可修改稀有度参数"），但**代码从未实现参数化**。S3 规格 §6 的"来源差异"属待实施，本次为现状核查。

### 是否可接受 / 不照搬旧品质表
- 当前"Draft 无差异 + 额外自动掉落"是 **G5 输出安全门的强度支撑**：G6-1 曾移除精英自动武器+护符，同口径 tactical 探针 **ACT2 单房输出中位 422→378，跌破 90% 门槛 396**，已回退（`docs/G6_现状诊断与改动建议_2026-11-20.md:8-11`；`room_flow.gd:58-59`；`reward_system.gd:1657-1658`）。
- 因此**不直接把旧精英品质表（20/50/27/3）塞给 Draft 加强度**——既绕开 `RARITY_DRAW_MULT` 统一梯度，也可能再次破坏安全门。
- 判断：精英差异目前靠 Draft 外额外物品堆出，与方案 §7"精英不再同时自动堆护符、主题武器和普通 Draft"的意图相反，但这是已验收的安全门依赖，**本轮不动**。

## 4. 是否需后续来源调优的明确结论

> **本轮不需要改动来源层。** 理由：
> 1. 六身份武器全部有合法获取路径（最窄的双式军刀仍有铁砧+宝箱），无"无来源"项，不补主题来源、不改 STARTER_WEAPONS。
> 2. 普通/精英 Draft 稀有度类别无差异是事实，但精英差异由 Draft 外额外物品承担，且是 G5 安全门强度支撑（G6-1 回退证据）——照搬旧品质表或削弱额外物品都会破坏已验收门槛。
> 3. 规格与代码的落差（精英稀有度参数化未实现）记为技术债，需与输出安全门一起作为**独立平衡任务**评审，不混在 S3-4。

**未来候选（不在本轮执行）**：若设计意图是让无元素 uncommon 武器也有战斗内来源，可为双式军刀补主题池；若要让 Draft 体现精英质量差异，须先补足替代强度来源以过 G5 安全门，再单轴实施。技艺/生存资源价值仍标未证实，留待真实选择行为数据。
