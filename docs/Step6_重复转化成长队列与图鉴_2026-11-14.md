## 2. 重复转化规则

| 本局状态 | 展示与结算 |
|---|---|
| 武器已在转轮带 | **该武器熟练 +N**（N 按品质：1 / 2 / 3 / 4） |
| 武器槽满但未拥有 | 冻结 `needs_replace`，由替换流程处理；直接结算返回 `needs_replace`，不消耗结算机会 |
| 护符已在护符槽 | 同层金币转化 |
| 护符槽已触顶（不能再开槽） | 同层金币转化 |
| 消耗品腰带已满 | 同层金币转化 |
| 同层候选不足 / 空池 | 同层金币或同层强化（Step 4 规则不变） |

熟练是既有成长通道：`grant_points` 只改本局 `mastery`，跨过 R2 / R3 时与房间结算一样欠一次铭印选择；
不直接发放铭印、不生成技艺、不读物品品质以外的随机。

## 3. 结算纪律

```text
build_loot_offer → 冻结 quality / options / grant / gold / power / mastery / skip
settle_loot_offer(index) 或 settle_loot_skip
→ 按冻结值结算一次
→ _loot_settled = true
→ 再次点击 / 回访 / 重抽 → already_settled
```

- 结算失败（例如武器槽满 `needs_replace`）**不**置位 `_loot_settled`，处理槽位后可重试。
- `reroll_loot_offer()` 在已结算后返回 `already_settled`，不改变任何状态。
- 普通授予只发一次：武器 / 护符 / 消耗品不会因重复点击进入两次；消耗品同时写入 `owned_consumables`。
- 重抽只换同层候选，不碰 `mastery`、`owed`、`growth.pending_picks`。

## 4. 图鉴与成长记录

| 记录项 | 口径 |
|---|---|
| 获得 | 武器 / 护符写入 `owned_weapons` / `owned_charms`；消耗品写入 `owned_consumables` |
| 来源 | `item_sources[path]` 追加 `{act, mode, loot_source, room/node…}`；同来源去重、每件最多 5 条 |
| 来源文案 | 图鉴显示 `ACTx · 棋盘/线性 · 普通战利品/精英战利品/BOSS 战利品/探索宝箱 · 房间` |
| 最高熟练 | 局末 `codex.record_run(mastery)` 记录 `best_rank` / `best_mastery` / 铭印组合 |
| 已收藏 | 不影响本局候选；图鉴已解锁但本局未装备的物品仍正常出现 |

重复转化只写本局熟练，不直接写图鉴最高熟练；最高熟练仍由局末统一结算，避免中途存档口径分叉。

## 8. 已知影响与下一步

- 熟练转化目前只在新的 `LootOffer` 结算通道生效；旧战后三槽屏仍按既有规则处理满槽（转金币 / 替换）。
  Step 7 把同层三选一接到玩家界面后，玩家会直接看到「已拥有 → 熟练 +N」。
- 护符 / 消耗品的重复仍走金币，因为这两类没有既有熟练通道；后续若给护符加成长，只需替换
  `_grant_state` 的 `passive` 分支，结算层无需改动。
- 转化数值（1/2/3/4 熟练）是模拟起点，Step 8 大样本再调。
- 图鉴来源新增 `loot_source` 字段只影响新记录；老档条目按原样显示。
