> 状态：设计文档（未实施）。本文件为权威规划，**取代此前含 `SymbolRegistry` 的旧版**（旧版注册表方案与"不用品全局注册表"的决策冲突，已作废）。
> 关联：`docs/UI_最佳实践改造方案.md`（Phase 0–3 已完成，控制器纯逻辑 / BattleHud 纯 UI 已分离）

## 0. 设计原则（"最佳实践"基准）

1. **数据即 Resource**：所有可配置内容（符号、武器、buff、物品、房间、奖励）定义为 `Resource`（.tres），通过 `@export` **直接引用**，而非 `id → 字典查表`。加内容 = 新建 .tres，不改代码、不碰全局表。
2. **无全局注册表 / 无枚举当主键**：禁止 `enum Id` + 硬编码 `Dictionary` + `get_symbol(id)` 这类间接查表。
3. **内容清单自动发现优先**：可用内容用"扫描文件夹"收集，避免手写路径数组（软注册表）。
4. **关注点分离已落地**（Phase 0–2）：控制器纯逻辑、BattleHud 纯 UI，本方案保持不变。
5. **固定规则可保留为模块**：五元素克制 `ElementCounter` 是规则而非内容，属设计数据，可接受；但不得改用 id 间接。
6. **死代码要治理**：未接线的 `enums.gd` 装备槽体系、`stat_modifier.gd` 词缀管线必须明确标注/隔离，不得伪装成活跃逻辑。

## 2. 目标架构（资源直接引用，零查表）

```
整备确认
  ├─ 所选武器 .tres  ──┐
  ├─ 所选 buff .tres  ─┤
  └─ 所选物品 .tres  ─┘
        │ 直接读取 @export 引用
        ▼
  pool: Array[ [SymbolData, weight], ... ]   ← 不再有 id
        │
        ▼  _weighted_random_sym() → 返回 SymbolData
  grid[reel][row] = SymbolData 引用
        │
        ▼  _evaluate() 直接读 sym.kind / sym.base / sym.element
   结算（伤害/护盾/治疗/状态/buff）
```

符号的真相来源只有两个：`WeaponData.symbol` 与 `BuffData.symbol`，二者都直接持有 `SymbolData` 资源引用。无第三方 CATALOG。

## 3. 数据模型（全部 Resource 化）

### 3.1 SymbolData（新增 `scripts/battle/symbol_data.gd`）
```gdscript
class_name SymbolData
extends Resource
@export var label: String = ""
@export var name: String = ""
@export var kind: String = "damage"     # damage|shield|heal|status|special|buff|trash
@export var base: float = 0.0
@export var element: String = "none"    # fire|ice|poison|light|dark|none
@export var status_type: String = ""     # 仅 kind=="status"：burn|frost|poison
@export var color: Color = Color(0.7,0.7,0.75)
```

### 3.2 WeaponData 改造（`scripts/equipment/weapon_data.gd`）
- **删除** `reel_symbols: Dictionary`（旧 `{符号id: 权重}`）。
- **新增** 直接引用：
```gdscript
@export var symbol: SymbolData          # 武器即符号，直接持有
@export var weight: float = 1.0
```
- 多效果武器后续可升级为 `symbols: Array[SymbolData]`；本期先单符号。
- 保留 `weapon_name` / `reel_element` / `special` 标记。

### 3.3 BuffData（新增 `scripts/items/buff_data.gd`）
```gdscript
class_name BuffData
extends Resource
@export var buff_id: String = ""
@export var name: String = ""
@export var desc: String = ""
@export var symbol: SymbolData          # 该 buff 在转轮上的符号
@export var effect_type: String = ""    # damage_mult|shield_gain|heal_gain|...
@export var effect_value: float = 0.0
@export var turns: int = 2              # 连线命中后持续回合
```

### 3.4 ItemData（新增 `scripts/items/item_data.gd`，合并消耗品+护符）
```gdscript
class_name ItemData
extends Resource
@export var item_id: String = ""        # 资源路径即身份，可不用额外 id
@export var name: String = ""
@export var desc: String = ""
@export var category: String = "active" # active(原消耗品) | passive(原护符)
@export var effect: String = ""         # active: purify/heal/assault/reroll; passive: damage_bonus/room_shield/...
@export var value: int = 0
@export var charges: int = 1            # 仅 active，每房回满
```

### 3.5 RoomData / RewardData（新增，资源化 ROOMS / REWARD_POOL）
- `scripts/battle/room_data.gd`：`name/hp/atk/jam/lock/chaos/heavy/element`，每个房间一个 .tres。
- `scripts/items/reward_data.gd`：`id/icon/label/desc`，每个奖励一个 .tres。

### 3.6 系统符号 TRASH（内置，非原生战斗符号）
`resources/symbols/trash.tres`（一个 `SymbolData`，`kind="trash"`）。在 `reel_symbol.gd` 位置新建轻量 `const TRASH_SYMBOL := preload("res://resources/symbols/trash.tres")`，供注废机制与 `chaos` 逻辑引用。它属机械填充物，不计入"原生符号"。

## 4. 运行时流程变化

| 现有函数 | 变化 |
|---|---|
| `_build_pool(loadout)` | 遍历所选武器/buff，直接收集 `[wd.symbol, wd.weight]` 入池；不再读 `reel_symbols` 字典。 |
| `_weighted_random_sym()` | 返回 `SymbolData`（原返回 `int id`）。 |
| `_evaluate()` | `sym = p[0]` 直接是 `SymbolData`，读 `sym.kind/base/element`；新增 `kind=="buff"` 分支写入 `player_buffs`。 |
| `grid` / 显示 | 存 `SymbolData` 引用，刷新直接取属性。 |
| `_apply_charms()` → `_apply_items()` | 仅聚合 `passive` 物品的本局加成。 |
| `_on_consumable_pressed()` → `_on_item_pressed()` | 仅处理 `active` 物品。 |
| `_find_status_*_by_id()` | 删除（状态字串直接存于 `SymbolData.status_type`）。 |

**关键不变**：`_evaluate` 仍按 `kind/base/element/status` 结算，武器自带符号天然复用 `damage/shield/heal/status/special` 分支；战斗逻辑（伤害、克制、胜负、净化、房奖励）行为不变。

## 5. 分阶段实施清单

### Phase A · 物品统一（低风险）
- 新增 `item_data.gd`；迁移 `resources/consumables/*.tres`(4) 与 `resources/charms/*.tres`(4) 到 `ItemData`。
- 控制器：`CONSUMABLE_POOL`+`CHARM_POOL` → `ITEM_POOL`；`selected_consumables`+`selected_charms` → `selected_items`；`_apply_charms`→`_apply_items`；`_on_consumable_pressed`→`_on_item_pressed`（只处理 active）；`consumable_charges` 改按 `ItemData.resource_path` 索引。
- `battle_hud.gd`：整备三列 → 两列（符号 / 物品），物品列内 active/passive 分组。
- **战斗逻辑零改动**。

### Phase B · 符号资源化（核心，消解注册表）
- 新增 `symbol_data.gd`；新建各武器对应的 `SymbolData` .tres（原 9 个原生符号 → 拆为「基础武器」资源，如铁剑→SLASH、火杖→BURN、战盾→BLOCK、圣徽→HEAL，保证开局有内容）。
- **删除** `ReelSymbol.CATALOG` + `enum Id` + `get_symbol`；替换全部 ~10 处调用为直接 `SymbolData` 访问。
- `WeaponData.symbol` + `weight`；`_build_pool` / `_weighted_random_sym` / `grid` / `run_symbol_bonus` / 两处 status 循环 全部改写。
- `TRASH` 改为内置 `trash.tres` 引用。

### Phase C · 主动 buff 符号（新建）
- 新增 `buff_data.gd`；整备选择携带 buff → 其 `symbol` 进池。
- `_evaluate` 增 `kind=="buff"` 分支，写入 `player_buffs`（带 `turns` 递减、可被净化抵消）。
- UI：符号列内武器 / buff 分组预览。

### Phase D · 软注册表清理 + 死代码治理
- `WEAPON_POOL/CONSUMABLE_POOL/CHARM_POOL` → 通用 `load_resources(folder, type)` 扫描文件夹自动收集。
- `ROOMS` → `RoomData` .tres（扫描 `resources/rooms/`）；`REWARD_POOL` → `RewardData` .tres（扫描 `resources/rewards/`）。
- `enums.gd` 装备槽体系（`EquipmentSlot`/`SLOT_NAMES`/`WeaponType`/`Archetype`/`Rarity`）：老虎机未使用，明确标注 `@deprecated / 仅预留`，或移出主工程。
- `stat_modifier.gd`：保留为词缀接口（见 §6），标注"未接线"。

### Phase E · UI 同步
- 图例 / tooltip 直接读 `SymbolData`（名称/类型/元素/对敌关系），不再经 `get_symbol`。
- 物品 tooltip 显示 `category`/charges/passive 效果。
- 武器符号预览、buff 符号角标。

### 词缀（仅接口，暂缓）
- （词缀系统已冻结废弃）原规划复用 `StatModifier` / `EquipmentEnums.StatTarget` 预留接口，已于 F-0 死代码清理中删除 `enums.gd` / `stat_modifier.gd`；`WeaponData` 仅保留 `archetype`/`weapon_type` 字段（被 8 个武器 `.tres` 引用），`get_implicit_modifiers`/`_mod` 死代码段已移除。

## 8. 验收标准

1. 转轮上是**武器 / buff 符号**；除 `TRASH`(系统) 外无脱离来源的"原生符号"。
2. **无任何 `ReelSymbol.CATALOG` / `enum Id` / `get_symbol(id)` 残留**；所有符号经 `SymbolData` 直接引用。
3. 整备界面为**两列**（符号 / 物品），物品内 active/passive 分组清晰。
4. 主动 buff 符号连线触发**临时增益**，可到期清除、可被净化抵消。
5. `WEAPON_POOL` 等路径数组改为**文件夹自动扫描**；`ROOMS`/`REWARD_POOL` 为 .tres 资源。
6. 战斗逻辑（结算/克制/胜负/净化/房奖励）**行为不变**。
7. 词缀为预留接口，本期不生效、不报错；`enums.gd`/`stat_modifier.gd` 已明确标注遗留/未接线。
