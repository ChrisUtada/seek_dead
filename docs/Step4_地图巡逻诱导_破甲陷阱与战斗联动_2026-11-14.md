## 1. 先说一个必须先解决的前置冲突

按 Step 3 的冻结数据，**任何巡逻怪都踩不到陷阱**：

| 原陷阱格 | 性质 | 被占时 起点→BOSS | 在巡逻环上 |
|---|---|---|---|
| 59 `(row4,col3)` | A→B 唯一咽喉（`60` 只能从 `59` 进） | ❌ 不可达 | 否 |
| 64 `(row4,col8)` | B→C 唯一咽喉（`65` 只能从 `64` 进） | ❌ 不可达 | 否 |
| 94 `(row6,col10)` | C 区死胡同（唯一邻居 `95`） | ✅ 可达 | 否（进不了环） |

三条巡逻环上的格**全部是非咽喉**。所以「怪物进入陷阱」在旧布局里不可能发生。

**作者口径（2026-11-14）**：把陷阱移到巡逻环上 —— 采用 **45 / 39 / 110**。

| 项 | 结果 |
|---|---|
| 陷阱坐标 | `45`（A，p0 环）、`39`（C，p1 环）、`110`（C，p2 环） |
| 可行走格 | 仍 61 |
| 陷阱数量 / 类型 | 仍 3 个 / 全 `armor_break` |
| 内容数量 | 不变（宝箱 4 / 神龛 4 / 商店 1 / 休整 2 / 普通 12 / 精英 3 / BOSS 1） |
| 区域分布 | A 1 / B 0 / C 2（原 A 1 / B 1 / C 1） |
| 任意陷阱被占 | 起点→BOSS 仍可达（已逐个验证） |
| 第 50 套 | 不写死坐标，无需改测试，`66/66` 仍全绿 |

同时把巡逻绑定的房间改为「**有护甲优先**」：act1 的 12 个 normal 房里只有 3 个带甲（12 / 16 / 10），纯字典序会选到护甲 0 的怪，破甲会退化成 `0 → 0`。

### 触发与结算规则（本步冻结）

| 情形 | 规则 |
|---|---|
| 巡逻走进陷阱格 | 记录一次触发，该怪 `trap_armed=true`，`trap_state[cell]` 记 `consumed=false` |
| 同一只怪再次经过同一陷阱 | 不再记录（`trap_armed` 或 `trap_used` 已置位） |
| 武装状态下接触 | 节点带 `armor_break=true`，`armor_before = 基础护甲`，`armor_after = 0`，文案「下一场战斗：敌方护甲 X → 0」 |
| 结算后再次接触同一只怪 | `armor_break=false`，`armor_before == armor_after`，护甲不被重复清零 |
| 玩家自己走进陷阱格 | 只移动、只推进一回合；**不触发、不受伤、不发奖** |
| 无陷阱路线直接开战 | 正常进入战斗，护甲保持原值（破甲不是开战条件） |

「顺序固定」体现在 `_advance_turn()`：**先移动 → 再判陷阱 → 最后判接触**，三只怪按 `order 0→1→2` 依次处理。

## 5. 已知限制（不属本步出口）

1. **破甲只落在待战节点**：真正进 `duel_controller` 时要把 `armor_after` 映射为 `enemy_armor_max = 0`。阶段值以房间基础护甲为准，实际战斗再乘 `hp_scale`；这一步等运行入口接入（Step 5A 之后）。
2. **陷阱是「时机」而非「路线」收益**：怪沿固定环走，玩家可以选择立刻打（护甲原值）或等它踩陷阱再打（护甲 0）。这是当前无追击设计下的自然结果，不是完整诱导玩法。
3. **陷阱每怪只生效一次**：`trap_used` 是「整只怪一次」，比 §3.4「同一只怪物同一陷阱一次」更严，避免跨陷阱重复武装。
4. **无 UI**：陷阱高亮与护甲预告文案的绘制属 Step 6，本步只提供 `trap_preview()` 数据。
5. **全量回归未跑**：只实跑第 56 套与第 50–55 套，全量 56 套交回用户验证。
