## 1. 方案要求的统一结算顺序（§5.3）

```
落点快照
→ 基础符号贡献
→ 通用连线/三连
→ 当前装备牌谱与签名
→ 已装备回路（固定优先级 → 槽位顺序）   ← G4 新增，最多 2 槽
→ 明确的回合级修正
→ 敌方护甲、护盾、状态和伤害闸口
```

要求：旧三连与新牌谱不能重复表达同一效果而不解释；每轨互斥/优先级在"当前赔付表"可查；
回路声明触发事件/目标/每SPIN·回合·房间上限/是否连锁；默认只响应原始事件（不自触发）；
表现可聚合，结算绝不因飘字条数截断；不做开放递归脚本，首版白名单事件。

## 2. 当前代码实际顺序（事实层）

`CombatSystem.evaluate()`（`scripts/battle/combat_system.gd:225`）：

| 步 | 调用 | 对应方案步 |
|---|---|---|
| 1 | `_phase_symbols(acc)` | 落点快照 + 基础符号贡献 + 通用连线/三连（含元素共鸣、连线倍率） |
| 2 | `_phase_defense(acc)` | 防御符号贡献 |
| 3 | `_phase_counter(counts, acc)` | 克制/核爆（部分回合级修正） |
| 4 | `_apply_patterns(acc)` | 装备牌谱与签名（武器轨/技能轨/通用牌谱） |
| 5 | `_phase_attack(counts, acc)` | 攻击结算 + 敌方护甲/护盾/状态闸口 |
| 6 | `_present_turn(acc, counts)` | 表现回放（结算与表现已分离，2026-11-16） |

**偏差**（G4 要解决）：
1. **无独立"回路"阶段**——回路系统当前不存在（`rule_mod` 类别禁用，§12.4 六路线专属规则代码零命中，见 `G0_3c`）
2. **通用三连与基础符号混在 `_phase_symbols`**——方案要求分开可查
3. **回合级修正分散**——`_phase_counter` 的核爆、元素充能爆发（`:1101`）等散布在各处，无统一"回合级修正"阶段
4. **敌方闸口在 `_phase_attack` 内**——未独立成阶段

## 3. 回路插入点（G4-2/3 实施依据）

**插入位置**：`_apply_patterns(acc)` 之后、`_phase_attack(acc)` 之前。

```
_apply_patterns(acc)      # 装备牌谱与签名
    ↓
_apply_circuits(acc)      # ← G4 新增：本局回路（固定优先级 → 槽位顺序，最多2）
    ↓
_phase_attack(counts, acc)# 攻击结算
```

理由：回路必须能看到"符号贡献 + 牌谱结果"的完整 acc，才能监听组合事件；
又必须在敌方护甲/闸口之前结算，否则赔付表的伤害修正无法应用。

"旧三连 vs 新牌谱"的关系。

## 5. 启用门槛（§5.3，G4-6）

`rule_mod` 类别恢复需**同时满足**：
1. ≥6 个机制不同的回路，覆盖 ≥4 类组合条件
2. 每个回路有可达性过滤、真实结算、独立反馈、递归测试
3. 构筑摘要能查看/比较/替换回路
4. 固定种子证明无"合法展示但整局无法触发"
5. 最多 2 个的替换流程和输出曲线通过验收
