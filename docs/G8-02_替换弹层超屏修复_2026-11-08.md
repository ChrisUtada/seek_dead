# G8-02 武器替换弹层超出屏幕（按钮被裁掉）修复

> 日期：2026-11-08
> 来源：作者实机试玩反馈——「棋盘中替换武器窗口太大，导致按钮被覆盖了，无法使用」
> 涉及：`scripts/ui/battle_hud.gd` 的 `request_weapon_replace()`（商店 / 营地 / BOSS 战利品 / 棋盘武器格 / 武器藏库共用）

## 1. 现象与原因

棋盘拿满两把武器后再获得武器（武器格、宝箱、武器藏库、营地补给、BOSS 战利品）会弹替换层：
上半屏是新武器详情，下面每个旧武器一块「卸下说明 + 替换后预览 + 替换按钮」，最后是「取消」。

弹层用 `CenterContainer + PanelContainer + VBoxContainer`，**完全按内容高度撑开、没有上限**。
480×270 是逻辑分辨率，内容在 2 把旧武器 + 多行新武器详情时很容易超过 270：

| 场景 | 内容高度 | 面板高度 | 结果 |
|---|---|---|---|
| 实测（火焰剑 / 匕首，新武器 2 行） | 280 | 284（y 0→284） | 面板上下都溢出，「取消」在 y 252→282，底边被裁掉 |
| 新武器带锋铸/熟练/铭印/追赶多行 | 302 | 302 | 更严重：第二个「替换」按钮和「取消」都在屏幕外 |

居中容器不会缩放，超出部分直接被画到屏幕外——所以点不到。

## 2. 修复

只改 `battle_hud.gd`，不动任何玩法数值：

1. 面板内部改为 `ScrollContainer`（横向关闭、纵向 AUTO），`VBoxContainer` 放进去并横向撑满；
2. 每次打开调用新的 `_fit_replace_dialog()`：固定宽 320，先量内容自然高度，
   再夹到 `HUD 高度 − 16`（480×270 下为 254）。不超屏时高度仍等于内容高度——**外观与原来一致**；
   超屏时才出滚动条，所有按钮都能滚到；
3. 每次打开把滚动位置复位到顶部；
4. 行间距 6 → 4（省 16px，常见情况不再触发滚动）。

`await` 后加了 `is_instance_valid` 守卫，弹层/HUD 在测量期间被释放不会报错。

## 3. 验证

探针工具：`tools/replace_dialog_probe.gd` / `.tscn`
（产物 `docs/baseline/2026-11-08_replace_dialog/`，跑在隔离 `APPDATA` 下）：

| 场景 | 面板矩形 | 滚动条 | 尾部按钮 |
|---|---|---|---|
| 修复前 | (88,0) 304×284，屏高 270 | 无 | 「取消」y 252→282，**屏内=否** |
| 修复后·常规 | (78,8) 324×253 | 不需要 | 「取消」y 229→259，**屏内=是** |
| 修复后·长内容 | (78,6) 324×258（内容 302） | 需要（302 > 254） | 滚到底「取消」y 232→262，**全局可视=是** |

截图：`01_replace_dialog`（常规，整层可见）、`02_long_dialog_top`（长内容顶部，右侧滚动条）、
`03_long_dialog_bottom`（滚到底，取消按钮完整可见）。

回归：全量 smoke 20 套 ALL GREEN（含 L1 lint 1191 / L2+L3 3617）。

## 4. 影响面

同一个函数被商店、营地、BOSS 战利品、棋盘武器格、武器藏库共用，所以这五处一起修好。
其余弹层（营地、武器藏库）内容更短，本次未改。

## 5. 顺带修掉的测试抖动

验证过程中 `g5_journal_test` 的「时长已记录」失败过一次：`duration_sec` 按 0.1 秒取整，
headless 跑得比真实时间快，模拟局有可能在 50ms 内跑完而被取整成 0.0。
已改为在 `finish()` 前等足真实 150ms（不改进游戏逻辑，只让测试确定），连跑 3 次均 17/17。
