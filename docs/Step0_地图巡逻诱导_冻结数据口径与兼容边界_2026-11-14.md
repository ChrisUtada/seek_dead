## 1. 结论

现有工程里有**两套并存的地图模型**：`board_generator.gd` 的 1D3 节点骨架（25–29 节点、三幕）与 `board_grid.gd` 的 4×4 扫雷内容灰盒（16 格、3 套模板）。计划要求的 14×9 三区域逻辑地图**尚不存在**，也没有 `patrol` / `trap` 实现。本步把新地图要用的字段钉到唯一数据源上，并确认旧入口不被写坏。

🟢 **口径已定（2026-11-14）**：14×9 地图**替换**上述两套旧模型，工程内只保留一种地图；不通过 `layout_mode` 新增第三种模式。依据：计划 §8 明确把「出现第二套移动资源、行动点转轮或扫雷规则」列为停止条件，并存会直接触发该条；§3.1 也要求「三个区域，一张逻辑地图」。因此 Step 0 出口「旧地图和战斗回归入口仍可运行」按 §5 / §6.1 重新解释，不再按「保留旧地图」理解。

⚠️ 计划文档、`docs/mockups/patrol_trap_map_ui.png`、`tools/make_patrol_trap_mockup.py` 等是 2026-11-14 12:01–12:34 的**并行产物**，不是本步产出；本次仅在主计划补一条决定注记，未改其实质内容。

## 3. 字段冻结（Step 0 任务 2 / 3）

### 3.1 地图格字段

| 字段 | 冻结口径 | 唯一数据源 | 现有对应 |
|---|---|---|---|
| 地形 `terrain` | 新增；枚举至少含 `walkable / wall / door`；区域 A/B/C 用地形或地板色区分，不新增读图成本 | 新 `MapGrid` 静态数据 | 无（4×4 全格可行走） |
| 坐标 `row / col` | 14 列 × 9 行 = 126 格；`col ∈ [0,13]`、`row ∈ [0,8]`，行优先，`col + row*14` 为 id | `MapGrid` | 4×4 已有 `row/col/distance`，同名复用 |
| 内容 `content` | 复用现有 `type` 枚举；宝箱 / 商店 / 休整 / BOSS / 精英沿用 11 种节点类型，不新增平行类型 | `BoardNodeData.make()` | 13 字段：`id/type/depth/act/next/room/ria/battle_index/item_path/title/desc/icon/final` |
| 可见性 `visibility` | 位置**始终公开**（§3.4）；现有 `revealed` / `visible` 两套标记需收敛为一个只读派生值，不写回节点 | `BoardSystem.revealed` | 4×4 有 `revealed`、`visible`、`frozen` |
| 消耗状态 `consumed` | **只存运行时字典，不写节点**；回访不重复发奖 | `BoardSystem.consumed` | 现有注释已明确「消耗状态由 BoardSystem.consumed 保存，不写入节点本身」 |
| 击败状态 `defeated` | 同上，运行时字典 | `BoardSystem.defeated` | 已有 |

**禁止**：把 `terrain / 巡逻 / 陷阱` 结果写进 `resources/weapon_templates/`、`charms/` 等共享装备资源；不为地图新增第二套装备目录。
