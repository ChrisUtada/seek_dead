## 1. 纠偏结论

当前版本已经完成部分主题换色、细线框和少量图标接入，但与目标图仍存在结构性差异：

1. 玩家与 BOSS 的实际显示尺寸过大，BOSS 还使用了非整数倍率。
2. 左侧双武器、技能/护符和消耗品仍是小图标或扁按钮，不是目标的大图标卡片。
3. 顶栏仍保留旧“本局加成”等信息结构，金币与回合布局未按目标收敛。
4. 右侧仍以文字列表为主，缺少图标化属性、中央 HP 和机制摘要。
5. 普通敌人仍未完成红色风格化。

本轮必须优先解决上述五项。**不得只用“整体风格接近”“回归测试通过”代替视觉验收。**

## 2. 严格执行边界

### 2.1 允许修改

- 战斗 HUD 的场景、节点布局、尺寸、颜色和文本刷新。
- 左栏装备/消耗品显示组件。
- 右栏属性与机制摘要的显示组件。
- 与角色尺寸直接相关的 `ENEMY_SPRITE_SIZE`、`PlayerSprite` 和样板 BOSS `art_scale`。
- 普通敌人与 BOSS 的风格化副本及资源引用。
- 纯展示用的机制摘要字段或等价展示配置。
- 现有截图采集工具和必要的 UI 定向验证。

### 2.2 禁止修改

- 不修改伤害公式、成长、奖励、掉落、房间机制、存档和 RNG。
- 不修改 `balance_config.tres`、武器数值或 BOSS 数值。
- 不新增角色技艺、武器铭印或其他系统。
- 不批量制作全部武器、全部符号或全部敌人图标。
- 不执行全量武器小人化。
- 不做大规模代码重构，不顺带清理无关债务。
- 不覆盖原始 `assets/enemy.png`、`assets/bossbf.png` 和原始角色帧。
- 不使用 `git reset --hard`、`git checkout -- .`、`git clean -fd` 等命令清除现有工作。
- 不把其他未提交改动视为可丢弃内容。

### 2.3 目标图使用原则

- 目标图决定布局、比例、颜色和组件形式。
- 目标图中的示例数值不是游戏真实数据，HP、回合、护甲和机制周期必须读取实时状态。
- 不为追求像素位置一致而把整个 HUD 改成绝对坐标，继续使用 Container 与锚点。
- 可以存在少量文字宽度差异，但不得改变规定的组件类型和角色尺寸。

## C1 · 玩家与 BOSS 尺寸必须回到目标比例

### 强制目标

| 对象 | 逻辑显示尺寸 | 说明 |
|---|---:|---|
| 玩家 | **48×48** | 与原始 48×48 帧 1:1 显示 |
| 普通敌人 | **48×48** | 样板默认敌人与玩家同规格 |
| 冰封铁瓮 | **96×96** | 原始 48×48 图以整数 2×显示 |

### 必改项

- `scenes/ui/battle_hud.tscn` 中 `PlayerSprite.custom_minimum_size` 从 96×96 调整为 48×48。
- `scripts/ui/battle_hud.gd` 的 `ENEMY_SPRITE_SIZE` 调整为与 48×48 普通敌人一致的基准。
- `resources/rooms/frozen_urn.tres` 的 `art_scale` 从 2.25 改为 **2.0**。
- 检查动画 scale 脉冲结束后恢复原值，不得把运行时尺寸永久留在其他倍率。
- 保持玩家和 BOSS 的中心、脚底和地面阴影位置合理，不得因缩小留下错位。

### 验收

- 日志或截图采集实测玩家为 48×48、冰封铁瓮为 96×96。
- 玩家与 BOSS 的显示比例约为 1:2。
- BOSS 不遮挡转轮、SPIN、意图和 HP。
- 不允许再把角色整体放大当作“增强存在感”的替代方案。

## C2 · 左侧必须改成大图标卡片结构

### C2-1 双武器

强制改为两列大图标槽位：

- 每槽建议 36–38px 宽、38–42px 高，受左栏实际宽度约束可微调。
- 每槽使用武器的 24×24 `art`；无 `art` 时才使用 16×16 `icon_tex` 或旧 emoji 回落。
- 图标下方允许保留短名称，最多一行，不得把卡片撑宽。
- R 等级和熟练信息放 tooltip，不在槽内堆长文字。
- 保留完整武器名、元素、熟练和铭印 tooltip。
- 不得继续只显示“16px 图标 + 元素 emoji + R 等级”的横向小行。

建议将 `WeaponsRow` 改成两列 Grid/HBox 结构，节点路径保持不变；动态槽位构建可继续由 `player_panel_view.gd` 负责。

### C2-2 技能与护符

- 主技能和主护符使用与武器区协调的大图标槽位。
- 已有图标使用图标，无图标保留文字/emoji 回落，但槽位尺寸保持一致。
- 技艺图标不得把主技能槽挤成多行小字；可放在次级小图标行或 tooltip 中。
- 不改变技能、护符和技艺的实际数据。

### C2-3 消耗品

- 保持 2×2 排列。
- 每格由当前 34×20 扁按钮改为约 34–36px 宽、30–34px 高的方格。
- 格内显示居中图标和剩余次数，名称与详细说明放 tooltip。
- 空位、禁用和律法锁定状态必须仍可辨。
- 不得因为方格增大而撑宽左栏或挤压中央舞台。

### C2 验收

- 双武器在截图中是两个明显的大图标槽位，而不是小文本行。
- 消耗品是清晰的 2×2 方格，而不是四个扁按钮。
- 左栏总宽保持约 88–92px，不出现横向溢出。
- 所有物品仍能通过 tooltip 查看完整信息。

## C3 · 顶栏必须按目标重排

### 强制结构

```text
ACT/房间  ·  金币              回合              商店  下一房
```

### 必改项

- `RoomLabel` 显示当前幕与房间，例如 `ACT I · 房 3/8`，不得只显示无幕信息的旧格式。
- 金币移到顶栏左侧区域，使用现有 `assets/icons/16/gold.png` 或保持一致的金币语义。
- `TurnLabel` 保留并居中或位于中央区域。
- `RunLabel` 从顶栏移除或隐藏；其承载的共鸣/本局加成信息不得直接删除，应移到左栏弱信息行或现有 tooltip。
- `GoldLabel` 若迁移节点，必须同步更新 `battle_hud.gd` 的 `@onready` 路径。
- 商店与下一房保留原禁用和间歇逻辑；下一房可用时金色强调，商店战斗中禁用。
- 左栏不再重复显示大号金币信息，可保留给装备或成长状态使用。

### 验收

- 顶栏不再出现“本局加成”占用主信息位。
- 房间、金币、回合、商店和下一房在 480×270 下完整可读。
- 共鸣/本局加成仍能在左栏或 tooltip 查到。
- 顶栏高度保持约 21–23px，不能因新增金币明显增高。

## C4 · 右侧与中央信息必须图标化、摘要化

### C4-1 右侧属性

- HP 使用 `assets/icons/16/hp.png`。
- 护甲/护盾使用现有 shield/armor 图标。
- 充能使用 `assets/icons/16/charge.png`。
- 弱点、抗性、意图保持明确颜色语义，不只靠颜色，必须同时有文字或图标。
- 右栏顺序保持：BOSS/敌人名称 → HP → 护甲 → 弱/抗 → 下一意图 → 充能 → 状态 → 机制摘要。
- 名称、HP、意图是主层级；机制摘要是次级层级，不能全部同样高亮。

### C4-2 中央 HP

- 玩家精灵下方增加简短 HP 显示。
- 敌人精灵下方增加简短 HP 显示。
- 使用绿色 HP 图标/文字，低 HP 时可按现有危险规则变红。
- 新节点必须接入 `_refresh_meta()` 或等价统一刷新，不得只在截图时写死数值。

### C4-3 BOSS 机制摘要

- 为 BOSS 增加纯展示用机制摘要配置，或复用现有资源中的等价描述。
- 默认空值时不占位，不破坏其他敌人。
- 冰封铁瓮必须显示与真实 `gimmick_params` 一致的短摘要，例如“每 3 回合 / 叠加护甲 / 火系可破”。
- 不得照抄目标图中的“每 2 回合”示例数字；以真实配置为准。
- 摘要最多 2–3 行，完整机制仍通过 tooltip 或现有说明查看。

### C4 验收

- 右侧不再只是无图标的长文字列表。
- 玩家与 BOSS 下方 HP 随实际战斗刷新。
- 冰封铁瓮摘要与真实机制周期一致。
- 右栏无长文本越界，所有重要信息在 480×270 下可读。

## 附录 A · 示例图标绘制规范（强制）

本附录是 C2/C3/C4 的组成部分。执行 AI 不得只满足“有图标”，还必须按以下规格绘制或复用目标图同款图标。若重新绘制，不得自行改成描边卡通、厚涂、线性矢量或 emoji 风格。

### A.1 画布与文件

| 用途 | 画布 | 内容区域 | 文件 |
|---|---|---|---|
| 转轮、属性、状态、左栏小图标 | **16×16 RGBA** | 主体限制在 x=2…13、y=1…14，四周保留至少 1px 透明安全区 | `assets/icons/16/{id}.png` |
| 武器与奖励卡片主图 | **24×24 RGBA** | 16×16 主体居中，外框/留白属于卡片规格 | `assets/icons/24/{id}.png` |

- 16×16 与 24×24 必须分别设计排布，禁止通过拉伸、双线性缩放或 48→16 缩小生成。
- 文件必须为透明背景，不得带白色、黑色或近纯色底。
- 图标不得预先烘焙匹配角标、元素色条、稀有度框或选中框，这些由 UI 组件负责。
- 引擎中使用 NEAREST；16px 图标按 1:1 显示，卡片 24px 版也按 1:1 显示。

### A.2 像素与颜色规则

- 每枚图标最多使用 **3 个实体颜色 + 透明色**。
- 允许颜色：深描边 `#3A222B`、暖白 `#E2D7BD`、次级 `#A99D89`，以及对应语义主色和必要的同族暗阶。
- 生命用 `#A4BC4D`，护盾/护甲用 `#62A1C2`，危险/火焰用 `#E35B50`，金币/充能/技能用 `#D5A33D`，玩家/中性武器用 `#B9B8B0`。
- 不使用渐变、抗锯齿、柔边、投影、外发光、噪点和半透明过渡像素。
- 轮廓以直角和 45°阶梯为主，不使用平滑矢量曲线。
- 图标以实心大色块为主，深描边只在确有必要时分隔结构，不给所有图标机械加统一黑框。
- 同一图标的亮部面积不得过大，避免在暗底上变成无法辨认的一团。

### A.3 逐图标造型要求

| 图标 | 强制造型 | 禁止偏差 |
|---|---|---|
| **HP 心形** | 约 11×11px；双圆角方形瓣，顶部两瓣对称，向下逐级收束成尖角；生命绿实心 | 不使用文字“HP”代替，不画成圆形或细线心形 |
| **护盾** | 约 10×12px；平顶，左右竖边后向下阶梯收尖；蓝色外框，内部保留暗色盾芯 | 不画成盔甲人物，不使用蓝色实心方块 |
| **护甲** | 与护盾同族但主体更实，蓝色盾面配暗色内部分隔，必须与 HP 一眼可分 | 不与护盾做成完全无关的另一套透视 |
| **金币** | 约 10×10px 阶梯方圆形；金色外圈，内部用暗色形成竖向币纹或小方孔 | 不使用字母 G、圆形渐变金币或成堆硬币 |
| **剑/火斩** | 约 12×16px；左下至右上的对角剑，刃宽 2–3px，暖白或元素色剑刃，金色短护手，暗色剑柄 | 不画成细针、水平剑或带复杂花纹的写实剑 |
| **战斧/斧斩** | 约 12×15px；斜向斧柄，斧头明显偏右上，单侧宽刃形成不对称轮廓，灰白金属 | 不画成锤子、剑或对称双翼斧 |
| **火焰/灼烧** | 约 12×16px；顶部火舌向右错峰，底部较宽，外层主色，内部保留约 4×6px 金色火芯 | 不画成对称水滴、圆形火球或满格方块 |
| **消耗品药剂** | 约 11×14px；短瓶盖、窄颈、阶梯方瓶身，红/紫液体，底部保留少量暖白高光 | 不画成烧杯、试管或带标签文字的瓶子 |
| **充能** | 约 10×14px；金色折线闪电，顶部偏右，中部收窄，底部反向折回 | 不画成电池、星星或字母 E |
| **技能/星芒** | 约 12×12px；四角星，中心约 3×3px，四臂以 1–2px 阶梯延伸，金色 | 不画成五角星、圆形光晕或复杂法阵 |

### A.4 风格一致性验收

执行 AI 必须输出一张包含全部样板图标的 contact sheet，同时提供 1×、2×和 4×视图，并逐项满足：

- 在 16×16 原生尺寸下不放大也能识别用途。
- 转为纯黑剪影后，剑与斧、火焰与药剂、护盾与金币不会混淆。
- 同组图标的主体大小、视觉重量和明暗比例一致。
- 没有调色板外颜色、抗锯齿过渡色和孤立单像素噪点。
- 图标在转轮格、卡片和右栏中不被边框、角标和元素色条遮挡。
- 不得用“AI 生成图风格不同”作为豁免理由；不合格就重画或改用目标图同款资源。
