## 2. Step 1 · 真实对策查询

`scripts/systems/readability_system.gd` 新增只读查询：

| 查询 | 数据来源 | 用途 |
|---|---|---|
| `_symbol_paths_of_kind(kind)` | 当前 `reel_system.reel_strips` | 护盾 / 治疗 / 特殊 / 输出符号 |
| `_pierce_paths()` | 符号 `pierce_armor = true` | 穿透护甲直接扣 HP |
| `_consumable_counter(effect)` | 当前 `consumable_slots` 且 `charges > 0` | 治疗 / 净化 / 清净 / 破甲 / 强化 / 攻击 |
| `current_gimmick.recovery_window()` | 现有 BOSS 机制 | 熔铸间隙是否真实存在 |
| `pending_jam/lock/chaos/auto_stop`、`player_frost`、`player_status` | 现有战斗状态 | 干扰与玩家侧负面状态 |

规则：**只列当前真实存在且能生效的对策**；无资源时不生成对应建议；护盾/治疗/破甲等选项的 tooltip 带真实符号名，
消耗品带真实物品名。重击保留「硬吃 N」兜底，干扰保留「照常停轮」兜底，不把不跟随建议记为错误。

## 3. Step 2 · 局势 + 多对策提示

### 3.1 提示结构

```text
⚖ 重击 52 · 可应对：护盾符号 / 治疗符号 / 治疗药剂 / 硬吃 52 · control
```

- 主栏只保留「局势 + 短标签」；每条对策的符号名/物品名/预计伤害放在 tooltip。
- 标准模式不再显示 `🎯 唯一目标`；`target_symbol_path` 仅保留给遥测与 A/B 口径。
- `--p1-target` 固定对照仍显示 `🎯` 单目标行，保证既有 P1 数据口径不失真。

### 3.2 局势判定顺序

重击 → 低血（≤40%）→ 熔铸间隙 → 高甲 → 干扰（含寒霜/酸蚀）→ 残血（≤25%）→ 输出窗口。

### 3.3 遥测

`run_telemetry.gd` 新增：

- `stop_kinds`：玩家主动停中的符号类别计数（damage/shield/heal/special/status/buff/trash）；
- `consumable_uses`：消耗品 effect 使用计数；
- 两者进入 `summary()` 与 `summary_text()`；机制替停不计入玩家停轮类别。
