# G2-01 真机验收清单 · 棋盘装备替换与追赶

> 版本：2026-11-06（G2-01 实施后）

## 0. 前置与判定

1. 备份存档：
   ```text
   %APPDATA%\Godot\app_userdata\Seek Dead Prototype\lobby_data.json
   ```
2. 整备页确认默认配装为**双武器**（武器槽 2/2），再开棋盘。
3. 每项按「步骤 → 预期」执行；不符合就记 `×`，附截图和所在房/节点，**不要改数值或重开同一局补数据**。
4. 全部通过的标准：第 1–5 节所有项为 `√`，且第 6 节能核对到来源信息（若 UI 暂未展示，记 `N/A` 并注明）。

## 1. 棋盘武器格（满双武器）

| # | 步骤 | 预期 |
|---:|---|---|
| 1.1 | 双武器已满，掷骰落到武器格（n2） | 弹出「棋盘武器：替换」层，不是直接顶掉一把武器 |
| 1.2 | 看替换层 | 每把旧武器先有一行「卸下：名称 · 攻X · 元素 · R 熟练 · 铭印（熟练/铭印保留，重装恢复）」 |
| 1.3 | 看同一把旧武器下方 | 有「替换后：」带子格数增减 / 共鸣得失；无变化时写「替换后：无变化」 |
| 1.4 | 看新武器信息 | 含元素、真实攻击（含锋铸）、命中、熟练/铭印、以及「追赶：熟练 X → Y（有效清房每房 +1）」（新武器落后时） |
| 1.5 | 点「取消」 | 回到棋盘；未获得新武器；信息栏/日志说明节点已消耗 |
| 1.6 | 取消后再掷骰经过同一节点 | 不会再次弹出替换层、不会重复结算该节点 |
| 1.7 | 重开一局，再落到武器格，点某把旧武器 | 替换成功：新武器入槽、入图鉴；旧武器仍在收藏（整备可再选）；转轮带立即更新 |
| 1.8 | 替换后继续走一步 | 节点只结算一次，不发生二次替换或二次入图鉴 |

## 2. 战后三槽的武器卡（满双武器）

| # | 步骤 | 预期 |
|---:|---|---|
| 2.1 | 普通/精英胜利后，三槽「构筑」位出现武器卡 | 点它弹出「胜利奖励：替换武器」层 |
| 2.2 | 点「取消」 | 回到**同一三槽屏**，不是黑屏/卡死；三张卡仍可选 |
| 2.3 | 取消后改选补给或成长 | 正常结算，本次成长不丢失 |
| 2.4 | 再点同一张武器卡 | 替换层再次打开；确认后奖励只结算一次（不会连发两把武器） |
| 2.5 | 三槽都不想要时点「放弃本次成长」 | 正常结束战后界面，进入下一房/回棋盘 |

> 这是旧 A/B 记录里 V4/V5 的场景。若取消后出现无法继续、重复同屏或必须重开，记 `×` 并保留截图。

## 3. BOSS 战利品替换

| # | 步骤 | 预期 |
|---:|---|---|
| 3.1 | 满双武器时在 BOSS 战利品里选武器 | 弹出「★ BOSS 战利品：替换武器」层 |
| 3.2 | 点「取消」 | 回到 BOSS 战利品界面，其他战利品仍可选；BOSS 奖励没有被吞 |
| 3.3 | 再选同一把武器并确认 | 替换成功，进入后续流程，只结算一次 |
| 3.4 | 检查旧武器 | 旧武器回到收藏，熟练/铭印保留；新武器入图鉴 |

## 4. 商店替换购买

| # | 步骤 | 预期 |
|---:|---|---|
| 4.1 | 满双武器时点商店武器 | 弹出「替换武器」层 |
| 4.2 | 点「取消」 | 回商店；**金币未扣**；该商品未售出，可再次购买 |
| 4.3 | 再次点同一商品并确认 | 扣除标价；旧武器回收藏；新武器入槽/图鉴；商品标记售出 |
| 4.4 | 金币不足时点武器 | 只提示金币不足，不打开替换层、不扣钱 |

## 5. 换装追赶

| # | 步骤 | 预期 |
|---:|---|---|
| 5.1 | 中段换上一把新武器（此前熟练 0），打 1 个普通房 | 日志出现「追赶 +1：对齐本局最高熟练 N」；该武器本房 +2（基础 1 + 追赶 1） |
| 5.2 | 下一房为精英 | 该武器本房 +3（基础 2 + 追赶 1），**不超过每房上限 3** |
| 5.3 | 打到追平本局最高熟练后再清房 | 只显示基础 +1/+2，不再出现「追赶」 |
| 5.4 | 把换下的旧武器再装回（棋盘/商店/奖励均可） | 熟练与铭印保留，不重新从 R1 开始，也不再触发追赶 |
| 5.5 | 追赶跨过 R2 | 成长位出现该武器的铭印选择（锋铸/调律），需要手动选；不会自动发放 |
| 5.6 | 同一房多次结算 | 追赶不会在同一房重复叠加，每房最多一次 |

> 追赶只对**局中新换上**的武器生效；开局配装的两把武器不触发追赶。

## 8. 失败分支（不要顺手改数值）

| 现象 | 先查 | 不要做 |
|---|---|---|
| 取消后卡死/黑屏 | 替换层的 on_cancel 是否正确回到来源界面 | 不要通过“取消也发武器”绕过 |
| 取消后节点还能再结算 | 棋盘 `_board_weapon_cancel` 与节点消耗标记 | 不要改成“取消可重抽” |
| 同一武器连发两次 | 奖励结算入口是否被替换层提前调用 | 不要调奖励概率 |
| 追赶不触发/超上限 | `catchup_target`、`_start_paths`、每房 `ROOM_GAIN_CAP` | 不要直接加熟练数值 |
| 换回旧武器熟练丢失 | `mastery`/`imprints` 是否被换装路径清空 | 不要用补偿数值掩盖 |

验收完成后，把结果回写 `docs/统一制作执行计划_2026-11-06.md` §6 G2-01 与 §14 看板。
