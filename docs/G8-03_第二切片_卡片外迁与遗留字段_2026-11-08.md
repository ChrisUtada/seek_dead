## 2. 卡片构造外迁（`scripts/ui/card_factory.gd`）

### 2.1 边界

`CardFactory` 是 `RefCounted`，只按数据造控件：

- 持有 `_hud`（BattleHud）与 `_ctrl`（DuelController）两个引用，不持有任何局内状态；
- 不做布局挂载、不做每帧刷新——挂载与选中态仍由 `reward_screen` / `shop_screen` /
  `meta_screen` / `loadout_scene` 各自负责；
- 点击信号仍由 HUD 发出（`_hud.<signal>.emit`），因此所有外部监听点与调用点不变。

### 2.2 外迁的 9 个构造器

| 方法 | 产物 | 原 HUD 包装 |
|---|---|---|
| `source_tag(kind)` | 来源标签文本 | `_source_tag` |
| `item_card(data, path, kind)` | 整备/侧栏多行物品卡（Button） | `_make_item_card` |
| `reward_card(rw, index, slot_label)` | 房奖励三选一 / BOSS 前 | `_make_reward_card` |
| `post_growth_card(cand)` | 战后成长位 | `_make_post_growth_card` |
| `boss_reward_card(cand)` | BOSS 战利品 | `_make_boss_reward_card` |
| `meta_card(opt)` | 局末元进度三选一 | `_make_meta_card` |
| `unlock_card(cand)` | G6-02 生涯定向解锁 | `_make_unlock_card` |
| `shop_card(offer)` | 商店货架卡（含价格/槽位状态） | `_make_shop_card` |
| `sell_card(...)` | 商店卖出区 | `_make_sell_card` |

HUD 保留同名薄包装（一行转发）。这样 `reward_screen.gd`、`shop_screen.gd`、
`meta_screen.gd`、`loadout_scene.gd` 与测试都不需要改动。

判定逻辑（价格重算、替换/开槽/槽满文案、暴击率与命中率拼接、payload 取图优先级）随函数体
逐行搬移，未改任何数值、文案或布局常量。

## 3. ARPG 遗留字段

### 3.1 已删除（代码 0 引用 + `.tres` 0 写入）

`WeaponData`：`weapon_scene`、`grip_point`、`visual_offset`、`visual_scale`、
`heat_per_attack`、`bullet_scene`。这 6 个字段在 90 个武器 `.tres` 中都没有写入，
删除不会让任何资源属性失配。

### 3.2 保留（`.tres` 仍写入，删字段会让资源属性失去落点）

| 字段 | 写入的武器资源数（/90） |
|---|---|
| `damage` | 24 |
| `attack_speed` / `attack_range` | 24 / 24 |
| `damage_type` | 18 |
| `cleave_angle` | 17 |
| `knockback_force` | 16 |
| `status_effect_type` / `_damage` / `_duration` | 10 / 10 / 10 |
| `bullet_speed` | 6 |
| `can_dual_wield` | 5 |
| `max_ammo` | 3 |
| `ammo_per_shot` | 1 |

这些字段仍不参与转轮战斗，但清理必须连同 `.tres` 一起改（或做一次资源迁移），
属于独立立项，不随本切片做。`docs/武器制作逻辑_设计规范.md` §7 已记录现状与建议。
