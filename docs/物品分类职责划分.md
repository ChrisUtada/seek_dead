# 物品分类职责划分（宪章 + 落位表 + 来源标签）

> 文档状态：v1 · 2026-08-03 建立
> 关联改动：`battle_hud.gd` 已落地来源标签（`_source_tag`）；`docs/数值膨胀与策略深度设计框架.md` §15.9 的「增益→技能」重构已并入本划分。
> 适用范围：技能（skill）/ 护符（passive）/ 消耗品（active）/ 武器（weapon）四类整备槽位。

---

## 0. 结论（一句话）

三分类的**机制分工一直是对的**，玩家觉得"重合"是因为**按效果读、看不到机制差异**。修法是两件事：

1. **来源标签（已落地）**：每张卡/tooltip 显示 `【武器】/【常驻】/【主动】/【转轮】`，让"同一效果为何在三处"一眼可辨。
2. **内容宪章（本文 §4）**：未来加物品时先定机制，禁止"同形复读"。

不推翻重分、不开第 5 类。

## 1. 三分类职责宪章

| 类别 | 键 | 触发机制 | 风险 / 收益 | 职责（job to be done） | 边界（什么**不**属于它） |
|---|---|---|---|---|---|
| **武器** | `weapon` | 整备装配；符号**进轮**，RNG 连线命中 | 免费 + 不确定；武器 base/特殊符号是老虎机核心 | 定义**输出形态**（哪些符号、什么特殊） | 非武器符号的增益/减益 |
| **护符** | `passive` | 整备装配；**整局/整房被动常驻**，必定生效 | 零操作、零 RNG、永远在线；常带负面或仅涓流 | 定义 **build 基底**：永久乘区/加值、每回合涓流、抗性、净化容量 | 需临场决策或 RNG 的临时效果 |
| **消耗品** | `active` | 战斗**手动按钮**，按 `charges` 消耗，用掉即消耗（不每房回满） | 强效但有限；策略核心是"何时花"，可商店补 | **应急工具箱**：大回复、解干扰、重转、定向爆发 | 被动常驻 / 纯 RNG 的临时增益 |
| **技能** | `skill` | 符号**进轮**，RNG 连线命中，临时（回合递减），免费 | 免费但不确定；爽点是"天胡 combo" | **老虎机奖金**：转轮联动、combo 倍率、爆发收割 | 常驻基底 / 玩家手动决定的效果 |

**核心判别法**：新效果先问"它怎么触发？"
- 常驻、装配即生效 → **护符**
- 玩家手动、限时、有限次 → **消耗品**
- 进转轮、靠 RNG、临时 → **技能**
- 决定输出符号池 → **武器**

## 2. 来源标签（已落地）

### 2.1 标签含义
| 标签 | 类别 | 一句话 |
|---|---|---|
| `【武器】` | weapon | 进轮输出形态，决定符号池 |
| `【常驻】` | passive | 装配即生效，整局/整房一直在线 |
| `【主动】` | active | 战斗中手动按，有限次、用掉即消耗、可商店重复购买同类补满（固定 4 格腰带，整备仅选 1 类） |
| `【转轮】` | skill | 入转轮靠 RNG 触发，临时 |

### 2.2 代码位置（`scripts/ui/battle_hud.gd`）
- 新增辅助函数 `_source_tag(kind: String) -> String`（紧邻 `_kind_name`）。
- 注入四处：
  1. `_make_item_card`：整备四列卡名前置标签；
  2. `_make_shop_card`：商店卡标题前置标签（`%s%s · %s`）；
  3. `_sell_fill`：卖出卡名前置标签；
  4. `_refresh_meta`：玩家 buff 行改为 `【转轮】技能:`。

> 注：转轮格子的符号 tooltip（`_show_symbol_tooltip`）沿用语义 `技能/护盾/治疗…`，那是**符号 kind**维度，与物品的**来源**维度正交，不强行改。

## 4. 内容宪章与决策规则（防止未来"同形复读"）

> **宪章**：同一效果允许跨类存在，**但必须有不同的 SHAPE**（永久 / 瞬时 / RNG），禁止两个物品在"机制 + 数值级"上重复。

### 4.1 决策规则（加新物品时按序判）
1. 先定**触发方式** → 落到对应类别（见 §1 判别法）。
2. 再查本类是否已有同效果：
   - 无 → 直接加；
   - 有但 SHAPE 不同（如护符永久 ×1.5 vs 技能本回合 ×1.5）→ 允许并存，且**同数值也无妨**：二者是「护符乘区」与「技能 RNG 乘区」两个独立乘区，结算时相乘（=×2.25），正是设计想要的乘法深度；感知重叠已由 `【常驻】/【转轮】` 来源标签 + 伤害分解面板（分列"护符×/增益×"）解决，无需拉开数值（见 §5）；
   - 有且 SHAPE 相同 → **禁止**，要么换机制，要么砍掉旧的。
3. 护符/消耗品/技能三者**职责互斥**，新机制优先复用现有 effect 字段，不新开平行系统。

### 4.2 当前"看似重合"的合规判定
| 效果 | 三处来源 | 判定 |
|---|---|---|
| 伤害放大 | 狂怒护符×1.5(永久) / 锋锐×1.10(永久) / 深渊×1.15(永久) / 锈蚀+4(永久加值) / 强袭×2(手动定向) / 迅捷×1.5(转轮临时) / 狂怒印记+3(转轮临时) | ✅ 七种 SHAPE 全不同；狂怒护符×1.5 与迅捷×1.5 看似撞车，实为两独立乘区相乘(=×2.25)，是设计想要的深度；感知重叠已由标签+分解面板解决（见 §5） |
| 治疗 | 回春护符+6/回合(涓流) / 治疗药剂+30(瞬回) | ✅ 常驻 vs 主动，互补 |
| 护盾 | 守望+12开局 / 铁壁+8回合 / 守备+4回合 | ✅ 仅护符，无跨类 |
| 净化 | 净化药剂即时解控 | ✅ 净化仅走消耗品路径（腰带 4 格）；玩家需为净化药剂预留格子 |
| 抗扰 | 抗扰护符 / 呓语残页 | ✅ 仅护符，强度档位不同 |

→ **无真冗余**，符合宪章。

## 5. 数值巧合说明（原"微调建议"已撤销）

> ⚠ **2026-08-03 更正**：原文档曾建议"把迅捷改成 ×1.6 拉开数值"，经核查代码后确认这是**误判**——狂怒护符与迅捷的 ×1.5 是**两个独立乘区，结算时相乘（=×2.25）**，属设计本意（少乘区、独立相乘），非冲突。故该微调建议**撤销，数值保持不动**。

| 现象 | 结论 | 理由 |
|---|---|---|
| 狂怒护符 ×1.5（永久）与 迅捷 ×1.5（本回合）看似"数值撞车" | **不改动（已撤销原建议）** | 二者是「护符乘区」×「技能 RNG 乘区」两独立乘区，`_agg_damage_mult()` 返回 `charm_damage_mult * _buff_damage_mult()`，命中迅捷的那回合计 ×2.25；这是求之不得的乘法深度。感知重叠由 `【常驻】/【转轮】` 标签 + 伤害分解面板（分列"护符×1.5/增益×1.5"）已解决 |
| 守护/铁壁/守备三护符护盾档位（12/8/4） | 维持梯度即可 | 已自然分层，无需动 |

> 仅"守护/铁壁/守备护盾梯度"可作纯可读性确认，不影响机制。

## 6. 与「增益 → 技能」重构的关系

- 旧架构的"增益（buff）"槽位 = 进轮临时增益，与武器同池竞争稀释。
- 2026-08-03 重构：把"增益"改名为"**技能**"（机制照搬：进轮、初期限 1 个），并将原 4 个增益拆分——`haste`/`rage` 留作技能，`bulwark`/`regen` 转为护符（新增 `heal` 护符被动）。
- 由此，原"增益 vs 护符 vs 消耗品"的三方重叠，自然收敛为本文的三分类职责划分；技能 = 进轮奖金、护符 = 常驻基底、消耗品 = 应急工具，边界清晰。
- ~~文档滞后提醒~~（已于 2026-08-03 回写）：`数值膨胀与策略深度设计框架.md` 的"增益/buff"措辞已统一为"技能(skill)"，并补「技能」双义区分说明（按停技巧层 vs 物品分类）。
