# Seek Dead · 武器成长与 BOSS 换装解耦执行方案

> 日期：2026-11-15  
> 状态：待执行  
> 优先级：P1；已发现的 BOSS 主题武器品质空池问题仍应作为独立 P0 处理  
> 适用范围：双武器槽、武器熟练、锻造铭印、换装、成长战利品、替换预览  
> 核心决策：**通用数值跟随稳定武器槽；武器熟练与符号专精跟随具体武器；换装不复制成长，也不让通用培养失效。**

---

## 1. 背景与问题判定

当前游戏需要玩家根据 BOSS 的元素弱点、抗性和机制更换武器。与此同时，武器熟练 R1–R4 与铭印会提升当前武器的攻击、命中、暴击或符号权重。

这会产生一个结构性冲突：

```text
把成长投入武器 A
→ 下一个 BOSS 需要另一种元素
→ 用武器 B 替换武器 A
→ A 的熟练与铭印仍保留，但不再参与当前战斗
→ 本次为 A 投入的成长暂时失去当局收益
→ 玩家倾向于不培养武器，或只选永不过期的通用成长
```

问题不是“克制换装比继续使用旧武器更强”。克制换装本来就应该有优势。真正需要解决的是：

1. 通用数值培养因换装而失去当前战斗收益。
2. 玩家无法在替换前清楚判断哪些成长继承、哪些成长暂停生效。
3. 新武器虽然已有熟练追赶，但仍需要重新形成有效战力。
4. 如果所有成长都无条件复制给新武器，又会消灭武器身份并产生重复成长。

## 2. 当前实现边界

执行前必须承认以下现状，不得重复造一套已有系统：

- 当前为双武器结构；替换时旧武器卸下，新武器进入转轮带。
- 武器熟练是本局状态，`WeaponMastery.reset_run()` 会清除熟练、铭印和欠选；不能把本局熟练误写成跨局永久属性。
- 图鉴会记录历史最高熟练，用于横向铸式解锁；这与本局熟练不是同一份数据。
- R2 需要 3 熟练、R3 需要 7 熟练、R4 需要 12 熟练。
- R2、R3 各产生一次铭印选择；同种铭印每把武器最多 2 次。
- 锋铸当前为基础攻击 +2；校准为命中 +5%；暴虐为三连暴击倍率 +0.25；调律为指定符号权重 +1。
- 新换上的武器已有每房 +1 的熟练追赶，直到接近本局其他武器的最高熟练；追赶跨过 R2/R3 时会进入现有铭印队列。
- 旧武器的熟练与铭印已经会保留，重新装备时可以恢复。
- `run_symbol_bonus` 已按符号路径记录，本方案不改变其作用域。
- 横向铸式 `ForgeStyleSystem` 是跨局选择，不能与本方案的槽位成长混为一谈。
- 棋盘 BOSS 信息已经能展示弱点和玩家当前武器元素，不需要重做 BOSS 信息系统。
- 元素克制当前为 ×1.5、抵抗为 ×0.85，本轮先不改倍率。

当前实现的不足是：熟练追赶只缩短成长时间，并不会让旧武器上的锋铸、校准、暴虐和调律作用于新武器。

## 3. 目标与非目标

### 3.1 必须达到的目标

1. 玩家针对 BOSS 换装时，已获得的通用攻击、命中和暴击成长立即继续生效。
2. 武器熟练、调律和武器身份仍然属于具体武器，不变成无条件共享。
3. 换装不增加铭印总预算，不允许通过反复换装复制数值。
4. 所有替换入口使用同一个槽位规则，不能出现商店继承而 BOSS 战利品不继承的差异。
5. 替换预览与实际战斗数值、实际转轮带完全一致。
6. 满级、满铭印或无法产生实际效果的武器训练不得再占据奖励候选。
7. 不改变稀有度与转轮频率解耦的现行规则。

### 3.2 非目标

- 不增加永久攻击、永久命中或无限局外属性成长。
- 不增加新货币、新经验条或第三个武器槽。
- 不把所有专属机制复制给每把武器。
- 不取消元素克制，不让旧武器无条件优于克制武器。
- 不重做棋盘生成器，不新增大地图探索规则。
- 不在本方案中处理 BOSS 主题池缺品质、商店概率或铁砧概率。
- 不通过提高武器基础数值来掩盖成长归属问题。

## 4. 拍板后的成长归属

| 成长或修正 | 归属 | 换装后的规则 | 是否跨局 |
|---|---|---|---|
| 锋铸：基础攻击 | 稳定武器槽 | 新武器立即继承 | 否 |
| 校准：命中 | 稳定武器槽 | 新武器立即继承 | 否 |
| 暴虐：三连暴击倍率 | 稳定武器槽 | 新武器立即继承 | 否 |
| 武器熟练 R1–R4 | 具体武器路径 | 留在旧武器上；新武器走现有追赶 | 否 |
| 调律：指定符号权重 | 具体武器 + 符号 | 留在旧武器上，不作用于新武器 | 否 |
| 符号灌注 | 符号路径 | 按现行共享规则处理，不改 | 否 |
| 横向铸式 | 具体武器路径 | 只作用于选择了该铸式的武器 | 是，现有系统 |
| 全局符号伤害 `run_power_bonus` | 本局玩家构筑 | 保持现有规则，不并入槽位 | 否 |
| 物品稀有度 | 物品资源 | 不决定转轮格数，不改 | 资源定义 |

关键语义：

- 槽位成长表示玩家对这一战斗位置的综合运用，不表示某把武器独有的物理属性。
- 调律仍绑定具体武器，因为它修改的是该武器携带的具体符号。
- 旧武器卸下后不再显示“锋铸仍属于旧武器”；锋铸已经改属槽位。旧武器保留的是自己的熟练和调律。
- 旧武器以后装入哪个槽，就使用哪个槽的通用成长，不能带走先前槽位的数值。

## 5. 数值与预算规则

### 5.1 保留现有单次数值

首轮实施不改以下数值，避免同时引入成长归属和战斗平衡两个变量：

- 锋铸：每级基础攻击 +2。
- 校准：每级命中 +5%，最终命中仍封顶 100%。
- 暴虐：每级三连暴击倍率 +0.25。
- 调律：指定符号权重 +1，必须真实改变转轮带格数才可成为候选。
- 熟练门槛、每房熟练上限和换装追赶保持现状。

### 5.2 防止换装刷成长

每个武器槽建立独立的通用铭印预算：

- 每槽最多选择 **2 次通用数值铭印**。
- 锋铸、校准、暴虐共享这 2 次预算。
- 同一种通用铭印每槽最多 2 次。
- 通用预算在整局内不随武器替换重置。
- 调律仍按具体武器计算，每把最多 2 次；它只改变该武器自己的符号，不在卸下后继续贡献。
- 某武器到达 R2/R3 时，如果槽位通用预算已满且自身没有合法调律候选，则不再产生空的铭印欠选。
- 不允许通过“卸下旧武器 → 装回 → 再卸下”刷新任何预算。
- 不允许把旧槽位成长复制到新槽位；换槽只读取目标槽已有成长。

这套预算保留了原本“两次铭印形成一条小型成长弧”的强度，同时允许玩家自由选择两次都投入通用数值，或把成长机会用于具体武器的调律。

## 6. 战斗与预览的统一公式

### 6.1 实际战斗数值

对位于槽位 `s` 的武器 `w`：

```text
最终基础攻击 = WeaponData.base_power
             + SlotGrowth(s).forge
             + ForgeStyle(w).power

最终命中率 = clamp(
               WeaponData.hit_rate
               + SlotGrowth(s).calibrate
               + ForgeStyle(w).hit,
               0, 1)

最终三连暴击倍率 = WeaponData.crit_mult
                 + SlotGrowth(s).tyrant
```

符号权重仍按现有顺序聚合：

```text
武器符号基础权重
+ 该武器的调律
+ 该武器的横向铸式修正
+ 共鸣修正
+ 本局符号灌注
→ 现有跨来源聚合与格数规则
```

禁止事项：

- 不得同时保留“旧武器锋铸”和“槽位锋铸”两份加成。
- 不得让校准同时通过 `weapon_hit()` 与另一处 MISS 注入重复生效。
- 不得因物品稀有度额外改变格数。
- 不得把槽位基础攻击再加到技能符号上。

### 6.2 预览必须支持假设配装

`ReelPreview` 不能只读取当前真实装备，否则替换弹层里的新武器无法继承目标槽成长。

预览输入必须包含两套完整上下文：

- 替换前：武器数组、各武器所在槽、槽位成长、调律、铸式、灌注、敌方干扰。
- 替换后：假设武器数组、目标槽位、同一个槽位成长、各武器自己的调律和铸式。

替换前后使用同一计算函数。实际建带和预览必须共享格数、命中与元素计算口径，不能各写一份近似公式。

### 6.3 不显示虚假的综合胜率或 DPS

替换界面只展示可准确计算的项目：

- 基础攻击变化；
- 命中率与 MISS 格变化；
- 三连暴击倍率变化；
- 具体符号与共鸣增减；
- 对当前已公开 BOSS 的元素倍率；
- 通用成长继承与武器专精暂停生效的内容。

不要把多武器、多符号、三连、状态和敌人机制压成一个无法验证的“胜率”。

## 7. 分阶段执行步骤

每个阶段完成并通过对应测试后再进入下一阶段。不要一次性改完全部文件后再排错。

### Step 0 · 冻结基线与建立追踪

1. 运行当前 `run_smoke.bat`，记录现有通过数和任何既存失败。
2. 新建专项测试场景 `tests/weapon_slot_growth_test.tscn` 与脚本 `tests/weapon_slot_growth_test.gd`。
3. 先写失败用例，锁定“换装继承通用成长但不复制”的目标行为。
4. 将专项测试加入 `run_smoke.bat`，同步更新套件数量与说明。

验收：基线结果已记录；专项测试能在旧实现上明确失败，而不是只验证导入成功。

### Step 1 · 建立稳定武器槽成长模型

建议新增 `scripts/systems/weapon_slot_growth.gd`，只负责运行时的两个武器槽，不操作 UI、奖励或存档。

每槽至少记录：

```text
forge      锋铸次数
calibrate  校准次数
tyrant     暴虐次数
total      已消耗通用铭印次数
```

必须提供的能力：

- 新一局清空两个槽位。
- 按当前装备路径找到槽位；未装备时返回无效槽，不得默认落到槽 0。
- 查询槽位攻击、命中和暴击修正。
- 校验通用预算、单项上限、命中上限和暴击合法性。
- 选择成功后只消耗一次预算；重复结算不得再次增加。
- 只读导出预览所需数据，不暴露可被 UI 随意改写的内部字典。

在 `DuelController` 初始化、整局重置和状态刷新处接入，生命周期与 `WeaponMastery` 的本局状态一致。

验收：两个槽位独立；重置只清本局槽位成长，不改图鉴、历史最高熟练和横向铸式。

### Step 2 · 所有换装入口改为原位替换

当前多处使用 `erase(old_path)` 后 `append(new_path)`，会把被替换武器移到数组末尾。槽位成长落地前必须统一为原位替换。

在装备/整备职责层建立唯一替换入口，至少完成：

1. 找到旧武器下标；找不到则拒绝。
2. 校验新武器合法、未重复装备。
3. 记录目标槽下标。
4. 使用 `selected_loadout[slot] = new_path`，不得删除后追加。
5. 保持槽位成长不变。
6. 保留原武器自己的熟练和调律，不清空、不复制。
7. 重建转轮池、刷新状态并记录日志，且只结算一次。

接入以下来源：

- 商店替换；
- 营地补给替换；
- 普通/旧奖励武器替换；
- 成长战利品替换；
- BOSS 战利品替换；
- 棋盘装备格与武器藏库替换。

重点文件：

- `scripts/systems/shop_system.gd`
- `scripts/systems/reward_system.gd`
- `scripts/battle/duel_controller.gd`
- `scripts/systems/loadout_system.gd`

验收：同一组双武器在替换前后的另一把武器顺序不变；所有来源继承相同槽位成长；取消替换不消耗任何状态。

### Step 3 · 将通用数值读取迁移到槽位

1. `weapon_power()` 改读槽位锋铸，不再读取武器路径上的锋铸。
2. `weapon_hit()` 改读槽位校准，不再读取武器路径上的校准。
3. `ReelSystem` 构建攻击与暴击映射时改读目标武器所在槽。
4. 保留横向铸式修正，并验证相加顺序与旧公式一致。
5. 删除或迁移旧的武器路径数值铭印读写，避免双份加成。
6. 更新所有 UI 摘要、图鉴当局记录和日志中的归属文案。

重点文件：

- `scripts/battle/duel_controller.gd`
- `scripts/battle/reel_system.gd`
- `scripts/systems/weapon_mastery.gd`
- `scripts/systems/forge_style_system.gd`
- `scripts/ui/card_factory.gd`

验收：同一把武器分别放入槽 0 和槽 1 时，只产生对应槽位的数值差异；共享 `.tres` 文件永远不被运行时修改。

### Step 4 · 改造铭印候选、结算和奖励合法性

1. R2/R3 仍由具体武器的实际使用与追赶触发。
2. 锋铸、校准、暴虐候选读取该武器当前所在槽的预算与升级前后数值。
3. 调律继续读取具体武器和具体符号。
4. 选择通用铭印时写入槽位；选择调律时写入武器。
5. 通用预算已满时隐藏通用候选，不显示“选择后不变”的死卡。
6. 武器训练候选增加有效性检查：
   - R4 且没有后续实际解锁收益时不再出现；
   - 增加的熟练不会超过任何有效成长目标时不再出现；
   - 仍可通过后续调律或槽位预算获得真实成长时可以出现。
7. 保留现有追赶规则，不额外复制旧武器的调律或铭印。
8. 重抽、免费跳过和未选成长清空规则保持不变。

重点文件：

- `scripts/systems/weapon_mastery.gd`
- `scripts/systems/growth_loot_offer.gd`
- `scripts/systems/post_battle_system.gd`
- `scripts/battle/room_flow.gd`

验收：普通、精英、BOSS 来源的品质和重抽规则不变；不会出现已满级仍提供无收益武器训练的情况。

### Step 5 · 统一替换预览与面板表达

武器详情拆成两组，避免继续把所有修正混在一行：

```text
槽位锻造：锋铸×1（攻 +2）· 校准×1（命中 +5%）
武器专精：R3 · 调律「火斩」×1
```

替换弹层必须显示：

1. `替换槽位：武器槽 1/2`。
2. `继承：该槽通用锻造保持不变`。
3. 旧武器熟练与调律保留，但卸下后暂停贡献。
4. 新武器自己的熟练、调律、铸式和追赶目标。
5. 替换前后真实攻击、命中、MISS、符号格和共鸣变化。
6. 若 BOSS 已公开，分别显示旧武器和新武器对它的元素倍率。

棋盘装备预告 `_equip_line()` 不得只比较列表中的第一把旧武器；应让玩家看到各合法替换目标，或明确进入逐槽替换预览。

验收：预览显示的新武器数值与替换完成后的实际面板、转轮带和战斗映射逐项一致。

### Step 6 · 数值回归与完整验收

首轮只做归属迁移，不调元素倍率。使用固定种子完成以下对照：

| 场景 | 必须得到的结果 |
|---|---|
| 已培养中性武器 → 未培养克制武器 | 通用攻击/命中/暴击继承；克制仍来自元素倍率 |
| 有调律旧武器 → 无调律新武器 | 旧调律不转移，新武器符号带真实变化 |
| 新武器连续参与清房 | 现有熟练追赶正常，跨级欠选不丢失 |
| 同一槽反复换装 | 通用预算不重置，数值不叠加复制 |
| 旧武器重新装回 | 自己的熟练/调律仍在，数值读取新所在槽 |
| 两个槽培养不同方向 | 两槽数值互不串扰 |
| 满级/满预算 Build | 不出现无收益武器训练或死铭印卡 |
| 实际建带与替换预览 | 符号、MISS、攻击、命中和暴击口径一致 |

只有专项与全量回归通过后，才允许另开任务评估 ×1.5/×0.85 是否需要调整。不得在本阶段顺手修改元素倍率。

## 8. 专项测试清单

`weapon_slot_growth_test` 至少覆盖：

1. 新一局两槽通用成长均为 0。
2. 槽 0 锋铸后，槽 0 当前武器攻击 +2，槽 1 不变。
