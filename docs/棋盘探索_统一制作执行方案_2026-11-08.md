# Seek Dead · 棋盘探索统一制作执行方案（2026-11-08）

> 状态：整合设计定稿，供后续制作按步骤执行；本文不代表功能已经实施  
> 范围：三幕连续地图、主动走格、巡猎者、战术布局、迷雾、精英/BOSS 弹簧节奏、受控随机与像素美术  
> 核心结论：**一张世界地图、三个局部区域；玩家每次主动走一格；少量可见巡猎者按固定节奏接近；迷雾管理信息，精英/BOSS 用蓄势—爆发—释放形成压力；任何随机内容在玩家决策前冻结。**

---

## 1. 本文如何使用

本文是本轮棋盘制作的统一执行入口，整合此前关于以下内容的讨论：

- 微缩地图化棋盘与具体装备预告；
- 受控随机拓扑、怪物、武器、护符和特殊格；
- 三幕整合进一张世界地图；
- 删除缺乏决策意义的常规移动骰子；
- 普通巡猎者主动接近，固定精英与 BOSS 守门；
- 战术分支布局与双方路线预告；
- 三层迷雾与精英/BOSS 弹簧压力模型。

专项数值、战斗公式、成长、装备与既有 G1 记录仍由对应文档承担。本文不重新设计转轮战斗，不修改伤害公式，不把 AI 自动化结果当作真人难度结论。

### 1.1 一句话体验目标

玩家看地图时，不仅问“下一格拿什么”，还要能回答：

> “我走到哪里，巡猎者会怎么动；是否值得在这里开战；迷雾后有什么目标；精英或 BOSS 何时爆发、何时给我反击窗口。”

### 1.2 统一状态顺序

```text
当前区域地图待机
→ 悬停前向相邻节点，预览节点结果与巡猎接触风险
→ 玩家确认并前进一格
→ 执行节点效果
→ 若发生战斗：确认层 → 现有战斗 → 战后成长
→ 返回地图
→ 完成一次世界行动计数
→ 巡猎者按倒计时移动
→ 若接触玩家：触发同一场战斗确认与结算
→ 返回地图待机
```

菜单、tooltip、商店购买界面停留、战斗中的每次旋转都不算额外世界行动。

## 2. 核心设计决策表

| 主题 | 统一决定 | 禁止做法 |
|---|---|---|
| 世界结构 | 一张世界地图，ACT1/2/3 是三个连续区域 | 63 节点全部同屏平铺 |
| 当前视图 | 当前 ACT 局部放大，世界总览只看区域进度 | 频繁拖动镜头、当前区域显示过小 |
| 玩家移动 | 每次主动前进一个相邻节点 | 常规 1D3、剩余步数与“继续”按钮 |
| 巡猎者 | 初版 1 个普通巡猎者；每 2 次玩家世界行动移动 1 格 | 全部怪物追击、随机方向、无预警生成 |
| 固定敌人 | 普通守门怪保证基础成长；精英先固定守门 | 所有精英同时在地图上追击 |
| BOSS | 固定在区域尾路，不移动、不跨幕 | 巡猎者进入 BOSS 或跨幕追击 |
| 分支 | 巡猎区至少两条，目标三条；支路容纳 2–3 节点 | 单节点支路立即汇合、假岔路 |
| 回头 | 不开放自由回头；可加向前斜切换道 | 反复踩格、无限遛怪和重复奖励 |
| 迷雾 | 当前/相邻、已探索、未探索三层 | 揭示时重抽内容、迷雾中无预警撞击 |
| 重大奖励 | 武器/护符等构筑目标保持可见 | 迷雾把 Build 目标变成纯盲盒 |
| 精英/BOSS 弹簧 | 蓄势→预警→爆发→恢复窗口 | 根据玩家 HP/Build 暗改 HP、攻击、抗性 |
| 随机 | 开局按种子生成并冻结，公开层级明确 | 落地、揭示、进出区域时重新随机 |
| 战斗奖励 | 沿用现有战后成长与 BOSS 专属战利品 | 节点、巡猎、接触额外叠一套平行奖励 |
| 动画 | 短促、可跳过、不消耗全局 RNG | 逐只怪长动画、用动画拉长时长 |

## 3. 世界地图与三幕连续结构

### 3.1 两层地图，不做一张拥挤平面图

#### 世界总览显示

- 三个区域的轮廓、主题与连接；
- 玩家当前区域；
- 各幕完成状态；
- 已击败的区域 BOSS；
- 最终目的地。

不显示全部小节点的名称、HP 和详细 tooltip。

#### 区域视图显示

- 当前 ACT 的完整拓扑；
- 玩家、巡猎者、固定精英与 BOSS；
- 当前可前进节点；
- 具体装备和节点奖励；
- 迷雾状态与接触风险；
- 世界地图入口。

### 3.2 三幕连接

```text
ACT1 墓园废墟
→ 区域 BOSS
→ 专属战利品
→ 世界地图拉高
→ 新区域开放
→ ACT2 深渊回廊
→ 区域 BOSS
→ 同一流程
→ ACT3 破碎王座／最终 BOSS
→ 整局结算
```

区域过渡允许一次简短的信息整理或既有整备入口，但不增加一套免费成长。不得每幕结束自动满血，不让区域过渡变成额外奖励层。

### 3.3 状态边界

- 三幕共享玩家 HP、Build、消耗品、成长和收藏状态。
- 当前幕、当前节点、当前房间、区域难度位置必须有明确来源。
- ACT1/ACT2 BOSS 是区域门槛，不触发整局结束。
- 只有 ACT3 最终 BOSS 触发整局元进度结算。
- 整局内容在开局由种子冻结；进入新区域不得重抽。
- 巡猎者不进入下一幕，未解决的本幕巡猎状态不带入下一幕。
- 原型继续不做中途棋盘存档，局外收藏和成就沿用现有保存规则。

### 3.4 数量口径

当前 ACT1 参考规模为 21 节点、单局约 12 格、约 8 场战斗。三幕整合不是让玩家走完全部 63 节点，而是每幕只走自己的一条路线。

巡猎者最多增加一次接触战；若总战斗数、时长或成长预算明显超出当前基线，优先调整巡猎与路线，不直接改敌人 HP。

## 4. 主动走格与巡猎者规则

### 4.1 玩家移动

- 只可选择当前节点的前向相邻节点。
- 每次前进一格并结算一次。
- 合法节点、路径和结果在点击前可见。
- 已消耗节点不可再次结算。
- 不做倒退、循环地图和自由漫游。

### 4.2 初版巡猎者

首批只放一个普通巡猎者，固定精英继续守门，BOSS 不动。

| 规则 | 统一口径 |
|---|---|
| 移动频率 | 玩家每完成 2 次世界行动，巡猎者前进 1 格 |
| 路径 | 沿可见拓扑接近玩家，使用确定性的最短路径 |
| 并列路径 | 使用固定顺序或预先公开的规则，不用随机选择 |
| 世界行动 | 战斗节点完成、商店、休整、拾取各计一次 |
| 非行动 | 打开菜单、查看说明、单次转轮操作不计数 |
| 玩家撞上 | 玩家进入巡猎者节点，触发战斗 |
| 巡猎撞上 | 巡猎者进入玩家节点，移动结束后触发战斗 |
| 重复接触 | 同一巡猎者被击败后移除，不重复刷新 |
| 节点叠加 | 初版不让巡猎者与固定敌人叠成双重战斗 |
| BOSS 区 | 不进入 BOSS 节点，不跨幕追击 |

### 4.3 战斗与奖励边界

- 接触战沿用现有战斗确认层，明确敌人、HP、攻击、属性和机制。
- 巡猎者战斗提供正常战斗成长，不额外发“追击奖励”。
- 节点已有奖励只结算一次；接触战不能复制节点奖励。
- 初版接触战应尽量替代路线中的普通战斗压力，而不是形成无限额外成长。
- 固定守门怪必须保证进入 BOSS 前有基本成长，不能零战斗直达 BOSS。

### 4.4 预警要求

巡猎者始终显示：

- 当前位置；
- 再经过几次玩家行动后移动；
- 下一步位置；
- 当前与玩家的最短路径关系；
- 玩家悬停某节点后是否会发生接触。

禁止在玩家相邻格无预警生成敌人，禁止在商店、奖励或迷雾揭示时偷偷移动。

### 4.5 查看构筑、营地整备与撤回整备

棋盘必须区分三种功能，不使用含义模糊的“返回”：

| 功能 | 可用时机 | 对当前远征的影响 |
|---|---|---|
| 查看构筑 | 随时可用 | 只读查看武器、技能、护符、消耗品、真实转轮带、技艺、铭印与共鸣，不改变状态 |
| 营地整备 | 仅在营地、休整或商店等明确节点 | 使用该节点已有的恢复、替换或购买功能，并正常计一次世界行动 |
| 撤回整备 | 随时可发起，必须二次确认 | 结束本次远征并返回整备页，不恢复同一棋盘 |

#### 撤回确认必须公开

- 保留已经入账的图鉴、收藏、解锁与局外点数。
- 失去本局临时成长、当前棋盘进度与尚未结算的奖励。
- 不发放区域 BOSS、通关或其他胜利结算奖励。
- 终局原因记录为“主动撤回”，不伪装成 BOSS 战败。
- 当前原型没有棋盘中途存档，不得暗示可以稍后继续本局。

#### 撤回与地图状态边界

- 打开查看构筑或撤回确认层，不推进世界行动、不移动巡猎者、不改变迷雾、不消耗节点、不消耗 RNG。
- 取消撤回后，棋盘和战斗流程必须完全保持原状。
- 确认撤回后，本局结束；重开生成新局，不能利用撤回刷新当前装备、路线或奖励。
- 在战斗、商店、迷雾、BOSS 确认层中发起撤回，也不能重复结算当前节点。
- 真正的中途保存/恢复是后续独立功能，需要另行保存种子、节点消耗、巡猎位置、迷雾、HP、Build 和成长队列，不与普通撤回混做。

## 5. 战术布局与展示方式

### 5.1 当前 ACT 的三个区域

```text
① 入口与教学区
   固定战斗 → 武器 → 固定精英
                    │
② 巡猎与分支区     ↓
        ┌─ 上路：商店 → 普通 → 护符 ─┐
        ├─ 中路：战斗 → 武器 → 战斗 ─┤
        └─ 下路：休整 → 普通 → 补给 ─┘
                    │
③ BOSS 门前区       ↓
              固定守门战 → 尾路 BOSS 选择
```

该图表达结构职责，不要求所有路径奖励完全相同。

### 5.2 布局硬约束

- 入口区以单路为主，不在开局立即夹击。
- 巡猎区至少两条真实支路，目标三条；支路有 2–3 个节点。
- 分支不仅是奖励文字不同，还要有位置、接触时机和战斗数差异。
- 可加入向前斜切的换道连接，不能形成回头奖励循环。
- BOSS 区重新收束，剩余巡猎压力不进入 BOSS 战。
- 当前 ACT 一屏读完，不因追击频繁拖动镜头。

### 5.3 界面替换

#### 顶栏

删除骰子点数、剩余步数、“掷骰前进/继续”，替换为：

- ACT 与区域名称；
- 当前世界行动数；
- 巡猎移动倒计时；
- HP、金币与既有基础资源。

#### 底部/侧栏

- 选中节点：具体奖励、敌人、替换得失、移动后接触结果。
- 当前威胁：巡猎者名称、属性、位置、倒计时和下一步。
- 主操作：直接点击高亮相邻节点，不再常驻骰子按钮。
- 顶栏或系统菜单提供“查看构筑”和“撤回整备”；撤回必须二次确认，不能与主要前进操作相邻。
- `Esc` 只打开系统菜单，不直接结束远征；撤回确认按钮写“结束并撤回”，取消按钮写“继续远征”。

### 5.4 双方路线预告

悬停合法节点时至少显示：

```text
节点奖励／风险
→ 玩家移动结果
→ 节点结算结果
→ 巡猎者是否移动及去向
→ 本次是否接触
```

会接触时必须明确写出“移动后将遭遇巡猎者”，不靠颜色暗示。

### 5.5 棋子与节点可读性

| 对象 | 表现要求 |
|---|---|
| 玩家 | 暖白骑士＋蓝色盾牌底座 |
| 巡猎者 | 红色敌人棋子＋清楚朝向 |
| 固定普通怪 | 小型红色节点图标 |
| 固定精英 | 尖刺框或金色底座 |
| BOSS | 大型区域地标，不用普通棋子 |
| 合法前进 | 金色边框＋方向箭头 |
| 巡猎下一步 | 红色目标框＋方向箭头 |
| 即将接触 | 独立碰撞图标和文字 |

棋子可站节点侧边，避免完全遮住奖励图标。初版同节点不叠多只巡猎者。

## 6. 迷雾模型

### 6.1 三层状态

| 层级 | 展示内容 |
|---|---|
| 当前与相邻 | 完整图标、名称、奖励、敌人、接触风险 |
| 已探索 | 降低亮度，保留地形、道路和节点记忆 |
| 未探索 | 暗色地形＋节点类型剪影，次要具体内容隐藏 |

### 6.2 不被迷雾隐藏的关键信息

- 地形轮廓和逻辑道路；
- 当前与相邻节点；
- 节点大类：普通、精英、商店、休整、BOSS；
- 巡猎者位置、倒计时、下一步与接触风险；
- 精英/BOSS 名称、元素与核心机制；
- 重要武器、护符等 Build 目标。

### 6.3 适合隐藏的信息

- 远处普通怪的具体身份；
- 普通补给的具体数量；
- 后续宝箱的具体内容；
- 次要支路的小型变化；
- 未接近区域的非交互装饰细节。

### 6.4 迷雾铁律

- 迷雾是信息模型，不是动态数值难度模型。
- 开局内容已冻结，揭示迷雾不能重抽怪物或奖励。
- 可影响玩家下一步的巡猎者不能从未知区域无预警撞击。
- 已探索信息不再次遮蔽。
- 迷雾层不遮挡合法落点、道路和当前棋子。
- 不用随机噪点、动态噪声或大量透明颗粒制作雾。

## 7. 精英与 BOSS 的弹簧压力模型

### 7.1 正确定义

弹簧模型负责战斗压力的蓄势、爆发和释放：

```text
蓄势 → 明确预警 → 高压爆发 → 压力释放 → 玩家反击窗口
```

它不表示“玩家表现越好，敌人越强”，也不表示“玩家快输了，系统暗中放水”。

### 7.2 精英样板

- 普通回合建立防御、充能或其他既有资源。
- 高强度意图提前展示具体后果。
- 重击、锁轮、注废等高压手段后安排短暂恢复窗口。
- 恢复窗口允许玩家调整转轮目标、治疗或爆发。
- 机制应使用现有意图、充能和状态系统，不新增加一条平行资源轨。

### 7.3 BOSS 样板

- 阶段初期允许玩家理解机制。
- 阶段转换提高决策密度，而非只提高 HP。
- 大招前有明确预警，大招后有可识别的喘息窗口。
- 既有按 BOSS 自身 HP 的阶段阈值可继续使用。
- 不根据玩家当前 HP、伤害、武器稀有度或连胜表现暗中改变 BOSS 数值。
- 不动态回血抵消玩家成长，不用后期堆血强行拉时长。

### 7.4 低难度与辅助

若需要低难度辅助，应作为明确可选模式或公开规则单独评审，不藏在弹簧模型里。强势 Build 必须实际更强，弱势 Build 也不应被系统进一步针对。

## 8. 受控随机与奖励公开

### 8.1 总原则

> 开局随机生成，移动前按公开层级展示，落地、揭示和确认后不再变化。

随机负责每局差异，玩家负责路线规划。不得因玩家 Build、HP 或即将落点暗换怪物与奖励。

### 8.2 拓扑随机顺序

- 第一版只使用一套人工战术拓扑，先验证巡猎和迷雾。
- 固定拓扑通过后，再制作 4–6 套人工校验模板。
- 不做任意程序连线；每套模板的道路、分支和美术逐个验收。
- 模板变化包括分支位置、支路长度、精英位置、装备位置和 BOSS 前路径。
- 所有模板必须单起点、可达区域 BOSS、无孤立节点、无奖励循环。

### 8.3 内容生成顺序

```text
整局种子
→ 固定三幕区域主题与模板
→ 分配各幕节点类型
→ 分配普通/精英/BOSS RoomData
→ 分配具体武器、护符与特殊内容
→ 校验可达性、重复、路线价值、成长与战斗预算
→ 冻结整局
→ 迷雾只控制信息公开，不参与生成
```

### 8.4 怪物与装备约束

- 普通、精英、BOSS 分池，只使用当前 ACT/Demo 合法内容。
- 避免同一路径连续重复同一敌人。
- 难度按路径深度与既有规则分配，不按玩家表现暗中变化。
- 不连续安排针对当前 Build 的高抗怪。
- 武器与护符具体物品预确定，确认后不再随机。
- 同一幕避免重复物品和只有名称差异的候选。
- 高风险路线对应更明确或更高质量的构筑奖励。
- BOSS 信物不进入普通格；白名单之外内容不出现。

### 8.5 特殊格

基础巡猎、迷雾和固定拓扑通过后，才允许评估宝箱、神龛、武器藏库：

- 每幕至多一个特殊格，替换普通节点，不增加总节点数。
- 宝箱公开品质或类别，结果生成时冻结。
- 神龛使用现有合法恢复、最大 HP 或一次性效果。
- 武器藏库展示两件可见武器选一件，可绑定明确精英战。
- 诅咒、献祭、隐藏房、复杂事件继续暂缓。

## 9. 像素美术与 UI 制作规范

### 9.1 规格

| 资产 | 建议规格 | 要求 |
|---|---|---|
| 地形图块 | 8×8 或 16×16，主规格统一 | 大色块、无随机单像素、无抗锯齿 |
| 可行道路 | 原生约 3–5px 宽 | 与逻辑连线一致，装饰路不得误导 |
| 普通/精英节点 | 16×16 主图标 | 图标与形状共同区分，不只换色 |
| BOSS 地标 | 16×16 或 24×24 | 使用可辨认剪影，不直接模糊缩小整图 |
| 武器/护符 | 沿用现有图标 | 具体物品可见，不用未知宝箱替代 |
| 玩家棋子 | 12×16 或 16×16 | 骑士持剑持盾，清楚脚底锚点 |
| 巡猎者棋子 | 同体系独立轮廓 | 红色敌人轮廓与朝向，不遮节点 |
| 状态框/箭头 | 独立资源 | 不预烘焙进节点主图标 |

节点视觉可以 16×16，点击热区建议至少 24×24，热区不能重叠。

### 9.2 三幕视觉主题

| 区域 | 主题 | 配色方向 |
|---|---|---|
| ACT1 | 墓园、锈铁、枯林 | 暗褐、灰绿、敌人红 |
| ACT2 | 冰封回廊、深渊遗迹 | 冰蓝、暗紫、迷宫纹路 |
| ACT3 | 破碎王座、虚空裂隙 | 暗金、裂红、虚无黑 |

环境亮度低于交互层。节点周围保留干净负空间，树木、岩石、草丛使用成组剪影，不铺随机噪点。

### 9.3 动画

- 玩家棋子单格移动保持短促。
- 巡猎者在节点结算后一次移动，建议约 0.15–0.25 秒。
- 区域过渡约 0.25–0.4 秒，可跳过。
- 多只未来敌人同时移动，不逐只播放长动画。
- 所有动画不消耗全局 RNG，不改变世界行动计数。
- 不用全屏闪烁、持续抖动或大面积粒子遮蔽地图。

# 10. 按步骤制作与验收

## Step 0 · 冻结基线并处理既有阻塞

### 制作

- 保存当前线性/棋盘流程、16 套回归和当前资源状态。
- 保留线性入口与现有棋盘作为对照，不删除旧测试入口。
- 先定位并修复既有 readable 连续局在第 7 房精英胜利后的阻塞，避免新棋盘掩盖旧问题。
- 记录当前 ACT1 节点、战斗数、成长和难度映射。

### 范围外

不改战斗数值、成长数值、掉落概率或装备基础值。

### 出口

当前流程无已知战后阻塞；回归全绿；新旧模式入口明确。

## Step 1 · 固定战术拓扑灰盒

### 制作

- 只调整 ACT1 节点坐标和连接，形成入口区、巡猎区、BOSS 区。
- 保留当前节点类型和既有战斗/成长结果。
- 支路容纳 2–3 节点，加入必要的向前斜切换道。
- 完成全部节点可达、无奖励循环、BOSS 可抵达验证。

### 出口

不看说明也能指出起点、终点、分支和汇合；每条支路都有明确位置价值。

## Step 2 · 主动走格与单个巡猎者

### 制作

- 删除常规骰子及剩余步数 UI，玩家每次前进一格。
- 加入一个普通巡猎者、两次世界行动移动一格、固定路径和接触战。
- 接入倒计时、下一步位置、悬停接触结果和现有战斗确认。
- 商店、休整、战斗、拾取各只计一次世界行动。
- 巡猎者被击败后移除，不进入 BOSS 或下一幕。

### 出口

- 玩家理解为什么发生战斗，至少一次因奖励或威胁主动选路。
- 不出现无预警接触、重复结算、连续不可逃避战斗或无限避战。
- 战斗数和成长预算仍处于 ACT1 基线附近。

## Step 3 · 双方信息与战术界面

### 制作

- 完成顶栏、节点详情、威胁摘要和双方路线预告。
- 节点、玩家、巡猎者、精英、BOSS 使用不同轮廓和状态。
- 点击前明确显示移动后是否接触。
- 加入只读“查看构筑”和带二次确认的“撤回整备”，检查入口不会误触或推进巡猎。
- 撤回确认明确显示保留的永久收藏、失去的本局进度及不发通关奖励。
- 完成 480×270、960×540、1440×810 实机截图。

### 出口

玩家能在一次悬停内理解节点奖励、巡猎移动与接触结果；无文字遮挡和热区重叠。取消撤回后状态不变，确认撤回后正确回整备且不能恢复旧棋盘或重复领取奖励。

## Step 4 · 三层迷雾

### 制作

- 只加入当前/相邻、已探索、未探索三层显示。
- 先不改变任何节点内容、敌人或奖励。
- 检查巡猎者、重大奖励、精英/BOSS 关键信息不被隐藏。
- 验证揭示不重抽、不推进巡猎倒计时、不消耗 RNG。

### 出口

迷雾增加探索感但不制造盲盒伏击；玩家始终能解释当前风险。

## Step 5 · 精英/BOSS 弹簧样板

### 制作

- 选择一个固定精英和一个 ACT1 BOSS。
- 使用既有意图、充能、状态和阶段系统，整理蓄势—预警—爆发—恢复节律。
- 明确展示高压后果和恢复窗口。
- 只调整该样板的机制编排，不做全局敌人数值缩放。

### 出口

玩家能说出高压何时到来、何时可以反击；强势 Build 仍有真实优势，恢复窗口不是假提示。

## Step 6 · 微缩地图美术与世界总览

### 制作

- 制作 ACT1 地形、道路、节点、玩家和巡猎者资产。
- 制作包含三个区域的世界总览静态样稿。
- 区域过渡只展示开放和位置变化，不新增奖励。
- 当前区域视图与世界总览互不争夺主操作。

### 出口

地图有旅程感；交互层始终比环境醒目；世界总览不显示拥挤的小节点文字。

## Step 7 · 受控随机模板

### 制作

- 固定战术拓扑通过后才制作 4–6 套模板。
- 接入怪物、装备和 BOSS 的种子冻结与公开层级。
- 加入重复、白名单、路线价值和战斗预算校验。
- 特殊格另行小步验收，不与首批模板同时上线。

### 出口

同种子结果一致，不同种子有真实路线/目标差异；无最优模板、重复刷取或针对 Build 的暗改。

## Step 8 · ACT1 完整真人验收

### 必须记录

- 每局路线、世界行动、巡猎接触、战斗数、成长、换装和死亡点。
- 普通/精英/BOSS 回合数、承伤、总时长和再玩意愿。
- 玩家是否理解迷雾、巡猎倒计时、精英爆发与恢复窗口。
- 玩家是否主动追逐装备、是否因威胁改变路线。

### 数据纪律

- 不把 control 零延迟输入死亡当作难度信号。
- 不把 readable 的 AI 27/27 等结果当作真人反应或难度证据。
- AI 数据只用于流程、复现和自动回归，不关闭真人体验出口。

### 出口

ACT1 无流程阻塞；玩家能复述路线、成长、巡猎接触和 BOSS 应对；时长没有因地图移动明显失控。

## Step 9 · ACT2/ACT3 接入

### 制作

- 先连接 ACT1→ACT2，验证 HP、Build、成长、收藏、区域难度与 BOSS 奖励连续。
- 两幕通过后再接 ACT3 与最终结算。
- 为每幕应用独立主题、合法池和区域机制，不复制同一张地形换色。
- 每幕只结算一个区域 BOSS；未走尾路不结算。

### 出口

完整三幕是同一局连续远征；ACT1/2 不误触整局结束，ACT3 才进入最终元进度；无跨幕巡猎和重复成长。

## 11. 自动测试最低覆盖

- 所有模板和种子下 BOSS 可达，无孤立节点、死路和奖励循环。
- 玩家只走合法前向相邻节点，单次移动只结算一次。
- 世界行动计数只在节点完成时增加一次。
- 巡猎者按固定倒计时移动，路径和接触可复现。
- 商店、休整、战斗、拾取后正确回地图。
- 同一巡猎者不会重复生成或重复发奖励。
- 巡猎者不进入 BOSS、不跨幕，不与固定敌人形成双重战斗。
- 迷雾揭示不改变房间、物品、敌人、骰子历史或 RNG 序列。
- 悬停、动画和 tooltip 不消耗 RNG、不推进世界行动。
- 查看构筑和打开/取消撤回确认不改变 HP、Build、节点、巡猎、迷雾、行动计数或 RNG。
- 确认撤回只保留已入账永久内容，不发未结算/通关奖励，不重复结算节点；重开不能恢复旧棋盘。
- 同种子整局拓扑、房间、物品和 BOSS 分配一致。
- 精英/BOSS 的高压意图、阶段和恢复窗口与实际结算一致。
- ACT1/2 BOSS 不触发整局结束，ACT3 最终 BOSS 正确结算。
- 线性入口保留；既有 `run_smoke.bat` 全绿，新模块增加定向测试。

## 12. 停止条件与禁止回退

出现以下任一情况，停止扩模板、扩幕或加内容：

- 玩家不理解为什么发生接触或为什么受伤。
- 巡猎者造成无预警夹击、无限避战或连续不可逃避战斗。
- 分支只是文字奖励不同，没有位置与路线价值。
- 迷雾吞掉重大奖励、巡猎风险或 BOSS 信息。
- 弹簧模型变成按玩家 HP/Build 暗改敌人数值。
- 地图移动、敌人动画或区域过渡比战斗决策更耗时。
- 随机模板出现明显最优路线、重复奖励或针对构筑的连续高抗怪。
- 强势 Build 被动态压力抵消，成长失去意义。
- 自动回归失败，或 AI 结果被冒充为真人难度结论。

不得回退到：

- 常规移动骰子与剩余步数；
- 全部怪物同时追击；
- 63 节点同屏平铺；
- 迷雾揭示重抽；
- 动态 HP/攻击橡皮筋；
- 自由回头刷奖励；
- 新货币、平行追击奖励或每幕重复终局奖励。

## 13. 最终验收话术

成功的 ACT1 原型应让玩家能够回答：

- “我这一步为什么走这里，奖励和风险分别是什么？”
- “巡猎者何时移动，我是否主动选择了这次接触或避让？”
- “迷雾里哪些信息未知，哪些规则我仍然知道？”
- “精英/BOSS 什么时候爆发，我在哪个窗口反击？”
- “这局我追逐了什么装备，形成了什么 Build？”
- “下一局地图、路线或目标有什么不同？”

成功的三幕版本应进一步让玩家感觉：

> “我在同一张世界里完成了连续远征，每幕都有新区域问题，但每一次移动、战斗、成长和解锁都能被理解。”
