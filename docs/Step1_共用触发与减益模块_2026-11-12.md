## 2. 减益表（唯一事实来源：`DebuffSystem.DEFS`）

| id | 名称 | 类型 | 默认持续 | 效果 | 应对 | 解除 |
|---|---|---|---|---|---|---|
| `weak` | 💢 虚弱 | status | 1 回合 | 玩家攻击收益 ×0.8 | 换功能符号、清净 | 到期 / 清净 |
| `vulnerable` | 🩸 易伤 | status | 2 回合 | 玩家承伤 ×1.25 | 防御、抢斩杀、清净 | 到期 / 清净 |
| `corrode` | 🧪 腐蚀 | status | 直到解除 | 护盾收益 ×0.75 | 破甲、恢复、清净 | 破甲 / 清净 |
| `drain` | 🔋 吸能 | instant | 一次 | 充能 -2（≥0） | 提前爆发、重新积累 | 即时 |
| `heal_block` | 🚫 禁疗 | status | 1 回合 | 治疗收益 ×0.5（不完全禁止） | 护盾、抢攻、清净 | 到期 / 清净 |
| `blind` | 🌫 目盲 | interference | 2 回合 | 隐藏后续预览，当前中心仍可见 | 看当前格、净化 | 到期 / 净化 |
| `entangle` | 🪢 缠绕 | interference | 1 回合 | 手动停列必须按指定方向逐列 | 按顺序操作、净化 | 到期 / 净化 |
| `backlash` | ⚡ 反噬 | status | 1 回合 | 连续使用同符号受 2% maxHP 代价 | 换符号、清净 | 换符号 / 到期 / 清净 |
| `strip` | 🪓 剥增益 | instant | 一次 | 移除一个玩家增益（剩余回合最少者优先，确定性） | 提前使用、重新获得 | 即时 |

纪律：

- 首次施加打印「图标 名称：效果（持续）｜应对：…」，之后只打印叠加/仍在生效；提示不掷随机。
- 计时按「玩家实际经历过的转轮」计算：转轮前施加（入场 / 回合开始钩子）当回合生效、回合末 -1；结算中 / 敌人回合施加（受击 / 三连 / 破甲）从下一回合起算，当回合末不扣。
- 反噬代价先扣盾再扣血，且 HP 不低于 1（不允许减益直接造成死局）。
- 腐蚀显示「直到解除」，唯一解除路径为破甲或清净。

## 3. 结算接入点

| 效果 | 接入位置 | 说明 |
|---|---|---|
| 虚弱 | `combat_system._phase_attack` | 对「连线 + 穿透」总伤害乘算；核爆/充能爆发按 maxHP 比例，不受影响 |
| 易伤 | `combat_system.enemy_deal_damage` | 敌人→玩家唯一伤害闸口；意图攻击、重击、gimmick 直伤统一生效 |
| 腐蚀 | `combat_system._phase_defense` | 在符号 + 铁壁/回春聚合之后折算，覆盖全部护盾来源 |
| 禁疗 | `combat_system._phase_defense` + `consumable_system.use_heal` | 符号/回春与治疗药剂两条路径均 ×0.5 |
| 吸能 | `debuff_system._apply_instant` | 即时扣充能，下限 0 |
| 目盲 | `battle_hud._refresh_p1_previews` + `reel_spin_view._sync_preview` | 隐藏预览行/格底预览；当前中心符号照常可见 |
| 缠绕 | `reel_system.lock_reel`（仅 `reason == "player"`） | 越序按停被拒绝并提示下一列；自动停轮（forced）不受限，防死锁 |
| 反噬 | `combat_system._phase_symbols` → `note_turn_symbols` | 比较上一回合停轮符号；每回合最多一次；换符号立即结束 |
| 剥增益 | `debuff_system._strip_one_buff` | 只改 `player_buffs`，不碰护符/技艺 |
| 破甲 | `combat.on_counter` / `release_element_burst` → `ctrl.notify_armor_break()` | 清甲即解除腐蚀，并触发 gimmick `on_armor_break` |
| 阶段 | `duel_controller.apply_enemy_hp_floor` → `gimmick.on_hp_changed` | 任何扣血路径（直击/穿透/DoT/爆发/锁血收口）之后统一检查 |

## 4. 净化 / 清净分工

| 药剂 | 解除类别 | 现有内容 | Step 1 新增 |
|---|---|---|---|
| 净化药剂 | `interference`（转轮操作干扰） | 注废 / 锁轮 / 乱权 / 夺轮意图 | 目盲、缠绕 |
| 清净药剂 | `status`（玩家负面状态） | 冻结 / 酸蚀层数 | 虚弱、易伤、腐蚀、禁疗、反噬 |

两种药剂互不越界（`clear_interference` / `clear_status`），原有反馈前缀保持不变（`净化：抵消注废`、`清净：寒霜`）。

## 5. 触发模块（TriggerKit）

触发表写在房间 `gimmick_params.triggers`：

```gdscript
{
    "triggers": [
        {"on": "enter",       "debuff": "weak",      "turns": 1},
        {"on": "first_spin",  "debuff": "blind",     "turns": 2},
        {"on": "first_hit",   "debuff": "vulnerable","turns": 2},
        {"on": "every", "n": 3, "debuff": "corrode", "turns": 99},
        {"on": "armor_break", "debuff": "strip"},
        {"on": "phase", "hp": 0.4, "debuff": "vulnerable", "turns": 2},
    ]
}
```

- 一次性触发：`enter` / `first_spin` / `first_hit` / `armor_break` / 每个 `phase` 条目；
- `every`：按 `turn_count % n == 0`，同一回合只触发一次；
- 效果字段：`debuff` / `turns` / `stacks` / `order` → `ctrl.apply_debuff(...)`；`charge` → 充能增减；
- 未知触发名会 `push_warning` 并跳过，不影响其余条目；
- 纯确定性，不消耗全局 RNG。

怪物接线方式（Step 2 起）：

```text
RoomData.gimmick_script = preload("res://scripts/battle/gimmicks/triggered_gimmick.gd")
RoomData.gimmick_params = {"triggers": [...]}
```

复杂机制仍写专属 `BossGimmick` 子类，可复用 `TriggerKit` 做部分触发。

## 6. 测试与验证

```text
godot --headless --fixed-fps 60 --path . res://tests/step1_module_test.tscn
```

覆盖：

1. 9 个定义完整（名称/图标/效果/应对）与三分类；
2. 真实结算：虚弱 ×0.8、易伤 ×1.25、腐蚀 ×0.75、禁疗 ×0.5（符号与药剂）、吸能 -2；
3. 目盲隐藏预览、缠绕停列顺序（含自动停轮豁免、不软锁）；
4. 反噬代价、每回合一次、换符号结束、不致死；
5. 剥增益与空放；
6. 持续与结束（转轮前施加当回合生效、结算中施加下回合起算、1/2 回合到期、腐蚀破甲解除、≤2 回合自动结束）；
7. 净化/清净分工与真实药剂路径；
8. 触发模块 6 种时机各只触发一次；
9. HUD 状态行/tooltip 首次提示；全程不消耗全局 RNG。

全量回归：`run_smoke.bat` 34 套 → **35 套**。
