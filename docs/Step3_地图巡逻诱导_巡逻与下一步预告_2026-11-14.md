### 交互规则（本步冻结）

| 情形 | 规则 |
|---|---|
| 玩家想进入被巡逻占据的格 | `can_move` 返回 `reason="patrol"`，**不移动** |
| 玩家撞击被占格 | 立即进入与该巡逻的战斗（`contact`），本次移动不生效、**不推进回合**、不扣 HP |
| 玩家移动或等待 | 回合 +1，所有存活巡逻按 `order 0→1→2` 各前进一格 |
| 怪物走到玩家格 | 触发接触，挂起待战节点，玩家位置不变 |
| 战斗返回（胜） | `resolve_contact(true)`：巡逻退场，该格恢复可进入 |
| 战斗返回（未胜） | `resolve_contact(false)`：只清待战节点，巡逻留在原位 |

巡逻会经过宝箱 / 休整 / 精英格，语义是**守卫**：想拿该格内容就得先处理这只怪。路径上一律避开起点、BOSS 与区域门，所以不存在「怪站在门口导致 BOSS 不可达」。

> **Step 4 更新（2026-11-14）**：绑定房间改为「**有护甲优先**，其次按 `resource_path`」，因为 act1 的 12 个 normal 房里只有 3 个带甲，纯字典序会选到护甲 0 的怪，破甲陷阱退化成 0→0。另三个破甲陷阱已从 row4 咽喉（59/64）与 C 区死胡同（94）移到 45 / 39 / 110，正好落在三条环上，怪物能真实踩到；环本身与路径索引未变。

## 4. 已知限制（不属本步出口）

1. **接触不真正开战**：运行时只挂 `pending_battle`（含真实 `RoomData`），真正进入 `duel_controller` 的战斗流程要等运行入口接入（Step 5A 之后）。因此「不额外扣血」在本步表现为**完全不触碰 HP / 结算**。
2. **巡逻路径是手写冻结环**，不是自动生成。计划 §3.3 要求「明确、可循环、可预测」，手写更可核对；后续若要按幕生成多套巡逻，需另立扩展。
3. **怪物不追击**：只沿固定环走，符合 §2.3「不让所有怪物都动态追踪玩家」；追击行为未被设计，也不在本版范围。
4. **陷阱联动未接**：巡逻踩到破甲陷阱如何处理属 Step 4。
5. **无 UI**：地图与右侧栏的同步显示由 Step 6 收口，本步只提供 `patrol_preview()` 数据。
6. **全量回归未跑**：按纪律只实跑第 55 套与第 50–54 套，全量 55 套交回用户验证。
