## 2. 分级（pattern_tier）

`PatternData.pattern_tier` 取值（`scripts/battle/pattern_data.gd:34`）：`build`（基础）| `rare_signature` | `epic_signature` | `mastery`

| 档位 | 张数 | 含义 |
|---|---:|---|
| `build`（字段为空/默认） | 10 | 基础牌谱，装备条件满足即自动激活 |
| `rare_signature` | 5 | 稀有签名，强化对应基础牌谱的效果（较低成长） |
| `epic_signature` | 6 | 史诗签名，更强的效果改写（高成长/特殊机制） |
| `mastery` | 0 | 枚举存在但目前无牌谱使用 |

**签名分档明细**：

| 档位 | 签名（id / 名称） |
|---|---|
| rare | SIG_W01_EMBER 余烬蓄燃、SIG_W01_FIRESWORD 余烬处决、SIG_W06_EXECAXE 处刑重斩、SIG_W02_ICEGUN 稳态霜冻、SIG_W03_REAPER 疫病收割 |
| epic | SIG_W02_ZERO 零度领域、SIG_W05_ECLIPSE 蚀日、SIG_W01_FLAMESTAFF 炎爆展开、SIG_W02_GLACIER 冰川压制、SIG_W04_HOLYSWORD 圣裁齐射、SIG_W05_NIGHT 夜幕裁决 |

## 3. 获得方式

| 类别 | 获得机制 | 证据 |
|---|---|---|
| **基础牌谱 W01–W06** | 装备条件自动激活（凑齐 unlock_tags 数量或 unlock_paths 精确武器），无需习得 | `unlock_tags=["element:fire"], unlock_count=2` 等（各 w*.tres） |
| **基础牌谱 T01–T03** | 无解锁条件（`unlock_paths/tags` 为空），战斗中凑齐牌型即可 | t01–t03.tres |
| **SIG02 冰火二重** | 装备条件（冰、火装备各一件，tag_count=1），无需习得 | s02_frostfire_dual.tres |
| **签名 sig_*（11 张）** | **两步**：①三选一「图纸」习得（`learn_signature` effect）→ ②战斗中仍需携带**对应元素的武器**凑齐签名自己的 `match_rule` 牌型才生效。习得是前提，牌型是触发条件，二者缺一不可 | `pattern_system.gd:101-127` 的 `find_signature`：`learned.has(id)` + `PATTERN_MATCHER.solve_rule(cards, match_rule)` 两个条件都满足才返回；`seed_sig_*.tres` 的 `effects=[{"effect_id":"learn_signature",...}]` |

**关键结论（2026-11-19 变更，已按 `find_signature` 代码纠正）**：

- **旧机制**：携带签名专属的那把特定武器（`key_paths`，如 `fire_sword.tres`）→ 自动生效。
- **新机制**：①必须先三选一习得（`learned`）；②战斗中仍须凑齐签名自己的 `match_rule` 牌型——
  该牌型要求**对应元素的伤害牌**（如 sig_fire_sword 要求「燃烧符号 + 火元素伤害牌 + 武器牌」），
  所以必须携带**火元素武器**才能提供火伤害牌。
- **变化的本质**：不再绑定"某一把特定武器"，改为绑定"某元素/牌型"。换成另一把火武器也能触发，
  但换成冰武器则凑不出火牌型、签名不生效。「无论携带什么武器都生效」是错误表述，已删除。
- `key_paths` 字段现仅用于描述签名主题归属，不再是解锁/触发条件。基础牌谱 W01–W06 的装备条件自动激活**保持不变**。

## 4. 升级

| 项 | 结论 |
|---|---|
| 牌谱等级/熟练度/强化 | **无升级机制**。全项目搜索无 `pattern_level/pattern_upgrade/牌谱升级` 实现；`mastery` 是武器熟练系统（R1–R4），与牌谱无关 |
| 成长路径 | 签名即基础牌谱的"成长终点"——通过 `pattern_tier`（rare/epic）提供更强效果改写，属于**横向/纵向强度替代**，不是可升级的数值轴 |
| 重复获得 | 三选一 `seed_sig_*` 奖励 `max_stack=1`，每张签名只习得一次 |

## 5. 使用 / 触发

**触发流程**：

```
每回合停轮 → PatternMatcher.match(cards) 按 match_rule 判定命中哪些牌谱
  → PatternSystem.resolve_equipment(matched, unlocked, assist_id) 选本回合生效的装备牌谱（至多 1 条，按 priority 降序，同优先级按 id 升序）
  → 通用牌型 resolve_universal 全部返回（不互斥）
  → 签名 find_signature：base_pattern_id 匹配 + 已习得(learned) + 组件条件满足
  → 结算层按 effect_id 找实现，读 effect_params 应用效果
```

| 维度 | 说明 | 证据 |
|---|---|---|
| 判定条件 | `match_rule` 结构化 `{"all":[...], "any":[...]}`，条件含 `sym`（符号路径）、`kind`、`source_element`、`source_kind`、`skill_role` | `pattern_matcher.gd:38,140-142,191-215` |
| 牌型组成 | 通常为 3 张：符号牌 + 武器伤害牌 + 任意武器牌；T 类为 1 技能牌 + 2 武器牌 | 各 *.tres 的 match_rule |
| 生效数量 | 装备牌谱**至多 1 条/回合**（互斥，取最高优先）；通用牌型全部生效 | `pattern_system.gd:71-99` |
| 辅助 | `assist_allowed` 决定是否可被「连携卷轴」补牌凑成（通用牌型固定 false） | `pattern_data.gd:47` |
| 效果类型 | 伤害倍率（damage_mult）、穿透（pierce_ratio）、处决线（exec_threshold）、状态层数（burn/frost/poison_extra）、削敌攻（enemy_atk_mult）、护盾（shield_flat）、治疗（heal_mult）、武器伤害倍率（weapon_damage_mult） | 各 *.tres 的 effect_params |
