符号是转轮格上真正显示的东西。武器/技能/护符/消耗品都只是**把符号塞进转轮**，
转轮格显示什么取决于符号本身：

- `kind = damage` 且为 `*_slash` → 显示**携带武器的图标**（跟随武器）
- `kind = damage` 其余 → 仅当该武器只有它一个 damage 符号时才跟随武器
- `kind = heal / shield / status / buff / special` → **只显示符号自己的 icon_tex**，没有就回落 `label` 的 emoji

## 五、关键结论

数据摆出来之后，问题非常集中：

| 实体类别 | 数量 | 引用符号 | 其中缺图标 |
|---|---|---|---|
| 武器 | 14 | 14 件全部引用 | **1 件**（`holy_sword` 的 `holy_verdict`） |
| 技能 | 10 | 10 件全部引用 | **10 件全部** |
| 护符 | 17 | **0 件不引用符号** | — |
| 消耗品 | 10 | **0 件不引用符号** | — |

也就是说：

1. **护符和消耗品根本不引用符号** —— 它们在 UI 里显示的是物品自己的 `icon_tex`。
   这部分之前显示 emoji，是 `icon` 字段没清空 + UI 默认值的问题，与符号无关，已修。
2. **10 个技能 100% 中招** —— 每个技能的符号（`buff_rage` / `heal` / `arcane_bolt` …）
   全都没有图标。所以释放任何技能后，转轮上对应的那一格必然显示 emoji。
3. **武器只有 1 处缺失** —— `holy_sword` 的 `holy_verdict`（圣裁，special 符号）。
   其余 13 把武器的符号都有图标，或走 `*_slash` 跟随武器。

## 六、补图方式

符号图标有现成统一管线 `tools/recolor_symbols.py`：

1. 生成 96px 灰度母版到 `assets/icons/symbols/_source/<id>_96.png`（浅灰填充 + 近黑描边的平涂字形）
2. 在 `JOBS` 里加一行 `<id>: ("<元素>", "solid")`
3. 跑 `py -3.15 tools/recolor_symbols.py --only=<id>` 派生 32/16 两档
4. 在 `resources/symbols/<id>.tres` 里写 `icon_tex = ExtResource(...)` 指向 `assets/icons/symbols/16/<id>.png`

这样新符号与现存 29 个符号共用同一套色表与明暗结构，风格不会跳。

2. 符号 `.tres` 写 `icon_tex` 指向 `symbols/16/<symbol>.png`（`_cell_icon` 会自动换 32px 版）
3. `holy_verdict`（圣辉审判）原本没有技能图标，按同一「粗石 + 符文」形制补画一张（meanL 74.8），技能与符号共用

**结果：ACT1 相关 25 个符号缺图标数 = 0，转轮格不再出现任何 emoji。**

### 不需要改代码

`battle_hud.gd` 的格子逻辑本来就正确：

```gdscript
if icon != null:
    _cell_want_icon[reel][row] = layer.texture
    _cell_want_text[reel][row] = ""      # 有图标就清空文字
else:
    _cell_want_icon[reel][row] = null
    _cell_want_text[reel][row] = s.label  # 没图标才回落 emoji
```

所以只要符号有 `icon_tex`，emoji 自动不显示。
