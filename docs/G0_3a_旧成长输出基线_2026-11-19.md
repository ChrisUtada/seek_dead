## 2. 基线 B：旧成长类型对照（`p0_growth_baseline`）

> 目的：固定「成长类型」这一个变量，给 G7 删除旧熟练 / 铭印 / 槽位成长提供可归因对照。
> 状态：**已完成**（160 局 = 4 组 × 40 种子，headless 无加速，21m23s，退出码 0）。数据来自 `P0GROW|SUMMARY` 四行。

| 组 | 定义 | 对照意图 |
|---|---|---|
| G0_no_growth | 无成长、无熟练、无铭印 | 基准 |

### 2.2 关键结论：本探针**未测出**成长类型的输出贡献

必须如实声明，不能拿它当「旧成长有效」的证据：

1. **四组 160/160 全部在 ACT1 第 2–8 房死亡**（中位第 4–5 房），没有任何一组活到成长展开。bot「任何有效符号即停」在 ACT1 强度下活不久，成长窗口根本没打开。
2. **`picks_mean / forge_mean / tune_mean` 四组全为 0**：即便 G1/G2 有 21–22 次首次 offer（均值 3.14 / 3.59），bot 也从未真正领取任何成长选项。四组在「是否拿到成长」上实际无差异。
3. **TTK 与单房伤害无有效区分**：TTK 3.85–4.79（G3 最慢）、单房伤害 34.40–39.52（G3 最高但 TTK 也最慢），组间差异落在随机波动内，无法归因到 forge / tune / buff 任一路径。
4. 探针自带 note：`bot 固定任何有效符号即停；仅用于成长类型对照，不代表真人停中率`。

## 3. 安全门使用规则

1. G5 出口用与本文**完全一致**的探针命令重跑，比较 ACT1 / ACT2 / ACT3 单房输出中位数。
2. 通过线：各幕中位输出 ≥ 本文基线的 **90%**，且低分位无断层（不能出现大量零输出或无效房）。
3. ACT3 样本不足时，用 ACT1 + ACT2 做主判断，ACT3 只做观察并记录样本数。
4. 任何数值调整必须一次只改一个主轴（§14.4）；同时改带模型和回路数值时，本基线失效，需重新采集。
5. 本基线文件写入 `docs/baseline/`，不随代码改动覆盖；G5 复跑产物另建日期目录。

## 4. 口径锁定与阶段决策（2026-11-19 用户拍板）

> 本节为用户明确锁定的结论，优先级高于本文其余描述性文字，也覆盖任何「旧成长无效 / 删除无损」的推断。

### 4.1 三条锁定结论

1. **基线 B 只证明 bot 没有完成成长领取与展开**。`offer 21–22、picks=0` 应优先排查奖励选择 / 结算链路（`shown → selected → applied → 状态变化` 哪一环断了），**不能**用于评价锋铸、调律或成长强度。
2. **基线 A 可以作为 G5 的输出参考包络**，但**不能单独证明「新旧成长等效」**，更不能作为 G7 删除旧成长的充分依据。
3. **G7 前必须另做可归因 A/B**：同种子、同操作模型，至少区分「无成长 / 锋铸 / 调律 / 混合成长」四档，并确认每次预期奖励都完成 `shown → selected → applied → 状态变化`。

### 4.2 新探针的最低有效门槛

在可归因 A/B 探针满足以下四条之前，其数据不具备评价旧成长的资格：

1. bot 能稳定活过 ACT1，覆盖 ACT2 / ACT3；
2. 目标成长实际领取率为 **100%**，无结算失败；
3. 按幕记录输出、TTK、承伤和**低分位**结果；
4. 能明确回答「旧成长贡献了多少」，而不是只比较通关率。

### 4.3 阶段决策

| 阶段 | 决策 |
|---|---|
| **G5** | **可以继续做结构验收**（奖励真实有效、三选一合法性、武器三态、带编辑、回路等），输出曲线以基线 A 为参考包络，不等待可归因 A/B。 |
| **G7** | **「删除旧成长」保持阻塞**，直到 §4.2 的可归因 A/B 探针达标并给出旧成长贡献的量化结论；在此之前不得以任何理由执行删除。 |
| 排查项 | `offer 21–22 / picks=0` 作为待排查线索，优先检查奖励选择 / 结算链路是否真的把成长应用到了玩家状态，而非归入「bot 行为」了结。 |

> 落地提醒：§4.2 的可归因 A/B 不是本轮 G0-3a 的产物，也不是 G0-3b/c 的内容；它是 G7 的前置门禁。G0-4 建任务追踪时须单列此门禁项并标为「阻塞 G7」。
