## 0. 结论（一句话）

把"RPG 的强度"与"老虎机的频率"拆成**两个互不越界的轴**：**强度轴交给物品**（稀有度 / 攻击力 / 命中率 / 克制），**频率轴留在符号**（由 `kind` 自动派生）。符号的 `rarity_tier` 字段退役，频率改为 `kind → 档位` 的纯函数。这样既满足用户"稀有度在物品上"的诉求，又不会让神装"打不出去"。

---

## 1. 用户需求（原始三条）

1. **武器/技能 = 符号**：武器与技能就是符号的来源，因此符号的稀有度**由武器/技能的稀有度决定**（而非符号自带）。
2. **武器 = 经典 RPG 装备**：含攻击力 + 克制属性 + 命中率（命中率 ≈ 废铁），且这些属性**可升级**。
3. **技能 = 经典 RPG 分类**：含远程攻击、buff 加成、恢复等形态（而非当前只能塞一个 buff）。

---

## 2. 现状诊断（对照代码实证）

| 用户需求 | 现状（代码实证） | 差距 |
|---|---|---|
| ① 稀有度由物品决定 | `rarity_tier` 写在**每个 SymbolData 上**（S1 落地），武器 `WeaponData` 无稀有度字段 | 稀有度挂错层——该在物品 |
| ② 武器 = 攻击力+克制+命中率，可升级 | 攻击力三处缝合：`symbol.base` + `meta.weapon_base_bonus`(`_weapon_base_map`) + `_agg_power_flat`；克制在 `weapon.element`；**命中率不存在**，废铁是 S5 全局池级注入（按幕 15~23%，与具体武器无关） | 攻击力散落、命中率缺失、废铁是"全局税"而非"武器属性" |
| ③ 技能按 RPG 分类 | `SkillData` 只能提供**一个 buff 符号**（haste/rage），无攻击/恢复形态 | 技能形态单薄 |

**根本问题**：当前是"**符号中心**"——符号是原子、自带稀有度，武器只是符号搬运工。目标转为"**物品中心**"，但频率不能全盘上移（见 §3）。

---

## 3. 核心洞察：稀有度其实有两个轴（混合式的由来）

> ⚠ 这是整方案的关键前提，必须先确立，否则会自伤。

- **强度轴（power）**：传说武器 → 符号数值更强、命中更高、升级上限更高。✅ 该跟物品稀有度走。
- **频率轴（frequency）**：符号在转轮上出现多少次。

**如果频率也跟物品稀有度走 → 灾难**：传说武器"稀有" → 它的符号很少出现 → 你装备了神装却打不出去 = 废品。违背 RPG 直觉。

**结论（混合式）**：
- **物品稀有度 → 只决定强度**（base_power 量级、命中率基线、升级上限、商店价、掉落稀有度）。
- **符号频率 → 仍按"角色"治理**：攻击符号是主体、special（爆发）保持低频（唯一局内乘区，频率必须稀有）。频率与物品稀有度**解耦**。

---

## 4. 频率 = f(kind)：`rarity_tier` 退役

这是混合式最省事的地方——频率档**根本不用手填**，由 `kind` 自动派生：

| `kind` | 自动频率档 | 理由 |
|---|---|---|
| `damage` / `status` | 高频（主体） | 输出主力，该常见 |
| `special` | **低频（爆发）** | 唯一局内乘区，必须稀有（无论武器多神） |
| `buff` | 中频 | 增益点缀 |
| `gold` | 工具档 | 经济来源 |
| `trash` / `miss` | 填充档 | 由 hit_rate 决定 |

→ 频率 = f(kind)，强度 = f(物品 rarity)。**两个轴都是派生值，不在任何处手填稀有度**。
→ 现有 S2/S3/S6 的保底/上限治理**原样保留**，只是判定键从 `rarity_tier` 换成 `kind` 映射出的档。

## 5. 目标数据结构

### 5.1 物品层（武器 / 技能统一为 `LoadoutItem` 基类，待确认 #2）

```gdscript
# LoadoutItem（武器/技能的共同基类）
@export var category: String    # "weapon" | "skill"  —— 槽位/UI 分列依据
@export var rarity: Rarity      # 强度档位 + 升级上限 + 商店价（不定频率！）
@export var base_power: float   # 攻击力 / 效能（升级主通道，需求②）
@export var hit_rate: float     # 命中率（miss = 废铁，可升级，需求②）
@export var element: String     # 克制属性（通常固定）
@export var symbols: Array[SymbolWeight]  # 该物品贡献的符号（结算单元，不再自带 rarity）
```

### 5.2 符号层（SymbolData 减负，`rarity_tier` 退役）

```gdscript
@export var kind: String        # 结算行为 + 频率档来源
@export var base: float         # 数值偏移（相对 base_power 的权重）
@export var status_type: String
@export var element: String
```

> 符号只保留结算字段 + 角色（`kind`）。稀有度、攻击力、命中率、克制**全部上移到物品**。

## 6. 转轮池构建（对每件装备跑一遍）

1. **符号格**：按 `kind → 频率档` 给格数（special 少、damage 多）——频率轴。
2. **miss 格**：按 `hit_rate` 补废铁格（`1 - hit_rate` 越多 miss 越多）——强度轴的命中。
3. **强度**：物品 `rarity` + `base_power` 写入该物品符号的结算。

> 注入顺序建议（取代当前 S5 全局 trash）：
> 池符号（含 miss 格） → 最小带长平铺 → S4（符号私有化后删除，见 §8）→ S2/S3（保底/上限，按 kind 档）→ 洗牌。

---

## 7. 结算公式

```
伤害 = (物品 base_power × 符号 base 偏移) × 连线 × 克制(物品 element)
```

- 频率在转轮阶段已定型，结算只管强度。
- **没有新增任何伤害乘区**：`base_power` 是线性基础轨（契合双轨膨胀）；`hit_rate` 是频率不是乘区；`element` 是已有克制乘区。
- 唯一局内乘区仍是 special 三连连锁重触发（保留）。

## 8. 完整走查：传说火焰剑 vs 普通铁剑

| | 普通铁剑 | 传说火焰剑 |
|---|---|---|
| `rarity` | common | epic |
| `base_power` | 12 | 30 |
| `hit_rate` | 0.75（25% miss） | 0.92（8% miss） |
| `element` | none | fire |
| 转轮 | 铁斩(高频) + **25% 废铁** | 火斩(高频) + 火special(低频) + **8% 废铁** |
| 结算 | 12 × 连线 × 1.0 | 30 × 连线 × 克制(弱火 ×1.5) |
| 升级 | base_power↑ / hit_rate↑ | 同 |

**重点**：传说剑**又强（30>12）又准（92%>75%）**，但它的 `火special` 和普通剑的 special **一样低频**——稀有度让它更强更准，却没让爆发变廉价。这就是混合式不犯"神装打不出去"的原因。

## 9. 保留 / 改 / 删（对照现状）

| 保留 | 改 | 删 |
|---|---|---|
| 频率保底/上限治理（S2/S3/S6，改读 kind 而非 rarity_tier） | 攻击力三处缝合 → 收拢为 `base_power` | `SymbolData.rarity_tier` 字段 |
| special 连锁重触发（唯一局内乘区） | 废铁全局税（S5）→ 武器 `hit_rate` 注入 | S5 全局 trash 注入逻辑 |
| 元素克制、连线乘区、ante 曲线、双轨膨胀 | 技能扩成 远程/ buff / 恢复（需求③） | S4 `_enforce_symbol_cap`（符号私有化后无共享垄断） |
| 四槽位职责划分（`物品分类职责划分.md`） | 武器/技能合并为 `LoadoutItem`（待确认 #2） | **wild**（用户已认定是 debuff，物品中心模型里无归属） |

### 9.1 顺带解决的旧账
- **S4 burn 垄断**：符号改为**物品私有、不再跨武器共享**（火焰剑的 burn ≠ 火焰法杖的 burn），"共享符号累加垄断"从根上消失，`_enforce_symbol_cap` 可删。
- **S5 trash**：被 `hit_rate` 取代，全局注入逻辑删除。
- **S1 rarity**：从符号上移到物品，`rarity_tier` 字段退役。
- **S8 wild**：用户判定为 debuff，顺势删除。

## 11. 已确认的 3 个决策点（2026-08-03 用户拍板，按 AI 建议执行）

> 以下 3 点已于 2026-08-03 由用户拍板确认（均采纳 AI 建议），作为动工依据。

1. ✅ **频率 = f(kind)**（`rarity_tier` 退役）：符号频率档由 `kind` 自动派生，稀有度只定强度。采纳理由——避免"神装打不出去"，且频率档零手填、S2/S3/S6 治理逻辑原样保留（仅改判定键为 kind 映射档）。
2. ✅ **武器/技能合并为 `LoadoutItem` 基类**：统一 `rarity/base_power/hit_rate/element/symbols` 字段，以 `category`（"weapon"|"skill"）区分两类（决定槽位规则与 UI 分列）。采纳理由——消除 `WeaponData`/`SkillData` 重复字段、统一升级与结算通道。
3. ✅ **符号私有化**：每个物品的符号不跨物品共享（火焰剑的 burn ≠ 火焰法杖的 burn），从根源消除"共享符号累加垄断"，S4 `_enforce_symbol_cap` 可删。用户已知悉代价：失去"叠 burn"的火系 build 累加爽感，换取频率治理简化与无垄断。

## 12. 设计取舍记录（讨论中的评估结论）

> 供后续回顾，非动工依据。

- **纯物品中心（频率也跟物品稀有度）是退步**——神装打不出去。故采用混合式（频率留符号层）。
- **"命中率 = 废铁"是全方案最稳赚的一步**——比 S5 全局 trash 税更优雅、更 RPG；难度刹车回归由敌人 ante 涨血涨攻承担（已存在），但 ante 曲线需重新审视以补足失去的稀释。
- **转轮必须永远有 miss 是老虎机隐藏约束，RPG 模型没有**——hit_rate 不能趋近 100%，需人为留底（如 common 最低 70%），否则高命中神装让稀释刹车失效、转轮变无脑。
- **符号私有化会失去"叠 burn"爽感**——治病同时切了爽点，净收益待 F6 实测判断。
- **S1–S8 不后悔**——它教会我们"稀释/垄断/爆发稀有"三类失败模式，这些教训在任何模型下都需处理。
