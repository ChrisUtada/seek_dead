## 1. 一句话结论

第一阶段已把成长系统收敛到**单一加法出口**（`combat_system.agg_power_flat`）与**单一真实带模型**（`ReelPreview`/`cells_for`）；剩余问题不是"系统太多"，而是三类职责重叠：
1. **武器攻击力**被 6 条来源同时供给（武器基础/熟练 forge/槽位 forge/铸式 power/`run_power_bonus`/护符）；
2. **定向解锁**有 anvil 与 career 两套并行入口；
3. **图鉴历史熟练**与局内熟练并存（已解耦，仅历史记录）。

用户已批准：**熟练/铭印暂缓删除；定向解锁归一到生涯、S5 做单一账本迁移、旧铁砧侧只保留兼容；`run_power_bonus` 作为内部通道收敛来源。**

## 5. 架构定稿（四层职责）

| 层次 | 核心职责 | 本阶段归属系统 |
|---|---|---|
| 武器 | 构筑引擎、机制身份、符号来源/结构、适配方向 | WeaponData + 武器掉落/换装（G2）+ 铸式（横向变体） |
| 符号带/牌谱 | 构筑核心、符号配置、概率与组合、规则编辑 | ReelSystem + ReelPreview + pattern_system + circuit_system + strip_trim_system |
| 战后奖励 | 构筑扩展、战术调整、资源与机制选择 | RewardSystem + DraftComposer + RewardResolver + Presentation（G1/G2 已稳定） |
| 局外成长 | 内容解锁、收集、图鉴、记录、新选项 | MetaStore + **CareerSystem（定向解锁单一账本）** + CodexSystem |

**单一真源纪律**：
- 伤害出口唯一：`combat_system.agg_power_flat()`。
- 带模型唯一：`ReelPreview.compose()` / `ReelSystem.cells_for()`。
- 局外收藏唯一：`meta.owned_*`（由局内实际获得回填，G2 `remember_weapon` 已实现武器侧）。
- 定向解锁唯一：**生涯单一账本**（S5 迁移后）。
