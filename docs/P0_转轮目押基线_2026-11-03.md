## 2. 固定对照组规则（2026-11-03 当前版本）

### 2.1 速度

| 项 | 当前值 | 来源 |
|---|---|---|
| 起始每跳间隔 | `0.15s` | `ReelSystem._SPIN_BASE_WAIT` |
| 最快每跳间隔 | `0.06s` | `ReelSystem._SPIN_MIN_WAIT` |
| 加速 | 每跳 `-0.0010s`，封底 `0.06s` | `ReelSystem.on_spin_tick` |
| 稳定节奏 | 有 `steady` 技艺时，每房前 2 回合基础间隔 `0.17s` | `GrowthSystem.STEADY_WAIT / STEADY_TURNS` |

### 2.2 预览与输入

| 项 | 当前值 | 说明 |
|---|---|---|
| 可见槽位 | 5 槽 | `ReelSpinView.SLOTS` |
| 当前格位置 | 居中 | 前向可见 2 格、后向 2 格 |
| 洞察 | 额外显示下 1 个符号 | `ReelSystem.next_symbol` / `_sync_preview` |
| 输入缓冲 | 无 | 按停即取当前逻辑格，没有跨节拍宽限 |
| 自动选目标 | 无 | 玩家按空格逐列停，或点击单列停 |
| 敌人自动停 | 有 | 敌人机制 `pending_auto_stop` 每跳随机停一列，不属于玩家目押 |

**反应窗口口径**：目标进入前向 2 格视野到抵达中心的时间 ≈ `2 × 当前每跳间隔`。起步约 0.30s，随加速累计在带尾降到 0.21–0.24s，封底 0.12s。它不是“看到目标后可以犹豫的时间”，因为目标在视野中还会继续移动；真人测试仍需记录实际停中率。

### 2.3 带长与格数

| 项 | 当前规则 |
|---|---|
| 符号格数 | 权重 `<2` → 2 格；`≥2` → 3 格；`≥4` → 4 格 |
| 稀有度封顶 | 非 damage 的 rare/epic 单源封顶 2 格；damage 不受此封顶 |
| 共享源 | 同一 `(符号, 有效元素)` 被 ≥2 件装备携带时突破封顶，走正常档位 |
| MISS | 按 `Σ装备权重 × (1 - 命中率)` 占总权重比例折算，保底 1 格 |
| 金币 | 常驻 2 格 |
| 乱权/深渊废铁 | `pending_chaos` 追加基础带 20% 的废铁；`boss_trash` 追加 N 格 |
| 最小带长 | 逻辑基础带 <30 时，**整份复制**直到 ≥30；占比不变 |
| 实际带长 | 逻辑基础带 × 平铺份数；三列都是该带子的独立洗牌副本 |

关键结论：**实际带长不是成长量的单调函数**。调律可能让逻辑带从 14 → 16，但平铺份数从 3 降到 2，实际带长反而 42 → 32。任何界面都必须显示“最终实际带长”，不能只显示逻辑格数。

## 3. 代表性配装与“当前目标”

### 3.1 基准配装

| 项 | 选择 |
|---|---|
| 武器 | `fire_sword` + `ice_staff`（异元素双武器） |
| 技能 | 无（G3 除外，固定 `haste` + `rage` + `calm`） |
| 护符 | 无 |
| 消耗品 | 2 × 基础治疗药剂（仅用于低血自动喝药） |
| 目标符号 | `res://resources/symbols/fire_slash.tres` |

选择理由：

- `fire_sword` 是 ACT1 最常见的主武器之一，`fire_slash` 是它权重最高的伤害符号。
- 异元素双武器是当前探针的标准对照（M2 的 `S0/S3` 同口径），不会被同元素共鸣额外抬高目标占比。
- 目标在基准带中为 3 格/单位；调律后为 4 格/单位，便于观察“目标格 +1”是否真的转化为机会。

同元素配装 `fire_sword + flame_staff` 只用于转轮带对照（`C_same`），不进入本轮战斗基线，避免把共鸣权重和成长类型混在一起。

### 3.2 真人测试的“当前目标”定义

**规则：每局开始前声明且只声明一个目标符号，整局不切换。**

操作口径：

1. 打开武器面板，取**主武器中权重最高的伤害符号**作为默认目标。本轮基准固定为 `fire_slash`（火焰剑的 `burn` 是 status，不计入伤害目标）。
2. 在测试表上写下 `target_symbol = res://resources/symbols/fire_slash.tres`，并记录配装、技能、护符。
3. 中途不因“现在哪个符号更划算”改目标。调律增加了目标格数，仍然追同一个符号。
4. 若目标符号因构筑变化消失，或玩家确实想换目标：结束当前记录段，重新开局并重新声明，不能在同一段数据里混算。
5. 每次按停一列记录一条结果：
   - **目标命中**：该列中心落点 == 声明的目标符号。
   - **有效非目标**：落在其他伤害/状态/回复符号上。
   - **空停/废铁/MISS**：没有有效结算。
6. 统计口径固定为两个，避免“回合”和“列”混用：
   - **主指标：单列目标命中率** = 目标落点列数 / 玩家主动按停列数。
   - **副指标：回合目标覆盖率** = 至少一列命中目标的回合数 / 总回合数。
   - 敌人自动停、冻结列、锁轮列不计入分母；它们不是玩家目押结果。
7. A/B 两组必须使用相同目标、相同配装、相同房间顺序；组间交替进行，避免熟练度只偏向其中一组。

这样“目标停中率”才是同一个分母，不会因为每个人追不同符号而失真。

### 4.1 读表要点

1. **带长非线性**：B_diff 单位 14 → F_tune 单位 16，实际带长从 42 掉到 32。原因是平铺份数 3 → 2。只看“单位格数”会误判成长方向。
2. **调律有效但受平铺影响**：F_tune 的目标格从 3 → 4/单位，占比 21.4% → 25.0%，目标间隔 4.67 → 4.00 格，理论循环 5.44s → 4.30s。单看这一组，调律同时改善密度和循环；但实际带长缩短是平铺副作用，不是调律本身的“减带”设计。
3. **技能稀释是真实的**：D_buff3 单位带长从 14 → 21，目标仍 3/单位，实际目标占比 21.4% → 14.3%，目标间隔 4.67 → 7.00 格。3 个技能并没有缩短实际带长（42），但显著降低了目标密度。
4. **锋铸不碰带子**：E_forge 的带长/组成与 B_diff 完全一致，只把基础攻击 18/15 提到 22/19。它解决“停中后的收益”，不解决“更容易停中”。
5. **同元素不是天然更短**：C_same 因共鸣权重，目标 4/单位、占比 30.8%，但实际带长 39 与 B_diff 42 不同。同元素与异元素的比较不能只归因于带长。
6. **反应窗口随带内位置下降**：起步时约 `2 × 0.15 = 0.30s`，走到带尾因加速累计下降到表中 0.21–0.24s；封底是 `2 × 0.06 = 0.12s`。带子越长，后段反应窗口越窄；这和“目标密度”是两条独立轴，P1 必须分开测。
7. **理论循环不含结算**：表中的循环时间只累计旋转节拍，不含停轮、结算、动画和玩家犹豫；真人 TTK 以战斗探针与遥测为准。
8. **“0.17 全程假设”不是实际稳定节奏循环**：`steady` 只在每房前 2 回合把基础间隔抬到 0.17s，不会覆盖整条带子。这一列只用于比较“如果全程慢到 0.17”的时长量级，不能当成真实循环。

## 5. 成长类型战斗基线（`P0GROW`）

同一配装、同一 40 个种子、同一 ACT1 8 房：

| 组 | 成长 | 说明 |
|---|---|---|
| G0_no_growth | 无 | `growth.enabled=false`, `mastery.enabled=false` |
| G1_forge | 仅锋铸 | 有铭印时只选 `forge`，不选 `tune` |
| G2_tune | 仅调律 | 有铭印时只选 `tune`，拿不到就跳过，不混入锋铸 |
| G3_buff3 | 技能 Buff | 开局带 `haste` + `rage` + `calm`，无成长 |

bot 口径：伤害/状态/回复/特殊/Buff 任一有效符号即停、低血自动喝药、奖励跳过武器、不逛商店。`buff` 必须计入停轮目标，否则技能 Buff 符号永远不会落地，G3 会退化成纯稀释组。它不代表真人停中率，只用于固定“成长类型”这一变量。

|---|---|---:|---:|---|---:|---:|---:|---:|---:|---:|---:|
| G0_no_growth | 无 | 8/40 | 32/40 | 4:1 / 7:3 / 8:28 | — | 0.00 | 0.00 | 0.00 | 0.00 | 2.84 | 26.07 |
| G1_forge | 仅锋铸 | 13/40 | 27/40 | 4:1 / 7:4 / 8:22 | 3.05 | 2.70 | 3.77 | 3.77 | 0.00 | 2.76 | 24.12 |
| G2_tune | 仅调律 | 8/40 | 32/40 | 4:1 / 5:1 / 7:4 / 8:26 | 3.05 | 4.83 | 0.97 | 0.00 | 0.97 | 2.68 | 23.99 |
| G3_buff3 | 3 技能 Buff | 4/40 | 36/40 | 4:1 / 5:2 / 6:2 / 7:11 / 8:20 | — | 0.00 | 0.00 | 0.00 | 0.00 | 3.63 | 30.21 |

### 5.1 读表要点

1. **G0 与方案 §2.1 引用的当前 M2 S0 完全一致（8/40）**，说明配装、种子、bot 口径对齐。无成长组的死亡高度集中在第 8 房（28/32），当前 ACT1 的主要墙是 BOSS，不是前中期杂兵。
2. **锋铸是四组里唯一超出 40 种子噪声范围的通关提升**：8/40 → 13/40，每房承伤 26.07 → 24.12，BOSS 房死亡 28 → 22；每局平均拿到 3.77 次锋铸。它只改停中后的基础攻击，不改变带子，因此提升来自“同样停中、收益更高”。
3. **仅调律的通关率与无成长相同（8/40）**：调律每局平均只有 0.97 次，且本配装里只有 `fire_sword` 的 `fire_slash` 能真实 +1 格，`ice_staff` 的 `tune_target` 始终为空。也就是说，当前调律的“+1 目标格”出现频率太低，无法单独承担一条成长轴；它更适合作为锋铸之外的补充，而不是替代。
4. **G3 的 4/40 不能直接解读为“Buff 弱”**：这个 bot 见到任何 buff 都停，包括防御向 `calm`；它会在有伤害符号时放弃伤害去拿盾，且按停的是最左未停列，不是最优目押。G3 真正说明的是**技能入轮的机会成本是真实的**：3 个技能把单位带长从 14 拉到 21，目标占比 21.4% → 14.3%，每次拿 Buff 都在和伤害符号抢停轮。真人是否会选择性拿增伤 Buff、跳过防御 Buff，需要 P1 真人测试，不能用这个 bot 的 4/40 下结论。
5. **G3 对 bot 策略高度敏感**：同一组在“buff 不计入停轮”的旧口径下是 10/40（每房回合 2.84、承伤 22.78）。两个数字都不是 Buff 的真实强度，而是“使用方式”的上/下界：不拿 Buff 只吃稀释是 10/40，见 Buff 就拿是 4/40，真人应在两者之间按局面选择。
6. **G2 的成长屏/局（4.83）高于 G1（2.70）不是更好**：因为 G2 拒绝锋铸，欠选会反复回到成长屏；这是 bot 只拿调律造成的副作用，不是更多有效成长机会。
7. 表中的“每房回合”是 TTK 代理（回合数），不是秒；“每房承伤”是玩家实际掉血，不是输出。40 种子下 8 vs 10 这类小差距在噪声范围内，8 vs 13 才是值得跟进的信号。

### 5.2 使用限制

- G0–G2 不带技能，带内没有 `buff` 符号，因此“把 buff 加入停轮目标”只影响 G3；G3 是用最终版本探针单独重跑的。
- G2 的调律次数受当前规则限制：`tune_target` 只在“+1 权重真实改变格数”时出现，且每把最多 2 次。实测通常只有 `fire_slash +1` 一次，不能把它当成“每把稳定 +2 格”。
- 本探针不覆盖护符、同元素战斗、BOSS 机制废铁、商店和武器替换；这些变量留到后续专项。
- 历史 M2 数据（无成长 8/40、完整成长 19/40；同元素 32/40、36/40）使用不同的 bot 策略和成长开关，只能作为背景，不能与 G0–G3 直接相减。

## 7. 精简只修改本局状态：工程约定

P0 阶段尚未实现主动减带，但先锁定边界，避免 P2 把“本局整理”做成共享资源或局外收藏的修改。

### 7.1 允许修改

- `DuelController` 的本局运行时状态（新增字段或 `StripTrimSystem` 内部状态）。
- 本局 `selected_skills`（技能卸除只影响本局入轮，不回写拥有列表）。
- `ReelSystem.build_strips` 与 `ReelPreview.compose` 读取同一份本局精简状态。
- 每幕次数、已精简符号、已卸技能等计数，随本局开始/结束重置。

### 7.2 禁止修改

- `res://resources/` 下的 `.tres` 文件内容或路径。
- `MetaStore.meta` 的 `owned_weapons / owned_charms / owned_consumables / collection_milestones`。
- 局外收藏、图鉴解锁、铁砧点数、商店价格。
- 通过精简/恢复同一技能反复刷新商店、成长或随机结果。

### 7.3 现有代码的同类先例

- `WeaponMastery` 的 `imprints` 是运行时字典，`reset_run()` 清空，文件头明确“不改共享 .tres”。
- `ReelSystem.build_strips` 每次从 `pool_items` 重建 `reel_strips`，带子是运行时数组，不写回资源。
- `ReelPreview.compose` 与 `build_strips` 共用格数规则，避免预览和正式带子两套口径。
- `MetaStore` 是唯一负责局外持久化的入口；精简实现不得调用 `save_meta()`。

### 7.4 P2 落地时必须补的测试

1. 同种子 + 同精简状态 → 两次建带完全一致。
2. 精简前后，`res://resources/` 文件内容哈希不变。
3. 精简前后，`MetaStore.meta` 的拥有列表与里程碑不变。
4. 新开一局后，上一局的精简状态为空。
5. 精简预览的“实际带长/目标占比”与正式建带一致，包括最小带长平铺。
6. 技能卸除后，该技能的符号与 MISS 贡献按现有规则移除，且不可通过重开界面恢复来刷新随机结果。

## 8. 复现命令

版本锚点：Godot 4.7 stable，`--fixed-fps 60`，基线运行在提交 `99d5be0` 之上（P0 探针与本文档尚未提交）。

```bat
"D:\Godot\Godot_v4.7-stable_win64.exe\Godot_v4.7-stable_win64_console.exe" ^
  --headless --fixed-fps 60 --path . res://tests/p0_reel_baseline.tscn

"D:\Godot\Godot_v4.7-stable_win64.exe\Godot_v4.7-stable_win64_console.exe" ^
  --headless --fixed-fps 60 --path . res://tests/p0_growth_baseline.tscn
```

- 转轮探针输出 `P0REEL|`，退出码 0 表示 64 项检查全过。
- 战斗探针输出 `P0GROW|ROOM|...` 与 `P0GROW|SUMMARY|...`；它是测量型探针，不设断言，退出码 0 只表示脚本正常结束。
- 只复跑 G3：在上面的命令末尾加 `-- --only=G3_buff3`。
- 战斗探针会在启动时快照 `lobby_data.json`，结束后原样还原；它只应影响本局运行时状态。
