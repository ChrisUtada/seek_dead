# 意图系统资源化 · 执行方案

> 状态：**✅ T20 已落地（2026-08-07）**——IntentData + 默认三档表（DEFAULT_INTENT_WEIGHTS）+ `RoomData.intents` 房间覆盖 + 加权骰/净化/HUD 全链路迁移 + 21 房清理。本节以下为设计依据，实现以代码为准。
> 关联讨论：2026-08-07 设计讨论（"意图名称可配置化 → 是否做成 Resource → 普通小怪/精英怪也有意图"）
> 代码基线：`room_data.gd` / `duel_controller.gd` / `battle_hud.gd` HEAD
> 前置：`intent_names` 覆盖字段已随 T20 退役（名字归 IntentData 管）

---

## 1. 背景与问题

意图当前是「散装」的，新增 / 调整一个意图要动 4 处代码：

| 维度 | 现状 | 位置 |
|---|---|---|
| 概率 | `RoomData.jam/lock/chaos/heavy` 4 个 float | `room_data.gd:11-14`、21 个房间 `.tres` |
| 显示名 | HUD match 硬编码 + `intent_names` 每房覆盖 | `battle_hud.gd:779-785`、`room_data.gd:15` |
| 可净化名单 | 硬编码 `["jam","lock","chaos"]` | `duel_controller.gd:1296` |
| 执行 | 按 type 分发（attack/heavy/jam/lock/chaos） | `duel_controller.gd:1172` 起 |

**三个痛点：**

1. **加意图 = 动 4 处代码**：新增「锁格 / 倒计时注废」这类意图，要同步改概率字段、HUD match、净化名单、执行分发。
2. **无定义载体**：意图的名字 / 图标 / 描述 / 权重 / 可否净化散落在三个文件，BOSS 想做专属意图只能靠 `intent_names` 字符串补丁。
3. **与课程化冲突**：T10 BOSS 扩充（8+ 新 BOSS）+ 普通/精英课程化（18 个非 BOSS 房复核）会集中爆发意图需求，现有结构撑不住。

---

## 2. 目标

把「敌人会出什么意图」从**散落硬编码**重构为**一张可编辑的数据表 + 统一分发器**：

- **加意图 = 加 .tres**（首次出现时补一段执行分支），对齐「加内容不改代码」铁律。
- **全房型覆盖**：普通小怪 / 精英 / BOSS 都有意图表，按「房型×幕」分层默认表，课程化模型（先教分散子机制、BOSS 合成）直接落在数据上。
- **名字 / 图标 / 描述 / 权重 / 可净化**全部集中管理，`intent_names` 退役。

## 3. 目标设计：IntentData Resource

### 3.1 Resource 定义（新建 `scripts/battle/intent_data.gd`）

```gdscript
class_name IntentData
extends Resource

@export var id: String = ""            # attack|heavy|jam|lock|chaos|cell_lock|...
@export var display_name: String = ""  # 显示名（替代 intent_names 覆盖）
@export var icon: String = ""          # ⚔ 💥 ☣ 🔒 🌀 ...
@export var desc: String = ""          # 悬浮提示用描述
@export var weight: float = 1.0        # 池内加权概率（RoomData 表内相对权重）
@export var purifiable: bool = false   # 净化药剂可否抵消（替代硬编码名单）
@export var value_mult: float = 1.0    # 数值公式参数（heavy=2.0 → 伤害 atk×2）
@export var duration: int = 1          # 持续/延迟回合（倒计时注废 timed_jam=3）
```

- 行为**仍在代码侧**：`duel_controller.gd` 按 `id` 分发执行（与 gimmick 同模式）；Resource 只承载定义。
- 默认 5 个 .tres 落 `resources/intents/`：`attack / heavy / jam / lock / chaos`（purifiable 仅 jam/lock/chaos 为 true）。

### 3.2 默认三档表（按房型）

`RoomData.intents` 为空 → 按 `kind` 取默认表：

| 房型 | attack | heavy | jam | lock | chaos | 定位 |
|---:|---:|---:|---:|---:|---:|---|
| normal（普通） | 60 | 20 | 10 | 5 | 5 | 低干扰，教「看懂意图」 |
| elite（精英） | 40 | 20 | 15 | 15 | 10 | 干扰显著，净化药剂开始有存在感 |
| boss（BOSS） | 专属表 | 专属表 | — | — | — | 由 BOSS `.tres` 配置（gimmick 强制型 + 数值强化） |

**按幕渐进（课程化第一课）**：Act1 普通房只出 attack/heavy（教基础），Act1 精英引入 jam；Act2 普通加 lock/chaos，Act2 精英出倒计时类；Act3 BOSS 用机制意图。

### 3.3 RoomData 改造

```gdscript
@export var intents: Array[IntentData] = []   # 本房意图加权表；空 = 按 kind 取默认三档表
# 移除：jam / lock / chaos / heavy（4 个 float）、intent_names（过渡补丁）
```

- 21 个房间 `.tres`：**删除 4 个 float 行**（`jam=` / `lock=` / `chaos=` / `heavy=`），残留行 Godot 会忽略不崩，但会刷 warning，故批量清理（正则删行）。
- 想特化的房（如 BOSS）在 Inspector 里拖自己的 `Array[IntentData]`。

### 3.4 enemy_intent 字典新结构

```gdscript
enemy_intent = {"data": IntentData, "type": "jam", "value": 0}
# 旧结构 {"type", "value"} 兼容期内保留 type/value，HUD 与执行层改读 data
```

## 4. 执行层迁移（4 处调用点）

| 位置 | 现状 | 改造 |
|---|---|---|
| 加权骰 | `duel_controller.gd:880-890` 读 4 float | 读 `RoomData.intents`（空则默认表）按 weight 加权抽 |
| 执行分发 | `duel_controller.gd:1172` 起按 type | 按 `id` 分发（行为不变）；value 从 `value_mult × atk` 计算 |
| 净化判定 | `duel_controller.gd:1296` 硬编码名单 | 改读 `IntentData.purifiable` |
| HUD 意图栏 | `battle_hud.gd:779-785` match 硬编码 | 改读 `IntentData`（icon + display_name + desc），match 仅剩兜底 |

gimmick 强制意图（`whisper_lock` 等）：按 `id` 在房表中查 IntentData，查不到回落默认。

## 5. 意图候选池（T10 配套，本方案不实现）

> 以下为后续 BOSS/课程化扩充的意图候选，按与本作转轮机制的契合度排序；立项时逐条补执行分支。

| 意图 | id | 效果 | 可净化 | 优先级 |
|---|---|---|---|---|
| 锁格 | cell_lock | 锁死 1 个格子，该格保持当前符号不能停 | ✅ | ★★★ 首选 |
| 倒计时注废 | timed_jam | 3 回合后注入废铁（到点才生效，净化是时机决策） | ✅ | ★★★ 首选 |
| 断链 | chain_breaker | 你打出 special 三连时敌人追加反击（管住最强爽点） | ❌ | ★★☆ |
| 护符封印 | charm_seal | 下轮护符乘区失效（最高 ×6 的乘区受威胁） | ❌ | ★★☆ |
| 加速 | speedup | 下轮转速提升（对抗按停技巧层） | ❌ | ★★☆ |
| 吞噬废铁 | trash_eater | 你每停到 1 格废铁，敌人自愈/加攻（与 jam 联动） | ❌ | ★★☆ |
| 镜像 | mirror | 复制你上轮主符号元素，属性切换（split_ego 可抽成通用意图） | ❌ | ★☆☆ |
| 夺金 | tax | 本轮金币符号归它 / 直接偷 X 金（经济压力） | ✅ | ★☆☆ |
| 缴械 | disarm | 下轮腰带消耗品禁用（克制净化常驻流） | ❌ | ★☆☆ |
| 诅咒符号 | curse | 下轮治疗/金币符号变废铁（污染符号池） | ✅ | ★☆☆ |
| 反伤 | reflect | N 回合内伤害符号回弹 20% | ❌ | ★☆☆ |

净化边界原则：**干扰类可净化、机制/数值类不可净化**——避免「净化一键解所有」，给腰带取舍留空间。

## 6. 落地步骤（每步必验 + 独立提交，遵循方案B纪律）

1. **Step 1 · 定义层**：新建 `intent_data.gd` + `resources/intents/` 默认 5 个 .tres；`room_data.gd` 加 `intents: Array[IntentData]`（先保留旧 4 float 与 `intent_names`，双轨不冲突）。
2. **Step 2 · 消费层**：controller 加权骰改读房表（空→按 kind 默认表）；`enemy_intent` 挂 `data`。
3. **Step 3 · 呈现层**：HUD 意图栏改读 IntentData（icon/name）；`_intent_name` 同步。
4. **Step 4 · 净化**：purify 判定改读 `purifiable`。
5. **Step 5 · 清理**：删 `room_data.gd` 旧字段（jam/lock/chaos/heavy + intent_names）；批量清理 21 个 `.tres` 的 4 个 float 行；删 gimmick 对旧字段的引用。
6. **Step 6 · 验证**：F6 全流程（见 §7）+ 总清单 T20 勾选。
