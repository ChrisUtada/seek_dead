> 任务：把第三格预览入口搬进战斗——停第一/二列之后、停第三列之前，「🗂 预览」可见，
> 玩家能先看到第三列的候选组合，再决定怎么停。

## 1. 结论

- 战斗窗口 = `in_interroom == false` 且 `spinning` 且 `reel_stopped == [true, true, false]`，
  由 `DuelController.is_battle_combo_window()` 单点判定，HUD 只消费不判断。

- 间歇期入口行为不变：整本组合 + 本轮来源，且**不**给第三格预览。
- 停第三列（SPIN 按钮 / 点击第三列 / 空格）时，已打开的预览面板自动收起。
- 目标套件：`T3CPREVIEW|RESULT PASS (checks=38 fails=0)`；
  全量：`[smoke] RESULT: ALL GREEN`（55/55 步）。

## 4. 空格停轮与面板为何不会双触发

空格在 `_input()` 里处理且**不** `set_input_as_handled()`；若「🗂 预览」按钮此时持有焦点，
同一次空格会既走到 `_input` 停列、又被 Godot 当作 `ui_accept` 再按一次按钮（面板刚关又被打开）。
因此打开面板时 `gui_release_focus()`、点亮按钮时 `release_focus()`，把键盘交回战斗输入，
面板与空格各只触发一次。

## 5. 入口可见性的刷新点

| 刷新点 | 时机 | 作用 |
|---|---|---|
| `hud.set_reel_enabled()` → `_sync_battle_combo_entry()` | `reel_system` 起转 / 吸附开始 / **落定** / `finish_spin` | 真正点亮按钮的是**第二列落定**这一次（`_lock_at` → `set_reel_enabled(r, false)`）；吸附是延迟落子，只在按钮回调里同步会永远看不到入口 |
| `_on_spin_pressed()` | 起转 | 立即收起 |
| `_stop_next_column()` / `_on_spin_button_pressed()` / `_on_reel_clicked()` | 每次停列/点列之后 | 停第三列（吸附开始或落定）后收起 |
| `hud.set_interroom_enabled(true)` | 进间歇态 | 收起，避免残留 |
| `hud.set_battle_combo_available(on)` | 以上全部 | 唯一写 `visible/disabled` 的地方 |
