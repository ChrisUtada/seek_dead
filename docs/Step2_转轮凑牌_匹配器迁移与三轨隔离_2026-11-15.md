## 1. 牌面输入扩展了两个维度

`PatternMatcher.cards_from_grid()` 现在产出：

```gdscript
{
  sym, element,          # 符号与它的有效元素
  source,                # 武器 id（grid_src），技能牌为空
  source_kind,           # weapon | skill | resource   ← 新增
  source_element,        # 来源武器的元素              ← 新增
  valid,                 # 冻结列为 false
}
```

### 来源类别怎么判

技能符号段在 `pool_items` 里**没有来源 id**（`[[sym, weight, elem]]` 只有 3 项），
所以 `grid_src` 对技能牌是空串，不能靠它分类。

改用「符号归属」：

| 判断顺序 | 结果 |
|---|---|
| 符号路径在 `_skill_sym_kind` 里 | `skill` |
| `grid_src` 命中 `_source_element_map` | `weapon` |
| 其余（精华 / 金币） | `resource` |

两张表在 `_build_pool` 末尾的 `_sync_pattern_source_meta()` 里填，**结算路径不读它们**，
所以不会改变既有伤害语义（同源三连、专精倍率都不受影响）。

## 2. 三轨隔离

`_apply_patterns()` 现在分两组：

```text
武器轨：weapon_cards（只含 source_kind = weapon）
        → G01–G03（PatternMatcher.match）+ 至多一条 W（match_rules）
技能轨：恰好 1 张技能牌 + 2 张武器牌
        → 至多一条 T
```

两条轨独立结算，互不挤占 —— 同一回合可以各触发一条。

## 3. W01 的语义修正（Step 1 发现的问题）

火系武器的伤害符号 `element` 是 `none`（火斩是「无属性伤害」），只有状态符号是 fire。

原来的条件 `{"element": "fire"}` 匹配到的是**「燃」这张状态牌**，牌面变成「火斩 + 燃 + 燃」。

修正后：

```text
旧：{"all": [{sym: fire_slash}, {sym: burn}, {"element": "fire"}]}
新：{"all": [{sym: burn}, {"kind": "damage", "source_element": "fire"}, {"source_kind": "weapon"}]}
```

第二条才是「来自火系武器的伤害牌」，第三条排除技能牌。

W03/W04 同步改成按 `source_element` 判定。

## 4. 「任意武器牌」收紧为 `source_kind: weapon`

原来的 `{}`（任意有效牌）会被技能牌满足 —— 那样「2 武器 + 1 技能」也能触发 W，
与方案「武器牌谱只读武器牌」冲突。

三条现有 W 的最后一个条件全部改为 `{"source_kind": "weapon"}`。

## 5. 新增 `track` 字段

`PatternData.track`：`weapon_public | weapon_attack | skill_support`。

`PatternSystem.by_track()` / `combat_system._pick_track()` 按轨取子集。

现有六条资源的归属：

| 资源 | track |
|---|---|
| s01 / s02 / s03 / s04 | `weapon_attack` |
| s05 / s06 | `skill_support`（**已退役**，只是字段标了位置） |
