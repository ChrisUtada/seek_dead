## 1. 本切片范围

固定 4×4 网格已经通过 Step 1–5；本步把单一人工布局扩成 **3 套人工验证模板**，
按 seed 稳定轮换，使同种子可复现、不同种子出现真实的装备路线差异。

不是完全随机布雷：每套模板都由人工布置，只有房间 / 武器 / 护符 / 商店候选在模板内按 seed 冻结抽取。

## 3. 模板验证口径

`tests/grid_templates_test` 对每套模板逐项检查：

1. 类型构成与 `EXPECTED_COUNTS` 完全一致，战斗预算 8；
2. 起点 / BOSS 位置正确，`BoardGrid.validate()` 无错误（含全图连通、邻接对称）；
3. 起点有非战斗首选格，所有公开目标可见，至少一件武器距起点 ≤2；
4. 威胁密度：任何格子的数字 ≤3（不存在四面被普通怪围死），数字总和落在 16–23；
5. 可推理路线：存在一条起点 → BOSS 的路径，路径上每格数字 ≤2，不依赖强制 50/50；
6. 两件武器与护符都有冻结候选，装备目标不是空壳。

这组检查把「威胁密度、可推理路线、装备价值、战斗预算」落成可回归的数字。

## 4. Seed 轮换

```gdscript
static func template_index_for(seed_value: int) -> int:
    return absi(seed_value) % TEMPLATES.size()
```

- 默认 seed `20261110 % 3 == 1`，因此索引 1 保持为 Step 1–5 使用的默认样板，既有回归盘面不变；
- 相邻 seed（如 `20261110 / 20261111 / 20261112`）覆盖 3 套模板；
- 同一 seed 生成完全一致的类型、房间、武器、护符与位置；
- 不同 seed 除了模板轮换，模板内的房间 / 装备抽取也会改变，形成不同装备路线；
- `generate(act, seed, template_override)` 的第三参数仅供测试 / 采集强制指定模板，运行时不需要传。

## 5. 整备页入口

整备底栏新增并列的两个模式入口（只改本进程 `BoardConfig`，不写存档）：

| 按钮 | 行为 |
|---|---|
| `🗺 旧棋盘` | 开启旧 25 节点 / 1D3 棋盘；再点一次回到线性 |
| `💣 扫雷` | 开启 4×4 扫雷棋盘（`layout_mode = "grid4x4"`）；再点一次回到线性 |

点「确认开战 ▶」时由 `full_reset` 读取当前模式。命令行 `--board --grid` 仍然可用；
两者同时存在时命令行参数优先，按钮只反映当前实际状态。
