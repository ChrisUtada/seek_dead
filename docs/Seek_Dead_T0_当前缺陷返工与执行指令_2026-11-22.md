> 日期：2026-11-22  
> 审查基准：当前提交 `e662b8a` 及当时工作区。

## 1. 复核结论

当前需要返工的不是“所有优化都失效”，而是以下六个明确问题：

1. 营地二选一的免费整理次数可能在未选择整理时残留。
2. 宝箱存在开启前泄露、开启后缺少揭示及类别随机流污染。
3. 事件取消/放弃与支付能力不足的路径不清。
4. 回春、幕间锻魂、坚韧等真实治疗入口没有完整刷新 HUD。
5. 线性模式没有调用幕间锻魂，锻魂仍只挂在地图换幕路径。
6. 非战斗节点计入幕内 `ria`，会让后续敌人额外增强。

### 已确认修复，不重复返工

- F-16 当前以本局持有为商店判据，局外解锁不等于本局持有。
- 宝箱护符链已补槽位扩展、被动刷新与来源记录。
- C-01 已修复敌人攻击影子 HP 遮蔽治疗的基础场景。
- N-03/N-04 的结算账本与演出顺序不作为本次返工对象。
- 旧 `stack_rule/max_stack` 属独立设计/技术债，不在本次启用。

## 2. T0-1 · 营地二选一状态回收（第一步）

### 问题

当前进入营地时会授予一次整理机会，但选择休整、直接继续或取消整理后，没有明确回收未使用的机会。这会把二选一变成“回血后还能再整理”。

### 目标规则

- 进入营地只产生一次本次机会。
- 选择休整且未使用整理：回收本次机会。
- 直接继续且未使用整理：回收本次机会。
- 打开整理后取消且未使用：回到营地选择，但本次机会仍未消耗；最终休整/继续时回收。
- 实际完成整理：按现有 used/granted 规则消耗，不额外回收或补发。
- 不影响玩家通过其他合法来源已经拥有、且尚未使用的整理次数。

### 必测场景

1. 休整后，本次整理次数为 0。
2. 直接继续后，本次整理次数为 0。
3. 打开整理再取消，然后休整/继续，本次机会为 0。
4. 实际整理成功只消耗一次，重复回调不重复扣减。
5. 满血、无合法整理候选、无技能可卸均不软锁。
6. 已有其他来源整理次数时，不会误删玩家原有资源。

### 禁止范围

不重新设计营地选项，不改变回血 25% 规则，不修改精简强度，不做商店或地图调整。

## 3. T0-2 · 宝箱保密、揭示与随机隔离

### 问题

- 开启前的描述可能包含具体物品名称。
- 开启后主要写日志并立即推进，没有明确揭示阶段。
- 类别选择使用全局 `cat.shuffle()`，没有使用特殊房专用 RNG。

### 目标流程

```text
进入宝箱房
→ 只显示宝箱与“开启”按钮，不显示物品名/品质/效果
→ 玩家主动开启
→ 展示冻结的实际物品
→ 玩家确认继续
→ 只结算一次并进入下一房
```

### 规则

- 类别与具体物品均使用特殊房专用 RNG，不消耗全局战斗/奖励随机流。
- 冻结对象在生成后不变；开启、日志、入仓/入槽和展示使用同一对象。
- 武器进入本局仓库，不强制换装。
- 护符沿用已修复的入槽、扩槽、生效和图鉴路径，不回退。
- 消耗品沿用腰带与合法次数规则。
- 空池金币兜底只出现一次，不重复发放。
- 取消或重复点击不能刷新或重复领取。

### 必测场景

- 开启前 UI 不包含物品名称、品质或效果。
- 开启后 UI 展示的物品与实际获得物品一致。
- 同种子、同输入下类型和内容可复现。
- 调用宝箱生成前后的全局 RNG 序列不被类别洗牌污染。
- 武器、护符、消耗品和金币兜底各有真实结算覆盖。
- 重复开启/确认不重复发奖，不软锁。

## 4. T0-3 · 事件取消、放弃与支付能力

### 问题

当前“取消 / 继续”可能重新打开同一事件，并没有真正继续。支付不足的选项也可能展示到选择后才失败。

### 目标语义

| 操作 | 结果 |
|---|---|
| 取消当前选项查看/比较 | 留在事件页，不结算、不推进 |
| 明确放弃事件 | 不获得收益、不支付代价，推进 |
| 选择合法选项 | 应用一次收益与代价，然后推进 |
| 支付不足 | 选项禁用并说明原因，或在生成时过滤 |
| 无合法选项 | 显示明确空状态并允许继续 |

不得让“取消”和“放弃”共用含义相反的按钮文案。

### 必测场景

- HP 不足以支付、金币不足以支付、合法支付、拒绝交易。
- 取消后仍可选择，放弃后不能再次领取。
- 重复点击不重复扣款或发放。
- 无选项、资源恰好等于代价、资源少 1 点等边界。
- 事件奖励不触发战斗结算。

## 5. T0-4 · 真实治疗入口与 HUD 刷新

### 问题

`invalidate_state()` 只让 BattleState 缓存失效，不会主动刷新 HUD。以下入口存在缺口：

- `growth_system.apply_victory_perks()` 的回春；
- `growth_system.grant_act_boon()` 的锻魂 HP/最大 HP；
- `growth_system.pick("tough")` 的最大 HP 与当前 HP。

### 目标

每个真实入口完成后必须同时保证：

1. 真实 HP/最大 HP 正确；
2. BattleState 快照已更新；
3. HP 标签与血条读取新值；
4. 不被旧的受击影子值遮蔽；
5. 满血与溢出转盾仍按现有规则，不把设计行为误报为刷新 bug。

### 必测场景

- 分别从回春、锻魂、坚韧的真实函数入口触发，不只手动设置 `player_hp`。
- 无受击影子、受击影子未释放、满血、部分回血和最大 HP 变化。
- 治疗前后 HP 标签与血条比例一致。
- 不改消耗品治疗和战斗符号治疗已有正确路径。

## 5A. T0-4A · 敌方死亡演出与奖励切换

### 问题与代码证据

敌人死亡后缺少统一、可等待的死亡收口，奖励界面会遮盖最后的命中与死亡结果：

- 普通攻击在 `turn_flow.gd:on_spin_pressed()` 中等 `combat.evaluate()` 后直接打开奖励。
- DoT、免费重转和回合开始时的尸体收口也分别直接调用 `_show_reward_screen()`。
- `battle_animator.gd:play_kill()` 已有溶解方法，但没有生产调用点。
- 血条立即读取真实 HP，后续 tween 主要是白闪与火花；不能把它当作完整死亡演出。

本项只修表现与界面切换顺序，不重算伤害，也不把固定延迟伪装成死亡演出。

### 目标时序

```text
最后一击 / DoT 结算
→ 伤害数字出现，敌人 HP 与血条明确归零
→ 播放敌人死亡溶解，并显示“击败”
→ 等待死亡演出真正完成
→ 打开三选一或 Boss 战利品
```

### 目标规则

- 普通攻击、DoT、免费重转、回合开始尸体收口与 Boss 击杀统一经过一个异步死亡收口。
- 复用 `play_kill()`，等待真实 tween 完成；不在奖励前随意增加固定延迟。
- 奖励在死亡完成后只打开一次，不重复结算。
- 非致命回合不增加死亡等待；和平结局不播放击杀。
- 快速跳过可直接完成死亡视觉状态，但不得留下半透明尸体或未完成的 tween。
- 下一房敌人的透明度、缩放、立绘与血条必须正确复位。
- 不改变伤害、胜负判定、奖励内容、RNG 或战后结算次数。

### 必测场景

- 普通攻击与 DoT 击杀：死亡完成前奖励不可见，完成后只出现一次。
- 免费重转击杀与 Boss 战利品经过同一收口。
- 非致命回合不触发 `play_kill()`，和平结局不触发 `play_kill()`。
- 快速跳过仍得到完整最终视觉状态。
- 连续进入下一房，敌人立绘、透明度、缩放和 HP 显示正常。
- 同种子同输入的结算与 RNG 序列不变。

## 6. T0-5 · 线性模式幕间锻魂断链

### 已证实根因

- 当前唯一调用点位于 `advance_act()`。
- `advance_act()` 在非地图模式直接返回。
- 线性模式 `on_next_room_pressed()` 直接 `_start_room(room_index+1)`，不会调用锻魂。

### 目标规则

- 线性模式进入 ACT2/ACT3 的首个房间时触发一次对应锻魂。
- 触发依据是当前即将进入的真实 ACT 变化，不是单纯房间下标。
- 沿用 `granted_acts` 幂等守卫，同幕不重复。
- ACT1 开局不发放；最终 Boss 追加房不额外发放。
- 保留地图兼容路径，但不双发；地图正式退场在 M-04 另处理。

### 必测场景

- ACT1→ACT2：+8 符号效能、+20 最大 HP 与对应回血各一次。
- ACT2→ACT3：只发 ACT3 对应一次。
- 同一幕重复进入不重复发。
- ACT1 开局与最终 Boss 不额外发。
- 发放后 HUD、日志和 Journal 一致。

## 7. T0-6 · 非战斗节点不得提高敌人强度

### 问题

当前幕内 `ria` 若按房间数组位置/同幕房间数计算，会把宝箱、事件和营地也计入，从而让玩家没有战斗却提高后续敌人强度。

### 目标规则

- 普通/精英敌人按本幕实际战斗序号计算强度。
- 宝箱、事件和营地不占强度序号。
- Boss 继续使用幕末强度基准，不因非战斗节点额外提高。
- 日志、房间 UI、存档和探针分别保留“节点序号”和“战斗序号”，不混用。

### 必测场景

- 同种敌人在特殊房前与后的强度位置差只来自真实战斗。
- 第 3 房特殊节点不会使第 4 房精英额外加一层。
- 第 7 房营地不会改变第 8 房 Boss 的强度。
- 线性与旧兼容路径、三幕与最终 Boss 不出现强度错算。
