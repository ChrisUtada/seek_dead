## 1. 本切片范围

Step 1 只交付了「16 格内容数据」。Step 2 把它接进 `BoardSystem` 与 `BoardScreen`，形成可玩的最小闭环：

- 四方向普通威胁数字；
- 点击相邻未知格揭示内容；
- 敌人先弹确认再进入战斗；
- 装备 / 商店 / 休整按既有棋盘规则结算；
- 已揭示、已消耗、已击败与数字更新；
- 悬停高亮上下左右四格；
- 所有节点只结算一次，回访只移动。

**默认行为不变**：`BoardConfig.layout_mode` 默认仍是 `"legacy"`，旧 1D3 / 25–29 节点棋盘、旧测试与试玩入口完全不受影响。只有显式设置 `layout_mode = "grid4x4"`（或命令行 `--grid`）才进入 4×4。

## 2. 开关与入口

`scripts/board/board_config.gd`

```gdscript
@export var layout_mode: String = "legacy"   # "legacy" | "grid4x4"
@export var grid_seed: int = 20261110        # 内容冻结种子

func use_grid() -> bool:
    if layout_mode == "grid4x4": return true
    return "--grid" in OS.get_cmdline_user_args() or "--grid" in OS.get_cmdline_args()
```

`--grid` 仍需配合 `--board`（`BoardConfig.is_active()`）才开局；单独 `--grid` 不会改变线性入口。

## 3. 运行态模型

`scripts/board/board_system.gd` 新增字段（`reset()` 全部清空）：

| 字段 | 含义 |
|---|---|
| `grid_mode` | 本局是否走 4×4 网格 |
| `revealed` | 已揭示内容的格 id 集合 |
| `defeated` | 已击败的战斗节点 id 集合 |
| `last_move_revisit` | 本次移动是否踏入已消耗格 |
| `_grid_data` | Step 1 冻结内容（只读） |
| `_grid_validator` | `board_grid.gd` 实例 |

生成：`generate()` 检测 `cfg.use_grid()` → `_generate_grid()`，调用 `GRID.generate(act, grid_seed)`，写入 `nodes / by_id / battle_rooms / current_id / boss_ids`，起点标记 `consumed + revealed`，公开格写入 `revealed`；随后走 `_validate_grid()`（Step 1 全部校验 + BOSS 唯一）。

内容冻结：`_grid_data` 生成后不再重抽。移动 / 揭示 / 战斗胜利只改 `current_id / consumed / revealed / defeated`，因此同局的房间、武器、护符始终一致。

## 4. 数字规则

```gdscript
func number_of(id: String) -> int:
    count = 该格四方向相邻中 type == "normal" 且未 defeated 的格数
```

- 精英与 BOSS **不计入**数字；
- 数字是实时计算的，不写回节点 `number`（内容层仍为 `-1`）；
- 普通怪被击败后（`note_battle_won()` 写入 `defeated`），相邻数字立即减一；
- `numbers_snapshot()` 返回 16 格当前数字，便于 UI 与测试读取。

固定种子下的开局数字（`grid_seed = 20261110`）：

```
1 1 0 2
1 2 2 0
2 2 1 1
2 1 1 0
```

行优先对应 `g00..g33`；普通怪位于 `g02 / g10 / g13 / g20 / g21 / g31`。

## 5. 移动、揭示与一次性结算

- **相邻限制**：`legal_targets()` 返回当前格四方向全部邻格（含已消耗格），按 id 排序；`advance_to(id)` 拒绝非邻格。
- **进入即揭示**：首次进入写入 `revealed[id] = true`，之后该格显示真实类型与名称。
- **已消耗可回访**：不采用自避行走，避免把 BOSS 封死。回访只改 `current_id`，`last_move_revisit = true`，不再结算节点效果、不再弹战斗确认。
- **普通 / 精英 / BOSS**：进入后由 `BoardScreen` 弹战斗确认；确认才开战。战斗胜利回到棋盘时 `return_to_board()` → `note_battle_won()` 标记当前战斗节点 `defeated`；战败走局末，不经过该路径。
- **装备 / 商店 / 休整**：沿用既有 `BoardScreen._advance_to` 的非战斗结算路径（获得武器 / 护符、开商店、回血），只结算一次。
- **幂等**：重复调用 `note_battle_won()` 不改变数字；重复进入同一格不重复发奖励。
- **进度与骰子**：网格下 `can_roll() = false`、`roll_dice() = 0`、`has_steps() = false`；`progress_text()` 改为「已探索 x/16 格」。

## 6. 界面

`scripts/board/board_screen.gd` 新增网格分支，全部由 `_is_grid()` 判定：

- 隐藏「前进」按钮与骰子；底栏改为「数字 = 上下左右普通敌人数 · 点击相邻格探索」；右上角显示「已探索 x/16」。
- 16 个透明热区与 4×4 节点绘制；`_draw_grid_art()` 画网格底、邻接线、节点。
- **未揭示普通怪**：显示「?」，信息栏与 tooltip 统一为「未知格 / 进入后揭示具体内容 / 数字 N：上下左右有 N 个普通敌人」，不泄露房间身份。
- **公开内容**（精英 / BOSS / 装备 / 商店 / 休整 / 起点）：开局即可见名称与描述。
- **数字徽标**：0 用 `MUTED_DIM`，1–2 用 `ACCENT_GOLD`，3–4 用 `ENEMY`。
- **悬停高亮**：鼠标悬停任意格时，上下左右四格描边高亮；同时信息栏显示该格线索。
- **点击**：只有相邻格会移动；点击非相邻格只查看信息，不移动、不弹确认。
- **状态文案**：当前位置 / 已探索（可再次经过）/ 可探索（相邻）/ 不相邻 · 点击查看线索。
