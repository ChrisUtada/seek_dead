# Seek Dead · 四级品质战利品与大奖池分步执行计划

> 日期：2026-11-12  
> 状态：制作与实施计划；Step 0–4 已完成（2026-11-13），Step 5–8 待做  
> 核心原则：**采用四级品质，以机制差异为主、数值差异为辅；奖励等级由敌人与探索来源决定，三选一则在同价值选项中生成。**  
> 目标：形成可收集、可构筑、可重复探索的大奖池，同时避免“永远选择最高稀有度”。  
> 验收方式：全部使用资源检查、定向测试、固定种子、统计模拟与完整回归；不设置人工试玩出口。

---

## 1. 现状与改造判断

### 1.1 已有内容基础

当前资源已经使用 `common / uncommon / rare / epic` 四档字符串，可直接映射为四级品质，不需要重做存档 ID。

| 内容 | 当前数量 | 当前品质分布 | 本轮用途 |
|---|---:|---|---|
| 武器 `resources/weapon_templates/` | 90 | 36 / 27 / 18 / 9 | 重新核对机制定位与掉落层级 |
| 护符 `resources/charms/` | 45 | 9 / 8 / 14 / 14 | 补充基础通用件，整理 Build 联动 |
| 消耗品 `resources/consumables/` | 25 | 2 / 13 / 10 / 0 | 补充基础件，明确高阶消耗品定位 |
| 技能 `resources/skills/` | 40 | 16 / 12 / 8 / 4 | 作为构筑奖励的组成部分 |

现有约 200 项内容已足够支撑第一阶段。**第一阶段不设新增数量 KPI，先让已有内容在正确品质、正确来源和正确构筑家族中发挥作用。**

### 1.2 当前必须拆掉的三类耦合

1. **奖励卡稀有度不等于物品品质**  
   `RewardData.rarity` 当前用于治疗、金币、符号灌注等奖励卡的抽取权重；物品自身也有 `rarity`。新系统不能继续把二者混为同一层随机。
2. **物品品质不能暗中改变出现频率**  
   当前 `ReelSystem` 对单源 rare/epic 非伤害符号存在格数封顶。若品质要表达战利品层级，就必须把“品质”“符号权重”“实际带格数”拆开，不能出现高阶护符或技能因为品质升高而隐性更难触发。
3. **来源品质必须先于三选一**  
   不能先混抽普通与传说，再让三张卡一起展示。先由普通战、精英、BOSS、宝箱等来源确定本次品质，再生成同层候选。

### 1.3 保留的现有能力

- 文件夹资源扫描与图鉴收集；
- 奖励展示前冻结具体 payload；
- 满槽后的替换或折算流程；
- BOSS 主题奖励池；
- 技艺、铭印与武器熟练成长；
- 固定种子、遥测和现有自动化回归。

## 2. 最终规则

### 2.1 三个概念必须分开

| 概念 | 含义 | 不承担的工作 |
|---|---|---|
| **物品品质** | 机制定位、获得来源、收藏层级 | 不直接决定符号频率 |
| **强化／熟练** | 已拥有物品的纵向成长 | 不把低品质直接洗成另一件高阶物品 |
| **来源奖励等级** | 本次奖励应进入哪个品质层 | 不决定三个候选中哪一个更好 |

存档键继续使用：

| 层级 | 存档值 | 显示名 | 核心定位 |
|---|---|---|---|
| Ⅰ | `common` | 基础 | 稳定、通用、容易理解 |
| Ⅱ | `uncommon` | 进阶 | 明确服务一个构筑家族 |
| Ⅲ | `rare` | 稀有 | 可成为 Build 核心，改变联动方式 |
| Ⅳ | `epic` | 传说 | 改变规则，具有条件、限制或风险 |

### 2.2 四级品质不是四级线性数值

| 层级 | 机制要求 | 数值原则 | 示例 |
|---|---|---|---|
| Ⅰ 基础 | 一个直接效果，无复杂前置 | 稳定、可用、不过时 | 命中造成直接伤害；立即净化；下一房护盾 |
| Ⅱ 进阶 | 一个明确标签或状态联动 | 条件满足后高于基础件 | 灼烧目标提供充能；护盾存在时反击 |
| Ⅲ 稀有 | 改变两个系统之间的联动 | 数值受条件与频率预算约束 | 特定三连转化干扰；同类标签触发额外效果 |
| Ⅳ 传说 | 改变一条可感知规则 | 有明确限制，不无脑全面更强 | 某符号可触发两次，但额外消耗充能 |

高品质可以拥有更高的条件收益，但不能同时拥有更高基础数值、更高触发频率、更低命中损耗和无条件通用性。

### 2.3 同级三选一

候选生成顺序固定为：

```text
确定奖励来源
→ 按来源与幕次确定品质层
→ 收集该层合法候选
→ 排除本次重复与无实际效果项
→ 生成三个具体且冻结的候选
→ 展示装备／替换／转化结果
→ 玩家确认后一次性结算
```

同一组三选一必须满足：

- 三个选项处于同一品质层；
- 三个具体资源路径不重复；
- 至少覆盖两种不同的决策用途；
- 每项都有真实、当前可结算的效果；
- 展示具体物品后，确认时不得二次随机；
- 重抽只换同层候选，不重新抽品质；
- 空池时使用同层转化或强化选项，不混入更高品质凑数。

“同价值”指**同品质、相近预算、不同用途**，不要求不同 Build 下具有完全相同的即时 DPS。

## 3. 构筑家族与内容分工

### 3.1 首版机制家族

| 家族 | 基础件职责 | 进阶件职责 | 稀有／传说职责 |
|---|---|---|---|
| 火焰／灼烧 | 稳定火伤、少量灼烧 | 灼烧联动、充能 | 扩散、重复触发、状态转化 |
| 冰霜／迟滞 | 冰伤、基础控制 | 控制后输出 | 冻结窗口、行动规则变化 |
| 毒素／酸蚀 | 挂毒、少量破甲 | 层数联动、护甲联动 | 层数转移、爆发或延时收益 |
| 光明／恢复 | 治疗、净化、护盾 | 治疗后增益 | 恢复与攻击／符号联动 |
| 暗影／风险 | 稳定暗伤、小代价 | 低血或消耗资源换收益 | 高风险规则改写 |
| 护盾／反击 | 直接护盾 | 持盾触发 | 护盾转化、保留或反制 |
| 充能／爆发 | 获得或保存充能 | 达阈值触发 | 改变消耗、连发或爆发窗口 |
| 连击／三连 | 稳定连线收益 | 特定元素连线 | 三连附带破甲、转化或额外结算 |
| 转轮操作 | 预览、少量缓冲 | 指定列或标签协同 | 重排、锁定、替换等规则能力 |
| 消耗品／资源 | 治疗、金币、单次解场 | 多用途或条件充能 | 改变物品使用与资源循环 |

### 3.2 跨家族要求

- 每个家族至少有一种基础入口，不能只靠高阶核心才能运转。
- 高阶物品至少有一种跨家族配合，避免所有大奖池都变成封闭套装。
- 净化、排障等能力不能成为少数怪物唯一的强制门票。
- 不根据玩家当前强势家族暗中降低对应奖励权重。
- 只过滤真正非法或完全无效果的候选，不做动态克制 Build。

## 4. 来源与品质分配

### 4.1 首轮统计测试权重

下表是**模拟起点，不是不可修改的成品数值**：

| 来源 | Ⅰ 基础 | Ⅱ 进阶 | Ⅲ 稀有 | Ⅳ 传说 |
|---|---:|---:|---:|---:|
| 普通战 | 70% | 25% | 5% | 0% |
| 精英战 | 20% | 50% | 27% | 3% |
| 区域 BOSS | 0% | 10% | 60% | 30% |
| 探索宝箱／搜寻 | 35% | 40% | 22% | 3% |
| 特殊事件 | 按公开风险单独配置 |  |  |  |

规则：

- 幕次可以调整来源表，但不能与旧稀有度加权、BOSS 深度偏置叠加成多套隐式随机。
- 首版以来源表为唯一品质概率来源。
- 商店提供类别和品质确定性，不完全照搬战斗随机池。
- 真·最终 BOSS 若现有流程明确不发战利品，则保留局末结构，不为套表强行新增。
- BOSS 主题池仍然有效，但先在主题与合法来源内确定品质，再抽具体候选。

### 4.2 基础资源与战利品分开

- 小额金币、基础历练等按现有规则自动结算，不占战利品三选一名额。
- 治疗不能长期成为同层候选中的必选项；满血时不生成纯治疗。
- 技艺、铭印等成长奖励只有在实际触发时出现，不为凑满三张卡生成假成长。
- 战利品三选一与成长队列分开结算；不得把不同品质物品混作一组来保留旧三槽形式。

### 4.3 重复、跳过与重抽

- “已解锁图鉴”不等于“本局重复”，不得因此从本局奖池剔除。
- 本局已装备或已收纳的同路径物品再次出现时必须展示明确转化结果。
- 重复装备转化为该物品的熟练、铭印进度或既有通用资源，优先复用现有成长通道。
- 玩家可以跳过战利品并获得事先显示的同级转化收益。
- 重抽沿用当前来源与品质层，不能借重抽刷出更高品质。
- 不新增一套仅用于奖励转换的复杂货币。

## 5. 数据与展示规范

### 5.1 每项内容需要具备的设计元数据

| 字段 | 用途 |
|---|---|
| `rarity` | 四级品质，沿用现有存档值 |
| `family_tags` | 火焰、护盾、充能、转轮等一个或多个家族 |
| `role` | 输出、防御、恢复、控制、资源、操作、转化 |
| `mechanism_summary` | 一句话说明触发、效果与条件 |
| `act_min / act_max` | 合法幕次，不用幕次替代品质 |
| `source_tags` | 普通、精英、BOSS、宝箱、商店、事件等合法来源 |
| `unique_group` | 同屏互斥或同机制分组，避免三项只是换皮 |
| `conversion_rule` | 重复、满槽或跳过的明确转化口径 |

这些字段是制作规范；实际实现应优先扩展现有 `LoadoutItem`、`ItemData` 与奖励 payload，不另建平行物品目录。

### 5.2 数值预算规范

每个品质层建立一份预算表，至少包含：

- 无条件基础效果；
- 条件效果的触发频率；
- 状态层数与持续时间；
- 转轮带格数变化；
- 资源消耗；
- 使用次数；
- 替换成本；
- 负面条件与适用范围。

禁止只比较 `base_power`。同一个效果还必须同时检查其实际出现频率和每回合可触发次数。

### 5.3 卡片展示顺序

```text
品质与名称
→ 核心机制
→ 当前 Build 中的真实变化
→ 条件／代价
→ 装备、替换、收纳或转化结果
```

必须显示真实变化，例如“该符号 2 格 → 3 格”，不能只写“概率提升”。品质颜色只辅助识别，不能替代机制文本。

## 6. 分步骤实施

## Step 0 · 冻结口径与建立现状快照

**任务**

1. 确认四级显示名与现有存档字符串映射。
2. 导出所有物品的品质、类别、家族、数值、符号、来源和当前获取通道。
3. 记录当前奖励抽取、BOSS 主题池、商店、拆解／折算和成长队列行为。
4. 标记所有“品质影响频率”和“奖励卡品质影响物品品质”的旧路径。

**主要位置**

- `scripts/battle/loadout_item.gd`

- `scripts/items/reward_data.gd`
- `scripts/systems/reward_system.gd`
- `scripts/systems/post_battle_system.gd`
- `scripts/battle/reel_system.gd`

**自动出口**

- 资源清单能完整生成；
- 每项现有资源都有唯一路径与可读取品质；
- 旧概率与结算入口均有清单，没有遗漏的隐藏奖池。

## Step 1 · 建立品质定义与构筑家族标签

> 状态：✅ 已完成（2026-11-13）。落地说明与定向回归见 `docs/Step1_品质定义与构筑家族标签_2026-11-13.md`；新增第 38 套 `item_taxonomy_test`。

**任务**

1. 为现有内容逐项分配家族、用途和合法来源。
2. 先修正明显错层：无条件高数值基础件、没有机制的高阶件、缺乏基础入口的家族。
3. 为每项写一句机制摘要，标明触发条件与限制。
4. 不为了填数量复制换皮装备。

**自动出口**

- 所有可掉落内容至少有一个合法家族、用途和来源；
- 不存在无法从任何来源获得的可掉落物品；
- 高阶物品必须包含机制差异，不能只有品质与基础数值差异；
- 每个首版家族都有可用的基础入口。

## Step 2 · 解耦品质、频率与强化

> 状态：✅ 已完成（2026-11-13）。落地说明与前后对照见 `docs/Step2_品质与频率解耦_2026-11-13.md`；新增第 41 套 `loot_frequency_test`。

**任务**

1. 将物品品质从符号格数规则中剥离。
2. 符号频率只由明确的符号权重、类型、构筑效果和带规则决定。
3. 强化／熟练继续服务纵向成长，不修改物品原始品质。
4. 对受旧封顶影响的非伤害符号生成前后对照表。

**自动出口**

- 仅修改物品 `rarity` 时，同一 Build 的实际转轮带格数不变；
- 明示的符号灌注与减带仍按原规则工作；
- 已有武器、技能和护符在测试配装下能正常结算；
- 不出现因为升到高品质而触发次数下降的物品。

## Step 3 · 实现来源品质表与统一候选池

> ✅ 已完成（2026-11-13）：见 `docs/Step3_来源品质表与统一候选池_2026-11-13.md`；全量 42/42 ALL GREEN，第 42 套来源池 83 项。

**任务**

1. 用统一来源表替代分散的奖励稀有度与物品品质串联随机。
2. 建立按品质、幕次、来源、主题和合法性筛选的候选池。
3. BOSS 保留主题过滤，商店保留类别过滤。
4. 固定种子下，来源品质与候选内容都可复现。

**自动出口**

- 每个来源与幕次组合都能返回合法结果或明确空池原因；
- 同一品质和来源下重复生成不消耗额外地图 RNG；
- 非法幕次、非法来源和非法主题不会混入；
- 统计模拟能够逐项还原来源表权重。

## Step 4 · 实现同层三选一与冻结 payload

> ✅ 已完成（2026-11-13）：见 `docs/Step4_同层三选一与冻结payload_2026-11-13.md`；全量 43/43 ALL GREEN，第 43 套 34 项。来源接入与 UI 收口分别留 Step 5 / Step 7。

**任务**

1. 先抽品质，再无放回抽三个具体候选。
2. 生成时检查同层、不同资源、不同用途和真实效果。
3. 在展示前冻结物品、数值、替换对象和转化结果。
4. 无足够物品时使用同层强化／转化候选，不跨层补位。
5. 重抽沿用品质；跳过显示固定转化结果。

**自动出口**

- 批量生成的每组奖励均为同层且恰好三个有效选项；
- 不出现同路径重复、空名称、空效果或确认后换物；
- 满血、满槽、全收集和空主题池均有合法出口；
- 重抽不改变品质，跳过的转化与展示完全一致。

## Step 5 · 接入普通、精英、BOSS 与探索来源

**任务**

1. 普通战使用普通战来源表。
2. 精英战提供更高品质机会，但不附加同屏混层大奖。
3. 区域 BOSS 在主题池内生成高阶战利品。
4. 探索宝箱／搜寻使用探索来源表，地图内容生成时冻结。
5. 商店按类别、幕次和价格提供确定性补全，不与战斗共用全部随机逻辑。

**自动出口**

- 各来源只读取自己的品质表；
- BOSS 主题和最终房规则不变形；
- 探索奖励在揭开前已经冻结，查看、撤回、回访和重开界面不会重抽；
- 同一奖励只能结算一次。

## Step 6 · 接入重复转化、成长队列与图鉴

**任务**

1. 本局重复物品进入熟练、铭印或既有资源转化。
2. 技艺与铭印继续由真实成长触发产生，不与物品品质混抽。
3. 图鉴记录实际获得、来源和最高熟练。
4. 已收藏物品仍可在新一局出现，不做全局永久剔除。

**自动出口**

- 重复转化只执行一次，并能推进所展示的成长；
- 成长队列不因战利品重抽而丢失或重复；
- 图鉴来源与实际来源一致；
- 撤回、战败和通关仍按现有保存规则处理。

## Step 7 · 完成信息展示与交互收口

**任务**

1. 统一四级名称、颜色和机制文本。
2. 展示当前 Build 下的真实变化与替换得失。
3. 同层候选不使用“更高品质”角标诱导选择。
4. 奖励界面支持查看、确认、替换、转化与重抽的明确状态。
5. 保留现有 UI 边界，不让长文本遮挡转轮和战斗信息。

**自动出口**

- 固定分辨率下卡片文本、按钮和数值均在容器内；
- 所有候选有品质、机制、条件与结果文本；
- 鼠标、键盘和取消路径不会重复发奖；
- 奖励开关过程不改变地图内容或无关 RNG 序列。

## Step 8 · 大奖池统计、平衡与完整回归

**任务**

1. 对每个来源与幕次进行大样本统计。
2. 对每种品质进行基础 Build、单家族 Build 和混合 Build 的可用性检查。
3. 比较“只按品质选择”与“按家族联动选择”的模拟结果，排查品质长期压倒构筑的情况。
4. 运行完整自动跑局，检查空奖励、成长中断、无法推进和异常耗时。
5. 执行项目完整 `run_smoke.bat`。

**自动出口**

- 大样本来源分布落在预设容差内；
- 同层不存在大量无条件严格上位物品；
- 各家族都有可完成一局的基础路径；
- 自动跑局不出现空奖励、重复结算或流程死锁；
- 全部既有与新增自动测试通过。

## 7. 自动化验收矩阵

| 维度 | 方法 | 通过条件 |
|---|---|---|
| 资源完整性 | 扫描全部 `.tres` | 路径唯一、品质合法、来源与家族非空 |
| 品质分布 | 每来源／幕次至少 10,000 次抽样 | 实测比例与目标误差不超过 ±2 个百分点 |
| 三选一同层 | 批量生成至少 10,000 组 | 混层、重复、空 payload 均为 0 |
| 落点频率独立 | 同 Build 仅替换品质 | 带格数与符号顺序保持不变 |
| 展示冻结 | 展示后重复读取并确认 | 路径、数值、替换与转化结果完全一致 |
| 重抽纪律 | 对固定来源连续重抽 | 品质不变，只改变同层候选 |
| 幂等 | 重复确认、回访、撤回和重开界面 | 奖励与成长均只结算一次 |
| 来源合法 | 遍历全部来源和幕次 | 无非法主题、幕次或类别混入 |
| 构筑可用 | 多种固定 Build 自动跑局 | 每个基础家族均能完成流程，不依赖唯一传说件 |
| UI 安全 | 固定分辨率与边界文本测试 | 无越界、遮挡、无法确认或无法取消 |
| 全项目回归 | 标准 smoke 入口 | 所有套件通过 |

统计模拟用于发现分布、支配和流程问题，不把 bot 胜率直接解释为游戏乐趣或最终难度结论。

---

## 8. 停止条件与返工规则

出现以下任一情况，不进入下一步：

- 三选一中混入不同品质，导致最高品质成为显然答案；
- 品质仍然暗中影响符号频率；
- 高阶内容只有更大的基础数值，没有机制差异；
- 候选在展示后或确认时重新随机；
- 玩家当前 Build 越强，系统越刻意不给对应内容；
- 为填满三个选项而生成无效果、满血治疗或无法结算的奖励；
- 新来源表与旧稀有度权重、深度偏置同时叠加且无法解释；
- 重复奖励、满槽或空池导致流程卡死；
- 自动化统计或完整回归未通过。

返工时优先修改**单项规则或单张物品**，不要同时调整品质概率、敌人 HP、伤害和转轮频率，避免无法定位收益变化来源。

## 9. 完成后的玩家体验目标

- 普通战提供稳定构筑部件，而不是永远重复数值卡；
- 精英和 BOSS 提供更明显的机制跃迁；
- 同一组三选一需要比较用途，而不是只比较颜色；
- 基础装备可以持续强化并服务整个一局；
- 高阶装备提供新联动，同时保留条件和代价；
- 重复获得仍有成长价值；
- 大奖池由多个可理解、可混合的机制家族组成；
- 图鉴、来源和收藏记录能够支持长期探索。

最终验收不以“新增了多少件装备”为完成标准，而以**四级品质职责清楚、来源分布可控、同层候选有真实选择、既有内容全部能进入统一循环**为完成标准。
